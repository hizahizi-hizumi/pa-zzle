# skill-reviewer

- 受け取るもの: レビューする SKILL.md か `.claude/skills/share/` のファイルのパス
- 返すもの: 下の「返す形」で書いた、重さごとの指摘とほかの気づき

## 手順

1. `.claude/rules/skills.md` を読む
2. 対象を決める
   - SKILL.md を受け取ったときは、そのディレクトリ配下のファイルを Glob で挙げ、SKILL.md が参照する `share/` のファイルと合わせて対象にする
   - `share/` のファイルを受け取ったときは、`.claude/skills/*/SKILL.md` を Grep してそのファイルを参照する SKILL.md を探し、それらと合わせて対象にする
3. 対象のファイルを読む
4. skills.md の各項目で対象を検査する。そのうち次の項目は、それぞれ次のように検査する
   - 「SKILL.md にはそのスキルが使うすべての補助ファイル…」は、2 で挙げた補助ファイルの各パスと読む・使うタイミングが SKILL.md に書かれているかを確かめる
   - 「2つ以上のスキルが使う補助ファイルは各スキルに写さず…」は、対象の補助ファイルと同じ名前のファイルを `.claude/skills/**/` から Glob し、読み比べて同じ内容かを確かめる
   - 「`share/` には2つ以上のスキルが使うファイルだけを置く」は、`share/` の各ファイルのパスを `.claude/skills/*/SKILL.md` から Grep し、参照するスキルを数える
   - 「ルールの決まりやデザイントークンの値のように…」は、対象に書いた決まりや値を `.claude/rules/*.md` と `frontend/styles/globals.css` から Grep し、写していないかを確かめる。「」で名指しした文言は写しとしない
   - 「手順の中で起動するほかのスキルは `disable-model-invocation: true` でないものに限る」は、起動先の SKILL.md のフロントマターを読んで確かめる
5. SKILL.md と補助ファイルに書いたパスのうち、読む・使う既存のファイルとして書いたものは、リポジトリのルートとその SKILL.md のディレクトリの両方から Glob し、どちらにも無いものを無いとする。`<…>` を含むパス、作るファイルのパス、例のコードブロックの中のパスは除く
   - SKILL.md の本文の `${CLAUDE_PROJECT_DIR}` はリポジトリのルート、`${CLAUDE_SKILL_DIR}` はその SKILL.md のディレクトリとして確かめる
   - 補助ファイルの中ではこの2つが置き換わらないので、これらを含むパスは無いとする
6. 各指摘を下の重さに振り分ける。1つの指摘が複数の重さに当たるときは重い方にする
7. skills.md の項目に当たらない気づきは、指摘と分けて「ほかの気づき」に書く

## 重さ

- Critical: スキルが読み込まれない・読む先が無いもの。フロントマターが YAML として読めない、読む・使う既存のファイルとして書いたパスのファイルが無い
- Major: skills.md の項目に反し、スキルを使うエージェントの動作や判断、スキルの起動のされ方が変わるもの
- Minor: skills.md の項目に反するが、直してもスキルを使うエージェントの動作や判断、スキルの起動のされ方は変わらないもの

## 返す形

```markdown
## Skill Review: <受け取ったファイルのパス>

### Critical
- <ファイル>:<行>: <問題> — <直し方>

### Major
- <ファイル>:<行>: <問題> — <直し方>

### Minor
- <ファイル>:<行>: <問題> — <直し方>

### ほかの気づき
- <ファイル>:<行>: <気づき>
```

- 指摘の無い重さには「なし」と書く。気づきが無ければ「ほかの気づき」を省く
- 直し方には書き換え後の文を書く
