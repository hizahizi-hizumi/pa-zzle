# SKILL.md 作成ルール

`.claude/skills/<name>/SKILL.md` を新規作成・編集する際の記法ルール。判断軸（どのレイヤーに書くか）は本ファイルでは扱わない。

## 1. フロントマター

- YAMLフロントマターは `---` で囲む
- 公式リファレンス表に列挙されたフィールドのみ使う（フィールド一覧と書式は公式仕様を正本とし、本ルールで再掲しない）
- `name`: ディレクトリ名と一致。小文字とハイフンのみ、64文字以内。予約語（`anthropic` / `claude` 等）を含まない
- `description`: 必ず付与する。起動条件を網羅した三人称の文。50〜500字を目安とし、`description` + `when_to_use` の合算は1,536字で打ち切られる
- `allowed-tools` を指定する場合は最小権限で列挙する
- 採用したパターンに応じて、フィールドの組合せがそのパターンの意図と整合していることを確認する

## 2. `description` の書き方

- 三人称で書く。英語の定型句を使う場合は `This skill should be used when...` の形にする
- 起動条件の文言を具体的に列挙する（英語キーワードは必須、日本語キーワードは任意）
- 主要用途を最初に書く（1,536字で打ち切られるため）
- 50字未満の曖昧な `description` は避ける
- 第二人称の文は使わない（例: `You should...`）

## 3. 本文

- 章立て例: 動作フロー / 出力先 / 参照する正本 / 制約
- 起動コマンド（`/<name>`）を冒頭で示す
- 500行未満を目安とする（スキルは起動後ずっとコンテキストに残るため、行数が反復トークンコストになる）
- 1,000〜3,000語を目安とする
- 命令形または不定詞形で書く（例: 「XするにはYする」）
- 第二人称を避ける
- 章構造を論理的にする（関連項目をグループ化し、フローを追えるようにする）

## 4. 段階的開示（補助ファイル）

- 詳細なリファレンス / 例 / スクリプトは `references/` `examples/` `scripts/` `assets/` 等のサブディレクトリに分離する
- SKILL.mdからは「これを参照するときはこのファイル」と参照先を書く
- 1階層分離を基本とする（深いネストは避ける）
- スクリプトは実行されるがコンテキストを消費しない

## 5. 動的コンテキスト挿入

- `!` を使うコマンド埋め込み構文でシェル出力をスキル内容に埋め込める
- 複数行は動的コマンド用のコードフェンスで書く
- 起動前に実行されるため、Claudeは出力後の最終プロンプトのみを見る
- `${CLAUDE_SESSION_ID}` `${CLAUDE_SKILL_DIR}` `$ARGUMENTS` `$N` 等の文字列置換が使える

## 6. 本リポ固有の追加観点

- 外部参照を持つスキルは参照先パスをSKILL.md内に明示する
- ディレクトリ名 = `name` フィールド = 起動コマンド `/<name>` の三者が一致する
- `description` には英語の起動条件を必ず含める。日本語の起動条件は任意

## 7. アンチパターン

- 曖昧な `description`（例: `helper` `assistant` のような汎用語のみ）
- SKILL.md本文に詳細を詰め込み過ぎる（`references/` に分離すべき内容）
- `description` が第二人称
- 起動条件の文言が抜けている（Claudeが起動条件を判断できない）
- 例やリファレンスが必要な場面（出力形式が具体的にある等）で補助ファイルを持っていない
- フロントマターに公式リファレンス表にないフィールドを書く
- ディレクトリ名と `name` フィールドが不一致
