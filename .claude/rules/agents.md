# エージェント定義ファイル作成ルール

`.claude/agents/<name>.md` を新規作成・編集する際の記法ルール。判断軸（どのレイヤーに書くか）は本ファイルでは扱わない。

## 1. フロントマター

- YAMLフロントマターは `---` で囲む
- 公式リファレンス表に列挙されたフィールドのみ使う（フィールド一覧と書式は公式仕様を正本とし、本ルールで再掲しない）
- `name`: ファイル名（`<name>.md`）と一致。**動作主名詞**で動作主を表す。動詞から派生する名詞で、`-er` / `-or` / `-ist` / `-ant` 等の接尾辞を取る（例: `verify` → `verifier`、`extract` → `extractor`、`discover` → `discoverer`）
- `description`: 必ず付与する。三人称で何を入力に何を返すか1〜2文と起動条件を含む
- `tools` を指定する場合は最小権限で列挙する。読み取り専用エージェント（調査系）には `Write` を渡さない
- `description` で約束した入出力が `tools` と本文で実現可能になっている

## 2. `description` の書き方

- 三人称で書く。英語の定型句を使う場合は `This agent should be used when...` の形にする
- 入出力を1〜2文で記述する（例: 「URLリストを巡回してトピック候補をCSVに追記する」）
- 起動条件を含める（Claudeが委譲判断できるようにする）
- 1〜2文で簡潔にする

## 3. システムプロンプト（本文）

### 章立て

- 役割（1〜2行）: このエージェントが何の専門家か
- 責務: 何を入力に何を返すか
- 参照する正本: 読み込むファイル / API / 文書のパス
- 出力形式: 構造化された出力ならスキーマを示す
- 制約: 権限境界 / してはいけないこと
- 該当時のみ優先度の既定値
- 該当時のみ観点別の検査手順

### 整合性

- `description` で約束したことを本文が実現している
- 観点 / 優先度 / 出力スキーマ等は `description` と一致する

## 4. ツール権限

- 最小権限で列挙する（使わないツールは渡さない）
- 読み取り専用エージェント（調査 / レビュー系）には `Write` / `Edit` / `Bash` 等を渡さない
- `Bash` を渡す場合はコマンドパターンで限定する（例: `Bash(git status *)`）

## 5. アンチパターン

- 一人称の `description`（例: `I will help you with...`）
- 過剰権限（使わないツールも渡している）
- システムプロンプトの長文化（主要セクションが埋もれて参照しづらい）
- `description` で約束した動作を本文が実現していない
- `name` が動作主名詞でない（動詞そのまま / 名詞のみ等）
- ファイル名と `name` フィールドが不一致
