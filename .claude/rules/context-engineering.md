# コンテキスト設計ルール（どこに書くか）

`CLAUDE.md`（本リポでは `AGENTS.md`）/ `.claude/rules/` / `.claude/skills/` / `.claude/agents/` / `docs/` のどこに新しい開発情報を置くかを判断するためのルール。書き方は本ファイルでは扱わない（各レイヤーの記法ルールを `paths` の範囲で分離している）。

## 1. レイヤー早見表

| レイヤー | 配置場所 | 読み込みタイミング | トークンコスト |
|---|---|---|---|
| CLAUDE.md / AGENTS.md | リポジトリルート | 毎セッション自動 | 常に消費 |
| `paths` なしルール | `.claude/rules/*.md` | 毎セッション自動 | 常に消費 |
| `paths` ありルール | `.claude/rules/*.md` | 該当パスのファイル編集時 | 条件付き消費 |
| SKILL.mdフロントマター | `.claude/skills/<name>/SKILL.md` | 毎セッション自動（`description` のみ） | 極小 |
| SKILL.md本文 | 同上 | 起動時に展開 | 起動時のみ |
| エージェントの `description` | `.claude/agents/<name>.md` | 毎セッション自動（`description` のみ） | 極小 |
| エージェント本文 | 同上 | 起動時に独立コンテキストへ | メイン消費なし（隔離） |
| 開発者向け文書 | `docs/` 配下 | 明示的な `Read` でのみ | 必要時のみ消費 |

## 2. 各レイヤーの責務

### CLAUDE.md / AGENTS.md（リポジトリルート）

- 毎セッション確実に伝えたい最小限の情報のみ
- プロジェクト一行説明、技術スタック、ビルド / テスト / リントのコマンド
- コードから推論できない規約（例: pnpmを使う、デフォルトエクスポート禁止）
- `docs/` のディレクトリマップと「いつ参照すべきか」のヒント

### `paths` なしルール

- CLAUDE.md / AGENTS.mdの関心事ごとの分割（人間の管理都合のみ）
- 分割してもエージェントから見た合計指示数は変わらない（トークンコストも注意資源の劣化も改善しない）

### `paths` ありルール

- 特定パスを編集するときだけ必要になる規約
- サブディレクトリ固有の規約はサブディレクトリCLAUDE.mdではなくここに置く

### SKILL.md（`.claude/skills/<name>/`）

- 特定の作業に対する実行手順・成果物例・検証ロジックのパッケージ
- 「スラッシュコマンドで起動する」と自然に表現できる単位
- 段階的開示: フロントマターの `description` のみ常駐し、本文は起動時に展開する

### エージェント（`.claude/agents/<name>.md`）

- 独立したコンテキストウィンドウで動作する特化型作業者
- メインセッションを汚染せずに大量ファイル読み込み・外部API調査・並列作業を隔離する
- `description` のみメインに常駐し、本文は起動時に新しいコンテキストへ読み込む

### 開発者向け文書（`docs/`）

- 特定のスキル / エージェントに属さないが、開発時の文脈理解に必要な背景情報
- ADR、ドメイン知識、外部依存仕様、人間向け開発ドキュメント等
- Claude Codeの段階的開示機構の外。明示的な `Read` が必要

## 3. 判断フローチャート

新しい開発情報をエージェントに伝えたい:

1. **`Hooks` で決定論的に強制できるか?** → はいなら `Hooks`（CLAUDE.md / ルールには書かない）
2. **エージェントが毎セッション知る必要があるか?**
   - はい、かつ全ファイル共通 → CLAUDE.md / AGENTS.md（チーム管理都合で分割するなら `paths` なしルールも可）
   - はい、かつ特定パスのみ → `paths` ありルール
3. **特定の作業種別に紐づくか?（スラッシュコマンドとして表現できるか?）** → はいなら `.claude/skills/<name>/`
4. **独立コンテキストで動作する特化型作業者として切り出せるか?** → はいなら `.claude/agents/<name>.md`
5. **どのスキルにも属さない横断的な開発知識か?** → `docs/`（CLAUDE.md / AGENTS.mdに参照先を記述）

## 4. トークンコストの管理

- CLAUDE.mdと `paths` なしルールは毎セッション消費される固定コスト
- CLAUDE.mdから `paths` なしルールへ分割してもトークンコストは変わらない（合計が同じ）
- 遵守率が低下した場合の対処順:
  1. 不要な指示の削除
  2. 静的チェックの `Hooks` への委譲
  3. 特定作業向け手順のスキルへの移行
  4. 特定パス向け規約の `paths` ありルールへの移行

## 5. 本リポ固有の禁止事項

- **サブディレクトリCLAUDE.mdは作らない** — 散乱するとどこに何が書いてあるか追えなくなる。サブディレクトリ固有の規約は `paths` ありルールで代替する
- **CLAUDE.md / ルール / スキル / エージェントの自動生成は避ける** — 人間が書く前提。自動生成は遵守率を下げる傾向がある（スキルの初期生成のみ `skill-creator` 等のツールで生成し、人間がレビュー編集する形は許容）
