# CLAUDE.md / AGENTS.md / CLAUDE.local.md 作成ルール

リポジトリルート直下のメモリーファイル（CLAUDE.md / AGENTS.md / CLAUDE.local.md）を編集する際の記法ルール。判断軸（どのレイヤーに書くか）は本ファイルでは扱わない。

## 1. サイズ

- 200行以下を目安とする
- 超えたら `.claude/rules/`（`paths` あり / なし）への分割を検討する
- `@import` 構文で子ファイルへ分けても合計トークンコストは減らない

## 2. 具体性

- 検証可能な具体的指示を書く
  - 良い例: 「2スペースインデントを使う」「コミット前に `npm test` を実行する」「APIハンドラは `src/api/handlers/` に置く」
  - 悪い例: 「コードを適切に整形する」「変更をテストする」「ファイルを整理する」
- コードから推論可能な情報は書かない（フレームワーク一般作法等）
- 静的チェックで強制できるものは `Hooks` に委譲する（フォーマッター、リント、テスト実行）

## 3. 構造

- Markdown見出しと箇条書きで構造化する
- 関連項目をグループ化する（密度の高い段落より、整理されたセクション）
- 各行に対して「この行がなければエージェントはどんな具体的なミスをするか」と問い、答えられないなら削除する

## 4. 矛盾の回避

- 2つのルールが矛盾する場合、エージェントは恣意的に選ぶ
- ネストしたCLAUDE.md / `.claude/rules/` も含めて定期的に矛盾を点検する

## 5. `/init` の使用

- 新規プロジェクトでは `/init` で雛形を生成する
- `/init` はコードベースを解析してビルドコマンド / テスト方法 / 規約を発見する
- 発見できない情報（人間しか知らない規約）は手で追記する

## 6. `@import` 構文

- `@path/to/file` で他ファイルを展開できる（相対 / 絶対パス両方可、最大5段）
- `@README` `@package.json` 等で既存ファイルを取り込む
- 取り込んだファイルは起動時にコンテキストへ展開される（遅延読み込みではない）

## 7. CLAUDE.local.md

- 個人的なローカル設定（サンドボックスURL / テストデータ等）
- `.gitignore` に登録する（`/init` の `personal` モードが自動で行う）
- 共有しない情報のみ。チーム共有規約はCLAUDE.md（AGENTS.md）側に書く

## 8. AGENTS.md と CLAUDE.md の関係

- Claude Codeは `CLAUDE.md` を読む（`AGENTS.md` ではない）
- Claude Codeと他のAIコーディングエージェントで共有したい場合はCLAUDE.mdから `@AGENTS.md` で取り込むかシンボリックリンクを張る
- 本リポでは `CLAUDE.md → AGENTS.md` のシンボリックリンク。実体は `AGENTS.md`

## 9. アンチパターン

- フォーマット / リント規則をCLAUDE.mdに書く（`Hooks` に委譲すべき）
- 一般的なフレームワーク作法を書く（コードから推論可能）
- 200行を大幅に超えても分割しない（遵守率が低下する）
- 抽象的指示（「適切に書く」「きれいに整理する」）
- LLMにCLAUDE.md自体を生成させる
