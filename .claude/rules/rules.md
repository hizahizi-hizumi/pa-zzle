# ルールファイル作成ルール

`.claude/rules/<name>.md` を新規作成・編集する際の記法ルール。判断軸（どのレイヤーに書くか）は本ファイルでは扱わない。

## 1. フロントマター

- `paths`（任意）— グロブ配列。指定時は該当ファイル編集時のみ読み込まれる
  - グロブ表記が公式仕様（`**/*.ts` / `src/**/*` / `dir/**/*.{ts,tsx}` 等）に従っている
  - 適用範囲は最小限にする（関係ない編集に読み込まれないようにする）
- `description` フィールドは付与しない（ルールに起動条件はない）
- `name` フィールドは付与しない（ファイル名がそのまま識別子）

## 2. 本文

- 必達項目を短い箇条書きで列挙する。段落主体の長文は避ける
- 判断軸（どこに書くか / どのレイヤーが適切か）を持ち込まない
- 採用する設計パターンを1つに決め打ちした記述をしない（例: 「ラッパースキルでは...」「レビュー系エージェントでは...」）。汎用的に書く
- 例示は最小限。冗長な修正前後の対比や事例集は持たない

## 3. 自己完結原則

- ルール本体で完結すべき規約・手順を `docs/` 配下や他ルールへ逃がさない
- ルールに複製すべきでない正本データ・仕様・語彙を利用する場合は、正本パスと読み込みが必要なタイミングを明示して参照してよい
- 参照先を読まないとルール自身の適用条件や実行手順を理解できない構成にしない
- ルールから他ルールへの依存リンクを作らない
- 1ファイルが膨らんだら `paths` の適用範囲を狭めて複数ルールに分割する

## 4. サイズ目安

- 200〜400行を目安。500行を超えたら分割を検討する

## 5. アンチパターン

- `paths` 未指定で常時投入されるが内容が限定的なケース（一部編集者にしか関係ないルールを全員に読ませる）
- ルール本体で定義すべき規約・手順を `docs/` に逃がし、「詳細は文書を参照」だけで済ませる
- 参照先の正本内容をルールに重複記載して二重管理する
- 1ファイルに複数の関心が混在（記法 + 判断軸 + 運用手順等）
- 公式ドキュメントのコピーやURL列挙
