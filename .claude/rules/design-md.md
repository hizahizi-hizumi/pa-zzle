# DESIGN.md の書き方

## 書く範囲

- 決まりは「どの意味・状態・場面のときに、どう見せ、どう反応させ、どう聞かせるか」の単位で書く
- 共通部品は、操作ボタン・選択肢・ゲームピクトグラムのように種類で呼ぶ
- 特定の画面・ゲーム・コンポーネント実装を名指しした決まりは書かない
- 何を表示するか・しないかの選択は書かない
- 決まりは、複数の画面・ゲームで同じ意味を持つと確かめたものだけを足す

## 構成

- Google Labs の DESIGN.md Format の8節に、次の `##` 節でこの順に従う。決まりの無い節は省く
- 節の見出しは次の語をそのまま使い、番号を付けない
  1. 概要: 人格、与えたい印象、表現の強さ。個別の決まりが無いときの判断の拠り所
  2. 色: 色の体系と、各トークンの役割・使い分け
  3. タイポグラフィ: 書体の使い分けと、文字階層の各段の役割
  4. レイアウト: 余白・密度・画面幅への対応
  5. 奥行き: 面・影・レイヤーによる前後関係の示し方
  6. 形: 角丸・境界による形の言語
  7. コンポーネント: 共通部品の種類ごとの指針
  8. すべきこと・避けること: どの節にも収まらない短い歯止め
- 8節に収まらないアプリ全体の決まり（操作と状態、動き、音など）は独自の `##` 節にし、「コンポーネント」と「すべきこと・避けること」の間に置く
- 1項目だけの `###` 節を作らない
- 複数の節に関わる決まりは、最も近い節に置く

## 用語

- 表現の強さの段階は、平常・操作・解く場面・達成と呼ぶ

## 値とトークン

- 正確な値（色値・数値・フォント名など）は書かない
- 値の正本 `frontend/styles/globals.css` の `@theme` への参照を、表題の直後、最初の `##` 節より前に1か所だけ置く
- YAML フロントマターとトークンのコードブロックは置かない
- トークン名を書く・変える前に `@theme` を読み、そこにあるトークンだけを書く
- トークン名は `@theme` の名前から先頭の `--` を除き、色のトークンは `--color-` も除いて書く

  ```
  OK:
  - `primary`（`--color-primary`）
  - `radius-sm`（`--radius-sm`）
  ```

- トークンは、名前と、そのトークンを使う意味・状態を言葉で定義した文で書く
- 意味と使い分けを決めないまま、トークンや段階の定義を足さない
- トークンの定義を足す・変える・消すときは、同じ変更で `@theme` も揃える
