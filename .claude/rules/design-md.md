# DESIGN.md 作成ルール

`DESIGN.md` を新規作成・編集する際の、書く範囲・構成・記法のルール。

## 1. 書く範囲

- アプリ全体で共有するデザインシステムだけを書く
- 特定の画面・ゲームを名指しした決まりを書かない。画面ごとの Why / Why not も書かない
- コード上のコンポーネント名・ファイル名を名指ししない。共通部品は種類（操作ボタン・入力・選択肢など）で呼ぶ
- 決まりは「どの意味・状態のときに、どう見せるか」の単位で書く。画面名で分けない
- 何を表示するか・しないかは書かない
- コードから読める What / How（配置、構成、寸法、使う部品）は書かない

## 2. 構成

- 正式フォーマット（Google Labs DESIGN.md Format）の8節に対応する次の `##` 節を、この順に置く。見出しはコロンの前の語をそのまま使い、番号は付けない。該当する決まりが無い節は省く
  1. 概要: 人格、与えたい印象。個別の決まりが無いときの判断の拠り所
  2. 色: 色の体系と各トークンの役割・使い分け
  3. タイポグラフィ: 書体の使い分け、文字階層の各段の役割
  4. レイアウト: 余白・間隔・密度・画面幅への対応の考え方
  5. 奥行き: 面・影・レイヤーによる前後関係の表し方
  6. 形: 形の言語、角丸・境界
  7. コンポーネント: 共通部品の種類ごとのスタイル指針
  8. すべきこと・避けること: 短い歯止め。他の節の言い直しにしない
- 8節に収まらないアプリ全体の決まり（操作状態、動き、効果音など）は独自の `##` 節にし、「コンポーネント」と「すべきこと・避けること」の間に置く。独自節は操作状態、動き、効果音の順に置き、それ以外はその後ろに置く
- `#` 見出しは表題だけに使う
- YAML front matter やトークンのコードブロックは置かない

## 3. 値とトークン

- 正確な値（色値・数値・フォント名など）は書かない
- 値の正本 `frontend/styles/globals.css` の `@theme` への参照は、表題の直後、最初の `##` 節より前に1か所だけ置く
- トークン名を書く・変える前に `@theme` を読み、そこにあるトークン名だけを使う
- 本文は、トークン名と、そのトークンを使う意味・状態を言葉で定義した文で書く
- DESIGN.md でトークンの定義を足す・変える・消すときは、同じ変更で `@theme` も揃える
- 意味と使い分けを決めないまま、トークンや段階の定義を足さない

## 4. 決まりを足すとき

- 一つの画面の要求を一般化して決まりにしない。複数の画面・ゲームで同じ意味を持つと確かめたものだけを足す
