# コードのコメント

- 処理が何をどうしているかは、コメントでなく、名前・型・データ構造・関数やモジュールの分割・制御フロー・設定の構造で表す
- 実装コメントには、コードだけでは表せない次のことだけを書く
  - その実装・制約・例外処理が要る理由
  - 外部のシステムや仕様に由来する、離れた箇所に及ぶ制約や特異な挙動
  - 型・契約・構造で表せない不変条件や前提
  - 意図して選んだ非自明なトレードオフ・回避策・互換性の理由
  - 複雑な処理の全体が何をしているかの要約（個々の手順は含めない）
- 単純にできそう・消せそうに見えるコードを意図して残すときは、残す理由をコメントに書く
- 実装コメントには、今も有効な制約だけを現在形で書く

  ```
  OK:
  // iOS Safari は pointercancel の後にも click を送る
  NG:
  // 以前は setTimeout で待っていたが playAnimations に置き換えた
  // 変更後は scripts/verify.sh を実行すること
  ```

- 公開APIのドキュメント文字列には、利用者に要る目的・契約・使用上の制約を書き、シグネチャ・型・実装の手順は書かない
