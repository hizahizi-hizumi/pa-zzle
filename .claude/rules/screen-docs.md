# 画面の文書の書き方

## 書く範囲

- 仕様に書かれていない場面でその画面を足す・変える・レビューするとき、作業者がプロダクトオーナーと同じ方向に判断できるようにすることだけを書く
- その画面の今の意図だけを書く
- 画面の仕様と、配置・構成・大きさ・動きの手順・表示項目の並びは書かない
- 何を表示するか・しないかは、遊ぶ人が知る価値があるかの判断と、その理由を書く
- 複数の画面で同じ意味を持つ見せ方の決まりは `DESIGN.md` に書く
- 画面の決まりは、その画面の文書にだけ書く
- 1文ごとに「この文が無ければ、作業者はこの画面でどんな判断を誤るか」に答えられるものだけを残す
- 意図のある決まりが一つも無い画面には、文書を作らない

## 構成

- 1つの画面を1つの文書にし、ファイル名を `SCR-nnn.md` にする
- フロントマターには `id` だけを置く
- 表題は画面名にする
- 表題の後に次の `##` 節をこの順に置く。決まりの無い節は省く
- 節の見出しは次の語をそのまま使い、番号を付けない
  1. 目的: 遊ぶ人がその画面で何を得るか
  2. 優先すること: その画面で何を強く見せ、何を退かせるかと、その理由
  3. やらないこと: 一般には良さそうに見えるが、その画面ではやらないことと、その理由

## 参照

- 要求・要件・仕様の決まりに触れるときは、言い直さずに ID で指す
- 別の画面に触れるときは、その画面の文書の表題で呼ぶ
