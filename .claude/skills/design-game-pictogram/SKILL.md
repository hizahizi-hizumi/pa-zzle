# design-game-pictogram

ゲーム一覧で対象ゲームを素早く識別でき、そのゲーム自身の姿を保ち、既存ピクトグラム群と並べても成立する高品質なピクトグラムを制作する Skill。

## 起動

`/design-game-pictogram`

対象ゲーム、表示サイズ、色数などの制約を引数または会話 context から受け取る。

## 目的と成果物

第一の目的は、人間が複数の十分に磨かれた候補を比較し、採用する方向性を判断できる状態を作り、その選択後に高品質な完成ピクトグラムへ仕上げることである。

大量生成は AI が最終案を決めるためではなく、人間へ提示する価値のある異なる方向を見つけるために使う。生成した粗案をそのまま提示せず、AI 側で明らかな弱点・重複を落とし、各方向を人間が公平に比較できる品質まで磨いてから提示する。

人間による方向選択の前は、異なる方向を代表する複数の SVG 候補、同じ実表示サイズ・同じ文脈で並べた比較表示、候補ごとの短い方向説明を成果物とする。

人間による方向選択の後は、選択された方向を仕上げた SVG ピクトグラムと `scripts/check_svg.py` の最終検査結果を成果物とする。

探索途中の大量候補、内部比較、試作 SVG は原則として一時ファイルに置く。人間へ提示する候補も、方向選択前は完成見本やプロダクション成果物として扱わない。

## 依頼別の入口

依頼内容に応じて開始位置を変える。

- **新規制作**: Step 1 から開始し、着眼点の探索から完成 SVG まで進める。
- **既存 SVG の改善**: 既存 SVG と利用条件を読み、Step 7 で問題を診断してから Step 8 以降で再探索・仕上げを行う。
- **レビュー / 検証のみ**: 対象 SVG を変更せず、Step 7 の実サイズ比較と Step 10 の機械検査を行い、`references/method.md` の評価軸に沿って findings を返す。変更は依頼された場合だけ行う。

## 参照する正本

制作開始時に次を確認する。

- `DESIGN.md` — ゲームを表す視覚表現と一覧での視覚的優先順位
- `references/method.md` — 探索とふるい分けで使う評価方法
- `examples/README.md` — レビュー済み完成見本と品質観点

評価軸の外部根拠が必要な場合だけ `references/research.md` を参照する。PoC の途中経緯が必要な場合だけ `docs/立ち上げ/ゲーム選択ピクトグラムPoC.md` を参照する。

## 動作原則

- 安い表現で広く探索し、有望な案だけ高コストな表現へ進める。
- 生成前に候補を厳密なスキーマへ押し込まず、生成後の選別と改善に構造化を使う。
- 初期探索では微差の完成度より着眼点の幅を優先する。
- AI の選別は「人間に見せる価値がある方向を残す」ところまでにする。最終方向を AI が勝手に一本化しない。
- 方向間の多様性を維持する。同じ発想の微差を複数提示して選択肢を水増ししない。
- 人間へ見せる前に、各候補を独立にブラッシュアップする。粗案と完成度の高い案を同じ比較に混ぜない。
- 候補間の完成度差が方向評価を歪めないよう、実表示サイズ、線、余白、光学的重量、機械制約の最低品質を揃える。
- 人間の選択は、候補全体だけでなく「A の構図 + C の要素」のような部分選択も受け付ける。
- 人間が明示的に選択を委任した場合を除き、方向提示後は選択を待ってから最終仕上げへ進む。
- 候補数そのものを達成条件にしない。異なる有力方向を比較できることを重視する。

## 動作フロー

### 1. 制作条件を確認する

対象ゲーム、実表示サイズ、SVG 制約、比較対象となる既存ピクトグラム群を確認する。未指定のブランド規則を勝手に追加しない。

### 2. 着眼点を大量生成する

SVG を作る前に「何を描くか」の候補を一文程度で大量生成する。数十案規模になってもよく、説明の丁寧さより着眼点の幅を優先する。

### 3. AI 側で粗くふるい分ける

`references/method.md` の「着眼点の選別」を使い、弱い案と重複案を落とす。一方向だけを勝者として残さず、人間が意味のある選択をできるよう異なる有望方向を維持する。

### 4. 有望方向を具体的な構図へ展開する

残した各方向から複数の構図案を生成する。主役、補助要素、配置、余白、具体性、省略内容などを振り、同じ方向の微差だけを増やさない。

### 5. 人間提示へ進める方向を選ぶ

`references/method.md` の「構図案の選別」を使い、SVG 化して磨く価値のある方向を複数残す。目的は最終案の決定ではなく、人間が方向性を比較できる候補集合を作ることである。

### 6. 各方向の SVG 試作を生成する

選んだ方向ごとに SVG を作る。必要なら一方向の内部で複数試作を作り、その方向を最もよく表す代表案を探す。この内部試作はまだ人間へ提示しない。

必要に応じて機械検査を行う。

```sh
python3 .claude/skills/design-game-pictogram/scripts/check_svg.py path/to/candidate.svg
```

### 7. 人間提示前に各候補をブラッシュアップする

各方向を独立に改善し、人間が方向そのものを比較できる品質まで引き上げる。

`references/method.md` の「人間提示前の品質条件」を使い、代表サイズと最小サイズで確認する。必要なら各方向の内部で再生成・分岐し、弱い内部試作を捨てて最も強い代表案を残す。

一候補だけを丁寧に仕上げ、他候補をラフなまま比較対象にしない。

### 8. 複数候補を人間へ提示する

ブラッシュアップ済み候補を同じ条件で並べ、代表サイズと最小サイズの両方を見せる。

```sh
python3 .claude/skills/design-game-pictogram/scripts/make_review_sheet.py \
  --output /tmp/pictogram-review.html \
  --size 112 \
  candidate-a.svg candidate-b.svg candidate-c.svg existing.svg
```

各候補には識別子と一行程度の方向説明を付ける。候補を順位付けして一案へ誘導せず、採用する方向、組み合わせたい部分、または再探索の要否を人間へ確認する。

人間が明示的に選択を委任していない限り、ここで最終 SVG を確定しない。

### 9. 選択された方向を仕上げる

人間が選んだ方向、または選んだ要素の組み合わせを起点に、線幅、要素間隔、余白、黒量、視覚階層、光学中心、最小サイズでの可読性を詰める。

部分採用を指定された場合は、その意図を新しい一案へ統合して実サイズ比較を再実行する。

### 10. 最終 SVG を検査する

採用する SVG に対して `scripts/check_svg.py` を実行する。機械検査を意味の分かりやすさ、魅力、光学的重量の自動判定として扱わない。

## 完成条件

新規制作では、人間による方向選択を経て `references/method.md` の最終収束条件を満たし、採用 SVG が最終機械検査を通ることを完了条件とする。

人間へ方向候補を提示した時点は中間成果であり、明示的に選択を委任されていない限り完成扱いにしない。

レビュー / 検証のみの依頼では、対象を変更せず評価結果と機械検査結果を返した時点を完了とする。

## 制約

- `DESIGN.md` をこの Skill の成果物として変更しない
- ゲーム本体コンポーネントの縮小・再利用を目的にしない
- ゲーム固有図形の無理な共通コンポーネント化をしない
- 生成案を構造化すること自体を目的にしない
- 大量生成した候補を保存すること自体を目的にしない
- 機械検査で視覚評価を代替したと主張しない
- SVG 内に実装履歴や PoC 経緯をコメントとして残さない
