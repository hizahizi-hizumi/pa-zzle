# ゲーム選択用ピクトグラムの探索・評価方法

この文書は `/design-game-pictogram` で候補を探索・選別・改善するときの判断方法を定義する。特定ゲームの正解形状や、固定された制作順序は定義しない。

## 1. 目的

ゲーム選択用ピクトグラムの目的は、ゲーム一覧で対象ゲームを素早く識別でき、そのゲーム自身の姿を保ちながら、一覧内で魅力的な視覚表現として成立することである。

制作時の大量生成は、人間が複数の十分に磨かれた方向を比較して選択するための探索手段として使う。AI が大量生成から一案を自動選出して完成扱いすることは目的にしない。

実ゲーム盤面を忠実に縮小すること、一般的な UI 操作アイコンへ還元すること、ブランド装飾を追加すること、制作工程を再現することも目的ではない。

## 2. 探索の原則

### 2.1 安い表現から高い表現へ進む

探索では、候補一つあたりの制作コストが低い段階ほど広く発散する。

代表的な順序は次の通り。

1. 一文程度の着眼点を大量生成
2. 有望方向を具体的な構図へ展開
3. 人間提示候補となる方向を複数選択
4. 各方向の SVG を生成
5. 各候補を人間提示可能な品質まで個別に改善
6. 人間が方向を選択
7. 選択方向を最終仕上げ

早い段階で大量に捨てられるよう、SVG にする前に「何を描くか」「どう見せるか」を十分探索する。

### 2.2 生成と評価を分ける

初期生成では発想の幅を優先し、生成後のふるい分けで評価軸を使う。視覚語彙や評価軸を、全候補へ必須記入する構造化スキーマとして使わない。

### 2.3 大量生成の目的を人間の選択に置く

大量生成は候補数を増やすこと自体が目的ではない。人間が比較する価値のある、意味の異なる方向を見つけるために行う。

AI の粗選別では、明らかに弱い案を落とし、重複案をまとめ、同じ方向の中でより強い代表案を探し、異なる有望方向を残す。異なる方向を横断して最終勝者を決めない。

### 2.4 人間提示前に品質を揃える

人間はラフさの差ではなく方向性の差を比較できる必要がある。

候補を提示する前に、各方向について独立に再生成・局所修正・光学補正を行う。一案だけ仕上げ、他案を粗い状態で並べることを避ける。

候補ごとの制作回数を同じにする必要はない。必要な改善量が違っても、提示時の品質水準を揃える。

### 2.5 多様性を人間選択まで維持する

初期の完成度だけで一方向へ絞らない。同じ方向の類似案は内部でまとめつつ、異なる有望方向を人間提示まで維持する。

人間が方向を選んだ後は、その選択を探索範囲の境界として使い、選択方向の中で仕上げる。

## 3. 視覚語彙

視覚語彙は候補生成の発想材料や、良案を分析するための診断語彙として使う。

- **対象**: ゲーム内で見る物体
- **構造**: 対象同士の空間関係や盤面構造
- **状態・記号**: 数字、液体、向き、空きなど識別に必要な状態
- **関係・動作**: 移動、積層、流入など、静止画でも重要な関係

列挙した全てを描かない。意味的距離を縮め、弁別性を上げるものだけを使う。

視覚語彙を最初に完全列挙することや、各候補をこの4分類へ必ず分解することは要求しない。

### 最小構成

最小構成は「要素数が最少」ではなく、次の両方を満たすために必要な視覚情報が過不足なく残っている状態を指す。

1. 対象ゲームへの意味的距離が十分近い
2. 他ゲームのピクトグラムと区別できる

役割の異なる特徴を組み合わせると、同種の細部を増やすより少ない情報量で識別できる場合がある。

例:

- ウォーターソート: 容器という対象 + 水という状態
- ナンプレ: 格子という構造 + 数字という記号

この組み合わせは PoC で得た例であり、固定テンプレートではない。

## 4. 評価軸

### 意味的距離

ピクトグラムの見た目と、表したいゲーム概念との隔たり。

確認:

- ゲーム名を隠したとき、対象ゲームまたは十分近いゲーム類型へ結びつくか
- 汎用的な「水」「格子」「車」だけで止まっていないか
- 追加した細部がゲーム識別に寄与しているか

ゲーム名を完全に当てられること自体を絶対条件にはしない。診断では、何を表しているか理解不能な状態や、別ゲームへ強く誤認される状態を問題として扱う。

### 構成要素の知覚可能性

描いた各要素が、意図した物体または形として認識できるか。

確認:

- 数字が格子線に埋もれていないか
- 容器と水が別要素として読めるか
- 小サイズで隙間や境界が潰れていないか

### 視覚複雑性

認識のために処理しなければならない線、面、記号、状態の量。

確認:

- 問題状態の再現にしか使わない情報を持っていないか
- 同じ意味の情報を過剰に繰り返していないか
- 色や濃淡を増やす前に余白と配置で分離できないか

単純化自体を目的にしない。情報を減らして意味的距離や弁別性が悪化するなら戻す。

### 具体性

現実の対象またはゲーム中に見る対象との形状的な近さ。

抽象化自体を目的にしない。具体性を下げて対象ゲームとの結びつきが弱くなるなら戻す。

### 弁別性

一覧中の他ゲームと見分けられるか。

単体表示だけで判断せず、既存ピクトグラム群と同じサイズ・条件で比較する。

### 光学的重量

見た目としての強さ。面積、線幅、黒量、密度、余白、形状によって決まる。

数値上同じサイズや線幅でも揃うとは限らない。

確認:

- 一つだけ大きく、濃く、細かく見えないか
- 識別に必要な副要素が主構造に負けていないか
- 幾何学的中央より見た目として偏っていないか

### 実表示サイズでの成立

代表サイズと最小サイズで、識別に必要な情報が維持されるか。

拡大表示でだけ成立する細部や、縮小時に一塊になる隙間は、実利用では存在しないものとして扱う。

## 5. 段階ごとのふるい分け

### 着眼点の選別

この段階では造形品質を評価しない。ゲーム固有性がない、汎用記号だけ、小さな一枚絵へ変換しにくい、説明文依存、盤面全体の縮小コピー前提など、明確な弱点で落とす。

残った候補は、同じ方向をまとめながら異なる着眼点を維持する。

### 構図案の選別

SVG 化する前に、主に意味的距離、視覚複雑性、具体性、弁別性、実表示サイズへ縮小できる見込みを見る。

明確な欠点のある案を先に落とす。ただし目的は最終順位を決めることではなく、人間へ見せる価値のある異なる方向を残すことである。

### 人間提示前の品質条件

各方向の SVG は、人間へ提示する前に少なくとも次を満たす。

- 代表サイズと最小サイズで主要要素が知覚できる
- 方向固有の意図が SVG 上で実現できている
- 明らかな線幅・間隔・配置の破綻がない
- 既存ピクトグラム群と比べて光学的重量が極端に外れない
- その方向のまま直せる既知の大きな弱点が残っていない
- SVG の構文・色数・外部依存等の制約を満たす

候補間で完全に同じ線幅や情報量にする必要はない。比較時に「粗いから弱く見える」状態をなくす。

### 人間による方向選択

ブラッシュアップ済み候補を同じ表示条件で並べる。

人間には、一つの候補方向を採用、複数候補の部分を組み合わせる、どの方向も採用せず再探索する、のいずれも選べる形で提示する。

AI は候補の問題点や違いを説明してよいが、明示的に委任されない限り最終方向を代わりに決めない。

## 6. 候補の内部改善と選択後の再探索

### 人間提示前

各方向の内部では複数案を作ってよい。

利用できる方法:

1. **全体発展**: 主題を保ち、配置・具体度・余白などを振る
2. **誇張**: 方向の特徴をさらに強める
3. **削減**: 主題を維持したまま副要素や状態を減らす
4. **局所修正**: 線幅・位置・余白など明確な問題を直す

ここでの目的は、方向間を一本化することではなく、各方向の代表候補を強くすることである。

### 人間選択後

人間が選んだ候補や部分要素を起点に、必要なら部分採用、合成、選択方向内での派生を行う。

構造化は、人間が選んだ意図を理解して仕上げへつなげるために使う。

## 7. 局所修正と分岐探索

原因と直し方が明確なら局所修正する。

例:

- 数字が格子線に負ける → 線幅や大きさを調整する
- 外形が右へ重く見える → 光学中心を補正する
- 隙間が小サイズで潰れる → 間隔または要素数を調整する

直し方が複数考えられる場合、またはさらに上振れを狙える場合は分岐して複数案を比較する。

局所修正で変更理由を追えることは有用だが、判断記録を残すこと自体を目的にしない。

## 8. 機械化する範囲

スクリプトで判定してよいもの:

- SVG として解析可能か
- `viewBox` の有無
- 色指定の種類数
- gradient / filter / 外部画像等の使用
- `<text>` 使用の有無
- 比較用 HTML の同一サイズ配置

人間または視覚モデルで確認するもの:

- 意味的距離
- 構成要素を正しく知覚できるか
- 視覚複雑性
- 具体性
- 光学的重量
- 一覧内での弁別性
- 実表示サイズでの成立
- 候補の魅力
- 候補間の部分比較と合成判断

機械検査の PASS をデザイン品質の PASS と同一視しない。

## 9. 収束条件

### 人間提示前

次を満たした候補群を作った時点で、人間へ方向選択を依頼する。

- 複数の候補が実質的に異なる方向を表している
- 各候補が「人間提示前の品質条件」を満たす
- 一候補だけが仕上がって見えるような品質差がない
- 既存ゲーム群と同条件で比較できる

この時点では制作完了としない。

### 最終完成

人間が方向を選んだ後、次を満たすまで仕上げる。

- 対象ゲームへの意味的距離が十分近い
- 必要な構成要素が実サイズで知覚できる
- 既存ゲーム群と弁別できる
- 一覧内で光学的重量が突出しない
- 盤面の縮小コピーや汎用アイコンへ逃げていない
- 人間が選んだ方向・要素が最終形に反映されている
- 与えられた色数・線・SVG 制約を満たす
- 直近の比較で重大な問題ではなく微調整だけが残っている

探索過程の全候補や全判断を永続化する必要はなく、完成物と必要な判断だけを残す。
