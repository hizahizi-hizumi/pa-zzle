# ゲーム選択用ピクトグラムの探索・評価方法

この文書は `/design-game-pictogram` で候補を探索・選別・改善するときの判断方法を定義する。特定ゲームの正解形状や、固定された制作順序は定義しない。

## 1. 目的

ゲーム選択用ピクトグラムの目的は、ゲーム一覧で対象ゲームを素早く識別でき、そのゲーム自身の姿を保ちながら、一覧内で魅力的な視覚表現として成立することである。

実ゲーム盤面を忠実に縮小すること、一般的な UI 操作アイコンへ還元すること、ブランド装飾を追加すること、制作工程を再現することは目的ではない。

評価方法と探索手順は、高品質な完成物へ到達するための手段として扱う。

## 2. 探索の原則

### 2.1 安い表現から高い表現へ進む

探索では、候補一つあたりの制作コストが低い段階ほど広く発散する。

代表的な順序は次の通り。

1. 一文程度の着眼点
2. 具体的な構図案
3. SVG 試作
4. 有望 SVG の派生
5. 最終仕上げ

早い段階で大量に捨てられるよう、SVG にする前に「何を描くか」「どう見せるか」を十分探索する。

### 2.2 生成と評価を分ける

生成中から全評価軸を満たそうとすると、似た無難な案へ収束しやすい。

初期生成では発想の幅を優先し、生成後のふるい分けで評価軸を使う。視覚語彙や評価軸を、全候補へ必須記入する構造化スキーマとして使わない。

### 2.3 候補数ではなく探索幅を見る

候補数を固定しない。初期探索は数十案規模になってもよい。

次の状態を次段階へ進む目安とする。

- 新しい着眼点がほとんど出なくなった
- 有望方向が複数見つかった
- 追加生成しても既存方向の微差ばかりになった

「規定数を生成した」こと自体を成果としない。

### 2.4 多様性を残してから収束する

初期の完成度だけで一方向へ絞らない。同じ方向の類似案はまとめつつ、異なる有望方向を複数残す。

類似案の小さな差が認識性や光学的重量を大きく変える可能性がある場合は、別候補として残して比較する。

## 3. 視覚語彙

視覚語彙は候補生成の発想材料や、良案を分析するための診断語彙として使う。

- **対象**: ゲーム内で見る物体
- **構造**: 対象同士の空間関係や盤面構造
- **状態・記号**: 数字、液体、向き、空きなど識別に必要な状態
- **関係・動作**: 移動、積層、流入など、静止画でも重要な関係

列挙した全てを描かない。意味的距離を縮め、弁別性を上げるものだけを使う。

視覚語彙を最初に完全列挙することや、各候補をこの4分類へ必ず分解することは要求しない。

### 最小構成

最小構成は「要素数が最少」ではなく、次の両方を満たすために必要な視覚情報が過不足なく残っている状態を指す。

1. 対象ゲームへの意味的距離が十分近い
2. 他ゲームのピクトグラムと区別できる

役割の異なる特徴を組み合わせると、同種の細部を増やすより少ない情報量で識別できる場合がある。

例:

- ウォーターソート: 容器という対象 + 水という状態
- ナンプレ: 格子という構造 + 数字という記号

この組み合わせは PoC で得た例であり、固定テンプレートではない。

## 4. 評価軸

### 意味的距離

ピクトグラムの見た目と、表したいゲーム概念との隔たり。

確認:

- ゲーム名を隠したとき、対象ゲームまたは十分近いゲーム類型へ結びつくか
- 汎用的な「水」「格子」「車」だけで止まっていないか
- 追加した細部がゲーム識別に寄与しているか

ゲーム名を完全に当てられること自体を絶対条件にはしない。診断では、何を表しているか理解不能な状態や、別ゲームへ強く誤認される状態を問題として扱う。

### 構成要素の知覚可能性

描いた各要素が、意図した物体または形として認識できるか。

確認:

- 数字が格子線に埋もれていないか
- 容器と水が別要素として読めるか
- 小サイズで隙間や境界が潰れていないか

### 視覚複雑性

認識のために処理しなければならない線、面、記号、状態の量。

確認:

- 問題状態の再現にしか使わない情報を持っていないか
- 同じ意味の情報を過剰に繰り返していないか
- 色や濃淡を増やす前に余白と配置で分離できないか

単純化自体を目的にしない。情報を減らして意味的距離や弁別性が悪化するなら戻す。

### 具体性

現実の対象またはゲーム中に見る対象との形状的な近さ。

抽象化自体を目的にしない。具体性を下げて対象ゲームとの結びつきが弱くなるなら戻す。

### 弁別性

一覧中の他ゲームと見分けられるか。

単体表示だけで判断せず、既存ピクトグラム群と同じサイズ・条件で比較する。

### 光学的重量

見た目としての強さ。面積、線幅、黒量、密度、余白、形状によって決まる。

数値上同じサイズや線幅でも揃うとは限らない。

確認:

- 一つだけ大きく、濃く、細かく見えないか
- 識別に必要な副要素が主構造に負けていないか
- 幾何学的中央より見た目として偏っていないか

### 実表示サイズでの成立

代表サイズと最小サイズで、識別に必要な情報が維持されるか。

拡大表示でだけ成立する細部や、縮小時に一塊になる隙間は、実利用では存在しないものとして扱う。

## 5. 段階ごとのふるい分け

### 着眼点の選別

この段階では造形品質を評価しない。主に次の明確な弱点で落とす。

- ゲーム固有性がない
- 汎用記号だけで成立させようとしている
- 小さな一枚絵へ変換しにくい
- 説明文を前提にしないと意味が成立しない
- 盤面全体の縮小コピーを前提にしている

残った候補は、同じ方向をまとめながら異なる着眼点を維持する。

### 構図案の選別

SVG 化する前に、主に次を見る。

- 意味的距離
- 視覚複雑性
- 具体性
- 弁別性
- 実表示サイズへ縮小できる見込み

明確な欠点のある案を先に落とし、残った案を相対比較する。

### SVG 試作の選別

実物になって初めて分かる次の問題を重く見る。

- 構成要素の知覚可能性
- 実表示サイズでの成立
- 光学的重量
- 既存ピクトグラム群との弁別性
- 一覧全体で見たときの魅力と静けさ

文章段階で評価が高かった案でも、実物で弱ければ捨てる。

### 最終候補の選別

全評価軸と SVG 制約を確認する。

数値採点の合計で自動的に採用案を決めない。評価軸は問題を特定し、候補同士の違いを説明するために使う。

## 6. 良案からの再探索

SVG 試作から有望案が見つかったら、最初の案をそのまま磨くだけでなく、良い要素を起点にもう一度候補を生成する。

利用できる方法:

1. **全体発展**: 良案の主題を保ち、配置・具体度・余白などを大きく振る
2. **部分採用**: A の外形、B の余白、C の記号配置など、強い部分を取り出す
3. **合成**: 複数候補の強い部分を新しい一案として再構成する
4. **誇張**: 良さの原因と思われる特徴をさらに強める
5. **削減**: 良さを維持したまま副要素や状態を減らす

この段階で「なぜ良いか」を分析する。構造化は、良い偶然を理解して次の探索へつなげるために使う。

合成や派生で複数要因を同時に変えてよい。探索を一変数ずつの実験へ限定しない。

## 7. 局所修正と分岐探索

原因と直し方が明確なら局所修正する。

例:

- 数字が格子線に負ける → 線幅や大きさを調整する
- 外形が右へ重く見える → 光学中心を補正する
- 隙間が小サイズで潰れる → 間隔または要素数を調整する

直し方が複数考えられる場合、またはさらに上振れを狙える場合は分岐して複数案を比較する。

局所修正で変更理由を追えることは有用だが、判断記録を残すこと自体を目的にしない。

## 8. 機械化する範囲

スクリプトで判定してよいもの:

- SVG として解析可能か
- `viewBox` の有無
- 色指定の種類数
- gradient / filter / 外部画像等の使用
- `<text>` 使用の有無
- 比較用 HTML の同一サイズ配置

人間または視覚モデルで確認するもの:

- 意味的距離
- 構成要素を正しく知覚できるか
- 視覚複雑性
- 具体性
- 光学的重量
- 一覧内での弁別性
- 実表示サイズでの成立
- 候補の魅力
- 候補間の部分比較と合成判断

機械検査の PASS をデザイン品質の PASS と同一視しない。

## 9. 収束条件

候補を多く作ったことや、同じ工程を再現できたことを完了条件にしない。

次を満たすまで、必要に応じて生成・選別・再探索・局所修正を繰り返す。

- 対象ゲームへの意味的距離が十分近い
- 必要な構成要素が実サイズで知覚できる
- 既存ゲーム群と弁別できる
- 一覧内で光学的重量が突出しない
- 盤面の縮小コピーや汎用アイコンへ逃げていない
- 与えられた色数・線・SVG 制約を満たす
- 直近の比較で重大な問題ではなく微調整だけが残っている

最終判断に視覚評価が含まれることを許容する。探索過程の全候補や全判断を永続化する必要はなく、完成物と必要な判断だけを残す。
