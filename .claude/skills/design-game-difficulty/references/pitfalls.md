# 難易度の失敗パターン

過去のパズル追加・作り直しで、人間に指摘されてから直したもののうち、難易度と問題の質に関わるもの。各行は「兆候 → 予防（流れの番号と検査の ID）」。流れは SKILL.md、検査は `checks.md`。

`/add-puzzle` の自己点検役に渡すときは、「人間の判断の巻き戻し」「版の波及漏れ」「1人の記録への過適合」の3行は「いつ」を「全項目」として扱い、ほかの行は「いつ」を difficulty・problem-pool として扱う。

## 面白さ・問題の質

| パターン | 兆候 | 予防（流れ・検査） |
|---|---|---|
| 核の天井が低い | 最上位でも数秒で解ける。盤面全体を見渡せる | 流れ 6: D1・D2。天井を受け入れるなら資料と報告の「人間に残す」に書く |
| 罰で難しくする | 穴・即死・50/50 の推測で失敗率を上げている | 流れ 2: 追加要素を「先読みを要求するか、罰を増やすか」で分け、罰の側は挑戦に入れない |
| 生成器の偏り | 生成条件がレベルごとに1つの値に張り付く。一意化の操作で易しい盤ばかりになる | 流れ 4・6: E2。生成条件を巡回して採る |
| 素朴な解き方が戻らない | いつでも打てる手があるパズル（塗る・消すなど）で、試し置きして戻す解き方の戻した回数が0になり、上限まで進むだけになる | 流れ 3・6: D1 の「実装」（合法手と行き詰まりの扱い）に従って書き、戻した回数を見る |
| 移植で供給が黙って変わる | 調査コード（Python 等）からの移植で、解の数は一致するが探索の打ち切り（節点数の上限など）に関わる量が違い、問題の採否や分布が変わる | 流れ 3・4: F2。結果だけでなく、採否を決める量（節点数・試行回数）の一致もテストで固定する |
| 自明・重複・単調の混入 | 回転反転の重複、角始点の蛇行、同じ形の繰り返し | 流れ 6: E3。正規化キーと解手順の指紋で重複0、自明の下限、単調さの代理 |
| 推論の種類の偏り | 上位の推論が1つの手筋や「仮置きの回数」だけ | 流れ 6: B5。偏りが残るなら資料に書く |
| 解き順・視点への依存 | 手筋の適用順や同点の扱いで帯が動く。UI の進め方だと深い読みが要る | 流れ 3・6: A3 |
| 同値解で難易度が再現しない | 解の道筋ごとに帯が2段以上揺れる | 流れ 1・3: 一意解を採るかを前提で決め、許すなら道筋に依存しない特徴を先に作る。A3 |

## 難易度

| パターン | 兆候 | 予防（流れ・検査） |
|---|---|---|
| 最上位が試行錯誤で押し切られる | 一致・違反・正誤の即時表示がある。解法器のレベルは高いのに手数・時間の代理が短い。「レベル5でも簡単すぎる」 | 流れ 1・3・6: 合意した補助表示のもとで素朴な解き方（1手ずつの試し置き等）を当て（D1）、上位は押し切れない問題に限る |
| 1つのつまみだけ | レベルごとの基準表の列が1つ。レベルの説明が「〜が多い」の言い換えだけ。特徴どうしの相関が高い | 流れ 2・3: 2〜3系統のつまみを出し、B4 で系統間の相関を測る。利用者向けの一言を各レベルで言えるか |
| 規模の扱いを誤る | 「規模は難易度ではない」を理由に全レベル同じ盤面にする／逆にレベル＝盤面サイズになる | 流れ 1: 規模をつまみに使うかを前提で決める。流れ 6: B2 で同じ規模にそろえた隣接レベルの分かれ方と、規模とレベルの相関を両方出す |
| 盤面の逆転 | 上位ほど盤面が小さい。同じレベルで広い盤面ほど早く解ける | 流れ 5・6: C2。密度をそろえ、逆転なしをテストで固定する。プレビューにも波及する（`ripple.md` 段 6） |
| 解法器の量と人の手応えがずれる | 連鎖の深さなど解法器の量はレベルごとにきれいに上がるのに、試遊で「レベル1と3が同じ」「3の方が楽」。1本ずつの読みやすさ（例: 1つの塊だけの行・列の割合）がレベル間で大きく重なる | 流れ 6・7: B3 で人が1か所ずつ読むときの負担の量もレベルごとに分布を並べ、隣接レベルの重なりを見る。各レベルを試遊で遊ぶ |
| 図柄の規則が近道になる | 左右対称などの規則で作った問題を、規則を仮定して推論を飛ばして解ける。同じレベルで規則の有無により所要時間が数倍違う | 流れ 4・6: D3。上位では規則のある作り方を除くか、規則を仮定した解き方で押し切れる割合を測る |
| 帯の中のばらつき | 「これほんまに同じ難易度？」。最上位に上限が無い | 流れ 5・6: C1・C3。帯内の分布と最弱の問題を出す。入口の広さ（初手で確定できる箇所数）を特徴に入れる |
| 解法器が緩い・深すぎる | 上位が多すぎ／少なすぎ。手で追うと浅く解ける | 流れ 6: F1。代表問題を手で追って確かめる。既知の解を落とさないテスト |
| 状態の混同 | 評価不能を5へ、軽すぎを1へ押し込む | 流れ 5・6: A1。評価の状態を分けて返す |
| 分位点で閾値を決める | 閾値が三分位・五分位・平均。「境界を変えたら合った」 | 流れ 5・8: 境界の置き方は `難易度開発手順.md` の工程7、ずれの原因の探し方は工程10 に従う |
| 人間の判断の巻き戻し | 再校正で、人間が入れると決めたつまみを外す | SKILL.md の守ること 4 |
| 版の波及漏れ | 問題集を作り直したのに基準時間・プレビュー・SPEC が古い | 流れ 9: `ripple.md` を上から通し、段ごとに通したかを報告に書く |
| 1人の記録への過適合 | 校正の根拠が1人・1レベル・慣れた再プレイ | `recalibration.md` の 5: 件数と人数と限界を書き、全レベルを同じ根拠で動かさない |
