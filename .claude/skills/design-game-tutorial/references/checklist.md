# チュートリアル見直しチェックリスト

2段に分ける。「原則」は1つでも満たさなければ重大な問題として直す。「細部」は見つけたらまとめて直すが、これだけを理由にレビューをやり直さない。確かめていない項目は「確かめていない」と報告に書く。

## 原則（重大）

SKILL.md「1. 原則」と同じ6つ。各原則の下の確認点は、その原則を満たしているかを見る観点の例で、網羅ではない。原則に照らして問題があれば、確認点に無くても重大として扱う。

### P1. 始まった時点で、何をするパズルか・ゴール・始まりの盤面が分かる

- [ ] パズルを知らない人が、入口の目的の一文と完成した盤面だけで「何を目指すか」を言える
- [ ] 手順1に入るまでに、目的・ゴール・始まりの盤面を、絵と言葉の両方で一度ずつ見せている

### P2. ルールは言い切ってから、すぐその盤面で使わせる

- [ ] 各ルールを言い切る一言があり、その直後の手がそのルールで決まる
- [ ] （作り手）盤面の条件（SKILL.md「4. 盤面の条件」）を探索とテストで確かめた
- [ ] 知っているルールだけで考えて置く手がある

### P3. 人が横で教えるような、自然で1つにそろった言葉で話す

- [ ] 全文を声に出して読んで、直訳調・意味の曖昧な言い方・不自然な言い回しがない
- [ ] 評価・クイズ口調・指図・中身のない一文がない
- [ ] 動詞と呼び名が、チュートリアル・チップ・違反の一言・遊び方ダイアログで1つにそろっている

### P4. 画面の反応が、言葉で教えたことと食い違わない

- [ ] どの操作をしても、そのときの一言と盤面の反応が矛盾しない（教えたとおりに動くはずの操作が無反応、前の一言が残る、後の手順で覆る言い切り、などがない）
- [ ] 間違えたときは、何が起きたかと当たったルールが分かる

### P5. 本番へ正直につなぐ

- [ ] 完成した盤面と完成後の画面がご褒美として見え、押せない盤面のように見えない
- [ ] 完成時の一言が本番の難しさを約束しすぎず、開いた場所（難易度選択・プレイ中）に合っている

### P6. 誰でも同じ体験にたどり着け、プレイを邪魔しない

- [ ] 動きを減らす設定でも、P1 の目的・ゴール・始まりが伝わる
- [ ] 入口の演出はいつでも飛ばせ、飛ばした操作で盤面が変わらない
- [ ] プレイ中から開いて閉じても経過時間が進み続け、チュートリアルのプレイは記録・採点されない

## 細部（まとめて直す。10項目以内）

- [ ] 見出しが375px幅で1行に収まり、2行になる文は意味の切れ目で折り返る
- [ ] 要素どうしが重ならず、画面の端に詰まっていない
- [ ] 一言欄の高さが固定され、文言の長さで盤面が動かない
- [ ] 演出に跳び・ちらつき・何も動かない長い間がなく、動きの値はトークンか名前付き定数になっている
- [ ] 途中で一瞬だけルールに合わない状態を通るゲームでは、違反への反応を少し遅らせて画面を揺らさない
- [ ] 「もう一度」では、すでに見せた名前・目的・ゴールを省いている
- [ ] 今のルールのチップは、示した手順でだけ目立たせている
- [ ] 途中経過を示す見た目は、完成時には外している

## 実画面での確認（作り手の手順）

- [ ] 幅375pxで最初から完成まで1手ずつ進め、全手順のスクリーンショットを自分で見た
- [ ] わざと間違えた、止まってヒントを出した、演出を飛ばした、動きを減らす設定で開いた、プレイ中から開いて閉じた
- [ ] 入口・完成・「もう一度」の演出を約150msごとのコマで並べて見た
- [ ] ブラウザのエラーが0件
- [ ] `bun run --cwd frontend check`、`typecheck`、`test` が通る
