# design-game-tutorial

パズルを知らない人が、小さな盤面を実際に操作してルールと操作を身につけ、そのパズルを遊びたくなるチュートリアルを設計・実装・見直す Skill。

## 起動

`/design-game-tutorial`

引数 `$ARGUMENTS` を対象ゲームとして扱う。引数が無ければ会話 context から対象ゲームを決める。既存チュートリアルの見直しだけを頼まれた場合は「8. 見直し」から始める。

## 1. 目的と範囲

- **対象**: そのパズルを知らない人、ルールがうろ覚えの人。自分で開いた人だけ（自動では始めない）。
- **終わったときの状態**: ルールと操作が分かり、レベル1〜2を自分で始めて楽しめる。主目的は「遊んでみたくなる」ことで、ルールが分かることはその前提条件。
- **扱う範囲**: 基本ルールまで。基本ルールとテクニックの線引きはパズルごとに判断する。ルールそのものと、その直接の帰結（ルールを盤面に当てはめるだけで決まる読み）は基本に入れる。仮定を重ねる読みなど上位レベルで要る読みは、別機能のテクニック集に回す。
- **遊び方ダイアログとの分担**: ダイアログは知っている人が数秒で確認する場所。チュートリアルは知らない人が操作して1〜2分で体験する場所。
- 判断に迷ったら `APP.md` の最上位の体験軸（面白い・楽しい・ワクワク）と `GAME.md` を優先する。

## 2. 体験の型

1枚の本物の盤面を、最初から最後まで使う（複数の小盤面を渡り歩かない）。次の順に進める。

1. **入口の演出**: パズルの名前とピクトグラムを中央に大きく出す → 完成した盤面を本番と同じ完成演出で見せる（ゴールの提示）→ プレイヤーが置くマスを消して最初の盤面に戻す → 名前を上部の見出しへ移す。飛ばし方などの扱いは「5. 操作・反応・演出」に従う。
2. **ゴールと操作**: 「何を目指すパズルか」を一文で言い、1マス目を実際に操作させる。操作の種類ごとに1手ずつ。
3. **ルールを1つずつ**: ルールを言い切り、そのルールで決まる1マスをすぐ置かせる。ルールのチップはその手順で現れ、そのときだけ輪郭で目立たせる。
4. **知っているルールだけで推理**: 新しいルールを足さずに1マス以上置かせる。
5. **ヒントの知らせ**: 迷ったら少し待つと印が出ることを伝える。
6. **自由に完成**: 残りを自分で埋めさせ、本番と同じ完成演出で締める。
7. **本番へ**: 「レベル1を遊ぶ」へつなぐ（プレイ中から開いた場合は「プレイに戻る」）。「もう一度」も置く。

## 3. 盤面の条件

盤面と手順は次をすべて満たす。満たすかどうかは推測せず、総当たり探索と単体テストで確かめる。

- **最初の配置だけで解が1つに決まる**: 操作の練習で置かせる手を、解を決めるために使わない。
- **各手順の印のマスは、その時点で示したルールだけで決まる**: ルールを示す手順の印のマスは、そのルールで決まり、それまでのルールでは決まらない。
- **プレイヤーが置いた手が後の根拠になる**: 操作の練習で置いたマスが、次のルールの説明の決め手に使われると、手順が一本の流れになる。
- **自由に埋める残りは、ルールで1マスずつ解き切れる**。
- **間違いに手応えがある**: 1マスでは違う方を置いても違反にならない手順は、2マスに印を付けるなどして違反が起きる形にする。
- **比較の相手が見つけやすい**: 別の行・列と見比べるルールは、真上や隣など相手が近い配置にし、一言で相手を示す。
- 条件を満たす盤面は「存在しない」という結論を、自分で探索せずに受け入れない。

## 4. 文言

- **口調**: 短く言い切る、柔らかいですます調。プレイヤーと一緒に盤面を埋めていく距離感にする。
- **書かないもの**:
  - 評価や褒め言葉（「そう。」「その調子」「解けた！」）。上から目線に感じられる。
  - クイズ口調の問いかけ（「入るのは？」）。先生と生徒の関係になる。
  - 促し・指図（「〜しよう」「見よう」）。お願いが要る操作だけ「〜してください」。
  - 中身のない一文（「ここからは、ルールに合うように埋めます」）。
  - 無機質な体言止めだけの文。
- **見出しは375px幅で1行**に収める。収まらなければ言い換えて縮める。
- **呼び方を遊び方ダイアログとそろえる**（例: 「四角」「丸」）。
- **違反の一言**: 何が起きたか（「上の行と同じ並びになっています」）と、当たったルールを言う。直前に置いたマスが関わる違反を優先する。
- 書いたら、知らない人の目と、上から目線・無機質に敏感な人の目で全文を読み直す。

## 5. 操作・反応・演出

- **誘導中は印のマスだけ受け付ける**。他のマスを押しても何も置かず、印を付け直す。
- **違反への反応を遅らせる**（例: 500ms）。切り替えの途中で一瞬違反になる状態に反応して画面が揺れないようにする。一言欄の高さは固定する。
- **ヒント**: 手が止まったら、今のルールで決まるマスに印を出す。
- **プレイ中から開く**: プレイの経過時間は止めない。チュートリアルのプレイは記録・採点しない。
- **演出の扱い**:
  - 入口の演出は約2〜2.5秒に収め、どこを押しても飛ばせるようにする。飛ばすために押したタップで盤面にタイルが置かれないようにする。
  - `prefers-reduced-motion` では最初から本編の状態で開く。
  - 「もう一度」では名前の演出を省き、盤面を戻す動きだけにする。
  - 動きの値は `DESIGN.md` §12 と `frontend/styles/globals.css` のトークンに合わせる。

## 6. コードの置き場所

| 置き場所 | 中身 |
|---|---|
| `frontend/src/games/tutorial.ts` | ゲームに依存しない契約と進行の純関数（手順、ルール、導入、手の結果、完成） |
| `frontend/src/components/TutorialOverlay.tsx`、`components/TutorialOverlay/` | ゲームに依存しない枠、入口の演出、チップ、一言欄、完成時の操作 |
| `frontend/src/games/<game>/tutorial/` | 盤面、手順、手の判定、決め手とヒントの導出、違反の一言（純粋な TypeScript） |
| `frontend/src/games/<game>/ui/<Game>Tutorial.tsx` | 盤面の表示、盤面の演出、`games/tutorial.ts` の進行関数での駆動 |

- 層の依存は `.claude/rules/game-structure.md` と Biome の依存規則（`frontend/scripts/dependency-rules.ts`）に従う。
- state の変化を見て演出を始める effect を書かない。開く・押すなどのイベントか、盤面からの完了通知で進める。
- 2つ目以降のパズルでは、共通の契約と部品をそのまま使えるかを確かめ、使えない部分だけを契約側で一般化する。

## 7. 進め方

1. **調べる**: 対象パズルの有名な実装のチュートリアルと、一般的な知見を先に調べる（事例と出典は `references/takuzu-case.md`）。
2. **目的と範囲を決める**: 「1. 目的と範囲」をそのパズルに当てはめ、基本ルールとテクニックの線引きを決める。
3. **盤面を探索で作る**: 「3. 盤面の条件」を満たす盤面を総当たりで探し、候補から流れの良いものを選ぶ。
4. **実アプリで作る**: アーティファクトなど別の見た目の試作ではなく、本物の盤面部品で作る。見た目が違うと判断できない。
5. **自分で見直す**: 「8. 見直し」をすべて行う。サブエージェントの報告やテスト結果だけで「確認済み」と言わない。
6. **人間に見せる**: プレビュー URL と、手順ごとの一言の表、自分で見つけた懸念を添えて渡す。

人間に聞くのは、本当にその人が決めることだけにする。全部入れれば済む選択肢を並べて聞かない。

## 8. 見直し

`references/checklist.md` のチェックリストを上から順にすべて確かめる。特に「実画面での確認」は、サブエージェントに任せた場合でも、スクリーンショットとコマを自分の目で見る。

- **静的検証**: `bun run --cwd frontend check`、`typecheck`、`test` を通す。
- **画面確認の手段**: `bun run --cwd frontend dev` で開発サーバーを起動し、Playwright（Chromium は導入済み）で幅375pxを操作してスクリーンショットとブラウザのエラーを取る。ChatGPT 環境では `docs/メモ/ChatGPT画面確認.md` の手順と `scripts/chatgpt_playwright.py` を使う。
- **人間に見せる場所**: ブランチを push すると Cloudflare Workers のブランチプレビューができるので、その URL を渡す。
