# 失敗の型と検査

過去の難易度プレビューで、人間に指摘されてから直したもの。各行は「兆候 → 検査（いつ・何で確かめるか）」。「いつ」は SKILL.md の流れの番号。実例は `examples.md` の「覆された経緯」。

流れ 4 では案（記法）に、流れ 5 では候補の実装に、流れ 8 と見直し・レビューでは仕上げた図に全行を当てる。当たった行は直すか、直せない理由（どの制約か）を報告に書く。

## 失敗の型

| 型 | 兆候 | 検査（いつ・何で） |
|---|---|---|
| プレビューに実問題を描く | 代表問題の縮小。マスが潰れる。上位のレベルが同じに見える。問題集を作り直すと図が変わる | 4・8: 挑戦を抽象化して描く。プレビューのファイルが問題集・問題の選び方（`problem-selection`・問題集のデータ）を import していないことを確かめる。図の定数が手で書いた配置で、上のコメントに「実際の問題ではない」とある。問題集の値はテストで照合するだけにする |
| 軸でない違いでプレビューの差を作る | レベル間で差の無い量を描き分けている。見た目の分かりやすさのために、実際の難易度要因でない規則性（揃える・混ぜるなど）を足している | 1・4・8: 図の定数から、レベルごとに変わる量（個数・列数・長さ・折れる回数・色の数など）をすべて書き出し、各量が挑戦の表の「描く軸」の行に対応し、問題集で測ってレベル間に差があることを確かめる。対応しない量は全レベルで同じにする |
| プレビューの描き込みすぎ・答えを描く | 3色以上。挑戦に関わらない数字・格子・記号・ヒント欄。決まるマスを埋めて描く。説明文を添える | 2・4・8: 描かない物のリストを先に作り、図と突き合わせる。色は盤面の地のほかに2色程度まで。決まるマスは中身（塗り・数字・タイル）を描かず、線や地の淡い色で示す。図の中と選択肢に、レベルの帯とラベル以外の文字が無い |
| 既存プレビューの意図を読まずに置き換える | 見直しで、前の図が描いていた挑戦（数字の密度など）を捨てた。人間が決めた形を理由なく戻した | 0・8: 変える前に、今の図の意図を「意図のメモ」に書く（`SKILL.md` 流れ 0）。テストが固定している関係は、残すか、覆す理由を報告と記録に書く。人間が決めた形を覆すときは自分で決めず、別案として画像で並べる |
| 盤面の逆転 | 上位ほど図の盤面・幅が小さい。上位ほど要素が少なく見える | 1・8: 規模を描くなら、隣接レベルで幅を下げないことと、そのレベルで遊ぶ盤面の範囲に入ることをテストで固定する。規模を描かないなら全レベルで同じ大きさにする |
| スマホで潰れる・軽すぎる | マスや数字が読めない。盤面全体を枠に押し込み、既存ゲームより細く軽く見える。直しても同じ指摘が残る | 4・5・8: 記法の段階で、スマホの枠に収めたときのマスの大きさを計算し、既存のプレビューのマスの大きさ（各ファイルのクラスと変数）と比べる。全体を描かず切り出して大きさを保つ。実寸の画像で既存ゲームと並べ、拡大でもレベル1と5を見る |
| 模式図が別の物に読まれる | 進み具合の表示、ヒントの線、途中まで解いた跡、答えの絵に見える。見本と実物（プレイ画面の盤面）が合わない | 5・8: 本番の描画部品で描き、プレイ画面と同じ向き・同じ姿にする。文脈を持たない確認者に、レベルを伏せて並べ替えた5つの図だけを見せ、何に見えるか・どれが難しいか・何が違うかを言わせる |

## 検査の手順

### 量の書き出し（軸でない違い・逆転）

1. 図の定数を読み、レベルごとに「描かれている量」を表にする（要素の数、列数・行数、線の長さや折れる回数、色ごとの要素の数、空き・未開示の数など）。
2. 各量について、隣接レベルで変わるか、変わるならどの挑戦の軸に対応するかを書く。
3. 対応する軸の値を、問題集で測ったレベルごとの値（中央値と範囲）と並べる。値の出所は `/design-game-difficulty` の検査の出力か、そのゲームの分析コード。
4. 軸に対応しない量が変わっていれば直す。軸に対応する量は、テストで定義・問題集と照合する。

### 描かない物の突き合わせ（描き込みすぎ・答え）

1. 流れ 2 のリストの各項目を、図の DOM と画像で探す（数字・文字は `textContent`、色は使っているクラスを数える）。
2. 決まるマスについて、その中身（塗り・数字・タイル）が描かれていないかを見る。
3. 色の数を数える。盤面の地・格子の色を除き、2色を超えたら減らす。

### 意図のメモとの突き合わせ（意図を読まずに置き換える）

1. 流れ 0 の意図のメモの各行（描いている挑戦、レベル間の関係、描かないもの、人間が決めたこと）について、新しい図でどうなったかを書く。
2. 「捨てた」行があれば、理由と、捨てない別案の画像を報告に入れる。

### スマホ幅での見え方

1. `review-sheet.md` の型で、iphone（390）と pc（1280）の難易度選択を撮る。行の高さと見本の幅は幅によらず同じなので、マスの大きさは iphone の画像で決まる。
2. 拡大（`zoom`、4倍）でレベル1とレベル5の図を撮り、マス・数字・線が潰れていないか、枠からはみ出していないかを見る。
3. 同じ画像で既存ゲーム2つ以上の難易度選択と並べ、見本の大きさ・重さ（線の太さと面積の濃さ）が突出していないかを見る。
4. ブラウザエラーが無いことを `browser-errors.log` で確かめる。

### 読まれ方の確かめ（模式図が別の物に読まれる）

文脈を持たない確認者（汎用のサブエージェント）に、ゲーム名とプレイ画面の画像1枚、レベルの順を伏せて並べ替えた5つの図だけを渡し、次を答えさせる。正解や意図は渡さない。

- それぞれの図は何に見えるか（盤面の一部、進み具合、ヒント、答えなど）。
- 難しいと思う順に並べるとどうなるか。理由は図のどこか。
- 図とプレイ画面の盤面は同じゲームに見えるか。

順が合わない、または盤面以外の物に読まれたら、流れ 3 に戻って描き方を変える。サブエージェントを起動できない立場（`/add-puzzle` の実装役の中）では行わず、起動側に頼むと報告に書く。
