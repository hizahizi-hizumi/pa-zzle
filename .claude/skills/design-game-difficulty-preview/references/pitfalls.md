# 失敗の型

過去の難易度プレビューで、人間に指摘されてから直したもの。各行は「兆候 → 検査（いつ・何で確かめるか）」。「いつ」は `SKILL.md` の流れの番号。確かめる手順は `checks.md`、実例は `examples.md` の「覆された経緯」。

`/add-puzzle` の自己点検役に渡すときは、全行を「いつ」が difficulty-select の行として扱う。

流れ 4 では案（記法）に、流れ 5 では候補の実装に、流れ 8 と見直し・レビューでは仕上げた図に全行を当てる。当たった行は直すか、直せない理由（どの制約か）を報告に書く。

| 型 | 兆候 | 検査（いつ・何で） |
|---|---|---|
| プレビューに実問題を描く | 代表問題の縮小。マスが潰れる。上位のレベルが同じに見える。問題集を作り直すと図が変わる | 4・8: `SKILL.md` の守ること 2 に当てる。プレビューのファイルが問題集・問題の選び方（`problem-selection`・問題集のデータ）を import していないことを確かめる |
| 軸でない違いでプレビューの差を作る | レベル間で差の無い量を描き分けている。DESIGN.md「難易度選択」が避けるとしている違いで差を作っている | 1・4・8: `checks.md` の「量の書き出し」 |
| プレビューの描き込みすぎ・答えを描く | 色が多い。挑戦に関わらない数字・格子・記号・ヒント欄。決まるマスを埋めて描く。説明文を添える | 2・4・8: `checks.md` の「描かない物の突き合わせ」と「色の数」。決まるマスは中身（塗り・数字・タイル）を描かず、線や地の淡い色で示す |
| 既存プレビューの意図を読まずに置き換える | 見直しで、前の図が描いていた挑戦（数字の密度など）を捨てた。人間が決めた形を理由なく戻した | 0・8: `checks.md` の「意図のメモとの突き合わせ」。人間が決めた形を覆すときは自分で決めず、別案として画像で並べる |
| 盤面の逆転 | 上位ほど図の盤面・幅が小さい。上位ほど要素が少なく見える | 1・8: 規模を描くなら、隣接レベルで幅を下げないことと、そのレベルで遊ぶ盤面の範囲に入ることをテストで固定する。規模を描かないなら全レベルで同じ大きさにする |
| スマホで潰れる・軽すぎる | マスや数字が読めない。盤面全体を枠に押し込み、既存ゲームより細く軽く見える。直しても同じ指摘が残る | 4・5・8: `checks.md` の「スマホ幅での見え方」。全体を描かず切り出して大きさを保つ |
| 模式図が別の物に読まれる | 進み具合の表示、ヒントの線、途中まで解いた跡、答えの絵に見える。見本と実物（プレイ画面の盤面）が合わない | 5・8: 本番の描画部品で描き、プレイ画面と同じ向き・同じ姿にする。`checks.md` の「読まれ方の確かめ」 |
| 正本の構成と食い違う | DESIGN.md「難易度選択」が求めるレベル間の構成（入れ子など）と図の関係が違う | 3・8: `checks.md` の「入れ子」 |
