# 既存の難易度プレビュー

流れ 1・2 の前と、見直し・追従の入口で読む。値や形を流用せず、何を挑戦の差として描き、何を描かないかの決め方を読む。数値はコードを正とし、ここに書いたものは読む先の目印にとどめる。

## 読む場所

- 実装とテスト: `frontend/src/games/<game>/ui/<Game>DifficultyPreview.tsx` と同名の `.test.tsx`。多くは図の定数の上のコメントに、描く挑戦・レベル間の関係・描かないものが書いてある（ウォーターソートのように無いものもある）。
- 置かれる枠: `frontend/src/components/DifficultyOption.tsx`（スマホは横長の行、PC は縦長のカード。見本の幅を固定して全ゲームでラベルの位置をそろえる）と、各ゲームの `frontend/src/views/<Game>DifficultyView.tsx`。
- 決めた理由と比べた案: `git -C <root> log --all --format='%h %ad %s%n%b' -- '*DifficultyPreview*'` のコミット本文と、`docs/パズル/導入調査/<パズル名>/` の実装前提調査・難易度の資料（「難易度プレビュー」で検索）。
- main に無いゲーム（ブランチだけにあるもの）は `git -C <root> grep -l -e DifficultyPreview <ブランチ> -- 'frontend/src/games/*/ui/*DifficultyPreview.tsx'` で探し、`git -C <root> show <ブランチ>:<パス>` で読む（`git ls-tree` はパスの `*` を展開しないので使わない）。

## 作り直しを経て残った形

7ゲームの今の実装に共通する事実。決まりは正本（`SKILL.md` の「参照する正本と読む時」）を見る。

1. **手で作った図**。図はレベルごとの定数（文字の格子や配置の表）で持つ（`SKILL.md` の守ること 2）。
2. **盤面の一部を切り出す**。帯・数行・局面の行だけを描き、マスを読める大きさに保つ。マスの大きさは全レベルでそろえ、規模が挑戦の軸のときだけ、切り出した図の幅（列数）で規模の差を見せる。
3. **本番の描画部品で描く**。セル・駒・ボトル・光路などプレイ画面と同じ姿にし、プレビュー専用の記号を作らない。
4. **差は1〜2個の量だけ**。その量の値はレベルごとの定数で持ち、難易度の組み合わせ定義か問題集の値とテストで照合する。差に使わない量は全レベルで同じにする。
5. **レベル間の関係**。入れ子（上のレベルが下のレベルの要素を同じ位置に含む）なのはナンプレ（減らす向き）・マインスイーパー・パーキングジャム・リフレクション。入れ子でないのはウォーターソート（レベルごとの配置）・スライドパズル（幅の違い）・バイナリパズル（レベルごとの局面）。入れ子にするかどうかは DESIGN.md「難易度選択」に従う（`checks.md` の「入れ子」）。
6. **静かで小さい**。`aria-hidden`、説明の文字なし、動かない。色の数は `checks.md` の「色の数」。
7. **枠は共通部品が持つ**。見本の幅と行の高さは `DifficultyOption` が持ち、各プレビューはその中に収める。スマホの高さは行に収まる範囲（各プレビューの `h-12`〜`h-14`）、PC は `lg:` で広げるものがある。
8. **テストは関係を固定する**。包含・単調・定義との一致・描かないもの・図が成り立つこと（可解、解法器で示したマスが決まる）を `_private` の定数で確かめる。

## 覆された経緯

人間のレビューで作り直したもの。失敗の型（`pitfalls.md`）の実例として読む。

| ゲーム | 最初の形 | 覆った理由 | 決着 |
|---|---|---|---|
| ナンプレ | 5段階化で、各レベルで初めて要る手筋の局面を数字なしで描き、補足の一文を添えた | 数字の無い模式図は読み取れない。既存の「数字の密度」の意図を読まずに置き換えた。説明文を足した | 盤面の切り出しの数字の密度へ戻し、補足文を消す（`92b87075`） |
| マインスイーパー | 外周の地雷と開示マスの数字 → 盤面と地雷の割合が増える縮小盤面 | 縮小盤面ではマスが潰れ、レベルの差が見えない | プレイ画面と同じ表現の3行盤面、中段の数字で隣接数を見せる（`8ae22533`、#358） |
| パーキングジャム | 手設計 → 代表問題の本番盤面の縮小 | 実際の開始盤面は比較に不要な情報が増え、規模は判定要因でもない | 同じ大きさの手設計の駐車場で、レバーの差だけを見せる（`230912d4`） |
| スライドパズル | 実際に遊ぶ大きさの盤面 → 問題集の盤面 | 5×5 でマス約 9px・数字約 5px。同じ大きさの2段が見分けられない | 上2行の切り出し。同じ幅の下の段だけ1行目を揃える。プレビューに合わせてレベルと盤面サイズの割り当ても改めた（`261a5afa`） |
| バイナリパズル | 決まるタイルを置いたタイルと同じ見た目で描く | 答えを描いている（レベル2の盤面が埋まって見える） | 決まるマスは空きのまま淡い色だけ付ける |
| リフレクション | 3行の帯に、光路をレベルの数だけと、ピース4種・外周ヒントの数字・記号 | 賑やかすぎる | 2行の帯に光1本、鏡の組の数で折れる回数を見せる。2色（`b09db36a`） |
| ウォーターソート | 易しいほど色を揃え、難しいほど混ぜる | 見た目が成立しない（`docs/メモ/画面設計.md`） | ボトルと色と空きの数 |

## main に無いプレビュー（参考）

ブランチだけにあり、人間の決定を経ていない。成功例として扱わない。

| ゲーム（ブランチ） | 形 | 残ったこと |
|---|---|---|
