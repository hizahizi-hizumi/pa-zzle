# 比較画像の型と撮り方

流れ 5・6・8 で使う。候補を、本物の難易度選択の枠に入れた実寸で、既存ゲームと同じ条件で並べる。

## 一時的な比較の画面

候補と既存ゲームを同じ画面に並べるため、対象ゲームの難易度選択の View を一時的に書き換える。置き場所と後始末（消す、コミットしない、`git status` で確かめる）は `SKILL.md` の「一時的な変更の置き場所と後始末」。

- 書き換えるのは `frontend/src/views/<Game>DifficultyView.tsx` だけ。本物の選択肢の下に、候補ごと・比べる既存ゲームごとのまとまりを足す。まとまりは小さな見出し（候補の短い名前かゲーム名）と、`DifficultyOption` で包んだ5レベルの見本。`playPath` は対象ゲームのものを渡してよい。
- 候補の図は、まとまりごとの一時的なコンポーネントにする（候補の実装が1つのファイルなら、そのファイルを複製して名前を変える）。比べる既存ゲームの図は、そのゲームの `<Game>DifficultyPreview` をそのまま import する。

## 撮り方

開発サーバーを起動し、`.claude/skills/add-puzzle/scripts/playtest-driver.mjs`（使い方は冒頭）を iphone と pc で常駐させて、難易度選択のパスへ `goto` し、`shot`・`scroll`・`zoom` で撮る。画像の 1px は CSS の 1px。

- iphone（390 幅）: まとまりごとに1枚になるよう `scroll` で送る。
- pc（1280 幅）: 1枚に、まとまりの5列の行が2〜3段入る。入りきらなければ段ごとに撮る。
- 拡大: iphone で、推奨案と各別案のレベル1とレベル5の見本を `zoom`（4倍）で撮る。
- 順を伏せた画像の組（読まれ方の確かめ用）: iphone で各レベルの見本だけを `zoom` で切り出し（レベル名・ラベルを写さない）、ファイル名を無作為な記号にする。記号とレベルの対応は報告ファイルにだけ書く。
- 320 幅やダーク（`<html>` に `.dark`）は driver では撮れない。見本の枠は幅によらず同じなので通常は不要。`/add-puzzle` からは撮らず、撮っていないと報告に書く（実装役は Playwright を直接動かせない）。ほかの入口で図にダーク用の色を付けたときは、起動した会話でその場の Playwright で1枚撮ってよい（スクリプトにはしない）。

## 画像の型

| 画像 | 端末 | 中身 | 目的 |
|---|---|---|---|
| 候補の列 | iphone | 1つの候補の5レベル（本物の行の形） | 候補ごとの見え方 |
| 既存の列 | iphone | 比べる既存ゲームの5レベルを、候補と同じ型で1枚ずつ | 大きさ・重さの基準 |
| 並べた表 | pc | 推奨案・別案・既存ゲームの5列の行を縦に並べる | 候補どうしと既存ゲームの比較 |
| 拡大 | iphone | 各候補のレベル1とレベル5の見本の4倍 | 潰れ・はみ出しの確かめ |

- 比べる既存ゲームは2つ以上（この Skill で既存ゲームと並べるときの数は、ここを正とする）。図の形が近いもの（同じ格子の切り出し、同じ線の描き方など）と、形が違うもの1つを選ぶ。
- 並べる順は、推奨案、別案、既存ゲームの順。テーマ・状態（何も押していない）をそろえる。
- ファイル名は `<順の2桁>-<候補の短い名前かゲーム ID>-<iphone|pc>[-zoom-L<レベル>].png`。

## 添える文

候補ごとに次の4行を添える。記号だけで呼ばず、中身で説明する。

- 描く挑戦: 利用者向けの一言（「上のレベルほど、光が鏡で折れる回数が増える」など）。
- レベルで変わるもの: 図のどの量が、どう変わるか。
- 描かないもの: 答え・数字など、あえて描かなかったもの。
- 利点と不利な点: このゲームで何が伝わりやすく、何が伝わりにくいか。検査で残った所見も書く。

推奨案には推奨の理由を添える。別案には配置の記法も添え、選ばれたら作り直せるようにする。単独で起動されたときは、人間に選ぶ方向（候補全体か、「A の切り出し + B の量の見せ方」のような部分の組み合わせ）を聞く。

## 渡し方

- 画像は作業ディレクトリ（`/add-puzzle` からは実装役が渡したもの。単独の起動では `/tmp/<ゲーム ID>-difficulty-preview/`）に置く。
- `/add-puzzle` からは、画像のパスの一覧と添える文を報告ファイル `<作業ディレクトリ>/design-game-difficulty-preview-report.md` に書く（`SKILL.md` の「出力」）。人間に見せる資料（Artifact など）にするのはメインで、パスや内部用語はそこで外す。
- 単独の起動では、画像と添える文を会話で人間に示す。
