# 受け口の契約

`pictogram-showcase.svg` をアプリへ渡すための書き方の規則。アプリ側の受け口（`frontend/src/components/GamePictogram.tsx`、`GameSelectionGallery.tsx`）がこの形を前提に表示する。機械的に確かめられる規則は `scripts/check_animation.py` が `FAIL` / `WARN` にするので、違反の詳細はその出力で確かめる。

契約の変更は人間の判断で、この Skill の外で行う。変える場合は、アプリ側の受け口・`DESIGN.md`・この文書・`scripts/` の検査とギャラリーを同じ変更で揃え、決め直した理由は `docs/adr/README.md` に従って ADR に残す。

## 1. ファイルと座標系

- 置き場所は `frontend/src/games/<game>/assets/pictogram-showcase.svg`。無いゲームは白黒 `pictogram.svg` が代わりに表示される。
- 1 ファイルで、一覧の選択中に見せる静止状態とヒーローの動きを兼ねる。ルートは `<svg>`、`viewBox="0 0 120 120"`。
- 静止状態は白黒版と同じ形にし、違うのは色だけにする（2 節）。動きの途中の姿は、白黒版と同じ構成要素・枠組み・視点を保つ範囲で変えてよい。範囲は `references/motion.md` の 4 節。

## 2. 静止状態と再生

- アニメーション指定の無い基本スタイルで描かれた姿が静止状態。一覧の選択中と、OS の動きを減らす設定ではこれが表示される。
- 選んだ瞬間に変わるのは色だけにする（`DESIGN.md` の「ゲームピクトグラム」、ADR-0016）。静止状態は白黒版の図形（要素・座標・大きさ・線幅・字形）をそのまま使い、変えるのは塗りと線の色だけにする。足してよい要素は、白黒版の線に囲まれて空いている面に敷くゲーム固有色の面だけで、これも色の変化に含める（`DESIGN.md` の「ゲームピクトグラム」）。何をどの色にするかと、面を敷く条件は 3 節。ゲーム固有色の無いゲームは何も変えない。
- 候補が `base_revision` で白黒版を直す場合は、この節と 3 節で比べる相手の白黒版は修正案になる。修正案は、静止状態の図形を写して色だけを濃淡 2 色に変えて作る。白黒版に合わせる場合も修正案に合わせる場合も、片方の図形をもう片方へ写して作り、似せて描き直さない。
- アプリはヒーローの動きを、周の終わりの静止状態から再生し始める。静止状態の区間が 600ms より長ければその終わりの 600ms から、短ければその頭から始める（`frontend/src/components/game-pictogram-motion.ts`）。そのため、どの再生形式でも周の終わりを静止状態にし、選んだ直後のヒーローは静止状態を見せる。アプリは静止状態の区間を keyframe の値から求めるので、周の終わりの静止区間では、見えない要素（opacity 0 など）も含めて keyframe の値を変えない。変えると、見た目は止まっていても再生の入口が周の終わりへずれる。ホームがタイトルに覆われている間は静止状態のまま待ち、覆いが外れたときにそこから始める。
- animation は SVG 内 `<style>` の CSS animation で書く。animation を付けるルールは `@media (prefers-reduced-motion: no-preference)` の内側に置き、祖先の `[data-pictogram-motion="play"]` を条件にする（例: `[data-pictogram-motion="play"] .pz-<game>-x { animation: … }`）。この属性はアプリがヒーローの祖先に付ける。SVG 自身や対象には付けない。
- 全 animation を `infinite` にし、再生形式を次の 3 つから選んで manifest の `playback` に宣言する。どの場面でどれを使うかは `references/exploration.md` の 3 節「再生形式を選ぶ」、作り方は `references/motion.md` の 1 節。
  - `cut`（切り替えループ）: 開始の姿で始まり、見せ場まで動き、見せ場の後の姿（= 静止状態）で周の終わりまで止まり、周の境界で開始の姿へ 1 コマで切り替える。開始の姿は静止状態と違う。
  - `rest-cut`（静止状態から始まる切り替えループ）: 静止状態で始まり、見せ場まで動き、見せ場の後の姿で止まり、1 コマ（1 フレーム以内）で静止状態へ切り替え、周の終わりまで 600ms 以上静止状態のまま止まる。止まりから静止状態へ切り替えるのは周の途中のこの 1 回だけにする。動きの途中で静止状態と同じ姿を通るのはよい。600ms 以上にするのは、選んだ直後に、色の入った静止状態を `cut` と同じ長さ見せてから動き出すためである。この形式を認めた理由は ADR-0017。
  - `seam`（継ぎ目ループ）: 0% と 100% を同じ姿にし、その継ぎ目を静止状態にする。周の途中で見えている要素を跳ばさない。
- `cut` と `rest-cut` は全 animation を同じ周期・同じ遅延にする。切り替えを全要素で同じコマに揃えるためである。

## 3. 色

色は、濃淡 2 色とゲーム固有色に限る。`DESIGN.md` の「ゲームピクトグラム」が濃淡 2 色の代わりに許すのは、解く場面で使うゲーム固有色の姿だけだからである。

- ゲーム固有色は、`DESIGN.md` の「ゲーム固有色」（ゲームの識別色、盤面データから決まる色、駒など題材に由来する色）のうち、そのゲームのプレイ画面で使っている色を指す。プレイ画面がアプリのトークンで塗っている要素は、次の基準で分ける。
  - プレイ画面でゲームの状態の区別（置いた / 置いていない、確定 / 未確定など）を担うトークンは、この Skill ではゲーム固有色と同じに扱う。
  - 盤や駒という種類を共通UIの面・境界の色（`bg-muted`・`bg-card`・`border-border` など）で塗っているだけのトークンは写さない。面の色で塗った盤は、濃淡 2 色の姿でもゲーム固有色の姿でもない第 3 の姿になる。
  - ホバー・フォーカス・押下・選択など、操作への反応に使うトークン（`accent`・`ring` など）は共通UIの色として写さない。選んでいることをアプリ共通の色で強調する見せ方は、ADR-0016 で退けている。
- ゲーム固有色を持たせない線と面（輪郭や補助線など）は、白黒版と同じく前景を `var(--game-pictogram-strong)`、補助を `var(--game-pictogram-soft)` で描く。ライト/ダークはアプリがこの 2 変数で切り替える。
- 白黒版で線に囲まれて空いている面（盤の地など）には、ゲーム固有色の面を敷いてよい（`DESIGN.md` の「ゲームピクトグラム」）。次をすべて満たす。
  - 色は、白黒版が描く状態でその面がプレイ画面で取る色（盤の地、空きマスの地など）にする。状態の違いを表す色を敷いて、白黒版の盤の中身を変えない。
  - 面は囲む線まで隙間なく敷き、線より下に重ねる。線や図形の座標・大きさは変えない。
- 静止状態のインク量が他ゲームの白黒版の範囲を超えて重くなるとき（面を敷くと起きやすい）は、その量と比較列で見た重さを manifest の `notes` に書き、人間に問う。測り方と、先に確かめることは `references/motion.md` の 5 節。
- ゲーム固有色は、プレイ画面の値をそのまま使う。
  - Tailwind のパレット色や TS/CSS の定数は実値を hex か `rgb()` で書く。値は `scripts/resolve_color.py` で引く。
  - アプリのトークンは同じトークンを `var()` で参照する。`check_animation.py` の許可リストは書ける記法の上限で、そのトークンを写すかは上の基準で決める。
  - テーマで値が変わる色は、祖先 `.dark` を条件にしたルール（`.dark .pz-<game>-x { fill: … }`）で色だけを切り替える。keyframes で動かす色は、`.dark` で切り替える `--pz-<game>-*` 変数を keyframes から参照する。`prefers-color-scheme` は使わない。
- ゲーム固有色の無いゲームは、静止状態を白黒版そのものにする。選んでも色は変わらず、A と B は動きだけで伝える。動きの中で強調を移す（動く対象を濃い方にするなど）ときも濃淡 2 色の間で入れ替え、3 色目や面の塗りを足さない。
- 例外として、プレイ画面の値のままでは実表示サイズで背景に溶けるゲーム固有色の線・面は、見えることを優先して近い役割の色（同じ色の一段濃い段など）で代え、理由を manifest の `notes` に書く。ライト/ダークの両方で確かめる。
- 定義元の調べ方は `references/exploration.md` の 1 節。

## 4. 同時 2 表示

SVG はページへインライン展開され、一覧の選択中とヒーローで同時に 2 つ表示される。`<style>` はページ全体に効く。

- クラス名・keyframes 名・id は `pz-<game>-`、独自変数は `--pz-<game>-` 接頭辞にする。セレクタの対象は接頭辞付きクラスにする。
- id 参照（gradient、clipPath など）は避ける。使うなら同時 2 表示で壊れないことをセルフレビューで確かめる。

## 5. 文字

- 数字・記号は白黒版の字形（パス）を流用する。無い字形は `<text>` で書き、`font-family` にシステムの sans-serif 系を明示する。

## 6. 使わないもの

script・外部参照・SMIL・`transition`・`foreignObject` / `image`・`d` の CSS アニメーション。古い WebKit が解釈しない記法（`oklch()` などのリテラル色、`color-mix()`、入れ子の CSS）も避ける（`references/motion.md` の 7 節）。
