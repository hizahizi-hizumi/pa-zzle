# 姿の探索方法

`/design-game-pictogram-showcase` の材料抽出、発散、候補整理に使う。目的は案数を稼ぐことではなく、目的 A（遊びが分かる）と目的 B（解けた気持ちよさが見える）を満たしうる異なる方向を、安い段階で広く確保することにある。

## 1. 材料を抽出する

発散の前に、ゲームから材料を短く列挙する。次の 2 つは必須とし、欠けたまま発散へ進まない。

```yaml
central_action:   # A の材料。プレイヤーが何を見て、何を考え、何をするか
  - 一番上の色が同じ瓶を探す（考える）
  - 瓶を選び、別の瓶へ注ぐ（する）
solved_moment:    # B の材料。何が揃い、どう終わるか
  - 1 本の瓶が単色で満ちる
  - 全瓶が単色で揃い、盤面が静まる
```

加えて次を拾う。

- 動かせる対象と、その所属関係（容器と中身、盤とマス、駒と通路など）
- 題材の物理（重力、流動、衝突、整列、反転など）
- プレイ画面で使う色と、その色が担う役割（識別、状態、完了）と定義元のパス。ライト/ダークで値が変わるか（Tailwind の `dark:` クラス等）と、両テーマの実際の値
- 白黒版が何をどの構図で描いているか。どこを色にすると同じパズルのまま姿が立つか
- ゲーム中には実際に起きないが、ゲームの意味から無理なく連想できる誇張

`central_action` は操作の名前ではなく、考える部分とする部分の両方を書く。考える部分が動きで見えないと、A は「何をするか」止まりになる。

## 2. アイデアカードを作る

初回発散ではコードを書かない。1 案につき次だけを短く記録する。

```yaml
id: pour-settle-01
name: 注いで揃う
idea: 片方の瓶が傾き、上の色がもう片方へ移り、受け側が単色で満ちて止まる
aim_play: 「同じ色の上へ注ぐ」判断と操作を 1 回で見せる
aim_payoff: 受け側が単色で満ちた瞬間に動きが止まる
static_pose: 揃った後の姿（2 本の瓶、片方が単色で満ちている）。再生の終点でもあり、始点は注ぐ前の姿
playback: once
references:
  - 中心の操作: 注ぐ
  - 解けた瞬間: 1 本が単色で満ちる
```

- `aim_play` は遊んでいる瞬間の動きで見せる。規則を矢印や記号で説明する図解寄りの案は、遊びたくなる姿にならず除外されやすい。
- `aim_play` / `aim_payoff` は評価点ではなく、後で束ね、セルフレビューで「宣言どおり読めるか」を確かめるための仮説である。
- `static_pose` は一覧選択中の色付き静止画であり、1 回再生の終点、切り替えループの止まり、継ぎ目ループの継ぎ目でもある。動きと切り離して考えない。
  - `once`（1 回再生）: 終点を静止状態にする。「解けた後の姿」を静止状態にすれば、見せ場で終わってそのまま止まれる。始点は静止状態と異なってよい（例: 解く前の姿から始める）。
  - `cut`（切り替えループ）: 1 回再生と同じ動きの後、見せ場の姿（= 静止状態）で止まり、周の境界で開始の姿へ瞬時に切り替えて繰り返す。静止状態の決め方は `once` と同じでよい。
  - `seam`（継ぎ目ループ）: 0% = 100% の継ぎ目を静止状態にする。「解く前の姿」を静止状態にするなら、解けた状態から元へ戻す流れが要る。「解けた後の姿」を静止状態にするなら、一度崩してから再び揃える流れになる。
- `playback` は仮置きでよい。同じ案の `once` 版と `cut` 版を比べてよい（選び方は 3 節）。

## 3. 再生形式を選ぶ

まず `once` か `cut` を検討する。どちらも「解く前 → 見せ場 → 解けた姿で止まる」という 1 回再生の流れをそのまま使え、構図も周期も膨らまない。`cut` は同じ流れを繰り返し見せたい場合に使う。

- `once`: 見せ場で終わって静まる。ヒーローを見ている間ずっと動かない分、D を侵しにくい。
- `cut`: 見せ場の姿で止まった後、開始の姿へ瞬時に切り替えて繰り返す。切り替えは「場面の頭出し」として読まれ、フェードや巻き戻しで戻すより自然に受け取られた。
- `seam`: 継ぎ目が意味として自然に成立する場合だけ検討する。不可逆な操作のゲーム（注ぐ、消す、置く等）は元に戻らないため、継ぎ目に「次の問題が来る」「役割が交代する」などの物語が要り、構図が変わり周期も伸びやすい。ウォーターソートでは「次の問題」系は除外され、「交代」は瓶の大きさを揃える点だけが採用された。
- フェードで開始の姿へ戻すループは、ループ自体は受け入れられても戻りが不自然と受け取られた。途中経過を見せる戻し方は試作しない。

ヒーローには枠がないため、画面端から対象が出入りする動きは描画域の端で切れて見え、D を損なう。`seam` の継ぎ目を作るために出入りを使わない。

組み立て方と周期の目安は `references/motion.md`。

## 4. 一回の長い発散へ依存しない

同じ prompt で案数だけ増やすと、後半が言い換えになる。複数回を独立させ、毎回違う刺激を与える。

A 側の刺激:

- 中心の操作を 1 回だけ、はっきり見せる
- 「考える」部分（探す、見比べる、迷う）を間で見せる
- 操作の結果として盤面がどう変わるかを主役にする
- 動きを極端に少なくして操作の核だけ残す

B 側の刺激:

- 揃った瞬間に動きが止まる「静まり」を見せ場にする
- 最後の一手、最後の一滴など終端の間を主役にする
- 一つの完了から連鎖させる
- 完了したものの色が初めて全部見える構成にする

これはカテゴリごとのノルマではない。同じ局所解から離れるための刺激として使う。

D（落ち着き）は発散段階で案を縛らない。ただし、常時大きく動き続ける、強く点滅する、画面外へ飛び出す・画面端から出入りするなど、明らかに D を侵す案は試作対象にしない。

## 5. 初回の量は探索空間に合わせる

ウォーターソート程度の単純な題材なら、30〜60 枚程度のアイデアカードを作り、重複を整理してから 10〜20 程度を試作する運用が一つの目安になる。数値は固定条件ではない。

- 十分に異なる方向が揃えば増やさない
- 同系統しか出なければ、案数ではなく刺激を変える
- 実装コストが高い題材では、カードを増やして試作数を減らす

## 6. 微差と別方向を分ける

次の差だけでは、通常は同じ案として扱う。

- 速度、移動距離、回転角度、イージング、開始時刻
- 同じ色の別配色

同じ「注ぐ」動作でも、次は別方向として残しうる。

- 普通に注いで揃う: A を操作そのもので見せる
- 迷ってから注ぐ: A の「考える」部分を見せる
- 最後の一滴で揃う: B の終端の間を見せる

動作の形ではなく、`aim_play` × `aim_payoff` の組み合わせが異なるかを見る。

## 7. 束ねて代表を選ぶ

- 似た `aim_play` と `aim_payoff` を持つカードを同系統にまとめ、各系統から代表を残す
- 説明しにくいが他と明らかに異なる案を、無理に既存系統へ入れない
- モデルが「成功しそう」と感じる案だけで寄せない
- C（選んだ手応え）を束ねや選定の基準にしない。C は A/B の結果として確かめる

初回試作の目的は勝者予測ではなく、人間が方向を比較できることにある。

## 8. 試作では核心以外を削る

試作は `aim_play` と `aim_payoff` が伝わる最小実装にする。

- 静止状態を先に描き、白黒版と並べて同じパズルだと分かることを確かめる
- 色はプレイ画面の定義元から値を写す。試作の段階でも別の色に置き換えない。テーマで変わる色は、ダーク側の値を祖先 `.dark` 条件のルールで切り替える
- 輪郭など前景の線は `var(--game-pictogram-strong)`、補助は `var(--game-pictogram-soft)` にする
- 例えば「最後の一滴」が核なら、液体の完全な流体変形より、主要部分が移った後に一滴だけ遅れて落ちることを優先する
- 回転・拡縮は `transform-box: fill-box` と `transform-origin` を明示する
- 緩急は keyframe 内の `animation-timing-function` で付け、イージングを線形 keyframe へサンプリングしない（`references/motion.md`）
- 構図の調整は `references/motion.md` の「構図を変えてよい範囲」に収める

完成品質の細部に時間を使うのは、人間が方向を選んだ後にする。

## 9. 選択後は探索範囲を狭める

方向が選ばれたら、選択理由（残す A と B）を変えずに 4〜8 案程度へ分岐するのが目安になる。

変える候補:

- 見せ場までの間、軌道、反応順、誇張の強さ、終わり方
- 静止状態にする瞬間、再生形式（`once` / `cut` / `seam`）、止まりと開始の間の長さ
- 色の置き方（どの要素に色を持たせるか、量）
- 他候補から部分採用する表現

さらに方向が定まったら 1〜3 案へ絞って仕上げる。

## 10. 再発散する条件

次の場合は、選択済み方向の微調整を続けず広い発散へ戻る。

- A または B の核自体が弱いと人間が判断した
- C が生まれず、A/B の作り方を直しても改善しない
- D を侵さないと A/B が成立しない
- 白黒版と別物にしないと成立しない
- 候補間の差がタイミングや量の微差だけになった

再発散は失敗ではない。探索空間へ戻るための通常の操作として扱う。
