# 動きの作り方

`/design-game-pictogram-showcase` の候補を試作・仕上げするときの、再生形式の組み立て、周期と静止の割合、緩急、構図の扱い、静止状態の大きさと重さ、動きの量、Safari（WebKit）で崩れない書き方、入れ子の transform。再生形式の定義と契約は `references/contract.md`、どの形式を選ぶかは `references/exploration.md` の 3 節「再生形式を選ぶ」を正とする。

## 1. 再生形式の組み立て

各形式の定義は `references/contract.md` の 2 節。ここでは keyframes の組み方を書く。どの形式でも、全 animation を `infinite` にし、keyframes の 100% を静止状態の値にする。周の終わりの静止区間では、見えない要素も含めて keyframe の値を変えない（同じ節）。

### `cut`（切り替えループ）

```css
@keyframes pz-<game>-piece {
  0%, 6% { transform: translate(-24px, 0); animation-timing-function: cubic-bezier(.3, 0, .2, 1); } /* 開始の姿で間 0.3s */
  40% { transform: translate(4px, 0); animation-timing-function: ease-in-out; }
  52%, 100% { transform: none; } /* 見せ場の後の姿（= 静止状態）で止まる 2.4s（周期 5s） */
}
```

- 全 animation を同じ周期・同じ遅延にする。周の境界は全要素で同時に来るため、100% から 0% への切り替え（例では `none` から `translate(-24px, 0)`）は 1 フレームで終わる。
- 見せ場の後の止まり（目安は 2 節）は、見せ場が「終わった」と読める長さにする。短いと見せ場を読む前に切り替わり、長いと動きが止まったように見える。落ち着き（D）はこの止まりで保つ。
- 開始の間（目安は 2 節）は、切り替えを「場面の頭出し」として読ませる。無いと切り替え直後に動き出し、跳んだように見える。
- 0% を見せ場の後の姿にして、周の途中で開始の姿へ跳ぶ形にしない。周の終わりが開始の姿になり、アプリが周の終わりから再生し始めたとき、選んだ瞬間に形が跳ぶ。
- 開始の姿へ戻すためのフェード・巻き戻し・縮小などの途中経過を置かない。
- `animation-delay` を使うなら `backwards` / `both` を付ける（ギャラリーと観察スクリプトは SVG を 0% から再生するので、遅延中に静止状態 = 見せ場の後の姿が出ないように。アプリは遅延の後へ進めて再生する）。

### `rest-cut`（静止状態から始まる切り替えループ）

```css
@keyframes pz-<game>-cell {
  0%, 40% { opacity: 0; animation-timing-function: ease-out; } /* 静止状態（このマスは空き）。開始の間と、ほかの要素が解いていく間 */
  46% { opacity: 1; } /* 最後のマスが埋まって解ける */
  85% { opacity: 1; animation-timing-function: step-end; } /* 見せ場の後の止まり 1.8s。終わりで 1 コマで切り替える */
  85.1%, 100% { opacity: 0; } /* 周の終わりの静止状態 0.7s（周期 4.7s） */
}
```

- 全 animation を同じ周期・同じ遅延にし、各 keyframes の 0% と 100% を静止状態の値で明示的に書く。書かない値があると、`check_animation.py` は止まりと切り替えの時間を検査できない。
- 見せ場の後の止まりは、`cut` の止まりと同じく見せ場が「終わった」と読める長さにする。周期を目安に収めるには、目安の下側に寄せてよい（2 節）。
- 静止状態への切り替えは、止まりの最後の keyframe に `animation-timing-function: step-end` を付けて書く。次の keyframe の時刻で全要素の値が一度に変わる。1 フレーム（約 16.7ms）以内に 2 つの keyframe を並べる書き方も通るが、間に描かれたフレームが途中の姿を 1 枚見せることがある。フェード・巻き戻しなど、静止状態へ戻る途中経過は置かない。
- 静止状態の区間は周の頭と終わりにあり、周をまたいでつながって 1 つの止まりに見える。そのため周の頭の開始の間は短くてよい。

### `seam`（継ぎ目ループ）

- 要素ごとに 0% と 100% を同じ値にする。周期が違う animation を混ぜると全体が揃うのは最小公倍数ごとになるため、原則として周期を揃える。
- 見えない間（opacity 0）に位置を戻すのはよい。見えている要素が周の途中で跳ばないようにする。

## 2. 周期と静止の割合の目安

人間が自然と受け取った試作の値から決めた目安。固定条件ではなく、試作の出発点にする。

| 項目 | 目安 | 根拠にした試作の値 |
|---|---|---|
| 動き（見せ場まで） | 2.5〜3.5 秒。見せ場が操作の後ろにある案は 3.5 秒を超えてよい | 見せ場が操作の後ろにある案: 3.7〜3.9 秒 |
| 見せ場の後の止まり（`cut`・`rest-cut`） | 1.5〜2.5 秒。動きが長い案と `rest-cut` は 1.5〜1.8 秒に寄せてよい | 見せ場が操作の後ろにある案: 1.6〜1.8 秒。`rest-cut`: 1.7 秒 |
| `cut` の開始の間 | 約 0.3 秒 | |
| `rest-cut` の周の終わりの静止状態 | 600ms 以上（`references/contract.md` の 2 節） | 0.7 秒（周の頭の間 0.3 秒と合わせて 1 秒） |
| 周期（全形式） | 4.5〜6 秒。7 秒を超えると間延びしやすい | |
| 1 周のうち静止している割合（`cut`） | 3〜5 割。動きが長い案は 3 割程度、動きが短い案は 5 割を超えてよい | 見せ場が操作の後ろにある案: 32〜37% |

- 見せ場が 1 周に複数ある案（例: 左右が交代で満ちる）は、途中の見せ場にも読める短い止まり（0.5〜1 秒）を置き、最後の見せ場に長い止まりを置く。その分周期が伸びるため、周期が目安を超えるなら見せ場を 1 つに絞る案と比べる。
- 見せ場が操作の後ろにある案（操作を終えた後の余韻や連鎖が見せ場）は、見せ場までの動きが 3.5 秒を超えてよい。条件は、超えた分が見せ場そのもの（溜め、余韻、連鎖）であり、前段の操作を引き延ばしていないこと。前段は他の案と同じ 2.5〜3 秒に収める。
  - 周期は 6 秒前後まで伸びてよいが、7 秒を超えない。そのため止まりは目安の下側に寄せ、静止の割合は 3 割程度まで下がってよい。
  - 止まりを 1.5 秒未満に削って周期を保つより、前段の動きを詰める。止まりが短いと見せ場を読む前に切り替わる。
- 動きが短い案（1 手で終わる、見せ場まで 2.5 秒に満たない）は、動きを引き延ばして目安に合わせない。間延びしてかえって操作が読みにくくなる。
  - 止まりと開始の間の目安を優先し、周期は短くなってよい。その結果、静止の割合が 5 割を超えてよい。周期が 4.5 秒未満で忙しく見えるなら、止まりを目安の上側（2〜2.5 秒）に寄せる。
  - 繰り返すほど同じ 1 手が目立つなら、止まりを目安の上側へ寄せて繰り返しの間隔を空ける。
  - 手を足して長くするなら、足した手が A（考えて選ぶ）か B（解けた瞬間）を強めるときに限る。
- 止まりと開始の間は `observe_animation.cjs` が時刻を止めて測る（`cut` は `hold` / `start beat` / `still ratio`、`rest-cut` は `payoff hold` / `closing rest` / `start beat`）。実フレームの値はフレームの粒度で最大 2 フレーム短く出る（`references/self-review.md`）。`check_animation.py` は keyframe の書き方から読める範囲だけを `WARN` / `FAIL` にする。

## 3. 緩急はセグメントごとのイージングで書く

CSS の `animation-timing-function` は keyframe と次の keyframe の間（セグメント）ごとに効く。keyframe 内に書いた値はそこから始まるセグメントに、書かなければ animation 側の値が使われる。

- keyframe は姿が変わる点（動き出し、到達、向きが変わる点、止まる点）だけに置き、各セグメントに `ease-in-out`・`ease-out`・`cubic-bezier()` などを付ける。
- イージングを細かい線形 keyframe へサンプリングして近似しない。セグメントの境目ごとに速度が不連続に変わり、60fps でもかくついて見える（特に動きの遅い区間）。`check_animation.py` は多数の keyframe に `animation-timing-function` が無い keyframes を `WARN` にする。
- 同じ向きに続く 2 つのセグメントを `ease-out` → `ease-in` でつなぐと、境目で一度止まって見える。止める意図がなければ 1 セグメントにまとめるか、境目の速度が揃う `cubic-bezier()` を選ぶ。
- 止まりのセグメントは値が同じなのでイージングは見た目に影響しない。

## 4. 構図を変えてよい範囲

静止状態は白黒版と同じ形にする（`references/contract.md` の 2 節）。次の調整は、白黒版と同じ構成要素・枠組み・視点を保ったまま、動きの途中の姿に対してだけしてよい。静止状態にも及ぶ調整が要るなら、白黒版をその形に描き直す修正案を `base_revision` で添える。

- 動きを描画域に収めるための縮小・配置調整（例: 持ち上げる・傾ける対象が viewBox からはみ出さないよう、動いている間だけ縮小して下へ寄せる）。動きの余地を作るための個々の要素の縮小・間隔調整も配置調整に含む。静止状態まで縮小・下寄せが要るなら、白黒版も同じ大きさで描き直す修正案を添える
- 役割が入れ替わる・比較を見せるために、対象の大きさを揃える（例: 白黒版で大きさが違う 2 つの対象を同じ大きさにして役割を交代させる）
- 開始の姿と動きの途中の盤の中身（状態）を、ゲームで実際に起こりうる別の状態にする（`references/exploration.md` の 2 節）

構成要素を足す・減らす、枠組み（マスの数や並び、容器の数）や視点（真上から / 横から）を変える必要が出たら、構図の調整ではなく別の題材である（線に囲まれた面に敷くゲーム固有色の面は、構成要素を足すことに当たらない。`references/contract.md` の 2 節）。仕上げを止めて再発散する（`references/exploration.md`）。

動きの全期間で viewBox からはみ出さないようにする（`observe_animation.cjs` の `min viewBox margin`）。画面の外へ出ていく表現は、切り抜き（入れ子の `<svg>` の viewport や `clip-path`）の内側で走り去らせてよい。はみ出し・重なり・余白は切り抜いた後の描画される範囲で測る（切り抜き自体が viewBox の外へ広がれば、その分ははみ出し）。

## 5. 静止状態の大きさと重さ

静止状態は白黒版と同じ形なので、大きさと位置は白黒版のものになる。重さは、ゲーム固有色の分だけ白黒版と変わる。数値と比較列をあわせて確かめる。`observe_animation.cjs` は次を出す。

- `static bounds`: 静止状態の見えている図形の外接矩形（線幅込み、viewBox 単位）と中心・下端、白黒版との中心のずれと大きさの比、他ゲームの `pictogram.svg` の中央値との大きさの比（外接矩形の面積の平方根の比）と中心・下端の中央値
- `ink coverage`: 一覧サイズ（46px）の静止状態のインク量（各画素の背景からの色の距離を前景色までの距離で割り、正方形全体で平均した値）。他ゲームの白黒版の中央値との比と、その範囲。盤のように外枠が描画域いっぱいのピクトグラムは外接矩形がほぼ同じになり重さの差が出ないため、重さはインク量で比べる。範囲を外れると `NOTE` が出る

修正案（`base_revision`）の無い候補では、`static bounds` の白黒版との差が中心 (±0, ±0)・大きさ ×1.00 になる。ずれていれば図形を写し損ねているので、形の一致を確かめる手がかりにする（線に囲まれた面を敷いても線の内側なので変わらない）。

重さは、一覧選択中サイズで他ゲームのピクトグラムと並べた比較列で、突出していないかを見る。インク量の目安は他ゲームの白黒版の範囲内で、中央値の 1.25 倍を超えたら比較列で重く見えないか特に確かめる。範囲を超えるときは、先に次を確かめる。それでも超える場合の扱いは `references/contract.md` の 3 節。

- プレイ画面でその色が淡い役割（マスの状態の地など）なら、淡いまま写せているか
- 線の太さが白黒版より太くなっていないか

### 白黒版の修正案を作るときの大きさと位置

修正案は白黒版として他ゲームと並ぶので、次を目安にする。固定条件ではなく、比較列を見る前の目安とする。

| 項目 | 目安 |
|---|---|
| 今の白黒版からの中心のずれ | 縦横それぞれ 6（viewBox の 5%）程度まで |
| 他ゲームの中央値との大きさの比 | 0.85〜1.15 倍程度（既存の白黒版どうしは 0.95〜1.05 倍、中心はほぼ (60, 60)） |

- 動きを収めるために修正案ごと縮小・下寄せすると、中心が下へずれ、大きさの比が下がる。例えば約 86% に縮小して下寄せすると、中心が約 13 下がり、他ゲームの中央値の約 0.78 倍になり、比較列でやや小さく下寄りに見える。目安を外れたら、比較列で偏り・小ささ・突出が見えないかを確かめ、縮小幅を減らす・動きの軌道を詰めるなどで寄せられないかを先に試す。
- 持ち上げる・傾けるなど動きの外形が静止状態より大きく、大きさの比と中心のずれの目安が両立しない場合は、中心の代わりに下端をそろえる。修正案の下端を他ゲームの下端の中央値（`static bounds` の `bottom`）に合わせ、上の余白を動きに使う。そのうえで大きさの比をできるだけ目安へ近づけ、比較列で下端が揃って並んで見えるかを確かめる。
- この目安から外したまま修正案を進める場合は、理由を manifest の `notes` に書く。

## 6. 動きの量の誇張

ゲーム固有色はプレイ画面の値のまま変えない（実表示で見えないときの例外は `references/contract.md` の 3 節）。動きの量（移動量・振れ幅・回転角・拡縮）は、プレイ画面の演出の量にそろえる必要はなく、ヒーローの実表示で読める大きさまで誇張してよい。プレイ画面の演出は盤全体を見る大きさで作られており、138px へ縮めると同じ量では動いたと読めないことが多い。

| 動き | 読める最小の目安（ヒーロー 138px、viewBox 1 単位 ≒ 1.15px） |
|---|---|
| 移動・振れ幅 | 4px（viewBox で約 3.5）以上 |
| 回転 | 対象の端が 4px 以上動く角度 |
| 拡縮 | 対象の縁が片側 2px（両側で 4px）以上動く量 |
| 一瞬の動き（揺れ・跳ね） | 1 往復 150ms 以上。これより速いと 60fps で 9 フレーム未満になり、ちらつきに見える |

- 上限は幾何が決める。動く対象が隣のマス・隣の対象・盤の枠に重ならないこと（`--overlap` / manifest の `overlap`）と、viewBox からはみ出さないこと（`min viewBox margin`）。盤面の隙間が小さいゲームでは、隙間の中で動ける量が読める最小を下回ることがある。
- 幾何の上限が読める最小を下回るなら、量を無理に上げて重ねない。対象を盤の外へ持ち上げる（大きさを一時的に上げて手前に来たように見せる）、色や塗りの変化と組み合わせる（ゲーム固有色の無いゲームは濃淡 2 色の入れ替えに限る。`references/contract.md` の 3 節）、動かす対象を減らして 1 つを大きく動かすなど、見せ方を変える。構図の調整（4 節）で対象を大きくできるかも検討する。
- 誇張しても D（落ち着き）を侵さないこと。常時の大振幅や、画面の他要素より強い主張にしない。

## 7. Safari（WebKit）で崩れない書き方

人間は iOS の Claude アプリ（WebKit）でもギャラリーを見る。アプリは SVG をインライン展開し、人間用ギャラリーは `<img>` の SVG 文書として表示する。古い WebKit が解釈しない値はその宣言だけが無視され、塗りが消える・ルールが効かないなどの崩れが Chromium の確認では見つからない。

- 色: リテラルは hex（`#rrggbb` / `#rrggbbaa`）か `rgb()` で書く。`oklch()`・`oklab()`・`lab()`・`lch()`・`color()`・`color-mix()`・`light-dark()`・相対色（`from`）は使わない。Tailwind のパレット色の `oklch()` は `scripts/resolve_color.py` で hex に変換する。アプリのトークンの `var()` 参照は、アプリと同じ値が効くので使ってよい。
- CSS: 入れ子のルール（`&`）を使わない（`check_animation.py` が `FAIL`）。
- 動き: `transform`・`opacity`・`fill`・`stroke`・`stroke-dashoffset` など広く対応した性質で書く。`d`（パスの形）の CSS アニメーションは、対応していない WebKit の版があり崩れうるため使わない。形を変えたいときは、変わる前後の図形を重ねて `opacity` で切り替えるか、`transform` の拡縮・`clip` で代える。
- `<img>` の SVG 文書: ページの CSS 変数・フォント・スクリプトは届かない。変数は `make_review_gallery.py` が外側の `<svg>` に与える。`<text>` のフォントはシステムフォントだけが使える（`font-family` にシステムの sans-serif 系を書く）。OS の動きを減らす設定が届かない場合がある。
- 確認: `observe_animation.cjs --webkit` は、WebKit を起動できれば静止状態・終点のスクリーンショット（`<id>-webkit-*.png`）と終点・静止状態の一致、`pageerror` を出す。起動できない環境では `NOTE: WebKit was not checked` が出るので、Safari での表示を確かめていないことを `self-review.json` の `notes` と人間への報告に残す。

## 8. 入れ子の transform

持ち上げる・運ぶ・傾けるを別々のイージングで重ねると、transform を持つ `<g>` を入れ子にすることになる。`transform-box: fill-box` の基準枠は、その要素の子孫を含めた外接矩形（子孫の transform を適用した後）で決まる。

- 親に `transform-box: fill-box` と `rotate` / `scale` を付けると、子の変形（傾き・移動）で親の外接矩形が変わり、親の回転・拡縮の中心が再生中に動く。回転の中心が揺れ、軌道がかくついたり想定外の位置へずれたりする。
- 入れ子にするなら、親は原点に依存しない `translate` だけにし、`rotate` / `scale` は最も内側の要素（中心を決めたい図形を直接含む要素）に置く。例: 外側 `translate`（持ち上げる）→ 中 `translate`（運ぶ）→ 内側 `rotate`（傾ける、`transform-origin` は回転の支点）。
- 親で回転・拡縮が必要なら、`transform-box: view-box` と viewBox 座標の `transform-origin` で中心を固定する。
- `<text>` を含む要素を `transform-box: fill-box` で拡縮・回転しない。字の外接矩形は描画の大きさに応じて画素単位で変わるため、中心が拡縮の途中で揺れる（`observe_animation.cjs` で text だけに速度の急変が出る）。`transform-box: view-box` と viewBox 座標の `transform-origin` で中心を固定する。
