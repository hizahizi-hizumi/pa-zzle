# レビューの入出力契約

`review` と `review-rules`・`review-docs`・`review-quality` が共有する形式。評価基準や規約をここへ書き写さない。

## 専門スキルへの入力

- 対象 ref: 不変のコミット SHA または固定した対象版
- 基準 ref: PR 比較時の対象元コミット。指定範囲のレビューでは省略可
- レビュー種別: `PR` / `指定範囲`
- 対象パス: 検査するファイル・機能とその周辺の調査許容範囲
- 変更目的: 既知の要件・Issue・PR から確認できる目的。推測は推測と明示
- 評価条件: 利用できる実行環境、未実施とすべき検証

## 専門スキルからの出力

```markdown
## 対象
- 専門: review-rules / review-docs / review-quality
- ref・レビュー種別・対象パス:

## Findings
- [Major] <同一出力内のID> — <問題名>
  - 場所: `path:line`
  - 影響と発生条件:
  - 根拠: <コード・正本・実行結果のパス／節>
  - 反証の確認: <確認したガード・例外・反例>
  - 状態: 実行で再現 / コードで成立を確認
  - 修正方向:

## 追加検証が必要な疑義
- <疑義、未確定の根拠、必要な検証>

## 基準側・既存の課題
- <正本の不足、変更前から存在する問題>

## 実施・未実施
- <調査した範囲、実際に行った検証、実施できない検証と理由>
```

- 重大度: Critical＝主要機能・データ・安全性の重大な破綻、Major＝通常利用の重要な不具合や契約違反、Minor＝局所的な不利益。根拠のない好みは指摘しない。
- 成立そのものが不明な候補は Findings に混ぜず「疑義」に置く。
- `Findings` の ID は同一出力内で重複しない値にする。統合時は「専門名/ID」で出典を残す。

## オーケストレーターからの出力

```markdown
## 対象と実行状況
- ref・目的・対象範囲:
- 実施した専門レビュー:
- 未実施の専門レビューと理由:

## 統合 Findings
- [Major] <問題名> — <場所>
  - 発生条件・影響・根拠・反証:
  - 検証状態:
  - 出典: <review-rules/R-1, review-quality/Q-1 等>
  - 修正方向:

## 保留・追加検証
- <矛盾・疑義・検証不能な内容>

## 実施した検証と対象外
- <確認した範囲・実施していない範囲>
```

- 同じ根本原因のみ統合し、異なる発生条件を落とさない。根拠が矛盾する場合は採否を急がず保留する。
- 実行されなかった専門レビューは `指摘なし` に数えない。
