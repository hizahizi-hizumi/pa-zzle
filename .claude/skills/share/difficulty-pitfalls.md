# 難易度の失敗パターン

過去のパズル追加・作り直しで、人間に指摘されてから直したもののうち、難易度と問題の質に関わるもの。各行は「兆候 → 予防（流れの番号と検査の ID）」。流れと検査の ID は `design-game-difficulty` スキルのもの（流れは `.claude/skills/design-game-difficulty/SKILL.md` の「流れ」、検査は `.claude/skills/design-game-difficulty/references/checks.md`）。`design-game-difficulty` の中では予防の流れと検査を当てる。ほかのスキルでは兆候だけを当て、当たった行の予防は `design-game-difficulty` スキルを起動して行う。

## 面白さ・問題の質

| パターン | 兆候 | 予防（流れ・検査） |
|---|---|---|
| 核の天井が低い | 最上位でも数秒で解ける。盤面全体を見渡せる | 流れ 6: D1・D2 |
| 罰で難しくする | 穴・即死・50/50 の推測で失敗率を上げている | 流れ 2: 追加要素を「先読みを要求するか、罰を増やすか」で分け、罰の側は挑戦に入れない |
| 生成器の偏り | 生成条件がレベルごとに1つの値に張り付く。一意化の操作で易しい盤ばかりになる | 流れ 4・6: E2。生成条件を巡回して採る |
| 素朴な解き方が戻らない | いつでも打てる手があるパズル（塗る・消すなど）で、試し置きして戻す解き方の戻した回数が0になり、上限まで進むだけになる | 流れ 3・6: D1 |
| 移植で供給が黙って変わる | 調査コード（Python 等）からの移植で、解の数は一致するが探索の打ち切り（節点数の上限など）に関わる量が違い、問題の採否や分布が変わる | 流れ 3・4: F2。結果だけでなく、採否を決める量（節点数・試行回数）の一致もテストで固定する |
| 自明・重複・単調の混入 | 回転反転の重複、角始点の蛇行、同じ形の繰り返し | 流れ 6: E3。正規化キーと解手順の指紋で重複を0にし、自明さの下限と単調さの代理を測る |
| 推論の種類の偏り | 上位の推論が1つの手筋や「仮置きの回数」だけ | 流れ 6: B5。偏りが残るなら資料に書く |
| 解き順・視点への依存 | 手筋の適用順や同点の扱いで帯が動く。UI の進め方だと深い読みが要る | 流れ 3・6: A3 |
| 同値解で難易度が再現しない | 解の道筋ごとに帯が2段以上揺れる | 流れ 1・3: 一意解を採るかを前提で決め、許すなら道筋に依存しない特徴を先に作る。A3 |

## 難易度

| パターン | 兆候 | 予防（流れ・検査） |
|---|---|---|
| 難易度の量だけで要素を外す | 難しさの指標に効かない、数問で手応えが出ない、を理由に床・駒などの要素を見送る。後で戻して問題集を作り直す。「なんでそんな外したがんの？」 | `.claude/skills/design-game-difficulty/SKILL.md` 冒頭の面白さの原則: 外す前に形を変えて試し、外すなら面白さを弱める理由を書く |
| 早すぎる収束 | つまみを1案に決めてから問題集・採点まで作り、後で境目を何度も動かす。作り切ってから「簡単すぎ」で全部作り直す。弱そうな案を数問の観察で捨てる | 流れ 3: 案を広げて上限と分かれ方を測ってから決める（`/add-puzzle` では調査で） |
| 最上位が試行錯誤で押し切られる | 一致・違反・正誤の即時表示がある。解法器のレベルは高いのに手数・時間の代理が短い。「レベル5でも簡単すぎる」 | 流れ 1・3・6: 合意した補助表示のもとで素朴な解き方（1手ずつの試し置き等）を当て（D1）、上位は押し切れない問題に限る |
| 1つのつまみだけ | レベルごとの基準表の列が1つ。レベルの説明が「〜が多い」の言い換えだけ。特徴どうしの相関が高い | 流れ 3: つまみの案を互いに違う系統で広げてから決め、B4 で系統間の相関を測る。各レベルを利用者向けの一言で言えるかを確かめる |
| 規模の扱いを誤る | 「規模は難易度ではない」を理由に全レベル同じ盤面にする／逆にレベル＝盤面サイズになる | 流れ 1: 規模をつまみに使うかを前提で決める。流れ 6: B2 で同じ規模にそろえた隣接レベルの分かれ方と、規模とレベルの相関を両方出す |
| 盤面の逆転 | 上位ほど盤面が小さい。同じレベルで広い盤面ほど早く解ける | 流れ 5・6: C2。密度をそろえ、逆転なしをテストで固定する |
| 解法器の量と人の手応えがずれる | 連鎖の深さなど解法器の量はレベルごとにきれいに上がるのに、試遊で「レベル1と3が同じ」「3の方が楽」。1本ずつの読みやすさ（例: 1つの塊だけの行・列の割合）を測ると、レベル間で大きく重なる | 流れ 3・6: 案を比べる段階で B3 を測る |
| 図柄の規則が近道になる | 左右対称などの規則で作った問題を、規則を仮定して推論を飛ばして解ける。同じレベルで規則の有無により所要時間が数倍違う | 流れ 4・6: D3。上位では規則のある作り方を除くか、規則を仮定した解き方で押し切れる割合を測る |
| 帯の中のばらつき | 「これほんまに同じ難易度？」。最上位に上限が無い | 流れ 5・6: C1・C3。帯内の分布と最弱の問題を出す。入口の広さ（初手で確定できる箇所数）を特徴に入れる |
| 解法器が緩い・深すぎる | 上位が多すぎ／少なすぎ。手で追うと浅く解ける | 流れ 6: F1。代表問題を手で追って確かめ、既知の解を落とさないことをテストで固定する |
| 状態の混同 | 評価不能を5へ、軽すぎを1へ押し込む | 流れ 5・6: A1。評価の状態を分けて返す |
| 分位点で閾値を決める | レベルの境界の値を三分位・五分位・平均で置いている。「境界を変えたら合った」。境界以外の値（候補の下限など）には当てない | 流れ 5・8: 境界の置き方は `docs/パズル/難易度開発手順.md` の工程7、ずれの原因の探し方は工程10 に従う |
| 版の波及漏れ | 問題集を作り直したのに基準時間・図鑑・SPEC が古い | 流れ 9: `.claude/skills/design-game-difficulty/references/ripple.md` を上から通し、段ごとに通したかを報告に書く |
| 1人の記録への過適合 | 校正の根拠が1人・1レベル・慣れた再プレイ | `.claude/skills/design-game-difficulty/references/recalibration.md` の 5: 件数と人数と限界を書き、全レベルを同じ根拠で動かさない |
