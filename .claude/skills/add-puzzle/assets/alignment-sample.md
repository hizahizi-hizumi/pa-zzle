# ノノグラム: 認識合わせ

**返事がほしいこと**: 下の6点で想定と違うものがあれば、番号と一言で。触れなかった点は想定どおりに進めます。あわせて「許可」の3つに OK をください。許可が無いと作り始められません。

**所要**: 約5分。

## 違ったら作り直しが大きい前提

### 1. 完成図は機械で作る模様にする

- 想定: 塊のまとまりや左右対称を持たせた模様を機械で作る。意味のある絵と題材の名前は出さない。
- 根拠: 1レベル数百問を絵で用意する手段が無い（推測）。模様なら、7×7〜10×15 の候補の約4割が仮置きなしで解けた（小さな生成器で6万候補を計測）。
- 違ったら: 生成器・問題集・難易度・クリアの演出を作り直す。

### 2. 盤面はズームなしで、幅10列まで

- 想定: 盤面とヒントをスマホの1画面に収め、幅10列・縦15行程度までにする。大きさは難易度のつまみの1つにするが、大きさだけでレベルを決めない。
- 根拠: 幅390の画面で1マス約30px、幅320で約24px（計算）。以前の試作で 10×10・29px の直接タップとなぞりを確かめている（計測）。
- 違ったら: プレイ画面・生成器・難易度・問題集・難易度選択の図・基準時間を作り直す。

### 3. 最上位でも、仮置き・推測なしで解ける問題だけにする

- 想定: どのレベルも、1本の行・列のヒントと今の盤面を読んで確定させるだけで最後まで解ける。上のレベルは、読みのつながりの長さと、手を付けられる行・列の少なさで難しくする。
- 根拠: この条件でも、最も難しいレベルの問題を500問・約1分で作れた（計測）。その代わり、熟練者には天井が低くなる（推測）。
- 違ったら: 生成器・解き方の判定・難易度・問題集を作り直す。

### 4. 正誤は出さず、ヒントに合った行・列を薄くするだけにする

- 想定: 答えと照らした正誤、数字ごとの消し込み、空いたマスへの自動の×は出さない。
- 根拠: 正誤を出すと、試しに塗って当てる遊びになる（推測）。正誤なしでは、試しに塗るだけのプレイヤーはレベル3以上をほぼ解けなかった（計測）。
- 違ったら: 難易度の測り方・問題集・スコアを作り直す。

### 5. 良いプレイは速さを主にし、塗り直しで軽く減点する

- 想定: 速さを主にし、塗ったマスを後から消した・×に変えた数で軽く減点する。×の付け外しと、盤面を最初に戻すことは減点しない。
- 根拠: 読んでから塗るプレイを称え、×はメモとして自由に使えるようにする（推測）。
- 違ったら: 記録の形とスコアを作り直す。

### 6. 表示名は「ノノグラム」、ゲーム ID は `nonogram`

- 想定: 「ピクロス」「お絵かきロジック」「イラストロジック」は使わない。
- 根拠: 一般名として広く使われている。商標の確認はしていない（推測）。
- 違ったら: 名前の付け替えが作るもの全体に及ぶ。

## 許可

- `ng/` で始まるブランチ（作業用・PR 用・試し用）の作成・push・force-push・削除
- 導入調査 Issue と、層ごとの PR の作成と更新（PR の付け替え先の変更を含む）
- 置き換える既存の PR: 無し

## どんなパズルか

各行の左と各列の上に、黒の塊の長さが順に並ぶ。ヒントどおりにマスを塗り、全行・全列が合えばクリア。ミスという扱いは無い。

面白さは、1本の行・列から「ここは必ず黒・必ず白」を決め、決めたマスが交わる列の手がかりになって次を開くつながりを追うこと。作業の量や罰で難しくしない。

## AI が決めて進めること（返事は要りません）

- 操作はタップと、行・列をなぞって続けて入れる操作。塗りと×はボタンで切り替える。
- 難易度は、大きさ・読みのつながりの長さ・手を付けられる行・列の数の組み合わせで5段階にする。
- 1レベル数百問を前もって作り、問題集にする。

## 確かめたこと・確かめていないこと

- 確かめた: 模様で一意に解ける問題を作れる割合（約4割、計測）、幅10列の1マスの大きさ（計算）、試しに塗るだけではレベル3以上が解けないこと（計測）。
- 確かめていない: 模様がクリアの報酬として足りるか、縦13〜15行が背の低いスマホに収まるか、iPhone でのなぞる操作。
