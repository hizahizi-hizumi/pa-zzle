# 認識合わせ

人間の指示が伝わったかを確かめる。AI が思い描いているパズルを、触れる見本と図のページで見せ、人間に「イメージどおりか」を見てもらう。方針を決めてもらう場ではない。あわせて、後で要る許可を得る。

## 先に調べるもの

- main の作業ツリーだけでなく、全リモートブランチ・オープンの PR と Issue を探す。名前違いやルールの言い換え（「ぶつかるまで進む」「一筆書き」など）でも探し、候補台帳・導入調査・既存ゲームも見る。
- 同じパズルや近縁が見つかったら、ページの「似ているゲームとの違い」に出し、引き継ぐか作り直すか・統合するか別にするかの AI の考えを添える。

## 見せるページ

`assets/alignment-sample.html`（ノノグラムの見本）を複製して次の構成で作り、Artifact にする。見た目と書き方は SKILL.md の「人間への知らせ方」に従う。

1. 頭: パズル名と、こう理解していること。返し方を最初の画面に置く: 合っていれば「OK」だけでよい。違えば、この会話に一言かスクショで。
2. 触ってみる: 小さな盤面で、ルールとクリアを実際に触れる見本。描画・操作・ブラウザエラーを確かめてから出す。
3. 解き方: 途中とクリアの図。何を推論して解くパズルか（作業の量や罰で難しくするものではないこと）。
4. レベルの違い: いちばん易しいレベルと難しいレベルの盤面を並べ、上で何が変わるか。
5. 似ているゲームとの違い: 既存ゲーム・候補と並べて一言ずつ。
6. 畳む参考: こちらで決めて進めること（下の「見本に映すもの」の表のうち、見本や図に映せないもの）、まだ分からないこと。

ページに書く数値（マスの大きさなど）は、計算か小さな計測で確かめたものだけにする。確かめていないものは「まだ分からないこと」へ置く。

出す前に、SKILL.md の「実行役」のページの読み手に見せ、次を返させて直す: 何のパズルかを一言で言えるか、図と説明の食い違い、分からなかった語。

## 見本に映すもの

覆ると作り直しが大きい前提を、触れる見本か図に映して見えるようにする。この表を一度全部当て、このパズルで当てはまるものを映す。映せないもの（表示名・最上位の難しさ・良いプレイの定義・図鑑の枠の数など）は、「こちらで決めて進めること」に理由と一緒に1行ずつ書く。

作り直す範囲は、覆ったときに作り直しが始まる `references/build-order.md` の項目で書く（その項目から後を作り直す）。作り直しが1つの項目で閉じる前提（音の方向、問題の特徴の切り口など）はここに置かず、AI が決めて最終レビューで聞く。

| 点 | 作り直しが始まる項目 |
|---|---|
| 既存の実装（別ブランチ・オープンの PR）を引き継ぐか作り直すか | research（全部） |
| 近縁ゲームと統合するか、別ゲームにするか | research（全部） |
| 表示名とゲーム ID（商標を避けた一般名。ID はディレクトリ名・ブランチ名になる） | research（全部の名前の付け替え） |
| ルールの変種（床や手がかりの種類など）のどれを採るか | rules |
| クリア条件の型（到達・最短手数・全回収など） | rules |
| 一意解を要求するか、同値解を許すか | rules |
| 補助・状態の知らせ（一致・違反・正誤の表示）をどこまで出すか | play-ui（難易度の素朴な解き方が補助に依るので difficulty も） |
| 待った・置き直し・リセットの有無と、良いプレイの定義（何を減点するか。リセットで減点が消えてよいか） | play-ui（score・result-records も） |
| 盤面の大きさを難易度のつまみに使うか、上位ほど広い盤面を許すか、スマホで操作できる上限はどこか | difficulty |
| 推測を要する問題を出すか | difficulty |
| 最上位をどこまで難しくするか（誰向けか） | difficulty |
| 図鑑の枠の数（レベルごとの問題集の件数） | problem-pool |

## 送り方

会話には、ページの URL と次の2つだけを書く。

- 「イメージどおりか見てください」
- 許可の問い1つ: このパズルのブランチ（作業ブランチ・層ごとの PR のブランチ・別案の使い捨てのブランチ）の作成・push・force-push・削除、導入調査 Issue と層ごとの PR の作成と更新（base の付け替えを含む）、置き換える既存の PR を閉じること（あるときだけ）

## 返事の扱い

- 「OK」や許可だけの返事は、ページのとおりで伝わっているとみなす。
- 違うと言われたら、どこが違うかを読み取り、見本と図を直して同じ URL で出し直す。読み方が二通りあって、どちらかで作り直す範囲が大きく変わるときだけ、一言で聞き返す。
- 許可は、返事で明示されたものだけを得たとする。許可に触れていない返事には、許可だけを一言で聞き直して待つ。
- 許可の一部が断られたら、断られたものの代わりの進め方（例: PR を開かずに作業ブランチの URL で最終レビューする）を推奨つきで示して待つ。
