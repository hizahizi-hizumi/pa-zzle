# 再開と main への追従

## 再開

作業ディレクトリのファイルは消えている前提で進む。

1. 導入調査 Issue を題 `導入調査: <パズル名>` で探し、合意節の識別表の写しから接頭辞を得る。確かめの記録・作業ブランチ `<接頭辞>/work`・実装前提調査から進み具合を判定する。
2. `git worktree prune` の後に、`git worktree add <作業ディレクトリ>/work -B <接頭辞>/work origin/<接頭辞>/work` で worktree を作り直す。
3. brief を合意節から、引き継ぎファイルを確かめの記録と作業ブランチの履歴から作り直し、新しい実装役に渡す。
4. 作業ディレクトリにしか無かった確かめの入力は、次の確かめの準備で作り直す。
5. 作業ブランチの分岐点より後に main で契約が変わっていれば、続きの前に、下の「main への追従の作業カード」を渡す。

## main への追従の作業カード

作業ブランチを作った後に main で契約が変わり、それに合わせて直すときに、実装役に渡す作業カードに次を書く。

- 分岐点のコミット
- 分岐点からの main のマージのうち契約を変えたもの（`.claude/rules/game-*.md`・`frontend/src/games/` 直下・`frontend/src/game-catalog/` を変えた PR の番号と、変わった契約の一言）
- 範囲: 今の main の契約に合わせ、`references/build-order.md` の各項目の完成条件を満たし直す。「一時的に置くもの」の列は当てない
