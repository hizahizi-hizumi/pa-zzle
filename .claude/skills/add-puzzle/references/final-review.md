# 最終レビュー

作り切ったものを人間に1回だけ知らせ、指摘を反映する。人間は自分の都合でスマホで見て、経緯を覚えていない。資料だけで判断が完結するようにする。

## 資料に載せる中身

資料は Artifact にし、回ごとに同じ URL で更新する。上から順に置く。

| 節 | 中身 |
|---|---|
| 所要時間と途中でやめてよい地点 | 全体で15〜20分に収める。核（ルール・挑戦・難易度の軸）を最初に置き、「ここまでで違和感があれば以降は見なくてよい」地点を示す |
| 何を作ったか | ルールと挑戦の核を数行。iPhone で遊べる URL と、レベルごとの代表問題を開く URL を少数 |
| 認識合わせからの変更点と理由 | 無ければ「無し」 |
| 見てほしい点 | 3点まで。AI が自信を持てない好みと、遊んで決めるものだけ。各点に、試す操作・開く URL・推奨と別案 |
| AI の試遊の要約 | 最初に分からなかったこと、操作のつまずき、レベルごとの手応え、つまらなかった点・理不尽だった点、既存ゲームとの比較。直したものと、直さずに残した好みや面白さの所見を分ける。AI の試遊であり人間の体感の代わりではないと書く |
| AI が決めたことと理由 | 覆すと費用が大きい順。上位3件を本文に、残りは折りたたむ。「何も言わなければこのまま」と書く |
| 前回からの差分と回帰の確認 | 2回目以降。前回の指摘の原文 → AI の読み方 → 今どうなったか（前後の画像）。前回までに直したものが戻っていないか |
| iOS 実機で見てほしい点 | この環境は Chromium しか無く確かめられないもの（ダブルタップ、描画順、拡大時のはみ出し、スクロールとの競合など） |
| 確かめていないこと・未決 | 実施できなかった検査、main との共通契約のずれ、素朴なプレイヤーでは分からないこと（人間の速さ、見渡しの負荷、面白さ）、表示名の商標確認（人間が行う）、見つけた並行作業の形跡 |
| PR 一覧とマージの順 | 下の段から |

## 作り方

- 遊べる URL は Workers Builds の check run にある版ごとのプレビュー URL（PR の無いブランチでも出る）。全段を push して URL が出てから知らせる。測ったものと遊ぶものを一致させるため版ごとの URL を主にする。この環境からプレビュー URL は開けないので、描画は手元で確かめ、そう書く。
- 画像は判断に使うものだけを、同じ条件（端末・テーマ・状態）で並べる。難易度プレビューは既存ゲームの難易度選択と並べ、ピクトグラムはゲーム一覧の実表示サイズで既存と並べる。
- 数値は判断に要る1〜2個だけにし、計測の詳細やレビューの件数は PR 本文に置く。
- 記入欄を作らない。指摘は会話かページへのコメントの一言とスクショで受け、AI が構造化する。普通に遊んだ記録の JSON を貼ってもらえれば校正に使うと添える。

## 書き方

認識合わせと「成り立たない」の知らせにも当てはめる。

- 結論から書く。最初の1〜2行で、何ができたかと、何をしてほしいか。
- 人間が開ける形（Artifact、プレビュー URL、画像）だけを渡す。`/tmp` のパスや、説明の無い内部用語（「段10」など）を使わない。
- 案を記号（案A など）だけで呼ばず、中身で説明する。難易度の案は、判定に使うつまみと利用者向けの一言で示す。
- 推奨を既定にする。推奨の理由は、このパズルで何が良くなるかを具体的に書き、不利な点も並べる。「一般的だから」で済ませない。

## 別案の出し方

- 既定は AI の推奨案で、作ったものには推奨案を入れておく。別案は、人間の好みで決まるか前提が連鎖するもので、AI が自信を持てないものだけ。1回に出す軸は少なく（目安2軸）、難易度に影響する軸は1つまで。
- 難易度への影響は、プレイ条件を引数に取る分析で同じコードのまま測り、表の要点を載せる。
- 遊んで決める別案（補助表示・待った・盤面の上限・ルールの変種など）だけ、推奨案から1軸だけ変えた使い捨てのブランチ（PR なし）を作り、問題集は小さな仮のものにする。決まったら採用案を原因の段に組み込み、ブランチは消す。
- ピクトグラムや難易度プレビューの案は、ブランチにせず画像で並べる。

## 指摘の反映

人間の指摘は短い口語で、1回に複数届く。

- 指摘ごとに、どの画面のどの要素の話かを決める。曖昧なら AI の読み方を決めてその読み方で直し、資料の「前回からの差分」に読み方を書く（聞き返して待たない）。スクショを受け取れていなければ、推測で直さずにそう書く。
- 具体的な指示にはそのまま従う。人間が選んだ案や値を、取り込むときに勝手に調整しない。
- 人間が決めたこと・覆した判断は、決まったこととして記録し、以後のサブエージェントへ渡す。
- 原因の段で直し、波及先を同じ回で一気に通す。波及の連鎖: 補助・状態の知らせ・ルール → 素朴なプレイヤーと難易度 → 問題集 → 基準時間・採点 → 難易度プレビュー → SPEC → 記録の互換。プレビューから難易度の割り当てへ戻る向きもある。
- 指摘の画面を、指摘と同じ条件で直す前と後に撮る。計測は指摘の画面そのものを測り、自分の読み方を裏付けるだけにしない。
- 反映したら品質の作り込みからやり直し、資料を更新して1回だけ知らせる。
