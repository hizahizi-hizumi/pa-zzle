# design-puzzle-tutorial

`/design-puzzle-tutorial <game>`

パズルのチュートリアルを作る、改める、または見直す。チュートリアルは、パズルを知らないプレイヤーが本物の小さな盤面を1枚解きながら、パズルのルールとゲームでの操作を身につけ、そのゲームを遊びたくなるものにする。

- `<game>`（`$ARGUMENTS`）は、対象のパズルを遊べる形にしたゲームの、`frontend/src/games/` のディレクトリ名にする。
- 本物の盤面は、本番と同じルールと盤面部品で作った盤面を指す。マスを確定させていくパズルでは完成形が1つに決まり、手を重ねて状態を進めるパズルでは完成に届く盤面にする。大きさは本番と違ってよい。

## 決まりの重さ

- 必ず守る: 「合格の条件」と「動作フロー」。条件を1つでも満たしていないか、動作フローを飛ばしていれば、作業は終わっていない。
- 迷ったらこうする: 「基本の形」。パズルに合わなければ、合格の条件を守る範囲で変えてよい。ただし `DESIGN.md` と `GAME.md` で決まっている所は変えない。
- 書いていないこと: `AGENTS.md` が読むよう求める文書と「参照する正本」で決まっていない見た目・言い回し・演出などは、作った本人が合格の条件に照らして決める。案を並べて PO に選ばせない。

## 合格の条件

どれも、できた画面を操作して数えるか測って確かめる。確かめずに満たしたことにしない。

- C1. 遊びになっている。手を離した後に自分で決める手の数が、指さしどおりに打つ手の数以上ある。そのうち1手以上は、伝えたことを順に当てはめるだけでは決まらず、盤面を読んで選ぶ手になっている。
- C2. 盤面で教える。画面の文は、場面ごとに見出し1つ（2行まで）だけにする。補足の文を添えるのは入口と完成だけにする。ルールの定義と、盤面の物の動き方を、文で説明しない。
- C3. 教えることを絞る。1枚で伝えるのは、操作と、盤面の手を決めるルール2つまでにする。それより多く要るパズルは、盤面に出す物の種類を減らして、要るルールを減らす。それでも伝えきれないことは、遊び方の説明に任せる。
- C4. 入口で答えを見せない。完成形がそのまま解き方になるパズルでは、入口に完成形を出さず、始まりの盤面を見せる。
- C5. 盤面が動かない。入口から完成まで、盤面の位置と大きさが変わらない。大きさは、同じ画面の幅で開いた本番の盤面の8割以上にする。
- C6. 伝えた順に使わせる。ルールは1つずつ伝えてすぐ盤面で使わせ、伝えていないルールが要る手を求めない。
- C7. 盤面の反応が、伝えたことと食い違わない。
- C8. 375px 幅でも、動きを減らす設定でも、伝えることが欠けたり崩れたりしない。
- C9. 本番を変えない。チュートリアルのために、本番の盤面の見た目・演出・ルールを変えない。チュートリアルだけの助けや例外を、本番にもあるように言わない。本番に足りないと感じた所は、直さずに PO へ別件として伝える。
- C10. 共通の枠と合図を変えない。`TutorialStage` と `TutorialCue` に合わない所は、盤面の側で合わせる。合わせられなければ作業を止め、どこが合わないかを PO に伝える。

## 基本の形

- 場所: プレイ画面と同じ地の上に盤面を置く。画面を覆わず、盤面の色と形を本番のまま見せる。
- 入口: ゴールの盤面（C4 に当たるパズルでは始まりの盤面）に、何をするパズルかの一文とゴールの一言を添える。「はじめる」1回で、すぐ1手目に入る。
- 手を引く: 最初に操作を教え、次のステップからはルールを1つ伝えては、そのルールで決まる手を打たせる。
  - 打つ所を、輪郭の印と、押すしぐさをする指で指し、印の所の操作だけを受け付ける。
  - ステップは、完成へ進む手だけにして、3つまでにする。進まない手でしか見せられないルールと、弾かれるために押させる手はステップにしない。手を離した後にそうなったときに、盤面の反応に見出しを1つ添えて伝える。
  - 教える操作は、この盤面を解き切るのに要るものまでにする。取り消し方や長押しなど、解くのに要らない操作は、遊び方の説明と本番に任せる。手詰まりから戻る操作は、手を離した後に手詰まりになったその場で、戻る操作を指して伝える。
- 手を離す: 盤面の手を決めるルールをすべて伝えたら、残りを自分で解かせる。
  - 盤面の反応は本番と同じにし、ルールに合わない手を打ったときだけ見出しを替える。止まったときは、次に打てる所を指で指す。
  - 盤面の一部を仕上げるたびに、仕上げた印を残す。
- 完成: 本番と同じ完成演出を見せてから、完成の一言を出し、覚えたルールを振り返って、本番へつなぐ。
- 言葉: 人が横で教える言い方の、です・ます調の普通の文にし、読点を打たない。

印、指さし、仕上げた印、違反を伝える見出し、手がかり、完成の祝い方はチュートリアルの画面だけに置き、本番には足さない（`GAME.md` の、先回りして次の手を示さないことと、操作の結果を文章ではなく盤面の反応で返すこと）。

## 動作フロー

始め方:

- 新しく作る: 1から進める。
- 既存のチュートリアルを改める: 前の表は、`frontend/src/games/<game>/tutorial/` を最後に変えた PR の本文から `【PO】` ごと引き継ぐ。1を行い、今の盤面が2-1の条件を満たすかを確かめる。満たさなければ2から作り直す。`TutorialOverlay` に載っていれば、3で `TutorialStage` へ載せ替える。
- 改めずに見直した結果だけを求められた: 6を新しいサブエージェントに頼み、結果を報告する。PR は開かない。

1. パズルを知る:
   1. 該当パズルの仕様、遊び方の説明、`frontend/src/games/<game>/puzzle/` のルールの実装を読み、ルールを書き出す。
   2. 開発サーバーでレベル1と2を1問ずつ解き、ゲームでの操作を確かめる。
   3. 書き出したルールを、「このチュートリアルで伝える（C3 の数まで）」「盤面に出さないので要らない」「遊び方の説明に任せる」に分ける。
   4. `references/reference-tutorial.md` を読み、`frontend/src/games/water-sort/tutorial/` と `frontend/src/games/water-sort/ui/WaterSortTutorial.tsx` を見本として読む。
2. 盤面とステップを決める:
   1. 次をすべて満たす盤面を、一時的なスクリプトで総当たりして探し、1枚選ぶ。見つからなければ、盤面に出す物の種類か大きさを変えて探し直す。
      - 1-3で「伝える」に分けたルールだけで解ける。
      - ステップが3つまでで、どのステップの手も完成へ進む。
      - 手を離した後に自分で決める手が、ステップの手の数以上ある（C1）。
      - 手を離した後に、盤面を読んで選ぶ手が1手以上ある（C1）。
      - 2-3の条件を満たす。
   2. 盤面とステップの表を `assets/step-table.md` の形で作る。
   3. 選んだ盤面・ステップ・手の判定を `frontend/src/games/<game>/tutorial/tutorial.ts` に書き、次の条件を同じディレクトリのテストに残す。
      - 手を引く間: マスを確定させていくパズルでは、操作を教える手はゴールの盤面と一致し、ルールを伝えた後の各手はそれまでに伝えたルールで1つに決まる。手を重ねて状態を進めるパズルでは、どの手も完成へ進み、それまでに伝えたルールで打てる。印の手を打つ途中の盤面も、まだ伝えていないルールに反しない。伝えるルールのそれぞれが、1つ以上の手の決め手になる。
      - 手を離した後: 2-1の、自分で決める手の数と、盤面を読んで選ぶ手がある。マスを確定させていくパズルでは、伝えたルールで残りが解き切れる。手を重ねて状態を進めるパズルでは、どう進めても完成へ届くか、届かなくなったときに戻る操作で続けられる。
   4. `commit-pr` スキルを起動して `tutorial/` をコミットし PR を開く。PR 本文に2-2の表を載せる。
3. 実装する: 「参照する正本」のうち動作フローの3の行を読む。本番の盤面部品と演出を使い、共通の進行と `TutorialStage` に載せる。盤面は、`TutorialStage` が渡す領域いっぱいに、どの場面でも同じ大きさで置く。
4. 言葉を整える: 表の一言を、出る場面・改行位置と一緒に見直す。新しいサブエージェントに `references/review-requests.md` の「編集者役」で挙げさせ、`【PO】` の言い回しを除いて直す。画面の一言を変えたら、PR 本文の表も揃える。
5. 自分で通して測る: `AGENTS.md` の全品質検証を通す。375px 幅の通常の設定と、375px 幅の動きを減らす設定で、入口から完成まで自分で操作し、場面ごとにスクリーンショットを撮る。同じ操作の中で次を測り、`assets/measurement.md` の形で PR 本文に載せる。1つでも合格の条件から外れていれば、直してから測り直す。
   - 指さしどおりに打つ手の数と、手を離した後に自分で決める手の数（C1）。
   - 場面ごとの、見出しの行数と、補足の文の有無（C2）。
   - 伝えるルールの数（C3）。
   - 入口・各ステップ・手を離した後・完成での、盤面の要素の位置と大きさ（`getBoundingClientRect`）。同じ幅で開いた本番のレベル1の盤面の大きさ（C5）。
6. 見直す: 新しいサブエージェントに、`references/review-requests.md` の「審査役」「作る側」「遊ぶ側」で見直させる。3つは並行して走らせてよい。
   - 審査役が不合格にした条件は、直す。
   - 合格の条件から外れた所と不具合は直す。同じ原因の所がほかにないか探し、まとめて直す。
   - 遊ぶ側が迷った・止まった・つまらないと書いた所は、どの条件に当たるか原因を探して直す。
   - それ以外は、直す価値があるものだけ直す。
7. PO に見せる: PR のプレビュー URL を添えて確認を頼む。5の測った結果、自分で決めたこと、直さなかった指摘を、判断を求めずに短く添える。出来に点数や評価の言葉を付けない。実端末でしか確かめられない所（ブラウザの上端と下端の色、音）は、確かめていないと書く。

進め直し:

- 6で直したら、言葉を変えたときは4から、それ以外は5から、5まで進め直す。合格の条件から外れた所か不具合を直したときだけ、もう一度6を行う。
- 6は最初を含めて2回までにする。2回目で審査役が不合格にした条件が残ったら、7へ進まず、残った条件と、満たせない理由を PO に伝える。

PO から指摘を受けたとき:

1. どの合格の条件に当たるかを特定し、6と同じように直して進め直す。6の回数は0に戻す。
2. どの条件にも当たらない指摘は、そのチュートリアルだけを直し、この Skill には足さない。PO が言い回しを決めたときは、表のその一言に `【PO】` を付ける。
3. 合格の条件を見直したほうがよいと考えたときは、`AGENTS.md` の進め方に従って、条件を直す案と直さない案を PO に出す。

## 出力先

- 盤面・ステップ・手の判定と、2-3のテスト: `frontend/src/games/<game>/tutorial/`
- 画面と、ゲームのホーム・プレイ中のメニューからの入口: `.claude/rules/game-structure.md` の「チュートリアル」節の置き場所
- 盤面とステップの表と、5で測った結果: PR 本文
