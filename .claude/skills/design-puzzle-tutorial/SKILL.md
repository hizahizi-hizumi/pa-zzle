# design-puzzle-tutorial

`/design-puzzle-tutorial <game>`

パズルのチュートリアルを作る、改める、または見直す。チュートリアルは、パズルを知らないプレイヤーが本物の小さな盤面を1枚解きながら、パズルのルールとゲームでの操作を身につけ、そのゲームを遊びたくなるものにする。

- `<game>`（`$ARGUMENTS`）は、対象のパズルを遊べる形にしたゲームの、`frontend/src/games/` のディレクトリ名にする。
- 本物の盤面は、本番と同じルールと盤面部品で作った盤面を指す。マスを確定させていくパズルでは完成形が1つに決まり、手を重ねて状態を進めるパズルでは完成に届く盤面にする。大きさは本番と違ってよい。

## 決まりの重さ

- 必ず守る: 「大原則」と「動作フロー」。大原則を1つでも破っているか、動作フローを飛ばしていれば、作業は終わっていない。
- 迷ったらこうする: 「基本の形」。パズルに合わなければ、大原則を守る範囲で変えてよい。ただし `DESIGN.md` と `GAME.md` で決まっている所は変えない。
- 書いていないこと: `AGENTS.md` が読むよう求める文書と「参照する正本」で決まっていない見た目・言い回し・演出などは、作った本人が大原則に照らして決める。案を並べて PO に選ばせない。

## 大原則

- P1. 本物の盤面を1枚、プレイヤー自身の手で解いて完成させる。
- P2. 何をするパズルかとゴールを、操作より先に見せる。
- P3. ルールは1つずつ伝えてすぐ盤面で使わせ、伝えていないルールが要る手を求めない。
- P4. 言葉は、盤面と操作で伝わらないことだけにする。
- P5. 手の正誤への盤面の反応は、伝えたことと食い違わない。
- P6. 375px 幅でも、動きを減らす設定でも、伝えることが欠けたり崩れたりしない。
- P7. チュートリアルだけの助けや例外を、本番にもあるように言わない。
- P8. チュートリアルのために、本番の盤面の見た目・演出・ルールを変えない。本番に足りないと感じた所は、直さずに PO へ別件として伝える。

## 基本の形

- 場所: プレイ画面と同じ地の上に、本番と同じ大きさの盤面を置く。画面を覆わず、盤面の色と形を本番のまま見せる。
- 入口: 盤面の上にピクトグラムとゲームの名前を大きく見せ、ゴールの盤面に、何をするパズルかの一文とゴールの一言を添える。ゴールは、これから解く1枚の完成形にする。「はじめる」1回で、名前を上部へ動かし、盤面をゴールから始まりへ替えて、すぐ1手目に入る。
- 手を引く: 最初に操作を教え、次のステップからはルールを1つ伝えては、そのルールで決まる手を打たせる。
  - 打つ所を、輪郭の印と、押すしぐさをする指で指し、印の所の操作だけを受け付ける。印以外の操作は盤面を変えず、指を出し直して印へ目を向けさせる。
  - ステップは、完成へ進む手だけにして、3つ前後に収める。進まない手でしか見せられないルールと、弾かれるために押させる手はステップにせず、手を離した後にそうなったときに、盤面の反応に一言を添えて伝える。
  - 教える操作は、この盤面を解き切るのに要るものまでにする。取り消し方や長押しなど、解くのに要らない操作は、遊び方の説明と本番に任せる。
- 手を離す: 盤面の手を決めるルールをすべて伝えたら、残りを自分で解かせる。
  - 残りは、伝えたルールを順に当てはめるだけの一本道にせず、そのパズルの考えどころが1回入る盤面にする。
  - 盤面の反応は本番と同じにし、ルールに合わない手を打ったときだけ一言を足す。止まったときは、次に打てる所を指で指す。
  - 盤面の一部を仕上げるたびに、仕上げた印を残し、一言と進み具合で応える。
- 進み具合: 入口から完成までを、上部の線と「済んだ数 / 全体の数」で見せる。数えるのは、終えたステップと、手を離した後に仕上げた所。
- 完成: 本番と同じ完成演出を見せてから、完成の一言を強めて出し、覚えたルールを振り返って、本番へつなぐ。
- 言葉: 一言は盤面のすぐ下に1つだけ出す。人が横で教える言い方の、です・ます調の普通の文にし、読点を打たない。

印、指さし、仕上げた印、違反を伝える一言、手がかり、完成の祝い方はチュートリアルの画面だけに置き、本番には足さない（`GAME.md` の、先回りして次の手を示さないことと、操作の結果を文章ではなく盤面の反応で返すこと）。

## 動作フロー

始め方:

- 新しく作る: 1から進める。
- 既存のチュートリアルを改める: 前の表は、`frontend/src/games/<game>/tutorial/` を最後に変えた PR の本文から `【PO】` ごと引き継ぐ。1を行い、今の盤面が2-1と2-3の条件を満たすかを確かめる。満たさなければ2から作り直す。満たせば、2-2の表と2-3のテストを揃えて2-4を行い、3へ進む。`TutorialOverlay` に載っていれば、3で `TutorialStage` へ載せ替える。
- 改めずに見直した結果だけを求められた: 6の「作る側」と「遊ぶ側」を新しいサブエージェントに頼み、結果を報告する。PR は開かない。

1. パズルを知る: 該当パズルの仕様、遊び方の説明、`frontend/src/games/<game>/puzzle/` のルールの実装を読み、ルールを書き出す。開発サーバーでレベル1と2を1問ずつ解き、ゲームでの操作を確かめる。
2. 盤面とステップを決める:
   1. 2-3の条件を満たし、ステップが3つ前後で、手を離した後に考えどころが1回入る小さめの盤面を、一時的なスクリプトで総当たりして探し、1枚選ぶ。
   2. 盤面とステップの表を `assets/step-table.md` の形で作る。
   3. 選んだ盤面・ステップ・手の判定を `frontend/src/games/<game>/tutorial/tutorial.ts` に書き、次の条件を同じディレクトリのテストに残す。
      - 手を引く間: マスを確定させていくパズルでは、操作を教える手はゴールの盤面と一致し、ルールを伝えた後の各手はそれまでに伝えたルールで1つに決まる。手を重ねて状態を進めるパズルでは、どの手も完成へ進み、それまでに伝えたルールで打てる。印の手を打つ途中の盤面も、まだ伝えていないルールに反しない。1で書き出したルールのうち盤面の手を決めるもののそれぞれが、1つ以上の手の決め手になる。
      - 手を離した後: 2-1の考えどころが入る。マスを確定させていくパズルでは、伝えたルールを当てはめるだけで残りが解き切れる。手を重ねて状態を進めるパズルでは、どう進めても手詰まりにならない。手詰まりを避けられないパズルでは、手詰まりから戻る操作（待ったや盤面を戻すなど）を、解くのに要る操作として手を引く間に教える。
   4. `commit-pr` スキルを起動して `tutorial/` をコミットし PR を開く。PR 本文に2-2の表を載せる。
3. 実装する: 「参照する正本」のうち動作フローの3の行を読む。本番の盤面部品と演出を使い、共通の進行と `TutorialStage` に載せる。ゲーム独自の印や合図の見た目は足さない。
4. 言葉を整える: 表の一言を、出る場面・改行位置と一緒に見直す。新しいサブエージェントに `references/review-requests.md` の「編集者役」で挙げさせ、`【PO】` の言い回しを除いて直す。画面の一言を変えたら、PR 本文の表も揃える。
5. 自分で通す: `AGENTS.md` の全品質検証を通す。通常の設定に加えて、375px 幅と、動きを減らす設定でも入口から完成まで自分で操作し、スクリーンショットで確かめる。入口から1手目へ替わる間と、完成の一言が出る間は、途中の姿も撮って確かめる。
6. 見直す: 新しいサブエージェントに、`references/review-requests.md` の「作る側」と「遊ぶ側」で見直させる。2つは並行して走らせてよい。
   - 大原則の違反と不具合は直す。同じ原因の所がほかにないか探し、まとめて直す。
   - 遊ぶ側が迷った・止まったと書いた所は、どの大原則に反しているか原因を探して直す。言葉に引っかかった所は、同じ種類の言葉が他にも残っているとみて、4でまとめて直す。
   - それ以外は、直す価値があるものだけ直す。
7. PO に見せる: PR のプレビュー URL を添えて確認を頼み、自分で決めたことと、直さなかった指摘を、判断を求めずに短く添える。実端末でしか確かめられない所（ブラウザの上端と下端の色、音）は、確かめていないと書く。

進め直し:

- 6で直したら、言葉を変えたときは4から、それ以外は5から、5まで進め直す。大原則の違反か不具合（遊ぶ側の迷いから見つけたものを含む）を直したときだけ、もう一度6を行う。
- 6は最初を含めて2回までにする。2回目で出た大原則の違反と不具合は直して自分で確かめ、7へ進む。

PO から指摘を受けたとき:

1. どの大原則に反しているかを特定し、6と同じように直して進め直す。6の回数は0に戻す。
2. どの大原則にも当たらない指摘は、そのチュートリアルだけを直し、この Skill には足さない。PO が言い回しを決めたときは、表のその一言に `【PO】` を付ける。
3. 大原則を見直したほうがよいと考えたときは、`AGENTS.md` の進め方に従って、大原則を直す案と直さない案を PO に出す。

## 出力先

- 盤面・ステップ・手の判定と、2-3のテスト: `frontend/src/games/<game>/tutorial/`
- 画面と、ゲームのホーム・プレイ中のメニューからの入口: `.claude/rules/game-structure.md` の「チュートリアル」節の置き場所
- 盤面とステップの表: PR 本文
