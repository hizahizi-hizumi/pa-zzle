# design-puzzle-tutorial

`/design-puzzle-tutorial <game>`

パズルのチュートリアルを作る、改める、または見直す。チュートリアルは、パズルを知らないプレイヤーが本物の小さな盤面を1枚解きながら、パズルのルールとゲームでの操作を身につけ、終えたらレベル1を自分で進められて、そのゲームを遊びたくなるものにする。

- `<game>`（`$ARGUMENTS`）は、対象のパズルを遊べる形にしたゲームの、`frontend/src/games/` のディレクトリ名にする。
- 本物の盤面は、本番と同じルールと盤面部品で作った盤面を指す。マスを確定させていくパズルでは完成形が1つに決まり、手を重ねて状態を進めるパズルでは完成に届く盤面にする。大きさは本番と違ってよい。

## 決まりの重さ

- 必ず守る: 「大原則」と「動作フロー」。大原則を1つでも破っているか、動作フローを飛ばしていれば、作業は終わっていない。
- 迷ったらこうする: 「基本の形」。パズルに合わなければ、大原則を守る範囲で変えてよい。ただし `DESIGN.md` と `GAME.md` で決まっている所は変えない。
- 書いていないこと: `AGENTS.md` が読むよう求める文書と「参照する正本」で決まっていない見た目・言い回し・演出・ステップの数などは、作った本人が大原則に照らして決める。案を並べて PO に選ばせない。

## 大原則

- P1. 本物の盤面を1枚、プレイヤー自身の手で解いて完成させる。
- P2. 何をするパズルかとゴールを、操作より先に見せる。
- P3. ルールは1つずつ伝えてすぐ盤面で使わせ、伝えていないルールが要る手を求めない。
- P4. 言葉は、盤面と操作で伝わらないことだけにする。
- P5. 手の正誤への盤面の反応は、伝えたことと食い違わない。
- P6. 375px 幅でも、動きを減らす設定でも、伝えることが欠けたり崩れたりしない。
- P7. チュートリアルだけの助けや例外を、本番にもあるように言わない。本番で減点になることを、気軽にできることとして勧めない。
- P8. 伝えたことだけで、本番のレベル1を進められる。
- P9. 手を離した後は、プレイヤーが求めるまで手がかりを出さない。自分で解いている間に割り込まない。

## 基本の形

- 見せ方: プレイ画面と同じ地の上で見せる。印・合図・覆い・一言の枠は全ゲームで同じにし、盤面と手順の組み立てはそのパズルに合わせる。
  - 本番では見出しにあり、手を決めるのに要る表示（残りの数、操作の切り替えなど）は、チュートリアルの上部に置けないので、ゲーム側で盤面のすぐ上に置く。
- 印と覆い: どこに印（輪郭と指）を付け、どこを覆いから抜くかは、`SCR-008` の決まりに従う。印が押す所と目指す所の2つの意味を持つと、どちらかで迷わせるため。
  - 印は輪郭（`mark`）に、押すしぐさをする指（`pointer`）を添える。指を出さない所（`SCR-008`）では輪郭だけにする。
  - 指は、下に物が詰まるマス目では `placement="center"` で押す物の中に置く。スワイプで動かす物を指すときは `swipe` で向きを渡す。動かす物と着く所が別で、着く所に輪郭を付けるときは、動かす物の指を `outlined={false}` で指だけにし、輪郭を1つにする。指が盤面の外へはみ出して一言に重なるときは、ゲーム側で盤面の領域に余白を取る。
  - 覆いから抜く所に `TutorialSpotlight` を置き、盤面の要素に `TUTORIAL_SPOTLIGHT_AREA_ATTRIBUTE` を付けて、覆う間だけ `spotlighting` を渡す。
- 入口: ゴールの盤面、ゲームの名前、何をするパズルかの一文と、ゴールの盤面に添える補足を1つ見せ、「はじめる」1回で始まりの盤面へ替えて、すぐ最初の手順に入る。ゴールは、これから解く1枚の完成形にする。
- 手を引く: 最初の手順で操作を1つ教え、次の手順からはルールを1つ伝えては、そのルールで決まる手を打たせ、最後に、レベル1を進めるのに要る読み（該当パズルの仕様の難易度1の挑戦）を1回使わせる。ルールを知っているだけでは進められないパズルでは、その読みを手順にする。
  - 教える範囲: 伝えるルールは本番のレベル1を進めるのに要るものに、教える操作はこの盤面を解き切るのに要るものに絞る。手詰まりを避けられないパズルでは、手詰まりから戻る操作も解くのに要る操作として教える。
    - 操作が複数あるパズルでも、最初の手順で教える操作は1つにする。ほかの操作は、それが初めて要る手順の直前か、その手順の中で教える。
    - 範囲に入らないこと（駒の動きの一覧、上のレベルで初めて出る要素、取り消し方や長押しなど）は、遊び方の説明と本番に任せる。チュートリアルの上部の「遊び方」からその場で開けるよう、遊び方の説明を `TutorialOverlay` に渡し、ルールを任せたときは一言でその在りかを伝える。P8 は、遊び方の説明と合わせて満たせばよい。
  - 考えずに通れない形: ルールを伝える手順と読みを使わせる手順は、印を押すだけでは通れず、伝えたルールを自分で使って手を決める形にする。形は操作の型で選ぶ。
    - 押して値を選ぶパズル（マスを押すたびに変わるなど）: 何も考えずに印の所を1回操作した結果がそのルールの違反になる盤面にするか、打つ所や置く物を自分で選ばせる。
    - 向きを選ぶ・なぞる・滑らせるパズル: 印は行き先（止まる所・着く所）だけに付け、向きや道筋は自分で選ばせる。
    - 手を重ねて状態を進めるパズル（車を出す、液体を注ぐなど）: 最後の読みの手順は印を付けず、どの手を打つかを自分で選ばせる。
  - 手への応え: 正しい手には盤面の合図で応える。手順を終えた手の結果を見せている間は、見え終わるまで今の一言を保ち、次の手順の一言を先に出さない（手本: takuzu）。
    - 印のある手順では、印の所の操作だけを受け付ける。印以外の操作は盤面を変えず、印を濃くし直して目を向けさせる。
    - ルール上は成り立つが手順に無い手と、印の無い手順で外れた手は、黙って無視せず、今の手順で何をするかが分かる一言で返す。黙っていると、ルールで打てない手だと読まれるため（P5）。
    - ルールの違反は本番と同じ違反の表示で見せ、一言で何に当たったかと直し方を返す。取り消せない違反（地雷を踏むなど）を体験させるなら1回だけにし、盤面を最初からやり直させず、踏んだ結果を分かったこととして手順を先へ進める。
  - 進め方: 教える進め方は、確実に解き進められることを優先し、最短でなくてよい。ただし本番でミスとして数えられる行為（入れ間違い、誤った王手など）は勧めない（P7）。
- 手を離す: 盤面の手を決めるルールと読みをすべて伝えたら、残りを自分で解かせる。残りには、伝えた読みがもう一度ずつ要るようにする。
  - 盤面の反応は本番と同じにし、その上に、ルールに合わない手へ、何に当たったか・直す所・直し方を一言と直す所の印で添える。違反が盤面に残らないパズルでは、印を付ける物が無いので一言だけで返す。答えと違うだけの手に返すのは、本番でも途中で正誤を示すゲームだけにする。
  - 手がかりは、プレイヤーが「ヒント」を押したときだけ、手を引く間と同じ見せ方で出し、次の手で消す。
- 完成: 本番と同じクリア演出を見せ、その完了のあとに覚えたルールを振り返ってから本番へつなぐ。
- 一言: です・ます調の普通の文で書き、句点を打たず、語を半角スペースで区切らない。読点は、語を並べる間に要るときだけ打つ。言うべきことを省かず、3行に収まる長さ（全角45字ほど）までにする。補足は1つまでにする。
  - 画面は一言を文節の切れ目で折り返す（`PhrasedText`）ので、折り返すための改行は置かない。改行（`\n`）は、2つの文を並べるときと、1つの文を意味のまとまり（主部と述部など）で2行に分けたいときだけ置く。表と下の例では、改行を `/` で書く。
  - 文の主体は遊ぶ人にする。物を主語にした定義（「XはYです」）で言わず、遊ぶ人が何をするか、何ができるか、盤面に何が見えるかで言う。ルールは「〜できません」「〜してください」で言わない。
  - 画面に見えている物を、見えているとおりの、ふだんの言葉で呼ぶ。ルールを整理するために作った呼び名（「穴」「通れる隣」「道の終わり」「行き先」「置き場所」など）を、遊ぶ人に向けて使わない。書いたら、文に出てくる名詞を1語ずつ、その場面のスクリーンショットと突き合わせる。同じ物は、どの文でも同じ名前で呼ぶ。
  - 短くまとめるために中身を省かない。操作の文は、押す物が何で、押すと何が起きるかまで言う。「この」「どの〜も」「〜にも」で済ませず、何を指すか、何に加えてなのかを書く。意味を足していない語（「ルールどおりに」「自分で」「あとから」）は削る。
  - 言い方は、規則を当てて決めず、下の例（左が直す前、右が PO の直し）と、人が書いたパズルの説明（ニコリの各パズルのルールと「遊び方」など）を読んで、同じ言い方になっているかで決める。今の文が例と同じ言い方なら変えない。
    - 「このボトルをタップします」→「注ぐボトルをタップして選択します」
    - 「このマスをタップします」→「このマスをタップして四角を置きます」
    - 「同じ色の上にも注げます」→「空のボトルだけでなく同じ色の上にも注げます」
    - 「どのレベルも同じルールです」→「全てのレベルが同じルールです」
    - 「すべてのマスを四角か丸でルールどおりに埋めるパズルです」→「すべてのマスを四角か丸で埋めるパズルです」
    - 「行どうしも列どうしもすべて違う並びになります」→「全ての行と行、列と列で違う並びにします」
    - 「あとから置き直さないほど高く評価されます」→「置き直さないほど高評価です」
    - 「島から出る橋は数字と同じ本数です」→「島からは数字と同じ本数/橋が出ます」
    - 「数字は周りの8マスにある地雷の数です」→「周り8マスにある/地雷の数が書かれています」
    - 「左上の4は行き先が2つです」→「左上の4の島から橋を架けられる島は2つです」
    - 「穴以外のすべてのマスを1回ずつ通る道を引くパズルです」→「全てのマスを一筆書きでなぞるパズルです」
    - 「そこは穴です」→「そこは通れません」
    - 「通れる隣が1つのマスは道の終わりになります」→「マスが1つのみ隣接するマスがゴールになります」
    - 「右上で旗に切り替えて地雷のマスに置きます」→「右上のボタンで旗に切り替えて地雷のマスに旗を置きます」
    - 「次に玉を取れる王手を毎回かけます」→「自分の番はいつも王手をかけます」
  - 一言は、PO が読んで決める。書いた文は、場面のスクリーンショットと並べて PO に見せる。PO が直した文は、直す前の文と対にして上の例に足す。

印、正しい手への合図、違反を伝える一言、手がかりはチュートリアルの中だけに置き、本番には足さない（`GAME.md` の、先回りして次の手を示さないことと、操作の結果を文章ではなく盤面の反応で返すこと）。本番の盤面の見た目・演出・振る舞いは、チュートリアルのために変えない。

## 動作フロー

始め方:

- 新しく作る: 1から進める。
- 既存のチュートリアルを改める: 前の表は、`frontend/src/games/<game>/tutorial/` を最後に変えた PR の本文から `【PO】` ごと引き継ぐ。1を行い、今の盤面が2-3の条件を満たすかを確かめる。満たさなければ2から作り直す。満たせば、2-2の表と2-3のテストを揃えて2-4を行い、3へ進む。
- 改めずに見直した結果だけを求められた: 6の「作る側」と「遊ぶ側」を新しいサブエージェントに頼み、結果を報告する。PR は開かない。

1. パズルを知る: 該当パズルの仕様、遊び方の説明、`frontend/src/games/<game>/puzzle/` のルールの実装を読み、ルールを書き出す。仕様の難易度1の挑戦を読み、レベル1を進めるのに要る読みを書き出す。書き出したルールを、レベル1を進めるのに要る教えるルールと、遊び方の説明に任せるルールに分ける（基本の形の「教える範囲」）。開発サーバーでレベル1と2を1問ずつ解き、ゲームでの操作と、その読みで実際に進むことを確かめる。
2. 盤面とステップを決める: 「参照する正本」の手本3つの `tutorial/` と `ui/<Game>Tutorial.tsx` を読んでから始める。
   1. 2-3の条件を満たす小さめの盤面を、一時的なスクリプトで総当たりして探し、1枚選ぶ。
   2. 盤面とステップの表を `assets/step-table.md` の形で作る。
   3. 選んだ盤面について、次の条件を `frontend/src/games/<game>/tutorial/` のテストに残す。
      - 手を引く間: 操作を教える手はゴールの盤面と一致し、ルールを伝えた後の各手は、それまでに伝えたルールで決まる。印の手を打つ途中の盤面は、まだ伝えていないルールに反しない（伝えているルールの違反に必ず伴う違反は除く）。1で分けた教えるルールと、書き出した読みのそれぞれが、1つ以上の手の決め手になる。取り消せない違反を体験させる手と、手詰まりから戻る操作を教える手順は、伝えたルールで決まらなくてよく、その後の盤面からゴールへ届く。
      - 考えずに通れないこと: ルールを伝える各ステップと読みのステップが、基本の形の「考えずに通れない形」のうち、そのパズルの操作の型の形になっている。押して値を選ぶパズルでは、印の所を1回操作しただけの盤面がそのルールの違反になるか、打つ所や置く物の選び方が2通り以上ある。向きを選ぶ・なぞる・滑らせるパズルでは、印が行き先だけに付く。手を重ねて状態を進めるパズルでは、最後の読みのステップに印が無く、打てる手が2通り以上ある。
      - 手を離した後: マスを確定させていくパズルでは、伝えたルールを当てはめるだけで残りが解き切れる。手を重ねて状態を進めるパズルでは、どう進めても手詰まりにならない。手詰まりを避けられないパズルでは、教えた操作（待ったや盤面を戻すなど）で手詰まりから戻れる。レベル1を進めるのに要る読みが、手を離した後にも要る。
   4. テストをコミットしてブランチを push し、PR を開いて、PR 本文に2-2の表を載せる。PR はゲームごとに分け、ほかのゲーム・ルール・この Skill の変更を入れない。
3. 実装する: 本番の盤面部品と演出を使い、共通の進行と画面に載せる。印・合図・覆いは共通の部品だけで描き、ゲーム独自の見た目を足さない。ゲームのホームとプレイ中のメニューにチュートリアルを渡し、そこから開けるようにする。
4. 言葉を整える: 表の一言を、出る場面・改行位置と一緒に見直す。新しいサブエージェントに `references/review-requests.md` の「編集者役」で挙げさせ、`【PO】` の言い回しを除いて直す。画面の一言を変えたら、PR 本文の表も揃える。
5. 自分で通す: `AGENTS.md` の全品質検証を通す。通常の設定に加えて、375px 幅と、動きを減らす設定でも入口から完成まで自分で操作し、スクリーンショットで確かめる。考えずに印を押すだけの進め方と、わざと違反する進め方、手順に無い手を打つ進め方も通し、どの手にも黙らずに応えることを確かめる。入口から最初の手順、手を置いた瞬間、手順の切り替わり、完成の瞬間は、100〜200ms おきの連写で動きを確かめる。
6. 見直す: 新しいサブエージェントに、`references/review-requests.md` の「作る側」と「遊ぶ側」で見直させる。2つは並行して走らせてよい。
   - 大原則の違反と不具合は直す。同じ原因の所がほかにないか探し、まとめて直す。
   - 遊ぶ側が迷った・止まったと書いた所は、どの大原則に反しているか原因を探して直す。言葉に引っかかった所は、同じ種類の言葉が他にも残っているとみて、4でまとめて直す。
   - 遊ぶ側が、教わったことと遊び方の説明だけではレベル1を進められなかったら、P8 の違反として2から作り直す。
   - それ以外は、直す価値があるものだけ直す。
7. PO に見せる: PR のプレビュー URL を渡して確認を頼む。そのときに、自分で決めたことと、直さなかった指摘を、判断を求めずに短く添える。

進め直し:

- 6で直したら、盤面かステップを作り直したときは2から、言葉を変えたときは4から、それ以外は5から、5まで進め直す。2から作り直したときは、6の回数を0に戻す。大原則の違反か不具合を直したときだけ、もう一度6を行う。
- 6は最初を含めて2回までにする。2回目で出た大原則の違反と不具合は直して自分で確かめ、7へ進む。

PO から指摘を受けたとき:

1. どの大原則に反しているかを特定し、6と同じように直して進め直す。6の回数は0に戻す。
2. どの大原則にも当たらない指摘は、そのチュートリアルだけを直し、この Skill には足さない。PO が言い回しを決めたときは、表のその一言に `【PO】` を付ける。
3. 大原則を見直したほうがよいと考えたときは、`AGENTS.md` の進め方に従って、大原則を直す案と直さない案を PO に出す。

## 出力先

- 盤面・ステップ・手の判定と、2-3のテスト: `frontend/src/games/<game>/tutorial/`
- 画面: `frontend/src/games/<game>/ui/<Game>Tutorial.tsx`
- ゲームのホームからの入口: `frontend/src/views/<Game>HomeView.tsx` から `GameHomeScreen` の `renderTutorial` に渡す
- プレイ中のメニューからの入口: `frontend/src/games/<game>/ui/<Game>Play.tsx` から `GamePlayFrame` の `renderTutorial` に渡す
- 盤面とステップの表: PR 本文
