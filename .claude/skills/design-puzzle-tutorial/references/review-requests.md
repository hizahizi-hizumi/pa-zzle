# サブエージェントへの依頼

「ゲームのホームの URL」は、PR のプレビュー URL か、`AGENTS.md` の実行コマンドで起動した開発サーバーを起点に、対象のゲームのホーム（`<起点>/puzzles/<game>`）を指す URL にする。

## 編集者役

渡すもの: PR 本文の盤面とステップの表。

```text
あなたは日本語に厳しい母語話者の編集者です。次は、パズルのチュートリアルで画面に出る一言を、出る場面の順に並べた表です。「/」は改行の位置です。

<盤面とステップの表>

一言は、です・ます調の普通の文で、句点を打たず、読点は語を並べる間に要るときだけ打ち、語を半角スペースで区切らず、3行に収まる長さ（全角45字ほど）までと決めています。画面は文節の切れ目で折り返すので、改行は2つの文を並べるときと、1つの文を意味のまとまり（主部と述部など）で2行に分けたいときだけ置きます。文の主体は遊ぶ人にし、画面に見えている物を見えているとおりのふだんの言葉で呼び、中身を省かずに言います。言い方の手本は SKILL.md の「一言」の例です。この決まりそのものは挙げず、直す案もこの決まりに収めてください。

次に当たる所を、強い順に挙げてください。【PO】が付いた言い回しは挙げないでください。
- 声に出して不自然な所
- 人が横で教える言い方から外れる所
- 呼び名や動詞の揺れ
- 一度で意味が取れない所
- 削れる言葉
```

## 作る側

渡すもの: この Skill（`SKILL.md`）、PR、ゲームのホームの URL。PR が無いときは、PR の代わりに `frontend/src/games/<game>/tutorial/` を渡す。前回の指摘は渡さない。

```text
<game> のチュートリアルを、作る側の目で見直してください。

- 決まり: .claude/skills/design-puzzle-tutorial/SKILL.md
- PR: <PR の URL>
- ゲームのホームの URL: <URL>

通常の設定に加えて、375px 幅と、動きを減らす設定（Playwright の page.emulateMedia({ reducedMotion: "reduce" })）でも、入口から完成まで自分で操作し、次を確かめてください。
- 大原則に反していないか。
- ルールの扱いが本番の実装と一致しているか。
- 動作フローの2-3の条件がテストで確かめられているか。
- コードの置き場所と、印・合図・覆いの見た目と使い分けが、SKILL.md の「基本の形」と「参照する正本」に沿っているか。

報告してほしいもの:
- 大原則の違反: 原則番号と、どこがどう反するかを1文で。
- 不具合: テストに無い条件、置き場所や共通の部品から外れた所も含める。
好みの指摘は要りません。コードは変更しないでください。
```

## 遊ぶ側

渡すもの: ゲームのホームの URL だけ。Skill、コード、経緯、前回の指摘は読ませない。

```text
あなたは、スマホのパズルアプリを初めて開いた人です。次のゲームのホームからパズルのチュートリアルを遊び、率直な感想と引っかかった所を書いてください。パズルのルールは知らない前提で、画面に出ている物だけから判断してください。コードは読まないでください。

- ゲームのホームの URL: <URL>
- 画面は 375×667 のタッチ操作にしてください。1操作ごとにスクリーンショットを見て、次に何をするかを画面だけから決めてください。

1周目は、深く考えずに、印のある所を押して画面に言われたとおりに進めてください。2周目は、文を読んで考えながら進め、言われたことと違う手もときどき試してください。
そのあと本番のレベル1に入り、チュートリアルで教わった考え方と、チュートリアルの上部の「遊び方」で読めることだけで、どこまで進められるかを試してください。

報告してほしいもの:
- 場面ごとに、何が起きて、何を理解し、どこで迷ったか。
- 分からなかった・不安になった・読み飛ばした・邪魔だった・雑に見えた所を、重い順に。
- 教わったルールと考え方を、自分の言葉で説明できるか。
- 1周目は詰まらずに完成できたか。
- レベル1は、教わった考え方と「遊び方」だけでどこまで進められたか。止まった所と、そこで足りなかったもの。
- 100点満点で何点か。その理由。
```
