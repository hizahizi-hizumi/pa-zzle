# サブエージェントへの依頼

「ゲームのホームの URL」は、PR のプレビュー URL か、`AGENTS.md` の実行コマンドで起動した開発サーバーを起点に、対象のゲームのホーム（`<起点>/puzzles/<game>`）を指す URL にする。

## 編集者役

渡すもの: PR 本文の盤面とステップの表。

```text
あなたは日本語に厳しい母語話者の編集者です。次は、パズルのチュートリアルで画面に出る一言を、出る場面の順に並べた表です。「/」は改行の位置です。

<盤面とステップの表>

次に当たる所を、強い順に挙げてください。【PO】が付いた言い回しは挙げないでください。
- 声に出して不自然な所
- 人が横で教える言い方から外れる所
- 呼び名や動詞の揺れ
- 一度で意味が取れない所
- 削れる言葉
```

## 作る側

渡すもの: この Skill（`SKILL.md`）、PR、ゲームのホームの URL。PR が無いときは、PR の代わりに `frontend/src/games/<game>/tutorial/` を渡す。前回の指摘は渡さない。

```text
<game> のチュートリアルを、作る側の目で見直してください。

- 決まり: .claude/skills/design-puzzle-tutorial/SKILL.md
- PR: <PR の URL>
- ゲームのホームの URL: <URL>

通常の設定に加えて、375px 幅と、動きを減らす設定（Playwright の page.emulateMedia({ reducedMotion: "reduce" })）でも、入口から完成まで自分で操作し、次を確かめてください。
- 大原則に反していないか。
- ルールの扱いが本番の実装と一致しているか。
- 動作フローの2-3の条件がテストで確かめられているか。
- コードの置き場所と、印や合図の見た目が、SKILL.md の「参照する正本」に沿っているか。

報告してほしいもの:
- 大原則の違反: 原則番号と、どこがどう反するかを1文で。
- 不具合: テストに無い条件、置き場所や共通の部品から外れた所も含める。
好みの指摘は要りません。コードは変更しないでください。
```

## 遊ぶ側

渡すもの: ゲームのホームの URL だけ。Skill、コード、経緯は読ませない。画面の幅や設定、試す操作、感想の観点も指示しない。

```text
次のゲームのホームから、パズルのチュートリアルを初めてのプレイヤーとして入口から完成まで遊び、感想を自由に書いてください。

- ゲームのホームの URL: <URL>
```
