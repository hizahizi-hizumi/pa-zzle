# review-docs 評価用の正解候補

レビュー担当には渡さない。提供ファイルは仮想的な断片であり、実リポジトリの内容ではない。

- `DOC-HIGHER-REQUIREMENT`: 要件は9を許可するが、実装は `n < 9` で9を拒否する。要件とコードの不整合を指摘する。実装に責任がある。
- `DOC-STALE-SPEC`: 仕様と実装は一致しない。ただし `.claude/rules/documents.md` ではコードとテストが下位の仕様より強いので、根拠のないコード不具合とせず、古い仕様の更新候補として扱う。要求・要件が別にあると推測しない。
- `DOC-HISTORICAL-ADR`: ADR は過去の意思決定であり現行基準そのものではない。現在の `DESIGN.md` と実装が整合するため、古い ADR の文言を根拠にコードの違反を指摘しない。

構成上の整合と製品としての妥当性は別の評価である。誤検出と真の矛盾の両方を測る。
