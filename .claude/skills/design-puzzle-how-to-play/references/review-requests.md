# サブエージェントへの依頼

「ゲームのホームの URL」は、今のブランチで `AGENTS.md` の実行コマンドで起動した開発サーバーを起点に、対象のゲームのホーム（`<起点>/puzzles/<game>`）を指す URL にする。PR のプレビュー URL は PO に渡すものにし、サブエージェントには渡さない。

## 編集者役

渡すもの: スクラッチの `how-to-play-<game>-tables.md` の項目の表と呼び名の表。6の後に頼むときは、遊ぶ側が言葉に引っかかった感想も添える。

```text
あなたは日本語に厳しい母語話者の編集者です。次は、パズルの遊び方（ヘルプ）の画面に出る文を、入口とタブごとに並ぶ順に書いた表と、文に出る呼び名・動詞と、それがプレイ画面のどこに出るかの表です。「文」の欄の「/」は文節の切れ目です。

文は、人が横で盤面を指しながら教える敬体の話し言葉にしています。「〜します」「〜です」と言い切り、手が通るかのルールは遊ぶ人が盤面でする手を動詞で言い、盤面の形のルールは目指す形で言い、禁止（〜てはいけません）ではなくできることか目指す姿で言い、依頼（〜してください）と終助詞（ね・よ）とテーマで変わる色の名前は使いません。並べる語は中黒（・）でつなぎます。

<項目の表>

<呼び名の表>

<遊ぶ側が言葉に引っかかった感想（あれば）>

次に当たる所を、強い順に挙げてください。【PO】が付いた言い回しは挙げないでください。
- 声に出して不自然な所
- 読点のある文（読点を外し、外すと読み違えるなら文を分けるか語順を変えた形を返す）
- 人が横で教える言い方から外れる所
- 仕様書の定義文（「〜は、…です」）や、システムの言葉（物を役割で呼ぶ言葉、操作を仕組みで言う言葉。水のパズルなら「注ぎ先」「注ぐボトルに選べない」）に聞こえる所
- 呼び名や動詞が、遊び方の中で、またはプレイ画面・チュートリアルと揺れている所
- 一度で意味が取れない所
- どのパズルにも当てはまる、何も言っていない言葉（「ルールどおりに」など）
- 削れる言葉
```

## 作る側

渡すもの: このスキル（`SKILL.md`）、スクラッチの `how-to-play-<game>-tables.md`（無いとき（見直しだけのとき、3-3 で控えたほかのゲーム）は、表の行を「表: 無し（基本の形から変えたわけはコードから読み取ってください）」にする）、遊び方の画面・図・テストのパス、ゲームのホームの URL。前回の指摘は渡さない。Playwright が使えないときは、依頼文の Playwright の段落と、ブラウザで確かめる行（迷いそうな所で開く、図の大きさと質感）を外す。

```text
<game> の遊び方（ヘルプ）を、作る側の目で見直してください。

- 決まり: .claude/skills/design-puzzle-how-to-play/SKILL.md（その「決まりの重さ」で必ず守るとした文書も読んでください）
- 表: <how-to-play-<game>-tables.md のパス>（基本の形から変えたわけは、項目の表の「根拠」の欄にあります）
- コード: <遊び方の画面・図・テストのパス>
- ゲームのホームの URL: <URL>

Playwright でブラウザを動かし、次の組み合わせで、ゲームのホームとプレイ中のメニューの両方から遊び方を開き、3つのタブを最後まで見て、例とゴールの盤面を押してください。
- PC 1280px（細かいポインター）
- スマートフォン（Playwright の devices['iPhone 13']）
- スマートフォンで、動きを減らす設定（page.emulateMedia({ reducedMotion: "reduce" })）

そのうえで、次を確かめてください。
- SKILL.md の「決まりの重さ」で必ず守るとした文書と大原則に反していないか。
- ルール・操作・状態の知らせ・補助・数え方が、本番の実装と一致し、過不足が無いか。
- 1問を途中まで遊び、迷いそうな所でプレイ中のメニューから遊び方を開いたとき、その答えに当たる項目がすぐ見つかるか。
- 例の ✓ / ✕ が、盤面を見た印象と食い違っていないか（✕ の例に、通る手やできる形が見えていないか。✕ のわけが押す前に読めるか）。
- 例が、本番のその入口（指・マウス）と同じ反応だけを返しているか（本番に無い反応や、ほかの入口の反応を借りていないか）。触った後も、判定と印が今の盤面と合っているか。
- 呼び名と動詞が、プレイ画面とチュートリアルと揺れていないか。
- SKILL.md の動作フローの3-2に挙げたことが、本番の関数と照らすテストで確かめられているか。
- 図が、プレイ画面の盤面と見比べて同じ物に見える大きさと質感か。
- コードの置き場所と共通の部品の使い方が、.claude/rules/game-structure.md の「遊び方」と SKILL.md の「出力先」に沿っているか。

報告してほしいもの:
- 違反: 反した文書の項か大原則の番号と、どこがどう反するかを1文で。
- 不具合: テストに無い条件、本番と食い違う所、置き場所や共通の部品から外れた所も含める。
- 基本の形からの外れ: SKILL.md の「基本の形」と違う所と、そのパズルに合わせて変えたわけが読み取れるか。
好みの指摘は要りません。コードは変更しないでください。
```

## 遊ぶ側

渡すもの: ゲームのホームの URL だけ。スキル、コード、経緯は読ませない。画面の幅や設定、試す操作、感想の観点も指示しない。

```text
次のゲームのホームから、初めてのプレイヤーとして遊び方（ヘルプ）を読んで遊び、感想を自由に書いてください。ブラウザは Playwright で動かし、画面だけを見て遊んでください。リポジトリのコードと文書は読まないでください。

- ゲームのホームの URL: <URL>
```

## 採点役

渡すもの: ゲームのホームの URL、ゲームの表示名（`frontend/src/games/<game>/display-name.ts`）、`DESIGN.md` のパス。スキル、経緯、前回の採点は渡さない。

```text
あなたは、一流の商用モバイルパズルアプリの UI を見てきたプロダクトデザイナーです。パズルアプリ pa-zzle の「<ゲームの表示名>」の遊び方（ヘルプ）画面を、遊び方の画面単体として採点してください。アプリのほかの画面と同じ出来かではなく、遊び方単体の出来を見ます。基準は「一流の商用パズルアプリの遊び方として、そのまま出せるか」です。厳しく見てください。

- ゲームのホームの URL: <URL>（右上の「メニュー」の「遊び方」から開けます）

実物を自分で開いて確かめてください。Playwright でブラウザを動かし、スマートフォン（Playwright の devices['iPhone 13']）と PC 1280px の両方で、すべてのタブを最後まで見て、例の盤面と冒頭の盤面を実際に押してください。スマートフォンでは、タブを上に留めたまま中身を少しずつ送り、送っている途中の重なりも見てください。

前提: アプリのデザイン原則は <DESIGN.md のパス> にあります。読んでから採点し、これに反する提案はしないでください。コードは変更しないでください。

報告してほしいもの:
1. 120点満点の点数（100点が「一流の商用アプリの水準」、120点が「その中でも抜きん出ている」）と、根拠を3行で。
2. 点数を下げている所を、重い順に最大10個。それぞれ、どの画面のどこか、何が商用品質に見えないか、どう直すと良いか（具体的に）、遊び方の中だけで直せるか（本番の盤面の見た目・動きや、チュートリアルを変えないと直らないか）。ピクセル単位のずれ（中央に置いたはずの物が寄っている、行の頭がそろっていない、余白が不ぞろい）、文字の大きさと太さの強弱が付いていない所、重なり順の崩れ、何も言っていない文（どのパズルにも当てはまる言葉）、例の ✓ / ✕ と盤面の見た目が食い違う所（✕ なのにできるように見える例）も拾ってください。
3. すでに一流の水準に達していて変えないほうがよい所。
```
