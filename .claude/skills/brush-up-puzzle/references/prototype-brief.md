# 試作を作るサブエージェントへ渡す文面

`<…>` を埋めて、そのまま渡す。サブエージェントの種類は `general-purpose` にし、モデルは `CLAUDE.md` の決まりに従って選ぶ。

```text
pa-zzle（<リポジトリのパス>）のパズル「<表示名>」（`frontend/src/games/<game>/`）の、盤面の見た目と手応えを作り直す、遊べる試作を1つ作ってほしい。人がこの試作を触って、この方向で作るかどうかを決める。

## 方向

<方向の名前と一文>
姿: <盤面を何として描くかの一言>
強める瞬間: <どの気持ちよい瞬間を、どう強めるかの一言>
<深掘りのときだけ: 作り方: （この案がどこで勝負するかの一文）。出発点にする試作: `prototypes/（選ばれた試作の id）/`。これを読んでよい。>

場面ごとの返し方:
<場面ごとの一言を、場面の数だけ>

今の画面の部品に手を足すのではなく、この方向の姿として、盤面の要素をすべて作り直す。光の向き、素材、構図を画面全体で1つに決めてから細部を作る。場面ごとの返し方は出発点で、強める瞬間がもっとはっきり気持ちよくなる返し方があれば替えてよい。

## 作るもの

- 置き場所: `frontend/src/games/<game>/ui/prototypes/<id>/`。この中のファイルだけを作る・変える。ほかのファイルは変えない。
- 入口: `<id>/<部品名>.tsx` に、今の画面をそのまま描く仮の部品が置いてある。これを、同じ名前・同じ props のまま試作に書き換える。切り替え口には登録済みで、`<開発サーバーの URL と、brief.md の「通す問題」の入口パスに look=<id> のクエリを足した URL>` で開ける。
- 変えてよいもの: 盤面の姿、動き、操作への反応、地。
- 変えないもの: <brief.md の「変えないもの」>
- 保つもの: 今の画面の操作できる要素の読み上げ名（`aria-label`）とボタンの名前。通すスクリプトと撮影が、これで場所を求めるため。
- 足さないもの: 解く場面に、盤面で伝わらないことを補う説明の文字を足さない。振動は使わない。音は、強める瞬間に要るときだけ足してよい。フォントや画像を、実行時に外から読み込まない。
- 後回しにするもの: ダークモード、PC 幅、動きを減らす設定への対応は、選ばれた後に作る。ここでは作らない。
- 一時ファイル: `frontend/` の中には置かず、`<出力先>` の下に置く。
- ほかの試作: 自分のディレクトリの外の試作は読まない。同時に作られているので、`typecheck` で出るほかのディレクトリのエラーは無視する。

## 出来の目安

この方向で作れる最も良い画面を作る。描き込みの水準は、同じアプリで仕上がりを認められた次の画面に合わせる: <brief.md の「物差し」の画像のパス>。配置・文字の読みやすさ・動きのつながり・演出の間の操作まで作り込む。

省いてよいのは、テスト・文書・`.claude/rules/` に沿った書き方だけ。少なくとも次を満たす。

- `bun run --cwd frontend typecheck` で、自分のディレクトリのファイルにエラーが無い。
- 1問を始めから完成まで遊べる。
- 強める瞬間が、実際に操作したときに、今の画面よりはっきり気持ちよい。
- 物差しの画面と並べて、描き込みが足りなくない。撮った画像を物差しと見比べて直すことを、少なくとも3回くり返す。
- 演出の間に次の操作をしても、通らない・別の所に当たることが無い。

## 確かめ方

開発サーバーは起動済み（<開発サーバーの URL>）。起動・停止しない。`.claude/skills/share/playtest-driver.mjs` の冒頭のコメントを読み、driver をポート <driver のポート>、端末 `iphone`、出力先 `<出力先>` で起動して、上の URL を開き、`<brief.md の「通す問題」の通すスクリプトのパス>` で1問を通す（使い方はスクリプトの冒頭のコメントを読む）。通すのは、作り終えてからの確かめの1回でよい。途中の見た目は、盤面の一部を自分で操作して確かめる。<通す問題で出会えない場面があるときだけ: （場面の名前）は、（入口パス）を開いて（操作の列）で起こせる。>終わったら driver を `quit` で止める。

## 返すもの

- 作ったファイルの一覧
- 狙いを1行
- 始まり・操作の途中・完成の瞬間の画像のパス
- できなかったこと
```
