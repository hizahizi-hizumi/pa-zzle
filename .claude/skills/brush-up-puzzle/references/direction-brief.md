# 方向を出すサブエージェントへ渡す文面

`<…>` を埋めて、そのまま渡す。サブエージェントの種類は `general-purpose` にし、モデルは `CLAUDE.md` の決まりに従って選ぶ。4つのうち2つには「題材あり」、2つには「題材抜き」を渡す。

題材抜きの文面では、パズルの名前と、題材から来る言葉（水、瓶、数字、マス、駒など）を使わない。`brief.md` の「変えないもの」「気持ちよい瞬間」「場面」を、「場所」「列」「しるし」「かたまり」のような題材を持たない言葉に書き直す。盤の大きさや並び方はルールなので残す。

## 題材あり

```text
スマートフォンで遊ぶパズルゲーム「<表示名>」の、プレイ画面の見た目と手応えを作り直す「方向」を8個出してほしい。ファイルは下の画像を読むだけで、何も書き換えない。コードは読まない。

今の画面: <始まり・操作の途中・完成の瞬間の画像のパス> を Read で見る。

変えないもの（ルールと操作の意味）:
<brief.md の「変えないもの」>

<共通の指示>
```

## 題材抜き

```text
スマートフォンで遊ぶ、あるパズルゲームのプレイ画面を新しく作る。その見た目と手応えの「方向」を8個出してほしい。ファイルは読まず、書き換えもしない。考えて書くだけでよい。

パズルのルール（題材はまだ決まっていない。何として描くかから考える）:
<題材抜きの言葉に書き直した「変えないもの」>

<共通の指示>
```

## 共通の指示

上の2つの `<共通の指示>` に、次を入れる。題材抜きの文面では、気持ちよい瞬間と場面も題材抜きの言葉にする。

```text
このパズルを遊んでいて気持ちよい瞬間:
<brief.md の「気持ちよい瞬間」>

出してほしいのは、この気持ちよい瞬間を、今よりはっきり強く感じさせる方向。変わっていること、ほかと違うことは目当てにしない。誰でも思いつく素直な方向で構わない。その方向で作った画面を、遊ぶ人が一目見て「これは遊びたい」「触ると気持ちよさそう」と思うかで考える。

「方向」の書き方:
- 名前と、どんな画面かの一文。
- 盤面を何として描くかを一言。<題材ありだけ: 今の画面の姿に限らない。>
- どの気持ちよい瞬間を、どう強めるかを一言。
- 次の場面がどう見え、どう返るかを一言ずつ。
  場面: <brief.md の「場面」を番号つきで>

条件:
- 遊ぶ人に、どれが入るか・次にどこを見るべきか・どこへ動かせるかを、先回りして示さない。機能や操作の種類を足さない。
- 8個は、互いに別の画面になること。同じ画面の言い換えを並べない。
<2周目だけ: 次の方向はすでに出て、どれも選ばれなかった。（前の周の方向の名前と一文の一覧）選ぶ人の返事は次のとおり。（PO の返事）これを踏まえて出す。>

返す形: 方向ごとに「番号. 名前: 一文」「姿: 一言」「強める瞬間: 一言」と、その下に場面の番号ごとの一言。前置きや分類は要らない。日本語で。
```
