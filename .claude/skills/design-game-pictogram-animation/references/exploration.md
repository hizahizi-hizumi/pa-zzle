# ギミック探索方法

`/design-game-pictogram-animation` の発散と候補整理に使う。目的は案数を稼ぐことではなく、面白さが上振れる可能性のある異なる方向を、安い段階で広く確保することにある。

## 1. 先にアイデアカードを作る

初回発散ではコードを書かない。1案につき、次だけを短く記録する。

```yaml
id: siphon-01
name: サイフォン
idea: 液体が一度上方向へ吸い上げられてから隣の容器へ流れ込む
interesting_point: 重力の予想を一度外す
references:
  - 液体の移送
  - 送り側と受け側の容器
```

`interesting_point` は評価点ではない。「この案のどこが面白くなる想定か」を後から比較するための仮説である。

## 2. 一回の長い発散へ依存しない

同じ prompt で案数だけ増やすと、後半が既存案の言い換えになりやすい。複数回を独立させ、毎回違う刺激を与える。

刺激として使える観点:

- 実ゲームの操作を短く誇張する
- 状態変化や達成の瞬間を主役にする
- 題材固有の物理現象を強くする
- 物理的な予想を一度だけ外す
- 対象ではなく対象同士の反応を主役にする
- 最後の一滴、最後の一台など終端の「間」を主役にする
- 極端に少ない動きで成立させる
- 一つの変化から連鎖させる

これはカテゴリごとの生成ノルマではない。同じ局所解から離れるための刺激として使う。

## 3. 初回の量は探索空間に合わせる

ウォーターソート程度の単純なピクトグラムなら、30〜60枚程度のアイデアカードを安価に作り、意味の重複を整理してから15〜25程度を試作する運用が一つの目安になる。

この数値は固定条件ではない。

- 10案で十分に異なる方向が揃えば増やさない
- 50案出しても同系統しかなければ、案数ではなく発散の刺激を変える
- 実装コストが高い題材では、アイデアカードを増やして試作数を減らす

## 4. 微差と別ギミックを分ける

次の差だけでは、通常は同じギミックとして扱う。

- 速度
- 移動距離
- 回転角度
- イージング
- 同じ出来事の開始時刻

一方、同じ「注ぐ」動作でも、次は別方向として残しうる。

- 普通に注ぐ: ゲーム操作そのものの気持ちよさ
- 最後の一滴だけ遅れる: 終端の間
- 一度逆流してから注ぐ: 予想外の挙動

動作の形ではなく `interesting_point` が異なるかを見る。

## 5. 重複整理では外れ値を残す

アイデアカードをまとめるときは、似た `interesting_point` とゲーム参照を持つものを同系統として扱う。

次を優先する。

- 同系統の微差をすべて試作しない
- 各系統から代表を残す
- 説明しにくいが他と明らかに異なる案を、無理に既存系統へ入れない
- モデルが「成功しそう」と感じる案だけで寄せない

初回試作の目的は勝者予測ではなく、方向性を人間が比較できることにある。

## 6. 試作では核心以外を削る

試作は完成品ではない。`interesting_point` が伝わる最小実装にする。

例えば「最後の一滴」が核なら、液体の完全な流体変形より、主要部分が移動した後に一滴だけ残り、遅れて落ちることを優先する。

完成品質の細部に時間を使うのは、人間が方向を選んだ後にする。

## 7. 選択後は探索範囲を狭める

一つの方向が選ばれた後は、その方向を選んだ理由を変えずに4〜8案程度へ分岐するのが一つの目安になる。

変える候補:

- 見せ場までの間
- 軌道
- 複数要素の反応順序
- 誇張の強さ
- 終わり方
- 他候補から部分採用する表現

さらに方向が定まったら1〜3案へ絞って仕上げる。

## 8. 再発散する条件

次の場合は、選択済み方向の微調整を続けず広い発散へ戻る。

- 面白さの核自体が弱いと人間が判断した
- ゲームらしさを維持すると選択方向が成立しない
- 静的ピクトグラムを大きく崩さないと成立しない
- 候補間の差がすべてタイミングや量の微差になった

再発散は失敗ではない。未知の探索空間へ戻るための通常の操作として扱う。
