# アニメーション候補の比較とレビュー

`/design-game-pictogram-animation` の試作候補を同一条件で比較し、人間へ見せる前の品質確認と、人間の方向指定を次の探索へ渡すための形式を定義する。

## 1. manifest

比較候補は JSON manifest でまとめる。

```json
{
  "title": "Water Sort animation exploration",
  "candidates": [
    {
      "id": "siphon-01",
      "file": "siphon-01.svg",
      "family": "吸引・圧送",
      "hypothesis": "液体が一度上方向へ吸われてから隣の容器へ流れ込む",
      "interesting_point": "重力の予想を一度外す"
    }
  ]
}
```

必須項目:

- `id`: manifest 内で一意な識別子
- `file`: manifest からの相対パスまたは絶対パス
- `hypothesis`: 何が起きる案か
- `interesting_point`: どこが面白くなる想定か

任意項目:

- `family`: 同じ方向をまとめる表示名
- `notes`: 実装上の制約や比較時に残したい補足

## 2. ギャラリーで見るもの

`make_review_gallery.py` は、候補を同じ表示サイズで並べる。候補アニメーション自体は JavaScript が無効でも表示できるようにし、JavaScript が有効な環境では次の操作を追加する。

- 全候補を最初から再生
- 全候補を一時停止 / 再開
- 候補を個別に最初から再生
- 候補ごとに簡易な判断とメモを付ける
- 現在のレビュー結果を JSON として表示する

レビュー結果は採点表ではない。次の方向指定だけを扱う。

- `candidate`: ベース候補として残す
- `explore`: この系統をさらに掘る
- `part`: 一部の発想や表現だけ使う
- `reject`: この方向は捨てる

## 3. 人間へ見せる前の実描画レビュー

`check_animation.py` の PASS は構造検査の結果であり、人間へ提示できる品質を保証しない。人間レビューへ進む前に、エージェント側で実ブラウザを使って候補を確認する。

現在の `DESIGN.md` を確認したうえで、実際の利用箇所に近い背景と実表示サイズで各候補を少なくとも 1 ループ通して観察する。開始状態だけ、または数枚の代表スクリーンショットだけではレビュー完了としない。

少なくとも次を見る。

- 開始状態が元の静的ピクトグラムとして成立している
- 主要な動きとギミックの見せ場で、対象同士の位置関係が破綻しない
- 容器外へのはみ出し、液体や駒の分離、不自然な重なりがない
- 回転中心、クリップ、変形によって一瞬だけ壊れるフレームがない
- 実表示サイズで、何が起きたかを追える
- 終了状態またはループ復帰時に、不自然なジャンプや崩れがない
- `pageerror` と意図しない `console.error` がない

問題があれば修正または候補から除外し、修正した候補はもう一度 1 ループ確認する。人間へ提示するのは、この実描画レビューを通過した候補だけにする。

この段階では「面白くなさそう」という予測で候補を捨てない。役割は、ギミックの多様性を残したまま、人間が比較できる最低品質へ揃えることに限定る。

## 4. 人間レビューで考えること

次は点数化せず、会話の材料として確認する。

- 見ていて面白い、またはもう一度見たいと思う要素があるか
- そのゲームだから成立する動きになっているか
- 小さい表示でも何が起きたか読み取れるか
- 意外性が意味不明さになっていないか
- 何度か見ても煩雑さが先に立たないか
- 候補全体ではなく、一部分だけ残したいものがあるか

「面白いがゲームらしくない」「普通だが最後の間だけ良い」のような混ざった評価をそのまま残してよい。

## 5. レビュー結果の使い方

人間の発言やギャラリー出力を、次の探索への指示として扱う。

例:

```text
siphon-01 を掘る
last-drop-02 の最後の間を混ぜたい
bridge-01 は液体表現だけ使いたい
その他は除外
```

Skill はこの指示を「候補の順位」としてではなく、残す面白さの核と変更可能な部分として解釈する。

## 6. 仕上げ後の再レビューと完成判断

最終候補を仕上げた後も、人間へ提示する前に Section 3 と同じ実描画レビューを繰り返す。微調整によって面白さの核が消えたり、一時フレームだけ破綻したりしていないことを 1 ループ通して確認する。

最終的な採用は人間が判断する。自動検査やエージェントの実描画レビューを面白さの承認として扱わない。

候補が技術的には成立していても、採用したい方向がなければ再発散する。
