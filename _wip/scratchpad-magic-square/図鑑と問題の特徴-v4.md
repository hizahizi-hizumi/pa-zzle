# 魔方陣 調査: 図鑑と問題の特徴

調べた版: 作業ブランチ `magic-square/work` の worktree（未コミット。難易度の調査コードは 10:12 の版）。難易度は版 4 の C2。書いたもの:

- 観点の結果: この文書
- 調査コード: `docs/パズル/導入調査/魔方陣/調査コード/magic_square_features.py`（読むモデル・分類・生成は `magic_square_difficulty.py` を呼ぶだけ）

## 結論

**条件つきで成り立つ。** 推奨の切り口は「盤面」「最初の数（2個ごとにまとめる）」「空きだけの列（まとめない）」の3つ。今の実装（盤面と最初の数、3個ごと）は2点で足りない。

- L1 では絞り込みの軸が1つも出ない。L1 は 4×4 だけで、最初の数は 568問すべて 8個だった。
- 盤面を選んだ後、L3 の 6×6 と L5 の 5×5 では、最初の数の 95% が1つの選択肢に入る。

問いごとの答え:

- **レベルの中で値が分かれるか**: 3つとも成り立つ（盤面は L1 を除く）。
  - 盤面: L2〜L5 は2種、L1 は 4×4 だけ。割合は、問題集でどの盤面を何問にするか（問題供給の観点）で決まる。
  - 最初の数: L1 は1種（8個）。L2〜L5 は 8〜10種。2個ごとにまとめるとレベル全体で 5〜8種・最多 25〜56%、盤面を選んだ後も 2〜5種・最多 41〜86%。
  - 空きだけの列（与える数が1つも無い縦・横・斜めの列）: L1 は3種（0本 63%・1本 33%・2本 4%）。L2〜L5 は 3〜4種・最多 54〜81%。ただし 6×6 は 0本が 82〜94% を占める。
- **ほかの案の特徴と重ならないか**: 条件つきで成り立つ。
  - 最初の数と盤面は、同じレベルの中で盤面をまたいで測ると +0.76〜+0.88。ただし最初の数の値の帯は盤面ごとに分かれ、まとめた選択肢が盤面をまたぐことは無かった（幅2・幅3とも、どのレベルも）。盤面を選ぶと、ほかの盤面の最初の数は数0になって選べない（GAME-009）。2つの軸は入れ子になり、最初の数は盤面の中を分ける役になる。
  - 空きだけの列は、同じレベル・盤面の中で最初の数と −0.43〜+0.09（L4 5×5 の 33問だけ −0.63）、同じレベルの中で盤面と −0.28〜−0.45。
- **難易度の写しにならないか**: 空きだけの列は成り立つ。最初の数は条件つきで成り立つ。盤面は難易度の盤面の割り当てそのもの。
  - 空きだけの列: レベルとの順位相関は −0.03（同じ盤面だけで 5×5 +0.12・6×6 +0.18）。同じレベル・盤面の中で、読みの量（組の突き合わせ・巡・段3）との順位相関の絶対値は 0.45 以下、試し置きの戻しとは 0.34 以下。
  - 最初の数: 同じ盤面ではレベルと −0.63（5×5）・−0.58（6×6）。ただし隣のレベルと値が重なる（5×5 の 10 / 50 / 90 パーセンタイル: L2 11/12/13、L3 10/11/12、L4・L5 9/10/11）ので、レベルの写しにはならない。同じレベル・盤面の中では、組の突き合わせの回数と −0.15〜−0.72（L4・L5 では段3の所の数と −0.39〜−0.73）。読みの種類ではなく、読む所の数（作業量）の目安になる。
  - 盤面: レベルと +0.57（難易度の観点の値と同じ）。
- **採らない案**:
  - 1マスだけ空いた列・いちばん埋まった列の空き・入口のマス: L2 と L3 の境目そのもの。L3〜L5 では全問同じ値で、レベルとの順位相関は −0.85・+0.85。ADR-0004 の「難易度の写し」に当たる。
  - 配置の対称: 669問中1問しか当たらない。埋まった列: 85〜100% が0本。
  - 大きい数の数: 列の構造を保つ並べ替え × 補数で値が変わる（全部で変わらない問題は 16%。並べ替えは数を変えないので、補数で変わる）。盤面と +0.68〜+0.84。
  - 角の数: 列の構造を保つ並べ替えで値が変わる（全部で変わらない問題は 23%）。4×4 では、難易度が除いた四隅の仮想の列に触れる。
  - 2マス空いた列: 読みの量と −0.57、1マス空きの列と −0.78。
  - 斜めの空き: L1 の中で段1の巡の数と +0.50。
  - 大きい数と小さい数の差、1 と最大の数: 値は分かれ、難易度との相関も小さい。ただし、次の1問を選ぶ手がかりとしての意味が薄い（推測）。

## 事実と推測

- 事実（計測）: L1 の 4×4（段1で極小）は、568問すべて最初の数が8個だった。盤面も 4×4 だけなので、今の実装（盤面と最初の数）では、L1 の図鑑に問題の特徴の軸が1つも出ない。根拠は、選択肢が1つの軸は出さない作り（`frontend/src/features/zukan/zukan-filter.ts` の `ZukanLevelFeatures.axes`）。測ったのは `measure` の (1)
- 事実: 図鑑の数の選択肢は、レベルの値が8種以下ならそのまま、超えたら `Math.floor(値 / 幅)` でまとめる。幅を持たない軸はまとめない: `frontend/src/features/zukan/zukan-filter.ts`
- 事実: 特徴の値の形は、数（単位は 個・本・台・マス・か所・種類・手・枚）か盤面だけ: `frontend/src/components/problem-features.ts`。「配置の対称」「点対称の位置にも数がある割合」は、この形に載らない
- 事実: 前例のまとめ幅は 3 が多い（ナンプレの初期数字・タクズの初期配置・橋をかけろの島・ハミルトン路の穴・ウォーターソートの色・パーキングジャムの車・詰将棋の盤上の駒）。リフレクションのピースは4、マインスイーパーの地雷は5、ウォーターソートの空ボトルとパーキングジャムの植え込みは2。氷の床迷路の各軸と詰将棋の手数・持駒はまとめない。氷の床迷路は、無い要素（0個）を問題の詳細に出さない: `frontend/src/games/*/ui/problem-features.ts`
- 事実: 今の実装は、盤面（`square-board-size`）と最初の数（個、幅3）を、問題集の項目（与える数を `.` でつないだ文字列）から数える: `frontend/src/games/magic-square/problem/problem-pool.ts`・`ui/problem-features.ts`。空きだけの列も同じ文字列から数えられる（導出）
- 事実（計測）: 盤面・最初の数・空きだけの列は、回転・裏返しでも、列の構造を保つ並べ替えと補数でも、全問で値が変わらない（`measure` の (4)）。どちらの同型の判定で問題集の重複をまとめても、同じとみなした問題は図鑑で同じ値を示す
- 事実: 遊び方の図とチュートリアルは、どちらも同じ 4×4 の魔方陣 `14 4 5 11 / 9 2 7 16 / 8 13 12 1 / 3 15 10 6` を使う。今の固定の問題集の L1（`0.4.5.0.0.2.0.0.0.0.12.1.3.0.10.6`）も、与える数がこの魔方陣と一致する: `frontend/src/games/magic-square/ui/MagicSquareHowToPlayDialog/figure-boards.ts`・`tutorial/tutorial.ts`・`problem/problem-pool.ts`
- 導出: 最初の数の選択肢を幅3でまとめたとき、5×5 が14個以下、6×6 が15個以上なら、選択肢が盤面をまたがない（14 と 15 が別の帯に入る）。幅2 では、14 と 15 が同じ帯（14〜15）に入る。計測した範囲では 5×5 は14個以下（L3〜L5 は13個以下）、6×6 は16個以上で、幅2 でもまたがなかった
- 導出: 1マスだけ空いた列があれば、その空きは最初の1巡で決まる。よって L3〜L5（入口が無い）では、1マスだけ空いた列は必ず0本になる。L2 と L3 の境目をそのまま示す特徴になる
- 推測: 空きだけの列は、盤面を見てすぐ分かる見た目の違い（縦・横・斜めのどれか1本が丸ごと空き）。手がかりの無い列なので、交わる列から埋めることになる。難易度と相関しないので、選ぶとレベルの中の難しさではなく、盤面の見た目と始め方が違う問題に当たる。遊ぶ人がこれで次の1問を選ぶかは試遊と最終レビューで確かめる
- 推測: 最初の数は、同じレベル・盤面の中で、読む所の数（作業量）と負に相関する。「今日は短めの問題を」という選び方の手がかりになる。前例のナンプレ（初期数字）・タクズ（初期配置）と同じ役
- 推測: 1 と最大の数、大きい数と小さい数の差は、数としては分かれる。ただし、遊ぶ人が「1 と 25 が両方置いてある問題」を選ぶ理由が見当たらない。表示名も盤面ごとに変わる（16・25・36）
- 推測: 本文の候補の盤面の配分（L3 は 5×5 59%）は、生成条件の数で決まったもので、問題集の配分ではない。問題集で 6×6 を増やすと、空きだけの列が 0本の割合は上がる（6×6 は 82〜94% が0本）

## 仮決定の候補

- 問題の特徴の切り口: [推奨] 盤面・最初の数・空きだけの列の3つ / [理由] どれも始めたときの盤面で数えられ、同型の判定で値が変わらない。空きだけの列は、L1 で分かれる（63% / 33% / 4%）唯一の推奨の軸。レベルとも読みの量ともほぼ相関しない（レベルと −0.03、層の中で絶対値 0.45 以下）。最初の数は盤面の中を分け、作業量の目安になる。盤面は前例と同じ / [比べた案] 盤面と最初の数だけ（今の実装。L1 に軸が無い）。3つ目を「1 と最大の数」（どの層でも最多 49〜57% で分かれ、相関も小さい。選ぶ手がかりとしての意味が薄い）。2マス空いた列（読みの量と −0.57、1マス空きの列と −0.78。読みの材料をそのまま数える）。斜めの空き（L1 の中で段1の巡の数と +0.50）。1マスだけ空いた列（L2・L3 の境目そのもの） / [覆したときに作り直す範囲] zukan の項目だけ（`problem/problem-pool.ts` の `MagicSquareProblemFeatures`・`findMagicSquarePoolProblemFeatures`・`magicSquareProblemFeatureAxes` と、`ui/problem-features.ts` の表示）。問題集は変えない
- 最初の数のまとめ幅: [推奨] 2 / [理由] 最初の数の値は盤面ごとの2つの帯に分かれ、本文の候補でも L3 10種・L5 9種と8種を超えてまとめが効く。各レベル500問ではほかのレベルも超える見込み（推測）。幅3 では、盤面を選んだ後に L3 6×6 と L5 5×5 の 95% が1つの選択肢に入り、盤面の中を分けられない。幅2 なら 82〜86% に下がり、まとめが効く L3・L5 の選択肢は5〜6つに収まる / [比べた案] 3（今の実装と多くの前例。盤面をまたがないことが帯の境目から言える）。まとめない（盤面を選んだ後の最多が 43〜53% と最もよく分かれるが、レベル全体で9〜10個以上の選択肢が並ぶ。8を超えたらまとめる共通の作りの意図と合わない） / [覆したときに作り直す範囲] `ui/problem-features.ts` の `rangeWidth` の1か所
- 空きだけの列の書き方: [推奨] 表示名「空きだけの列」、単位「本」、まとめない（値は0〜3本で、8種を超えない）。問題の詳細では1本以上のときだけ示す（氷の床迷路の要素の数と同じ）。絞り込みには0本も選択肢として出る / [理由] プレイ画面と遊び方の言葉（縦・横・斜めの「列」、マスの「空き」、チュートリアルの「空きが1つの列」）に合わせた。0本は大半の問題に当たるので、詳細に毎回出すと読む量が増える / [比べた案] 「数の無い列」、0本も詳細に示す / [覆したときに作り直す範囲] 表示だけ
- 1マスだけ空いた列・入口を特徴にしない: [推奨] 特徴にしない / [理由] L3〜L5 では全問0で、レベルとの相関は −0.85。L1 の中でも段1の巡の数と −0.77。難易度の境目と中身の写しになる（ADR-0004 の背景） / [比べた案] L1・L2 だけに出る軸として持つ / [覆したときに作り直す範囲] zukan の項目だけ
