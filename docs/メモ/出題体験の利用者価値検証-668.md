# 同じパズルを続けても新鮮に遊べるか — #668 体験検証

## 対象にする人と体験

同じパズルを続けて遊ぶ人が、いつもどおり解いて結果を受け取り「次の問題」に進むだけで、単調にならず発見を楽しめるかを調べる。利用者要求 RQ-008「同じパズルを繰り返し新鮮に楽しみたい」に対応する。ただし、現行の出題が退屈だという利用者の証拠はまだない。

分析指標を見せる「別の考えどころを探す」は撤回する。プレイヤーは特徴量を検索するために遊んでいるのではなく、パズルを解く過程を楽しむために遊んでいる。結果画面の主操作、難易度、記録、図鑑、既存出題設定の意味は変えない。厳選以外を二軍として格付けしない。

## 同じ難易度で連続して遊ぶ比較

研究専用の入口は /studies/continuous。ナンプレ・パーキングジャムの Lv3〜5 で、同じゲームと同じ難易度の10問を連続プレイできる。通常ナビゲーションにこの入口を加えない。プレイ・結果・次の問題という一連の操作は変えず、指定した問題IDへ進む。

比較条件は次の二つとする。

- 無作為対照：同一難易度・生成条件・問題規模で最大の候補層から、再現可能な疑似乱数で問題を選ぶ。
- 変化調整：同じ候補層から4問を抽出し、直前の2問と軽量な特徴が違うものを優先する。ナンプレでは初期ヒント配置、パーキングジャムでは既存生成条件から得られる軽量な特徴を使う。

各条件は10問。問題IDの重複は同一の問題列では発生しない。問題列は番号0〜99で再現できる。開発者は問題列と条件を切り替えられるが、参加者URLには条件の切替を表示しない。

この無作為対照は、通常のランダム出題そのものではない。難易度と問題規模を統制した比較対象であり、プレイヤーの出題設定・既挑戦状態は反映しない。したがって、結果をそのまま本番出題へ導入しない。通常の出題と図鑑の使用感は別に観察する。

比較する特徴距離は面白さを保証しない。特にパーキングジャムの生成条件と、ナンプレの初期ヒント配置は実際の解法の体験を完全には記述しない。選定方式によって思考上の違いが生じたか自体も、試遊で確認する必要がある。

## 試遊手順と採否

まず、同じパズルを続ける人について初心者・習熟者を区別し、研究担当者が参加者を異なる方式・問題列へ割り当てる。参加者には選定方式の意味を知らせない。同じ人に同じ問題を異なる条件で繰り返し遊ばせ、学習効果を比較結果に混ぜることを避ける。

10問は探索的試遊に使う仮の長さで、最適な長さという意味はない。疲れたら中断可能にし、完走を強制しない。観測するのは、実際に次へ進んだ回数、途中離脱、プレイ時間、印象に残った気づき、単調さ、疲労・理不尽さ、次も遊びたいか、やめた理由である。各問題の解法特徴やゲーム内スコアを楽しさの代理指標にしない。

予備試遊を本比較と区別し、観測方法や所要時間を確認した後、必要な参加者数を決める。複数の異なる問題列で結果を確かめ、逆効果・個人差・技能差も報告する。数人の感想だけで統計的な優位や長期継続率の改善は主張しない。

採否の基準は次のとおり。

- 新しい出題順が楽しさ・継続意向を改善せず、負担を減らさないなら現行維持。
- 同じ操作のまま実際の体験改善が確認できれば、候補の供給数・実行費・既挑戦設定との整合を測り、通常の次問選択の改良候補として扱う。
- 人間による厳選を採用するのは、低コストの選択を超える体験上の価値を複数系列で示し、審査時間・合格率・更新費が見合う場合だけとする。今回の比較だけでは人手による良問認定や専用モード採用を正当化できない。
