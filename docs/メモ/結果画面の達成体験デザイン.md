# Issue #690 結果画面の達成体験デザイン

設計案。製品の実装・採点式・評価閾値・記録比較・保存・プレイUIの変更ではない。

- [実画面の構図・演出・文言・図鑑の色をまとめたデザイン資料](./結果画面の達成体験ビジュアル案.html)
- HTMLはJavaScriptを使用せず、ゲームの既存ピクトグラムを内包する。演出はHTML標準の`details`とCSSによる説明用の絵コンテで、実プレイ画面との接続ではない。
- 例示した成績・保存結果・図鑑の問題は設計サンプルであり、実記録ではない。

## 何を主役にするか

結果は、最後に解いた操作の手応えを受け取り、**今回の評価を最も強く伝え、その出来を把握した流れで次の問題へ進める画面**とする。

1. ゲーム固有の完了：ウォーターソートなら最後の注ぎ、ナンプレなら最後の数字を終わらせる。
2. 今回の評価：ゲームのピクトグラム・評価名・点数をひとまとまりとして示す。
3. 比較できる記録：自己ベストがあれば何が変わったかを示し、なければ実際に記録した事実を静かに伝える。
4. 次の問題：演出が終わるまで操作を待たせない。

65点のクリアも成功したプレイとして扱う。100点では最上位評価を明確に示すが、過去記録の更新と今回の得点の高さを混同しない。通常時は共通UIを静かにし、喜びの表現はゲームの完成と結果の評価へ集中させる。メダル・紙吹雪・個別カードを増量する方向は採らない。

## 評価文言を確定するための比較

評価の実データは `clear / good / great / perfect` の4段階である。文言の選定基準は、**評価の上下関係が初見で伝わること、4段階が同じ文法・温度感であること、相手を採点者目線で褒める言い方にしないこと、長さが結果の構図を壊さないこと**。語尾を揃えるだけでは十分でない。

| 系統 | clear / good / great / perfect | 判断 |
|---|---|---|
| 既存の混成 | クリア！／ナイスプレイ！／すばらしい！／パーフェクト！ | 外来語の競技用語・人への称賛・スコアの絶対評価が混じるので不採用 |
| 会話的な日本語 | クリア！／いい感じ！／すごい！／完璧！ | 温度は近いが、goodが曖昧で、上位の差が気分に依存する。かわいらしさが先に立つので不採用 |
| 説明的な評価 | クリア！／好プレイ！／高評価！／満点！ | 正確でも採点報告に近く、祝賀の言葉として味気ないので不採用 |
| **既存段階名の統一表現** | **クリア！／グッド！／グレート！／パーフェクト！** | **採用候補**。段階の意味に一対一で対応し、すべて短いランク名の感嘆形で揃う |

選定案は、上から目線の「よくできました」、曖昧な「いい感じ」、点数に依存しない「最高」を避ける。結果の得点はコピーの直下に示し、単語だけでは分からない数値の差を補う。発音・表記はすべてゲーム内のランク名として統一する。図鑑の凡例は従来のデータ名 `clear / good / great / perfect` を使い、結果画面のコピーは流用しない。

長い「パーフェクト！」はアイコンを潰したり文字を改行させたりせず、320px幅の主表現だけ文字サイズを調整する。評価を強めるために漢字・カタカナの揺れや句読点を増やさない。

## 図鑑の配色：連続する一つのグラデーション

**「単色」の意図は緑色への固定ではない。複数の無関係な色で4段階をバラバラに区別せず、一つの連続した色の流れで見せること**である。この点を誤って緑の濃淡だけにした以前の案は廃止する。

比較した配色は「海色からインディゴ」「空色からバイオレット」「ピーチからプラム」。採用候補は**空色からバイオレットへ、明度と色相が連続的に変化する寒色系**とした。青みを持つブランドの静かなトーンに近く、ウォーターソートの青・ナンプレの紫のピクトグラムとも競合しにくい。海色案はgood以前の青緑がやや強く、ピーチ案は他のゲームの題材より装飾色が前に出るため採らない。

以下は設計用サンプルの色であり、製品用トークンはまだ追加していない。

| 図鑑の状態 | ライトのジグソーピース | 暗色背景上のピース | 結果の評価名（ライト） |
|---|---|---|---|
| 未挑戦 | `#F1F4F5` | `#263039` | — |
| 挑戦中 | `#D3DBDF` | `#3B4954` | — |
| clear | `#B6D9EA` | `#304F6B` | 中立 `#263139` |
| good | `#7FB4D8` | `#3974A0` | `#246A96` |
| great | `#4D84C2` | `#5886CD` | `#315DA6` |
| perfect | `#6550A1` | `#9F8CDD` | `#5B449F` |

色相は水色→青→青紫→紫へ動き、明度はライトでは段階的に下がる。これらの4点を一つの連続したグラデーションの中から切り出す。**ジグソーピース自体はそれぞれ1色で塗る**。1ピースの内部を勾配で塗ると小さなマスで状態を読み取れなくなるため、草のような離散的な色見本にする。連続グラデーションそのものは凡例で見せる。

未挑戦・挑戦中は無彩色に固定する。状態は従来の6種類を維持する。ランクは固定の評価閾値に従い、GitHubの活動量の相対分位点へ置き換えない。ジグソーの形と問題集の順序を保持する。新規クリア／ランク更新を押し込む既存の図鑑演出も維持し、色が変わる方向に自然な段階差を作る。

`DESIGN.md` では評価段階の色を画面間で一致させるため、正式に導入する際は `frontend/styles/globals.css` のトークン、結果画面の色、図鑑のマス・凡例・絞り込みの見本・変化前後の表現を同じ配色へまとめて変更する。ゲーム固有ピクトグラムの色は変更しない。選択・焦点・状態の説明は色だけに依存しない。

## 結果画面の構図

スマートフォンでは `ゲーム名と難易度 → ピクトグラム・評価名・点数 → 主要成績 → 記録通知 → 次の問題 → 二次操作`。評価を一つの主表現にし、指標ごとに個別カードを作らない。ウォーターソートは手数・時間の2列、ナンプレは時間・ミス・待ったの3列。成績は細い仕切りで読み分け、得点の主表現より目立たせない。

結果名の文字は評価カラー、得点は通常の前景色。記録更新は別の紫系の一まとまりを使い、グラデーションの段階が得点を意味することと混同させない。ゲームピクトグラムの青・紫は、評価ランクのために塗り替えない。ピクトグラムの背景も評価によって色が変化しない。

次の問題は全幅の主操作。「問題選択」「もう一度」は同格の二次操作で、「パズル選択」「内訳を見る」は補助導線。320×568でも、評価・点数・主要成績・記録・次の問題を初期画面に置く。3指標更新の詳細は必要に応じて展開する。PCでは横長の2領域構成に変え、左が評価、右が成績・記録・次の操作になる。

## 記録通知：空欄の代わりに何を伝えるか

記録欄を埋めるための賑やかな文句は足さない。成功した保存・初記録・自己ベスト更新など、起きた事実を異なる強さで知らせる。

| 状態 | 通知の内容 | 見せ方 |
|---|---|---|
| 初記録 | はじめての記録／このゲーム・難易度で最初の記録です | 小さな印と説明。PBとは別の意味 |
| 更新なし、保存成功 | 今回のプレイを記録しました | 中立の短い知らせ。更新がないことを否定しない |
| 一指標更新 | 自己ベスト更新／時間 01:18 → 01:02、16秒短縮 | 前後差と改善幅で進歩を具体化 |
| 複数指標更新 | 自己ベスト更新 3項目／得点・時間・ミスを更新 | 要約と展開できる差分 |
| 保存失敗 | 記録を保存できませんでした | クリアの成立を取り消さないが、保存できたと偽らない |
| 記録の再表示 | 保存済みの結果を静止表示 | 初回の達成と保存告知を再演しない |

既存の記録比較ロジックを変更しない。初記録は #689、更新がない場合の過去との差分は #503 の責務を尊重し、この設計で勝手に代替しない。記録を保存できない場合に通常保存成功の告知を表示しない。

## 演出：最後の一手の手応えを結果につなぐ

[ウォーターソート・ナンプレの演出を再生できるデザイン資料](./結果画面の演出再設計.html)を別に置く。各ゲームの通常クリア・高評価、自己ベスト更新・非更新を含む4場面を、同じ情報階層で比較できる。JavaScriptは使用せず、ブラウザ標準の `details` とCSSだけで一度再生する。前半の盤面描画は既存のプレイ演出を示す模式図であり、新しい注ぎや入力を製品で再実行する提案ではない。

### 演出の主役と切り替え点

- ウォーターソート：ゲーム側で最後の注ぎを完了し、水面が静まるまで見せる。結果への切り替え後は、既存のボトルのピクトグラムの水面をなぞる短い反応だけにする。注ぐ手をもう一度再生しない。
- ナンプレ：ゲーム側で最後の数字を確定して盤面完成を見せ、既存の完成時の脈動を終えてから結果へ切り替える。結果側では、既存のピクトグラムの最後のマスに短い輪郭の反応を返す。81マスを再点滅させない。
- 共通の切り替え：盤面で成功を確定させることと、結果画面で評価を受け取ることを別の反応として区別する。ピクトグラム・評価文言・得点・主要成績・次の問題は、結果画面の初期描画から成立させる。画面全体の拡縮・暗転・紙吹雪・数字のカウントアップで待たせない。

### 結果画面に入ってからの時間構造

結果画面の表示開始を `t=0` とする。時間は採用する場合のデザイン目安で、ゲーム側の既存完成演出に追加する待機時間ではない。

| 時点 | 役割 | 動く対象 |
| --- | --- | --- |
| 0 ms | 評価・点数・成績・操作が読める | 配置は最終状態のまま。主操作も押せる |
| 0〜300 ms | 解けたことの短い余韻 | ウォーターソートはピクトグラム内の液面、ナンプレは最後のマスの輪郭を一度だけ収束 |
| 250〜500 ms | 過去からの進歩を知らせる | 自己ベストを更新したときだけ、既存の通知欄の印が一度反応。値を遅らせず、位置も動かさない |
| 500 ms以降 | 静止して成績を受け取る | ループなし。更新がない通知、初記録、保存失敗は報酬演出を増やさない |

- 評価段階の強弱は同じゲーム固有の反応の振幅で変える。clearは成功が分かる小さな反応、good/great/perfectは順に明確にするが、新しいオブジェクト・演出段数・画面全体の動きを増やさない。
- 評価名と点数の色は既存の4段階を維持する。図鑑の色・文言・画面構成はこの再設計では一切変更しない。
- 進歩の通知は得点の称賛と競わせない。値の比較を読む前に印だけが控えめに反応する。非更新時は静止した「今回のプレイを記録しました」を表示する。
- 結果へ入った瞬間の既存の評価段階別報酬音は、`clearing → result` の一度だけ鳴らす。結果BGMが報酬音の余韻を消さない既存の間を維持する。視覚の演出に音を付け足して重複させない。
- 演出の途中でも次の問題・問題選択・もう一度は操作でき、移動すると動きは終わる。再読み込み・履歴表示では静止した完成状態を示し、達成を再演しない。動きを減らす設定でも同じ完成姿を即時表示する。

### 絵コンテの読み方

別HTMLの再生は計約2.1秒で、前半が**すでにゲームにある最後の一手・完成反応**、後半が**新しく提案する結果側の余韻**である。前半の時間は説明用にまとめたものであり、結果を表示するまで2.1秒待たせる仕様ではない。既存画面の静止レイアウト、評価コピー、単一のグラデーション、記録通知の意味は前案のまま保持する。

## 採用しないこと／境界

- 子ども向けの軽い感嘆を4種類並べ、評価の強弱を文字のテンションだけで表すこと。
- 4ランクを無関係な暖色・寒色に割り当てること、逆に色相の違いを消して同じ色だけを濃くすること。
- 図鑑をカレンダー化し、問題順やジグソーの形を捨てること。
- 結果画面の賑やかさのために、紙吹雪・メダル・大きな更新カード・数値カウントアップを増やすこと。
- 結果を閉じるまで主要操作を押せなくすること、低得点を「惜しい」と叱ること。

本提案は設計の更新であり、画面構成、ゲームUI、色トークン、保存ロジックを製品へ実装したわけではない。Issue #690の製品上の受け入れ条件を満たしたと判断するには、別途本番画面への実装と検証が必要である。
