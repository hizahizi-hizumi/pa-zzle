# パズル選択体験の再設計：調査と判断

更新: 2026-11-11  
対象: `SCR-001`（ホーム／パズル選択）のみ。プレイ・結果画面やアプリ全体の体験設計は対象外。

## 問題設定

既存のプレイ画面・結果画面は、デザインの方向性と最低限の整合性を考えるための**参考**であり、ホームの完成形ではない。ホーム独自に、見分けやすさ、選ぶ楽しさ、頻繁な利用への耐性を高水準で両立させる。既存の3案の相対評価をもって完成度の評価としない。

代表的な利用場面は、(1) いつものゲームをすぐ始める、(2) 次に遊ぶゲームを探す、(3) ゲームの違いを眺めて新しい遊びを選ぶ、(4) プレイから戻り、別のゲームへ移る、の4つ。それぞれで同じ画面が働く必要がある。説明や成績を増やして解決しない。

## 外部事例と採用・非採用の判断

| 参照 | 学べる原理 | そのまま採用しない理由 |
|---|---|---|
| Nintendo Switch HOME メニュー | 候補識別とすぐ遊べる導線が明快 | アイコン密集の水平リストをそのまま持ち込むと、個別ゲームの鑑賞性が低下する |
| PlayStation 5 のゲームハブ | 選択中のコンテンツが舞台の主役になる、情報の階層が明確 | 大量の画像素材・告知・統計は10種類のパズルには不要 |
| Apple Games | 「見つける」「戻って遊ぶ」の双方を支える | 情報カードやレコメンドは今回の目的・仕様から逸脱 |
| Material Design Carousel | 主役と隣接候補のサイズ・見切れ方を設計要素とする | コンポーネントの形を模倣するだけでは固有の完成度が上がらない |
| Nielsen Norman Group のカルーセル研究 | 遠い候補へは順次スワイプが負担。見切れと明示性が必要 | 10ゲーム・循環・慣性移動なら全件一覧の常設が必須とは限らない。実機評価は必要 |

## 現行C案の診断（改修前）

1. **情報階層が解体されている**：ヘッダー、孤立した大きいピクトグラム、離れたゲーム名と位置表示は互いに関連しない部品として見える。
2. **余白に機能がない**：広い空白が主役を浮き上がらせる構図にならず、未完成の見た目に寄る。
3. **図柄の個体差を吸収していない**：10ゲームの線量、輪郭、色面積、密度が異なる。一律の「裸のアイコン拡大」では図柄ごとに見た目の重心が揺れる。
4. **周辺候補が切れた部品に見える**：隣接の図柄が背景から浮かず、画面端の見え方が規則的な空間として成立していない。
5. **動きと選択確定が分断されやすい**：従来の待機式スナップは撤去済みだが、色・主役・表示内容の変化が指の動きと一致するか引き続き検証が必要。
6. **遠い候補へのアクセス**：常設の小一覧を撤去したため、左右キー・慣性・循環で補っているが、10件の中から既知の1件を探す効率は実機で判断する。

## 比較した方向性

- **明るい編集デザイン**：白〜暖灰色の面、図柄を額装する方式。ブランドとの接続は弱めだが、読みやすく清潔。余白の弱さを再発しやすい。
- **暗い最小限の舞台**：図柄の白い展示面と低彩度の暗い背景が連続する。図柄に高いコントラストを与え、視線が固定される。一方、周辺ゲームが視認できなくなる危険がある。
- **暗いギャラリー**：展示面を保ちつつ、左右の作品が連続して現れる構図。ゲームの違いの発見と鑑賞を両立しやすい。オブジェクトを密集させないこと、白いカードの陳列にならないことが条件。

採用する試作方針は**連続した展示空間**。暗い背景に独立した白いカードを浮かべる構成は、中央が孤立し左右の候補が切れた部品に見えるため退けた。円形のスポットライトも、四角い盤面などゲーム固有の形と合わない。淡い展示面を横幅いっぱいに連続させ、中央を大きく、隣接候補を小さく、しかし全体を識別できる大きさで見せる。ゲーム名と位置は同じ展示面で結び付け、独立した「遊ぶ」ボタンは設けない。

スクロール方向と逆向きに図柄を移動する補正は、指と図柄の動きに差が出るため退けた。隣接候補の見え方はトラックの間隔と図柄の縮尺で成立させ、中央への移動に合わせて自然に主役が入れ替わることを優先する。ピクトグラムの図形・色・ゲーム固有のアニメーションは維持する。

これは**完成案の決定ではなく、比較試作から選んだ実装仮説**であり、ユーザーの実機での評価をもって完成とする。

## 独立した品質基準

### 必ず満たすこと（単体テスト・実ブラウザ確認）

- 初見でゲームの図柄、ゲーム名、開く操作が対応付く。
- 指・マウスの移動にスライドが追従する。スナップの完了待ちで中央のゲームが開けなくならない。
- 1件目と最後が双方向に循環する。途中位置へ戻したときに視覚的なジャンプがない。
- 320〜430pxの幅とPC幅で、主役が見切れずページが縦横へ意図せずスクロールしない。
- 戻る・設定・記録・並び順・タイトル画面・続き情報の既存導線が退行しない。
- キーボードと動きの軽減設定にも対応し、意図しない `console.error` / `pageerror` がない。

### 目視・操作レビューで判定すること

5観点を各4段階（0:成立しない / 1:弱い / 2:妥当 / 3:明確 / 4:洗練）で独立評価する。比較案内で「相対的に1位」でも、いずれかに1以下があれば完成扱いにしない。

| 観点 | 観察する具体的なこと |
|---|---|
| 構図・視線誘導 | 1秒以内に主役を理解でき、ゲーム名・続き情報が自然に読めるか |
| 選ぶ喜び | ゲームの入れ替わりが連続し、隣へ進みたくなるか |
| 素材の扱い | 10種類すべてで図柄の太さ・色・密度の違いを魅力として扱えているか |
| 操作の気持ちよさ | ゆっくり・速く・逆方向・端・連続操作をしても遅れや引っ掛かりがないか |
| 長期使用 | 繰り返しても装飾やアニメーションが邪魔にならず、目的のゲームへ辿れるか |

**評価の限界**：外部UI事例は設計原理の参考であって本アプリ利用者のテスト結果ではない。iPhone実機Safariの慣性・戻る操作・ブラウザ下端色はエミュレーションだけで保証しない。ユーザー評価を受けて反復する。
