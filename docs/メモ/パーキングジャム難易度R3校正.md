# パーキングジャム難易度 R3 校正

## 目的

Issue #250 の R3「難易度を人間負荷として再設計する」で、生成条件や単一の依存深さを難易度そのものとして扱わず、実際に盤面を読む・順序を判断する挑戦と対応する難易度判定へ作り直す。

この文書は検証途中の仮説・固定コーパス・人間比較方法を残すメモであり、現在仕様の正本ではない。

## 現在の挑戦仮説

パーキングジャムで中心になる挑戦は、盤面から次を読み取って退出順を判断することである。

- 現在どの車を退出させられるか
- 退出可能な車が複数あるとき、どれを先に出すか
- ある車を出すことで、どの車が新しく退出可能になるか
- ボトルネックになる車と、その前に必要な退出関係を追えるか
- 一台の車について、どちら向きの退出が成立するか

車両数、盤面面積、車セル密度、道路開口量、進路長は視覚探索量や判断材料を変え得るが、それ自体を難易度とはみなさない。構造的な制約と交差させ、人間比較で影響を確認する。

## 候補特徴

既存 `dependencyDepth` / `solutionOrderFreedom` に加え、現在は次を再現可能に観測する。

| 観点 | 候補特徴 | 観測したいもの |
| --- | --- | --- |
| 選択肢 | `averageLegalVehicleRatio` / `minimumLegalVehicleRatio` | プレイ中に退出候補がどの程度絞られるか |
| 強制選択 | `forcedChoiceStateRatio` | 複数台残っている局面で、実質一台しか選べない頻度 |
| 解放 | `averageNewlyUnlockedVehicleCount` / `maximumNewlyUnlockedVehicleCount` | 一台の退出が後続候補をどの程度変えるか |
| 必須先行 | `requiredPrecedenceCount` / `maximumRequiredPredecessorCount` | どの合法解順でも崩れない先行関係とボトルネック |
| 遮断 | `maximumVehicleBlockingOutDegree` / `maximumVehicleBlockingInDegree` | 一台が複数台を塞ぐ、または一台が複数台に塞がれる構造 |
| 方向判断 | `averageLegalDirectionCount` | 退出可能な車について方向選択がどの程度残るか |
| 視覚探索候補 | `vehicleCellOccupancyRatio` / `longVehicleRatio` | 盤面上で追う車両・占有量 |
| 境界・進路 | `roadOpeningCoverageRatio` / `averageExitPathLength` / `maximumExitPathLength` | 出口量と確認する進路の長さ |

16台以下では全到達状態を列挙し、合法な車両退出順、強制選択、解放、必須先行関係を同じ状態空間から取得する。これらは校正候補であり、値を取得できることだけを採用理由にしない。

## 固定コーパス

生成条件の大小と構造的な難しさを意図的に逆向きにした6問を固定する。問題は generator version / seed / generation conditions / generation attempt から復元する。

- `small-deep`: 小さいが依存が深い
- `large-shallow`: 大きいが依存が浅く解順自由度が高い
- `dense-free`: 車セル密度が高いが必須先行関係がない
- `sparse-bottleneck`: 車セル密度が低いが強いボトルネックを持つ
- `few-exits-shallow`: 道路開口が少ないが構造制約は比較的浅い
- `many-exits-deep`: 道路開口が多いが依存構造が深い

固定値そのものは `frontend/src/games/parking-jam/difficulty-calibration.ts` を正とする。

## ブラインド比較

`/puzzles/parking-jam/calibration` で5ペアを順にプレイする。

1. 小規模・深い依存 vs 大規模・浅い依存
2. 高密度・自由 vs 低密度・ボトルネック
3. 少ない道路開口・浅い依存 vs 多い道路開口・深い依存
4. 構造制約の境界比較
5. 視覚探索量の境界比較

比較中は難易度ラベル、生成条件、機械判定値を表示しない。各問題について次を自動記録する。

- 完答時間
- 最初の退出操作までの時間
- 不成立操作数
- 待った回数
- やり直し回数

2問を完答した後に「問題A / 同じくらい / 問題B」のペア比較を記録する。結果は `localStorage` へ保持し、利用できない実行環境では同一セッション中のメモリへ退避する。

## 校正後に決めるもの

人間比較前には次を確定しない。

- どの候補特徴を難易度判定へ採用するか
- 特徴同士の組み合わせ方
- 難易度帯の境界
- 各帯を継続供給する生成プロファイル
- 現行 `dependency-v1` の置換方法

比較が機械特徴とずれた場合は、閾値だけを合わせず、挑戦仮説・特徴の意味・不足特徴から見直す。
