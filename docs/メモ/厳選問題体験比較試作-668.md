# 厳選問題の提示は既存の遊び方を超えるか — Issue #668 検証記録

## 判断と証拠の境界（2026-11-07）

**現段階では製品採用を保留する。** ナンプレとパーキングジャムで、同じ難易度・問題規模を揃えつつ解析上の解き方が異なる6問（セットA）と、同じ条件から乱数で選んだ6問（セットB）を固定した。両セットは、一覧提示と順番提示のどちらでも、既存のプレイ画面で遊べる。ランダム出題と図鑑への入口も残した。

この実験は、**「解析上の違いが、利用者にとって価値ある楽しさになるか」**を検証するためのものであり、セットAを良問と認定するものではない。実際の人間による比較試遊は未実施。機械解析・画面の正常動作だけから「より楽しい」「次も遊びたい」と断定しない。

調査したものと残るものは以下の通り。

| 論点 | 今回の証拠 | 未判定・限界 |
|---|---|---|
| 既存の問題品質 | 2ゲームのLv3〜5、計3,900問を既存の人間向け解法解析器で全量解析。分析不能・不成立は0件 | 人間が感じる良問性。残り8ゲームとLv1・2の深い解法多様性（#660の領域） |
| 候補の代表性 | 全量分布・候補の位置・選抜条件を確認 | 厳選セットは意図的に差の大きいものを選んだため、平均的な6問ではない |
| 比較対象 | レベル、ヒント数／盤面規模を対応させた乱数固定セットBを追加 | 盤面のすべての潜在的な難しさは揃わない。対照セット1組には乱数のばらつきがある |
| 提示方法 | どちらの固定セットにも一覧／順番の2方式を適用 | プレイから自動で次問に戻らない、別タブ操作による摩擦が残る |
| 体験価値 | 交絡要因・観測項目・棄却条件を事前に整理 | 人間試遊・継続意向・熟練度別の結果は未観測 |
| 運用 | 全量解析の処理時間と代替候補の供給密度を測定 | 人手での盤面審査、継続更新の実費は未測定 |

## 評価すべき価値と外部知見

「良問」を単なる高難易度、手筋の多さ、盤面の珍しさ、クリア時間の長さとはしない。以下の三層を分ける。

1. **問題そのもの**: 理解可能な問題、意味のある判断・先読み、行き詰まりからの発見、解法の納得感。単純作業の量や読みの理不尽さは別の負の側面。
2. **問題列**: 同じ考え方の反復による単調さと、新しい考え方の導入・定着の両立。変化の多さだけを最大化すると学習の連続性を損なう可能性がある。
3. **提示体験**: 次に遊ぶまでの選択負担、能動的に選ぶ楽しさ、順番に出される気軽さ。問題内容とUIが変わると効果を識別できない。

先行知見は評価軸の候補を与えるが、このアプリでの効果を保証しない。

- Sweetser & Wyeth, *GameFlow* (2005): 集中・挑戦・技能・制御・明確な目標・反応などを楽しさの観点として整理。https://doi.org/10.1145/1077246.1077253
- Linehan et al., *Learning curves* (2014): 良好なパズルゲームで、技能を段階的に導入し練習・組み合わせへ進む構成を観察。解法をばらばらに並べるだけでは不十分。https://pure.york.ac.uk/portal/en/publications/learning-curves-analysing-pace-and-challenge-in-four-successful-p/
- Lomas et al., *Is Difficulty Overrated?* (CHI 2017): 難易度と選択・新奇性を独立に操作した大規模実験。選択権や新奇性が結果に影響するため、問題の厳選と選択UIを混同しない。https://doi.org/10.1145/3025453.3025638
- *Difficulty-skill balance does not affect engagement and enjoyment* (2023): 難易度と技能の釣り合いが楽しさを必ず高めるとの単純な仮定に否定的な事前登録研究。https://doi.org/10.1098/rsos.220274
- *Leveling up fun* (2025): 既存のゲームデータでは、期待した難しさ、成功、学習の進展も満足度と関連。難易度を揃えるだけで全条件を制御できるわけではない。https://pmc.ncbi.nlm.nih.gov/articles/PMC12488971/
- Nielsen Norman Group, *Internal vs. External Validity of UX Studies* および *Between-Subjects vs. Within-Subjects*: 比較順序の無作為化・練習試行・学習と疲労の影響の分離。https://www.nngroup.com/articles/internal-vs-external-validity/ 、https://www.nngroup.com/articles/between-within-subjects/
- *Game Experience Questionnaire* は没入・有能感・挑戦などの視点の参考とするが、元の尺度の検証状況には限界がある。本調査の短い独自質問を「GEQの妥当性が保証された尺度」と呼ばない。https://game-evaluation.github.io/questionnaires/repository/geq.html

## 調査対象と再現手順

- **正確な対象**: PR #682 の親である `main` の `add7b90d4d6889973f92ca8af84d2251c3366a17` と一致する Repository Snapshot。PRの対象コミットは `7989d41ad0cdfc5b465af198778cde05eb5cddd9`（今回の修正前）。この2ゲームの問題集は両コミットで同一。
- 対象ソース: `frontend/src/games/{nanpure,parking-jam}/problem/problem-pool.json`。Lv3〜5を全件扱う。全量の低コスト解析はLv1〜5も含め、ナンプレ1,500問・パーキングジャム5,000問の生成条件・規模を確認。
- ナンプレの詳細解析: `listNanpurePoolEntries` → `decodeNanpurePoolProblem` → `analyzeNanpureDifficulty`。ヒント数、解法の最深手筋、手筋別の使用回数、候補削除ラウンド、連続長などを記録。すべて `analyzed`。
- パーキングジャムの詳細解析: `listParkingJamPoolEntries` → `toParkingJamPoolIdentity` → `restoreParkingJamProblem` の `difficultyAnalysis`。盤面・車両数・依存深さ・最大先行車両数・読み違い誘発数・初期遮断関係などを記録。すべて `analyzed`。
- 実測は難易度帯ごとに分割し、Node/Vitest で各ゲームの既存の解析コードを呼び出した。全3,900問の詳細解析の所要は **約140秒**（Lv3約43秒、Lv4約58秒、Lv5約39秒、同一ChatGPT実行環境内の実測）。ナンプレの詳細解析は各難易度約1秒、パーキングジャムが大部分を占める。CPU・環境依存であり、本番サーバーの負荷見積もりではない。
- 次の統計は**全問の算術・度数分布**であり、抽出標本からの推定ではない。解析特徴は人間の体験に対する代理値にすぎない。ランダムな比較セットの抽出は `668/20261107/control/{game}/{level}` を固定した乱数系列で、同難易度・同じ問題規模の層内から非重複抽出した。
- 問題IDは `createProblemId(identity)` で再現。パーキングジャムのseedは生成条件が異なれば同一でも別問題なので、ID・難易度・生成条件の対応まで確認する。テストは24問すべての存在とID・seed、規模一致、プレイURLを担保する。

## 継続供給の検証と費用

候補を1回作れたことと、何度も品質を維持して供給できることを分ける。**厳選の特徴を極端に固定すると、全量3,900問あっても供給は薄い。**

| 条件を固定した母集団 | 条件を満たす候補数 | 解釈 |
|---|---:|---|
| ナンプレLv3・24ヒント | 109問中、削除1回: 28問 / 9回以上: **2問** | 現候補の強い連続差を何度も再現しにくい |
| ナンプレLv4・24ヒント | 101問中、最深Hidden Triple: **1問** / 最深Naked Pair: 70問 | Hidden Tripleを厳選の常設テーマにできない |
| ナンプレLv5・23ヒント | 46問中、最深XYZ-Wing: **3問** / 最深XY-Wing: 42問 | 特殊な一手を何度も新規提供するには不足 |
| パーキングジャムLv3・6×6・8台・固定物0・開口3 | 38問中、深さ2: 14問 / 深さ3: 24問 | この尺度では供給余地があるが、同型は未検査 |
| パーキングジャムLv4・8×8・14台・固定物0・開口4 | 82問中、深さ3・先行2・誘発12以上: **5問** / 誘発8以下: 19問 | 極端な誘発局面は限定される |
| パーキングジャムLv5・8×8・14台・固定物0・開口4 | 141問中、深さ4・誘発9〜11で先行3以下: **4問** / 先行9以上: **2問** | 現候補と同じ大きな対比を常時供給できない |

厳密な同じ特徴セットを30問連続で提供する発想は上表だけで既に成立しない。**多様性を「レアな極端値」と同一視する選び方は見送る**。採用するなら、難易度に応じた手筋の学習・定着も含む複数の比較軸を許し、実際の人の反応で選定条件を絞る。現時点の12問は上限を見積もる**探索・体験試作**であり、継続供給の保証ではない。

運用費の見方を区別する。

- 現在のUIは定数の固定IDと既存のプレイURLだけであり、実行時に解析器・ランキング・サーバー処理を追加しない。
- **機械的再解析**は約140秒/1回（現在の実行環境、2ゲーム・Lv3〜5全問）だった。更新ごとに自動化するか、最初の選定の時だけ行うかは採用前に決める。
- **人間の審査・試遊**が必要だが、これに要する工数は未測定。単に機械解析の時間を保守費と称さない。試遊回数・審査時間・棄却率・再評価頻度を実測してから月次・問題当たり費用へ換算する。
- **再現性**: 固定IDと原盤の生成器版・生成条件・seed・生成試行に依存する。プールから消えたIDは通常プレイ画面で他の問題へ置き換わり得る（ADR-0001）。既存のテストが候補24問の現在プール内の存在を保証するが、問題集改訂時に「遊べたから大丈夫」と判断しない。ID不一致・レベル変更は検証を失敗にし、候補と試遊結果の版を明示して更新する。
- **重複と履歴**: 同じIDなら通常の記録・図鑑の同じ1問へ帰属する（ADR-0004）。厳選だけの実績・重複したスコア・独自の難易度・独自の図鑑区分は追加しない。試遊は初挑戦のブラウザプロファイルで行い、クリア済み・挑戦中を混ぜない。ランダム側の既存履歴フィルター仕様は#652の決定を追う。

## 人間による比較試遊の実施計画（未実施）

試遊の実測がない段階で採用基準を後付けすると、好都合な結果の解釈になりやすい。次の手順と主観評価を試遊前に固定する。

### 1. 問題内容の比較と提示方法の比較を分離する

| 要因 | 条件 | 固定すること |
|---|---|---|
| 問題内容 | A: 意図して差をつけた6問 / B: 条件一致の乱数固定6問 | ゲーム・レベル配列・ヒント数／盤面規模 |
| 提示方法 | 一覧から選ぶ / 順番に1問を見る | 同じA・Bのどちらにも両方のUIを用意 |
| 現実の比較 | 通常のランダム / 図鑑 | 既存の実装そのまま。問題ID、履歴・絞り込み条件・選択時間を記録 |

**最初の比較は2×2（A/B × 一覧/順番）を参加者間で割り当てる**。1人に全条件を遊ばせず、同じ問題を二度解く学習効果を避ける。参加者が各条件を自由に選ぶと得意・好みの偏りが入るので、条件は進行担当者が割り当てる。技能・ゲーム経験・使う端末で層を分け、4条件に均等割当。ナンプレとパーキングジャムは混ぜて1つの平均値にしない。割当シード・参加者匿名ID・条件・問題IDを記録し、事後変更しない。

各参加者は、対象ゲームの基本操作を確認する練習1問（評価対象外）の後、担当された固定6問を順番どおり／一覧で自分で選んで遊ぶ。プレイごとにID、完了・中断、かかった時間、やり直し、迷った局面と後から説明できる根拠を記録する。中断も脱落として残し、解けた人だけの平均にしない。ゲームのスコアを「面白さ」の代用にはしない。

**別途、現実のランダム・図鑑条件**を対象ゲームの新規問題・同じレベル帯で観察する。こちらは自動割当条件とは別に、実際に選ばれた問題ID、未挑戦の残数、利用中の出題設定、選択開始から開始までの時間、離脱率を記録する。本人による選択が入るため、この観測だけで「厳選内容の効果」とは言わない。

### 2. 1問と1条件の観測

**各問題の直後**に、5段階で「解き方に気づきがあった」「自分で根拠を持って進められた」「この問題をまたは別の同種の問題を続けたい」「負担・徒労感が強かった」を回答してもらう。さらに「どの局面が印象に残ったか」を任意の一文で回答する。終了後に、一連の6問について「解くたびに変化を感じた」「単調な繰り返しだった」「次の6問も遊びたい」「選ぶ操作が負担だった」を同じ5段階で尋ねる。質問は短くし、解法名を最初から教えない。

一次評価項目は**6問後の「次の6問も遊びたい」**。副次は「変化を感じた」「気づきがあった」「選ぶ操作の負担」「完走率」。実際に翌日・次回も遊んだかはこの試作では測れないため、継続意向と実際の継続行動を混同しない。想起可能な印象・プレイ記録と回答が食い違う場合もそのまま反例として残す。

### 3. 解析・判断の仕方

- 予備試遊で各条件の迷い、所要時間、回答負荷を観察し、問題の割当方法と操作上の不具合を先に修正。予備試遊の結果を正式評価に流用しない。正式評価の人数は予備データから分散と必要精度を見積もって決め、根拠のない小標本のp値や単純平均で採否を決めない。
- 集計はゲーム別・技能層別、条件別の分布、完走率、選択所要、代表的な自由記述、個人差と悪化例を併記する。5段階の平均値に加え、条件別の回答分布を出す。初回の新奇性と6問後の飽きを混ぜない。
- **内容A vs B**: 同じ提示方法・技能層で、Aに十分な継続意向の向上があるか、かつ徒労感・離脱が悪化しないかを確認。Bは1種類の固定乱数セットなので、確認段階では**別の乱数固定セットを独立に用意し再現性を見る**。
- **提示方法**: 同じ内容セットの一覧 vs 順番を比較し、選ぶ楽しさと開始までの摩擦を分ける。両方式の優劣と内容Aの優劣は別の結論にする。
- **終了判断**: 機械的な特徴差だけなら未採用。優位な体験が認められず、または選択負担・途中離脱が悪化するなら不採用。初回で好評でも、供給の希少性と審査費が過大なら不採用。小規模予備試遊の良い感想だけでは全ゲーム展開しない。
- **採用の追加条件**: 既存より分かる価値があり、限られたゲームで継続供給する別のホールドアウト問題列でも再現すること。プール改訂、既挑戦問題の除外、図鑑・成績との一元性、運用の審査時間が許容範囲に収まること。全ゲーム一律の新モードは本Issueの対象外。

## 比較試作の実装・検証状況

- 試作URL: `/studies/curated`。通常のアプリナビゲーションには追加しない。`?game=nanpure|parking-jam&set=a|b&presentation=list|sequence&position=0..5` で実験条件と現在位置を固定できる（初期値はナンプレ/A/一覧/0）。ゲーム・セット・提示方法を変えたら現在位置を先頭へ戻す。
- 両セットの選定理由と seed は画面には表示しない。6問の難易度は表示する。別タブで既存のプレイ画面を開き、解いたあと研究画面へ戻る。実際のアプリへの採用を約束しない。
- 問題集の復元とIDの対応、A/B両セットの問題規模、プレイリンク、切替と画面状態は自動テストで検証する。ユーザーが試遊の評価結果を入力・保存する機能や新しい履歴保存は設けない。
- **技術的な実画面検証**と**人間による楽しさの比較試遊**は別。前者でブラウザエラーが無いことは後者の完了を意味しない。

## 結論

この実験で比較可能な候補を作り、意味のある特徴差も確かめられた。一方、選抜上位の特殊な候補ほど継続供給が薄いことが数値で示された。したがって、**採用判断は人間試遊と、通常の問題列でも価値が再現できるかの検証まで保留**する。「厳選してある」こと自体をサービスの利点と宣伝せず、現段階では開発用の試作にとどめる。#660 の問題品質調査と #652 のランダム出題設計には、この調査で得た問題ID・特徴差・供給上の限界を共有できる。
