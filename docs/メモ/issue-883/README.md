## これまでに分かったこと

- 既存の `games/`・`pages/`・`views/` と、アプリへゲームを接続する境界には意図的な設計の経緯がある。全面的なゼロベース再編の必要性は**確認されていない**。
- ただし `records/`・`zukan/`・`collection/`・`game-catalog/`・`components/`・`lib/` の一部は、名前と実際の所有範囲のずれ、別責務からの利用、曖昧な依存方向を持つ。**それだけで移動が正しいとは限らない**。
- 今の有力方針は「従来設計の有効な部分を維持し、不足する所有範囲を明確化し、根拠がある実装差分だけ整理する」。実装単位を小さくすることは、設計を局所化する理由にはならない。
- 機能別構成（高凝集・低結合）を基本にし、FSD/DDD/クリーンアーキテクチャの定型階層を無条件導入しない。
