## 維持の意味

- **責務・依存方向**：何を誰が決めるかを維持する。内部実装やすべての現在位置を固定しない。
- **物理ディレクトリ境界**：分離する理由が明確なときだけ現在のディレクトリ構造を維持する。
- **動作・データ契約**：整理を理由にURL、問題ID、記録、ゲーム体験を意図せず変更しない。

## A：維持確定（PO確認済み）

| 現行境界 | 維持する責務 | 所有しない責務・留保 | 維持の根拠 |
|---|---|---|---|
| `frontend/src/games/<game>/` | 1ゲームの規則・問題・難易度・採点・プレイ状態・固有UI | アプリの画面遷移や共通の記録保存方式 | APP.md / GAME.md / game-structure.md |
| `frontend/src/games/` 直下 | 意味が一致するゲーム共通契約・共通の仕組み | 特定ゲームだけの規則を無理に共通化すること | game-structure.md |
| `frontend/src/pages/` | ルーターが要求するURL・ルート定義 | 画面合成・ドメインの処理 | pages.md / generouted |
| `frontend/src/views/` | ルートのUI合成、画面固有状態、遷移、各機能の接続 | 独立した記録・図鑑等の機能規則 | views.md / PR #180 |
| `frontend/src/components/ui/` | shadcn/ui由来の一般UI | ゲーム固有UI・機能規則 | shadcn-ui.md |

この「維持」は、**境界とその責務を維持する**承認であり、内部の全ファイルを移動禁止とするものではない。既存のゲーム内部の責務分割も、意味のあるものを維持し、形式だけの統一は要求しない。

## B：責務は必要だが物理配置は未確定

| 現行領域 | 必要な論理責務 | 再判定する部分 |
|---|---|---|
| `components/`（`ui/`以外） | ゲーム横断のUI、画面全体で使う表現、アプリの共通導線 | アプリ専用UI・設定・音の接続と、純粋な再利用UIの境界 |
| `lib/` | 音声・動き・型ガード・整形・ブラウザ技術の仕組み | 出題条件や並び順設定など、意味を持つアプリ機能 |
| `records/` | プレイの事実、保存、比較、履歴と成績 | 機能UI、画面合成、記録からの再プレイとの関係（#249と調整） |
| `zukan/` | 各問題の進捗、収集、図鑑、前回の状態との比較 | ゲームホーム全体の表示や状態まで図鑑が所有するか |
| `collection/` | ゲーム横断の問題収集・集計 | 図鑑・記録と統合すべきか、独立すべきか |
| 利用者設定（複数領域） | 設定値の保存と編集 | 出題条件の評価や、機能固有の判断まで設定側が所有するか |
| アプリの起動・シェル・ホーム（複数領域） | 初期化と体験全体の接続 | 画面合成・機能・汎用部品との分担 |

上の表は、**現状のディレクトリを維持すると決めたものではない**。論理的な責務同士をさらに統合・分割する余地がある。

## C：物理境界も再評価する

`frontend/src/game-catalog/` は維持確定から外す。**ゲームを登録してアプリへ接続する仕組みの必要性**は認めるが、現在のディレクトリ全体を維持する根拠にはならない。

- 2ファイル：カタログ一覧と `GameCatalogEntry` の大きな契約
- ゲーム別33ファイル：11ゲーム × 登録・プレイ・記録結果のアダプター
- 残り14ファイル：アプリホーム、ゲームホーム、プレイ・結果、ナビゲーション、記録履歴、出題、音・診断等（実装49ファイルの分類）

※ この分類ではカタログ契約の2ファイル以外の共通14ファイルを一括りにしている。詳細の責務対応は `decomposition.md` を参照。

`game-catalog/` の導入時（PR #424）の目的、すなわち具体ゲームの接続を共通化し、ゲーム間の直接依存と追加時の手作業を減らすことは維持対象。ただし**その目的をどのモジュールで実現するかは未決定**。

## 破壊してはいけない動作契約

- 問題ID、記録IDによる結果復元、再プレイの可否、保存済みの記録・試行と旧版データの受理条件。
- 各ゲームの規則、問題供給、難易度の意味、採点、操作感。
- ゲームホームの進捗、図鑑の前回差分、記録一覧、ゲーム横断コレクションの意味。
- 各具体ゲーム同士を直接依存させず、統合層で接続する原則。
- URLと依存検査、生成処理、動的なアセット読込の整合。

参照：ADR-0001/0002/0004/0012/0018、APP.md、GAME.md、`.claude/rules`。
