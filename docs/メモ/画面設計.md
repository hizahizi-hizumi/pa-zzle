# 画面設計メモ

画面設計を詰める過程で得た、まだ正本へ固定しない制作上・検証上の知見を残す。

現在仕様の判断には `APP.md` / `GAME.md` / `DESIGN.md` / `docs/画面/` を優先する。

## 開始条件選択画面

ウォーターソートの難易度選択画面を詰める過程で、次の知見が得られた。

- 文字情報を減らすだけでは、選択画面としての密度やゲームらしさまで失うことがある。説明文を戻す前に、ゲーム固有の視覚表現で選択肢を成立させられないか確認する。
- 実際の開始盤面をそのまま代表例として見せると、比較に不要な情報まで増えやすい。開始条件の差を理解するために必要な要素だけを残した簡略表現の方が扱いやすい場合がある。
- 見た目の分かりやすさを作るために、実際の難易度要因ではない規則性を加えると誤解を生む。ウォーターソートでは「易しいほど色を揃える / 難しいほど混ぜる」表現は採用しなかった。
- プレビューとラベルだけを配置しても、選択肢全体が操作対象だと伝わらないことがある。操作可能範囲の境界や遷移を示す補助表現まで含めて実画面で確認する。
- 共通化候補は、一つのゲームで成立した実装だけを根拠に固定しない。別ゲームで同じ役割を持つ画面を作ったときに、同じ意味と振る舞いが残るかを比較する。
- 画面の成立確認では、文書や静止コードだけでなく、スマートフォンとPCの実ブラウザで、視線の流れ・比較しやすさ・操作可能範囲を確認する。
