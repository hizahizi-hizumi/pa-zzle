# システム要件

pa-zzle が製品として保証する能力・性質を定義する。

機能要件は `FR-nnn`、非機能要件は `NFR-nnn` の一意な識別子を持つ。機能要件は製品が提供する振る舞い・能力を、非機能要件はその能力や製品全体に要求する品質・制約を扱う。

一つの要件は、実装や画面構成が変わっても独立して満たす・満たさないを判断できる粒度とする。画面上の配置、保存方式、関数・型などの実現方法は含めない。

一つの要件は、満たす・満たさないを一つの問いで判定できる保証とする。「かつ」「そのうえで」で結ばれた二つの保証が、一方だけを満たす状態を想定できるなら、別の要件に分ける。範囲を限定する文（「〜は保証しない」「〜でも」）は同じ要件に含めてよい。

要件に根拠となる上位正本がある場合は `upstream` から参照し、直接参照する上位正本を持たない場合は `upstream: []` とする。利用者要求への参照は、要件として成立するための必須条件としない。

`upstream` には、その要件が無いと満たせなくなる利用者要求だけを記す。体験全体の要求（RQ-001）を、個々の要件へ一律に付けない。

要件文は一つの意味へ絞り、曖昧な形容や複数の独立した保証を一文へまとめることを避ける。

「楽しく」「気持ちよく」「ワクワク」などの体験品質の形容は、その体験が要件の存在理由である場合に限り機能要件の本文に含める。含めた形容は、体験品質を扱う非機能要件（NFR-001）の基準で判定する。

要件に数値を書くのは、その値に利用者要求・実測などの根拠がある場合に限る。根拠が無いときは、「測定可能な基準を仕様で定め、それを満たす」形で要件を置く。

要件の本文は、ID体系外の文書（`docs/パズル/` の難易度文書など）を参照しなくても意味が決まるように書く。横断文書は要件を満たすための原則・工程を定める側であり、要件の意味を補わない。
