# パズル仕様

パズルごとに `PZL-nnn` の識別子を持つ。ファイル名・YAML フロントマターの `id`・文書の表題を一致させる。

要件を満たすため、そのパズルだけの決まりを置く。パズルを追加・変更するときに、知らずに変えてはいけないことを書く。

主に次を決める。

- 何を遊ぶもので、何を満たせばクリアか。何をミスとして数えるか。
- どんな問題を出すか。
- 何が状態の知らせで、何が補助か（SPEC-017）。
- どのやり直しの操作を提供するか（SPEC-007）。
- 難易度ごとの挑戦の違い。
- 評価で何を称え、どう配点するか。自己ベストで何を比べるか。

## 評価の記述形式

採点の共通原則と成績の契約は [SPEC-006](../仕様/ゲーム/SPEC-006.md) に従う。

各パズルの `## 評価` は、次の小見出しをこの順番で持つ。

1. `### 称えたいプレイ`: ルール・操作・考える過程から、どんな解き方を上手なプレイとして称えるか。現行の採点項目や減点対象を言い換えるだけにしない。
2. `### 採点項目`: 各項目がどんな上手さを表し、その上手さをプレイ中のどの事実から測るか。重要な操作や観点を評価しない場合は、その理由も書く。
3. `### 配点`: 各項目の点数と、それらの上手さのうち何を相対的に重視するか、その理由。
4. `### 自己ベスト`: どの値を、どちらの方向で比較するか。

採点項目を決める前に称えたいプレイを定め、採用した項目の計測値がその上手さを表すか確認する。現行の採点方式から理由を逆算しない。既存方式の根拠を確認できない場合は、正当化する理由を作らず、別途採点設計を評価する。

評価段階の境目や難易度を分ける範囲のように、値自体がプロダクトの判断となるものは記す。調整用の係数や上限はコードを正とし、ここには書かない。

調査・検証の過程は `docs/パズル/導入調査/` に置く。
