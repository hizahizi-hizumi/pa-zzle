# パズル仕様

そのパズルだけの決まりを置く。パズルを追加・変更するときに、知らずに変えてはいけないことを書く。

主に次を決める。

- 何を遊ぶもので、何を満たせばクリアか。何をミスとして数えるか。
- どんな問題を出すか。
- 何が状態の知らせで、何が補助か（SPEC-017）。
- どのやり直しの操作を提供するか（SPEC-007）。
- 難易度ごとの挑戦の違い。
- 評価で何を称え、どう配点するか。自己ベストで何を比べるか。

## 評価の記述形式

各パズルの `## 評価` は、次の小見出しをこの順番で持つ。

1. `### 称えたいプレイ`: どのような解き方を称えるか。
2. `### 採点項目`: 何を計測・評価するか、採用しない観点をどう扱うか。
3. `### 配点`: 各項目の点数と、何をどの程度重視するかの理由。
4. `### 自己ベスト`: どの値を、どちらの方向で比較するか。

称えたいプレイから採点項目と配点まで、判断の関係を読めるようにする。既存の判断の理由が確認できない場合は、現在の方式を正当化する理由を作らず、別途評価する。

調査・検証の過程は `docs/パズル/導入調査/` に置く。
