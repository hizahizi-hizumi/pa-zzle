# 仕様

要件を満たすための今の決まりを置く。書く基準は [docs/README.md](../../README.md) に従う。

- 今の決定だけを、言い切りで書く。理由・経緯・出典は書かない（理由が要るものは ADR）。
- 実装から読める振る舞いの詳細（画面の配置・見た目・演出、アルゴリズム、記録の項目など）は書かない。コードとテストを正とする。
- 値は、その値自体がプロダクトの判断であるもの（評価段階の境目、難易度を分ける範囲など）だけを書く。調整用の係数や上限は書かない。
- 要件や他の仕様の言い換えを書かない。

一つの仕様は、一つの変更理由でまとまって変わる決まりを単位とし、`SPEC-nnn` の識別子を持つ。

配置は責務の最も狭い場所を選ぶ。

- [`アプリ/`](アプリ/): 個々のゲームを知らなくても成立する、アプリ全体の決まり。
- [`ゲーム/`](ゲーム/): パズルの種類によらず、すべてのゲームが同じ意味で従う決まり。
- [`パズル/`](パズル/): そのパズルだけの決まり。

複数のパズルで実装が似ていることだけを理由に、ゲーム共通の決まりへ上げない。
