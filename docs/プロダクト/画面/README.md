# 画面

要件・仕様を利用者との接点へ落とした、画面種別ごとの情報設計・操作設計を定義する。

各画面文書は `SCR-nnn` の一意な識別子を持つ。一つの画面種別を一つの文書として扱い、画面の目的、利用者が達成すること、必要な情報と優先順位、主要操作、状態、アプリ共通とゲーム固有の境界、画面サイズに応じた成立を扱う。

画面は関連する利用者要求・ユーザーストーリー・システム要件・仕様を参照する。画面固有の情報設計を上位の要求や仕様へ逆流させない。

採点式、保存形式、問題生成規則、React部品構造、正確なデザイントークン値、Issueの作業完了条件、検証手順は画面文書に含めない。

既存ゲームの画面構成を新しいゲームの規格としてコピーせず、同じ役割に必要な一貫性だけを共通化する。
