# SCR-003 プレイ

## 役割

利用者が問題を読み、自分で考え、操作し、パズルを解くための画面。pa-zzle の中で最もゲーム固有性が強い画面であり、共通UIよりパズルそのものを主役にする。

## 主領域

盤面、問題文、駒、入力領域など、そのパズルで判断と操作の対象になるものへ画面資源を最優先で使う。

ゲーム名、経過時間などプレイの文脈を保つ情報は、主領域と競合しない強さで示す。評価の詳細、自己ベスト、最短値、内部識別子、難易度診断値など、現在の一手を考えるために不要な情報は持ち込まない。

## 判断と操作

ルール上可能な操作は、利用者が盤面を読んで判断できることを基本とする。合法手、正解、将来の最善手などを通常UIが先回りして教えない。補助が必要な場合は、ゲーム性として意図した明示的な機能として定義する。

主操作は盤面と直接対応させる。元に戻す、やり直す、新しい問題へ移るなど、パズルを解く行為そのものではない操作は主領域と競合させない。

操作を受け付けたこと、現在の選択、盤面がどう変化したか、操作が成立しなかったことは、次に何を判断すればよいか分かる形で返す。

## 状態遷移と演出

ゲームルール上の状態変更と、それを伝えるアニメーションを同一視しない。演出が継続していても、ルール上独立して受け付けられる次の操作まで一律に停止しない。

クリア成立はゲーム側の契約で判定し、画面側が見た目から再判定しない。クリアが確定したら、最終操作の結果を利用者が認識できる状態を経て結果へ進む。

## 画面サイズ

スマートフォンでは、通常のプレイ中にページ全体を移動しながら盤面と入力UIを往復する必要がないよう、判断・操作対象を一つの視野へ収めることを優先する。

PCではスマートフォン向け配置を中央へ置いて余白だけを増やさず、ゲーム性を損なわない範囲で盤面・入力領域の把握しやすさへ広さを使う。
