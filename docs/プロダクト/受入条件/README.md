# 受入条件

利用者要求とユーザーストーリーで求めた価値、およびシステム要件が、製品として**成立したと判断する条件**を定義する。

一つの受入条件文書は、一つの利用者価値または密接な要件群についての条件集合とし、`AC-nnn` の一意な識別子を持つ。検証対象となる `RQ-nnn`・`US-nnn`・`FR-nnn` / `NFR-nnn` を参照する。

受入条件は Issue の作業完了条件やテスト手順ではない。`verify.sh` の成功、Playwright の実行、特定ファイルの追加などは開発工程で扱う。自動テストで受入条件を保証してよいが、検証手段は交換可能とする。

仕様の内部実装を確認する条件ではなく、利用者から観測できる結果や製品として保証すべき状態を中心に記述する。
