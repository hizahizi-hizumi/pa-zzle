# プロダクト文書

pa-zzle の意図と決まりの正本を置く（ADR-0003）。

- `要求/`: 利用者が実現したい状態。
- `要件/`: そのために製品が保証する能力・性質。
- `仕様/`: 個々のゲームを知らなくても成立する、アプリ全体の決まり。
- `ゲーム/`: パズルの種類によらず、すべてのゲームが共通して従う決まり。
- `パズル/`: パズル固有の遊び・出題・体験・難易度・評価に関する設計判断。
- `画面/`: 画面ごとの目的と、その画面で優先すること・やらないことの意図。画面の配置・構成は書かない。

各ディレクトリの意味と書き方は、それぞれの README を正とする。

## ファイル名

ID付き文書のファイル名は `ID-タイトル.md` とする。タイトルには文書の見出しからIDを除いた表題を使い、空白を除く。ファイル名のIDとYAMLフロントマターの `id` を一致させる。

## 識別子

要求、機能要件、非機能要件、アプリ仕様、ゲーム共通仕様、パズル仕様、画面は、それぞれ `RQ-nnn`、`FR-nnn`、`NFR-nnn`、`SPEC-nnn`、`GAME-nnn`、`PZL-nnn`、`SCR-nnn` の系列ごとに一意な識別子を持つ。各系列は `001` から採番し、番号に意味を埋め込まない。採番体系を変更する場合は識別子と全参照を同時に更新する。通常の追加・変更では、割り当て済みの識別子を変更・再利用しない。

ID付き文書は YAML フロントマターに `id` を持つ。要件だけは、根拠とする要求を `upstream` に列挙する（無ければ `upstream: []`）。ほかの文書は upstream を持たない。
