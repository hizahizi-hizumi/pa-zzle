# プロダクト文書

pa-zzle の意図と決まりの正本を置く（ADR-0003）。

- `要求/`: 利用者が実現したい状態。
- `要件/`: そのために製品が保証する能力・性質。
- `仕様/`: 要件を満たすための今の決まり。アプリ・ゲーム共通の取り決めと、パズルごとの定義。
- `画面/`: 画面ごとの目的と、その画面で優先すること・やらないことの意図。画面の配置・構成は書かない。

各ディレクトリの意味と書き方は、それぞれの README を正とする。

## 識別子

要求、機能要件、非機能要件、仕様、画面は、それぞれ `RQ-nnn`、`FR-nnn`、`NFR-nnn`、`SPEC-nnn`、`SCR-nnn` のリポジトリ内で一意な識別子を持つ。番号に意味を埋め込まず、一度割り当てた識別子は変更・再利用しない。ただし `SCR-nnn` は、ADR-0003 で廃止した旧画面文書の番号を使い直している。

ID付き文書は YAML フロントマターに `id` を持つ。要件だけは、根拠とする要求を `upstream` に列挙する（無ければ `upstream: []`）。ほかの文書は upstream を持たない。
