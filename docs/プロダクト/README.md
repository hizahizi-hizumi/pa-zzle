# プロダクト文書

pa-zzle の意図と決まりの正本を置く（ADR-0003）。

- `要求/`: 利用者が実現したい状態。
- `要件/`: そのために製品が保証する能力・性質。
- `仕様/`: 要件を満たすためのアプリ・ゲーム共通の取り決め。
- `パズル/`: パズルごとのルール・問題・難易度・評価の定義。
- `画面/`: 画面ごとの目的と、その画面で優先すること・やらないことの意図。画面の配置・構成は書かない。

各ディレクトリの意味と書き方は、それぞれの README を正とする。

## ファイル名

ID付き文書のファイル名は `ID-タイトル.md` とする。タイトルには文書の見出しからIDを除いた表題を使い、空白を除く。文書の `id` は変更しない。

## 識別子

要求、機能要件、非機能要件、共通仕様、パズル仕様、画面は、それぞれ `RQ-nnn`、`FR-nnn`、`NFR-nnn`、`SPEC-nnn`、`PZL-nnn`、`SCR-nnn` のリポジトリ内で一意な識別子を持つ。番号に意味を埋め込まず、一度割り当てた識別子は変更・再利用しない。ただし `SCR-nnn` は、ADR-0003 で廃止した旧画面文書の番号を使い直している。旧パズル仕様に割り当てていた `SPEC-nnn` は廃番とし、再利用しない。

ID付き文書は YAML フロントマターに `id` を持つ。要件だけは、根拠とする要求を `upstream` に列挙する（無ければ `upstream: []`）。ほかの文書は upstream を持たない。
