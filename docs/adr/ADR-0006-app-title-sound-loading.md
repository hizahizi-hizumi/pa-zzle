# アプリを開いたときにタイトルで効果音を読み込んでから遊び始める

## 要約

- **決定**: ホームを開いて文書を読み込んだときだけ、ホームの上に全面のタイトルを出し、効果音すべての読み込みを上限付きで待ってから入れるようにする。ゲームのピクトグラムからはそのゲームのホームへ直接入れる。上限を過ぎたときと読み込めない音があったときは、音なしで進める。
- **主な選択肢**: タイトルを置かず各画面で読み込む（今まで） / 全 URL でタイトルを出す / ホームを開いたときだけタイトルを出し、上限付きで待つ / 読み込み終えるまで待ち続ける。
- **背景**: 効果音を同梱の音声ファイルにし、読み込み前に鳴らそうとした音は鳴らさないことにしたため、回線が遅い・初めて開くなどで、遊び始めた最初の操作の音が鳴らなかった。
- **要約**: アプリをホームで開いたときだけタイトルを出し、効果音すべての読み込みと AudioContext を動かす最初の操作を、遊び始める前に済ませる。タイトルを置かない案、全 URL で出す案、読み込み終えるまで待つ案と比べた。ピクトグラムで直接ゲームへ入れるので1手が選ぶ操作そのものになること（NFR-006）と、待ちに上限を置き失敗しても音なしで遊べることを重視した。

## 背景と問題

効果音は同梱の音声ファイルを Web Audio API で鳴らす。音はそれを鳴らす画面を出したときに読み込み始め、読み込み前に鳴らそうとした音は鳴らさない。遅れて鳴らすと、操作や演出とずれた時に鳴るからである。

そのため、回線が遅いときや初めて開いたときは、プレイを始めた直後の数回の操作音、ゲームのホームへ直接来てすぐ押した「始める」音、ホームを開いてすぐ選んだ「選ぶ」音が鳴らなかった。遊び始めの手応えが欠けるのは、体験の入口を弱める（RQ-001）。

また、ブラウザは利用者が操作するまで音を出させない。最初の操作で AudioContext を作って動かすまでは、どの画面でも音を出せない。

一方、選んで始めるまでに無関係な手間を求めないこと（NFR-006）を保証しており、入口に1手増やすことはこれと衝突しうる。共通UIは静かで、ゲームより前に出ないこと（DESIGN.md）とも釣り合わせる必要がある。

## 判断基準

- 遊び始めた最初の操作から効果音が鳴ること。
- 遊び始めるまでに、選ぶことと関係しない手間を増やさないこと（NFR-006）。
- 回線が悪くても、効果音が読み込めなくても、遊べないまま待たせないこと。
- 効果音を鳴らさない利用者を待たせないこと。
- 共有された URL やブックマークでゲームの画面へ直接来た利用者の流れを妨げないこと。

## 検討した選択肢

1. **タイトルを置かず、各画面で読み込む**（今まで）
2. **どの URL を開いてもタイトルを出す**
3. **ホームを開いたときだけタイトルを出し、上限付きで待つ**
4. **ホームを開いたときだけタイトルを出し、読み込み終えるまで待ち続ける**

## 採用した選択肢と理由

採用: **ホームを開いたときだけタイトルを出し、上限付きで待つ**。理由: 遊び始める前に、効果音の読み込みと音を出せるようにする最初の操作の両方を済ませられる。タイトルに全ゲームのピクトグラムを置き、押せばそのゲームのホームへ直接入れるので、タイトルの1手はホームで遊ぶゲームを選ぶ操作をそのまま前へ出したものになり、選ぶことと関係しない手間にならない。ゲームを決めていない利用者には、pa-zzle と遊べるゲームを最初に一望させる入口の体験にする。

- ホーム以外の URL へ直接来た利用者は、遊ぶものを既に決めているので、タイトルを挟まない。その代わり、開いたときに効果音すべての読み込みを始めておく。アプリの中でホームへ戻ったときも出さない。
- 待つ時間には上限を置き、上限を過ぎたときと読み込めない音があったときは、待ち終えたものとして音なしで進める。効果音は操作に添えるもので、音が出ない環境でも同じように遊べるようにしている（DESIGN.md）ので、音のために遊ぶのを止めない。間に合わなかった音は、今までどおり読み込み終えるまで鳴らさない。
- 効果音を鳴らさない設定では待たない。待つ理由が無い。
- タイトルから入る操作そのものでは効果音を鳴らさない。画面遷移そのものに音を付けないという決まり（DESIGN.md）に従う。ピクトグラムで入るときは、ホームでゲームを選んだときと同じ音を鳴らす。

### 帰結

- Good: ホームから遊び始めると、最初の選ぶ音・始める音・操作音から鳴る。
- Good: ゲームを決めている利用者は、ピクトグラムで今までより少ない手数でゲームのホームへ着く。
- Bad: ゲームを決めていない利用者には、ホームに入るための1手が増える。
- Bad: 回線が遅いと、ホームを開いてから入れるまで上限の時間だけ待たせる。
- Bad: ホーム以外の URL へ直接来て、読み込み終える前に押した音は、今までどおり鳴らない。

## 各選択肢の良し悪し

### タイトルを置かず、各画面で読み込む

- Good: 手数も待ちも増えない。
- Bad: 回線が遅いと、遊び始めの音が鳴らない。最初の操作が AudioContext を動かす操作を兼ねるので、その操作の音は鳴らしにくい。

### どの URL を開いてもタイトルを出す

- Good: どこから来ても、遊び始めから音が鳴る。
- Bad: 遊ぶものを決めて直接来た利用者に、選ぶことと関係しない1手を求める（NFR-006）。

### ホームを開いたときだけタイトルを出し、読み込み終えるまで待ち続ける

- Good: 読み込める音はすべて鳴る。
- Bad: 回線が悪いと、いつまでも遊び始められない。効果音のために遊ぶこと自体を止める。
