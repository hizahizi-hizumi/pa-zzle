# ブリッジパズルの島を上下左右に隣り合わせない

## 要約

- **決定**: ブリッジパズルの問題では、島どうしを上下左右に隣り合わせない（間に1マス以上空ける）。盤面の型・生成器・問題の契約のすべてでこの規則を守る。
- **主な選択肢**: 隣り合う島を許し、なぞる操作だけで架ける / 隣り合う島の間ごとにボタンを置く / 隣り合わせない。
- **背景**: スマホの 10×10 では、隣り合う島の間に見える線の長さが約 7px しかなく、タップで押し分けられない。合意の操作は「島と島のあいだをタップ」である。
- **要約**: ブリッジパズル（橋をかけろ）の島は上下左右に隣り合わせず、盤面の型・生成器・問題集のすべてでこの規則を守る。隣り合う島を許してなぞる操作だけで架ける案、島の間ごとにボタンを置く案と比べた。スマホの 10×10 でも島の間をタップで押し分けられ、合意したタップの操作だけで全問を解けることを重視した。

## 背景と問題

ニコリの「橋をかけろ」は隣り合う島を許す。ブリッジパズルはスマホで 10×10 までの盤面を遊ぶので、390px 幅で1マス約 36px、島の丸は直径約 29px になる。隣り合う2島の間に見える線は約 7px で、指で押し分けられない。合意の操作は「島と島のあいだをタップで 1本 → 2本 → なし」で、なぞる操作は補助として付ける。

## 判断基準

- 合意したタップの操作だけで全問を最後まで解けること。
- スマホの 10×10 で誤タップが少ないこと。
- 問題の供給と難易度の分け方を損なわないこと。

## 検討した選択肢

1. **隣り合う島を許し、なぞる操作だけで架ける**
2. **隣り合う島の間ごとにボタンを置く**
3. **島を隣り合わせない**

## 採用した選択肢と理由

採用: **島を隣り合わせない**。理由: 島の間に必ず1マス以上の線が見え、どの橋もタップで押せる。研究用の生成器も既にこの規則で、問題の供給と難易度の分け方は成り立った（導入調査の計測）。

### 帰結

- Good: どの問題もタップだけで解け、なぞる操作は補助にとどまる。
- Good: 盤面の型（`assertBridgesBoard`）が隣り合う島を拒むので、生成器や問題集の誤りが盤面を作る時点で分かる。
- Bad: 隣り合う島の組（「1」と「1」を並べるなど）を使った問題は出せず、ニコリの問題とは盤面の作りが違う。

## 各選択肢の良し悪し

### 隣り合う島を許し、なぞる操作だけで架ける

- Good: ニコリと同じ盤面を出せる。
- Bad: タップで解けない問題ができ、合意の操作と食い違う。

### 島の間ごとにボタンを置く

- Good: 隣り合う島の間も押せる。
- Bad: 交わる所でボタンが重なり、盤面の見た目に操作の部品が増える。
