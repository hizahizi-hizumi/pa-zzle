# 結果画面を記録IDの専用パスで開く

## 要約

- **決定**: 記録を保存できたプレイの結果画面を、記録IDで開く専用パス `/puzzles/<game>/result/<記録ID>` とし、保存した記録から結果を作り直して描く。
- **主な選択肢**: プレイ画面の中の状態のままにする / 結果の値を location state だけで運ぶ / 記録IDの専用パスで記録から作り直す。
- **背景**: 結果画面がURLを持たず、結果を見たまま再読み込みすると結果が消えて次の問題が始まっていた。
- **要約**: 記録を保存できたプレイの結果画面を記録IDで開く専用パス /puzzles/<game>/result/<記録ID> とし、保存した記録から現在の規則で結果を作り直して描く。プレイ画面の中の状態のままにする案、結果の値を location state だけで運ぶ案と比べた。再読み込みで結果を失わないことと、保存した記録を結果の正本にできることを重視した。

## 背景と問題

結果画面はプレイ画面の中の状態で、URLを持たなかった。結果を見たまま再読み込みすると、結果が消えてプレイ画面が新しい問題を始めた。

一方、記録には難易度、問題の識別情報、プレイ事実が保存されており、評価点や評価段階は保存事実から現在の規則で導出する（SPEC-001）。結果画面に出す内容も、記録から作り直せる。

## 判断基準

- 結果を見たまま再読み込みしても、同じ結果が示され、次の問題が意図せず始まらないこと。
- 結果の内容を、保存した記録と別の経路で持たないこと。
- 記録の保存に失敗したプレイでも、結果を示せること。
- ゲームを列挙せず、ゲームカタログから結果画面を描けること。

## 検討した選択肢

1. **プレイ画面の中の状態のままにする**
2. **結果の値を location state だけで運ぶ専用パス**
3. **記録IDの専用パスで、記録から結果を作り直す**

## 採用した選択肢と理由

採用: **記録IDの専用パスで、記録から結果を作り直す**。理由: 記録は保存済みで一件ごとに識別できるので、記録IDだけを持つURLから同じ結果をいつでも作り直せる。結果の正本を記録に一本化でき、プレイ中の結果の計算をゲームごとの純関数に切り出して、記録からの作り直しと共用できる。

クリアして記録を保存できたら、結果画面へ履歴を置き換えて遷移し、保存結果（自己ベスト更新など）は location state で渡して告知に使う。記録の保存に失敗したプレイは、従来どおりプレイ画面の中で結果を出す。存在しない記録、別ゲームの記録、結果を作り直せない古い記録、未知のゲームの記録は、区別せず「記録が見つかりません」とする。

### 帰結

- Good: 結果表示中に再読み込みしても、同じ結果のまま次の行動を選べる。
- Good: 結果の計算がプレイ中と記録からの作り直しで一つになる。
- Bad: 記録の保存に失敗したプレイは専用パスを持てず、プレイ画面の中で結果を出す経路が残る。
- Bad: 自己ベスト更新などの告知はクリア直後の遷移で渡す location state に依存し、URLを直接開いたときには出せない。
- Bad: 古い版の記録など、今の規則で結果を作り直せない記録の結果は開けない。

## 各選択肢の良し悪し

### プレイ画面の中の状態のままにする

- Good: 遷移が無く、実装が最も小さい。
- Bad: 再読み込みで結果が消え、新しい問題が始まる。

### 結果の値を location state だけで運ぶ専用パス

- Good: 記録の有無に関わらず、どのプレイの結果も同じ経路で出せる。
- Bad: 結果の内容を記録と別に持つことになり、URLを直接開くと結果を出せない。

### 記録IDの専用パスで、記録から結果を作り直す

- Good: URLが記録IDだけを持ち、記録が残る限り同じ結果を開き直せる。
- Bad: ゲームごとに記録から結果を作り直す処理と、その版の扱いが要る。
