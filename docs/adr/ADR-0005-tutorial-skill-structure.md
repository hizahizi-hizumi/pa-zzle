# チュートリアルを作るスキルを、大原則と作り方に絞って組み立てる

## 要約

- **決定**: `design-game-tutorial` スキルは、必ず守る大原則・迷ったときの基本の形・書かずに作る側が決めることの3段で組み立てる。見直しは実装する側と遊ぶ側の2つの視点で行い、日本語は大原則に入れずに編集者役の見直しを作り方の手順に置く。指摘の経緯はスキルに持たず、理由はこの ADR に残す。
- **主な選択肢**: 指摘のたびに原則・チェックリスト・細部へ決まりを足す / 大原則を絞り、細かい判断を作る側に任せる。
- **背景**: バイナリパズル・スライドパズル・ウォーターソート・マインスイーパーのチュートリアルを作る中で、スキルが指摘の寄せ集めになり、作る側が個別の細かい判断をオーナーに回すようになった。
- **要約**: design-game-tutorial スキルを、大原則（P1〜P6）・基本の形・書かないことの3段で組み立て、見直しを実装する側と遊ぶ側の2視点にし、日本語は編集者役の見直しを作り方の手順に置く。指摘のたびに原則・チェックリスト・細部へ決まりを足す案と比べた。大原則と枝葉が同じ重さで並ぶと、決まりで決まらない細かい判断がオーナーに回ることを重く見た。

## 背景と問題

チュートリアルは、1枚の本物の盤面をルールを1つずつ使わせながら解かせる形で作ってきた。手本にしたのは 0h h1 のチュートリアル（https://github.com/florisluiten/0hh1 の `js/tutorial.js`）。

指摘を受けるたびに、その事例を原則・チェックリスト・細部の決まりとして足していった。その結果、次のことが起きた。

- 「同じ盤面を最後まで使う」のような大原則と、読点や擬人化のような言い回しの決まりが、同じ大きさで並んだ。原則そのものも条文のように長くなり、読んでも判断の軸として働かなくなった。
- チェックリストが30項目近くになり、見直し役はチェックリストに沿って細かい指摘を出し、その指摘がまた決まりになった。
- 決まりで決まらないこと（選んだボトルの見た目、効果音、手順の形など）が判断待ちとして積み上がり、オーナーに回された。個別のチュートリアルの細かい判断は、オーナーがすべきものではない。

一方で、日本語については放っておくと崩れることが分かっている。スライドパズルでは、遊ぶ側の見直しで言葉の引っかかりが挙がったのは2か所だけだった。しかし編集者役に全文を出る順に見直させると、20か所近くに直すべき所が見つかった。遊ぶ側は言葉を細かく言わないので、遊ぶ側の感想だけでは言葉は直らない。

## 判断基準

- 必ず守ることと、作る側が決めてよいことの区別が、読んですぐ分かること。
- 個別のチュートリアルの細かい判断を、オーナーに回さずに済むこと。
- 見直しが、作った本人には見えない問題を拾い、細かい決まりを増やさないこと。
- 日本語が崩れないこと。

## 検討した選択肢

1. **指摘のたびに決まりを足す**（原則・チェックリスト・細部に事例を足していく）
2. **大原則を絞り、細かい判断を作る側に任せる**（大原則・基本の形・書かないことの3段にする）

## 採用した選択肢と理由

採用: **大原則を絞り、細かい判断を作る側に任せる**。理由: 決まりを足し続けると、大原則と枝葉の区別がつかなくなり、決まりで決まらない細かい判断がオーナーに回る。大原則を1行ずつの少数に絞れば、それ以外は作る側が大原則に照らして決められる。

- 大原則は、破れば完成と呼べないものだけにする。言い回しや見た目の細かい決まりは入れない。
- 基本の形（入口・手を引く・手を離す・完成）は、迷ったときの既定にとどめる。パズルに合わなければ変えてよい。
- 見直しは2つの視点で行う。
  - 実装する側: 大原則の違反と不具合だけを報告させる。経緯や前回の指摘は渡さない。経緯を知っている目では、初めての人の分かりにくさに気づけないため。
  - 遊ぶ側: 画面の開き方だけを渡し、操作も感想の観点も指示しない。観点や操作を指示すると、自然に遊ぶ人の体験ではなく、指示された点検の結果が返ってくるため。
- 日本語は大原則に入れず、作り方の手順として、日本語に厳しい母語話者の編集者役に一言を出る順にすべて見直させる。言葉の決まりを原則に書き足すと枝葉が増えるが、見直しを省くと日本語が崩れるため、手順で担保する。
- 指摘の経緯や事例はスキルに持たない。スキルは今の決まりだけを書き、蒸し返されたくない決定の理由はこの ADR に書く（`docs/README.md`）。

### 帰結

- Good: スキルが短くなり、必ず守ることがすぐ分かる。細かい判断は作る側が決め、オーナーには完成したものを見せるだけで済む。
- Good: 個別の指摘がスキルの決まりとして積み上がらない。
- Bad: 細かい決まりを書かないので、同じ種類の細かい失敗を別のパズルで繰り返すことがありうる。見直しの2つの視点と編集者役で拾う前提にしている。
- Bad: 過去の指摘の事例をスキルから読めなくなる。必要なら PR #493・#553 や各チュートリアルのブランチの履歴をたどる。

## 補足

- 1枚の本物の盤面を、ルールを1つずつ使わせて解かせる形の手本: 0h h1（Q42, 2014）。ルールより先にゴールを言い、光ったマスだけを押させ、最後に通常のクリア演出を流す。
- その場で出す説明が効き、長い説明の効果は薄い: Andersen et al., CHI 2012（https://grail.cs.washington.edu/wp-content/uploads/2015/08/andersen2012tio.pdf ）。
- 関連: PR #493（バイナリパズルのチュートリアル）、PR #553（このスキル）。
