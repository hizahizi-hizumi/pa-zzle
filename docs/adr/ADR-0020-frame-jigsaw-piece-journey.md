# 選ぶ・解く・結果の行き来を、額の中のジグソーを1ピースずつ揃える体験として繋ぐ

## 要約

- **決定**: アプリ全体を、壁に掛けた額の中のジグソーを1問1ピースずつ揃えていく体験にする。奥行きは壁・額・台紙・ピースの順で、選ぶほど寄り、解き終えると戻る。ホームの額の中にはそのゲームの台紙を見せ、ゲームのホームも同じ壁と額で囲み、結果には解いた問題のピースを今回の評価の色で「問題選択」の上に小さく浮かべる。解いたピースは、1つの質感の定義から描く高級な実物とし、アプリの中で質感の豊かさが際立つのをゲーム固有表現と解いたピースだけにする。結果から次の問題へ進むときは、そのピースを結果の「問題選択」へしまってから進む。
- **主な選択肢**: 行き来ごとに別の比喩を当てる / 額や奥行きだけで全部の行き来を通す / 画面は変えず、行き来の間だけピースを出す / 壁・額・台紙・ピースを画面に置き、寄って戻る一本の筋で繋ぐ。ピースの質感は、平らな絵で評価に添える / 大きく強い光の立体で見せる / 小さく控えめな光の立体を、1つの質感の定義から描く、と比べた。
- **背景**: ホーム・ゲームのホーム・プレイ・結果の間の行き来は、ゲームのホームからプレイへを除いてどれも一瞬の切り替えで、台紙からピースを抜いて入る既存の演出と、図鑑でピースに色が付く既存の演出が、間の画面で途切れていた。
- **要約**: ホームを壁に掛けた額、額の中をそのゲームの台紙、1問を1ピースとし、選ぶ・解く・結果の行き来を、奥行きへ寄って戻る一本の筋で繋ぎ、解いたピースは1つの質感の定義から描く高級な実物にする。行き来ごとに別の比喩を当てる案、額や奥行きだけで通す案、行き来の間だけピースを出す案と、平らなピースや大きく強い光の立体と比べた。額の中へ入ったと見え、ピースが唐突に現れて消えず、静かな画面に馴染みながら際立つことを重視した。

## 背景と問題

ホームは、上下の暗い帯に挟まれた明るい面に、選んでいるゲームのピクトグラムと題名を見せていた。ゲームのホームは、ゲームの地の上に図鑑の台紙を置き、1問を1ピースのマスとして並べる。台紙のマスから始めると、そのピースが台紙から抜けてプレイへ入る。図鑑のマスには、解くと結果画面と同じ評価の色が付き、その変化は図鑑を開いたときにまとめて見せる（ADR-0004、GAME-009）。

一方で、ホームからゲームのホーム、プレイから結果、結果から次の行き先への行き来は、どれも一瞬の切り替えだった。抜いたピースは、プレイへ入ったあと結果でも見えず、図鑑へ戻ったときに、行き来とは無関係に色が付く。ピースは、台紙でも結果でも、評価の色の平らな塗りで描いていた。

## 判断基準

- 選ぶ・解く・結果を通して、意図が一本に読めること。
- 既にある見た目と演出（台紙、ピース、評価の色、図鑑の変化の演出）を、作り直さずに繋げられること。
- ホームからゲームのホームへ入ったとき、額の中へ入ったと見えること。
- 行き来の動きが、遷移先で始まる演出と重ならないこと。
- 選ぶ場面と解く場面の静けさ（`DESIGN.md` の「表現の強さ」）を崩さないこと。結果では、プレイの評価を主役にすること。
- 解いたピースが、静かな画面の中で異質なくらい高級な質感を持ちながら、周りの画面に馴染むこと。

## 検討した選択肢

行き来の筋は、次の4つを比べた。

1. **行き来ごとに別の比喩を当てる**: 額に入る、額に収まる、額が開く、を行き来ごとに当てる。
2. **額や奥行きだけで全部の行き来を通す**: 進むときは奥へ、戻るときは手前へ、を全部の行き来に当てる。
3. **画面は変えず、行き来の間だけピースを出す**: 解き終えた盤面の上にピースを現して色を付け、結果へ溶かす。
4. **壁・額・台紙・ピースを画面に置き、寄って戻る一本の筋で繋ぐ**: ホームの額の中にそのゲームの台紙を置き、結果に解いた問題のピースを置いて、行き来は奥へ寄るか、ピースを台紙へ運んで戻る。

解いたピースの質感は、次の3つを比べた。

- **平らな絵で評価に添える**: 評価の色の平らな塗りのピースを、結果の評価に添える。
- **大きく強い光の立体で見せる**: 結果のピースを、大きく、強い光を当てた立体で回す。
- **小さく控えめな光の立体を、1つの質感の定義から描く**: 結果のピースを「問題選択」の上で、「問題選択」と釣り合う小ささの立体で回し、光は控えめにし、台紙と運ぶピースも同じ質感の定義から描く。

## 採用した選択肢と理由

採用: **壁・額・台紙・ピースを画面に置き、寄って戻る一本の筋で繋ぐ**。理由: アプリ全体が、額の中のジグソーを1問1ピースずつ揃えていく体験になり、既にある台紙・ピース・評価の色が一本に繋がる。ホームの額の中とゲームのホームの台紙が同じものなので、額へ寄るだけで額の中へ入ったと見える。結果にピースの実体があるので、行き来の動きはそのピースを運ぶだけで済み、ピースが唐突に現れて消えない。

ピースの質感は、**小さく控えめな光の立体を、1つの質感の定義から描く** を採った。理由: アプリ全体を額の中を行き来する静かな美術館としたので、ピースはその中で異質なくらい高級な質感を持って浮いているくらいがよく、アプリの中でリッチすぎて浮くのは、それぞれのパズルとジグソーくらいにする。そのうえで周りの画面に馴染ませ、ほかの画面にも同じ質感を合わせやすくする。

画面は次のとおり。

- ホーム: ブランドのシルバーの壁に、濃い細い縁と白いマットの額を掛け、額の中に選んでいるゲームの台紙を見せる。台紙は、ゲームのホームを開いたときに開くレベルのものと同じ並びと形で、解いたピースには評価の色が付く。ピクトグラムは台紙に刷った絵として見せ、ピースの間の溝をその上にも通す。題名は額の下の壁に置く。
- ゲームのホーム: 背景はホームと同じ壁にし、台紙をホームと同じ額で囲む。ゲームの地は、プレイ画面とチュートリアルにだけ敷く。
- 結果: 解いた問題のピースを、今回の評価の色で塗り、「問題選択」の上に、「問題選択」と釣り合う小ささで、ゆっくり回りながら浮き沈みさせる。上下のブランドの帯は残す。

ピースの質感は次のとおり。

- 解いたピースは共通UIと分けて扱い、質感の豊かな実物として見せる。アプリの中で質感の豊かさが際立つのは、それぞれのゲーム固有表現と解いたピースだけにする。
- 際立たせるのは素材の質で、光と陰の強さでは目立たせず、周りの画面に馴染ませる。
- 結果のピース、ゲームのホームの台紙の解いたピース、行き来で運ぶピースは、立体でも平面でも、1つの質感の定義から描き、面は評価段階の色で塗る。ホームの額の台紙は除く。
- 結果のピースは立体で回し、立体を描けないとき・描けるまで・動きを減らす設定では、同じ質感の平面で見せる。

行き来の筋は次のとおり。

- ホームからゲームのホームへ: 額に寄る。額は消えずに大きくなってゲームのホームの台紙を囲む額になり、額の中の台紙は、ゲームのホームの台紙のピースとぴったり重なってから替わる。台紙に刷ったピクトグラムと、額の下の題名が、見出しへ移る。戻るときは、出てきたゲームを選んだホームを開き（SPEC-006）、額が小さくなってそのゲームの額に収まる。
- ゲームのホームからプレイへ: 選んだピースへ画面ごと寄っていき、ピースが画面を覆った所でプレイになる。額へ寄って台紙に入るのと同じ向きに、もう一段ピースの中へ入る。ゲームが選んだ問題（ランダムに遊ぶ）では、台紙を送ってそのピースを見える所へ運び、線で囲んで台紙のどれかを見せてから寄る。
- プレイから結果へ: 解き終えた画面がピースの形になって縮み、結果に添えたピースの所へ収まる。
- 結果からゲームのホームへ: 結果のピースが台紙の元の場所へ飛んではまり、図鑑の変化の演出がそのピースを押して色を入れる。
- 結果から次の問題へ: 結果のピースが結果の「問題選択」へ収まってから、次のプレイへ進む。ゲームのホームは経ない。結果から同じ問題をもう一度遊ぶときも同じにする。
- 結果からホームへ: 結果のゲームを選んだホームを開き、結果のピースが、ホームの額の台紙の元の場所へ飛んではまる。はまるのは、額の台紙が同じ難易度で、その場所が額の中に見えているときだけで、はまったその1問は額で変化を見せ終えたものとして扱う。はまらないときは、ピースはその場で消え、結果を先に引いてから、壁と額が少し大きい姿から退いて収まる。
- プレイからホームへ: 壁と額が少し大きい姿から退いて収まる。

ピースを運ぶ動きも含め、行き来の動きの間に画面を押すかキーを押すと、最後の姿まで飛ばす。

### 帰結

- Good: 台紙のピースが、解く・結果・台紙へ戻るまで途切れない。図鑑で色が付く演出が、結果から運んだピースの続きとして読める。
- Good: ホームの額の中で、解いてきたピースの色が見え、ゲームのホームの台紙へそのまま寄っていける。
- Good: 行き来の動きの種類を、行き来する画面の組から一か所で決めるので、行き来を起こす各所に動きを書かずに済む。
- Good: ピースの質感を1つの定義から描くので、結果・ゲームのホームの台紙・運ぶ間でピースが同じものに見え、ほかの画面でも同じ質感に合わせやすい。
- Bad: ホームで台紙を描くために、ゲームごとに問題集の全問を並べる。重いので、選んでいるゲームの分のほかは空いている時間に求める。
- Bad: ホームの額の台紙で前回からの変化をそのまま見せると、ゲームのホームで見せる変化が無くなる。額の台紙では変化する前の状態で見せ、結果から運んだピースが額の台紙にはまったときだけ、はまったその1問を見せ終えたものとして扱う。同じ台紙のほかの変化は、ゲームのホームで見せるよう残す。
- Bad: 結果からホームへ戻るとき、ピースの場所が額の中に見えていない（別の難易度の台紙を見せている、見えている行の外にある）と、ピースははまらずにその場で消える。
- Bad: 解き終えてから結果が開くまでと、ホームからゲームのホームへ入るまでが、一瞬の切り替えより長くなる。動きの途中の操作で最後の姿まで飛ばせるようにして受け入れる。
- Bad: 結果から次の問題・もう一度へ進むと、ピースが台紙にはまるところは見えず、その変化は次にゲームのホームを開いたときに見る。
- Bad: 台紙から抜かずに始めた問題（URL を直接開いたプレイなど）では、結果に添えるピースの形が台紙のマスの形と一致しない。台紙へ戻すときに、マスの形へ替える。
- Bad: 行き来の動きは View Transitions API に依る。使えないブラウザでは、動かさずに切り替わる。
- Bad: ブラウザの戻る・進むでは、ブラウザ自身の動き（Safari のスワイプで戻る動きなど）と重ねないよう、動かさない。行き来の筋は、アプリの中の操作で行き来したときにだけ見える。
- Bad: 結果のピースの色は今回の評価で、台紙のマスの色は問題ごとの最高評価（ADR-0004）なので、最高評価を上げなかったときは、戻ったピースとマスの色が一致しない。このときは、はめたピースをすぐマスへ替える。
- Bad: 結果のピースを立体で描くために、結果画面で three.js を遅延読み込みする。
- Bad: ホームの額の中の台紙は、実装の都合で質感を付けず平らな塗りで描くので、ゲームのホームの台紙のピースと質感が揃わない。
- Bad: 解いたピースは、影やグラデーション、平常での動きについての共通UIの決まり（`DESIGN.md`）の外に置く。
- Bad: 額を掛ける壁を `brand` で塗るので、pa-zzle の識別を担うときだけというブランド色の用途に、例外が一つ増える。

## 各選択肢の良し悪し

### 行き来ごとに別の比喩を当てる

- Good: 行き来ごとに作れるので、既存の画面に手を入れない。
- Bad: 台紙から抜いたピースの筋と額の筋が2本になり、意図に一貫性が無くなる。試作で、プレイと結果のまわりにも額の動きをかぶせたところ、そうなった。

### 額や奥行きだけで全部の行き来を通す

- Good: 仕組みが1つで済む。
- Bad: 1問が1ピースであることを語れず、どのアプリにもある動きになる。

### 画面は変えず、行き来の間だけピースを出す

- Good: 結果画面を変えない。
- Bad: 試作で、ピースが盤面の上に唐突に現れ、結果へ溶けて消えた。行き来だけで語ろうとする無理が出る。

### 壁・額・台紙・ピースを画面に置き、寄って戻る一本の筋で繋ぐ

- Good: 額・台紙・ピースに実体があり、行き来は寄るか、ピースを運ぶだけになる。
- Bad: ホームと結果に、台紙とピースという要素が増える。

### 平らな絵で評価に添える

- Good: それまでの描き方のままで済む。
- Bad: ジグソーパズルの質感にこだわりたいという望みに届かず、静かな画面の中で際立たない。

### 大きく強い光の立体で見せる

- Good: 高級な質感がはっきり伝わる。
- Bad: 結果はプレイの評価が主役で、ピースはおまけなので、大きく見せない。試作で、方向性はよいが周りに馴染まなかった。「問題選択」とのサイズ感が合わずピースが大きすぎ、ライティングが過剰だった。

### 小さく控えめな光の立体を、1つの質感の定義から描く

- Good: 際立ちながら周りの画面に馴染み、ほかの画面にも同じ質感を合わせやすい。
- Bad: 結果画面で three.js を読み込み、立体を描けないときのために、同じ質感の平面も持つ。

## 補足

採用した選択肢の中で、途中で採らずに変えた見せ方と、その理由は次のとおり。書いた理由は、プロダクトオーナーが示したものである。

- ホームを上下の暗い帯で挟み、その間の明るい面を額の中として見せる案: 背景は暗すぎない方がよく、アプリ全体をライト寄りにするため、シルバーの壁に額を掛ける形にした。額は、モチーフであることが伝わる強さに留め、悪目立ちさせない。
- ホームの額の中にはピクトグラムと題名だけを置き、ジグソーのピースの線や成績を持ち込まない案: 額の中に、解いたピースに色の付いた台紙を見せる形にした。題名は、額の中のものではなく額に添える題名として、額の外に置く。
- ホームからゲームのホームへ、額の暗い帯が開いて額が消える案: ズームインで額が消えるなら、ズームアウトで額が現れるべきで、ゲームのホームで額を無くすと額の中に入ったように見えない。額を残してゲームのホームの台紙を囲む額にした。
- ゲームのホームに、プレイと同じゲームの地を敷く案: 問題選択の背景はパズル選択に合わせるので、ゲームのホームの背景はホームと同じ壁にし、ゲームの地はプレイ画面とチュートリアルだけにした。
- ピクトグラムを見出しへ運ばず、額の中で迫って通り抜けさせ、見出しのピクトグラムは見出しのほかの表示と一緒に現す案: ピクトグラムを台紙に刷った絵としたので、押した瞬間の姿のまま見出しへ運び、着いた先で続きから動かす形にした。
- ゲームのホームからプレイへ、台紙からピースを抜いて、その中へ入る案: 選んだピースへ画面ごと寄っていく形にし、額から台紙へ入るのと同じ向きに揃えた。
- 結果から次の問題へ、ピースを動かさず、結果がこちらへ迫って通り抜ける短い動きで次の盤面へ進む案: 結果でピースを見せたなら、そのピースが問題選択に収まるところも要るので、結果の「問題選択」へしまってから進む形にした。
- 結果から次の問題へ、ゲームのホームを経て、結果のピースを台紙へはめ、前回からの変化を見せ終えてから次のピースへ入る案: プレイが主役でピースはおまけで、解いたピースを主役にするのは違い、次の問題へ進む流れの邪魔になる。ゲームのホームを経ず、「問題選択」へしまう形に戻した。台紙からプレイ、プレイから結果へ出てくるピースに一貫した流れがあることは、結果のピースを台紙のピースと同じ形にし、「問題選択」へ収めることで保つ。
- ゲームのホームからホームへ戻るとき、ホームで選ばれているゲーム（最後にクリアまたは離脱したゲーム）の額へ収まり、出てきたゲームと違えばピクトグラムと題名をその場で入れ替える案: 出てきたゲームの額へ戻る形に直した。
- 額を、縁に `shadow-raised` とは別の影を重ねて壁から浮かせる案: `DESIGN.md` の「一つの面に枠と影を重ねない」に額だけの例外をわざわざ付けなくてよいので、額は縁とマットだけで示す形にした。

関連する ADR と、今の決まりの置き場所は次のとおり。

- ADR-0004 は、図鑑に1マス増えた・色が上がった瞬間を、結果ではなく図鑑を開いたときに見せ、解くたびには出さないと決めた。結果に添えるのは今回の評価を受け取ったピースで、図鑑に加わったことは結果では見せない。この ADR は ADR-0004 を置き換えず、変化を見せ終えたものとする場面に、結果から運んだピースがホームの額の台紙にはまったその1問を足す。
- ADR-0016 は、ホームで選んでいるゲームのピクトグラムをゲーム固有色と動きで見せ、色をそのゲームを解く場面の色にして、選んだあとのプレイと見た目をつなげるとした。この ADR は、その姿を額の中の台紙に刷った絵として見せ、ゲームのホームへ入るときに、押した瞬間の姿のまま見出しへ運ぶ。
- ADR-0019 は、プレイURLを問題IDで識別し、画面の行き来とプレイの終了を分けた。この ADR がホームへ戻るときに選んでおく出てきたゲームは、URL に載せず、ホームへ来る前にいた画面から決めるので、ホームの URL は変えない。
- 今の決まりは、`APP.md`、`DESIGN.md` の「原則」と「色」と「奥行き」と「動き」、SPEC-006、GAME-009、`docs/プロダクト/画面/` の SCR-001・SCR-002・SCR-004、`.claude/rules/motion.md`・`game-structure.md`・`source-ownership.md` を正とする。
