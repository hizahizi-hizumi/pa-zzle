# 選ぶ・解く・結果の行き来を、額の中のジグソーを1ピースずつ揃える体験として繋ぐ

## 要約

- **決定**: ホームを額、額の中の面を図鑑の台紙（白紙のジグソー）、1問を台紙の1ピースとして、選ぶ・解く・結果の行き来を一本の筋で繋ぐ。結果には、解いた問題のピースを評価の色で添える。
- **主な選択肢**: 行き来ごとに別の比喩を当てる / 額だけ・奥行きだけで全部の行き来を通す / 画面は変えず、行き来の間だけピースを出す / 画面にピースを置いて一本の筋で繋ぐ。
- **背景**: ホーム・ゲームのホーム・プレイ・結果の間の行き来は、ゲームのホームからプレイへを除いてどれも一瞬の切り替えで、台紙からピースを抜いて入る既存の演出と、図鑑でピースに色が付く既存の演出が、間の画面で途切れていた。
- **要約**: ホームを額、その中の面をゲームのホームの台紙（白紙のジグソー）、1問を1ピースとして、選ぶ・解く・結果の画面の行き来を一本の筋で繋ぎ、結果には解いた問題のピースを評価の色で添える。行き来ごとに別の比喩を当てる案、額や奥行きだけで通す案、行き来の間だけピースを出す案と比べた。既にある額・台紙・ピース・評価の色を一本に繋げられ、ピースが唐突に現れて消えないことを重視した。

## 背景と問題

ホームは、上下の暗い帯に挟まれた明るい面に、選んでいるゲームのピクトグラムを見せる。ゲームのホームは、ゲームの地の上に図鑑の台紙を置き、1問を1ピースのマスとして並べる。台紙のマスから始めると、そのピースが台紙から抜けてプレイへ入る（`docs/プロダクト/画面/SCR-002.md`）。図鑑のマスには、解くと結果画面と同じ評価の色が付き、その変化は図鑑を開いたときにまとめて見せる（ADR-0004、SPEC-026）。

一方で、ホームからゲームのホーム、プレイから結果、結果から次の行き先への行き来は、どれも一瞬の切り替えだった。抜いたピースは、プレイへ入ったあと結果でも見えず、図鑑へ戻ったときに、行き来とは無関係に色が付く。

行き来に演出を足す検討では、まず額（暗い帯）の開け閉めを全部の行き来に当てた。プレイと結果のまわりにも額の動きをかぶせた結果、台紙から抜いたピースの筋と額の筋が2本になり、意図に一貫性が無くなった。次に、画面は変えずに行き来の間だけピースを出し入れしたが、ピースが唐突に現れて消え、行き来だけで語ろうとする無理が出た。

## 判断基準

- 選ぶ・解く・結果を通して、意図が一本に読めること。
- 既にある見た目と演出（額、台紙、ピースが抜けて入る動き、評価の色、図鑑の変化の演出）を、作り直さずに繋げられること。
- 行き来の動きが、遷移先で始まる演出と重ならないこと。
- 選ぶ場面と解く場面の静けさ（`DESIGN.md` の「表現の強さ」）を崩さないこと。

## 検討した選択肢

1. **行き来ごとに別の比喩を当てる**: 額に入る、額に収まる、額が開く、を行き来ごとに当てる。
2. **額や奥行きだけで全部の行き来を通す**: 進むときは奥へ、戻るときは手前へ、を全部の行き来に当てる。
3. **画面は変えず、行き来の間だけピースを出す**: 解き終えた盤面の上にピースを現して色を付け、結果へ溶かす。
4. **画面にピースを置いて一本の筋で繋ぐ**: 額の中の面を台紙として運び、結果に解いた問題のピースを置いて、行き来はそのピースを繋ぐ。

## 採用した選択肢と理由

採用: **画面にピースを置いて一本の筋で繋ぐ**。理由: アプリ全体が、額の中の白紙のジグソーを1問1ピースずつ揃えていく体験になり、既にある額・台紙・ピース・評価の色が一本に繋がる。結果にピースの実体があるので、行き来の動きはそのピースを運ぶだけで済み、ピースが唐突に現れて消えない。

筋は次のとおり。

- ホームからゲームのホームへ: 額の暗い帯が開き、額の中の面がそのまま台紙になる。額の中の絵（選んでいるゲームのピクトグラム）はその場でこちらへ迫って通り抜け、その奥から台紙のピースの並びが現れる。ゲーム名は見出しへ移る。戻るときはその逆。
- 台紙からプレイへ: ピースを抜いて、その中へ入る（変えない）。
- プレイから結果へ: 解き終えた画面が、結果に添えたピースの形と位置へ絞られる。ピースの中へ入った動きの逆。
- 結果: 解いた問題のピースを、今回の評価の色で添える。
- 結果からゲームのホームへ: 結果のピースが台紙の元の場所へはまる。初めて解いたときと最高評価を上げたときは、続けて図鑑の変化の演出がそのマスへ色を入れる。
- 結果から次のプレイへ: 流れを切らないよう、ピースを動かさず、結果がこちらへ迫って通り抜ける短い動きで次の盤面へ進む。
- 結果・プレイからホームへ: ホームが額に収まる。

額は、ゲームを選んで入る・出るときにだけ使う。ホームの額の中の面には、ジグソーのピースの線を敷かない。敷く案を試したが、やりすぎで下品になった。

### 帰結

- Good: 台紙から抜いたピースが、解く・結果・図鑑へ戻るまで途切れない。図鑑で色が付く演出が、結果から運んだピースの続きとして読める。
- Good: 行き来の動きの種類を、行き来する画面の組から一か所で決めるので、行き来を起こす各所に動きを書かずに済む。
- Bad: 解き終えてから結果が開くまでと、ホームからゲームのホームへ入るまでが、一瞬の切り替えより長くなる。動きの途中の操作で最後の姿まで飛ばせるようにして受け入れる。
- Bad: 台紙から抜かずに始めた問題（結果からの次の問題、URL を直接開いたプレイ）では、結果に添えるピースの形が台紙のマスの形と一致しない。台紙へ戻すときに、マスの形へ替える。
- Bad: 行き来の動きは View Transitions API に依る。使えないブラウザでは、動かさずに切り替わる。
- Bad: ブラウザの戻る・進むでは、ブラウザ自身の動き（Safari のスワイプで戻る動きなど）と重ねないよう、動かさない。行き来の筋は、アプリの中の操作で行き来したときにだけ見える。
- Bad: 結果のピースの色は今回の評価で、台紙のマスの色は問題ごとの最高評価（ADR-0004）なので、最高評価を上げなかったときは、戻ったピースとマスの色が一致しない。このときは、はめたピースをすぐマスへ替える。

## 各選択肢の良し悪し

### 行き来ごとに別の比喩を当てる

- Good: 行き来ごとに作れるので、既存の画面に手を入れない。
- Bad: 台紙から抜いたピースの筋と額の筋が2本になり、意図に一貫性が無くなる。

### 額や奥行きだけで全部の行き来を通す

- Good: 仕組みが1つで済む。
- Bad: 1問が1ピースであることを語れず、どのアプリにもある動きになる。

### 画面は変えず、行き来の間だけピースを出す

- Good: 結果画面を変えない。
- Bad: ピースが盤面の上に唐突に現れ、結果へ溶けて消える。行き来だけで語ろうとする無理が出る。

### 画面にピースを置いて一本の筋で繋ぐ

- Good: ピースに実体があり、行き来はそれを運ぶだけになる。
- Bad: 結果画面に要素が1つ増える。

## 補足

- ADR-0004 は、図鑑に1マス増えた・色が上がった瞬間を、結果ではなく図鑑を開いたときに見せると決めた。この ADR はそれを置き換えない。結果に添えるのは今回の評価を受け取ったピースで、図鑑に加わったことと前回からの変化は、今までどおり図鑑を開いたときに見せる。
- ADR-0016 は、選んでいるゲームのピクトグラムをゲーム固有色で見せ、選んだあとのプレイと見た目をつなげるとした。ピクトグラムを小さくしながら見出しへ運ぶ案は、額の中へ入っていく向きと逆に見えたので採らず、見出しのピクトグラムは見出しのほかの表示と一緒に現す。
- 今の決まりは、`APP.md`、`DESIGN.md` の「動き」、`docs/プロダクト/画面/` の SCR-001・SCR-002・SCR-004、`.claude/rules/motion.md` を正とする。
