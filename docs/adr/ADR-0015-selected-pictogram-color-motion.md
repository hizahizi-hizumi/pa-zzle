# 選択中のピクトグラムをプレイ画面の色と動きで見せる

## 要約

- **決定**: パズル選択で選んでいるゲームのピクトグラムを、白黒2色に限らずプレイ画面の色で見せ、選んだゲームを大きく見せるヒーローでは動きも付ける。選んでいない一覧と結果画面は白黒2色を保つ。
- **主な選択肢**: 白黒の静止画のままヒーローの構図で補う / すべてのピクトグラムを色付きにする / 選択中だけアプリ共通の色で強調する / 選択中だけプレイ画面の色と動きで見せる。
- **背景**: パズル選択のヒーローが白黒の静止画だけで寂しく、何をする遊びかも遊びたくなる期待も伝えにくかった。
- **要約**: パズル選択で選んでいるゲームのピクトグラムを、一覧の選択中ではプレイ画面の色で、ヒーローではその色と動きで見せ、選んでいない一覧と結果画面は白黒2色を保つ。白黒静止画のままヒーローの構図で補う案、すべてを色付きにする案、選択中だけアプリ共通色で強調する案と比べた。何をする遊びかの区別（FR-001）と遊びたくなる期待（RQ-002）を見せつつ、一覧の統一感と落ち着きを保てることを重視した。

## 背景と問題

パズル選択画面は、上部のヒーローに選んでいるゲームのピクトグラムを大きく出し、下部に候補の一覧を並べる。ピクトグラムは一覧として共通の描画言語を持つよう、濃淡2色の静止画で描いていた。

ヒーローは画面の大きな面積を占めるのに、白黒の静止画1つだけで寂しかった。FR-001 は、利用者がそれぞれのパズルで何を考え何をする遊びかを区別して認識し、楽しく選べることを求め、RQ-002 はこれからのプレイへの期待を高めたいとする。白黒の静止画では、盤面の形は分かっても、そのパズルで何をするのか、解けた・揃った瞬間がどう気持ちよいのかまでは見せにくい。

## 判断基準

- 選んだパズルで何を考え何をする遊びかが、動きで分かること（FR-001）。
- 解けた・揃った瞬間の気持ちよさが見え、遊びたくなること（RQ-001・RQ-002）。
- 選んだ手応えは、上の2つを満たせば生まれるものとし、それだけのための演出を足さないこと。
- 一覧の統一感と画面の落ち着きを不必要に損なわないこと。
- 動きを減らす設定でも、ゲームの姿を欠かさず見せられること。

## 検討した選択肢

1. **白黒の静止画のまま、ヒーローの構図や大きさで補う**
2. **すべてのピクトグラムを色付きにする**
3. **選択中だけアプリ共通の色（ブランド色やアクセント色）で強調する**
4. **選択中だけプレイ画面の色で見せ、ヒーローでは動きも付ける**

## 採用した選択肢と理由

採用: **選択中だけプレイ画面の色で見せ、ヒーローでは動きも付ける**。理由: 何をする遊びかと解けた瞬間の気持ちよさは、盤面の形だけでなく、色の分かれ方や揃い方、操作で何が動くかに表れる。選んでいるゲームに限れば、色と動きで見せても一覧全体の統一感は崩れない。

色はアプリ共通の色ではなく、そのゲームのプレイ画面の色にする。これから遊ぶものの本当の姿を見せ、選んだあとのプレイ画面と見た目をつなげるためである。

選んでいない一覧と結果画面は、一覧の統一感と落ち着きのため白黒2色を保つ。結果画面は利用側から意味のある色を与える場所であり、ゲームの色を持ち込まない。

一覧の選択中の色付きの静止した姿と、ヒーローの動く姿は、ゲームごとに1つの SVG で兼ねる。静止した姿は動きを付けない状態そのものとし、両者の見た目がずれないようにする。動きを減らす設定では、ヒーローもこの静止した姿を見せる。

### 帰結

- Good: ヒーローで、選んだパズルの遊び方と解けた瞬間を、文章に頼らず見せられる。
- Good: 選んだ候補と、これから遊ぶプレイ画面の見た目がつながる。
- Good: 色と動きを持つのが選んでいる1つだけなので、一覧の統一感と画面の落ち着きを保てる。
- Bad: ゲームごとに、白黒のピクトグラムに加えて色と動きを持つ SVG を作り、保つ手間が増える。
- Bad: 色付きの SVG を持たないゲームは従来の白黒で出るため、ゲームによって選んだときの見え方に差が出る。

## 各選択肢の良し悪し

### 白黒の静止画のまま、ヒーローの構図や大きさで補う

- Good: ピクトグラムを作り足さずに済み、一覧の描画言語を一つに保てる。
- Bad: 何をする遊びかと解けた瞬間の気持ちよさは、構図や大きさでは見せられない。

### すべてのピクトグラムを色付きにする

- Good: 選択中と未選択で絵を切り替えずに済む。
- Bad: 一覧がゲームごとの色で騒がしくなり、統一感と落ち着きを損なう。結果画面で利用側から与える色ともぶつかる。

### 選択中だけアプリ共通の色で強調する

- Good: どのゲームでも同じ作り方で済み、選んだことははっきりする。
- Bad: 選んだことを示すだけで、何をする遊びかも期待も増えない。プレイ画面と違う色になり、これから遊ぶものの姿を見せられない。

### 選択中だけプレイ画面の色で見せ、ヒーローでは動きも付ける

- Good: 判断基準をすべて満たせる。
- Bad: ゲームごとの SVG 制作と、動きの強さが落ち着きを損なわないかの確認が要る。

## 補足

- 関連: FR-001（遊ぶパズルを見分けて選べる）、RQ-001、RQ-002。
- 見せ方の決まりは `DESIGN.md` の「ゲームピクトグラム」を正とする。SVG の置き場所・色の渡し方・動きの再生の受け口は、コードと SVG を作るスキルを正とする。
- 受け口は、ウォーターソートで色付きの SVG を試作した知見を反映済みで、最初のゲームで採用した後に確定する。確定までの見直しで決定そのものが変わる場合は、この ADR を置き換える。
