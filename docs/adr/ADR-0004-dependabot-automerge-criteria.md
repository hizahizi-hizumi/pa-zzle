# Dependabot の更新を基準で自動マージする

## 要約

- **決定**: GitHub Actions の Dependabot 更新のうち、GitHub 公式が公開し除外リストにないアクションの minor・patch 更新だけを、必須チェックが通ったら自動マージする
- **主な選択肢**: すべて手動でマージする / アクション名を列挙したホワイトリスト / 発行元と更新の種類による基準 / major を含めてすべて自動マージする
- **背景**: アクションをロックファイルで固定し、更新を Dependabot の PR で受け取るようにしたため、毎週の PR を人が確認してマージする手間が生じた
- **要約**: GitHub Actions の Dependabot 更新のうち、GitHub 公式が公開し除外リストにないアクションの minor・patch だけを、dependabot/fetch-metadata で判定し必須チェック通過後に auto-merge する。全手動、アクション名のホワイトリスト、major を含む全自動と比べた。基準で判定すれば増えても迷わず、major と公式以外を人が確かめてサプライチェーンの危険を抑えられることを重視した。

## 背景と問題

外部アクションはワークフロー依存ロックファイル（`actions.lock`）でコミットに固定し、更新は Dependabot のバージョン更新 PR で受け取る。公開直後に侵害されたリリースを取り込まないよう、バージョン更新には公開から7日の cooldown をかけている。

固定したことで、タグ指定のときは自動で入っていた更新が、PR をマージしない限り入らなくなった。PR を毎回人が確認してマージするのは手間で、放置すると更新が止まる。一方で、どの更新も無条件にマージすると、固定した意味が薄れる。

## 判断基準

- サプライチェーン攻撃の危険を、固定する前より大きくしない
- 人の確認は、危険が大きい更新に絞る
- 対象かどうかを機械的に判定でき、アクションが増えても判断に迷わない
- 問題が起きたときに、そのアクションだけを自動マージから外せる

## 検討した選択肢

1. **すべて手動でマージする**
2. **アクション名を列挙したホワイトリスト**
3. **発行元と更新の種類による基準**
4. **major を含めてすべて自動マージする**

## 採用した選択肢と理由

採用: **発行元と更新の種類による基準**。理由: 名前を列挙するより、基準で判定する方がアクションが増えても判断がぶれず、危険が大きい major と公式以外の更新を人の確認に残せるため。

自動マージするのは、次をすべて満たす更新に限る。

- 更新の種類が minor か patch である。major はすべて手動でマージする。
- 発行元が GitHub 公式（`actions`・`github`・`dependabot` の各オーナー）である。
- 除外リストに入っていない。自動マージした更新が CI・成果物・セキュリティのいずれかで問題を起こしたアクションは、除外リストに入れる。

セキュリティ更新にも同じ基準を使う。セキュリティ更新には cooldown がかからないが、既に公表された脆弱性の修正を早く入れる利点を優先する。

判定は `dependabot/fetch-metadata` の出力で行い、自動マージを予約するだけにとどめる。実際のマージは、`main` の必須チェックが通ってから GitHub が行う。

### 帰結

- Good: 公式アクションの minor・patch 更新は、CI が通れば人手を介さずに入る。
- Good: major と公式以外の更新は、引き続き人が中身を確かめてからマージする。
- Good: 問題を起こしたアクションは、除外リストに1行足せば自動マージから外せる。
- Bad: 公式アクションの minor・patch に侵害されたリリースが紛れた場合、cooldown の7日を過ぎて CI が通れば、人が見ないまま入る。
- Bad: 自動マージには、リポジトリ設定で auto-merge を許可し、`main` に必須チェックを設定する必要がある。必須チェックは人が作る PR にもかかる。

## 各選択肢の良し悪し

### すべて手動でマージする

- Good: すべての更新を人が確かめる。
- Bad: 毎週の確認とマージが手間で、放置すると更新が止まる。

### アクション名を列挙したホワイトリスト

- Good: 対象が明示され、読めばすぐ分かる。
- Bad: アクションを足すたびに入れるかどうかの判断が要り、判断の根拠が残らない。

### major を含めてすべて自動マージする

- Good: 人手がまったく要らない。
- Bad: 互換性を壊す変更や、公式以外の侵害されたリリースも、CI が通れば入る。

## 補足

- 判定の実装: `.github/workflows/dependabot-automerge.yml`
- Dependabot の設定: `.github/dependabot.yml`（minor・patch を1つの PR にまとめ、major は個別の PR にする）
