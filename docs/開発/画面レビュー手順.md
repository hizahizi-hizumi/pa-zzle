# 画面レビュー手順

## 目的

pa-zzle の画面変更を、静止した完成画面だけでなく、実際の操作・途中状態・画面遷移まで含むゲーム体験として確認するためのレビュー手順。

画面の目的・情報構造・見た目の正解をこの文書で定義しない。判断基準は `APP.md`、`GAME.md`、`DESIGN.md`、対象の `docs/画面/` を正とし、この文書はそれらを実画面でどう確認するかを扱う。

## 1. レビュー対象を決める

変更箇所について、少なくとも次を確認する。

- 対象画面と主要な変更箇所
- 変更によって影響する前後の導線
- ゲーム固有UIかアプリ共通UIか
- スマートフォン、PC、または両方で確認すべき変更か
- アニメーションや非同期な表示進行を含むか

対象画面の正本を先に読み、実装だけから意図を推測してレビューしない。

## 2. 実ブラウザで描画する

- 対象画面を実際のブラウザで開く。
- 変更箇所が初期表示だけで確認できない場合は、必要な状態まで実際に操作する。
- レスポンシブ対応またはゲームプレイに関係する変更では、スマートフォン相当の画面幅を必ず確認する。
- PCでの配置・密度に影響する変更は、PC相当幅も確認する。

ChatGPT実行環境でのサーバー起動・Playwright接続方法は `../メモ/ChatGPT画面確認.md` を参照する。環境固有の接続方法を本手順へ複製しない。

## 3. 静止状態を確認する

対象画面の正本に照らして、少なくとも次を見る。

- 画面の主役が正しいか。
- 情報の優先順位が目的と一致しているか。
- 共通UIがゲーム固有表現より不必要に前へ出ていないか。
- 操作可能な範囲と非操作領域を識別できるか。
- 補助情報の有無で盤面や主要操作が不必要に移動しないか。
- スマートフォンでプレイ対象と主要操作を追えるか。
- PCで単に余白だけが増えていないか。

見た目が判断対象になる変更ではスクリーンショットを取得し、実際の描画結果を確認する。

## 4. 操作の連続性を確認する

単発のクリックだけで完了とせず、実際の利用順に操作する。

- 同じ種類の操作を連続して行う。
- 選択 → 実行 → 次の選択など、状態をまたぐ操作を行う。
- Undo、やり直し、再挑戦など、変更箇所と関係する補助操作も確認する。
- 高速に続けて操作できるゲームでは、演出完了を待たず次の入力を行うケースも確認する。

操作のたびに、何を操作したかと何が変化したかの因果を追えることを確認する。

## 5. 時間軸上の途中状態を確認する

アニメーションや表示進行を含む変更では、開始前と完了後だけでなく途中状態を確認する。

- 対象が二重に表示されない。
- 元の位置へ一瞬戻る、瞬間移動する等の巻き戻りがない。
- 複数演出が重なる場合も、それぞれの対象と状態を追える。
- 表示上の進行と論理状態の不一致によって、誤った対象を操作できるようになっていない。
- reduced motion や表示計測失敗等がゲーム進行停止の前提になっていない。

必要ならスクリーンショット、動画、Playwrightによる途中状態の観測を使う。特定の実装手段を必須にはしない。

## 6. 最後の操作から結果まで確認する

クリアを含む画面変更では、最後の操作だけを個別に確認せず、次を一続きで見る。

1. 最後の操作を行う。
2. その操作結果と完成状態を認識できる。
3. 必要な達成表現が成立する。
4. 結果画面または次の状態へ遷移する。

途中で完成状態が見えない、最後の操作が消える、結果画面が先に出る等、因果が飛ぶ遷移を残さない。

## 7. ブラウザエラーを確認する

レビュー操作の全体を通して、少なくとも次を確認する。

- `pageerror` がない。
- 意図しない `console.error` がない。
- 失敗したネットワーク要求がない。

エラーが変更と無関係と判断する場合も、無視せず理由を確認する。

## 8. レビュー結果を残す

レビュー結果には、必要に応じて次を残す。

- 確認した画面・ルート
- 確認した画面幅
- 実行した主要操作
- 途中状態・最終遷移を確認したか
- スクリーンショット等の確認結果
- ブラウザエラーの有無
- 未確認事項と理由

「表示できた」「テストが通った」だけを画面レビュー完了の根拠にしない。
