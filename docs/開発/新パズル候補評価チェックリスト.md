# 新パズル候補評価チェックリスト

## 目的

新しいパズル候補を pa-zzle へ導入できるか調査するときに、技術的に生成できることだけを根拠に採用判断へ進まないためのチェックリスト。

各観点を独立して確認し、前段の成立を後段の評価の代用にしない。たとえば「解がある」ことを「良問」「難易度を運用できる」「製品へ入れる価値がある」の根拠にはしない。

このチェックリストは採用候補の評価工程を揃えるためのものであり、個々のパズルの生成方式・難易度式・UIを共通化するものではない。

## 判定方法

各項目を次のいずれかで記録する。

- **成立**: 根拠を確認できた。
- **不成立**: 現在の方式では満たせないことを確認した。
- **要検証**: 仮説や一部の実測だけで、まだ結論を出せない。
- **対象外**: そのパズルでは意味を持たない。理由を残す。

`要検証` を `不成立` と同一視しない。各判定には、Issue、PR、実測、コード、再現可能な problem など確認可能な根拠を付ける。

## 1. 問題供給

- [ ] ルール上成立する problem を継続的に供給できる見込みがある。
- [ ] problem を後から同一内容へ再現できる。
- [ ] 可解性、一意性など、そのパズルで必要な成立条件を generator とは独立して検証できる。
- [ ] 生成失敗、探索上限、条件未達を「成立」と誤認せず区別できる。
- [ ] 製品で必要とする量・盤面規模について、供給成功率を実測している。

## 2. 配布品質

- [ ] ルール上正しい problem と、利用者へ配布したい problem を別に評価できる。
- [ ] 自明盤面、極端な偏り、重複など、そのパズルで配布したくない problem を説明できる。
- [ ] 配布しない problem の理由を、難易度や生成失敗と混同せず追跡できる。
- [ ] 複数の生成例を実際に確認し、生成器が特定の形だけへ偏っていないか確認している。

## 3. 難易度運用

詳細な難易度判定工程は、パズル横断の難易度検証で確定した正を参照する。このチェックリストでは、製品運用へ接続できる見込みだけを確認する。

- [ ] そのパズルで人間にとって何が難しいかを説明できる。
- [ ] 生成条件や機械探索量そのものを、人間向け難易度の代用にしていない。
- [ ] 複数段階の難易度へ problem の分布を動かせる見込みがある。
- [ ] 代表 problem と境界付近の problem を再現し、人間が比較確認できる。
- [ ] 現在の評価器で判断できない problem を、既存難易度へ無理に割り当てず扱える見込みがある。

## 4. プレイ成立性

- [ ] スマートフォン相当の実画面で、盤面・主要操作・必要情報を把握してプレイできる。
- [ ] 入力方式がタップ、ドラッグ、描線等の実操作として成立している。
- [ ] 代表的な盤面サイズを実際に操作し、必要なら初期提供サイズの上限を説明できる。
- [ ] UIがプレイヤー自身の判断を先回りして解答情報を漏らしていない。
- [ ] ゲーム固有の題材・手触りを、既存ゲームのUIへ無理に押し込まず表現できる。

画面の確認方法は `画面レビュー手順.md` に従う。

## 5. 性能・実行成立性

- [ ] 製品で対象とする盤面規模・端末・ブラウザで、生成時間・探索時間・成功率を実測している。
- [ ] 探索上限到達を「解なし」「評価済み」と同一視していない。
- [ ] リアルタイム実行がプレイ体験を阻害する場合、Worker、先読み、事前生成、キャッシュ、サーバー処理等の代替が成立するか確認している。
- [ ] PoC環境固有の単一計測値だけで、導入可否を判断していない。

## 6. 製品への導入判断

- [ ] 「技術的に実装できる」と「pa-zzle に導入する価値がある」を別の判断としている。
- [ ] そのパズルを遊ぶ体験が、既存ゲームと何が異なるか説明できる。
- [ ] 問題供給、配布品質、難易度運用、プレイ成立性、性能の未解決事項を列挙できる。
- [ ] 未解決事項を含めたうえで、採用候補に残す・追加検証する・見送る、の判断理由を説明できる。
- [ ] 採用可否と、MVP・直近開発での実装優先度を別に扱っている。

## 評価結果に残すもの

候補ごとに最低限、次を残す。

- 対象パズルと調査範囲
- 各チェック項目の判定と根拠
- 再現に使える代表 problem / seed / 条件
- 実測条件と主要な計測結果
- 要検証事項
- 採用候補 / 追加検証 / 見送りの結論と理由

個別調査の数値や実装詳細はこのチェックリストへ追記せず、対象の調査文書・コード・Issueを参照する。
