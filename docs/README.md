# 文書

pa-zzle の文書は、コードからは読めないものだけを置く。振る舞いの詳細はコードとテストを正とし、文書へ写さない（ADR-0003）。

## 正本

- [`プロダクト/`](プロダクト/): 意図と決まり。
  - `要求/`・`要件/`: 何を目指し、製品として何を保証するか。
  - `仕様/`: アプリ・ゲーム共通の取り決めと、パズルごとの定義。今の決定だけを書く。
- [`adr/`](adr/): 決定の理由。理由を失うと戻されたり蒸し返されたりする決定だけを書く。
- リポジトリ直下の `DESIGN.md`・`GAME.md`・`APP.md`: 設計原則。
- [`パズル/`](パズル/) の難易度文書（`難易度*.md`）: 難易度を作るときの手引き。
- `AGENTS.md`・`.claude/rules/`: エージェントが作業するたびに守る決まり。

## 資料（正本ではない）

- [`パズル/導入調査/`](パズル/導入調査/) とパズルごとの検討資料: パズル候補の調査・検証。
- [`棚上げ/`](棚上げ/): パズル候補の台帳。
- [`立ち上げ/`](立ち上げ/)・[`メモ/`](メモ/): 立ち上げ期の経緯と開発上の参考資料。

資料は必要なときに読むもので、正本として維持しない。資料と正本が食い違うときは正本を正とする。

## 決めたことの残し方

レビューや作業で決めたことは、同じ変更の中で次へ反映する。

- 振る舞い: コードとテスト。
- 後から守るべき決まり: 仕様・設計原則・エージェント向けルールのうち該当する文書。
- 理由が要るもの: ADR。
