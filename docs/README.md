# 文書

pa-zzle の文書は、コードからは読めないものだけを置く。振る舞いの詳細はコードとテストを正とし、文書へ写さない（ADR-0003）。この README が、どの文書に何を書き、どう保つかの正本である。いつ読むかは `AGENTS.md` を正とする。

## どの文書に何を書くか

| 文書 | 書くもの |
|---|---|
| `プロダクト/要求/` | 利用者が実現したい状態 |
| `プロダクト/要件/` | 製品として保証する能力・性質 |
| `プロダクト/仕様/` | 要件を満たすための今の決まり。アプリ・ゲーム共通の取り決めと、パズルごとのルール・評価・難易度の定義 |
| `APP.md` | アプリ全体の体験で大事にすること。アプリとゲームの分担 |
| `GAME.md` | 個々のゲームの体験で大事にすること |
| `DESIGN.md` | 見た目・情報の強弱・操作への反応・動きの決まり。値は `@theme` |
| `パズル/` の難易度文書 | 難易度の意味と、作るときの手引き |
| `adr/` | 理由を失うと戻されたり蒸し返されたりする決定の理由 |
| `AGENTS.md`・`.claude/rules/` | エージェントが作業するたびに守る決まり。置き分けは `.claude/rules/context-engineering.md` |

各ディレクトリの書き方は、それぞれの README を正とする。

## 書く基準

正本に書くのは、次の両方を満たすことだけ。

- 当たり前ではない判断であること。UI/UX の基本、一般的なエッジケースの扱い、どのゲームでも自然にそうなることは書かない。
- 知らずに変えると意図が壊れること。コードを読めば分かり、変わっても困らないことは書かない。

あわせて次を守る。

- 今の決定だけを言い切りで書く。理由・経緯・出典は書かない（理由が要るものは ADR）。
- 同じことを二つの文書に書かない。上位の文書で言えていることを言い直さない。
- 将来の予定や、まだ決めていないことは書かない。
- 今の実装に合わせるためだけに、要求・要件を書き換えない。

## 文書を変えるとき

レビューや作業で決めたことの反映先は `AGENTS.md` に従う。文書を変えたら、他の文書との重複や食い違いを作っていないか確かめる。

## 資料

正本ではない。必要なときに読み、正本と食い違うときは正本を正とする。

- `パズル/導入調査/`: まだ導入していないパズル候補の調査。
- `棚上げ/`: パズル候補の台帳。
- `メモ/`: 開発作業の手順など、正本に当たらない参考資料。

資料は役目を終えたら消す。パズルを導入したら、そのパズルの導入調査は消す（決まったことは仕様とコードへ移す）。消した資料は git の履歴から読める。
