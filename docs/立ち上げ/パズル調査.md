# シンプルパズルゲーム 自動生成可能性 一次調査

## 目的

ナンプレ、クロスワード、カラーウォーターソート、詰将棋などのシンプルなパズルゲームについて、
「計算的に問題を自動生成できるか」を一次調査として整理する。

ここでいう「自動生成可能」は、単にランダムな盤面を作れることではなく、以下を段階的に含む。

1. ルール上成立する問題を生成できる
2. 少なくとも1つ解が存在することを保証できる
3. 必要に応じて一意解を保証できる
4. 難易度をある程度制御できる
5. 人間にとっての「良問」を安定して供給できる

特に 4 と 5 は、単純な可解性とは別問題として扱う必要がある。

---

## 評価記号

| 記号 | 意味 |
|---|---|
| ◎ | 解ける良問を大量・安定生成しやすい。無限ステージ向き |
| ○ | 自動生成可能。ただし 解法探索器 / 一意解判定 / リジェクト生成が重要 |
| △ | 技術的には生成可能だが、人間にとっての良問判定が難しい |
| ▲ | 盤面生成より語彙・文章・画像など外部コンテンツ品質が支配的 |

---

## 自動生成方式の大分類

| 系統 | 代表例 | 自動生成適性 | 基本戦略 |
|---|---|---:|---|
| 完成形→ヒント削除 | ナンプレ、カックロ、ノノグラム | ◎〜○ | 完成解を作り、ヒントを削る |
| 完成形→逆操作 | 15パズル、倉庫番 | ◎〜○ | ゴールから逆方向へ構成する |
| ランダム生成→探索・棄却 | カラーウォーターソート | ○ | 標準形を生成し、探索器で可解性・最短手数を確認する |
| 制約を直接生成 | スリザーリンク、橋をかけろ、美術館 | ○ | CSP / SAT / 探索で条件を満たす盤面を作る |
| グラフ生成 | 迷路、ナンバーリンク、ワードラダー | ◎〜○ | 解答経路・グラフを先に構成する |
| ゲーム探索 | 詰将棋、N手詰め、詰碁 | ○〜△ | 逆算、AND/OR探索、評価関数を使う |
| 語彙ベース | クロスワード、アナグラム、ワードサーチ | ◎〜△ | 辞書＋制約充足 |
| 意味ベース | なぞなぞ、雑学クイズ | ▲ | 問題文そのものの生成・検証が必要 |
| 物理・空間系 | タングラム、ピン抜き | △ | シミュレーション＋探索 |

## ナンプレの典型パイプライン

```text
完成盤生成
  ↓
数字を削る
  ↓
解法探索器で一意解確認
  ↓
人間用解法探索器で使用テクニックを記録
  ↓
難易度付与
```

ヒント数だけでは難易度を正確に表せないため、
人間用解法探索器がどの推論手法を必要としたかを見る方が適切。

## カラーウォーターソートの詳細調査結果

Issue #27 の詳細調査では、pa-zzle での第一候補を次の方式とした。

```text
各色4単位を seed 付き乱数でシャッフル
  ↓
満杯ボトルへ分配 + 空ボトル2本
  ↓
自明盤面を棄却
  ↓
A* で可解性・最短手数を確認
  ↓
品質条件を満たす盤面だけ採用
```

Water Sort の注水は一般に不可逆なので、15パズルのように通常の合法手を単純に逆再生して混色盤面を作ることはできない。完成状態から生成する場合は「前向きの合法手で現在状態へ戻せる前状態」を構成する逆遷移専用処理が必要になる。

容量4・空ボトル2本のランダム盤面を使った試作 A* では、3〜8色は十分小さく、9〜10色は実装言語での再測定対象、11〜12色では秒単位の外れ値が出た。可解性・性能・難易度候補指標の詳細は [カラーウォーターソート成立性調査](カラーウォーターソート成立性調査.md) を参照する。

難易度評価候補:

- 最短解長
- 合法手の分岐数
- 強制手の割合
- 行き止まり数
- 最適経路から外れる合法手の数
- 空き容量の圧力
- 退避・崩しが必要な局面

探索器の展開状態数は実装依存なので、難易度の正本ではなく補助指標として扱う。

# 4. 倉庫番・ブロック移動系

| パズル | 自動生成 | 良問生成 | コメント |
|---|---:|---:|---|
| 倉庫番 | ○ | △〜○ | 可解盤面より良問生成が難しい |
| 箱押し | ○ | △〜○ | 倉庫番系 |
| ラッシュアワー | ○ | ○ | 状態探索しやすい |
| パーキングジャム | ○ | ○ | ゴール状態からの逆生成が可能 |
| ブロック脱出 | ○ | ○ | 解法探索器を併用 |
| ウッドブロック配置 | ○ | △ | 継続可能性の評価が必要 |
| タイル合わせ | ○ | △ | 配置品質が重要 |
| 麻雀ソリティア | ○ | ○ | 完成除去順を逆にたどれる |

## 倉庫番の特徴

完成状態から箱を「引く」逆操作で可解局面を作れる。

一方で良問には、

- 無駄な広い空間がない
- 強制手ばかりではない
- deadlockを見抜く必要がある
- 一時的な遠回りがある
- 箱の順序依存がある

などの品質指標が必要。

「可解性」と「面白さ」の乖離が大きい代表例。

# 6. 単語パズル

## クロスワード

```text
各単語スロット = 変数

交差位置の文字一致 = 制約
```

- クロスワードの盤面 → 計算問題

## 詰将棋の基本的な生成イメージ

```text
詰み局面
  ↑
1手戻す
  ↑
1手戻す
  ↑
候補局面
  ↓
攻方の全手を探索
  ↓
玉方の全応手を探索
  ↓
強制詰みか検証
```

逆算法やAND/OR探索が使える。

ただし詰将棋には単なる可解性以外に、

- 余詰がない
- 駒余り
- 無駄合
- 捨て駒
- 手順の意外性
- 駒配置の美しさ
- 収束の美しさ

など作品性がある。

したがって、

- 「詰む問題を作る」→ ○
- 「良い詰将棋作品を作る」→ △

と分けて考える必要がある。

# 12. 共通パイプライン案

問題生成器だけで終わらせず、
以下の形を共通基盤として考えるのがよい。

```text
問題生成器
  ↓
解法探索器
  ↓
検証器
  ├─ 解が存在する
  ├─ 一意解である
  ├─ ルール違反がない
  └─ 必要なら人間的手筋だけで解ける
  ↓
難易度評価器
  ↓
品質判定
  ↓
重複除去
  ↓
問題保存 / シード値
```

## 問題生成器

候補問題を生成する。

## 解法探索器

機械的に解を探索する。

## 検証器

- 可解性
- 一意性
- 最短解
- 禁止状態
- 論理解可能性

などを確認する。

## 難易度評価器

ゲーム固有の難易度指標を算出する。

## 品質判定

単に解けるだけでなく、
退屈・冗長・偶然解ける・極端な盤面を除外する。

## 重複除去

盤面対称性や同型問題を正規化して重複除去する。

---

# 13. 難易度評価の論点

自動生成で最も注意が必要なポイント。

## 機械的探索コスト ≠ 人間の体感難易度

例:

ナンプレ:
- clue数が少ないから難しいとは限らない
- 必要な論理テクニックの種類と深さが重要

カラーウォーターソート:
- 逆操作100回で作ったから100手問題とは限らない
- 相殺操作やショートカットが存在する

倉庫番:
- 最短手数だけでは難易度を表しにくい
- deadlock認識、順序依存、遠回りの必要性が重要

ノノグラム:
- SAT 解法探索器にとって難しい問題と、人間にとって難しい問題が一致するとは限らない

# 15. 一次調査時点の結論

## 結論1

シンプルパズルのかなり広い範囲は計算的に自動生成可能。

特に、

- 完成状態から情報を隠せる
- ゴール状態から逆操作できる
- CSP / SATとして定式化できる
- graphとして構成できる

タイプは自動生成と非常に相性がよい。

## 結論2

「生成できるか」よりも、
「良問を大量・安定供給できるか」の方が重要。

多くのゲームでは、

```text
盤面生成
```

より、

```text
一意解判定
難易度判定
人間的な面白さ判定
重複除去
```

の方が難しい。

## 結論3

多数のゲームを扱う場合でも、
生成基盤は5系統程度に抽象化できそう。

- 完成形生成・ヒント削除
- 逆操作生成
- 制約生成
- グラフ生成
- ゲーム木探索

この上に各ゲーム固有ルールを載せる設計が有望。

## 結論4

大量自動生成を前提とするプラットフォームなら、
まずは「◎」群を中心に構成し、
解法探索器や品質評価器の共通化可能性を検証する価値が高い。

# 18. ゲーム性要素との親和性（初期版選定用）

## 評価記号

| 記号 | 意味 |
|---|---|
| ◎ | 非常に相性がよく、ほぼ自然に導入できる |
| ○ | 相性がよい。軽い追加実装で導入可能 |
| △ | 導入は可能だが、ゲーム性として弱い / 設計が必要 |
| × | 基本的に相性が悪い |
| - | 評価対象外または意味が薄い |

## 評価対象

- **難易度**: 初級 / 中級 / 上級 などを自然に付与できるか
- **最短手数**: 最適手数・最小操作数を競技指標にできるか
- **タイム**: 解答速度を自然に記録・競争できるか
- **スコア**: 複数要素を点数化するゲームモードと相性がよいか
- **ミス記録**: 誤答・誤操作を意味のある指標として記録できるか
- **ヒント**: 段階的ヒントや次手提示との相性
- **元に戻す / やり直し記録**: 迷い・やり直しをプレイログとして記録する意味があるか
- **自己ベスト**: ベストタイム・ベスト手数等の再挑戦動機を作りやすいか
- **完全クリア評価**: ノーミス・ノーヒント・規定時間などを★や完全クリアにまとめやすいか
- **今日の問題**: 全員共通問題として毎日提供しやすいか
- **連続記録**: 連続日数・連続クリアとの相性
- **画面・操作**: スマホウェブ/PWAでシンプルに実装しやすいか
- **初期版**: 自動生成・実装量・ゲーム性を含めた初期採用向き度

> 注:
> - 「ミス」「元に戻す」「やり直し」は、初期版でスコアに反映しなくても**計測だけして保存する価値が高い**。
> - 「ヒント」はゲームごとのロジック実装が必要になりやすいため、親和性が高くても初期版では後回し候補。
> - 「完全クリア評価」は既存の計測値を束ねるだけなので比較的軽い。
> - 今日の問題 / 連続記録 はゲーム本体の面白さというより継続プレイのメタゲーム寄り。

# 19. 初期版で「実装」と「記録」を分ける案

初期版では、ゲーム性として見せるものと、将来の分析用に裏で記録するものを分ける。

## 最初からユーザーに見せやすい

- 難易度
- クリアタイム
- ベストタイム
- 手数
- ベスト手数
- 最短手数（解法探索器で安価に求められるゲームのみ）
- ミス数
- 完全クリア / ★評価

## とりあえず記録しておく価値が高い

- 元に戻した回数
- やり直した回数
- ミス数
- ヒント使用回数
- 開始からクリアまでの経過時間
- 実操作時間
- 操作数
- 途中離脱
- 再挑戦回数
- 同一問題のプレイ回数
- 最終クリア有無

これらは後から、

- 難易度補正
- 良問判定
- 離脱率分析
- スコア設計
- プレイヤー能力推定

に利用できる。

## 初期版では後回しでもよい

- 段階的ヒント
- 次の一手提示
- 横断評価値
- 複雑なスコアアタック
- グローバル順位表
- 連続記録の報酬
- 特殊ルールChallenge

ヒントは特に、
「答えを1個見せる」だけなら比較的軽いが、
「考え方を段階的に教える」にはゲーム固有の解法探索器説明能力が必要になるため、
初期版では無理に入れない。

# 21. 初期版のゲーム性方針（一次案）

初期版では横断的な高度設計を避け、各ゲームで自然に使えるものだけ採用する。

```text
共通表示:
- 難易度
- クリア時間
- 自己ベスト
- ミス数（意味のあるゲームのみ）

対応ゲームのみ:
- 手数
- 最短手数
- ベスト手数
- 完全クリア / ★評価

裏で記録:
- 元に戻す
- やり直し
- ミス
- ヒント使用
- 離脱
- 再挑戦

後回し:
- 段階的ヒント
- スコアアタックの複雑なルール
- 総合評価値
- 厳密なゲーム間正規化
- 高度なランキング
- 連続記録の報酬
```

この段階では、
「各パズル単体で遊んで面白い」
ことを優先する。
