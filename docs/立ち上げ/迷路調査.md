# 迷路の基礎仕様と自動生成の成立性調査

Issue #42 の調査結果。

## 結論

迷路は pa-zzle の採用候補として **次段階へ進めてよい**。

- 問題生成: 成立する。完全迷路として生成すれば、到達可能性と開始点・ゴール間の一意経路を構成上保証できる。
- 解法探索: 成立する。通常の格子迷路なら幅優先探索で最短経路を線形時間で求められる。
- 生成・探索コスト: 通常のスマホ向け盤面では問題になりにくい。
- 多様性: 複数の生成法と乱数シードを使えるため、継続供給に十分な余地がある。
- 難易度制御: 見込みはある。ただし盤面サイズや最短距離だけでは不十分で、分岐・誤経路・視覚条件を含めて検証する必要がある。
- 良問判定: 自動化候補となる構造指標は作れるが、人間の体感との対応はプレイログで補正する必要がある。

したがって、生成や解法探索の技術的成立性を追加検証するより、次段階では **複数生成法と特徴量計測を実装し、実プレイと難易度指標の対応を検証する** 価値が高い。

## 基礎仕様の候補

初期実装は、最も仕様が明確で扱いやすい **長方形の直交格子による完全迷路** を基準とする。

- 1マスを頂点とする。
- 上下左右に壁がなく隣接するマス間を辺とする。
- 1回の移動は隣接する1マスへの移動とする。
- 開始点とゴールを1つずつ持つ。
- 開始点からゴールへ到達した時点でクリアとする。
- 全マスが連結し、閉路を持たない完全迷路を基準とする。

完全迷路の通路グラフは全域木なので、任意の2マス間に経路がちょうど1つ存在する。このため、生成した時点で開始点からゴールへの到達可能性と経路の一意性が保証される。

開始点・ゴールは外周に置くのが画面上分かりやすい。ただし常に左上・右下へ固定すると問題特性が偏るため、生成後に候補を選び、最短距離や分岐などの特徴量を見て決める方がよい。

### 多経路迷路

完全迷路へ追加の辺を開通させれば、閉路や複数経路を持つ迷路も生成できる。

技術的には容易だが、以下が変わる。

- 開始点・ゴール間の一意経路が失われる。
- 最短経路と別経路の比較が必要になる。
- 「正解経路から外れた」という単純な評価ができなくなる。
- 難易度指標も完全迷路とは分けて考える必要がある。

初期実装では完全迷路を採用し、多経路迷路は後続の変種として扱うのが妥当。

## 生成アルゴリズム

代表的な方法はいずれも実用可能だが、生成される迷路の形には大きな差がある。

| 方式 | 特徴 | 初期用途 |
|---|---|---|
| ランダム化深さ優先探索 | 長い通路が生まれやすく、正解経路も長くなりやすい | 性質の異なる問題生成候補 |
| ランダム化Prim法 | 分岐や袋小路が多く、比較的短い通路が密に出やすい | 実装が簡単な基準候補 |
| ランダム化Kruskal法 | Union-Findで扱いやすく、全域木を直接構成できる | 生成法の追加候補 |
| Wilson法 | ループ消去ランダムウォークで一様全域木を生成する | 偏りの少ない比較基準候補 |
| Aldous-Broder法 | ランダムウォークから一様全域木を生成する | 理論上の基準。初期採用の必然性は低い |

1種類の生成法へ固定するより、複数方式を同じ盤面表現へ出力し、後段の難易度・品質評価で選別できる構成がよい。

### 一様全域木について

Wilson法と Aldous-Broder法は一様全域木を生成できる。これは「生成可能な全域木を同じ確率で選ぶ」という意味で、単純な深さ優先探索などとは生成分布が異なる。

一様であること自体は「人間にとって良い迷路」を意味しない。ただし、特定の生成法の形状バイアスを避けた比較基準として有用。

## 解法探索・最短経路

通常の格子迷路は重みなしグラフとして扱えるため、幅優先探索で開始点からゴールまでの最短経路を求められる。

- 頂点数を `V`、辺数を `E` とすると計算量は `O(V + E)`。
- 完全迷路では `E = V - 1` なので、盤面サイズに対して実質線形。
- 完全迷路では開始点とゴールの間に1本しか経路がないため、その経路がそのまま最短経路になる。

深さ優先探索でも唯一経路は取得できるが、将来多経路迷路を扱う可能性まで考えると、最短距離計算は幅優先探索を基準にする方が自然。

## 最小実験

調査だけでは生成法ごとの形状差と、実用サイズでの処理量が見えにくいため、直交格子の完全迷路について最小限の生成・探索実験を行った。

実験は Python の単純実装で、最適化した本番コードの性能測定ではない。数値は方式間の傾向と桁感を確認するためのもの。

### 20×20、各300問

| 方式 | 生成時間平均 | 開始→ゴール経路長平均 | 正解経路上の分岐平均 | 全袋小路数平均 |
|---|---:|---:|---:|---:|
| 深さ優先探索 | 0.82 ms | 121.3 | 12.6 | 42.3 |
| Prim法 | 0.69 ms | 43.0 | 24.9 | 129.5 |
| Wilson法 | 4.40 ms | 59.4 | 28.3 | 116.1 |

### 40×40、各100問

| 方式 | 生成時間平均 | 開始→ゴール経路長平均 | 正解経路上の分岐平均 | 全袋小路数平均 |
|---|---:|---:|---:|---:|
| 深さ優先探索 | 3.89 ms | 367.3 | 31.3 | 164.3 |
| Prim法 | 2.86 ms | 89.4 | 54.1 | 514.3 |
| Wilson法 | 28.20 ms | 142.3 | 69.8 | 468.4 |

同じ盤面サイズでも生成法によって、正解経路長・分岐・袋小路が大きく変わった。したがって **盤面サイズだけを難易度として扱うべきではない**。

各サンプル集合内では生成結果のハッシュ重複はなかった。これは重複問題が存在しないことの証明ではないが、通常利用で即座に多様性が枯渇する兆候は見られなかった。

### 最短経路探索

Prim法で生成した完全迷路を幅優先探索した平均時間は以下だった。

| 盤面 | 平均探索時間 |
|---|---:|
| 20×20 | 0.11 ms |
| 40×40 | 0.45 ms |
| 80×80 | 1.90 ms |
| 160×160 | 11.90 ms |

スマホ画面で現実的に使う盤面はこれより小さいと考えられるため、最短経路算出を生成時検証やスコア計算へ使うことに性能上の致命的な問題は見当たらない。

## 難易度評価

### 構造的難易度

難易度候補として最低限、以下を計測する価値がある。

- 開始点からゴールまでの最短距離
- 正解経路上の分岐数
- 正解経路から伸びる誤経路の数
- 誤経路の深さ・総距離
- 最長の袋小路
- 正解経路上の曲がり回数
- 全通路に占める正解経路の割合
- 分岐の位置。開始直後やゴール直前に偏っていないか

既存研究では、人間が迷路を解く際の難しさについて、経路上の T 字分岐数などが成績と相関することが報告されている。最短経路長だけでなく、意思決定を要求される地点の数を特徴量として持つ根拠になる。

ただし、これらから最終的な難易度式を今決めるべきではない。まず各特徴量を保存し、クリア時間、実移動距離、戻り量、離脱などのプレイログとの関係を検証する。

### 視覚的難易度

迷路の難しさは通路グラフだけでは決まらない。

迷路の壁・通路の太さや、直線か曲線かといった見た目を変えるだけでも、解答時間が変化する研究がある。視覚的混雑や図と地の分離が経路追跡へ影響するため、同じグラフでも表示条件によって体感難易度が変わりうる。

初期段階では、壁・通路幅・表示倍率などをできるだけ固定し、まず構造的難易度との関係を検証する方がよい。視覚条件を難易度調整へ使うのはその後に分離して扱う。

## 良問判定と生成パイプライン

生成可能性よりも、後段の選別を明示的に設計した方がよい。

```text
盤面サイズ・生成方式を選ぶ
  ↓
完全迷路を生成
  ↓
開始点・ゴール候補を選ぶ
  ↓
唯一経路・特徴量を計算
  ↓
難易度帯・品質条件を満たすか判定
  ├─ 満たす → 採用
  └─ 満たさない → 再生成または端点を再選択
```

初期の品質除外条件としては、次のようなものが考えられる。

- 正解経路が極端に短い。
- 正解経路上の意思決定点がほとんどない。
- 誤経路がすべて極端に浅く、分岐が実質的に意味を持たない。
- 長い一本道ばかりで探索というより単純移動になっている。
- 盤面を画面へ収めたときに視認性を損なうほど密になっている。

逆に、「袋小路が多いほど良い」「経路が長いほど難しい」と単調に決める根拠はない。最終的な採否・難易度境界はプレイログで補正する。

## 多様性・同型・対称性

完全迷路は全域木として非常に多くの候補を持つため、通常のサービス利用で生成候補そのものが不足する懸念は小さい。

初期段階で厳密なグラフ同型判定まで行う必要性は低い。重複除去が必要になった場合は、まず以下で十分。

1. 盤面を回転・反転した表現を列挙する。
2. その中で辞書順最小などの代表表現を正規形とする。
3. 正規形のハッシュを保存して重複判定する。

開始点・ゴールの入れ替えを同一問題とみなすかは、タイムや操作感まで含めると必ずしも同一とは限らない。初期は盤面形状の重複監視と、特徴量分布の偏り確認を優先する。

## ヒント・元に戻す・やり直しとの境界

### ヒント

完全迷路なら正解経路が一意なので、ヒントは安価に実装できる。

- 次に進む正しい方向だけ示す。
- 現在地から数マス分の正解経路を示す。
- ゴールまでの正解経路を表示する。

初期版で段階的ヒントを入れる必要はないが、解法探索側に追加の難しい推論器は不要。

### 元に戻す

通常の迷路では一歩戻ること自体が合法な移動であり、探索行動の一部になる。そのため、専用の「元に戻す」を必須機能とはしない。

プレイ評価では、最短距離とは別に実移動距離を記録すれば、迷いや戻りを自然に観測できる。

### やり直し

開始点へ戻す機能として扱える。再挑戦回数はプレイログとして保持する価値がある。

## プレイ評価との相性

迷路は pa-zzle が想定している計測値と相性がよい。

- クリア時間
- 最短距離
- 実移動距離
- 最短距離との差分
- 戻った距離
- ヒント使用
- やり直し回数
- 自己ベスト

特に `実移動距離 / 最短距離` や超過距離は、単純な最短手数競争とは違い、経路探索の精度を表す候補になる。ただし最終評価式はこの調査では決めない。

## 次段階

実装へ進む場合、最初から難易度式を固定せず、以下をまとめて検証できる最小実装がよい。

1. 完全迷路の共通盤面表現
2. 性質の異なる複数の生成方式
3. 幅優先探索による正解経路・最短距離計算
4. 構造特徴量の計測
5. シード値による再現
6. 実プレイログと特徴量を後から対応付けられる保存構造

この段階まで作れば、生成法・盤面サイズ・各特徴量のどれが人間の難易度や面白さへ効くかを実データで検証できる。
