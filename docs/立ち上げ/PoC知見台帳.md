# PoC知見台帳

## 目的

この文書は、PoCで得た知見を「今後の pa-zzle がどうあるべきか」という正の振る舞いとして棚卸しし、適切な正本・要件・設計へ移すための作業台帳である。

Issue、PR、調査文書、コード、テスト、実測は結論そのものではなく、各知見の根拠として扱う。PoC中の試行錯誤や不採用案を本文の主題にはせず、必要な場合だけ根拠から追跡できるようにする。

この文書自体は長期的な仕様の正本ではない。各項目は正本化・要件化・設計反映が完了したら、その参照先を正として扱う。

## 台帳の読み方

確度:
- 確定: 複数の実装・実プレイ・正本で確認でき、今後の前提として扱える。
- 有力: PoC上の根拠は強いが、要件・設計の確定または追加の横断確認が必要。
- 要検証: 仮説または特定ゲームでの成立までで、人間校正・実プレイ・別ゲーム比較等が残る。

扱い:
- 既存の正で十分: APP / GAME / DESIGN 等の文書、コーディング規約、Skill、コード上の型・API・テスト契約など、責務に合う既存の場所がすでに正を保持している。重複して文書化しない。
- 後続Issue所有: #7 / #8 / #71 / #72 / #74 / #134 / #135 / #137 等で、要件・設計・規約・画面正本として確定する責務が明示されている。Issue自体は正本ではないため、完了時に適切な正へ反映する。
- 今回の正本化候補: 既存の正にも後続Issueにも所有されておらず、PoC知見として今ここで正の置き場所を作る必要がある。
- 検証待ち: 実プレイ・人間校正・別ゲーム比較等が終わるまで結論自体を確定しない。

正の置き場所は文書に限定しない。利用者体験は APP / GAME / DESIGN / 画面正本、実装規則は .claude/rules、反復作業は Skill、正確な型・API・状態遷移はコードとテスト契約を優先する。

反映状態:
- 正本化済み: 現行の正本文書へ反映済み。
- 正本候補: 現行の正本へ昇格できる知見。
- 要件入力: #71 で利用者価値・システム要件として判断する。
- 設計入力: #72 で実現方式・責務・データ構造として判断する。
- 検証継続: 現時点では正本化せず、既存Issueやパズル固有検証を続ける。
- 専用正本化済み: Skill、コード、画面文書など、その責務に合う別の正本へ既に反映済み。
