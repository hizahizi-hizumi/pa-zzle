# pa-zzle アイコン設計

## 1. 目的

pa-zzle のブランドマークとして、`A` と `Z` の文字そのものが2枚のジグソーパズルとして成立し、両者が自然に噛み合って見えるアイコンを設計する。

「文字にジグソーパズルの装飾を足す」のではなく、**A と Z の字形と、2枚のピースの形状を同一の造形として成立させる**ことを目標とする。

本設計は `DESIGN.md` の視覚人格に従う。pa-zzle の共通UIは「ミニマルで静か」であり、ブランドマークもゲームそのものより前へ出る強い装飾ではなく、共通UI側の静かな記号として扱う。

## 2. 造形の核

アイコンの核は次の1点である。

> **静かな A と Z の造形の中で、両者の共有境界だけが物理的に正しいジグソー接合となり、「パズル」を説明せずに示す。**

そのため、パズルらしさを強める目的で不要な凸凹を追加しない。接合は中央の1か所を主役とし、A / Z の可読性と一体化させる。

## 3. ジグソーパズルとしての成立条件

中央の接合部は、A と Z が別々に描いた2本の線ではなく、**1本の共有境界**として設計する。

- A 側の凸と Z 側の凹は、幅・深さ・入口・曲率まで相補的にする。
- 2枚を離して表示しても、隙間を閉じれば完全に噛み合うと理解できる形にする。
- A / Z はそれぞれ1枚の物体として連続した形を保つ。
- 接合を作るために文字のストロークを途中で切断したり、意味のない枝や追加突起を生やしたりしない。
- 「ジグソーパズルっぽく見える」だけでは不十分とし、実際の2ピースとして形状が破綻していないことを優先する。

### Z 上側の凹み

Z の上横棒から斜線へ移る内側、`>` のように見える既存の空間を、そのまま「凹み」と呼ぶだけにはしない。

この領域を、**Z の字形を維持したまま本物のジグソーソケットへ造形し直す**。

- Z の上横棒から内側へ入る輪郭が、自然にソケットへ遷移する。
- ソケットの最深部から、Z の斜線へ自然に戻る。
- 丸い凹部を後付けするのではなく、Z が元から持つ「内側へ入り込む形」をジグソー接合として再解釈する。
- A 側は、そのソケットへ入る相補形状を A の右側輪郭の自然な延長として持つ。

理想状態では、`Z → 凹み → ジグソー` と説明しなくても、Z の内側そのものがジグソーのソケットとして読める。

## 4. pa-zzle の視覚人格への適合

`DESIGN.md` の「ミニマルで静か」を、アイコンでは次のように翻訳する。

- **説明しすぎない**: 「パズル」を示すためだけの追加ノブ、複数の凸凹、補助記号を置かない。
- **装飾しない**: 影、光沢、立体感、装飾目的のグラデーションを使わない。
- **低彩度で扱う**: 共通UIの情報階層に従い、ブランド専用の強い色を前提にしない。正確な色値は `@theme` を正本とする。
- **文字として自然にする**: 幾何学記号へ寄せすぎず、A / Z として読めるリズムと重量感を保つ。
- **余白を造形に使う**: パズルらしさを塗りや装飾量で出さず、共有境界と周囲の余白で見せる。
- **ゲームより強くしない**: ヘッダーなどに常駐しても盤面やゲーム固有表現と競合しない強さに抑える。

ブランドマークは「楽しいパズルゲーム」を強く主張するキャラクター的な表現ではなく、**2つの形が静かにぴたりと噛み合っている状態**を pa-zzle の象徴とする。

## 5. 検証する表現方向

造形の核と物理条件を固定したうえで、次の3方向を比較する。

### 5.1 完全形

A と Z の全体形を残し、中央の接合を明確に見せる。

- A / Z としての認識性を最も確認しやすい基準案とする。
- Z 上側の `>` 領域全体をジグソーソケットとして設計する。

### 5.2 透明な輪郭線

塗りつぶしをなくし、A / Z と接合部を輪郭線だけで表す。

- 内部は背景を透過させる。
- 線幅は一貫させ、透明なジグソーピースの輪郭のように見せる。
- 線画になっても、共有境界が2枚のピースとして追えることを条件とする。

### 5.3 接合フォーカス

輪郭線案を基に、A の左側と Z の右側をそれぞれ約2割省略し、中央の接合へ視線を集中させる。

- A / Z の完全な字形を見せることより、2枚が噛み合う瞬間を主役にする。
- 省略は意図的なトリミングとして見える必要があり、ピースが破損しているように見せない。
- 中央の接合構造と A / Z の識別に必要な輪郭は残す。

この3方向は見た目の比較対象であり、ジグソーとしての物理成立条件を緩めるものではない。

## 6. 小サイズでの成立条件

ヘッダー利用を前提に、小サイズでも次を満たす。

- A と Z の双方を認識できる。
- 中央の接合が単なる丸い出っ張りや装飾に見えない。
- Z 上側のソケット構造を追える。
- 輪郭線案では線が潰れず、接合部の内外が混ざらない。
- アイコンが周囲の共通UIより強く主張しない。

大きいプレビューだけで判断せず、実際のヘッダー相当サイズでも確認する。

## 7. 不採用とする方向

次の状態は採用しない。

- A / Z に一般的な丸いジグソーノブを後付けしただけの形。
- A と Z の接合線が相補形状になっていない形。
- Z の `>` の内側を加工せず、単に「ここが凹み」と見立てただけの形。
- 接合のために Z の字形やストロークが壊れている形。
- ジグソーらしさを示すために凸凹を複数追加した形。
- 角丸、影、グラデーション、立体感などがアイコンの主役になる形。
- 大きく表示したときだけ成立し、ヘッダーサイズでは接合構造が読めない形。

## 8. 完成判断

アイコンは、単に前案よりよくなったことを完成条件にしない。

少なくとも次を同時に満たしたときに完成候補とする。

1. A と Z の文字として自然に読める。
2. 2枚のジグソーピースとして物理的に成立している。
3. Z 上側の内側が、Z の字形と一体化した本物のソケットになっている。
4. 追加説明なしで「2つが噛み合っている」と理解できる。
5. `DESIGN.md` の「ミニマルで静か」という共通UIの人格と整合する。
6. ヘッダー相当の小サイズでも成立する。
