## 4. 実画面まで試した案

一覧全体は共通の静かな器を維持しつつ、カード上部の大部分を各ゲーム固有の代表表現へ割り当てた。

### カラーウォーターソート

- 汎用の水滴アイコンを廃止
- 色水の入った複数のボトルを代表表現として表示
- プレイ画面で意味が定まっている色定義を一覧側でも共有する方針
- プレイ盤面全体をそのまま縮小するのではなく、「色を分けるボトル」というゲーム認識に必要な要素だけを再構成

既存実装では `WaterSortBoard.tsx` 内にボトル視覚表現が存在することを確認した。PoC では、盤面コンポーネント自体を一覧へ流用するのではなく、色・形の意味をゲーム側で共有しつつ一覧専用の非操作表現を持つ方向を採用した。

### ナンプレ

- 汎用のグリッドアイコンを廃止
- 3x3 ブロック境界を持つ 9x9 盤面と数字を代表表現として表示
- 現時点の `SudokuPlay` は本物のプレイ盤面が未実装なので、一覧表現を将来のプレイ盤面コンポーネントへ依存させない
- 一覧用の盤面は操作できない代表表現として扱い、ナンプレ本体の最終 UI 設計を先取りしない

### 一覧レイアウト

実画面では次の構成を試した。

- 上部: `ゲームを選ぶ`
- 主見出し: `今日はどのパズルで遊びますか？`
- カード内: ゲーム固有の視覚表現 + ゲーム名
- 既存の長い説明文は表示しない
- スマートフォン: 1列
- PC: 2列

結果として、カードを見るとまず「ボトル群」「9x9 数字盤面」が目に入り、その後にゲーム名を読む視覚順序になった。

## 8. 現時点の PoC 所見

少なくともカラーウォーターソートとナンプレの2種類では、次の方向性は成立する見込みが高い。

1. 一覧の主役を「汎用アイコン + 説明文」からゲーム固有の代表表現へ移せる。
2. 代表表現はプレイ盤面の機械的な縮小である必要はない。
3. 一覧専用の見た目を完全に別物として作るのではなく、ゲーム側で意味のある色・形は共有した方が一貫する。
4. 共通 UI を静かに保てば、ゲーム固有の色や形を前面に出しても一覧全体は破綻しない。
5. 今回の2ゲームでは、従来の1文説明を常設しなくてもゲーム選択 UI として成立している。

ただし、ゲーム数がさらに増えた場合の密度・一覧性については今回の2ゲームだけでは未検証。
