# 記録画面

## 役偲

記録画面は、完了した過去のプレイを振り返り、同じゲーム・同じ開始条件での自分の上達を確認する画面である。

プレイ履歴と自己ベストを別々の機能として切り離さず、**現在の自己ベストがどの過去プレイから生まれたかを履歴と一緒に確認できる場所**として扱う。

## 達成したい体験

利用者が次を一続きに確認できることを目指す。

1. どのゲーム・開始条件の記録を見ているか。
2. その条件で現在の自己ベストが何か。
3. 過去の各プレイがどのような結果だったか。
4. どのプレイが現在の自己ベストに該当するか。

記録は他利用者との比較ではなく、過去の自分との比較に使う。

## 現在扱う情報

現在の記録画面で必要なのは次の情報である。

- ゲームの切り替え。
- そのゲームで記録が存在する開始条件の切り替え。
- 選択中の条件に対する現在の自己ベスト。
- 完了日時を含むプレイ履歴。
- 各プレイの主要評価と比較に必要なゲーム固有指標。
- 現在の自己ベストに該当する履歴の識別。

これらを独立した大きな領域として固定せず、同じ比較条件に属する情報としてコンパクトに扱う。ゲームと開始条件は一覧を常時展開せず、パズル数や条件数が増えても画面占有が増えない選択操作として扱う。今後追加する分析や可視化は、必要性と表示内容が決まった時点で設計し、未決定の機能を想定した枠や仮表示は置かない。

異なる開始条件の記録を一つの自己ベストとして混ぜない。ゲーム側が同一条件として比較できると定義した記録だけを同じ一覧へ載せる。

通常UIには次を置かない。

- seed、生成器版など問題再現のためだけの内部情報。
- 難易度判定や解法器の内部診断値。
- 保存形式の版など実装上のメタデータ。
- ランキングや他利用者との比較。

## 履歴の正本と導出値

履歴として保存する正本は、完了したプレイで実際に起きた事実である。

- プレイ開始・完了日時。
- 選択した開始条件。
- 問題を再現するために必要な情報。
- 経過時間、手数、ミス、待った、やり直しなど、そのプレイで計測した事実。
- ゲーム固有評価を後から再計算するために必要な問題側の事実。

プレイ評価、部分評価、自己ベスト判定、自己ベスト更新フラグなど、現在の評価規則から導出できる値を履歴の正本として保存しない。画面表示時またはプレイ完了時に、保存済みの事実と現在のゲーム仕様から導出する。

MVPではクリアしたプレイだけを履歴として確定する。途中離脱や未完了プレイは履歴に含めない。将来プレイ再開を扱う場合は、進行中プレイと完了済み記録を別の概念として扱う。

## 自己ベスト

自己ベストは保存済み履歴から導出する。

比較単位はゲーム側が定義し、ゲーム名だけで異なる開始条件を一括比較しない。問題単位の再挑戦記録を、通常の自己ベスト比較単位へ自動的に昇格させない。

自己ベストを単一の数値へ限定しない。各ゲームが、そのゲームで上達を感じるために意味のある指標を定義する。複数指標がある場合、それぞれ独立して自己ベストを持てる。

最初の完了プレイは「初記録」として扱う。既存ベストを厳密に上回った場合だけ「自己ベスト更新」とし、同値は更新扱いにしない。同値の記録は履歴上で現在のベストに該当する記録として示せる。

## 共通とゲーム固有の境界

### 共通層が所有するもの

- 完了プレイを履歴として保存・読み出すこと。
- 完了日時による時系列表示。
- ゲームと比較条件を切り替える枠組み。
- 自己ベストと履歴を同じ比較条件で扱うこと。
- ゲーム側が定義した指標について、過去記録から最良値を選ぶこと。
- 初記録・自己ベスト更新・通常記録という共通の意味。

### ゲーム側が所有するもの

- 保存すべきゲーム固有のプレイ事実。
- 何を同一の比較条件として扱うか。
- 何を自己ベスト指標として扱うか。
- 指標の大小のどちらを良い値とみなすか。
- 履歴の主要評価と補助指標として何を見せるか。
- 現在の評価規則からプレイ評価をどう導出するか。

共通層は、全ゲームへ同じ評価軸や同じ履歴行の内容を強制しない。

## 結果画面との接続

プレイ完了時に履歴を保存し、保存前の同条件履歴と比較する。

- 同条件の履歴がなければ「初記録」を返す。
- 一つ以上の自己ベスト指標を厳密に更新した場合、更新した指標と以前の値・今回の値を返す。
- 更新がなければ、結果画面へ特別な称賛を追加しない。

結果画面から記録画面へ移動できる導線を持つ。

## 密度とレスポンシブ

記録画面は複数の記録を比較する画面なので、見出しや独立面を増やして縦方向を消費しすぎない。ゲーム・開始条件・自己ベスト・履歴は、現在の情報量に見合う密度で連続して読めるようにする。

スマートフォンでは必要に応じて折り返しても、1件の履歴が結果画面のような大きな塊にならないことを優先する。PCでは数値同士を横方向にも比較できる密度を使う。

ゲーム・開始条件の切り替え直後に、自己ベストと履歴が同じ条件へ更新されることを明確に返す。

## 成立条件

記録画面は、少なくとも次を満たす。

- 完了したプレイが再読み込み後も残る。
- ゲームと開始条件を混同せず、比較可能な記録だけを同じ一覧へ表示する。
- 自己ベストが保存値ではなく履歴から導出される。
- 評価済みスコアを保存していなくても、現在の評価規則で履歴を表示できる。
- 初記録、厳密な自己ベスト更新、同値の記録を区別できる。
- 履歴から現在の自己ベストに該当するプレイを確認できる。
- seedや診断値など内部情報を通常の履歴へ露出していない。
- スマートフォンとPCの双方で、自己ベストと複数の履歴を比較しやすい。
