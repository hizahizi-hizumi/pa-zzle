# 開始条件選択画面

## 役割

開始条件選択画面は、ゲームを選んだ後、プレイ開始前にそのゲームで必要な条件を決める画面である。

**設定を入力するためのフォームではなく、これから遊ぶ体験を選ぶ場所**として扱う。

選ぶ条件はゲームごとに異なる。難易度、盤面規模、モード、カテゴリなどを取り得るため、画面共通の概念を「難易度選択」に限定しない。開始前に選択が不要なゲームでは、この画面を挟むこと自体を必須にしない。

## 達成したい体験

利用者が次を説明文に頼らず理解できることを目指す。

1. どのゲームを始めようとしているか。
2. 選択肢同士にどのような違いがあるか。
3. どこを操作すればその選択肢で始められるか。

選択は設定値の確定ではなく、**次に挑む体験を自分で選んだ感覚**につなげる。

ゲーム一覧からプレイへ進むにつれて、ゲーム固有表現を段階的に具体化する。開始条件選択では、一覧よりゲーム自身の姿を強く見せ、プレイ画面ほど情報量や操作を解放しない。

## 視覚・情報の優先順位

優先順位は次の順とする。

1. ゲーム固有の視覚表現。
2. 選択肢同士の違い。
3. 選択肢の名称。
4. 戻る導線などの補助操作。

ゲーム名は現在の文脈を保つために表示できるが、選択肢より強く主張させない。

選択肢の違いを説明文だけで成立させない。視覚表現で十分に区別できる場合、補助説明を追加しない。

## ゲーム固有の視覚表現

選択肢には、そのゲームで実際に見る・触る対象の視覚言語を使う。

プレイ画面の完全な再現は不要だが、簡略化によってゲームの姿や選択肢の意味まで失わせない。

簡略化するときは、次を基準にする。

- 実ゲームで使う視覚部品を再利用できるなら優先する。
- プレイ用の状態管理や操作ロジックまで持ち込む必要はない。
- 選択肢の違いとして自然に見える規模、密度、構成などを、見た目を揃えるためだけに均さない。
- 難しさや特徴を伝えるために、実態とかけ離れた誇張表現を作らない。
- 固定プレビューを使う場合も、内部診断値の可視化ではなくゲームとして自然な見え方にする。

## 情報と操作

通常必要なのは次の情報・操作である。

- 現在のゲームを識別する情報。
- 開始条件の選択肢。
- 各選択肢の名称。
- ゲーム固有の視覚表現。
- 前の画面へ戻る導線。

各選択肢は、視覚表現やラベルの一部分ではなく、**選択肢全体を一つの操作面**として認識・操作できるようにする。

境界、面の差、遷移を示す補助記号などは、装飾ではなく操作可能範囲を理解させるために使う。hover / press / focus では、入力を受け付ける対象であることを明確に返す。

通常UIには次を置かない。

- 問題生成や難易度判定の内部特徴量。
- seed や内部ID。
- 選択に不要な長い説明。
- ゲーム固有表現より前へ出る共通UI装飾。

## 共通とゲーム固有の境界

### 共通層が所有するもの

複数ゲームで同じ意味と振る舞いを持つことが確認できたものだけを共通化する。

候補となるのは次の責務である。

- 選択肢を一つの操作面として見せること。
- ラベルとゲーム固有の視覚表現を同じ選択肢としてまとめること。
- 選択後にプレイへ進むことを示すこと。
- hover / press / focus の共通UIとしての反応。
- 画面全体の基本的な余白とレスポンシブ配置。

共通コンポーネントの意味上の契約は、概ね「名称・ゲーム固有の視覚表現・選択後の遷移」を受け取る程度に留める。正確な公開APIは実装コードを正本とする。

### ゲーム側が所有するもの

- 何を開始条件として選ぶか。
- 選択肢の数と名称。
- 選択肢同士の体験上の違い。
- 何を見せればその違いが自然に伝わるか。
- 盤面、駒、ボトル、セルなどのゲーム固有部品。
- ゲーム固有色、形、規模、密度。
- 必要な場合のゲーム固有アニメーション。

「3段階の難易度」や特定ゲームのプレビュー構造を、開始条件選択画面の共通仕様にはしない。

## レスポンシブ・操作反応

スマートフォンを基準に、各選択肢の違いと操作範囲を一目で追える密度にする。

PCではスマートフォン向けの狭い選択肢を中央へ置くだけにせず、横並びなど広い画面を比較しやすさへ使える。

操作反応は短く明確にし、選択前から常時動く装飾は使わない。

## 成立条件

開始条件選択画面は、少なくとも次を満たす。

- 何のゲームを始める画面か分かる。
- 選択肢の違いを長い説明なしで認識できる。
- どこを押せばよいか迷わない。
- 各選択肢の操作可能範囲が視覚的にまとまっている。
- ゲーム一覧よりゲーム固有表現が具体的になっている。
- プレイ画面の完全な再現や過剰な情報量にはなっていない。
- 共通UIがゲーム固有表現より強く主張していない。
- スマートフォンとPCの双方で比較・選択しやすい。
- 操作時に入力を受け付けたことが分かる。
- 内部診断情報を利用者向けの差分説明として露出していない。
