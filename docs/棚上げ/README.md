# 棚上げ

パズル候補の台帳を置く。資料であり、正本ではない（ADR-0003）。台帳に載せること自体は、調査・設計・実装へ着手することを意味しない。具体的な作業は Issue で扱う。

## パズル候補

`パズル候補.csv` は、パズル候補と採用フローの進み具合を見渡すための台帳にする。

- PoC初期の一次調査に挙がった候補を広く載せる。同名・同一系統として扱っているものはまとめてよい。
- `問題供給`、`難易度運用`、`スマホプレイ`、`導入判断` で、現在どこまで確認できているかを記す。
- 各ゲートの状態は厳密なワークフロー制御には使わず、`未確認`、`確認中`、`通過` など、その時点を判断できる短い表現を使う。
- `導入判断` は `未判断` / `実装候補` / `条件付き保留` / `見送り` / `正式採用` を使い、成立性調査での実装候補化と現在のプロダクトへの正式採用を区別する。
- `詳細` が必要な候補だけ `パズル候補/<ID>.md` を置き、各段階の調査・検証資料への索引にする。調査内容そのものは複製しない。
- 採用後の候補を必ず削除するなど、一覧から外す時期は固定しない。
- 実装順や着手予定は管理しない。
