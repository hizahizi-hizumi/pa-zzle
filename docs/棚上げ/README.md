# 棚上げ

現在のプロダクト定義には採用していないが、将来の検討対象として失いたくない要求・要件候補やパズル候補と、その補足メモを置く。

`docs/プロダクト/` の現在仕様の正本には含めない。棚上げした候補を置くこと自体は、調査・設計・実装へ着手することを意味しない。

## Issue との違い

- 棚上げは、未採用の候補そのものを保持する。
- Issue は、調査・設計・実装・修正・正本化など、実行する作業の範囲と完了条件を管理する。
- 候補を棚上げするだけでは Issue を作らない。候補について具体的な作業へ着手するときに Issue を作る。
- 採用した候補は適切な正本へ反映し、棚上げから外す。

## 要件候補

`要件候補.csv` を一覧と索引にする。

- `ID`: 棚上げ内で候補を識別する。 `RQ-nnn` / `FR-nnn` / `NFR-nnn` など正本の識別子とは別物とする。
- `種別`: 候補の性質を示す。
- `概要`: 候補の内容を一覧で判断できる粒度で記す。
- `詳細`: 短い補足、または詳しいメモが必要な場合の `要件候補/<ID>.md` への相対参照を置く。不要なら空欄にする。

## パズル候補

`パズル候補.csv` には、成立性調査を通って実装候補に採用されたが、現在のプロダクト定義にはまだ採用していないパズルを置く。

- 一次調査で名前が挙がっただけのパズルは載せない。
- `詳細` には、候補として採用した判断を確認できる `docs/パズル/` の調査資料を参照する。
- 実装順や着手予定は管理しない。具体的に着手するときは Issue で扱う。
