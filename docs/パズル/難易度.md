# pa-zzle 難易度

## 役割

この文書は、pa-zzle における難易度の意味、目的、原則、用語を定める。

難易度の提供、判定、開発工程は別文書へ分ける。この文書では、それらの判断が立ち返る本質だけを持つ。

## この文書で実現すること

パズルの種類や具体化の方法が変わっても、「pa-zzle が何を難易度と呼び、何のために扱うのか」が揺れない状態を作る。

難易度に関する下位の判断が、この文書の定義と原則へ立ち返れるようにする。

## 難易度とは何か

pa-zzle における難易度とは、そのパズル固有の面白さを生む思考や技能という挑戦を、問題がどの程度要求するかを表す概念である。

難易度は、個々のプレイヤーが実際に感じる難しさそのものではない。人間のプレイ体験を基準として、問題間で要求される挑戦の強さを比較するために用いる。難易度そのものを特定の個人専用には定義しない。

難易度を高くすること自体を目的としない。挑戦の強さが異なっても、そのパズル固有の面白さが成立していることを前提とし、難易度が上がるほど、その面白さを生む挑戦がより強く要求されることを目指す。

## 原則

### パズル固有の挑戦を対象にする

難易度が表す対象は、そのパズルを解くためにプレイヤーが行う、そのパズル固有の思考や技能である。

何が挑戦になるかはパズルごとに異なる。異なるパズルの挑戦を、先に用意した共通の物差しへ無理に当てはめない。

挑戦の強さが変わっても、同じパズルでは同じ種類の面白さが残ることを目指す。低い難易度ではゲーム性を消し、高い難易度では別の負担へ置き換える設計にしない。

### 体感難易度と難易度を分ける

同じ問題でも、技能、経験、状態、利用する補助などによって、プレイヤーが感じる難しさは変わる。

pa-zzle の難易度は個々人の体感難易度そのものではなく、問題が要求する挑戦の強さを比較するための概念として持つ。

### 難易度は面白さのために使う

難易度は、難しい問題を作ること自体や、失敗を増やすこと自体を目的としない。

難易度によって、そのパズルの面白さを失わずに挑戦の強さを変えられることを重視する。

### 挑戦ではない負担を難易度にしない

手数、所要時間、反復操作などの作業量、盤面サイズや要素数などの複雑さ、視認・操作・理解・待機に由来するプレイ摩擦は、それ自体では難易度ではない。

これらが判断、記憶、先読みなどのパズル固有の挑戦を強める場合は難易度へ影響し得るが、値が大きいことだけを根拠に難しいとはみなさない。

### 問題成立性とプレイ成績を分ける

問題がルール上成立し、必要な可解性などを満たすことは難易度の前提であり、難易度そのものではない。解けない問題を高難易度として扱わない。

プレイ成績は、ある問題に対して一回のプレイでプレイヤーがどのように解いたかを表す。問題側の難易度とは別の概念として扱う。

### 人間のプレイ体験との対応を失わない

難易度は、人間が遊ぶときの挑戦を表す概念である。

別の量や性質が測りやすいという理由だけで、それを難易度と同一視しない。難易度として扱うものが人間のプレイ体験と明らかに矛盾するときは、難易度としての捉え方を見直す。

### ゲーム間の絶対尺度にしない

難易度は、各パズルの中で挑戦の強さを比較する。

異なるパズルの難易度を、同じ思考量、所要時間、成功率、技能水準などを表す絶対尺度として比較しない。

## 用語

| 用語 | 意味 |
| --- | --- |
| 挑戦 | パズルの目的を達成するためにプレイヤーへ要求され、理解・判断・技能の向上によってよりよく乗り越えられる、そのパズル固有の思考や技能 |
| 挑戦強度 | 問題が、そのパズル固有の挑戦をどの程度要求するか |
| 難易度 | 人間のプレイ体験を基準として、問題が要求する挑戦強度を問題間で比較するための概念 |
| 体感難易度 | 個々のプレイヤーが実際のプレイで感じる難しさ |
| 負荷 | プレイ中に生じる認知的、身体的、時間的な負担全般。挑戦だけでなく作業量やプレイ摩擦も含み得る |
| 作業量 | 問題を解くために必要な手数、時間、反復操作などの量 |
| 複雑さ | プレイヤーが扱う状態、要素、関係、選択肢などの多さや構造の入り組み方 |
| プレイ摩擦 | パズル固有の挑戦とは無関係に、理解、操作、視認、待機などから生じる負担 |
| 問題成立性 | 問題がルール上正しく遊べる問題として成立しているかを表す性質 |
| プレイ成績 | ある問題に対する一回のプレイで、プレイヤーがどのように解いたかを表す事実や評価 |
