# パーキングジャム難易度判定

> **実プレイを受けた再校正版**: `dependency-choice-v2` は、旧 `challenge-levers-v1` でレベル5が数秒・不成立0回で連続クリアできた実プレイを受け、難易度を「一部に深い依存があるか」だけでなく「プレイ全体で合法な選択肢がどれだけ絞られるか」まで含めて判定するよう見直したモデルである。現在の閾値は問題集合での分布と1人の実プレイから置いた初期値であり、複数人の実プレイによる校正は今後も必要である。旧モデルの設計経緯は [パーキングジャム難易度5段階調査](導入調査/パーキングジャム/パーキングジャム難易度5段階調査.md) に残す。

## 挑戦の定義

パーキングジャム固有の挑戦は次の通りとする。

> 塞がれた車の進路をたどって「どの車を先に出せば道が開くか」を読み、今出せる車とその方向を、試さずに見つけ続けること。

合法に出庫した車は盤面から消え、合法な出庫で後から手詰まりになることはない。したがって挑戦は数手先の配置を作る計画ではなく、遮断関係を読みながら、その時点で出せる車を見つけ続けることにある。

## 基準とするプレイ条件と分析の範囲

- ルールと操作（スワイプ・車近傍の前後操作）を理解している。
- 不成立操作で試さずに読むことを基準にする。待った・盤面を戻すは解法上不要なので前提にしない。
- 分析は、誰が誰の進路を塞ぐかの遮断関係と、単調削除の全到達状態（最大16台で `2^16` 状態）を扱う。
- 表現できるのは、遮断関係を何段さかのぼる必要があるかと、プレイ中に合法な車・出庫順がどれだけ絞られるかである。
- 視覚探索そのもの（見落とし・視線移動・密集の見た目）は直接測っていない。旧モデルで使った盤面規模と「読み違いを誘う車」は、問題集合と実プレイで難易度の順序を安定して説明できなかったため、`dependency-choice-v2` の分類要因には使わない。

## 問題成立性

生成器 version 2 は、車を1台ずつ「置いた時点で出庫できる」位置へ置く逆向き構築で問題を作り、並列削除で全車を出庫できることを確かめる。成立性（可解性）と難易度の分類は分離している。

## `dependency-choice-v2`

### 特徴

`frontend/src/games/parking-jam/problem/difficulty-analysis.ts` が問題から特徴を求め、`frontend/src/games/parking-jam/difficulty.ts` が次を分類に使う。

| 特徴 | 意味 |
| --- | --- |
| 段数 `dependencyDepth` | その時点で出せる車を全部同時に出す操作を繰り返した回数。段数2は「最初に出せる車を出せば残りは全部出せる」 |
| 最少先行台数の最大 `maximumPrerequisiteVehicleCount` | 各車が出せるようになるまでに最低何台を先に出す必要があるか、その最大値 |
| 平均合法車率 `averageLegalVehicleRatio` | 全到達状態で、残っている車のうち今すぐ出せる車が占める割合の平均。低いほど候補が絞られる |
| 解順自由度 `solutionOrderFreedom` | 全車の出庫順のうち、遮断関係を守って成立する順序がどれだけ残るか。低いほど順序が制約される |
| 初期遮断車数 | 初期盤面で出庫できない車の数（車両数 − 初期合法車数）。提供下限だけに使う |

### 2つの判定要因

挑戦を「依存」と「選択制約」の2要因に分け、それぞれ強さ1〜3で表す。

#### 依存

| 強さ | 条件 | 人間の負荷としての意味 |
| ---: | --- | --- |
| 1 | 段数2で、最少先行台数の最大が1 | 塞いでいる車は直接出せる |
| 2 | 段数3、または最少先行台数の最大が2以上 | 塞いでいる車がさらに塞がれている、または複数台の先行車を扱う |
| 3 | 段数4以上、または段数3で枝分かれが2以上 | 3段以上さかのぼるか、複数の依存を同時に保持する |

枝分かれは「最少先行台数の最大 −（段数 − 1）」で、1本の連鎖だけなら0になる。

#### 選択制約

| 強さ | 条件 | 人間の負荷としての意味 |
| ---: | --- | --- |
| 1 | 平均合法車率 `>= 0.85` **かつ** 解順自由度 `>= 0.85` | 多くの局面で複数の車を出せ、順序の自由度も高い |
| 3 | 平均合法車率 `< 0.70` **かつ** 解順自由度 `< 0.70` | 多くの局面で合法な候補が絞られ、成立する出庫順も少ない |
| 2 | 上記以外 | どちらか、または両方が中間にある |

平均合法車率だけを下げればよい、解順自由度だけを下げればよい、とはしない。強さ3は両方が低い問題に限り、「その場の候補が少ない」と「全体の順序が制約される」が同時に成立することを求める。

### 難易度1〜5への分類

難易度は2要因の強さを合わせて決める。

```text
レベル = 依存 + 選択制約 - 1
```

| 依存 \ 選択制約 | 1 | 2 | 3 |
| ---: | ---: | ---: | ---: |
| 1 | 1 | 2 | 3 |
| 2 | 2 | 3 | 4 |
| 3 | 3 | 4 | 5 |

同じレベルには異なる要因の組合せが入る。レベルの大小だけから各要因が個別に単調増加するとは限らないため、問題集合では2要因の分布と人間のプレイ体験を別途確認する。

| レベル | 体験としての位置づけ |
| ---: | --- |
| 1 | 依存が浅く、プレイ中も多くの車から選べる |
| 2 | 依存か選択制約のどちらか一方が一段強い |
| 3 | 両方が中程度、または一方が強くもう一方が弱い |
| 4 | 深い依存と中程度の選択制約、または中程度の依存と強い選択制約が重なる |
| 5 | 深い依存と強い選択制約が同時にあり、依存を読みつつ限られた合法候補を見つけ続ける必要がある |

盤面サイズ、車両数、固定物数、道路開口幅などの生成条件は難易度ラベルへ直接対応させない。生成条件が特徴へ影響することはあるが、分類するのは生成後の問題そのものである。

### 評価可能範囲・提供範囲

| 判定 | 条件 | 扱い |
| --- | --- | --- |
| 評価不能（`unsupported`） | 車両数が厳密解析の上限16台を超え、全状態由来の特徴を求められない | 提供しない |
| 軽すぎ（`too-light`） | 段数1、または初期遮断車数1以下 | 提供しない。出す順序を読む挑戦がほぼない |
| 重すぎ（`too-heavy`） | 段数7以上 | 提供しない。現行候補空間では極端に少なく、人間の確認も不足している |
| レベル1〜5 | 上記以外で2要因を計算できる | 2要因の組合せで分類して提供する |

## 旧モデルから見直した理由

`challenge-levers-v1` は依存・読み違い・規模の3レバーを使い、レベル1→2と3→4では主に「読み違い」を上げていた。問題集合を再解析すると、旧レベル3→4で平均合法車率・解順自由度がむしろ上がり、構造上は選択が自由になる逆転があった。

さらに実プレイで、旧レベル5を4〜8秒・不成立0回で複数回連続クリアできた。個別問題の identity は当時の履歴画面から保持できなかったため、その7問そのものを再分類することはできないが、「読み違いが多い」「盤面が広い」「一部の依存が深い」だけでは高難易度を保証しないことは確認できた。

`dependency-choice-v2` では、旧分析ですでに計算していた全状態特徴を使い、**プレイヤーが実際に遭遇する選択肢の絞られ方**を分類へ入れる。盤面規模や視覚的な紛らわしさは、実プレイとの対応を別途確認できるまで主判定から外す。

## 問題供給

全レベルを事前生成問題集から供給する。プレイ時には難易度判定や全状態解析をしない。

- 問題集: `frontend/src/games/parking-jam/problem/problem-pool.json`（各レベル1,000問）。生成条件表と各問の「条件表の番号・候補番号・生成試行」を持つ。
- 選択: `frontend/src/games/parking-jam/problem-selection.ts` が、プレイごとの seed で対象レベルの問題を選び、identity から盤面だけを復元する。
- 生成: `frontend/scripts/generate-parking-jam-problem-pool.ts`。難易度に依存しない192条件の候補空間を候補番号順に調べ、本番判定で分類し、回転・反転で同型の問題を除いて各レベル1,000問を採る。
- 検証: 同梱5,000問を identity から復元して再分析・再分類し、保存レベルとの一致と同型重複がないことを確認する。

### 現在の問題集の供給実測

現在の `dependency-choice-v2` の問題集は、192条件を141周回した27,072候補の範囲で全レベル1,000問を確保できた。各レベルで1,000問へ切る前の分類数は次の通り。

| レベル | 分類された候補 | 候補あたりの収率 |
| ---: | ---: | ---: |
| 1 | 2,916 | 10.77% |
| 2 | 2,094 | 7.73% |
| 3 | 4,665 | 17.23% |
| 4 | 1,306 | 4.82% |
| 5 | 1,005 | 3.71% |

採用した問題集の構成は次の通り。

| レベル | 盤面 6×6 / 6×8 / 8×8 | 車両 8 / 11 / 14台 | 固定物 0 / 1個 |
| ---: | --- | --- | --- |
| 1 | 239 / 372 / 389 | 698 / 269 / 33 | 540 / 460 |
| 2 | 126 / 385 / 489 | 550 / 369 / 81 | 539 / 461 |

高難易度を大盤面・多車両で埋める設計にはしていない。レベル5でも8台の問題を供給でき、問題規模ではなく依存と選択制約で難易度が上がる。

### 問題集合で確認した特徴の推移

各レベルの問題集から等間隔に100問を取り出して再分析した。中央値は次の通り。

| 特徴 | L1 | L2 | L3 | L4 | L5 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 段数 | 2 | 2 | 3 | 3 | 4 |
| 最少先行台数の最大 | 1 | 1 | 2 | 4 | 5 |
| 平均合法車率 | .855 | .780 | .768 | .696 | .598 |
| 解順自由度 | .869 | .818 | .799 | .750 | .614 |
| 必須先行関係数 | 2 | 3 | 4 | 7 | 11 |
| 初期合法車率 | .750 | .625 | .625 | .571 | .500 |

旧モデルで見られたレベル3→4の「上位の方が自由」という逆転は、この問題集合では解消している。これは問題集合上の構造的な確認であり、人間の体感を直接証明するものではない。

5,000問すべてについて復元→分析→判定した結果、保存レベルとの不一致は0件だった。採用した5,000問の回転・反転同型重複も0件だった。

## 旧3段階（`visual-local-load-v1`）の記録

3段階（かんたん / ふつう / むずかしい）時代の記録は、レベル1〜5へ読み替えず、旧区分のまま別の比較単位として表示する。旧ラベルとレベルの一対一の対応はない。旧記録は記録の採点版でそのまま再計算する（[パーキングジャム採点](パーキングジャム採点.md)）。旧区分の記録は再プレイの対象にしない。

## 難易度選択プレビュー

難易度選択のプレビューは、本番盤面と同じ描画部品を使った手設計の簡略図とする。全レベルで同じ8×8の駐車場を使い、上のレベルは下のレベルの車と道路開口を同じ位置のまま含める。

レベル1→2では選択制約、2→3では依存、3→4では選択制約、4→5では依存だけを一段強める。各プレビューが本番の `dependency-choice-v2` で表示レベルへ分類され、隣接レベルで他方の判定要因が弱まらないことをテストする。盤面そのものを拡大して難しさを表現せず、追加した遮断関係による判定要因の差を比較できるようにする。

## 検証根拠と限界

- 旧モデルの問題集と候補空間を全状態特徴で再解析し、旧レベル3→4の構造的な逆転と、旧レベル5の高い合法車率・解順自由度を確認した。
- 実プレイで旧レベル5を4〜8秒・不成立0回で複数回連続クリアした。個別 identity が残っていないため、その問題単位の事後分析はできない。
- 新モデルでは、同一候補空間から各レベル1,000問を継続供給でき、レベルが上がるにつれて平均合法車率・解順自由度・必須先行関係数が問題集合上で概ね一方向に変化することを確認した。
- 一方、実プレイによる校正は1人・短い観測に限られる。0.85 / 0.70 の境界が人間の知覚する5段階に最適であることまでは確認していない。
- `solutionOrderFreedom` は成立する出庫順の数に由来する代理値であり、人間がその全順序を列挙して考えるという意味ではない。
- 段数7以上を提供しない上限の根拠は引き続き弱い。

## 将来の再校正

記録には難易度、判定モデル版、採点版、問題識別情報、プレイ事実を保存している。実プレイ記録が集まったら、同じ判定モデル版の記録について問題識別情報から特徴を復元し、完答時間・最初の操作までの時間・不成立操作・待った・やり直しと照合する。

特に次を確認する。

- レベルが上がるにつれて、完答時間や最初の操作までの時間が系統的に増えるか。
- 平均合法車率と解順自由度のどちらが実プレイ差をよりよく説明するか。
- 0.85 / 0.70 の境界付近で体感が連続しているか。
- 依存3・選択制約1と、依存1・選択制約3のように同じレベルへ入る異なる問題が、同程度の挑戦として成立するか。
- 視覚探索・盤面規模・旧「読み違い」に、人間の難しさを説明する独立した効果が残っているか。

モデルの意味・特徴・境界を変える場合は `PARKING_JAM_DIFFICULTY_MODEL_VERSION` を更新し、問題集を生成し直す。
