# パズル

パズル横断の難易度設計と、個別パズルの導入調査を管理する。

## 難易度

難易度に関する文書は、本質から具体化へ向かう依存方向で分ける。

| 文書 | 役割 | 実現したい状態 |
| --- | --- | --- |
| [難易度.md](難易度.md) | 難易度の意味・目的・原則・用語 | 実装や工程が変わっても、何を難易度と呼ぶかが揺れない |
| [難易度提供.md](難易度提供.md) | 難易度を利用者へどのような意味の選択肢として提供するか | 多数のパズルで、利用者が望む挑戦強度を一貫した読み方で選べる |
| [難易度判定.md](難易度判定.md) | パズル固有の挑戦を再現可能に分析・分類する原則 | 共通式を強制せず、各パズルで人間の挑戦を機械的に扱える |
| [難易度開発手順.md](難易度開発手順.md) | 難易度を導入・変更するときの調査、実装、検証、正本化の工程 | 場当たり的な判定や根拠のない閾値調整を避け、検証可能な形で難易度を成立させる |

依存方向は次の通り。

```text
難易度.md
├─ 難易度提供.md ─┐
└─ 難易度判定.md ─┴→ 難易度開発手順.md
```

横断的な難易度の設計判断はこの配下の難易度文書を正とし、現在実装されている各ゲームの具体的な挙動・画面・特徴量・閾値は [../プロダクト/](../プロダクト/) とコードを正とする。

横断設計を変更した直後は、既存ゲームの現行仕様と一時的に差が生じることがある。差分は移行Issueで追跡し、現行挙動を説明する仕様を先に書き換えて実装済みのように扱わない。

現在の既知の移行差分:

- ナンプレ: 3段階 → 5段階を #295 で移行する。
- ウォーターソート: 3段階 → 5段階を #296 で移行する。

## 導入調査

[導入調査/](導入調査/) には、パズル候補の成立性、導入判断、難易度制御などの調査・検証資料を置く。現在仕様の正本ではない。

採用済みパズルの現在の契約は [../プロダクト/仕様/パズル/](../プロダクト/仕様/パズル/) を正とする。
