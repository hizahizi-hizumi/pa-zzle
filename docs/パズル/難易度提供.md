# 難易度提供

## 役割

この文書は、[難易度.md](難易度.md) で定めた難易度を、pa-zzle が利用者へどのような意味を持つ選択肢として提供するかを定める。

画面のレイアウトや具体的な文言は画面仕様、各ゲームで現在採用する段階数やラベルなどの具体契約はプロダクト仕様を正とする。この文書は、それらが満たすべき横断的な意味を持つ。

## この文書で実現すること

利用者が内部の特徴量や生成条件を知らなくても、難易度の違いを「このゲームをどの程度の挑戦強度で遊びたいか」という選択として理解できる状態を作る。

多数の異なるパズルが存在しても、難易度表現の読み方だけは共通し、それぞれのパズル固有の挑戦内容まで同一化しない。

## 原則

### 難易度は挑戦強度を選ぶために提供する

難易度の選択は、プレイヤーの能力を診断して格付けするためではなく、そのプレイで望む挑戦強度を選ぶためのものとする。

「この難易度を選べる人は上級者」といった能力ラベルを難易度の意味そのものにはしない。

### 難易度帯は利用者への約束として扱う

連続的な挑戦強度を利用者が選べる形へ区切ったものを難易度帯とする。

難易度帯は内部閾値の名前ではない。その帯を選ぶことで、別の帯とは意味のある挑戦強度の違いを体験できることを利用者へ約束する。

同じ帯の中にばらつきが存在することは許容するが、隣接する帯を区別できない、または帯の順序が明らかに逆転する状態を前提にしない。

### ゲーム間では相対的な位置を共通化する

異なるパズルで同じ難易度帯を使う場合、共通するのはそのゲームの挑戦範囲における相対的な位置と順序である。

同じ帯だからといって、異なるゲーム間で同じ思考量、プレイ時間、成功率、必要経験を保証しない。

各ゲームの挑戦内容は固有のままにし、「より低い帯より高い帯の方が、そのゲーム固有の挑戦を強く要求する」という読み方を共通にする。

### 段階数は体験差と供給可能性から決める

難易度帯を細かくすること自体を価値とはしない。

段階を増やす場合は、隣接する帯に利用者が意味を感じられる差があり、それぞれへ継続的に問題を供給できることを前提とする。内部値を細かく分割できるだけでは、段階を増やす理由にならない。

具体的な段階数と名称は、現在のプロダクト契約として別途定める。

### 利用者には体験の違いを伝える

難易度を説明するときは、生成条件、特徴量、閾値、内部スコアではなく、プレイすると何がどのように変わるかを利用者が理解できる情報を優先する。

盤面サイズなどが実際に変化する場合でも、それ自体を難易度の説明にせず、それによってどの挑戦が変わるのかを基準にする。

### 提供する帯は実際に供給できる範囲に限る

表示上の難易度帯だけを先に作らない。

pa-zzle が提供する難易度帯は、その帯に対応する問題を意図的かつ継続的に供給できることを前提とする。十分に供給できない帯を、選択肢として常設することは難易度提供として成立しない。

どのゲームに難易度提供を必須とするかは、現在のプロダクト要件を正とする。

### 問題難易度と個人向け推薦を分ける

問題の難易度そのものは、特定の個人専用に定義しない。

将来、プレイ履歴などから「次はこの帯が合いそう」と推薦することはできるが、それは共通の問題難易度の上に置く別の責務として扱う。

## 用語

| 用語 | 意味 |
| --- | --- |
| 難易度帯 | 利用者が挑戦強度を選べるよう、難易度を離散的な範囲へ区切った選択単位 |
| 難易度ラベル | 難易度帯を利用者へ識別させる名称や記号 |
| 難易度推薦 | 共通の問題難易度は変えず、プレイヤーの履歴や状態を根拠に選択候補を提示すること |

## この文書で固定しないこと

- 現在採用する難易度帯の具体的な数
- 各帯の具体的な名称・記号
- 難易度選択画面のレイアウトや視覚表現
- 各パズルにおける帯ごとの判定条件
- 個人向け推薦のアルゴリズム
