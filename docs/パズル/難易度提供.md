# 難易度提供

## 役割

この文書は、[難易度.md](難易度.md) で定めた難易度を、pa-zzle が利用者へどのような意味を持つ選択肢として提供するかを定める。

画面のレイアウトや具体的な文言は画面仕様、各ゲームで現在採用する段階数やラベルなどの具体契約はプロダクト仕様を正とする。この文書は、それらが満たすべき横断的な意味を持つ。

## この文書で実現すること

利用者が内部の特徴量や生成条件を知らなくても、難易度の違いを「このゲームをどの程度の挑戦強度で遊びたいか」という選択として理解できる状態を作る。

多数の異なるパズルが存在しても、難易度表現の読み方だけは共通し、それぞれのパズル固有の挑戦内容まで同一化しない。

## 提供する難易度の範囲

pa-zzle は、ルール上成立する問題のすべてを難易度として提供することを目的としない。

パズル固有の面白さが成立し、その面白さを生む挑戦の強さとして順序づけ、意図的に問題を供給できる範囲を、そのゲームの**提供範囲**とする。

提供範囲の下限は、そのパズル固有の挑戦が軽い形でも成立している側に置く。挑戦がほとんどなく単なる手続きや作業になった問題を、最も低い難易度として置くことを目的にしない。

提供範囲の上限は、そのパズル固有の挑戦を強く要求しつつ、その面白さを保って意図的に提供できる側に置く。単に長い、複雑、操作量が多い、判定できないなどの理由で、問題を最も高い難易度へ押し込まない。

提供範囲の外にある問題は、ルール上成立する問題であっても通常の難易度選択から提供しないことがある。

## 原則

### 難易度は挑戦強度を選ぶために提供する

難易度の選択は、プレイヤーの能力を診断して格付けするためではなく、そのプレイで望む挑戦強度を選ぶためのものとする。

「この難易度を選べる人は上級者」といった能力ラベルを難易度の意味そのものにはしない。

### 難易度帯は提供範囲を分ける選択単位とする

提供範囲を、利用者が挑戦強度を選べるよう離散的に区切ったものを難易度帯とする。

最も低い帯は「挑戦が存在しない問題」、最も高い帯は「作れる中で最も極端な問題」を意味しない。どちらも提供範囲の中で、そのゲーム固有の挑戦が成立している。

難易度帯は内部閾値の名前ではない。その帯を選ぶことで、別の帯とは意味のある挑戦強度の違いを体験できることを利用者へ約束する。

### 難易度帯は等間隔・等量でなくてよい

各帯が内部指標上で同じ幅を持つことや、生成される問題数を均等に分けることを目的にしない。

帯の境界は、利用者にとって意味のある挑戦差と、各帯を安定して提供できる範囲から決める。

同じ帯の中にばらつきが存在することは許容する。ただし、隣接する帯を区別する意味が失われるほど重なった状態や、帯の順序が継続的に逆転する状態を前提にしない。

### ゲーム間では相対的な位置と順序を共通化する

異なるパズルで同じ難易度表現を使う場合、共通するのはそのゲームの提供範囲における相対的な位置と順序である。

同じ帯だからといって、異なるゲーム間で同じ思考量、プレイ時間、成功率、必要経験を保証しない。

各ゲームの挑戦内容は固有のままにし、「より低い帯より高い帯の方が、そのゲーム固有の挑戦を強く要求する」という読み方を共通にする。

### 共通レベルとゲーム固有の体験説明を分ける

共通の難易度レベルは、難易度帯の順序と相対的な位置を識別するために使う。

そのゲームで実際に何が強く要求されるかは、ゲーム固有の挑戦内容に基づいて説明する。共通レベルだけに「どのように難しくなるか」まで背負わせない。

各ゲームは、難易度1〜5でどの挑戦がどのように強くなるのかを説明できる状態にする。利用者へどの情報をどの画面で見せるかは画面仕様で定める。

難易度を説明するときは、生成条件、特徴量、閾値、内部スコアではなく、プレイすると何がどのように変わるかを利用者が理解できる情報を優先する。

### 難易度は5段階で提供する

pa-zzle の共通の難易度表現は `難易度 1` から `難易度 5` までの5段階とする。

5段階は挑戦強度の等間隔な数値ではなく、各ゲームの提供範囲における順序と相対的な位置を表す。

| レベル | 共通の意味 |
| --- | --- |
| 1 | 提供範囲の中で挑戦が軽い側 |
| 2 | 1と3の間に位置する、比較的軽い側 |
| 3 | 提供範囲の中央に位置する |
| 4 | 3と5の間に位置する、比較的強い側 |
| 5 | 提供範囲の中で挑戦が強い側 |

この位置づけは統計的な五分位や等間隔を意味しない。難易度3も「平均的なプレイヤー向け」「推奨」「標準設定」を意味せず、難易度1も「初心者」、難易度5も「上級者」を意味しない。

各段階には、そのゲーム固有の挑戦において意味のある体験差が必要である。内部値を5等分できることや、問題数を均等に分けられることだけでは5段階が成立したとはみなさない。

5段階を継続的に供給できない場合は、無理に閾値を分割するのではなく、提供範囲、問題生成、難易度判定のどこに制約があるかを見直す。

### レベルの順序は帯同士の関係として保証する

同じゲームでは、難易度レベルが高いほど、そのゲーム固有の挑戦をより強く要求する問題群になることを保証する。

ただし、難易度帯は幅を持つため、低いレベルのすべての問題が高いレベルのすべての問題より必ず簡単である、という全問題間の厳密な順序までは保証しない。個々のプレイヤーの体感難易度についても同様である。

保証するのは、各帯の代表的な体験と問題群全体の傾向として、レベルの順序に沿って挑戦強度が高くなることである。

### レベルの意味を判定モデルから独立させる

難易度レベルは利用者へ提供する意味であり、特徴量、閾値、分類規則などの判定モデルそのものではない。

判定モデルを改善するときは、難易度1〜5の意味を変更するのではなく、同じ提供契約をより適切に満たすよう問題との対応を改善する。

提供範囲そのものを拡張・縮小し、各レベルが表す体験を実質的に変える場合は、単なる内部調整ではなく難易度提供の変更として扱う。

### 5段階の難易度提供を採用条件とする

pa-zzle に採用するすべてのパズルは、パズル固有の面白さを保ったまま、難易度1〜5それぞれに意味のある挑戦差を成立させ、各レベルの問題を意図的かつ継続的に供給できなければならない。

内部値を5分割できるだけでは採用条件を満たさない。5段階のいずれかで体験差または継続供給が成立しない場合、そのパズルは pa-zzle の採用対象としない。

表示上の難易度帯だけを先に作らず、5段階すべての体験差と問題供給が成立して初めて難易度提供が成立したとみなす。

### 提供する難易度は利用者が直接選べる

提供している難易度1〜5は、利用者がそのプレイで望む挑戦強度として直接選べるようにする。

難易度が高いことを能力や達成の証明とはしないため、低い難易度のクリアを高い難易度の解除条件にすることを、難易度提供の共通ルールにはしない。

将来、別の進行・解放要素を設ける場合は難易度とは別の目的と契約として扱う。

初期選択、前回選択の保持、推薦表示などは別途定めてよいが、それによって他の難易度を選ぶ自由を失わせない。

### 問題難易度と個人向け推薦を分ける

問題の難易度そのものは、特定の個人専用に定義しない。

同じ問題でも個々のプレイヤーの体感難易度は異なるため、各人が常に難易度帯の順序どおりに難しさを感じることまでは保証しない。

将来、プレイ履歴などから「次はこの帯が合いそう」と推薦することはできるが、それは共通の問題難易度の上に置く別の責務として扱う。

## 用語

| 用語 | 意味 |
| --- | --- |
| 提供範囲 | パズル固有の面白さが成立し、挑戦強度として順序づけ、意図的に問題を供給できる範囲 |
| 難易度帯 | 利用者が挑戦強度を選べるよう、提供範囲を離散的に区切った選択単位 |
| 難易度レベル | 5段階の難易度帯を `難易度 1`〜`難易度 5` で識別する共通表現。数値差を挑戦強度の等間隔差とはみなさない |
| 難易度ラベル | 難易度レベルに補足的に付与する名称や記号。共通の識別は難易度レベルが担う |
| 難易度推薦 | 共通の問題難易度は変えず、プレイヤーの履歴や状態を根拠に選択候補を提示すること |

## この文書で固定しないこと

- 各レベルでゲーム固有の挑戦がどう変わるかという具体説明
- 難易度レベル以外に併記する具体的な名称・記号
- 難易度選択画面のレイアウトや視覚表現
- 各パズルにおける帯ごとの判定条件
- 個人向け推薦のアルゴリズム
