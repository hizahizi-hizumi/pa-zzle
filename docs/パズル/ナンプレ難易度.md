# ナンプレ難易度判定

## 目的

ナンプレの難易度は、問題が一意解を持つか、機械探索が何手かかるかではなく、**人間が論理的に解くときに必要になる労力の相対的な大きさ**として扱う。

問題として成立していることは難易度評価の前提条件であり、難易度そのものではない。難易度評価では次を区別する。

1. 一意解を持たない問題: 評価対象外
2. 対応済みの人間向け手筋で解き切れない問題: `unsupported`
3. 対応済み手筋で解き切れる問題: 難易度を評価する

`unsupported` は `hard` と同義にしない。対応していない手筋が必要という事実だけでは、人間にとっての難しさは決まらない。

## 根拠

Radek Pelánek, *Difficulty Rating of Sudoku Puzzles: An Overview and Evaluation* では、実際の人間の解答時間を使って複数の難易度指標を評価している。

- ヒント数だけの相関は低い。
- バックトラッキング等の計算機探索量も人間難易度との対応が弱い。
- 人間向け論理手筋の複雑さに加えて、**各局面で次に進める論理手が何個あるかという手順間の依存構造**が難易度に影響する。
- Naked Single / Hidden Single だけで解ける問題でも、次の一手の候補が多い問題は易しく、候補が少ない問題は難しくなる。
- 依存構造を見る範囲は序盤20〜30手で結果が安定しており、25手は有効な範囲に含まれる。

参考: https://arxiv.org/abs/1403.7373

## `dependency-v1`

### 対応手筋

初版では次の2手筋を扱う。

- Naked Single
- Hidden Single

この2手筋の個別難易度には重みを付けない。研究上の単純モデルでも、この2手筋を同じ難易度として扱った上で依存構造に有意な説明力が確認されているため、初版では恣意的な手筋重みを導入しない。

追加手筋は、実問題・人間確認で `unsupported` が必要以上に多い、または分類精度が不足すると確認された時点で追加する。

### 依存構造の特徴量

各解法手順の直前に、Naked Single / Hidden Single として次に確定できる **異なる `cell + digit` の組数**を数える。

同じ配置が複数の行・列・ブロックや複数手筋の説明で成立しても、実際の次の一手としては1候補として数える。

解法序盤25手について次を記録する。

- `meanAvailablePlacementCount`: 次の一手候補数の平均
- `minimumAvailablePlacementCount`: 最小候補数
- `singleOptionStepCount`: 候補が1つしかなかった手数

初版の分類には `meanAvailablePlacementCount` を用いる。値が小さいほど、解法経路の自由度が低く難しいとみなす。

### 仮分類

`dependency-v1` の初期閾値は、generator version 1 で生成した固定1,000問を校正集合として決めた。

- ヒント数: 40 / 36 / 32 / 28 / 24
- 各200問
- 固定seed: `sudoku-rating-comparison:<clueCount>-<index>`
- Naked Single / Hidden Single で完答: 829問
- `unsupported`: 171問

完答829問の `meanAvailablePlacementCount` の三分位点は次だった。

- 33パーセンタイル: `9.36`
- 67パーセンタイル: `14.60`

この分布を使い、初版では次の仮分類とする。

| 難易度 | 条件 |
| --- | --- |
| easy | `meanAvailablePlacementCount >= 14.60` |
| normal | `9.36 < meanAvailablePlacementCount < 14.60` |
| hard | `meanAvailablePlacementCount <= 9.36` |

校正集合では `easy=274 / normal=279 / hard=276 / unsupported=171` となった。

この閾値は人間難易度の絶対値ではない。人間確認を行うために、生成問題を再現可能な相対グループへ分ける初期校正値である。

### 外部評価器との整合確認

同じ1,000問を Sukaku Explainer v1.18.1 の `serate` でも評価した。

Naked Single / Hidden Single で完答できた829問について、`meanAvailablePlacementCount` を難しい向きに反転した値と `serate ER` の相関は次だった。

- Pearson: `0.623`
- Spearman: `0.706`

逆数 `1 / meanAvailablePlacementCount` と `serate ER` の Pearson 相関は `0.660` だった。

これは `dependency-v1` が人間難易度を確定したことを意味しない。少なくとも既存の論理手筋ベース評価器と無関係な並びにはなっていない、という健全性確認として扱う。

## 問題生成・選別

難易度判定は、一意解が保証された問題に対して適用する。`rateUniqueSudokuDifficulty` 自身は一意解探索を重複実行せず、呼び出し側が一意解を保証する契約とする。現在の generator は候補を返す前に一意解を確認しているため、その後に難易度を評価する。

`generateSudokuProblemForDifficulty` は、難易度ごとに校正集合で成立率の高かったヒント数から候補を生成し、`dependency-v1` が指定難易度と判定した問題だけを受理する。`unsupported` は候補から除外する。

初期の優先ヒント数は次とする。

| 難易度 | 優先ヒント数 |
| --- | --- |
| easy | 40 → 36 → 32 |
| normal | 32 → 36 → 28 → 40 |
| hard | 28 → 24 → 32 |

これはヒント数を難易度そのものとして扱うものではない。目的の難易度を効率よく得るための候補生成順であり、最終判定は常に `dependency-v1` で行う。

## 人間確認

初期モデルの目的は、人間が無作為な問題群を手作業で仕分けることではなく、**比較可能な代表問題を自動的に用意すること**にある。

最初の確認では、各分類の中央付近と境界付近を優先して遊ぶ。

| 用途 | seed | `meanAvailablePlacementCount` |
| --- | --- | ---: |
| easy代表 | `sudoku-rating-comparison:36-71` | 18.00 |
| normal代表 | `sudoku-rating-comparison:32-1` | 12.00 |
| hard代表 | `sudoku-rating-comparison:28-102` | 6.00 |
| easy / normal境界 | `sudoku-rating-comparison:40-23` | 14.60 |
| normal / hard境界 | `sudoku-rating-comparison:40-15` | 9.36 |

確認するのは「このラベルが正しいか」だけではない。

- easy → normal → hard の順で体感難易度が上がるか
- 境界の前後で不自然な逆転がないか
- 同じ分類内のばらつきが大きすぎないか
- Hidden Single の多さなど、依存構造以外に明らかに効く要因があるか
- `unsupported` の中に、実際には簡単に感じる問題が多くないか

違和感があれば、先に特徴量や対応手筋を見直し、その後で閾値を再校正する。人間確認に合うまで閾値だけを動かして帳尻を合わせない。

## 将来の校正

実プレイデータが取得できるようになったら、少なくとも次を保存して再評価する。

- 完答時間
- ミス数
- 待った回数
- 中断・離脱
- 使用したヒント

モデルの変更時は `SUDOKU_DIFFICULTY_MODEL_VERSION` を更新する。特に次の場合は再校正する。

- 対応手筋を追加・変更した
- 解法手順の選択規則を変更した
- 問題生成器の性質が変わった
- 十分な実プレイデータが集まり、人間の体感とのずれを評価できるようになった
