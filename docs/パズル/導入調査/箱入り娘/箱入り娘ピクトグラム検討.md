# 箱入り娘ピクトグラム検討

箱入り娘のゲーム選択ピクトグラムをどう検討したかの記録。探索した着眼点、比べた候補、B（出口から抜け出す娘）を推奨する理由をまとめる。見直すときは、同じ比較をやり直さずに論点から始められる。

この文書は導入調査の資料で、現在仕様の正本ではない。
- 採用したピクトグラムの形: `frontend/src/games/hakoiri-musume/assets/pictogram.svg` を正とする。
- 制作手順と評価方法: `.claude/skills/design-game-pictogram/` を正とする。

記述の区別:
- **事実（リポジトリ）**: コードと文書から確かめたこと。
- **事実（実測）**: 候補 SVG を 112px と 48px で既存ピクトグラムと並べて描き、AI が見た見え方。
- **判断**: 上から導いた推奨と理由。

人間による方向の選択はまだしていない。人間のレビューは全段の実装後にまとめて行うので、AI が推奨案で仮に決めた。最終レビューで選び替えられるよう、代替の候補を `ピクトグラム検討/` に残している。

## 1. 結論

- 推奨は **B（出口から抜け出す娘）**。
  - 4×5 の箱を濃色の枠で描き、下辺の真ん中2マスを出口として開ける。
  - 濃色の娘（2×2 の角丸の四角）が、出口から下へ半分ほど抜け出している。
  - 箱の上側には、淡色の縦長・横長・小駒を残す。
- 推奨の理由:
  - 何をするゲームか（娘を出口から出す）が1枚で読める。
  - 大きさの違う駒が詰まった箱という姿が、プレイ画面の盤面と同じ意味で描ける（濃い大きな娘、淡い木の駒）。
  - 48px でも、枠の切れ目・はみ出した娘・上の駒が見分けられる（事実（実測））。
  - 既存のピクトグラムと構成が重ならない（事実（実測））。パーキングジャムは輪郭線の車と右の出口、スライドパズルは数字の格子。

## 2. 制約（事実（リポジトリ））

- `viewBox="0 0 120 120"`、線幅は 4 と 2 だけ、色は `var(--game-pictogram-strong)` と `var(--game-pictogram-soft)` の2色だけ。`check_svg.py` を通す。
- 盤は 4×5。出口は下辺の真ん中2マス。娘は 2×2 で、プレイ画面では朱漆に「娘」の字（`HakoiriMusumePieceFace.tsx`）。字は `<text>` を使えず、48px では潰れるので描かない。

## 3. 探索した着眼点

- 横刀立馬の初期配置をそのまま描く（A）
- 娘が出口から抜け出す瞬間（B）
- 娘の道を空けるために駒をよける動き（C）
- 娘の真下で出口をふさぐ横長（D）
- 娘の通り道を曲線で描く: 矢印の曲線が駒と重なり、112px でも読みにくかった（事実（実測））ので捨てた
- 「娘」の字を描く: `<text>` が使えず、字形のパスは 48px で潰れるので捨てた
- 箱のふた・木目: 箱の外形と区別が付かず、駒の詰まりが見えなくなるので捨てた

## 4. 候補（`ピクトグラム検討/`）

| 候補 | 方向 | 見え方（事実（実測）） |
|---|---|---|
| `a-横刀立馬.svg` | 有名な初期配置。縦長4・横長1・小駒4・娘を上に | 箱入り娘を知る人には一目で分かる。48px では小駒が細かく、密度が一覧で最も高い |
| **`b-出口の娘.svg`（推奨）** | 出口から抜け出す娘 | ゴールが読める。娘が枠の外へ出る形が一覧の中で目立つ |
| `c-よける.svg` | 横長を矢印でよける | 「動かす」は読めるが、矢印が 48px で小さい |
| `d-ふさぐ横長.svg` | 出口の前の横長が娘をふさぐ | 最も簡潔。詰まった箱らしさは弱い |

## 5. 見直すときの論点

- 結果（抜け出す娘）を描くか、問題（詰まった初期配置）を描くか。A と B の差。
- 駒の密度。A は箱入り娘らしいが重い。D は軽いが汎用の「枠の中の四角」に近い。
- 光学中心: B は娘がはみ出すぶん外形が下へ 4 伸びるが、上の駒の量で釣り合って見えたので補正していない。

## 6. 選択中のピクトグラム（`assets/pictogram-showcase.svg`）

白黒版 B と同じ形のまま、選んでいるときだけ色と動きを入れる（`/design-game-pictogram-showcase`）。色はプレイ画面の欅の駒の中間色 `#c08a47` と、娘の朱漆の中間色 `#a8301f`（`hakoiri-musume-tone.ts`）。どの案も再生形式は `cut` で、開始の間 300ms、娘は出口の前を止まらずに通り、箱の外へ半分抜けたところで止まる（1手の中で途中に間を置かない）。小駒は角で止め切らずに曲がる（曲がっても1手）。

人間による方向の選択はまだしていない。AI が推奨案で仮に決め、残りの案を `ピクトグラム検討/` に置いた。

| 候補 | 見せ場まで | 止まり / 周期 | 見え方（計測（観察スクリプト）と目視） |
|---|---|---|---|
| **`assets/pictogram-showcase.svg`（推奨、c3 順によける）** | 出口の前の小駒2つを、右の駒を右上へ、左の駒を左上へと順によけ、娘が抜ける | 2.01 秒 / 5.0 秒 | 挑戦の核の「どの駒をどこへどの順でよけるか」が読める。2つ目のよけで道が開く |
| `showcase-c1-yokete.svg` | 出口の前の小駒1つが右上へよけ、娘が抜ける | 2.41 秒 / 4.4 秒 | 最も簡潔。よける順は見えない |
| `showcase-c2-magarite.svg` | 小駒が右へ2マス、上へ2マスと曲がって1手でよける | 2.46 秒 / 4.6 秒 | 「何マス・何回曲がっても1手」の操作が読める |

- Safari（WebKit）での表示は確かめていない（この環境で WebKit を起動できなかった）。
