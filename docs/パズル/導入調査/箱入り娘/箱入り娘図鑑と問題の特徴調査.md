# 箱入り娘 調査: 図鑑と問題の特徴

## 結論

- 合意した前提（4×5 の盤、5段階、図鑑はレベルごとに数百問）は、この観点では崩れない。盤面はどの問題も 4×5 なので、盤面の大きさは特徴にしない（どのレベルでも値が1つしかなく、絞り込みに出ない）。
- **採る特徴は「横長」（横長の駒の数）・「小駒」（小駒の数）・「娘の下」（娘の下にある段の数 0〜3）の3つ**（条件つきで成り立つ）。根拠は次の3つ。
  - レベルの中で値が分かれる。下の「仮のレベル」のどれでも、横長は4〜7種類、娘の下は4種類に分かれた。小駒はレベル1〜3 で5〜7種類に分かれる。レベル4 は 2・4・6個の3種類で、4個 の割合は引き方で 47〜95% と変わる。レベル5 では 4個 だけになり（composition では 2個 が 2問混じる）、ほぼ絞り込みに出ない。
  - ほかの特徴と重ならない。3つの組の順位相関は、どのレベル・どの seed・どの引き方でも |ρ| ≤ 0.53 だった。
  - 難易度の写しにならない。レベルの中での最短手数との順位相関は |ρ| ≤ 0.37 だった。最も高いのはレベル1 の娘の下で、0.26〜0.36。
- 採らない案は、重なりか難易度の写しのどちらかに当たった。
  - 空きマス: レベルとの順位相関が −0.90。レベル1・2 の中でも最短手数と −0.44〜−0.61。難易度の写しになる。
  - 駒の数: レベルの中で小駒と ρ = 0.85〜1.00。レベルとの相関は 0.51〜0.67。
  - 長い駒（縦長+横長）: レベル5 では 5本 が 99% 以上。レベルとの相関は最大 0.77。
  - 縦長: 横長と ρ = −0.65〜−1.00。
  - 通り道の駒: 娘の下と ρ = 0.50〜0.89。
  - 空きのかたまり: 重なりも難易度の写しでもないが、駒が1手動くたびに変わる数で、次の1問を選ぶ切り口にならない。
- 値の書き方は「横長 3個」「小駒 4個」「娘の下 3段」を推奨する。今の単位（`ProblemFeatureCountUnit`）に「段」が無いので、足す必要がある（下の「仮決定の候補」）。
- 数をまとめる幅は付けない。どのレベルでも値の種類は最大7で、まとめる閾値（8種類まで）を超えなかった。
- 条件: レベルの分け方と問題の引き方は仮のもので、難易度の観点の結論で変わる。読みの量も仮に最短手数で測った。難易度の観点の結論が出たら、スクリプトの `--reading`（読みの量）と `PROVISIONAL_LEVELS`（レベルの分け方）を差し替えて測り直す。特に、上のレベルで「娘は上から始める」と決めると、娘の下はそのレベルで値が1つになり、絞り込みから消える。

## 事実と推測

- [事実] 図鑑には、始めたときの盤面で分かる特徴を示す。最短手数のように解かないと分からないことは示さない: `docs/プロダクト/仕様/ゲーム/SPEC-026.md`「問題の特徴」。合意でも、最短手数は解いた後に見せる（導入調査 Issue #600 の合意節）。最短手数は特徴にできない。
- [事実] 絞り込みの選択肢が1つしかない軸は出さない。数の値は8種類を超えたときだけ、`rangeWidth` の幅でまとめる: `frontend/src/zukan/zukan-filter.ts`（`MAX_EXACT_COUNT_OPTION_COUNT = 8`、`axes` のコメント）。
- [事実] 数の単位は `個`・`本`・`台`・`マス`・`か所`・`種類`・`手`・`枚` に限られ、`段`・`行` は無い: `frontend/src/components/problem-features.ts`。
- [事実] 前例では、駒・物の種類ごとの数を特徴にしている（パーキングジャムの車と植え込み、ウォーターソートの色と空ボトル、詰将棋の盤上の駒と持駒）。値が0の軸を問題の詳細で出さない前例もある（パーキングジャムの植え込み）: `frontend/src/games/parking-jam/ui/problem-features.ts`、`frontend/src/games/water-sort/ui/problem-features.ts`、`frontend/src/games/tsume-shogi/ui/problem-features.ts`。
- [事実] 項目が難易度の写しや全問に当たるものになると、図鑑の切り口として意味を持たない: `docs/adr/ADR-0004-zukan.md`「背景と問題」。
- [事実] 4×5 の盤で空き2マス・最短76手以上になるのは、小駒4・長い駒5の構成だけだった（例外は 縦2横4小2 の2状態）。上のレベルでは小駒・駒の数・空きマスが1つの値にそろう: 計測（上の表）。
- [推測] 横長は、娘と同じ2列の幅で娘の下をふさぐ駒で、横刀立馬の名前の由来でもある。遊ぶ人には「横長が多い＝娘の道をふさぐ駒が多い」と読める。縦長より横長を採る理由は、ほかに2つある。レベルとの相関が小さい（−0.02〜0.15 と 0.15〜0.46）ことと、レベル1〜3 で値の種類が多いこと。確かめるには、試遊で、横長の数で問題を選ぶかを聞く。
- [推測] 横長と縦長の両方を出すと、レベル4・5 では長い駒の数が5にそろうので、片方を選ぶともう片方が決まる（ρ ≈ −1）。同じ絞り込みが2つの軸に分かれて見える。問題の詳細に縦長を出すかは、絞り込みの軸とは別に決められる（`describePoolProblem` は軸と別）。
- [推測] レベルの中での順位相関が低いことには、最短手数を帯で区切ったことも効いている（範囲の制限）。レベルの中で選ぶ絞り込みでは、この低さがそのまま「同じレベルの中で難しさを選ぶ切り口にならない」ことを示す。確かめるには、難易度の観点の読みの量に差し替えて測り直す。
- [推測] 値の分布は問題の引き方で変わる。composition では小駒・縦長がより平らになった。実際の生成器が特定の構成や「娘が最上段」に寄せると、小駒・娘の下の値の種類が減る。確かめるには、生成器ができたら `PROVISIONAL_LEVELS` と `sample_pool` を生成器の出力に差し替える。

## 仮決定の候補

- 特徴の軸
  - 推奨: 横長・小駒・娘の下の3つを、この順で示す。
  - 理由: 3つとも、レベルの中で値が分かれ（4〜7種類）、互いに重ならず（|ρ| ≤ 0.53）、最短手数の写しにならない（|ρ| ≤ 0.37）。始めの盤面を見ればすぐ数えられる。駒の数で上下させるレベルの作りとも別の軸になる。
  - 比べた案: 駒の数（小駒と重なる。レベルの写しに近い）、空きマス（難易度の写し）、長い駒（上のレベルで値が1つ）、縦長（横長と重なる）、通り道の駒（娘の下と重なり、数えにくい）、出口前の駒・空きのかたまり（重なりも写しもないが、選ぶ切り口として弱い）。
  - 覆したときに作り直す範囲: 問題集の項目から特徴を求める関数・軸の定義・表示の定義と、そのテスト。
- 娘の下の書き方
  - 推奨: 名前は「娘の下」、値は「0段〜3段」。共通の単位 `ProblemFeatureCountUnit` に「段」を足す。
  - 理由: 値は「娘の下に残っている段の数」で、0段 は娘が最下段にいる（出口の横）ことを表す。「マス」では、娘の2列分を数えた 0〜6 と読み違えうる。
  - 比べた案: 「娘の下 3マス」（単位を足さずに済むが、読み違えうる）、「娘の高さ」（何を数えているか伝わりにくい）、「出口まで 0マス」（0 でも横へ1手要るので誤り）。
  - 覆したときに作り直す範囲: 表示の定義、`problem-features.ts` の単位の型（「段」を足した場合）。
- 数をまとめる幅
  - 推奨: 3つとも `rangeWidth` を付けない。
  - 理由: どのレベルでも値の種類は最大7で、閾値の8を超えない。小駒は1個ずつの違いが盤面の印象を変える。
  - 比べた案: 小駒に幅2（生成器が小駒7個以上を使うようになったときの備え）。
  - 覆したときに作り直す範囲: 表示の定義の1行。
- 問題の詳細での見せ方
  - 推奨: 3つとも、値が0でも示す。
  - 理由: 「横長 0個」「娘の下 0段」は盤面の特徴そのもの（横長の無い盤、娘が最下段）で、パーキングジャムの植え込みのように、無いことが当たり前の付け足しではない。
  - 比べた案: 0のときは示さない（パーキングジャムの植え込みの前例）。
  - 覆したときに作り直す範囲: 特徴を整形する関数とそのテスト。

## 確かめていないこと

- 本番の問題集での値の分布: 生成器とレベルの分け方は難易度の観点で決まる。この計測は、仮のレベルと、一様に引いた問題集の結果。
- 最短手数以外の読みの量との相関: 難易度の観点の結論がまだ出ていない。`READING_MEASURES` に関数を足せば `--reading` で差し替えられる。
- 遊ぶ人が横長・小駒・娘の下で次の1問を選ぶか: 人による試遊が要る。計測では、値が分かれ、重ならず、難しさの写しでないことまでしか言えない。
- 縦長+横長が8以上、小駒が7以上の構成: 計測した範囲（99構成）の外。空き2〜6の 4×5 では、これ以上はほとんど解けないか、ごく少ない配置だけと見込むが、測っていない。
- 同じ連結成分から引いた問題どうしの近さ（ある問題が別の問題の解く途中の局面になること）: この観点の問いの外。供給と難易度の観点で扱う。
