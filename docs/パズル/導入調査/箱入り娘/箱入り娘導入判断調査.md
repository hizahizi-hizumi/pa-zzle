# 箱入り娘 調査: 導入判断

## 結論

合意した前提は崩れていない。

- 近いゲームとの違い: **成り立つ**（別のゲームとして作れる）。スライドパズルは同じ形のタイルを決まった並びにそろえるゲーム、パーキングジャムは車を一度で外へ出す順を読むゲーム（手数は評価に使わない）、ブロック脱出は駒が決まった1方向にしか動かないゲームで、どれもルールが違う。箱入り娘は、形の違う駒を上下左右によけて娘1つを出口へ運ぶ。計測では、横刀立馬の最短81手の解（曲がる手がいちばん少ない解）で、10個の駒すべてが縦にも横にも動いた。ブロック脱出の1手の数え方（一直線だけ）にすると、同じ盤の最短が 81 → 90 手に変わる。ブロック脱出（PUZZLE-041）やラッシュアワー（PUZZLE-039）に PUZZLE-040 をまとめる理由はない。
- 表示名「箱入り娘」: **条件つきで成り立つ**。この種のパズルの日本での昔からの呼び名で、アプリの中のほかの名前（スライドパズル・パーキングジャム・ブロック脱出）とも重ならない。ただし商標の登録があるかどうかは、この調査では確かめていない（データベースを検索していない）。公開前に J-PlatPat で人間が称呼検索をすることを条件にする（前例: パーキングジャム・スライドパズル・アイスフロア迷路）。「Klotski」は表示名に使わない。
- 台帳の値: 案は `箱入り娘 / 問題供給 通過/ 難易度運用 確認中 / スマホプレイ 確認中 / 導入判断 条件付き保留`。名称の欄は「Klotski / 箱入り娘」から「箱入り娘」に変える。候補ファイルは [PUZZLE-040.md](../../../棚上げ/パズル候補/PUZZLE-040.md)。

## 計測

| 問い | 条件 | 結果 | スクリプト |
|---|---|---|---|
| 手数の数え方で最短がどれだけ変わるか（ブロック脱出・スライドパズルの数え方と比べる） | 4×5。同じ形の駒は区別しない。娘の左上が行3・列1でクリア。BFS で全探索（打ち切りなし）。乱数は使わない | 横刀立馬: 合意の数え方（同じ駒の連続移動を1手。曲がってもよい）81手、一直線を1手（ブロック脱出の数え方）90手、1マスを1手 116手。易しい例: 13 / 15 / 22手 | `scripts/research/hakoiri_musume_decision.py` |
| 最短の解で駒が縦と横の両方に動くか（ブロック脱出は1方向だけ） | 合意の数え方で最短の解のうち、曲がる手（一直線では届かない手）がいちばん少ない解を1つ選ぶ。駒は初めの盤の文字で区別して追う | 横刀立馬: 81手のうち曲がる手は最少で9手。娘1・横長1・縦長4・小駒4のすべてが縦にも横にも動いた。易しい例: 13手のうち曲がる手は2手。動いた7個のうち4個が縦にも横にも動いた | 同上 |
| 戻れない手（詰み）があるか | 初めの盤を含む連結成分の全ての辺で、逆向きの1手があるかを調べた | 両方の盤で全ての手が1手で戻せる（辺が対称）。連結成分の状態数は、横刀立馬 25,955（うちクリア状態 964）、易しい例 65,688（同 6,795） | 同上 |
| 計算の重さ | Python 3、1スレッド | 1盤あたり 9〜12秒（連結成分の列挙、3つの数え方の BFS、解の選び直しを含む） | 同上 |

限界: 調べた盤は2つ（合意の易しい例と横刀立馬）だけ。曲がる手の数と駒の動き方は、最短の解のうち1つを選んだ結果で、ほかの最短の解では違う値になりうる（曲がる手の数は最短の解全体の最小値）。

## 事実と推測

### 近いゲームとの違い

| | スライドパズル（SPEC-011） | パーキングジャム（SPEC-018） | ブロック脱出（PUZZLE-041、候補） | 箱入り娘（合意） |
|---|---|---|---|---|
| 盤 | 3×3〜5×5。盤の大きさがレベルの要因 | 格子の大きさは変わる。植え込みあり | 6×6、固定壁なし | 4×5 だけ |
| 駒 | 同じ大きさの番号つきタイル | 長さ2か3の車 | 長さ2か3の棒。目標のブロック1つ | 娘 2×2・縦長 1×2・横長 2×1・小駒 1×1 |
| 動き | 空白と同じ行・列のタイルが1マスずつ滑る | 向きに沿って一度で盤の外へ出る。途中で止まらない | 向きの軸の上だけを滑る | 上下左右どこへでも。なぞりながら角も曲がれる |
| 1手 | 動いたタイル1枚 | 手数を数えない | 1つのブロックを一直線に何マスでも | 同じ駒の連続した移動（何マス・何回曲がっても） |
| クリア | 全部のタイルが決まった並びになる | 全部の車が出る | 目標のブロックが出口に着く | 娘が出口の前に着く。ほかの駒の並びは問わない |
| 戻れない手 | なし | どの順でも詰まない | なし（手は全部戻せる） | なし（計測。全ての手が戻せる） |
| 考えどころ | 揃えた部分を崩さずにタイルを退避・送り込む順 | どの車を先に出せば道が開くかをさかのぼって読む | 目標の通り道をふさぐ棒を、どの順で軸の上へよけるか | 娘の通り道を作るために、どの駒をどこへどの順でよけるか。形が違う駒どうしの入れ替え |
| 評価 | 効率60（手数と最短の比較）・速さ40 | 正確さ40・速さ40・安定性20。手数は使わない | 未定（候補） | 手数の少なさが中心、速さも見る（合意） |

- パーキングジャム: 事実。`docs/プロダクト/仕様/パズル/SPEC-018.md`
- ブロック脱出: 事実。`docs/パズル/導入調査/ブロック脱出/ブロック脱出調査.md`「採用候補の基礎仕様」「1手の定義」。まだ実装されていない（`frontend/src/games/` に無い）
- 箱入り娘: 合意（導入調査 Issue #600 の合意節、認識合わせのページ「似ているゲームとの違い」）と上の計測
- 手が全部戻せるので、問題が正しく作られていれば、プレイの途中で解けなくなることはない。ウォーターソート（SPEC-009 の手詰まりの知らせ）やアイスフロア迷路（詰み）と違い、詰みの知らせは要らない（推測。計測した2盤では全ての手が戻せた。ルール上、どの手も逆向きの1手で戻せるので一般に成り立つと考える。rules の性質テストで確かめられる）
- スライドパズルの導入前提調査は、箱入り娘・ラッシュアワー・ブロック脱出を入れるときに名前が近くなることを心配し、「固有の名前で区別できる見込み」と書いている（事実。`docs/パズル/導入調査/スライドパズル/スライドパズル導入前提調査.md` §13）。「箱入り娘」はこの見込みに合う
- 一次調査は、Klotski / 箱入り娘 を「状態探索」で自動生成できる（○）とし、市場の代表例に Google Play の `com.momokka.hakoiri`（1万+）と日本の App Store の id6502583899（2評価）を挙げている。どちらも、パーキングジャム（1億+）やウォーターソートより市場の実績はずっと小さい（事実。`docs/パズル/導入調査/全体/パズル調査.md` 138行・925行）。合意で入れると決まっているので導入は止めないが、ゲーム一覧で目を引くかは市場の実績からは言えない（推測）
- 台帳の決まり: `導入判断` は `未判断 / 実装候補 / 条件付き保留 / 見送り / 正式採用`。成立性調査での実装候補化と、プロダクトへの正式採用を分ける（事実。`docs/棚上げ/README.md`）。spec の層で導入判断を正式採用にし、マージで決まる（事実。`/add-puzzle` の `references/build-order.md` の spec 行）

- 台帳の名称の欄は表示名にそろえた前例がある（事実。PUZZLE-094 は「アイスフロア迷路」、PUZZLE-032 は「スライドパズル」）

### 表示名

- 表示名は `display-name.ts` の1か所から出し、ゲーム ID・ディレクトリ・ルートとは分けて扱う（事実。`frontend/src/games/*/display-name.ts`）。そのため表示名を後で変えても、ゲーム ID `hakoiri-musume` は変えなくてよい（前例: パーキングジャム名称調査 §4.3、アイスフロア迷路の作業名と表示名）
- ゲーム ID を表示名のローマ字にした前例がある（事実。`nanpure`、`hitofude-puzzle`、`tsume-shogi`）
- 前例は、商標と考えられる名前を利用者に見える名前にしない（タクズ → バイナリパズル、Flow Free / ナンバーリンクを避けた経路接続）。一般名とみた名前は、登録が見つからなかったことと、公開前に称呼検索をすることを書いている（事実。`docs/パズル/導入調査/パーキングジャム/パーキングジャム名称調査.md` §0）
- 「箱入り娘」は、このスライディングブロックパズルの日本での昔からの呼び名で、木製の玩具やアプリの名前として多くの作り手が使っている（一般的な知識。原典と使用例の全文は確かめていない。リポジトリでは一次調査が `com.momokka.hakoiri` を代表例に挙げている）
- 「Klotski」は、ポーランド語で積み木を表す語から来た呼び名で、1990年代の Windows 用ゲームの題名にも使われた（一般的な知識。題名・提供元・商標の登録は確かめていない）。表示名にすると、日本の遊ぶ人にはなじみがなく、特定の製品の名前と結びつくおそれもある（推測）
- 「華容道」（中国での呼び名）、「横刀立馬」（その代表の初めの並びの名前）、「L'Âne rouge」（フランスでの呼び名）も知られている（一般的な知識。確かめていない）。「横刀立馬」は問題の名前としてだけ使える（推測）
- 「箱入り娘」の伝統的な駒には、父・母・番頭などの家の人の名前を付けたものがある（一般的な知識。確かめていない）。合意は駒を形の名前（娘・縦長・横長・小駒）で呼んでいるので、伝統的な役の名前は画面に出さない（推測。合意に沿う）
- 商標の登録: 「箱入り娘」「はこいり娘」「Klotski」「華容道」とも、この調査では J-PlatPat・USPTO・EUIPO・WIPO を検索していない。登録があるかどうかは分からない。一般的な知識の範囲では、第9類（ゲームのソフトウェア）・第28類（玩具・パズル）・第41類（オンラインゲームの提供）で「箱入り娘」が登録されているという話は知らないが、無いとは言えない。「箱入り娘」は日常の言葉でもあるので、菓子・酒など別の区分で登録があることはありうる（推測）。区分の違う登録はこのアプリの使い方とは関係が薄いと考えるが、判断は人間の確認に任せる

## 仮決定の候補

- 表示名: 推奨「箱入り娘」（ゲーム ID `hakoiri-musume`）/ 理由: (1) 日本で昔から使われるこのパズルの呼び名で、遊ぶ人が名前からルールの見当をつけられる。(2) アプリの「スライドパズル」・候補の「ブロック脱出」と言葉が重ならず、ゲーム一覧で見分けやすい（スライドパズル導入前提調査 §13 の心配に合う）。(3) 目標の駒「娘」と出口という題材が名前に入り、盤面の姿と音の題材（箱の中の木の駒）にもつながる / 比べた案: 「Klotski」（なじみが薄い。製品名と結びつくおそれ）、「華容道」（日本ではなじみが薄い）、「スライドブロック」などの説明的な名前（スライドパズル・ブロック脱出と見分けにくい） / 覆したときに作り直す範囲: `display-name.ts` の1行と、表示名を書いた仕様・遊び方・調査の文書。ゲーム ID・ルート・記録はそのまま
- 名前の確かめ方: 推奨は「公開前に人間が J-PlatPat で『箱入り娘』『はこいり娘』『ハコイリムスメ』を称呼検索し、第9類・第28類・第41類に同じか似た登録がないかを見る」/ 理由: この環境では原典を確かめていない。前例（パーキングジャム・スライドパズル・アイスフロア迷路）と同じ扱い / 比べた案: 調査で確かめたことにする（できない）、名前を一般的な説明の名前に変える（理由が無い）/ 覆したときに作り直す範囲: 登録が見つかったら、表示名だけを変える。代わりの名前の案は「箱入りパズル」（読みが近く、同じ登録に似ていると見られるおそれがある）か「娘出しパズル」（説明的。ほかと重ならない）。どちらにするかは人間が決める
- 台帳の名称: 推奨「箱入り娘」/ 理由: 前例は表示名にそろえる（PUZZLE-094・PUZZLE-032）。「Klotski」を台帳に残すと、使わない名前が残る / 比べた案: 「Klotski / 箱入り娘」のまま（一次調査とのつながりは残るが、表示名とずれる）/ 覆したときに作り直す範囲: CSV の1セル
- 台帳の値: 推奨 `問題供給 通過 / 難易度運用 確認中 / スマホプレイ 確認中 / 導入判断 条件付き保留` / 理由: (1) 問題供給は、4×5 の連結成分を全部たどれる（計測。1盤 10秒前後、2万〜7万状態）ので通過の見込み。件数は問題供給の観点の結果で決め、目安の数百問がそろわないときだけ「確認中」にする。(2) 難易度運用は、合意の「まだ分からないこと」に「4×5 だけで5段階を分けられるか」があり、ラベルを伏せた試遊が要るので確認中。(3) スマホプレイは、なぞって曲がる操作と iPhone での画面の動きを play-ui で測るまでは確認中（合意の「まだ分からないこと」）。(4) 導入判断は、難易度運用が確認中の候補を `実装候補` にしない前例（PUZZLE-078 ほか）に合わせ、`条件付き保留` にする。spec の層のマージで `正式採用` に変える / 比べた案: `実装候補`（研究段で全ゲートを通ったと読めてしまう。まだ2つが確認中）、スマホプレイを `通過`（ブロック脱出は実ブラウザの試作で通過にしたが、今回はまだ試作がない）/ 覆したときに作り直す範囲: CSV の1行と候補ファイルの各節。play-ui で実ブラウザの確認が済めばスマホプレイを `通過` に、試遊で5段階が分かれれば難易度運用を `通過` に上げる
- 1手の数え方（合意済み。覆したときの範囲だけ書く）: 合意の数え方（同じ駒の連続移動を1手、曲がってもよい）のまま。スマホ操作の観点で、なぞって曲がる操作が成り立たないと分かり一直線だけにすると、最短手数が変わる（横刀立馬 81 → 90、易しい例 13 → 15。計測）。そのときは最短手数・難易度の帯・問題集・評価の基準を全部作り直す
- やり直しの呼び名: 合意の「1手戻す」「最初から」は、アプリの呼び名の「待った」「盤面を戻す」（`frontend/src/games/play-vocabulary.ts`）に当てる / 理由: 呼び名はメニュー・結果・採点・記録で同じ語を使う決まり / 比べた案: 合意の言い方をそのまま画面に出す（ほかのゲームと語がずれる）/ 覆したときに作り直す範囲: 文言だけ。なお、合意の「スライドパズルとそろえる」は、スライドパズルには待ったが無い（SPEC-011「待ったは提供しない」）ので、そろうのは盤面を戻すときに手数を減らさないことだけになる。待ったで戻した手をどう数えるかは、待ったも手数の比較もあるウォーターソート（SPEC-009: 効率は待ったで取り消した後の手数で比べ、取り消した手は正確性で減点）と、なぞり1回をまとめて取り消す一筆パズル（SPEC-020）が近い前例になる。決めるのはスコアの項目

## 確かめていないこと

- 商標の登録（「箱入り娘」「はこいり娘」「Klotski」「華容道」）: この調査では商標のデータベースもウェブも検索していない（観点カードの範囲は手元の資料と一般的な知識）。公開前の人間の確認に残す
- 一般的な知識として書いたこと（「箱入り娘」が昔からの呼び名であること、「Klotski」の由来と Windows 用ゲームの題名、伝統的な駒の名前、ほかの国の呼び名）: 原典を開いていない
- 一次調査が挙げた市場の代表例2つの題名と中身: リポジトリの表にある id だけを見た。ストアのページは開いていない
- 合意の易しい例・横刀立馬以外の盤での、曲がる手の割合と駒の動き方: 2盤だけを測った。レベルごとの値は難易度・問題供給の観点の問題集で測れる
- 台帳の値は、ほかの観点の結果を受けて実装前提調査の「成立性」でまとめた
