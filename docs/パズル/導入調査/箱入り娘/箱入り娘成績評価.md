# 箱入り娘成績評価

箱入り娘の1プレイを100点満点で評価し、評価段階（`perfect` / `great` / `good` / `clear`）と自己ベストの比較へつなげるための検討記録。

この文書は資料で、正本ではない。
- 評価規則（称えるもの・配点・基準時間に使う量・待ったと盤面を戻すの扱い）は、[SPEC-028](../../../プロダクト/仕様/パズル/SPEC-028.md) の「評価」へ移した。
- 係数は SPEC に書かず、コード（`frontend/src/games/hakoiri-musume/score.ts`）を正とする。代表の値は `score.test.ts` で固定する。

根拠の見出し語: **計測（問題集）**（問題集 2,300 問の特徴から計算した。一時スクリプト）、**導出**、**推測**（係数・参照モデル・プレイヤー像はすべてここ）。**実プレイでは何も確かめていない。**

## 1. 前提として守ること

| 出どころ | 内容 |
|---|---|
| 合意 | 点数は手数の少なさが中心で、速さも見る。最短の手数は解いた後に見せる。「1手戻す」「最初から」で手数は減らさない |
| `SPEC-006` | 難易度は問題の性質、成績は起きた事実、評価は事実の意味として分ける。100点で `perfect`、90以上 `great`、80以上 `good` |
| 失敗パターン集（スコア・結果） | 事実の表から始める。二重減点にしない。基準時間はレベルではなく問題の作業の量から。評価値は保存しない |

## 2. 良いプレイ

> よける駒と順を先に読み、最短の手数で娘を出口へ運ぶこと。速く読めればなお良い。

- 1手は「どの駒をどこへよけるか」の判断で、読まずに動かした手（試し）はそのまま手数に表れる。
- 待ったで戻しても、取り消した手は手数に残る。待ったを使った総当たりでは手数の点が上がらない。

## 3. 事実の表

| 事実 | 意味 | 扱い | 理由 |
|---|---|---|---|
| 指した手の数 `moveCount` | 同じ駒の連続移動を1手。待ったで取り消した手と盤面を戻す前の手も含む | **使う**（効率） | 読みの確かさが最も直接に出る |
| 経過時間 `elapsedMs` | 開始からクリアまで。盤面を戻しても引き継ぐ | **使う**（速さ） | 合意の「速さも見る」 |
| 待った `undoCount` | 待ったの回数 | 記録だけ（内訳に出す） | 取り消した手は手数に、かかった時間は経過時間に入っている。別に減点すると二重減点 |
| 盤面を戻す `restartCount` | 始めの盤面に戻した回数 | 記録だけ | 同上 |
| 最短手数 `optimalMoveCount`（問題の量） | 問題集が持つ | **使う**（効率の基準・基準時間） | 作業の量 |
| 準備の長さ `preparationLength`（問題の量） | 問題集が持つ（難易度の分析と同じ量） | **使う**（基準時間） | 娘を進められないあいだに読む量。最短手数が同じでも、読む時間が違う |
| 娘の遠回り・空き・初手の数 | 難易度の分析の量 | 使わない | 読む時間への効き方を測れていない。準備の長さと強く相関する（順位相関 0.87） |
| 駒を動かした回数（1マスごと）・なぞりの長さ | 操作の量 | 使わない | 1手の中の動きは操作の手間で、読みの出来ではない |

## 4. 評価式

| 観点 | 満点 | 規則 |
|---|---:|---|
| 効率 | 70 | 手数が最短以下で満点。それより多ければ `70 × (最短 + 5) ÷ (手数 + 5)`。最短の2倍に5手足した手数で35点 |
| 速さ | 30 | 基準時間以内で満点。超過に応じて線形に減らし、基準時間の2倍で0点 |

```
基準時間 = 10秒 + 2.5秒 × 最短手数 + 2.5秒 × 準備の長さ
```

この式から言えること（導出。`score.test.ts` で固定）:
- `perfect` は、最短手数で基準時間以内にクリアしたときだけ。
- 待った・盤面を戻すを使っても、同じ手数と時間なら同じ点。
- 素朴な解き方（試して進む）は、最短の3倍以内に解けることがほぼ無く（難易度の資料 §8）、3倍の手数での効率は 70 × (最短+5) ÷ (3 × 最短 + 5) で 30点前後。`clear` を超えない。

## 5. 基準時間

### 5.1 案の比較（計測（問題集）、一時スクリプト）

1問ずつ所要時間を見積もる参照モデルを置いた（推測）: 盤面を見る 8秒 + 1.5秒 × 最短手数（操作）+ 3秒 × 準備の長さ（娘を進められないあいだの読み）。見たいのは絶対値ではなく、同じ腕前の人がどのレベルでも同じくらいの速さの点を取れるか。

| 案 | 式（秒） | 基準時間 ÷ 参照モデル（中央値、L1〜L5） | 参照モデルの1.3倍で解く人の速さの点（中央値） |
|---|---|---|---|
| T1（前の版） | 15 + 4 × 最短 | 1.60 / 1.19 / 1.12 / 0.98 / 0.96 | 30 / 27.3 / 25.2 / 20.3 / 19.4 |
| T3 | 10 + 2 × 最短 + 3 × 準備 | 1.20 / 1.15 / 1.14 / 1.12 / 1.12 | 27.5 / 26.1 / 25.8 / 25.3 / 25.2 |
| **T6（採用）** | **10 + 2.5 × 最短 + 2.5 × 準備** | 1.29 / 1.19 / 1.17 / 1.13 / 1.12 | 29.8 / 27.1 / 26.6 / 25.4 / 25.3 |
| T5 | 10 + 3 × 最短 + 1 × 準備 | 1.28 / 1.05 / 1.01 / 0.93 / 0.92 | 29.4 / 22.9 / 21.4 / 18.0 / 17.6 |

参照モデルの係数を変えた4通り（操作 1〜2秒・読み 2〜4秒、読みを準備の長さの2乗で増やす形）でも比べた。レベルごとの中央値の比の幅は次のとおりで、どれでも 1.0 を下回るレベルがほとんど無い。
- T3: 0.99〜1.32
- T6: 0.99〜1.42
- T1: 0.85〜1.78

- T1 を採らない: L4・L5 で基準時間が参照モデルを下回り、同じ腕前の人の速さの点が L5 で 19 点に下がる。「高いレベルを選んだだけで点が下がる」規則になる。
- T6 を採る（T3 と僅差）:
  - T3 は準備の長さの項が基準時間の過半を占める（L4・L5 の中央値で 54〜56%）。準備の長さは解法器が数えた量で、1つの項に寄せすぎると、その量の誤差がそのまま点に出る（失敗パターン「解法器の回数をそのまま時間にする」）。
  - T6 では準備の項は 22〜46%。
  - 同じ腕前の人の速さの点は L2〜L5 で 25〜27 点にそろう。L1 は 30 点近くで甘いが、短い問題は効率（1手の超過が大きく響く）で差がつく。
- 注意: 参照モデルは「準備の長さが長いほど読みに時間がかかる」と仮定しており、T6 がよく合うのはその仮定のもとでの確かめにすぎない。

## 6. 遊び直し（覚えた解をなぞる2回目）

計算（推測。1回目は参照モデルの1.3倍の時間で、最短の3割増しの手数。2回目は覚えた最短解を1手1.5秒＋5秒でなぞる）:

| 問題 | 1回目 | 2回目 |
|---|---|---|
| L3 の代表 `46r0lts5q8`（24 / 18、基準 115秒） | 31手・127秒 → 効率 56 + 速さ 27 = 83（`good`） | 24手・41秒 → 100（`perfect`） |
| L5 の代表 `mp32vtpf0j`（36 / 34、基準 185秒） | 47手・213秒 → 効率 55 + 速さ 25 = 80（`good`） | 36手・59秒 → 100（`perfect`） |

扱い（仮決定）: 2回目の `perfect` をそのまま認める。
- このゲームの挑戦は「よける順を読むこと」で、読み切った解をなぞれることも、その問題を解き切った結果と見る。
- 記録だけからは「覚えてなぞった」と「初めて読み切った」を分けられない。
- 図鑑の出来は最高の記録で見せるので、遊び直すと出来が上がる。

最終レビューの遊び直しのカードで、人がこれを納得するかを確かめる。別案は次のとおり。
- 同じ問題の2回目以降を自己ベストに入れない。
- 2回目以降の速さを0点にする。

どちらも共通の記録の仕組みに手を入れる。

## 7. 記録と自己ベスト

- 記録には事実だけを保存する。保存するのは、経過時間・手数・待った・盤面を戻すの回数と、問題の作業の量（最短手数・準備の長さ）。評価値・基準時間・基準との差は保存せず、今の規則で導く（`play-record.ts`）。
- 準備の長さも記録に残すので、問題集から外れた記録でも基準時間を求め直せる。
- 自己ベストはレベルごと（SPEC-002 の比較単位）に、点・基準時間との差・最短との手数の差で比べる。
- 結果画面と記録画面の比べる値（点・基準時間との差・手数の差）は、`createHakoiriMusumeResult` と `play-record.ts` の指標が同じ `score.ts` の関数から求める。

## 8. 抜け道（確かめたこと）

- 待った・盤面を戻す: 手数も時間も減らない（導出、`session.test.ts`）。
- 「…」メニューのリセット: 手数と時間が0に戻る。試してからリセットすると、減点の事実が消える（山場2の AI の試遊）。共通のプレイ画面の決まりで、最終レビューで人間に聞く（作業カード 05 の「直さないもの」）。
