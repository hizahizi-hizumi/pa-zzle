# 箱入り娘 調査: 問題供給

## 結論

- **件数（レベルごとの「もう1問」）: 条件つきで成り立つ。** レベル1〜4は各500問、レベル5は300問を推奨する。前例の問題集は1レベル200〜1000問で、最上位を300問に絞った前例もある（氷の床迷路・リフレクション）。「もう1問」を押したときは問題集から seed で引き、直前の1問だけを避ける（`frontend/src/games/problem-selection.ts`）。この引き方で、レベル5の1問（最短70〜95手）を遊ぶ人が300問を使い切ることはまず無いと推測する。体感では確かめていない。
- **そろえられるか: 成り立つ。** 4×5 の盤の状態は、駒の組ごとに出口から多始点 BFS で全部たどれた（空き2〜5の全組で、1組あたり最大 83万状態・55秒。計測表の空き4の行）。仮の5段階に 500/500/500/500/300 問を採ると、どのレベルでも採れる数のほうが多い。採る数の上限は1組500問として数えた。そのうえでも、レベル1は 9,315、レベル4は 1,739、レベル5は 760 問を採れた。
  - 条件: レベル5（最短71手以上）が採れる駒の組は、空き2の6組と空き3の2組しかない。出口に着ける連結成分も、71〜100手・71〜90手のどちらでも9個（空き2・3の合計。空き2だけなら7個）しかない。同じ連結成分の問題どうしは、解く道の後半が重なりやすい。そこで、同じレベルの中では、互いに6手以内で行き来できる2問を採らない条件を付けて数えた（「仮決定の候補」）。
- **左右反転: 同じ問題とみなす案を推奨する。** 反転を別の問題とみなすと、状態の数は約2倍、近い問題を除いて採れる数は約1.4〜1.7倍になる。一方で、1レベル500問の中に鏡写しの組が3〜8組入った。
- **問題集の大きさ: 成り立つ。** 1問を盤面の20文字と最短手数で表すと、2,300問で JSON 64,313 bytes（gzip 15,077 bytes）になった。2,500問では 69,921 bytes（gzip 16,137 bytes）。今ある問題集（29〜376 KB）の範囲に収まる。
- **生成時間: 成り立つ。** 問題集1つ（空き2〜4の駒の組を全部たどる）を、Python・1プロセスで約5分（実時間 309〜323秒、CPU 3分半）で作れた。測ったときは別の調査プロセスも同時に動いていた。
- 合意の「まだ分からないこと」（4×5 だけで5段階を分けられるか）は、供給の面からは妨げが無い。娘を上の真ん中から始める形に限っても、空き4〜5の盤なら最短8〜15手の問題が 98,182 / 209,327 問（反転を同一視）ある。最短71手以上は空き2・3でしか作れない。

## 事実と推測

- [事実] 今ある問題集の件数は1レベル200〜1000問。スライドパズル各200、ナンプレ各300、ひとふで・タクズ各500、氷の床迷路 500/500/300/300/300、リフレクション 500/500/500/300/300、詰将棋 500/1000/1000/1000/500、マインスイーパー・パーキングジャム・ウォーターソート各1000。大きさは JSON で 29〜376 KB: `frontend/src/games/*/problem/problem-pool.json`
- [事実] 遊ぶ問題は、問題集から seed のハッシュで1問を引く。直前の1問は避けて選び直す（上限8回）: `frontend/src/games/problem-selection.ts`
- [事実] 図鑑は問題集の全問を枠にする。番号は難易度の昇順、各難易度の中は問題集の並びで付ける。問題の特徴として示すのは始めたときの盤面で分かることだけで、最短手数は示さない: `docs/プロダクト/仕様/ゲーム/SPEC-026.md`
- [事実] 既存の問題集の並びは、生成条件を巡回した順で、最短手数の順にはしていない（スライドパズルのレベル5の先頭30問の最短手数は 44, 50, 58, 50, 46, …）。生成条件は巡回して採り、1つの条件に張り付かせない: `frontend/src/games/slide-puzzle/problem/problem-pool.json`、`.claude/skills/design-game-difficulty/SKILL.md` の流れ 4
- [事実] 問題集の件数と並びは遊ぶ人に見える。公開後に変えるには人間の判断が要る: `.claude/skills/design-game-difficulty/SKILL.md` の守ること 8
- [事実] 最上位の天井は横刀立馬くらい（80手前後）で合意している。4×5 には最短138手まであるので、供給は天井を縛らない: `導入調査 Issue #600 の合意節`、計測
- [事実] 計測用の pool は、確かめやすいように各レベルを最短手数の順に並べて出力した。推奨する並び（下の「仮決定の候補」）とは違う。
- [推測] レベル5の1問はスマホで10分以上かかる。300問を遊び切る人はまずいないので、件数を500にしても「もう1問」の体感は変わらない。それより、近い問題を除く幅（radius）を広くとって中身の違いを確保するほうが効く。プレイ記録（最上位の平均時間）と試遊で確かめられる。
- [推測] 同じ連結成分の問題は終盤の道が同じになりやすく、人には「また同じ問題」に見えるおそれがある。レベル5の候補（71手以上）は9成分に集まる（空き2・3の合計）。radius 6 で除いても、ある程度の重なりは残る。試遊で、同じ駒の組のレベル5を続けて数問遊べば確かめられる。
- [推測] TypeScript に移した生成器は、Python より速い見込み。今の5分でも、問題集を作るのは1回きりなので支障はない。

## 仮決定の候補

- 件数: [推奨] L1〜L4 各500問、L5 300問（計2,300問） / 理由: 前例の範囲に入り、最上位を絞った前例（氷の床迷路・リフレクション）とそろう。L5 は radius 6 でも採れる数が 760（seed 2 で 763）あり、2.5倍の余裕がある。L5 は1問が長く、遊び切られない / 比べた案: 全レベル500（radius 3 なら L5 も満たすが、互いに4手で行き来できる問題まで入る。radius 6 では採れる数 760 に対して500問になり、余裕が薄い）、全レベル300（L1〜L2 では引き直しで同じ問題が早く出る） / 覆したときに作り直す範囲: 問題集の JSON と、図鑑の枠と番号。公開後なら守ること 8 で人間に渡す
- 左右反転: [推奨] 同じ問題とみなし、問題集には代表の1つだけを入れる / 理由: 別にすると、同じレベルに鏡写しの組が3〜8組入る。図鑑で2枠を埋める結果が、実質1問を2回解くことになる。反転を除いても数は足りる / 比べた案: 別の問題とみなす（採れる数が約1.4〜1.7倍に増える） / 覆したときに作り直す範囲: 生成の重複判定と問題集の JSON
- 近い問題の除き方: [推奨] 同じレベルの中で、互いに6手以内で行き来できる2問を採らない（左右反転も含めて判定する） / 理由: 「ある問題を数手進めると別の問題になる」組を除ける。L5 でも件数の2.5倍の候補が残る / 比べた案: radius 3（L5 の候補 1,177）、radius 10（L5 の71〜100手で候補 440。300問は採れるが余裕が薄い）、除かない（同じ成分から隣り合う状態が並ぶ） / 覆したときに作り直す範囲: 問題集の JSON
- 並び: [推奨] 駒の組（生成条件）を seed 順に巡回した順に並べ、最短手数の順にはしない / 理由: 既存の問題集とそろう。最短手数は図鑑で解く前に示さない特徴なので、番号の順で手数の長短が透けないようにする / 比べた案: 最短手数の昇順（図鑑の番号が難しさの順になり、解かないと分からない情報が漏れる） / 覆したときに作り直す範囲: 問題集の JSON と、図鑑の番号
- 1問の表し方: [推奨] 盤面の20文字（娘・縦長の上・下・横長の左・右・小駒・空きの7種の文字）と最短手数 / 理由: 2,300問で 64 KB・gzip 15 KB と前例より小さい。生成器の版から復元する必要が無く、盤面がそのまま問題の同一性になる / 比べた案: seed と生成条件だけを持ち、遊ぶときに復元する（スライドパズル方式。小さいが、4×5 を遊ぶときに全部たどる処理が要る） / 覆したときに作り直す範囲: 問題集の読み込みと問題 ID
- 仮の5段階の帯（L1 8〜15手・空き3〜4 など）は、供給を測るための比較の条件で、レベルの境目ではない。境目は難易度の観点で決める。

## 確かめていないこと

- レベルをまたいだ近さ: radius はレベルの中でしか見ていない。L3 の問題が L5 の問題の解く道の途中の盤面になっている組が、どれだけあるかは数えていない。数えるには、問題集の全問の組について連結成分の中の距離を求める処理を足す必要がある。
- 同じ連結成分の問題が人に同じに見えるか: 計測では分からない。試遊で確かめる。
- 空き6以上の駒の組: 2組（最長11手・13手）を測ったところで止めた。空き5までで最長26手、空き6の2組でも13手以下だったので、易しいレベルを作るのに要らないと判断した（推測）。
- 生成時間の値は、別の調査プロセス（図鑑の観点）と同時に動かして測った。単独で動かしたときの値ではない。TypeScript に移したときの時間も測っていない。
- 難易度の観点が帯を決めた後の件数: 帯の境目が変われば、採れる数は上の帯ごとの表から読み直す必要がある。特に L5 の下限を71手より上げると、候補はさらに少ない駒の組に偏る。
