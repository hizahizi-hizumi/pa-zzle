## 2. 目的と制約

### 2.1 目的

ゲーム一覧で15パズルを素早く見分けられ、スライドパズルの姿を保ち、既存のピクトグラムと並べても強さが突出しないこと（`DESIGN.md`「ゲームピクトグラム」、`references/method.md` §1）。

### 2.2 制約（事実（リポジトリ））

- 共通描画契約: `viewBox="0 0 120 120"`、線幅は 4 と 2 だけ、色は `var(--game-pictogram-strong)` と `var(--game-pictogram-soft)` の2色だけ。`check_svg.py --max-colors 2 --forbid-gradients --forbid-filters --forbid-external-images --forbid-text` を通す（`SKILL.md`）。
- 色はライトとダークで `GamePictogram` が前景色と補助情報色から与え、結果画面では `currentColor` から与える。どのテーマでも読める形にする。
- 実表示サイズ: ゲーム選択のヒーロー 177px（PC）/ 138px（スマホ）、一覧のカード 60px（PC）/ 50px（スマホ）、結果画面 48px。一覧の 50〜60px が最も厳しい。
- 比べる既存ピクトグラム: ウォーターソート、ナンプレ、マインスイーパー（マインスイーパーは別ブランチで導入中のもの）。ナンプレは「外枠＋格子線＋数字」、マインスイーパーは「外枠＋淡い四角＋数字＋旗」で、15パズルは格子と数字の点で両方に近い。

### 2.3 人間の方向指示

検討の途中で人間が出した方向の指示（人間の指示）。

- 3×3 の盤も試す。
- 角丸を控える（タイルは角なし、外枠はナンプレ・マインスイーパーと同じ rx=2）。
- 数字は `<text>` ではなくパスにする。
- 動くタイルを濃色のベタ塗りにしない（§3.4）。

書体は、3×3 の6案（§3.2）から AI がナンプレ・マインスイーパーと同じ Noto Sans Mono 600 にそろえた（初回案は Noto Sans Bold）。

## 3. 検討の経緯

| 段階 | 振ったこと | 次へ持ち越したもの |
| --- | --- | --- |
| 初回案（A/B/B2/C） | 盤全体・右下2×2の拡大・主役タイルなどの方向 | AI が B（2×2「11・12・15」）を仮採用 |
| 3×3 の6案 | 3×3 で、数字の有無・塗りと輪郭・動きの向き | 3×3 の読みやすさと、ナンプレ・テンキーへの近さ |
| A0〜A10 | 4×4 の盤で、隙間とタイルの比・強調の形 | 隙間の比率と、塗りの強調が小サイズで残ること |
| B1〜B8 | A5 と A7 の間の重さ、ベタ塗りしない動くタイル | 太い輪郭で中を抜いた動くタイル |
| C1〜C6 | A5 の配置×A7 の輪郭タイル×「15」の動くタイル | C6（数字だけ濃色） |
| D1〜D6 | C6 を 3×3 に | 3×3 だと数字が読める |
| E1〜E6 | 動くタイル以外にも数字を入れる | E3 / E6（数字を1段小さく） |
| F1〜F5 | 動くパネルの枠線を濃色に、外枠の有無、右下だけの外枠 | F1 を採用 |

段階の名前（A0 など）は、検討時に比較画像で使った識別子のまま。初回案の A・B と、細部調整の A0〜A10・B1〜B8 は別のもの。

### 3.1 初回案: 方向を広げる

- 振ったこと: 着眼点を25件出し、汎用記号・説明に頼るもの・盤面の縮小コピーを落として、4方向を SVG にした（事実（作業記録））。
  - A: 4×4 の盤全体。個々のタイルと空白1つ、1枚が空白へ滑る途中。数字なし。外枠 rx=4、タイル rx=3。
  - B: 盤の右下 2×2 を拡大。淡色の「11」「12」の輪郭タイルと、空白へ滑る濃色の太い輪郭の「15」。
  - B2: B の外枠を右辺と下辺だけにした開いた角。
  - C: 淡色の無地タイルの中で、滑り込む1枚だけが「15」を持つ。
- 3×3 は、この時点ではナンプレ（3×3 の格子と数字）と誤認されやすいとして落としていた（判断）。
- 人間のフィードバック: この段階では人間の方向選択を経ず、AI が B を仮採用して実装した（事実（作業記録））。数字は Noto Sans Bold をパス化していた。
- 分かったこと: 2×2 の拡大は「15」が大きく読めるが、盤の一部に見えるかどうかは人間の確認を経ていなかった。

### 3.2 3×3 の6案

- 人間の指示: 3×3 を試す。角丸を控える。数字はパス化する。
- 振ったこと: 3×3（タイル 20、隙間 5）で、番号なしの塗りタイル＋濃色の「8」、1〜7 を抜いた塗りタイル＋濃色の「8」、輪郭タイル＋塗りの「8」、中央の空白へ下からせり上がる「8」、動きのない完成形 1〜8、「7」「8」の一括スライド。
- 分かったこと（事実（実測））:
  - 3×3 はタイルが大きく、数字が小サイズでも残りやすい。
  - 外枠をなくすと、ランチャーのアイコンやテンキーに見えた。全タイルを濃色にして数字を抜くと、重いうえにテンキーに見えた。
  - 空白を中央に置く案は、マインスイーパー（中央に数字）に近づいた。完成形は電卓・テンキーに近く、動きも伝わらない。
  - 一括スライドは、静止画では「78」という塊に見えた。
- 次の段階では、4×4 の A 案に戻して細部を詰めることになった（人間の指示）。

### 3.3 A0〜A10: 4×4 の盤の細部

- 振ったこと: 初回 A を基準（A0）に、角丸をなくし、隙間・外枠との溝・タイルの比を振った（隙間 5 : タイル 14 から 2 : 17 まで）。強調は塗り・太い輪郭・なし、数字「15」の有無、空白の位置を振った。
- 分かったこと（事実（実測））:
  - 点の格子に見えるかどうかは、隙間とタイルの比で決まる。A0 の 5 : 14 は 50px で点の格子に見え、3 : 16 程度なら 50px でも1枚の盤として読めた。
  - 詰めるほど淡色の面が増えて重くなり、2 : 17（A5）は 50px でほぼ灰色の板になった。
  - 輪郭だけのタイル（A7）は軽いが、50px では細かい粒になり、点の格子の懸念はかえって強くなった。
  - 強調は輪郭より塗りの方が 50px で強く残る。「15」は 138px 以上では読め、60px 以下では模様になった。

### 3.4 B1〜B8: 重さと動くタイルの描き方

- 人間のフィードバック（作業記録に残した要約）: A5（詰めた塗り）は重すぎる。A7（輪郭）は窮屈すぎる。動かすタイルが濃色のベタ塗りなのは微妙。
- A7 が窮屈に見えた原因（判断）: タイル間の隙間 4 が各タイルの内側の白 11 より狭いため、隙間が二重線に見え、外枠との溝も狭かった。
- 振ったこと: 外枠との溝を広げ、淡色の面積を A5（約 59%）と A7（約 21%）の間で振った。動くタイルは、濃色の太い輪郭で中を抜く、輪郭＋淡色の塗り、淡色のままずれだけで示す、細い輪郭などにした。
- 分かったこと（事実（実測））:
  - 50px で動くタイルが一目で分かるのは、濃色の太い輪郭で中を抜いたもの（B1 など）。ベタ塗りより明るい。
  - 淡色だけ・細い輪郭の動くタイルは、50px で目立たない。
  - 輪郭タイルの盤は余白が広いが、50px で粒の模様になる。塗りタイルの盤の方が盤として読めた。

### 3.5 C1〜C6: 輪郭タイルの盤に「15」の動くタイル

- 人間の指示: A5 の詰めた配置、A7 の輪郭タイル、「15」の動くタイルを組み合わせる。
- 振ったこと: 盤は溝 3・隙間 2・タイル 17 の淡色輪郭（線幅 2）。動くタイルの輪郭の色と太さ（濃色 2・濃色 4・淡色 2 など）と、「15」の大きさを振った。
- 分かったこと（事実（実測））:
  - 隙間 2 と輪郭の線幅 2 が同じなので、隣のタイルとの境が「線・白・線」の二重線になり、盤は目の細かい格子に見えた。方眼紙やカレンダーに見える懸念が残った。
  - 動くタイルの輪郭を線幅 4 にすると（C3）、内側が狭く、138px でも実質黒いタイルに見えた。
  - 50px では「15」が小さな黒い塊か点になり、数字としては読めなかった。
- 人間は C6（輪郭は盤と同じ淡色、濃色は「15」の数字だけ）を選び、次へ進めた（人間の指示）。

### 3.6 D1〜D6: C6 を 3×3 に

- 人間の指示: C6 の描き方を 3×3 にする。
- 振ったこと: 数字を「15」（ゲーム名と一致、枚数とは合わない）か「8」（3×3 の最後の1枚として整合、ゲーム名とはつながらない）か、字の大きさ、溝と隙間、滑らせるか定位置か。
- 分かったこと（事実（実測））:
  - 3×3 ではタイルが大きくなり、50px でも数字が読めた。格子の粒っぽさも減った。
  - 一方、3×3 の格子に数字1つという構成はナンプレに近い。差は、個々の四角が離れていることと、半マスずれた1枚があることだけで、定位置の D6 が最も近かった。
  - 半マスのずれは 3×3 の方が大きく（12.67）、4×4 より「動いている」と読みやすかった。

### 3.7 E1〜E6: 全タイルに数字

- 人間の指示: D1（「15」）と D3（「8」）の他のタイルにも数字を入れる。
- 振ったこと: 「15」系は 4×4 の完成盤面の右下 3×3 を切り出した並び（6 7 8 / 10 11 12 / 14 [15] 空）、「8」系は 3×3 の完成配置（1 2 3 / 4 5 6 / 7 [8] 空）。他のタイルの数字の濃さ（淡色か濃色か）と大きさ（cap 11 か 9.5）を振った。
- 分かったこと（事実（実測））:
  - 「15」系は2桁が6つ並ぶので、50px では灰色の文字の模様になる。「8」系は1桁なので粒がそろって見える。
  - 他のタイルの数字が淡色なら、動くタイルの濃色の数字だけが 50px でも残る。全部濃色だと、ずれた位置だけが手がかりになる。
  - 離れた四角の全部に数字が入ると、ナンプレ（数字2つ）からは D 系より遠くなった。
  - 代わりに、「8」系の 1〜7 の並びは電卓やテンキーに見えやすい。「15」系の 6〜14 はテンキーに見えにくい。

### 3.8 F1〜F5: 動くパネルの枠線と外枠

- 人間の指示: E3 / E6（数字 cap 9.5）を基に、動くパネルの枠線を濃色にする。外枠をなくした形も比べる。その後、F1・F2 に加えて、右下だけ外枠を付けた形（F5）を比べる。
- 振ったこと:
  - F1: E6（「8」系）の動くパネルの枠線を濃色（線幅 2）に。外枠あり。
  - F2: E3（「15」系）の動くパネルの枠線を濃色に。外枠をなくし、盤を 17..103 に広げた（タイル 27.33）。
  - F3・F4: F1・F2 と逆の組み合わせ（「8」系の外枠なし、「15」系の外枠あり）。
  - F5: F2 に、右辺と下辺だけの外枠（L字、線幅 4、右下の角は半径 2）を付けた。盤は 16..97（タイル 25.67）。
- 分かったこと（事実（実測））:
  - 動くパネルの枠線を濃色にすると、E3 / E6 より動くパネルがはっきりし、50px でも濃い四角が1枚あると分かる。線幅 2 なので黒い塊にはならない。
  - 外枠ありは、既存3ゲームと同じく太枠で囲まれ、一覧で並びがそろう。濃い線が外枠と動くパネルの2つだけになり、階層が分かりやすい。
  - 外枠なしはタイルが大きく数字が読みやすいが、既存3ゲームがすべて濃い外形を持つ中で淡い線の集まりになり、一覧では軽く、ややぼやけて見えた。
  - 外枠なしの「8」系（F3）は、テンキーに最も近く見えた。
  - F5 の L字は、盤を載せる台の縁や落ち影のように読め、F2 の軽さを補った。右下に濃い線が集まり、「右下の空白へ滑らせて完成させる」向きとも合う。一方で、囲みが半分だけなので未完成・はみ出しの印象を持たれうる。50px では太い角括弧のように見えた。
  - この時点の AI の所感は F4 > F2 > F1 > F3 の順だった（判断）。人間は F1・F2・F5 を最終比較に残し、F1 を選んだ（人間の指示）。

## 4. 採用案 F1

### 4.1 仕様（事実（リポジトリ））

- 外枠: `x=18 y=18 width=84 height=84`、`rx=2`、濃色、線幅 4。
- 盤: 3×3。タイルの外形は 23.33 角で、外枠の内縁との溝 3、タイル間の隙間 2（左上の位置 23 / 48.33 / 73.67）。輪郭は淡色・線幅 2 で、タイル外形の内側に描く。タイルの角は丸めない。
- 数字の並び: 1 2 3 / 4 5 6 / 7 [8] 空。1〜7 は淡色、「8」は濃色。
- 動くパネル「8」: 下段中央から右下の空白へ、ピッチの半分（12.67）滑り込んだ位置。枠線は濃色・線幅 2（他のタイルと同じ太さで、色だけが違う）。
- 数字: Noto Sans Mono 600 の字形をパス化したもの（cap 9.5）。ナンプレ・マインスイーパーのピクトグラムと同じ書体。
- 色は strong / soft の2色だけ。`check_svg.py` の2色・gradient / filter / 外部画像 / text 禁止の検査を通る。

### 4.2 採用理由

判断・推測としてまとめる（人間は理由を述べていない）。

- 外枠があり、既存3ゲームと同じく濃い外形を持つので、一覧で軽く浮かない（§3.8）。
- 濃い線が外枠と動くパネルの2つだけで、どれが動くかが 50px でも分かる（§3.8）。
- 1桁の数字なので、2桁の「15」系より小サイズで粒がそろい、模様になりにくい（§3.7）。
- 3×3 の最後の1枚が「8」なので、盤の枚数と数字が整合する（§3.6）。
- 半マスのずれが大きく、動きとして読みやすい（§3.6）。

一覧の中で魅力的に見えるという点では満足していない、と読める（判断）。

## 5. 再検討するときの論点

### 5.1 論点

- **ゲーム名との距離**: F1 は 3×3 で「8」が動くので、8パズルの姿である。ゲームの盤は 4×4 で、名前は「15パズル」。3×3 は小サイズで数字が読める利点があるが（§3.6）、ゲーム自身の姿からは一段離れる（判断）。
- **テンキーに見える懸念**: 1〜7 の並びは電卓・テンキーに見えやすい（§3.7）。外枠と、1枚だけずれた濃いパネルが、その印象をどこまで打ち消しているかは、人間が一覧で見て確かめていない。
- **ナンプレとの距離**: 3×3 に数字という点でナンプレに近い（§3.6）。全タイルに数字を入れたことで D 系より離れたが（§3.7）、一覧で並べたときの見分けやすさは人間の確認が必要。
- **外枠の有無**: 外枠ありは一覧で強さがそろうが、形としては他のゲームと同じ「箱」になる。外枠なしは駒の集まりとして読めるが、一覧で軽い（§3.8）。
- **プレイ画面との対応**: プレイ画面のタイルは角丸の面に数字（`15パズル導入前提調査.md` §10）。ピクトグラムは人間の指示で角なしの輪郭にしている。見た目が「パッとしない」原因の一部が、面を持たない輪郭の盤の弱さにある可能性がある（推測）。
- **4×4 に戻す場合**: 4×4 では隙間とタイルの比で点の格子・灰色の板・二重線のどれかに寄りやすく（§3.3〜§3.5）、「15」は 60px 以下で模様になる。4×4 へ戻すなら、この3つをどう避けるかから始める。

### 5.2 有力な代替案

| 案 | 内容 | 見直すときに候補になる理由 | 懸念 |

### 6.1 比べ直す手順

実表示の比較は、既存ピクトグラムと同じサイズ・同じテーマで並べて行う（`references/method.md` §4「弁別性」「実表示サイズでの成立」）。

```sh
# 2色の検査
for svg in docs/パズル/導入調査/15パズル/ピクトグラム検討/*.svg; do
  python3 .claude/skills/design-game-pictogram/scripts/check_svg.py "$svg" \
    --max-colors 2 --forbid-gradients --forbid-filters --forbid-external-images --forbid-text
done

# 既存ピクトグラムと並べた比較シート（ライトの固定色で並ぶ）
python3 .claude/skills/design-game-pictogram/scripts/make_review_sheet.py \
  --output /tmp/fifteen-puzzle-pictogram-review.html --size 112 \
  docs/パズル/導入調査/15パズル/ピクトグラム検討/*.svg \
  frontend/src/games/water-sort/assets/pictogram.svg \
  frontend/src/games/nanpure/assets/pictogram.svg
```

ダークテーマや結果画面の `currentColor` で比べるときは、2色を CSS 変数に戻したコピーを作り、`--game-pictogram-strong` / `--game-pictogram-soft` をテーマごとに与えた HTML に並べる。サイズは §2.2 の 177 / 138 / 60 / 50 / 48px を使う。

```sh
sed -e 's/#0a0a0a/var(--game-pictogram-strong)/g' -e 's/#737373/var(--game-pictogram-soft)/g' \
  docs/パズル/導入調査/15パズル/ピクトグラム検討/F2-15-frameless.svg > /tmp/F2.svg
```
