## 2. 認識合わせの合意

導入調査 Issue #985 の合意節を正とする。要点:

- ルール: 足し算の式の文字ごとに 0〜9 の数字を1つ当てる。違う文字は違う数字、各数の先頭は 0 でない。足し算が成り立てばクリア。
- 文字は意味のないアルファベット。式は足し算だけ。
- 一意解で、当てずっぽうなしに解ける問題だけを出す。場合分けは推理に入れる。
- 途中で正誤は出さない。知らせは、同じ数字の使い回し・先頭の0・右から埋まった桁の計算違いだけ。
- ひとつ戻す・最初からがある。点数で称えたい解き方の仮説は「× で候補を消し、決まってから ◯ を付ける」（点数の付け方は別案と比べて決める）。
- 5段階、図鑑はレベルごとに500問。
- 人間の返事: 盤面の上限（表は10行×10列まで）と、文字×数字の表という UI の形は確定とせず、調査と実装で決める。そのほかはイメージどおりとして進める。

### 4.1 実装で確定した差分

§4 の仮決定のうち、実装の途中で計画と違う形に決めたもの。今の決まりは PZL-013 とコードを正とし、ここには計画との違いと理由だけを残す。

| ID | 計画 | 実装で確定した形 | 理由 |
|---|---|---|---|
| D-09 | identity は `{generatorVersion, seed: 式の文字列, conditions: {lens}}` | 条件の名前を `{addendLengths}` にした。生成の乱数の seed は `fukumenzan:<足す数の桁>/<文字の数>/<組の中の候補番号>` で、identity の seed（式の文字列）とは別に持つ | 略語を避けて意味の分かる名前にした。研究用 Python の乱数は TypeScript へ移せず、問題の再現は式の文字列で足りる |
| D-09 | 同じレベルの近い問題は、生成条件と seed の順に並べてから飛ばす | 候補を調べた順（100巡ごとのまとまりの中の候補番号の順）に、採りながら飛ばす | 並列の数と途中からの再開で採る問題が変わらない。近さは対称なので、問題集に近い組は残らない（`--verify` で0） |
| D-08 | L4・L5 の文字の数は生成のまま（7〜9） | 候補ごとに 7・8・9 を順に先に決め、作り直しの間は変えない（L1〜L3 と同じ） | 「文字の数を候補ごとに先に決める」に合わせた。9文字の候補が増えて L4 の収率が下がった。判定を難易度の資料 §8.6 のとおり変えた後の収率は L4 0.30%（調査は 1.1%）で、生成は4並列で全レベル約1.5時間（[難易度](覆面算難易度.md) §5.1） |
| D-08 | L1 の 3+3 は100問まで | 上限は L1 の 20% のまま、採れたのは60問 | 3+3 は5文字だけなので、5文字の 200 問の枠を 4+3・4+4 と分け合った |
| D-10 | 式のタイルには決まった数字か文字だけを描く | × を付けた空の文字は、タイルの右下に残りの候補の数（10 − 自分で付けた × の数）を小さく出す。待ったで × を戻したら、その文字を選ぶ。落とし先は指の下で決め、運ぶ札だけを指の上に描く | 選びを外すと × の跡が見えず、待ったで何が戻ったか分からなかった（山場1の試遊）。札の中心で落とし先を決めると、指で狙った文字に入らなかった |
| D-17 | 遊び方の例は問題集にある形から選ぶ | 遊び方・チュートリアルの例（MRD+DDX=MUDU）は問題集に入らない式にし、同じ問題を問題集から除く | 例と同じ問題が問題集にあると、例の答えを写して解けた（山場1の試遊） |
| D-18 | リセットは提供しない | プレイ中のメニューにリセットを出さない。結果画面の「もう一度」は残す | GAME-005 の「クリア後の同じ問題の開始」はリセットと同じ意味で、点に入る事実を消す抜け道にはならない |

## 7. 確かめていないこと

- 人の手応え: L1〜L5 の違いが分かるか、特に L4 と L5 の差（強い読み手には L5 も1回の場合分けで解ける）と、L2→L3 が手数でなく読みの種類の差として感じられるか（試遊と最終レビュー）。
- 素朴な解き方の重さは L2 と L3 で逆になり（置いた数/文字の中央値 112 と 85）、L4 と L5 を分けない（[難易度](覆面算難易度.md) §4.1）。レベルの差は読みの種類で作っているので、試し置きで解く人には L2→L3・L4→L5 の差が出にくい。
- 規模が合意の見本と違う: 認識合わせで L5 の見本は10文字だったが、10文字では L4 が作れず L5 の収率も 0.6% なので、問題集は9文字までにした（D-04、[難易度](覆面算難易度.md) §5）。L1 の見本「3桁＋3桁＝4桁・6文字」も L1 に全数で2問しかない。最終レビューで人間に見せる。
- 難易度の残る揺れ: 1手の数え方・枝の中で2列をまとめるか・先読みの扱いを自然な範囲で変えると、L4・L5 の多くが範囲外へ出る（[難易度](覆面算難易度.md) §7）。試遊とプレイ記録からの再校正で確かめる。
- 1問にかかる人の時間。件数（各レベル500問）の根拠の一部で、L1 が1分を切るほど短ければ L1 だけ増やす案がある（[供給実験](覆面算供給実験.md)）。
- 意味のない文字で解けたうれしさが出るか（合意の「まだ分からないこと」）。
- 実機（iOS Safari）での札の運びやすさ・隣の札の連打・運んでいる札の見え方。`viewport-fit=cover` で縦画面の safe-area が 0 になるか（0 でなければ式のタイルが縮む）。
- 札の形で「この数字が入りうる文字は1つだけ」の推理がどれだけ手間になるか。スマホ操作調査の計測では10文字の問題の約半数で使い、8文字以下では使わなかった。問題集は9文字までなので、9文字で使うかを含めて play-ui の試作で確かめ、札を押さえている間その札に × の無い文字を光らせる案が要るかを決める。
- 札を押してから文字を押す・文字を押してから札を押すの順で入れると × を分ける形（D-10）が、遊ぶ人に分かるか。
- D-08 で文字の数を配分した後の、図鑑の特徴の分布とレベルの中の相関（[図鑑と問題の特徴](覆面算図鑑と問題の特徴.md) は配分前の生成で測った）。
- 近い問題（1か所の文字だけ違う）を人が同じに感じるか。
- 遊ぶ人が「同じ文字の桁」を切り口として使うか（最終レビューで聞く）。
- 「覆面算」の商標（人間が J-PlatPat で確かめる）。
