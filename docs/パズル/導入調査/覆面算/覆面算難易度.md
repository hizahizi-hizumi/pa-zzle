入力が札なので、同じ数字の使い回しは入力の形の上で起きない。そのため知らせは、合意の3つから先頭の0と計算違いの2つになる。

  - 隠れた1つを使う Lhi・NB6hi・強い端は、すでにそれを読みに入れている。

## 2. 読みのモデル（版6）

### 2.1 挑戦の1文

> 各列の「足す文字の和＋右からの繰り上がり＝答えの文字＋10×左への繰り上がり」と「違う文字は違う数字」から文字ごとの候補を絞り、1列で決まらなければ隣の列の式と合わせて少ない組を突き合わせ、それでも決まらなければ繰り上がりや候補の少ない文字に値を仮に置いて矛盾を見ることで、すべての文字の数字を決めること。

挑戦に入れないもの:

- 文字の数・桁の多さそのもの（作業量）。
- 当てずっぽうの試し置きと、計算違いの知らせを頼りにした総当たり。

### 2.2 読みと場合分け

| 種類 | 中身 |
| --- | --- |
| 1列ずつの読み | 1つの列の式（両辺で消える文字・和の大きさを含む）と表（決まった数字を消す、隠れた1つ、組の消去） |
| まとめる読み | 1列ずつの読みに、隣の2列・共通の文字を持つ隣でない2列のまとめを足す。強い端は、関係式の持ち回りを3列（組12。製品は隣り合わない3列も。§8.6）と式（2列・3列・全部の列の和の大きさ、2列の式の差）で近似する |
| 場合分け | 1つの変数（繰り上がりか候補の少ない文字）に値を仮に置き、枝を読んで矛盾した値を消す。1〜2手の先読みもここに入る |

- **1手（版6）:** 1つの規則（1つの列、1つのまとめる列の組、表）を1回当てて出た事実の数×その規則の重みを、手に数える。事実は、1つの変数の候補が減ったこと。重みは、1列と表が1、2列のまとめが2、3列が3。規則が矛盾を見たら、その規則を当てたところで枝を閉じる。
  - 1回当てて出た事実は、矛盾に要らないものも全部数える（調査コードの `FactStep6Reader(whole=True)`、製品の `case-splitting.ts` の `steps`）。だから、人が要る事実だけを数えた手より多いか同じ（導出）。
  - 18手は、この数え方で手で追った L4 の例（GVANK・DBRPR・MKCXE）が、どれも1回の場合分けで解ける最短の長さとして選んだ。
  - 要る事実だけを数える人には、L5 の一部が1回で解ける（§7.1 の C1。製品の問題集で最大 23%）。
- **場合分けの回数（版6）:** 1つの変数を1回分けて、その結論を入れて読み直すのを1回。二択も三択も1回。
- どの規則も候補を減らすだけの単調な規則（導出）。読み手を強めると、閉包は狭くなり、回数は少ないか同じになる（導出。例外は §10 の「確かめていないこと」）。

### 2.3 端の読み手

組の言い方は、読み方の解釈の和（族）の端の読み手で決める。軸がどれも単調なので、端で言えれば族の全員で言える（導出）。

| 読み手 | 中身 | 使い道 | 調査コード |
| --- | --- | --- | --- |
| Llo | 1列は組4まで書き出し、決まっていない文字が3つ以上で組の多い列は和の大きさ（最小と最大）だけで読む（製品は同じ側の違う文字を違う数字で取る。§8.6）。表は決まった数字を消すだけ | E を決める | `Fam4Reader(**L6_LO)` |
| Lhi | 1列は組を全部書き出す。隠れた1つ・組の消去 | H1 の下の側 | `Fam4Reader(**L6_HI)` |
| Clo50 | Llo に、隣の2列のまとめを足す。つないだ組8以下で、かつ探す手間50以下のときだけ。探す手間は、2列それぞれの組の数（両辺で消える文字を除いて数える）の積 | H1 を決める | `Fam6Reader(pair_prod_cap=50, **C6_LO)` |
| Chi | Lhi に、2列（積200かつないだ組50。消える文字を除く）、隣でない2列（組50）、3列（組12）を足す（製品は隣り合わない3列（組12）も。§8.6） | H2 を決める（前置き） | `Fam4Reader(**C6_HI)` |
| ChiA | Chi に、式の読み（2列・3列・全部の列を桁の重みでまとめた式と、共通の文字を持つ2列の式の差。決まっていない変数3つまでは書き出し、多ければ和の大きさ）を足す | H2 を決める | `Alg6Reader(**C6_HI)`（`_chi6`） |
| NB6lo・NB6hi | 組4（12）より多い列を読まない1列ずつの読み。決まっていない文字と組は、両辺で消える文字を除いて数える。NB6hi は隠れた1つ・組の消去も使う | E の中の1列の重さ（L1 と L2） | `NoBounds6Reader(**NB6_LO)`・`(**NB6_HI)` |
| 場合分けの弱い端 | Clo（探す手間の上限なし）で読み、繰り上がりの二択・三択と、候補2つの文字で場合分けする。枝は18手まで | 提供範囲と B1・B2 | `seq6(FactStep6Reader(step_k=18, whole=True, **C6_LO, r2_wl=2), weak_allowed(p))` |

- 場合分けの弱い端の土台には、探す手間の上限を置かない。置くと、F1 が手で1回の場合分けとした GVANK・MKCXE が2〜3回になる（計測。§3.1）。
- 強さの順: Llo ≦ Lhi、Llo ≦ Clo24 ≦ Clo50 ≦ Clo ≦ Chi ≦ ChiA、NB6lo ≦ Llo、NB6hi ≦ Lhi。場合分けの1回は、枝14手 ≦ 18手 ≦ 22手 ≦ 枝を閉包で読む人（導出。`selfcheck` で 28 問を確かめた。計測）。

### 4.1 素朴な解き方で押し切れる割合

素朴な解き方は、読まずに試し置きと知らせで押し切る解き方（`naive_trial`）。

- 右の列から、足す文字に、まだ使っていない数字（先頭の文字は0以外）を無作為な順で置く。
- 列の足す文字が埋まったら、答えの文字を計算して置く。
- 計算した数字が使用中（札が残っていない）か、先頭が0になるか、答えの文字がすでに別の数字なら、その列の最後の試し置きを戻して次を試す。
- 計算違いの知らせを最もうまく使う形にあたる。答えの数字を当てずに計算で置くので、知らせを待って当て直すより置く数は少ないか同じ（導出）。素朴な解き方に有利な側で測っている。
- 置いた数は、試し置きと答えの書き込みの合計。1問を3回（乱数を変えて）、上限2000回で解かせた。

### 8.2 判定の流れ（`classify6`）

1. Llo。解ければ E。規模が 2s か 3s なら NB6lo、止まれば NB6hi。
2. Lhi。解ければ mE（範囲外）。
3. Clo50。解ければ H1。
4. Chi、止まれば ChiA。どちらかが解ければ mH（範囲外）。両方止まれば H2。
5. H2 で規模が 3l なら sPcN。1〜2回なら sPN_18。
6. 組・段から `cell6`、規模と段から `CELLS6`、文字の数を `LETTERS6` で確かめて `level6`。3l・H1 は `CELLS6` に無いので範囲外。
7. 外れた問題の理由は `scope6`（§2.5。余白・組み合わせ外・文字の数・上限を超える・評価不能）。

- 組: `read_class6`。Chi で止まった問題は、ChiA を測るまで H2 と決めない（ChiA が無ければ止まる）。1列の重さ: `col_weight6`。提供範囲: `provided6`。場合分けの段: `split_weight6(rule="weak")`。

- `seq6` は、2回目より前に探す盤面が300を超えたら `"cap"`（評価不能）を返す。2回まで調べ尽くして解けなければ3（上限を超える）、進めなければ null。
- 1問の判定は、5+5+5 で平均 0.35 秒、5+5+4 で 0.21 秒（Python・1コア。生成を除く。計測）。

### 8.6 製品で変えた所

手解き（F1）と反例探し（A4）の指摘から、調査コードの判定を5か所変えた。1・2 は F1（rev2）・A4（rev2）、3〜5 は F1（rev3）・A4（rev3）の指摘から。どれも、読み手の族の端の定義を人が式を読む形にそろえる直しで、レベルの組（§6）・提供範囲・読み手の強さの値（組4・12・8・50・200、枝18手、2回まで）は変えていない。5 は強い端に、今の隣の3桁と同じ上限（組12）のまとめを足した。

1. **答えの先頭の文字を、最上位の足す桁の左への繰り上がりとして読む（F1（rev2）C1・M1・m1）。**
   - 調査コードは、答えが1桁長いとき、答えの先頭の文字だけの列（`c5 = H`）を別に持つ。人は最上位の列を `2N + c4 = G + 10H` と書くので、強い端の「共通の文字を持つ隣でない2列」が十の位と最上位の列を N・H でつないで読める。調査コードの形では H と c5 がつながらず、L4 の代表 7kdsrjbjhm が場合分けなしで解けるのを見落としていた。
   - 製品は、答えだけの列を最上位の足す列に畳み、答えの先頭の文字をその列の左への繰り上がりの変数にする（`column-model.ts`）。組の数・決まっていない文字の数・隣の判定・共通の文字・場合分けする変数もこの形で数える。答えの先頭の文字は最初から候補が2つまで（3）なので、場合分けしてよい変数の決まりは変わらない。完全な探索と素朴な解き方は、答えの桁ごとの形のまま。
2. **決まっていない文字と組を、どの読み手でも両辺で消える文字を除いて数える（A4（rev2）C2）。**
   - 調査コードは、E1 の軽い読み（組4・12）と H1 の探す手間（積50）では消える文字を除き、1桁ずつの弱い端（組4・文字3つ以上）とつないだ組8では消える文字も数えていた。どこでも除く。
3. **答えの先頭の文字の最初の候補を、繰り上がりの範囲にする（F1（rev3）C1・A4（rev3）C1）。**
   - 1 で答えだけの列を畳んだとき、調査コードの答えだけの列が持っていた繰り上がりの候補（c5 は 0〜2）が落ち、答えの先頭の文字は文字の候補（1〜9）から始まっていた。書き出しの多い桁を読まない読み手（NB6lo・NB6hi）は最上位の桁を読まないので、「答えの先頭は1（3つ足しなら1か2）」を知らないまま止まる。そのため L2 の約半分が、この事実を読むだけの問題になっていた。
   - 製品は、答えの先頭の文字の最初の候補を、ほかの繰り上がりと同じ範囲の0でない値（2つ足しは1、3つ足しは1か2）にする（`createInitialDomains`）。
4. **1桁の和の大きさを、違う文字は違う数字として読む（F1（rev3）M2）。**
   - 調査コードの和の大きさ（`_bounds`）は、同じ桁の違う文字が同じ数字を取れるとして最小と最大を出す。人は「足す文字が J と P の2つなら 9＋8＋2＝19 まで、答えの先頭は1」と読む。
   - 製品は、同じ側（係数の符号が同じ）の違う文字の最小と最大を違う数字で取る（`column-readers.ts` の `propagateColumnBounds`）。繰り上がりと、反対の側の文字との違いは区間のまま読む。F1 は最上位の桁だけで測ったが、製品はどの桁にも入れた。
5. **まとめる読みの強い端に、隣り合わない3桁のまとめを足す（F1（rev3）M1）。**
   - 強い端は、隣の3桁・共通の文字を持つ隣でない2桁・2桁の式の差を読むが、隣り合わない3桁はまとめなかった。例: BKTBT＋LXTLK＋BKKX＝LJBGKK は、一の位 `T+X=10` と千の位 `K+X+c3=10` の差 `T=K+c3` を百の位へ入れると `3K=G+7` になり、値を仮に置かずに決まる。定義（§2.2）では関係式の持ち回りは読みに数えるので、場合分けの問題に数えるのは言い過ぎだった。
   - 製品は、強い端（Chi・ChiA）に、隣り合わない3桁（一の位・百の位・千の位など）のまとめを、隣の3桁と同じつないだ組12まで足す（`FukumenzanReaderSettings` の `separatedTriples`）。3桁の中で隣り合う桁は繰り上がりでつなぐ。F1 はつながずに測った（L4 28.0%・L5 14.6% が余白へ）。

## 11. 人間の試遊で確かめること

- L1→L2: 決まっていない文字が3つある列を和の大きさで絞る問題を、L1 と別の重さと感じるか。
- L2→L3: 隣の列と合わせて組を突き合わせることに気づく難しさが、L2 より上と感じられるか。
- L3→L4: 値を1回仮に置く問題を、L3 と別の重さと感じるか。
- L4→L5: 場合分けを2回重ねる問題が、L4 より重いと感じるか。強い人には同じに感じられないか（§3.4）。
- 人が、枝を何手まで追えるか。L4 の三択1回が二択1回より重く感じられるか（§7）。

- 意味のない文字の問題で、解けたうれしさがあるか。

## 12. 難しさの源と採らない案

| 源 | 使い方 |
| --- | --- |
| 解き方（手筋） | 読みの組 E・H1・H2。線は「値を仮に置くか」 |
| 場合分けの重さ | 弱い端の回数1回（B1）と2回（B2）。二択も三択も1回 |
| 1列の重さ | E1・E2（L1 と L2）。両辺で消える文字を除いて数える |
| 2列の探す手間 | H1 の上限（一つずつの組の積50） |
| 読みの深さ（枝の長さ） | 提供範囲の条件（18手）。深さそのものでは分けない |
| 規模 | 足す数と桁。段を作らず、読みの段ごとに1つの規模を決める（下の段落） |
| 手がかり（最初から見えている文字） | 採らない |

**規模を階段に重ねる理由:** どの段も読みが上がり、規模だけで上がる段は無い（§6）。そのうえで各レベルを1つの規模に限り、ほかの規模の同じ読み（2s・H1、3s・H2、3l・H1 など）を範囲外にする。同じ読みを規模違いで別のレベルにすると、規模だけの段（挑戦と無関係な作業量の段）になる。同じレベルに混ぜると、レベルの中で作業量（文字の数）が難易度の写しになる（§6 の L3）。規模は、合意の「上ほど文字と足す数が増える」に沿って、読みが上がる段で一緒に上げる。L4・L5 を 3l に限るのはこのためで、場合分けの重さを 3s・2s で数えられないからではない。

採らない案:

- **版4 の線（先読みの手数で読みと場合分けを分ける）:** 人に見分けられない線の上に L4・L5 が乗っていた（A4・F1）。
- **二択か三択かで L4・L5 を分ける:** L5 が 5000 候補で10問しか残らない（§3.4）。
- **族の全員の回数で L4・L5 を分ける:** L5 が0問（§3.4）。
- **場合分けの読み手の土台に探す手間の上限を置く:** F1 が手で1回とした例が2〜3回になる（§3.1）。
- **4つ足し:** 一意解が出にくい（4+4+4+4 を文字8〜10 に寄せると、150 中 134 が作り直しの上限に達した）。
- **2l（2つ足しで5〜6桁）:** 3s と同じ読みの段で規模だけが違い、階段に入れる場所がない。

## 15. パズル仕様の難易度の節の案

spec の項目で PZL-013 の `## 難易度` へ移す。数値・分類条件はコードを正とし、ここに書かない。

### 基準とするプレイ

- 先頭の0と、右から続けて埋まった桁の計算違いだけを盤面が知らせる中で、読んで決めた数字だけを入れるプレイを基準とする。
- 当てずっぽうの試し置きと、計算違いの知らせを頼りにした総当たりは、難しさに含めない。
- 文字の数や桁の多さ（作業の量）そのものは、難しさにしない。

### 挑戦

- 各桁の「足す文字の和＋右からの繰り上がり＝答えの文字＋10×左への繰り上がり」と「違う文字は違う数字」から、文字ごとの候補を絞る。
- 1桁で決まらなければ、隣の桁の式と合わせて少ない組を突き合わせる。
- それでも決まらなければ、繰り上がりや候補の少ない文字に値を仮に置いて矛盾を見る（場合分け）。場合分けは推理に入れ、当てずっぽうを要する問題は出さない。

### 段階設計

| 難易度 | 挑戦 |
| --- | --- |
| 1 | 2つの数の足し算（3〜4桁）。書き出しの少ない桁を1桁ずつ読めば決まる。 |
| 2 | 3つの数の足し算（3〜4桁）。決まっていない文字が3つある桁を、和の大きさで絞る。 |
| 3 | 3つの数の足し算（3〜4桁）。1桁ずつでは決まらず、隣の桁と少ない組を突き合わせれば決まる。 |
| 4 | 3つの数の足し算（5桁を含む）。まとめて読んでも決まらず、1つの繰り上がりか文字を1回場合分けすれば決まる。 |
| 5 | 3つの数の足し算（5桁を含む）。場合分けを2回重ねる。 |

- 段階は、読み方に自然な幅のある人たち（読みの族）の端の読み手で言い切れることだけで分ける。人によって強さの違う読みの上に境目を置かない。
- どの段でも読みが1つ上がり、規模は下がらない。各段は1つの規模に限り、同じ読みを規模だけで別の段にしない。
- 場合分けは、二択も三択も1回と数え、2回までの問題だけを出す。
- 文字の数は段の中で配分し、図鑑の「文字」が難易度の写しにならないようにする。
