# 覆面算供給実験

調査日: 2026-11-24。導入調査であり、今の決まりの正本ではない。仮決定は [覆面算実装前提調査](覆面算実装前提調査.md) の仮決定一覧を正とする。

難易度は決定版（[覆面算難易度](覆面算難易度.md) の版6・案 `P50nk18w`・場合分けの上限2回）。L3 は 3s（3つ足し・4桁まで）だけで作る（調査の途中で決めた）。レベルは supply6 の行の `level` を使わず、行に残った読み手の結果（f6）から今の案で決め直した（s6_big.jsonl の `level` は上限3回のときの出力で、範囲外の 59 問を L5 に入れていたため）。

## 結論

- **件数: 条件つきで成り立つ。各レベル500問を推奨する（合意の「図鑑はレベルごとに500問」と同じ）。**
  - 「もう1問」の目安を「そのレベルを遊び続けても、次の1問が遊んだことのある問題になる確率が 10% 以下にとどまる回数」とした。ランダム出題の初期状態は全状態が対象（GAME-002）なので、500問なら 53 回まで、300問なら 32 回、1000問なら 105 回まで 10% 以下にとどまる（計算）。出題対象を未挑戦だけにすれば、500回まで新しい問題が出る。
  - 条件は、1問にかかる人の時間。これは測っていない。L1 が1問1分ほどで解けるなら、53回は約1時間にあたる。試遊で L1 がそれより短ければ、L1 だけ1000問に増やす。L1 の問題は1万問以上あるので、増やしても供給は足りる（下の行）。
  - 件数の差は、図鑑の枠と番号の差として遊ぶ人に見える（`/design-game-difficulty` の守ること 8）。公開前の今なら、作り直すのは問題集だけで済む。
- **一意解の割合と生成時間: 成り立つ。各レベル500問は、L1〜L3 が数分〜数十分、L4 が Python・4並列で約1時間でそろう（[覆面算難易度](覆面算難易度.md) §5。判定の打ち切りを2回にした後の値）。**
  - L1 は全数を数え上げた。L1 に入る問題は、3+3 で 644 問、4+3 で 14,270 問ある。
  - L2・L3（3s だけ）は、3s の候補を 1.5万作って直接数えた。L2 は 505 問当たり、違う問題は 496 問。L3 は 854 問当たり、違う問題は 852 問。各500問には、3s の候補が約1.5万要る。L2 と L3 は同じ候補から採れる。
  - L4 は [覆面算難易度](覆面算難易度.md) の見積もり（約4.5万候補）のまま。L3 を 3l から採らなくなっても、L4・L5 の時間は変わらない。
  - 実装した TypeScript の生成では、判定を人の読み方に合わせて変えた（難易度の資料 §8.6）後で L4 の収率が 0.30% に下がり、L4 は約16.5万候補・4並列で約1.4時間、全レベルで約1.5時間かかった（同 §5.1）。この行の Python の見積もりより長いが、オフラインで数時間までを受け入れる範囲（難易度の資料 §1 の D6）に入る。
- **同じ問題: 成り立つ。** 文字の付け替えと足す数の並べ替えでそろえたキー（`canonical_key`）で除く。
  - 一意解の問題では、文字の並びが同じなら解の数字の並びも同じになる（導出）。だから、このキー1つで「同じ解の数字の並び」の問題もそろう。
  - 重なりが多いのは L1 の 3+3 だけだった。当たった 590 問のうち 196 問が重なり。3+3 の L1 は全部で 644 問しかないため。
  - ほかのレベルの重なりは少ない（L2 9/505、L3 2/854、L4・L5 0）。レベルをまたぐ重なりは0だった。
- **近い問題（1か所の文字だけ違う問題）: 条件つきで成り立つ。**
  - 近い問題を持つ問題の割合は、L1 34%（3+3 では 97%）、L2 10.5%、L3 1.2%、L4・L5 0。
  - 先に採った問題と近い問題を飛ばしても、L1・L3 は500問そろう。L2 は手元の 496 問のうち 25 問が落ちる。
  - 3+3 の L1 は、近い問題を飛ばすと最大 222 問しか残らない。だから L1 で 3+3 の割合に上限が要る。
- **文字の数の配分: 生成を変えれば成り立つ。今の生成のままだと、L1〜L3 は5文字が 73〜86% に寄る。**
  - 寄る原因は2つある。
    - 生成のせい（4+3・4+4・4+4+3・4+4+4）: 一意解でないと作り直すが、作り直すたびに文字の数を引き直すので、一意解になりやすい5文字に寄る。全数で見ると、4+3 の L1 は6文字がいちばん多い（5文字 4,195・6文字 7,605・7文字 2,470）。
    - 問題そのもの（3+3・3+3+3）: 一意解は5文字にしかほぼ無い。3+3 の6文字は全数で 46 問、そのうち L1 は2問。7文字は0問。
  - 文字の数を候補ごとに固定すると、L1 の 6〜7文字、L2・L3 の 6〜7文字が 1〜67% の収率で作れた（下の計測）。L1〜L3 は文字の数ごとに配分でき、増える時間は1コアで数分〜十数分の見込み（推測）。L4・L5 は生成のままの分かれ方（7〜9文字）を推奨する。
- **並び: 成り立つ。** ランダム出題は問題集から均等に引く（GAME-002・`problem-selection.ts`）ので、並びが効くのは図鑑の番号だけ。続けて出る問題の似方は、並びではなく、レベルの中の問題の配分で決まる。生成条件と文字の数の組を交互に並べる（氷の床迷路・マインスイーパーの前例）。
- **識別子と大きさ: 成り立つ。**
  - identity の `seed` は式の文字列（例 `BYK+KTK=TKHH`）にする。式の文字列だけで問題が決まる。
  - 問題集は、各レベル500問で JSON 約56KB・gzip 約33KB の見込み。既存ゲームの問題集（gzip 3.5〜111KB）の中でも小さい側に入る。
- **合意との食い違いの知らせ（前提は崩れない）:** 認識合わせで L1 の見本として見せた「3桁＋3桁＝4桁・6文字」の形は、L1 にほぼ無い（全数で2問）。途中の図に使った WFX+TFM=CMMW は、今の案では範囲外（mH）。
  - L1 の問題は、3+3 なら5文字、4+3・4+4 なら5〜7文字になる。
  - 遊び方やチュートリアルで L1 の例を見せるときは、問題集にある形から選ぶ。

## 事実と推測

- [事実] ランダム出題は、選んだ難易度の出題対象の問題から均等に引き、直前の問題だけを除く。出題対象の初期状態は全状態: `docs/プロダクト/ゲーム/GAME-002-開始条件.md`、`frontend/src/games/problem-selection.ts`（`hashProblemSeed(seed) % entries.length`）
- [事実] 図鑑の番号は、問題集の並び（難易度の昇順、各難易度の中は問題集の並び）で付ける。問題は問題 ID で指し、番号では指さない: `docs/プロダクト/ゲーム/GAME-009-図鑑.md`「番号」
- [事実] 問題 ID は identity 全体のハッシュ。既存ゲームの identity は `{generatorVersion, seed, conditions}` で、氷の床迷路の `seed` は盤面そのものの符号: `frontend/src/games/problem-id.ts`、`frontend/src/games/*/problem/problem.ts`、`frontend/src/games/ice-floor-maze/problem/problem-pool.ts`
- [事実] 既存の生成スクリプトの前例は次のとおり。
  - 生成条件を交互に並べる: `generate-ice-floor-maze-problem-pool.ts` の `interleave`、`generate-minesweeper-problem-pool.ts`
  - 同型の重複と近い配置を除く: `generate-bridges-problem-pool.ts` の `symmetryKey`・`isNear`
  - 同じ解き方の流れの数に上限を置く: 同じファイルの `MAXIMUM_FLOW_SHARE` など
  - CI では `--verify` を回す
- [事実] 既存ゲームの件数は、供給が足りるときはビルドの大きさと前例で決めてきた。1問に何分かかるかからは決めていない: `docs/パズル/導入調査/氷の床迷路/氷の床迷路難易度.md` §5.2、`docs/パズル/導入調査/橋をかけろ/橋をかけろ実装前提調査.md` の D-09
- [事実] 合意では「図鑑はレベルごとに500問」を、こちらで決めて進めることとして見せ、人間は「他はok」と返した: [覆面算実装前提調査](覆面算実装前提調査.md)「認識合わせの合意」
- [事実] 生成器 `generate` は、作り直すたびに文字の数 n を引き直す: `fukumenzan_difficulty.py` の `generate`・`_supply6_task`
- [推測] 1問の人の時間は、L1 が最も短い（1〜2分）。L4・L5 は10分を超える。
  - 根拠: 決める文字が5〜10と少ない。L4・L5 は場合分けを要する。
  - 確かめ方: 試遊で測る。L1 の件数を決め直す材料になる。
- [推測] 近い問題（1か所の文字だけ違う）は、文字を無作為に当てるので、見た目では気づきにくい。ただし、解き始めの列の形が同じになりやすい。
  - 確かめ方: 試遊で、近い2問を続けて解いて同じに感じるかを見る。
- [推測] 文字の数を固定する生成は、TypeScript では今の生成とほぼ同じ時間で済む。判定が時間の大半を占め、固定で増えるのは作り直しの回数だけだから（作り直しは1回が ms 未満）。
  - 確かめ方: 実装後に `fixedn` と同じ組で測る。
- [推測] 4+4 の L1 は数万問以上ある。根拠は、4+4 の一意解の問題が 58万問あることと、`fixedn` で一意解の 11〜52% が L1 だったこと。数え終わっていない。

## 仮決定の候補

- 件数:
  - [推奨] 各レベル500問（計2,500問）
  - [理由]
    - どのレベルでも、53回まで次の1問が遊んだ問題になる確率が 10% 以下。未挑戦だけを出せば500回まで新しい問題が出る。
    - 合意で見せた数と同じ。
    - L4 の生成は Python・4並列で約1時間で、受け入れた範囲（数時間まで。難易度 D6）に入る。
    - 問題集は gzip 約33KB で、既存より小さい。
  - [比べた案]
    - L1（と L2）を1000問: 1問の短い L1 では「もう1問」に効く。供給も足りる。ただし人の時間が分かるまで根拠が推測だけで、合意の数から外れる。
    - L4・L5 を300問: 32回まで 10% 以下。L4 の生成が約0.8時間に縮む。ただし図鑑の枠がレベルで揃わず、短縮の理由が供給の都合になる。
    - 各1000問: L4 が約2.6時間。
  - [覆したときに作り直す範囲] 問題集と図鑑の番号。公開後に変えるなら、人間の判断が要る（守ること 8）
- 同じ問題のキー:
  - [推奨] 文字を最初に出た順に A, B, … と付け替え、足す数の並べ替えのうち最小の文字列（`canonical_key`）。全レベルを通して1問に1つ
  - [理由] 一意解なので、同じ解の数字の並びも同じキーになる。レベルをまたぐ重なりは0だった
  - [比べた案] 式の文字列そのもの（文字の付け替えを見逃す。L1 の 3+3 で 13% が重なる）
  - [覆したときに作り直す範囲] 生成スクリプトの検証と問題集
- 近い問題:
  - [推奨] 同じレベルの中で、1か所の文字だけ違う問題（`near_keys` を共有する問題）を、先に採った問題がいれば飛ばす。生成スクリプトの `--verify` でも数える
  - [理由] 飛ばしても L1・L3 は500問そろう。L2 も候補を少し足せばそろう。同じ並びの開き方の問題が続かない
  - [比べた案]
    - 近さを見ない（L1 の 34% に近い問題が残る）
    - 2か所まで違う問題も近いとする（測っていない）
  - [覆したときに作り直す範囲] 問題集だけ
- L1 の 3+3 の割合:
  - [推奨] L1 の 3+3 を100問（20%）までにする
  - [理由]
    - 3+3 の L1 は全部で 644 問、近い問題を飛ばすと 222 問で、そのほとんどが5文字。
    - 今の生成では、L1 の当たりの4割が 3+3 で、その3分の1が重なる。
  - [比べた案]
    - 生成条件ごとに同数（約167問。222問の上限に近い）
    - 3+3 を入れない（認識合わせで見せた 3桁＋3桁 の形が L1 から消える）
  - [覆したときに作り直す範囲] 問題集だけ
- 文字の数と生成:
  - [推奨]
    - 生成で、文字の数を候補ごとに先に決め、作り直しの間は変えない。
    - L1〜L3 は、レベルの中で文字の数ごとに配分する。例: L1 は5・6・7文字を 200・200・100、L2 は 250・150・100、L3 は 200・200・100。3+3・3+3+3 は5文字だけに使う。
    - L4・L5 は配分せず、生成のまま（7〜9文字）にする。
  - [理由]
    - 図鑑の特徴「文字の数」が、レベルの中で分かれる。
    - 今の5文字への寄りは、主に生成のせいで、問題そのものの分かれ方ではない（4+3 の L1 は6文字がいちばん多い）。
    - 固定しても L1〜L3 は収率 1〜67% で作れる。
    - L4・L5 の9文字は収率 0.35〜1.2% で、配分すると L4 の時間が大きく延びる。
  - [比べた案]
    - 今の生成のまま（L1〜L3 の5文字が 73〜86%）
    - 文字の数を固定するが配分しない（L1 は 5:6:7 が約 59:30:11 の見込み）
    - L4・L5 も配分する
  - [覆したときに作り直す範囲] 生成器・問題集・図鑑の特徴の値の分布。各レベルの配分の値は、[覆面算図鑑と問題の特徴](覆面算図鑑と問題の特徴.md) の結論と合わせて実装で決める
- 並び:
  - [推奨] レベルの中は、生成条件×文字の数の組を交互に並べる。組の中は生成の順。同じ seed から同じ並びにする
  - [理由]
    - ランダム出題は均等なので、並びは図鑑の番号にだけ効く。
    - 図鑑の頭から見たときに、同じ形が固まらない。
    - 前例（氷の床迷路・マインスイーパー）と同じ。
  - [比べた案]
    - 生成条件ごとにまとめる（図鑑の前半が 3+3 に偏る）
    - 文字の数の順（図鑑の並びが難易度のように見える）
  - [覆したときに作り直す範囲] 問題集の並びと図鑑の番号
- 識別子:
  - [推奨] identity は `{generatorVersion: "1", seed: 式の文字列, conditions: {lens}}`。問題集の1問は式の文字列で、文字の数などは読み込み時に式から求める
  - [理由]
    - 式の文字列だけで問題が決まり、生成器・判定器の版に依らずに復元できる（氷の床迷路の盤面の符号と同じ考え）。
    - 問題 ID は identity のハッシュなので、難易度は読み取れない（GAME-006）。
  - [比べた案]
    - 生成の seed 番号（判定の版が変わると同じ問題を作れない）
    - 同じ問題のキー（文字を付け直すことになり、問題集と図鑑の見た目が変わる）
  - [覆したときに作り直す範囲] identity の型・問題 ID・記録の読み込み

## 確かめていないこと

- 1問にかかる人の時間: 実プレイの記録が無い。件数の目安（53回）が何時間にあたるかは推測で、L1 を1000問にするかはこれで決まる。
- 4+4 の L1 の全数: 58万問の判定が、計測の打ち切りまでに終わらなかった。4+3 だけで 14,270 問あるので、件数の判断には効かない。
- `fixedn` の収率の確かさ: 1つの組あたり 200 候補で、当たりが少ない組（L2 の7文字は 400 候補で7問）が多い。配分の時間の見込みは2倍ほどずれうる。
- 近い問題を人が同じに感じるか: 試遊で確かめていない。2か所まで違う問題の数も測っていない。
- L4・L5 の文字の数ごとの収率の数え直し: [覆面算難易度](覆面算難易度.md) の値（5000 候補で L4 55・L5 104）を使った。f6_sup とその追加分（`f6_supx`・`f6_supx2`）を `level6` で合わせ直すと L4 63・L5 111 になり、一致しなかった。原因は、強い端の式の読み（ChiA）を渡さずに `level6` を呼ぶと Chi で代わりに分類していたことで、同じ問題で15問のレベルが違っていた。調査コードはこの呼び方を止めるよう直し、`classify6` で測り直すと L4 55・L5 104 で一致した（[覆面算難易度](覆面算難易度.md) §5）。
- 問題集に分析の値（基準時間に使う作業量など）を持つときの大きさ: 採点を決めるときに決まるため。文字の数を1つ足すと、gzip で1問あたり約0.5 bytes 増える（計測）。
