# 覆面算図鑑と問題の特徴

調査日: 2026-11-24。導入調査であり、今の決まりの正本ではない。仮決定は [覆面算実装前提調査](覆面算実装前提調査.md) の仮決定一覧を正とする。

## 結論

- **条件つきで成り立つ: 特徴は「文字の数」と「同じ文字が縦に並ぶ桁の数」の2つにする。** 3つの物差しで測った14案のうち、この2つがレベルの中で分かれ、2つが互いに重ならない（レベルの中の順位相関 −0.11〜−0.22）。条件は L3 を 3s（3つ足しで4桁まで）だけで作ること。L3 に 3l を混ぜると、文字の数と読みの量の順位相関が 0.56 から 0.80 に上がり、L3 の中で難易度の写しに近づく。
  - **文字の数**（`letters`。解き終えるまでに数字を入れる文字の数）: どのレベルでも3つの値に分かれる。ただし、いちばん多い値に 63〜86% が集まる（L1 は 5文字が 83%）。L1〜L3 では読みの量との順位相関が 0.47〜0.56 で、作業量の目安になる。一方、レベルを分けているのは読み方の段（難易度の資料 §2.4）なので、レベルの中で手筋を写しているわけではない。L4・L5 では 0.16・0.26。
  - **同じ文字が縦に並ぶ桁の数**（`repeatColumns`。答えの行も含め、右をそろえた1桁の中に同じ文字が2回以上出る桁の数）: 各レベルで4〜6つの値に分かれ、いちばん多い値は 32〜51%。読みの量との順位相関はどのレベルでも |0.18| 以下で、写しにならない。
- **成り立たない（使わない）: 足す数の数・答えの桁が増えるか・使われない数字の数。** 足す数の数はレベルの中で1つの値しかない（L1＝2、L2〜L5＝3）。答えの桁が増える問題は 96〜99%。使われない数字の数は 10−文字の数で、文字の数と同じ順位になる（順位相関 −1.00）。
- **盤面（筆算の大きさ）の軸は推奨しない。** 文字のマスの数（`cells`）は、レベルの中で3〜4つの値に分かれ、文字の数とも重ならない（0.17〜0.39）。ただし、L1〜L3 で読みの量との順位相関が 0.25〜0.51 あり、桁の数とはほぼ同じ順位（0.81〜0.95）、1%前後しかない値も出る。既存の値の形（`board-size` の行×列）で表すと、L4・L5 は 4行×6列 が 98〜99% になり分かれない。
- **値の書き方とまとめる幅:** どちらも `count`。文字の数は単位「種類」（ウォーターソートの「色 5種類」に合わせる）、桁は単位「か所」。値の種類はレベルごとに8以下なので（文字の数は `LETTERS6` の範囲で最大6種類、桁は答えの桁数＋1 で最大7種類）、`rangeWidth` は付けない。詰将棋の「手数」と同じ扱い。
- **測っている途中で見つけたこと:** [覆面算難易度](覆面算難易度.md) の調査で残した `s6_big.jsonl` の `level` は、場合分けの上限が3回だったときの出力だった。今の採る案（上限2回）で決め直すと、L5 106問のうち 59問が範囲外になる。決め直した L4 22・L5 47 は、`f6_sup` で同じ seed から決めたレベルと 2000問すべてで一致した。[覆面算供給実験](覆面算供給実験.md) でこのファイルの `level` を数えるときは、決め直しが要る。

## 事実と推測

- [事実] 図鑑の特徴は始めたときの盤面で分かるものに限る。値の種類が多い特徴は、パズルごとに決めた幅でまとめる: `docs/プロダクト/ゲーム/GAME-009-図鑑.md`「問題の特徴」「絞り込み」
- [事実] 値の種類が8以下なら値ごとに選択肢を出し、9以上のときだけ `rangeWidth` でまとめる。選択肢が1つしかない軸は出さない: `frontend/src/features/zukan/zukan-filter.ts`（`MAX_EXACT_COUNT_OPTION_COUNT`・`collectZukanLevelFeatures`）
- [事実] 値の形は `count` と `board-size` だけ。単位は「個・本・台・マス・か所・種類・手・枚」: `frontend/src/games/problem-feature.ts`、`frontend/src/components/problem-features.ts`
- [事実] 既存のゲームは「盤面」と数の特徴を1〜6軸持つ。「色 n種類」（ウォーターソート）、「手数」は `rangeWidth` なし（詰将棋）: `frontend/src/games/*/ui/problem-features.ts`
- [事実] 項目で問題を分ける図鑑の案は、項目が難易度の写しになったので採らなかった: `docs/adr/ADR-0004-zukan.md`
- [事実] 難易度の資料は、文字の数・桁の多さそのもの（作業量）を挑戦に入れない。レベルは規模と読み方の段の組（`CELLS6`）に、文字の数の範囲（`LETTERS6`）をかけて決める: `docs/パズル/導入調査/覆面算/覆面算難易度.md` §2.1・§2.4
- [事実] `s6_big.jsonl` の `level` には、今の採る案では範囲外になる場合分け3回の問題が L5 として 59問入っている: `fukumenzan_zukan.py measure` の `_level_now` が数えた
- [推測] 読みの量は、レベルを決めた弱い端の読み手が解き終えるまでに出す事実の数で近似した（L1 は NB6lo、L2 は Llo、L3 は Clo50 の閉包。L4・L5 は、場合分けの土台の閉包に、2回までの場合分けの各枝を閉包で読む事実を足した、いちばん少ない道）。難易度の資料 §2.2 の「1手」に合わせたが、閉包は読む順に依るので、人の最短の手ではない。順に依らない段の数でも符号と大きさの並びは同じだった（文字の数が最も高く、同じ文字が縦に並ぶ桁は0付近）。人の試遊の時間との順位相関を取れば確かめられる。
- [推測] 文字の数は遊ぶ人が「◯ を何個付けるか」としてすぐ分かり、短く遊ぶか長く遊ぶかを選ぶ切り口になる。同じ文字が縦に並ぶ桁は、筆算を見て最初に目に入る形の違いで、解きやすさの目安にはならない（読みの量と相関しない）。どちらも、遊ぶ人にとって意味がある切り口かは最終レビューで聞いて確かめる（add-puzzle の `final-review.md`「答える」）。
- [推測] 文字の数が 5 に寄るのは、使う数字の組を先に選んで全部を使い切る生成（digit-set-first）の性質で、レベル分けの性質ではない。生成を文字の数ごとに配分すれば、偏りは小さくできる（上の収率から見て、L1 の6〜7文字は作れる）。L2 の7文字（118問中1）は、今の生成では少ない。[覆面算供給実験](覆面算供給実験.md) の文字の数を固定した生成では収率が約1.75%で、実装前提調査 D-08 の配分（L2 の7文字 100 問）には約5700候補が要る見込み（推測）。

## 仮決定の候補

- 特徴の軸: 「文字」（`letters`、`count`・単位「種類」）と「同じ文字の桁」（`repeatColumns`、`count`・単位「か所」）の2軸 / 文字の数は遊ぶ人に最も分かりやすい作業量。同じ文字が縦に並ぶ桁は、どのレベルでも分かれ、難易度の写しにならず、文字の数と重ならない / 比べた案: 文字のマス（盤面の代わり。L1〜L3 で読みの量と 0.25〜0.51、桁とほぼ同じ順位、1%の値が出る）、いちばん多く出る文字の回数（分かれ方は良いが、2回目以降に出るマスや数の中の繰り返しと 0.3〜0.5 重なり、「何回」の単位が無い）、先頭に来る文字の数（L1 で2種類、遊ぶ人に意味が伝わりにくい）、文字の数だけの1軸（いちばん多い値が 63〜86% で、分ける力が弱い）、同じ文字の桁だけの1軸 / 覆すと `problem-features.ts`・`ui/problem-features.ts` とその試験だけ（zukan の項目の中で閉じる）
- 値の書き方: 「文字 7種類」「同じ文字の桁 2か所」。`rangeWidth` は付けない / 値の種類がどのレベルでも8以下で、`zukan-filter` はまとめない / 「7文字」のように単位「文字」を足す案（`ProblemFeatureCountUnit` を広げる共通の変更になる）、「列」を単位にする案（筆算では「桁」と呼ぶほうが自然） / 覆すと表示の定義と試験だけ
- 「同じ文字の桁」の数え方: 答えの行を含め、右をそろえた1桁の中に同じ文字が2回以上出る桁を数える / 筆算を縦に見たときに目に入る形そのもの / 足す数の中だけで数える案、文字の繰り返しを全体で数える案（2回目以降に出るマスと 0.8〜0.97 重なる） / 覆すと特徴の計算だけ
- L3 を 3s だけで作るか: 3s だけで作る（実装前提調査 D-06 で決め、[覆面算難易度](覆面算難易度.md) §8.3 も合わせた） / 3l を混ぜると、L3 の中で文字の数と読みの量の順位相関が 0.80 になり、文字の軸が難易度の写しに近づく / 3l を混ぜる（L4 を作る間に出る約950問を使える） / 覆すと L3 の問題集を作り直す。そのときは文字の軸を同じ文字の桁だけにするかを見直す
- 文字の数の偏り: 問題集の生成で文字の数ごとに配分するかは [覆面算供給実験](覆面算供給実験.md) に渡す。図鑑の側では、偏ったままでも軸は成り立つ（どのレベルでも2つ以上の値が出る） / — / 均等に配分する（候補のうち L1 になる割合は、4+3 の6文字 84%・7文字 30%、4+4 の6文字 24%・7文字 5%） / 覆すと生成の条件だけ

## 確かめていないこと

- 実際の問題集（各レベル500問）での分布: 問題集の配分（条件の比・文字の数・L3 の作り方）が実装で決まるため。ここでの割合は、条件を同じ数ずつ試して出たものを全部採った場合のもの。L2 は 118問、L4 は 102問しか標本が無い。
- 読みの量の近似が、人の解く時間や手と合うか: 人の試遊の記録が無いため。L4・L5 の枝は閉包で読んだので、弱い端の枝18手（sPN_18）とは違う。L5 の 53問は、閉包で読む枝なら1回で解ける。
- 遊ぶ人が「同じ文字の桁」を切り口として使うか、名前で意味が伝わるか: 画面がまだ無く、人が試していないため。最終レビューの「答える」で聞く。
- 図鑑の画面で2軸を出したときの見え方（ラベルの長さ、スマホでの並び）: 図鑑の画面は既存の共通部品で、実装の後に画面で確かめる。
