# 覆面算音

調査日: 2026-11-22。導入調査であり、今の決まりの正本ではない。仮決定は [覆面算実装前提調査](覆面算実装前提調査.md) の仮決定一覧を正とする。

この資料は、認識合わせで見せた文字×数字の表（空白→◯→× の巡回）を前提に測った。入力は実装前提調査 D-10 で札に変わり、巡回の順の推奨は意味を失った。札の形で鳴らす操作と本数は D-13 に書いた。

## 結論

- **どの瞬間に何を返すか: 成り立つ。** 鳴らす瞬間は3つの操作（◯を付ける＝文字に数字を当てる、×を付ける＝候補を消すメモ、空白に戻す）とクリアだけにする。`DESIGN.md`「音」に当てると、どれも盤面の印の操作が成立した前進か、その操作を取り消す向きの操作で、画面に変化がある。ひとつ戻す・最初から・知らせ（赤いマス・赤い下線）の出入りには鳴らさない。覆面算には、成立しない盤面操作も、ミスとして数える操作もない（途中で正誤を出さないと合意した）ので、不成立の音とミスの音は今のところ作らない。この割り当ては表の形に依らない。数字の札を押して当てる形に変えても、「文字を選ぶ」は対象を選ぶだけの操作なので鳴らさず、「当てる・メモ・外す」に同じ音を返せばよい。
- **素材: 条件つきで成り立つ。** 題材の「紙に書いた筆算に、鉛筆で ◯ と × を付けて解き、合えば花丸」から作れる。◯ は短い弧を描く擦れに小さな澄んだ芯、× は ◯ より乾いて短い2画、空白は消しゴムの柔らかな擦れ、クリアは右の桁から順に合っていく音と最後の和音、とする。ナンプレの数字の音とは素材で分かれる（推測。既存の音は聴いていない）。クリア音の形と時刻は、まだ決めていないクリア演出に合わせて決める。
- **回数: 合意した前提に影響する事実がある。** 称えたい解き方（× で候補を消し、決まってから ◯）を模した解き手では、× が ◯ の約7〜8倍になった（L5型の中央値で × 70個、◯ 10個）。見本のタップの巡回「空白→◯→×→空白」では × を付けるたびに ◯ を通るので、◯ の音が × とほぼ同じ回数鳴る（L5型の中央値で80回、そのうち最後まで残る ◯ は10回）。しかもそのうちの何割かでは、通りがかりの ◯ が赤い知らせ（使い回し・先頭の0）を一瞬出す。推奨は、巡回を「空白→×→◯→空白」にして ◯ の音を「当てた」瞬間に近づけること（タップも L5型の中央値で150回から90回に減る）。巡回の順はプレイUI（play-ui）で決める。どちらの順でも、◯ と × の音は回数の多い操作として小さく短く作り、`REPEATED_SOUND_VARIATION` を渡す。
- **大きさの目安: 成り立つ。** 既存は106本・631,265 バイトで、ゲームごとの中央値は9本・21,924 バイトだった。覆面算は **8本前後・20 KB 以下** にする。内訳は、操作の音3本（1本 0.05〜0.08 秒・2 KB 以下）とクリアの音5本前後（13 KB 前後）。足しても全体は約3%（約 0.65 MB）しか増えず、4秒の待ちの上限の中で転送し終えるのに要る帯域は 1.26 Mbps から約 1.30 Mbps に上がるだけ（転送だけを計算した値）。

## 事実と推測

- [事実] 鳴らす・鳴らさないの基準。盤面に付ける印の操作が成立したら鳴らし、外す向きもその手応えに含める。対象を選ぶだけの操作、待った・盤面を戻す・リセット、知らせのように表示され続ける状態には鳴らさない。正解かどうかで音を変えない。回数の多い操作ほど小さく短くし、同じ音を機械的に繰り返さない。ゲームの効果音は題材から作る: `DESIGN.md`「音」
- [事実] 印を巡回させて外す操作（空白へ戻す）にも音を返している前例がある（タクズの `emptied`、マインスイーパーの `flag-removed`）。ルール違反を表示しても、違反に別の音を付けていない（タクズ。PZL-005 は違反を控えめに知らせると決めている）: `frontend/src/games/takuzu/ui/use-takuzu-sound-effects.ts`、`frontend/src/games/minesweeper/ui/use-minesweeper-sound-effects.ts`、`docs/プロダクト/パズル/PZL-005-バイナリパズル.md`
- [事実] ナンプレの `mistake-entered` は、答えと違う数字を入れてミスに数えた入力に鳴らす。覆面算は途中で正誤を出さないと合意したので、この種の音は作れない: `frontend/src/games/nanpure/play/use-nanpure-play.ts`、[覆面算実装前提調査](覆面算実装前提調査.md)「認識合わせの合意」
- [事実] 効果音は FLAC で同梱し、アプリはタイトルで全部読み込み終えるまで（上限 4,000 ms）待つ。FLAC の合計が入るまでの待ちに効く。音の中身をコードで合成しない。盤面操作の音は `useOperationSound`、クリア音は `useClearSound` で完成演出の始まりに鳴らす。チュートリアルと遊び方の例も同じフックで鳴らす。結果の報酬・選ぶ・始める音と BGM はアプリが鳴らす: `.claude/rules/game-structure.md`「効果音」、ADR-0011、`docs/プロダクト/仕様/SPEC-005-アプリの入口.md`、`frontend/src/lib/app-launch.ts`
- [事実] 動きを減らす設定では、不成立の動きが出ず画面が何も変わらない操作の音と、完成演出なしですぐ結果へ進むときのクリア音を鳴らさない: `.claude/rules/game-structure.md`
- [事実] 既存の音は一度だけ合成して書き出している（ブリッジ・詰将棋・氷の床迷路のスクリプトは numpy と ffmpeg を使う）。詰将棋は CC0 の録音を加工した: `scripts/assets/bridges_sounds.py`、`docs/パズル/導入調査/氷の床迷路/氷の床迷路実装前提調査.md`、`docs/パズル/導入調査/詰将棋/詰将棋名称・権利調査.md`
- [推測] 鉛筆と紙の素材は、帯域を絞った雑音の擦れと短い減衰音で合成でき、録音の権利を扱わずに済む。作って聴いて確かめる。
- [推測] 空白→◯→× の巡回のまま ◯ に「当てた」手応えの音を付けると、聞こえる ◯ の音の約9割が × へ行く途中のものになり、前進の手応えの意味が薄れる。そのうえ通りがかりの赤い知らせと同時に鳴る。上の回数の計測から導いた。試遊で確かめられる。
- [推測] 指を速く動かして × を続けて付けると、0.08 秒を超える音は前の音と重なって濁る。既存の回数の多い音が 0.045〜0.08 秒に収まっていることから導いた。タップの間隔は計測していない。

## 仮決定の候補

- 鳴らす操作: ◯ を付ける・× を付ける・空白に戻す の3つとクリアだけにする / `DESIGN.md` の「印の操作の成立と、外す向き」に当たり、タクズ・マインスイーパーの前例と同じ / 比べた案: 空白に戻す操作を鳴らさない（巡回の中の1歩なので、無音だと押したのに反応がない1手になる） / 覆したときに作り直す範囲: 効果音のフックの分岐と、音1本
- 知らせに音を付けない: 赤いマス・赤い下線が出ても ◯ の音のまま。別の音にしない / 知らせは盤面の状態で、不成立でもミスでもない。巡回の途中で一瞬出ることも多い（L5の例で22回以上）。タクズは違反に音を付けていない / 比べた案: 知らせを出した ◯ に責めない短い音を返す（巡回の途中のたびに鳴って騒がしい。答えに迫ったかどうかを音で区別しないという決まりの線上にあるので、使うなら視覚の知らせと同じ意味に限る） / 覆したときに作り直す範囲: 操作の知らせに知らせの有無を足し、音1本を足す。採点（[覆面算採点の前提](覆面算採点の前提.md)）で知らせを出した操作をミスに数えると決めたら、ミスの音（不成立より一段重く、罰に聞こえない音。0.2 秒前後・4 KB 前後）を足す
- ◯ の音は数字で変えない: 1本に `REPEATED_SOUND_VARIATION` を渡す / ◯ の見た目はどの数字でも同じ印で、変えると10本に増える / 比べた案: 数字ごとに音の高さを変える（式の文字が数字になるので伝える意味はそろうが、大きさが増え、聞いた音から数字を探す遊び方を誘う） / 覆したときに作り直す範囲: 音の本数と、フックの分岐
- 巡回の順: 空白→×→◯→空白 をプレイUI（play-ui）へ推奨する / × が ◯ の約7〜8倍で、◯ の音を当てた瞬間にだけ鳴らせる。タップも約4割減る（L5型の中央値で150回から90回）。通りがかりの ◯ による一瞬の赤い知らせもなくなる / 比べた案: 見本どおりの空白→◯→×（◯ の音が × とほぼ同じ回数鳴り、その約9割は通りがかり） / 覆したときに作り直す範囲: 巡回の順は盤面の操作とチュートリアル・遊び方の文と図。音そのものは作り直さない（どちらの順でも ◯ と × を小さく短く作る）
- 素材と大きさ: 鉛筆と紙の音を一度だけ合成して FLAC（モノラル・16bit・48kHz）で同梱する。操作の音3本（0.05〜0.08 秒・各 2 KB 以下）と、クリアの音を右の桁から順の短い音4〜5本と和音1本（合わせて 13 KB 前後）。全部で 8本前後・20 KB 以下 / 既存のゲームの中央値（9本・21.9 KB）以下で、題材から作るという決まりに合う / 比べた案: ナンプレの音を流用する（`GAME.md`「やらないこと」と失敗パターン「そろえる所と当てはめる所の取り違え」に当たる）、クリアを長い1本にする（演出との時刻合わせがしにくい。ブリッジのようにクリアを大きくすると 100 KB を超える） / 覆したときに作り直す範囲: 合成スクリプトと音のファイルだけ
- クリア音の形: クリア演出が決まってから、その段の数と時刻に合わせる。右の桁から順の段を置くなら、段の音は桁数（L1 4桁〜L5 6桁）によらず固定の本数にし、タクズのように演出の長さへ割り付ける / 桁数で本数を変えると、L5 の6桁ぶん本数が増える / 比べた案: 桁ごとに1本（6本以上） / 覆したときに作り直す範囲: クリアの音のファイルと、フックの時刻計算

## 確かめていないこと

- 既存の音と、提案した素材の聞こえ方: 聴ける環境がなく、合成もしていない。ナンプレの音と素材で分かれるかは、作って聴き比べないと分からない。
- 音の大きさ（ピーク・RMS）: 標準ライブラリでは FLAC を復号できないので、バイト数と長さだけを測った。大きさは合成のときに、同じ頻度の既存の音に合わせる。
- 実際の人の × の付け方とタップの速さ: 解き手の模型による数で、試遊で確かめる。付け直し・空白に戻す回数は数えていない。
- 実際の回線での読み込み時間: 転送時間を計算しただけ。往復の待ち・同時接続の数・復号の時間は含めていない。
- クリア演出とクリア音の時刻、動きを減らす設定での扱い: 演出が未定。完成した盤面を見せ続けるなら、その姿に合わせたクリア音を `useClearSound` へ渡す。
- 1つの文字の行に2つ目の ◯ を付けたときの扱い（前の ◯ を外すか、拒むか）: プレイUI（play-ui）で決める。拒むなら、責めない短い不成立の音（0.14 秒前後・3 KB 前後）が1本増える。
