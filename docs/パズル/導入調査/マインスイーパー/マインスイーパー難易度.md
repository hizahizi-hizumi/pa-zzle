## 2. 前提として確定した条件

| 条件 | 内容 | 決定元 |
| --- | --- | --- |
| 推測不要 | 通常提供は、推測（確率判断）なしに最後まで論理的に確定させて解ける問題に限る | #339 で提案し、#342 の人間レビューで推測あり・救済方式と比較のうえ確定 |

### 2.2 最大盤面

**確定**: 最大盤面は **16行×12列**（縦長）とする。スマートフォン縦画面で、パン・ズームなしに盤面全体を表示・操作できることを条件とした。

本PRでの実ブラウザ比較とプレイ画面レビューで決めた。16×12 を実現するため、開く / 旗のモード切替を盤面下の2ボタンからヘッダー右上の1トグルへ移し、盤面に使える縦方向の領域を広げた。

計測結果（セル寸法は1マスの一辺、下端余白は盤面下端から表示領域下端まで）:

| 390×844 | 31.1px | 123px | 収まる |
| 375×667 | 29.8px | 44px | 収まる |
| 320×568 | 25.3px | 32px | 収まる |
| 1280×800 | 35.9px | 62px | 収まる |

タップ寸法を決めるのは行数ではなく列数である。390px 幅での列数とセル寸法は次のとおり。

### 2.3 盤面規模について決めていないこと

最大盤面が決まったことは、16×12 を提供範囲・標準盤面・難易度5の盤面にすることを意味しない。

- 最小盤面
- 提供する盤面形状（正方形、縦長、レベルや問題ごとに可変か）
- 地雷数・密度
- 初期開示領域の生成方法

は未決定である。これらは「どの盤面なら難易度1〜5の挑戦差を面白さを保って提供できるか」という難易度の意味から PR 7 / PR 8 で決める。盤面を大きくすることで高難易度帯を埋める設計はしない（[難易度提供.md](../../難易度提供.md)）。

## 3. マインスイーパー固有の挑戦

### 3.1 挑戦の定義

推測不要を前提とすると、マインスイーパー固有の挑戦は次のように定義できる。

> 見えている数字と総地雷数から、未開示マスのうち安全なもの・地雷であるものを論理的に確定させ、確定できる箇所を盤面から見つけ続けること。

この挑戦は二つの要素から成ると考える（仮説）。

1. **確定の推論**: ある箇所で、どの数字をいくつ組み合わせればマスを確定できるかを考えること。
2. **確定箇所の発見**: 盤面の境界（開示済み数字と未開示マスの接する線）のどこに確定できる箇所があるかを探すこと。

通常のマインスイーパーでは、確定手がない局面での確率判断も技能の一系統だが（[導入前提再調査.md](導入前提再調査.md) §3）、pa-zzle の通常提供ではこれを挑戦に含めない。

### 3.2 挑戦を強くするもの（仮説）

| 要因 | 内容 | 人間の挑戦が強まる理由 |
| --- | --- | --- |
| (a) 推論の幅 | 確定に同時に考慮すべき数字（制約）の数 | 同時に保持・照合する制約が増えるほど、作業記憶と組合せの検討が増える。単独の数字は「見れば分かる」が、3つ以上の数字の同時考慮は仮定を置いて整合を確かめる思考になる |
| (b) 推論の種類 | 単独の数字で完結 → 2つの数字の包含 → 2つの数字の重なり → 3つ以上の連鎖 → 総地雷数の利用 | 幅が同じでも、集合の関係が単純な包含（差を取るだけ）か、部分的な重なり（地雷数の上下限を考える）かで必要な思考が異なる。総地雷数の利用は局所から盤面全体へ視野を切り替える必要がある |
| (c) 探索の難しさ | 各局面で確定できる箇所が少ない（ボトルネック） | 確定箇所が多い局面ではどこを見ても進めるが、少ない局面では境界全体を見回して唯一の進め方を探す必要がある。ナンプレで「次に進める論理手の数」が難易度に影響する知見（Pelánek）の類推 |
| (d) 難しい局面の回数 | 高度な推論が1回だけか、繰り返し要求されるか | 1回だけなら偶然気付くこともあるが、繰り返し要求されると、その推論を使いこなすこと自体が問題の要求になる |

(b) は (a) の中の細分として扱える。(a)(b) は「1回の確定がどれだけ重いか」、(c)(d) は「その重い確定をどれだけ・どの状況で要求されるか」を表す。

### 3.3 挑戦にしないもの

次はそれ自体では難易度にしない（[難易度.md](../../難易度.md)「挑戦ではない負担を難易度にしない」）。

- 盤面の広さ（マス数、行数・列数）
- 地雷数・地雷密度
- クリック数・開示操作数（3BV を含む）
- 所要時間
- solver の探索量・探索時間・列挙した配置数

ただし規模が挑戦へ効く経路はありうる。

- 広い盤面ほど境界が長くなり、確定箇所の探索範囲が増える（(c) を強める方向）。
- 一方、広い盤面ほど確定できる箇所も増えやすく、ボトルネックが起きにくい（(c) を弱める方向）。
- 密度が高いほど大きな数字や数字同士の重なりが増え、(a)(b) を要する局面が出やすい。
- 盤面の縁（壁）の長さは、包含（L2）が起きやすい配置の量に関係する。

したがって規模指標は「難易度の根拠にしないが、特徴量が規模の代理になっていないかを検証する対照」として必ず併記する（[7.3](#73-規模の対照指標)、[9](#9-pr-6-で検証すること)）。

## 4. 基準とするプレイ条件

問題難易度は、次の条件で遊ぶプレイヤーを基準に比較する。

- ルールと基本操作（開示・旗・chord・モード切替）を理解している。
- 総地雷数（と自分の置いた旗数）を見られる。
- 旗は任意。確定した地雷を覚えておく手段として使ってよいが、旗の有無で問題難易度は変えない。
  - 分析上は、確定した地雷は「既知」として扱う（旗を置いたのと同じ情報）。旗を使わずに記憶で保持する負担はプレイ条件による体感差であり、問題難易度に含めない。
- ヒント・自動旗・確定手の提示を使わない。
- 確率判断をしない。確定したマスだけを開く。
- 1手ずつ論理的に確定させて進む。
- 時間制限なし。速さは難易度の基準にしない（速さの扱いはプレイ成績 #343 の責務）。

## 5. 人間の解法過程・手筋の調査

### 5.1 調査環境の制約

WebSearch（検索結果の要約）は利用できたが、WebFetch は調べた全ドメイン（chiark.greenend.org.uk、minesweepergame.com、cs.utoronto.ca、arxiv.org）で egress proxy により遮断された。そのため、以下の外部知見は検索結果要約・旧調査・一般知識に基づく。本文を一次資料で再確認できていない箇所は「要約」「未確認」と明記する。

### 5.2 戦略ガイドにあるパターン

コミュニティの戦略ガイドは、共通して次の手筋を挙げる。

| 手筋 | 内容（要約） | 出典 |
| --- | --- | --- |
| 単独数字（満たされた数字 / 埋まった数字） | 数字の周囲の既知地雷数が数字と一致すれば残りは安全。未確定マス数が残り地雷数と一致すれば全て地雷 | 各ガイド共通 |
| reduction（減算） | 既知の地雷を数字から差し引き、小さい数字として扱ってからパターンを探す。「旗が1つ隣にある3は実質2」 | https://minesweeper.now/help/patterns 、https://minesweepergame.com/strategy/patterns.php |
| 1-1 | 壁（盤端または開示済み領域）に接する2つの1。一方の1の未確定マスが他方に含まれるため、他方だけに接するマスは安全 | 同上、https://en.wikibooks.org/wiki/Minesweeper/Game_Patterns |
| 1-2（1-2-X） | 1と2が並ぶとき、2だけに接する側のマスは地雷。2が3マスに接し、そのうち2マスに1が接して地雷1個を持つため | https://minesweepergame.com/strategy/patterns.php |
| 1-1+ / 1-2+ | 1-1、1-2 の一般化。1の長い列（片側が壁）では、3つごとの1について最も近いマスに地雷がない、等 | 検索要約（minesweeper.online 系のパターン解説） |
| 1-2-1 | 並んだ 1-2-1 では両端の1の下が地雷、2の下が安全。1-2 を左右から2回適用した結果 | https://minesweeper.now/help/patterns 、https://rarepike.com/minesweeper/common-patterns/ |
| 1-2-2-1 | 並んだ 1-2-2-1 では中央の2つの下が地雷、外側が安全。1-2 と 2-1 の2回適用 | 同上 |
| パターンの連鎖 | 実盤面ではパターンが単独で出ることは少なく、1-1 で確定した地雷が近くの数字を減算し、新たな 1-2-1 を作る、という連鎖で進む | https://minesweepergame.com/strategy/patterns.php（検索要約） |
| 総地雷数 | 終盤、残り地雷数と残りマス数から確定する | Simon Tatham, Mines 説明書（旧調査）、https://www.chiark.greenend.org.uk/~sgtatham/puzzles/doc/mines.html |

ガイドの記述から読み取れること（仮説）:

- 人間は「数字の組合せ」を名前付きのパターンとして**かたまり（チャンク）で認識**している。1-2-1 は形式上は2つの数字の重なり推論を2回適用したものだが、熟練者にとっては一目で分かる1つの形である。
- パターンの多くは**壁際（盤端・開示済み領域の縁）**を前提にしている。壁があると未確定マスが減り、包含関係が成立しやすくなる。
- reduction は独立した手筋というより、他の手筋を適用するための**前処理**として説明されている。

### 5.3 Simon Tatham's Mines

- Mines は、最初の開示から最後まで推測なしに解けることを保証する盤面を生成する。推論には総地雷数を考える必要がある場合がある（出典: https://www.chiark.greenend.org.uk/~sgtatham/puzzles/doc/mines.html 、検索要約）。
- 生成器は「人間が行うのと同じ種類の推論」を行う solver を持つ。solver が途中で止まった場合、盤面を捨てずに、まだ開いていない領域の地雷を再配置して現在の境界で新しい推論が1つ以上できるようにする。これにより通常より高密度（16×16 に99地雷など）の盤面も生成できる（出典: https://www.chiark.greenend.org.uk/~sgtatham/quasiblog/mines-solver/ 、検索要約）。
- solver の推論は、「マス集合とその中の地雷数」を単位とし、集合の包含・差分から新しい集合を導く方式と理解している（旧調査・一般知識。本調査では一次資料未確認）。
- Tatham は、生成規則で盤面を過度に制約すると多様性を失うことを問題視している（[導入前提再調査.md](導入前提再調査.md) §3）。

pa-zzle への含意: 「人間と同じ種類の推論」を集合（制約）の組合せとして実装する方式は既存実装に実績がある。ただし Tatham の solver は生成保証のためのもので、推論の段階や必要な制約数を難易度として公開してはいない。

### 5.4 制約充足としてのマインスイーパー

- Studholme は、開示済み数字ごとに周囲の未開示マスへの制約を作り、変数を共有する制約同士を「結合」とみなして、結合した部分集合ごとに独立にバックトラック探索する方式を示した。確定マスがなければ、解の数から地雷確率を計算する（出典: https://www.cs.toronto.edu/~cvs/minesweeper/minesweeper.pdf 、検索要約）。
- Castillo & Wrobel は、マインスイーパーは「簡単に見えるが平均的な人間の成績は最適から遠く」、盤面上の空間関係に基づく論理・算術・確率の推論を要求すると述べている（出典: https://www.ijcai.org/Proceedings/03/Papers/079.pdf 、IJCAI 2003、検索要約）。

pa-zzle への含意: 完全性寄りの検証器は、Studholme と同じく「境界の連結成分ごとの厳密列挙」で実装でき、成分をまたぐ結合は総地雷数だけになる。

### 5.5 人間の難易度評価に関する研究

マインスイーパーについて、人間の解答時間や体感と推論構造を対応づけた研究は、今回の検索範囲では見つからなかった。近いパズルの知見を類推根拠として使う。

- Pelánek（ナンプレ）: 人間の解答時間に対し、ヒント数や計算機探索量の相関は弱く、人間向け論理手筋の複雑さと、各局面で次に進める論理手の数（依存構造）が効く。ヌリカベでは、制約を緩めたときの解の数・変数の固定度を見る「制約緩和」アプローチが r=0.9 と、人間の論理手筋ベース（r=0.8）より良い予測を示した（出典: https://arxiv.org/abs/1403.7373 、検索要約）。
- Wang, Wang, Sun（DiGRA 2012）: 人間志向の汎用的な難易度基準で、ナンプレ問題を平均解答時間に近い順序へ並べられた（出典: https://dl.digra.org/index.php/dl/article/view/615 、検索要約）。
- Espasa ほか（2021）: 最小不充足部分集合（MUS）の小さいものを順に使うことで、ペンシルパズルの人間向け段階的説明を作り、専門家の解説と平均89%一致した（出典: https://arxiv.org/abs/2104.15040 、検索要約）。「確定に必要な最小の制約集合の大きさ」を人間の推論の重さとして扱う考え方の根拠になる。
- コミュニティで「盤面の難しさ」として広く使われる 3BV は、勝つために必要な最小左クリック数であり、作業量の指標である（出典: https://minesweeper.now/faq/what-is-3bv-minesweeper 、検索要約）。pa-zzle では規模・作業量の対照として扱い、難易度にしない。
- No Guess 系サービスの説明では、No Guess の上級盤面でも 1-2-1 や部分集合推論、推論の連鎖が必要で「No Guess は簡単を意味しない」とされる（出典: https://www.minerace.io/no-guess 、https://minesweeperlab.com/no-guess-minesweeper/ 、検索要約）。一方、多くのサービスの難易度は依然として盤面サイズ・地雷数で区別されている（出典: https://minesweeper.now/faq/no-guessing-minesweeper 、検索要約）。

### 5.6 計算量の既知結果が通常規模で障害にならない理由

- Kaye（2000）: 与えられた局面に整合する地雷配置が存在するかの判定は NP 完全（Mathematical Intelligencer 22(2)、DOI: 10.1007/BF03025367）。
- Scott, Stege, van Rooij（2011）: 安全または地雷と確定できるマスが存在するかを問う推論問題は coNP 完全（DOI: 10.1007/s00283-011-9256-x）。FUN 2024 の論文は既存の困難性証明に意図しない推論が生じる欠陥を指摘し、修正した証明を与えている（出典: https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.FUN.2024.25 、検索要約）。

これらは任意サイズの盤面に対する最悪計算量の結果である。pa-zzle では次の理由から実用上の障害にならないと考える（仮説。PR 6 で計算時間を実測する）。

- 最大盤面は 16×12 = 192 マスで、未開示マスの上限が小さい。
- 厳密列挙が必要なのは境界の未開示マスだけで、しかも連結成分ごとに独立に扱える。成分をまたぐのは総地雷数の組合せだけで、成分ごとの「地雷数 → 配置数」表を畳み込めばよい。
- 推測不要の問題では、途中局面の境界は段階的に確定されるため、大きな未確定成分が長く残りにくい。
- 列挙量に上限を設け、超えた問題は「評価不能」または生成で棄却すればよい。計算の重さを難易度として扱わない。

### 5.7 手筋と分析段階の対応

[6](#6-分析モデル) の段階との対応。段階は「その確定に必要な最小限の推論」で決まり、手筋の名前では決まらない。

| 手筋 | 典型的な形 | 対応段階 | 備考 |
| --- | --- | --- | --- |
| 満たされた数字（残り地雷0） | 周囲の既知地雷数 = 数字 | L1 | chord で入力できる |
| 埋まった数字（未確定 = 残り地雷数） | 未確定マス数 = 数字 − 既知地雷数 | L1 | |
| reduction | 既知地雷を差し引いた残り地雷数で考える | 段階を上げない | 分析上は全制約を常に「未確定マスと残り地雷数」で表すため、前処理として吸収される |
| 1-1（壁際） | 1 {a,b}、1 {a,b,c} | L2 | {a,b} ⊂ {a,b,c} の包含。c が安全 |
| 1-2（壁際） | 1 {a,b}、2 {a,b,c} | L2 | 包含。c が地雷 |
| 1-2（開けた場所、1-2+） | 1 {a,b,c}、2 {b,c,d} | L3 | 部分的な重なり。{b,c} の地雷は最大1なので d が地雷、a が安全 |

| 1-2-2-1 | 同様 | L3 を2回 | |

| 派生制約の再利用 | 2つの数字から作った「この2マスに地雷1」を別の数字と組み合わせる | L4 | 派生制約を介すると、元の数字は3つ以上になる |
| 総地雷数 | 終盤の残り地雷数 = 0、残り地雷数 = 残りマス数、境界の最小地雷数と総数の比較 | L5 | [6.6](#66-モデルへの指摘と改善提案) の指摘を参照 |

## 6. 分析モデル

### 6.1 用語

- **マス**: 盤面の1セル。
- **既知**: 分析上、安全または地雷と確定したマス。安全と確定したマスは開示され、数字を与える。
- **制約**: 開示済みの数字1つについて、「周囲の未確定マスの集合 S に、残り地雷数 r 個がある」という条件。r は数字から周囲の既知地雷を引いた値。未確定マスがなくなった制約は消える。
- **境界**: いずれかの制約に含まれる未確定マス。
- **内部**: どの制約にも含まれない未確定マス。
- **総地雷制約**: 「全未確定マスに、総地雷数 − 既知地雷数 個がある」という条件。

### 6.2 段階（手筋レベル）

| 段階 | 名前 | 定義 |
| --- | --- | --- |
| L1 | 単独 | 1つの制約だけで確定する（r = 0 なら S は全て安全、r = \|S\| なら全て地雷） |
| L2 | 包含 | 2つの制約 A, B で S_A ⊆ S_B のとき、差 S_B \ S_A に r_B − r_A 個の地雷があることから確定する（0 なら全て安全、\|S_B \ S_A\| なら全て地雷） |
| L3 | 重なり | 2つの制約の未確定集合が部分的に重なり、共通部分の地雷数の上下限から確定する |
| L4 | 連鎖 | 3つ以上の制約を同時に考えないと確定できない局所推論。必要な最小の制約数を**推論幅**として記録する |
| L5 | 総地雷数 | 総地雷制約を使わないと確定できない推論 |

### 6.3 進め方

1. 初期開示状態から始める。0 の連鎖開示は開示処理として自動で行う（推論ではない）。
2. 各局面で、確定できる未確定マスを段階ごとに求める。
3. **最も低い段階で確定できるマスを全て同時に**確定し、安全マスを開示する（地雷は既知にする）。これを1ラウンドとする。
4. 全非地雷マスが開示されるまで繰り返す。

この進め方は、確定の探索順・tie-break に依存しない。ある段階で確定できるマスの集合は局面だけで決まり、その集合を全て同時に適用するためである。

人間が1手ずつ進めることとの違い（仮説）: ラウンドは「同じ局面から同時に見つけられる確定」をまとめた単位であり、ラウンド数は確定の依存関係の深さに相当する。人間の実際の手順とは一致しないが、手順の選び方によらない比較の単位になる。

「最も低い段階を優先する」ことにより、あるラウンドで L3 以上を使ったことは「その局面では、盤面のどこにも L2 以下で確定できるマスがなかった」ことを意味する。段階は「どこかで使えた」ではなく「その局面で使わざるを得なかった」推論として記録される。

### 6.4 完全性寄りの検証器

人間モデルとは独立に、各局面で「可視情報＋総地雷数から論理的に確定できるマス」を厳密に求める。

1. 境界を、制約を共有する未確定マスの連結成分へ分ける。
2. 成分ごとに、全制約と矛盾しない配置を列挙し、成分の地雷数ごとの配置数と、各マスが地雷になる配置数を数える。
3. 内部マス数 n と残り総地雷数 R から、各成分の地雷数の組合せ k_1..k_m のうち 0 ≤ R − Σk_i ≤ n を満たすものだけを許し、内部の配置数 C(n, R − Σk_i) を重みとして畳み込む。
4. 許される全配置で安全なマス・地雷であるマスを確定とする。内部マスも同様に判定する。

検証器で確定マスが1つもない局面が途中に現れる問題は「推測が必要」、最後まで確定を続けられる問題は「推測不要」とする。既知情報は単調に増えるだけなので、確定したマスをどの順で開いても結論は変わらない。

列挙量には上限を設け、上限を超えた問題は成立性を判定できないものとして扱う（生成なら棄却）。

### 6.5 4状態

| 状態 | 条件 | 扱い |
| --- | --- | --- |
| 成立しない | 検証器でも推測が必要な局面がある | 通常提供しない |
| 成立するが評価不能 | 検証器では最後まで確定できるが、人間モデルの段階・推論幅の上限を超える局面がある、または計算を打ち切った | 高難易度と推定しない。通常提供しない |
| 評価可能だが提供範囲外 | 人間モデルで最後まで確定でき特徴量も得られるが、提供範囲外 | PR 7 で基準を決める |
| 1〜5へ分類可能 | 人間モデルで評価でき、提供範囲内 | PR 7 で分類方法を決める |

この区別により、「計算機にとって重い」「人間モデルで説明できない」問題を難易度5へ押し込まない（[難易度判定.md](../../難易度判定.md)「判定できない問題と提供範囲外の問題を分ける」）。

### 6.6 モデルへの指摘と改善提案

上記モデルを文書化するにあたっての問題点と改善案。PR 6 の実装・検証で扱う。

#### (1) 段階と推論幅は「制約を組み合わせた厳密判定」で統一して定義する

L1〜L4 を手筋ごとの個別規則で実装すると、規則の書き方で取りこぼしが生じ、段階が実装依存になる。次のように定義すると、全段階を同じ方法で判定できる。

- **推論幅 k**: あるマスの値を、境界の制約のうち k 個（互いに未確定マスを共有して連結なもの）の同時充足だけから確定できる最小の k。k 個の制約の和集合の配置を厳密に列挙して判定する。
- L1 = k=1、L2 / L3 = k=2（2制約の関係が包含か重なりかで区別）、L4 = k≥3、L5 = 局所制約だけでは確定できず総地雷制約が必要。

これは「確定に必要な最小の制約集合」（Espasa ほかの MUS）と同じ考え方で、推論幅を実装の規則の数ではなく問題の性質として定義できる。L4 の探索は k の上限（例: 4〜5）を設け、上限を超えたら評価不能とする。

注意点:

- 数字の数ではなく、reduction 後の**異なる制約**の数で数える。別々の数字が reduction 後に同じ制約になる場合は1つとする。
- 2つの数字から作った派生制約（「この2マスに地雷1」）を第3の数字と組み合わせる推論は k=3 になる。人間はこれを「1-2 を見てから次を見る」段階的操作として行うため、同じ k=3 でも「派生制約を順に使う連鎖」と「3つを同時に仮定して整合を確かめる推論」の体感は異なりうる。PR 6 では k だけでなく、k 個の制約で確定する際に途中の派生制約で分解できるか（2制約推論の繰り返しで到達できるか）も記録することを提案する。

#### (2) L2 と L3 の区別が人間の体感と合うかは不確か

- ガイドでは壁際の 1-2（L2）と開けた場所の 1-2（L3）を同じ「1-2」として教えている。人間は包含と重なりを区別するより、形として認識している可能性がある。
- 1-2-1 は L3 の2回適用だが、最も有名なパターンとして暗記されており、未知の形の L2 より速く見つかることがありうる。
- L2 が成立しやすいのは壁際（盤端・開示済み領域の縁）なので、L2 / L3 の比率が盤面形状・縁の長さの代理になる恐れがある。

提案: PR 6 では L2 / L3 を別々に記録するが、**難易度の軸としては最初から序列を固定せず**、「k=2 の推論」として合算した場合と分けた場合の両方で分布を確認する。L2 と L3 を分けて使うのは、実プレイ（PR 7）で体感差が確認できた場合に限る。

#### (3) L5 には軽いものと重いものが混ざる

総地雷数の利用には、

- 終盤に残り地雷が0で、残りを全て開くだけのもの
- 残り地雷数 = 残りマス数で、全て地雷と分かるもの
- 境界の成分ごとの最小・最大地雷数を総数と比べて、内部マスや別成分を確定するもの

がある。前の2つは L1 と同程度に自明で、最後のものは局所推論より重い。L5 を一律に最高段階とすると、「最後に残り0で全部開いた」だけの問題が最高段階を持つことになる。

提案: 総地雷制約を「盤面全体に1つある制約」とみなし、L5 の中でも「総地雷制約単独で確定（L5-自明）」と「総地雷制約＋局所制約 k 個で確定（L5-結合、局所側の推論幅を併記）」を分けて記録する。最高段階の比較では L5-自明を L1 相当として扱う候補とする。

#### (4) ボトルネックの測り方は「マス数」ではなく「確定の発見箇所数」を主にする

1つの L1 で5マスが同時に安全になる場合、人間にとっては1つの発見である。マス数で数えると、数字が小さく未確定マスの多い箇所ほど「選択肢が多い」ことになり、Pelánek の「次に進める手の数」とずれる。

提案:

- **利用可能手数（発見単位）**: その局面で最低段階の確定を与える、互いに異なる最小制約集合の数。同じ制約集合から確定する複数マスは1つと数える。
- **利用可能手数（マス単位）**: 最低段階で確定できる安全マス数。地雷だけの確定は開示を進めないため、安全マスと地雷マスを分けて記録する。
- **ボトルネック**: 利用可能手数（発見単位）が1の局面。

両方を記録し、PR 6 の問題集合でどちらが規模の代理になりにくいかを比較する。

また、盤面が広いほど境界が長く利用可能手数が増えやすいため、絶対数は規模の代理になりやすい。境界の制約数に対する比（利用可能手数 / 境界の制約数）も併記し、規模との相関を比較する。

#### (5) 最低段階優先はボトルネックの定義と一体である

最低段階を全て適用する進め方では、L1 が盤面のどこかに残る限り、別の場所の L3 は後回しになる。後回しにした箇所は、別の場所の進展で開示された数字が加わり、後から L2 以下で確定できるようになることがある（境界の成分は総地雷数以外では直接影響し合わないが、開示で新しい数字が現れると成分が結合しうる）。このとき、その箇所の L3 は「必要だった」とは記録されない。この性質から、「L3 以上を使ったラウンド」は「盤面全体で他に進める手がなかった局面」と一致し、(c) のボトルネックと (b) の推論の種類が同じ局面で観測される。これは意図どおりだが、両者を独立した特徴量として扱うと二重計上になりうるため、PR 7 で相関を確認する。

#### (6) 空間的な距離は推論幅で表せない

同じ k=3 でも、3つの数字が隣接している場合と、境界に沿って離れている場合で見つけやすさは異なりうる。PR 6 では推論に使った制約の外接矩形の大きさを補助的に記録し、推論幅と独立した情報を持つかを確認する候補とする。

#### (7) 初期開示の扱い

初期開示領域の広さは問題が持つ条件であり、推論ではない。初期開示で盤面の大半が開く問題は、挑戦が軽いというより挑戦がほとんどない問題になりうる。これは難易度ではなく「提供範囲の下限」（挑戦が成立しているか）の判断材料として PR 7 で扱う。

## 7. 特徴量の仮説

### 7.1 挑戦の特徴量候補

| 特徴量 | 定義（案） | 値が変わると人間の挑戦がなぜ変わるか | 対応要因 |
| --- | --- | --- | --- |
| 最高段階 | 解き切るまでに使った最も高い段階 | その問題を解くには、少なくともその種類の推論を理解し実行できる必要がある。L3 を必要とする問題は、単独数字と包含だけで解ける問題より強い推論を要求する | (b) |
| 段階ごとの必要ラウンド数 | 各段階を使ったラウンドの数 | 同じ最高段階でも、それを何回要求されるかで、推論を使いこなす必要の強さが変わる | (b)(d) |
| L3以上ラウンド数 | L3 / L4 / L5-結合を使ったラウンドの数 | 2つの数字の単純な差では済まない局面の回数。1回だけなら偶然の発見で越えられるが、繰り返すと推論の習得が要求される | (d) |
| 推論幅の最大 | 全ラウンドで必要とした推論幅 k の最大 | 同時に保持・照合する制約の数の上限。作業記憶の要求の上限 | (a) |
| 推論幅の分布 | k=1, 2, 3, 4… のラウンド数 | 最大値だけでは、重い推論が1回か常態かを区別できない | (a)(d) |
| 利用可能手数の平均 | 各ラウンドの利用可能手数（発見単位 / マス単位）の平均 | 確定箇所が多いほど、どこを見ても進めるため探索の負担が小さい | (c) |
| 利用可能手数の最小 | 同上の最小 | 最も探しにくい局面の厳しさ | (c) |
| ボトルネック回数 | 利用可能手数（発見単位）が1のラウンド数 | 盤面全体から唯一の進め方を探す局面の回数 | (c)(d) |
| 総地雷数利用 | L5-自明 / L5-結合の有無と回数 | 局所の数字から盤面全体の数え上げへ視野を切り替える必要があるか | (b) |
| ラウンド総数 | 解き切るまでのラウンド数 | 確定の依存関係の深さ。深いほど、前の確定の結果を使って次を考える段数が多い。ただし規模の代理になりやすく、単独では使わない | (d)、要検証 |

### 7.2 特徴量の扱い

- いずれも仮説であり、現在仕様として確定しない。
- 単一の加算スコアへ最初からまとめない。最高段階・推論幅という「1回の確定の重さ」と、ラウンド数・利用可能手数という「要求の繰り返し・探索の厳しさ」を別の観点として保持する（[難易度判定.md](../../難易度判定.md)「必要な次元を一つの数値へ無理に潰さない」）。
- ナンプレの `dependency-v1` のように序盤 N 手に限定するかは、ラウンド数の分布を見て PR 6 / PR 7 で判断する。

### 7.3 規模の対照指標

次は難易度にしない。特徴量が規模・作業量の代理になっていないかを確かめるための対照として、全問題で記録する。

| 対照指標 | 内容 |
| --- | --- |
| マス数 | 行数 × 列数（および行数・列数） |
| 地雷数 | 総地雷数 |
| 密度 | 地雷数 / マス数 |
| 初期開示数 | 初期開示状態で開いている安全マス数 |
| 開示すべき安全マス数 | 全安全マス数 − 初期開示数 |
| 3BV（参考） | クリアに必要な最小開示操作数 |
| 盤端に接するマスの割合 | 形状（縦長・正方形）と壁の量の対照 |
| 検証器の列挙配置数・計算時間 | solver 探索量の対照 |

## 8. 問題成立性・旧PoC

### 8.1 問題成立性と難易度の分離

| 責務 | マインスイーパーでの内容 |
| --- | --- |
| 問題成立性 | 盤面サイズ・地雷配置・総地雷数・初期開示状態が整合していること（初期開示に地雷がなく、0 の連鎖開示と矛盾しない等）。検証器で最後まで推測なしに確定できること |
| 難易度分析 | 人間モデル（段階・推論幅・ラウンド）で解き、特徴量を記録する。人間モデルで解けなければ評価不能 |
| 難易度分類 | 評価可能・提供範囲内の問題を1〜5へ分類する（PR 7） |
| 問題供給 | 目的の難易度の問題を生成・選択する（PR 8） |

推測不要であることは成立性の条件であり、難易度ではない。「検証器でしか確定できない」ことを高難易度の根拠にしない。検証器と人間モデルを独立に実装することで、人間モデルの不具合（本来確定できない所で確定する誤り）を検証器との照合で検出できる。人間モデルが確定したマスは、必ず検証器でも確定していなければならない。

### 8.2 旧PoCから再利用する証拠と捨てた前提

[導入前提再調査.md](導入前提再調査.md) §10 の再評価を踏まえ、難易度に関わるものだけを整理する。

| 旧調査の内容 | 本書での扱い | 理由 |
| --- | --- | --- |

地雷数は `round(マス数 × 密度)` で決めるため、実際の密度は指定値から少しずれる（例: 12×10 の 0.12 は14地雷で 0.117）。seed は `ms-<行>x<列>-<地雷数>-<番号>` で、生成は `maximumAttempts: 1`（1 seed = 1候補）とした。したがって「評価可能」の割合は、無作為配置の候補1つが採用される率、つまり生成・検証・棄却での No Guess 採用率に当たる。

### 9.2 確認項目

1. **規模への依存**: 各特徴量と対照指標（マス数・地雷数・密度・初期開示数・開示すべき安全マス数・3BV）の順位相関。特にラウンド総数、段階ごとのラウンド数、利用可能手数の絶対値。
2. **特徴量同士の重複**: 特徴量同士の順位相関。実質的に同じ量を測っているものがないか（例: ボトルネック回数と L3以上ラウンド数）。
3. **探索順への非依存**: 同じ問題で、(i) ラウンド一括適用、(ii) 最低段階の確定から1マスずつ無作為順に適用、の2方式で最高段階・推論幅・段階ごとの推論回数がどれだけ変わるか。
4. **盤面の対称変換への不変性**: 盤面を回転・反転した問題で特徴量が一致するか（再現性と実装の健全性）。
5. **人間モデルと検証器の整合**: 人間モデルが確定したマスがすべて検証器でも確定しているか。人間モデルで評価不能になる問題の割合と、その原因（推論幅の上限、L5-結合、計算打ち切り）。
6. **計算時間**: 最大盤面 16×12 での人間モデル・検証器の1問あたり時間と、列挙上限に達する割合。

### 9.3 再現手順

状態の内訳と、問題ごとの特徴量・規模指標は、分析スクリプトで再現できる。A の例:

```sh
bun run --cwd frontend analyze:minesweeper -- --output <出力先>/A \
  --sizes 5x5,7x7,9x9,10x8,12x10,12x12,14x10,16x12 --densities 0.12,0.15,0.18,0.21 \
  --seeds 1000 --start random --jobs 4
```

B・C・S は `--sizes` / `--densities` / `--start` を 9.1 の条件に替える。出力（`.jsonl` / `.csv`）はリポジトリに入れない。

次の集計は分析スクリプトの出力に無いため、本検証では一時的な集計スクリプトで求めた。再現するときは同じ seed で問題を再生成し、次の定義で求める。

| 集計 | 定義 |

| 3BV | 初期開示後に残る安全マスについて、未開示の0領域の数 + 0領域に接しない未開示の非0安全マスの数 |

### 9.8 生成条件で帯が分かれていないか

- **盤面サイズ**: 密度を揃えると、最高段階・L3以上ラウンド数・L3以上比の分布は 5×5〜16×12 でほぼ同じだった（ε² ≤ 0.008、最高段階1の割合は 39〜53%）。サイズで変わるのはラウンド総数・L1ラウンド数・発見数の平均で、これらは規模の代理である。挑戦の特徴量で分類すれば、盤面サイズだけで別の帯へ分かれることはない。
- **密度**: 分布を大きく動かすが、帯は分けない。12×10 では、最高段階1の割合が 81.8%（0.10）から 5.0%（0.25）まで動く。それでも、どの密度にも L1 だけの問題と L3以上を含む問題の両方がある。密度は「その挑戦を持つ問題の出やすさ」を変えるもので、密度で帯が決まるわけではない。
- **開始位置**（S と A の比較）:
  - center は初期開示を広げる（12×10・0.15 の中央値 36 → 49、10パーセンタイル 16 → 24）。
  - 採用率は多くの条件で0〜7ポイント上がった。16×12・0.12 だけは 91.6% → 88.4% に下がった。
  - 最高段階3以上の割合と総地雷数 combination の割合は上がった（12×10・0.15 で 16.1% → 20.9%、9.7% → 12.1%）。
  - 開始位置で分布は動くが、帯を分けるほどではない。
  - center で combination が増える理由は、盤端・角が最後まで残りやすいためと推測する（未検証）。
- **形状**（C）:
  - 同じマス数・密度では、最も細長い 14×7 で L2 と L3 の絶対数がやや増え、最高段階3以上の割合も上がった（約100マス・0.15 で 10×10 17.5% / 12×8 14.0% / 14×7 21.2%）。
  - L2 / (L2 + L3 + L4) の比は形状でほとんど変わらなかった（0.15 で 0.93 / 0.93 / 0.91、0.21 で 0.84 / 0.85 / 0.82）。壁が多いほど L2 が増えるという懸念（6.6 (2)）は、この範囲では観測されなかった。
  - 形状が大きく効くのは採用率である（9.4）。

### 9.12 結論と PR 7 への申し送り

#### 挑戦の観測に使えそうな特徴量（実測に基づく）

- **最高段階**、**L3 / L4 ラウンドの有無と回数**、**総地雷数 combination の有無**は、盤面サイズからほぼ独立だった（マス数との順位相関 ≈ 0、サイズによる ε² < 0.01）。挑戦の種類（推論の重さ）を観測する主軸の候補になる。
- 密度とは中程度に相関する（0.3〜0.46）。3.3 の想定どおり、密度は数字同士の重なりを増やして挑戦へ効く経路である。PR 7 で分類へ使うのは特徴量であり、密度ではない。

#### 規模・長さの代理で、単独では使わないもの（実測）

- **ラウンド総数**、**L1ラウンド数**: 3BV・開示すべき安全マス数の代理。
- **発見数の平均**: 盤面サイズの代理（マス数と 0.52）。
- **ボトルネック回数**、**場所1ラウンド数**: 問題の長さの代理（条件内でラウンド総数と 0.80 / 0.87）。
- **正規化した指標**（ボトルネック比、発見数/frontier制約数）: マス数への依存は弱まるが、ラウンド総数との相関（条件内 ±0.62）が残る。探索の厳しさを規模から独立に測れているとは言えない。使うなら同じ盤面サイズ・密度帯の中の比較に限る（推測）。
- **推論幅の最大**: 最高段階とほぼ同じ量（0.85）。k≥3 は全体の1.3%しかない。L4 の内訳としてだけ残す。
- **矩形幅**: 段階と独立な情報は観測できなかった。記録は続けてよいが、特徴量候補からは外す提案とする。

#### 6.6 の指摘への実データでの回答

| 指摘 | 実データでの回答 |
| --- | --- |
| (1) 厳密判定での統一 | 人間モデルの確定は、全ラウンドで検証器の確定に含まれた。k > 5 で評価不能になる問題は0.05%。推論幅の上限5は、この条件範囲では提供を妨げない |
| (2) L2 / L3 の区別 | L2 の比率は壁の量（形状）の代理になっていなかった。L2 ラウンド数は長さと相関する（条件内 0.53）が、L3 は相関が弱い（0.14）。体感差は未検証のまま PR 7 の実プレイへ送る |
| (3) L5 の軽重 | combination の L5 は評価可能問題の3〜42%と多い。そのほとんどは終盤（未確定マス中央値6、残り地雷中央値2、65%が最終ラウンド）の数え合わせだった。L5 を一律に最高段階とすると、L3 / L4 を一度も使わない問題が最上位に来る（最高段階5の問題の79%は L3 / L4 を含まない）。PR 7 では L5 を L3 / L4 とは別の軸として扱うことを提案する。L3以上ラウンド数も「L3 / L4」と「L5」に分ける。L5 の中の軽重を未確定マス数や成分数で分けられるかは実プレイで確かめる（推測） |

#### 提供範囲（盤面サイズ・密度の候補領域）への示唆

- **盤面サイズ**: 同じ密度なら、挑戦の特徴量の分布は 7×7〜16×12 で変わらない。大きい盤面は長さ（ラウンド数・作業量）を増やすだけである。盤面を大きくしても高難易度にはならないという[難易度提供.md](../../難易度提供.md)の方針と整合する。盤面サイズはプレイ時間・操作性・採用率で選べる（推測）。5×5 は挑戦が薄いため、最小盤面は 7×7〜9×9 付近から検討する（PR 7 で決める）。
- **密度**: 0.10〜0.12 では大半が L1〜L2 だけの問題になる（最高段階1が63〜86%）。0.18〜0.21 で L3 / L4 を含む問題が20〜33%になる。0.23 以上は採用率が17%以下で、供給効率が悪い。高い難易度の候補領域は 0.18〜0.21 付近になる見込み（推測）。
- **形状**: 細長い盤面（14×7 など）は採用率が下がる。挑戦の特徴量への影響は小さい。

#### No Guess 採用率と供給上の懸念

- 生成・検証・棄却での採用率は、密度0.15で約75%、0.18で約50%、0.21で約25〜34%（9.4）。1候補2〜3ms なので、L1〜L3 の問題は棄却方式で十分に供給できる（推測: ブラウザでは数倍遅い可能性がある）。
- 評価可能問題のうち最高段階4は0.3〜2.3%。採用率を掛けると候補の0.2〜0.8%で、1問に100〜500候補が要る。L3 を3回以上含む問題は約2.3万問中33問と、さらに少ない。
- 「L4 を含む」「L3 を複数回含む」を高難易度の条件にすると、棄却方式だけでは供給が細い。PR 8 では Tatham 型の局所修正などの生成方式を比較する必要がある。成立しない問題の大半は途中（中央値9ラウンド目）で止まっており、局所修正で救える余地がある（推測）。

#### 分析モデルと本検証の限界

- 候補は無作為配置と棄却だけで作った。局所修正などの別の生成方式では、特徴量の分布（特に L4・L5 の頻度）が変わりうる。
- 人間の実プレイとの照合はしていない。L2 と L3 の体感差、L5 の軽重、ボトルネックの見つけにくさは、すべて仮説のままである。
- 高密度の条件は評価可能な問題数が少ない（16×12・0.25 は37問）。その条件の割合は幅を持って読む必要がある。
- L5 の性質は4条件336ラウンドの標本、適用順の比較は3サイズ × 3密度の1,381問で確認した。
- 計算時間は Bun / Linux で測った。ブラウザでの時間は PR 8 で測る。
