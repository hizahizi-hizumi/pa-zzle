# タクズ難易度

タクズ（利用者向けの表示名は「バイナリパズル」）の `難易度 1`〜`難易度 5` を、[難易度開発手順.md](../../難易度開発手順.md) の工程2〜10 に沿って組み立てた検討記録。

## 1. 目的と位置づけ

[タクズ導入前提調査.md](タクズ導入前提調査.md)（以下「前提調査」）§11 で立てた難易度の仮説を、製品コードの人間向け解法器と数千問の問題集合で確かめる。そのうえで、5段階の分類案を比べて推奨案を決め、人間が試遊で確かめるための代表・境界・異常な問題を残す。

この文書は現在仕様の正本ではない。採用した契約だけを、正本化の段階で `docs/プロダクト/仕様/パズル/` のバイナリパズル仕様へ移す。試した案、採用しなかった案、暫定の閾値、比較結果はこの文書に残す。

根拠は前提調査と同じ見出し語で区別する。

- **事実（実測）**: 本書 §6 の問題集合・§14 の問題集と、コミット済みの分析・生成スクリプトで測った結果。
- **導出**: 定義から論理的に導けること。
- **推測・仮説**: 実プレイで確かめていない判断。

この段階でまだ誰も実際に遊んで確かめていない。§10 の試遊が済むまで、各レベルの体験差は仮説として扱う。

## 2. 前提として引き継ぐ条件

前提調査 §16「仮決定一覧」から、難易度に関わるものを引き継ぐ。

| 条件 | 内容 |
| --- | --- |
| 盤面 | 全難易度で 8×8 に固定する。サイズを難易度にしない |
| ルール | 各行・各列で2種類が同数、同じタイルは3つ続かない、同じ並びの行どうし・列どうしを禁止 |
| 問題成立性 | 一意解であること。推測なしに解けることは別の条件として確かめる |
| 補助 | ヒント、自動補助、行・列の個数表示、元に戻すは提供しない |
| 誤りの表示 | 盤面だけから分かるルール違反（3連続、個数超過、完成した行・列の重複）はその場で示す。解答との照合は示さない |
| 基準とするプレイ条件 | ルールとタップ巡回の操作を理解している。違反の印に頼らずに盤面を読んで確定マスを置く。仮置きと後戻りはしない（前提調査 §11.2） |
| 供給 | 事前生成した問題集から出題する（問題集は §14） |

## 3. タクズ固有の挑戦

### 3.1 挑戦の定義（仮説。前提調査 §11.1 のまま）

> 盤面から次に確定できるマスを見つけ出し、局所の形で決まらないときは、行・列全体の残り個数や完成済みの行・列との比較まで読んで確定させること。

### 3.2 挑戦を強くするもの（仮説）

1. **必要な読みの種類**: 隣り合う3マスの形で決まるか。行の個数を数える必要があるか。行に残る1個の置き場所を読むか。完成済みの行と見比べるか。残りの多い行の並びを読み比べるか。
2. **読みが要る局面の数**: 深い読みを1回すれば後は流れるのか。流れが止まって、また深い読みが要る局面が来るのか。
3. **見つけにくさ**: その局面で確定を与える場所が盤面にいくつあるか。1か所しかない局面では、盤面を見渡して探す負担が大きい。

### 3.3 挑戦にしないもの

- 盤面サイズ（8×8 固定）。
- 空きマスの数、ラウンド数（連鎖の長さ）、タップ回数、所要時間。これらは作業量で、それだけでは難易度の根拠にしない。
- 2種類のタイルの見分けにくさ、セルの押しにくさ（UIで除く）。

## 4. 分析モデル（人間向け解法器）

実装は `frontend/src/games/takuzu/problem/generation/human-solver.ts`。問題成立性の確認は `generation/solver.ts`（完全探索）、特徴量の導出は `problem/difficulty-analysis.ts`、分類は `difficulty.ts` が持つ。

### 4.1 手筋

どの手筋も、1本の行・列の中だけで読む推論である。

| 記号 | 手筋（コード上の名前） | 内容 | 人間向けの言い換え |
| --- | --- | --- | --- |
| A | 隣接・挟み（`adjacency`） | 3マスの並びに同じタイルが2つあり、残る1マスが空きなら、そこは反対のタイル | 並んだ2つの両隣・挟まれた1つを埋める |
| B | 個数の完成（`count-completion`） | 行・列に片方のタイルが半分そろえば、残りの空きマスは反対のタイル | 行のタイルを数えて、足りた方の反対で埋める |
| C | 残り1個（`single-remaining`） | 片方のタイルが残り1個の行・列で、ルールを満たす並び（2種類が半分ずつ、3つ続かない）をすべて並べ、どれでも同じになるマスを確定する | 残り1個をどこに置けるかを読む |
| D | 重複の回避（`duplicate-avoidance`） | C と同じ行・列で、完成済みの行（列）と同じ並びになる置き方も除いて確定する | 完成した行と同じ並びにならないよう読む |
| E | 一般の行候補（`general-line`） | 両方のタイルが残り2個以上の行・列で、ルールを満たし完成済みの行・列とも重ならない並びをすべて比べて確定する | 残りの多い行で「ここがこうだと行の中で矛盾する」を読む |
| ― | 2本以上の行・列の組合せ | 扱わない | ― |

手筋の例（事実。`human-solver.test.ts` の入力）:

- C: 6マスの行 `A A B . . .` は A が残り1個。右端に A を置くと左の2マスが B になり、B が3つ続く。右端は B に決まる。
- D: 6×6 で1行目が `A A B A B B` で完成しているとき、4行目 `A . B A . B` は A・B が1個ずつ残る。置き方は `A B B A A B` と `A A B A B B` の2通りで、後者は1行目と同じ並び。2マス目は B、5マス目は A に決まる。
- E: 8マスの行 `A . . B . . A .` は A が残り2個、B が残り3個。右端に A を置くと、残りの並べ方がどれもルールを破る。右端は B に決まる。

### 4.2 進め方

1. 局面ごとに A → B → C → D → E の順で、確定できるマスがある最も浅い手筋を探す。
2. その手筋で確定するマスをまとめて置く。これを1**ラウンド**とする。
3. 全マスが埋まるまで繰り返す。どの手筋でも確定できなくなれば止まる。

各ラウンドで記録する値:

- 使った手筋。
- **確定を与えた場所の数**: A は3マスの並び、B〜E は行・列を1か所と数える。その局面で次の一手を見つけられる場所の多さを表す。
- 読んだ行・列の空きマス数（C〜E）。
- 完成済みの行・列との重複を除かないと確定しなかったか（E のラウンドで D と同じ読みが要ったかを表す）。

**導出**: どの手筋も健全である。解法器が解き切れた初期配置は、推測なしに解けて、解も1つしかない。

### 4.3 前提調査の案から変えた点

| 点 | 前提調査 | 本書 | 理由 |
| --- | --- | --- | --- |
| D の対象 | 重複回避一般 | 片方のタイルが残り1個の行・列に限る | 人間がよく使う重複回避は「残り2マスで、片方の置き方が完成済みの行と同じ」形と考えた（推測。実測では D のラウンドの 90% がこの形。§8.4）。これは C と同じ狭い読みに重複の比較を足したもの。残りの多い行での重複回避は E に含めた |
| D と E の順 | A → B → C → E → D | A → B → C → D → E | D と E は対象の行・列が重ならない（D は残り1個、E は残り2個以上）。E は行の中で仮定を重ねる読みで、D より深いと考えた。順序を入れ替えた場合の影響は §7.4 |
| E と重複 | 重複を扱わない | 重複の除外を含める | 残りの多い行を読むときに完成済みの行を無視する理由がない |

### 4.4 評価できる範囲

- 2本以上の行・列を組み合わせる推論（例: 2本の列の候補を突き合わせる）は解法器が扱わない。それが要る問題は**評価不能**とし、提供しない。
- **事実（実測）**: 一意解であることだけを保って初期配置を減らし切った問題の 54.5%（200問中109問）が評価不能だった（§7.1 の `uniqueness` の行）。8×8 の一意解の問題には、1本の行・列の読みでは解けないものが多い。製品の問題はすべて解法器で解き切れる範囲から作る。

### 4.5 問題成立性の確認

`countTakuzuSolutions` が、行ごとにルールを満たす並びを選び、列の個数・3連続・行の重複で枝を刈る完全探索で、解を 0 / 1 / 2以上 まで数える。列の重複は全行が決まってから確かめる。難易度分析は、解がちょうど1つのときだけ解法器を動かす。

## 6. 問題集合

### 6.1 生成方法

`problem/generator.ts` の生成器で作る。生成器は難易度を指定して問題を作る機能を持たない。問題集（§14）も同じ生成器で候補を作り、分類して振り分ける。

1. seed から 8×8 の完成盤を1つ作る（`findRandomTakuzuSolution`）。
2. 全マスを初期配置として始め、seed で決まる順にマスを1つずつ消す。消すと**手筋の上限**までの手筋で解き切れなくなるマスは残す。上限を `uniqueness` にしたときは、一意解であることだけを保つ。
3. 消し終えた初期配置へ、解から**戻すマスの数**だけマスを戻す（初期配置が多めの問題を作るため）。
4. できた問題を分析・分類する。手筋の上限で難易度を決めない。

### 6.2 条件

- 手筋の上限: A / B（〜個数の完成）/ C / D / E / `uniqueness` の6通り。
- 戻すマスの数: 0 / 2 / 4 / 6 / 10 / 14 の6通り。
- 各条件 200 seed。計 7,200 問。

### 6.3 再現手順

```sh
bun run --cwd frontend analyze:takuzu -- --jobs 4 --output /tmp/takuzu-corpus/corpus
```

seed は `tk-<手筋の上限>-<戻す数>-<番号>`。1問は次で再現できる（例: `tk-duplicate-avoidance-2-160`）。

```ts
generateTakuzuProblem(
  createTakuzuProblemIdentity("duplicate-avoidance", 2, 160),
); // seed は "tk-duplicate-avoidance-2-160"
```

`uniqueness` の seed は `createTakuzuProblemIdentity(null, …)` に対応する。同じ条件で2回実行し、7,200問の初期配置と分類がすべて一致することを確かめた。

スクリプトの出力で再現できるのは、§7.1 の条件ごとの分類、§7.2 の特徴量の中央値、§7.3 の相関と AUC（同条件内・同じ空きマス数）、§7.5 の生成時間、§8.1 の案の比較である。次の値は、出力した `.jsonl` の問題を読み直して一度だけ数えたもので、スクリプトには含めていない。

- §7.2 の難易度5 の内訳、§8.4 の D のラウンドの空きマス数と C を使わない難易度4 の数。
- §7.4 の対称変換（盤面を回転・A と B を入れ替えて分析し直す）と、手筋の順序の入れ替え（`human-solver.ts` の `takuzuTechniques` の D と E の並びを一時的に入れ替えて分析し直す）。

**隣り合うレベルの比較（AUC）**

同じ比較を2通りで行った。値は、隣り合う2レベルから1問ずつ取ったとき、上位レベルの値のほうが大きい確率（同値は0.5）。0.5 から離れるほど、その量でレベルが分かれている。

- **同条件内**: 同じ生成条件（手筋の上限・戻す数）の中で比べる。各レベルに10問以上ある条件だけを使い、少ないほうの問題数で重み付けして平均する。難易度1 と 2 が同じ条件に同時に現れないため、1→2 は求まらない。
- **同じ空きマス数**: 空きマスの数がちょうど同じ問題の中で比べる（同じ重み付け）。

| 量 | 比べ方 | 1→2 | 2→3 | 3→4 | 4→5 |
| --- | --- | ---: | ---: | ---: | ---: |
| 空きマスの数 | 同条件内 | ― | 0.67 | 0.41 | 0.49 |
| ラウンド数 | 同条件内 | ― | 0.78 | 0.41 | 0.65 |
| 場所が1か所しかない局面の数 | 同条件内 | ― | 0.74 | 0.46 | 0.66 |
| 確定を与える場所の少なさ | 同条件内 | ― | 0.80 | 0.41 | 0.68 |
| ラウンド数 | 同じ空きマス数 | 0.94 | 0.71 | 0.49 | 0.67 |
| 場所が1か所しかない局面の数 | 同じ空きマス数 | 0.78 | 0.69 | 0.53 | 0.67 |
| 確定を与える場所の少なさ | 同じ空きマス数 | 0.96 | 0.74 | 0.49 | 0.69 |

読み取れること:

- 事実: 空きマスの数が同じでも、難易度2 は 1 より次の一手の場所が少なく（0.96）、1か所しかない局面が多い（0.78）。1→2 の差は規模だけでは説明できない。
- 事実: 4→5 も同じ空きマス数で 0.67〜0.69、同条件内では空きマスの数が 0.49 で、難易度5 は長いからではなく見つけにくい局面が多い。
- 事実: 2→3 は同条件内で空きマスの数が 0.67 で、難易度3 は同じ生成条件の中で空きマスが多い。初期配置が少ないほど C が要りやすいためと考える（推測）。同じ空きマス数でも見つけにくさは 0.69〜0.74 あり、長さだけの差ではない。
- 事実: **3→4 はどの量でも 0.41〜0.53 で、難易度4 は 3 より長くも見つけにくくもない。** 3 と 4 の差は「完成済みの行と見比べる読み」が要るかどうかだけにかかっている（§8.4）。
- 推測: 空きマスの帯によってレベルの出やすさは大きく変わるが、空きマス 32〜51 のどの帯にも 5段階すべてが現れる。空きマスの数でレベルが決まってはいない。

### 7.4 探索順・対称変換への依存（事実（実測））

- 盤面を 90° 回転した問題、A と B を入れ替えた問題を分析し直すと、7,200問すべてで分類が一致した（解法器は行と列、A と B を同じに扱うので、導出どおり）。
- 手筋の順序を前提調査の A → B → C → E → D に入れ替えると、難易度4 の 1,583問のうち 132問（8.3%）が 5 になった。他のレベルは変わらなかった。D と E のどちらでも進める局面で E を先に使うと、E が要ったと数えられるため。D を E より浅いとみなす根拠は §4.3 の推測で、試遊で確かめる（§10）。
- ラウンドは「その手筋で確定するマスをまとめて置く」ので、同じ手筋の確定が複数の場所にあっても1ラウンドと数える。重複の回避が要った局面の数は「D の読みが要る局面が何回来たか」で、1局面に D の場所が2つあっても1と数える。

## 8. 5段階の分類

### 8.1 案と比較

どの案も、難易度1〜3 は最も深い手筋（A だけ / B が要る / C が要る）で決め、D 以上が要る問題を 4 と 5 に分ける。前提調査 §11.5 の案（1: A だけで見つけやすい、2: A・B で見つけにくい局面あり、3: C、4: D が1〜2回、5: D を何度も・C と D が連続）を具体化したもの。

| 案 | 難易度5 の条件（残りの D 以上は 4） | 4 / 5 の問題数 | 4→5 同条件内 AUC（空きマス / ラウンド / 1か所の局面 / 場所の少なさ） | 最も出やすい条件での割合 4 / 5 |
| --- | --- | --- | --- | --- |
| **P1（推奨）** | E が要る、または重複の回避が2つ以上の局面で要る | 1,583 / 1,038 | 0.49 / 0.65 / 0.66 / 0.68 | 59% / 72% |
| P2 | E が要る、または深い読みが2ラウンド以上続く | 1,573 / 1,048 | 0.49 / 0.56 / 0.55 / 0.58 | 60% / 59% |
| P3 | E が要る | 2,418 / 203 | 0.48 / 0.69 / 0.70 / 0.73 | 96% / 23% |
| P6 | P1 または P2 のどれか | 1,202 / 1,419 | 0.49 / 0.60 / 0.60 / 0.62 | 46% / 80% |
| P7 | E が要る、または（重複の回避が2局面以上 かつ 深い読みが2ラウンド以上続く） | 1,954 / 667 | 0.48 / 0.63 / 0.63 / 0.66 | 71% / 51% |

- どの案でも 4→5 の空きマスの数は 0.48〜0.49 で、難易度5 が長さで決まってはいない。
- P2（連続）は 5 と 4 の見つけにくさの差が最も小さい（0.55〜0.58）。
- P3（E だけ）は差が最も大きいが、難易度5 が 3% しかなく、E が要る問題は最も出やすい条件でも 23%。供給は可能だが、E の読みは人間に説明しにくい（§9 の E の例）。4 に「重複の回避を何度も要る」問題と「1回だけ」の問題が混ざる。
- P1 は、前提調査の「D を何度も」をそのまま条件にしたもので、見つけにくさの差（0.66〜0.68）と供給（59% / 72%）の両方が取れる。

### 8.2 推奨案 P1

| レベル | 利用者向けの一文（案） | 分類条件 | 提供範囲内の割合 |
| ---: | --- | --- | ---: |
| 1 | 並んだ2つ・挟まれた1つを見つければ、次々に決まっていく | A だけで解ける（4ラウンド以上） | 14.4% |
| 2 | 行や列のタイルを数えて埋める場面がある。次の一手を探す時間が増える | B が要り、C 以上は要らない | 32.1% |
| 3 | 行や列に残り1個のタイルを、どこに置けるか読む場面がある | C が要り、D・E は要らない | 14.3% |
| 4 | 完成した行・列と同じ並びにならないよう読む場面が1度ある | 重複の回避が1つの局面で要り、E は要らない | 23.7% |
| 5 | 完成した行・列との読み比べが何度も要る。または、残りの多い行で並びを読み比べる場面がある | E が要る、または重複の回避が2つ以上の局面で要る | 15.5% |

各レベルで強くなるもの:

- 1 → 2: 3マスの形だけでなく、行・列1本を数える読みが加わる。同じ空きマス数でも、次の一手の場所が少ない（§7.3）。
- 2 → 3: 数えるだけでなく、行の中の置き場所を仮に試して読む必要が出る。
- 3 → 4: 行の中だけでなく、盤面の別の場所にある完成した行・列と見比べる必要が出る。ただし 4 は 3 の読み（C）を必ず含むわけではない。難易度4 の 19%（1,583問中306問）は C を使わず、D だけで 4 になる（§8.4）。
- 4 → 5: その見比べが1度で済まず、流れが止まるたびにまた要る（または、行の中で2段の仮定を重ねる E が要る）。見つけにくい局面も多い（§7.3）。

実装は `difficulty.ts` の `classifyTakuzuChallengeDifficulty` と `assessTakuzuDifficulty`。

### 8.3 評価可能範囲と提供範囲

| 状態 | 条件 | 扱い |
| --- | --- | --- |
| 成立しない（`invalid`） | 解が無い、または2つ以上ある | 提供しない |
| 評価不能（`unsupported`） | 一意解だが、1本の行・列の読み（A〜E）で解き切れない | 提供しない。難易度5 へ押し込まない |
| 提供範囲外・軽すぎる（`out-of-range` / `too-light`） | 3ラウンド以内で解き終わる | 提供しない |
| 難易度1〜5（`classified`） | 上記以外 | §8.2 で分類する |

- **下限**: 3ラウンド以内で解き終わる問題は、初めに見える形を埋めるとほぼ全部が決まり、「次に確定できるマスを見つけ出す」挑戦がほとんど無い（確定を与える場所の数の平均は中央値 14.3。難易度1 は 8.8）。実測では A だけで解ける問題でしか起きなかった（240問、初期配置の中央値 34）。境界は §9.2 の問題で確かめる。
- **上限**: 設けない。解法器で評価できる問題のうち最も強い読み（E、または重複の回避の繰り返し）でも、1本の行・列の中で完結する読みで、ゲーム固有の挑戦から外れないと考える（推測）。E が重すぎないかは §10 で確かめる。

### 8.4 重点: 1 / 2 と 4 / 5、そして 3 / 4

**難易度1 と 2**

- 前提調査の仮説は「見つけやすさ」で分けることだった。推奨案は「B（数える）が要るか」で分けた。読みの種類が変わることを利用者に説明でき、そのうえで見つけやすさも大きく違う（場所の数の平均 8.8 と 3.8。同じ空きマス数での AUC 0.96）。
- 難易度1 のうち、場所の数の平均が難易度2 の中央値（3.8）を下回るものは 960問中4問、1か所しかない局面が4以上あるものは39問だった。A だけで解けても見つけにくい問題は少数だが存在する（§9.3 の `tk-adjacency-0-96`）。
- B が1ラウンドだけの難易度2 は 42問（2%）。終盤に1行を数えて埋めるだけで 2 になる問題があり、1 との差が薄い可能性がある（§9.2）。

**難易度4 と 5**

- 4→5 は同条件内で空きマスの数に差がなく（0.49）、同じ空きマス数で見つけにくさに差がある（0.67〜0.69）。回数の条件が長さの代理になっていない。
- 難易度5 の 80% は E を使わず、重複の回避を2つ以上の局面で要する問題。E が要る問題は 20%。
- 難易度5 には、初期配置が多くて短いのに重複の回避を2回続けて要する問題も入る（§9.3 の `tk-general-line-14-190`、ラウンド数 7）。

**難易度3 と 4（新たに見つかった懸念）**

- 3→4 は長さでも見つけにくさでも差が無い（0.41〜0.53）。4 は「重複の回避」という新しい読みが要ることだけで 3 と分かれる。
- 重複の回避の大半（D のラウンドの 90%）は、残り2マスの行を完成した行と見比べる形だった（提供範囲内の問題の D のラウンドのうち、読んだ行の空きマスが2マスのものが 3,377、3マス以上が 355）。これが C（残り1個の置き場所を読む）より難しく感じられるかは確かめていない。
- 難易度4 は 3 の上に読みを1つ足したものとは限らない。難易度4 の 19%（1,583問中306問）は C を一度も使わず、A・B と D だけで解ける（§9.2 の `tk-duplicate-avoidance-2-96`）。難易度5 でも 44問（4%）は C を使わない。3 と 4 の順序は「D は C より深い」という §4.3 の推測だけに支えられている。
- さらに、プレイ画面は完成した行・列の重複をその場で違反として示す（前提調査 §7.3）。D の大半を占める残り2マスの行（A・B が1個ずつ残る）では、片方のマスへどちらかを置けば残る1マスは個数で決まり、行が埋まった時点で重複の印が出るかどうかで正誤が分かる。違っていればタップで2マスを入れ替えるだけで直せる。基準とするプレイ条件は「違反の印に頼らない」だが、実際の体験では D が「見比べる読み」ではなく試し置きになり、C より易しくなるおそれがある。

## 11. ずれた場合の見直し方針

工程10。閾値だけを動かして合わせず、次の順で原因を疑う。

1. 挑戦の定義（§3）
2. 観測できていない挑戦
3. 特徴量の意味・計算（§5）
4. 判定方法（段の組み立て方）
5. 帯の境界（閾値）

推奨案に即した例:

- **3 と 4 に差が無い場合（§10 の4）**
  1. 挑戦の定義: 「完成した行と見比べる」ことが、残り1個を読むことより深い読みだという前提を疑う。
  2. 観測できていない挑戦: 違反の印を使った試し置きで、D が実質的に試行になっていないか。
  3. 特徴量: D を、残り2マスの行（見比べるだけ）と3マス以上の行（C の読みに見比べを足す）に分ける。ラウンドごとに読んだ行の空きマス数は記録済み。
  4. 判定方法: 残り2マスの D を C と同じ段に数え、4 を「残り3マス以上の D」または「C 以上が2つの局面で要る」に組み替える。回数で段を作る場合は、長さの代理にならないかを §7.3 の AUC で確かめる。
  5. そのうえで境界を動かす。
- **1 と 2 の差が薄い場合（§10 の1・2）**: 見つけにくさ（1か所しかない局面の数）を 1 と 2 の条件に加える。空きマスの数と相関する（ρ = 0.64）ので、供給で空きマスの範囲をそろえたうえで確かめる。
- **4 と 5 の差が回数の運に見える場合（§10 の5）**: 案 P7（重複の回避の繰り返しが、易しい手筋を挟まずに続く問題に限る）へ寄せる。
- **E が重すぎる場合（§10 の6）**: E を提供範囲外（重すぎる）とし、5 は重複の回避の繰り返しだけで作る。E を除いても難易度5 は 835問あり、供給は保てる見込み。
- **順序は合っているが、同じレベルの中で長い問題が重く感じる場合**: 長さは挑戦ではない（§3.3）。判定は変えず、問題供給で空きマスの範囲をレベルごとにそろえる。

## 12. 未解決の不確実性と限界

- **実プレイをしていない**。§9 の所感は解法器の経過を目視で追ったもの。各レベルの体験差は §10 の試遊まで仮説である。
- **3 と 4 の差**は「重複の回避」という新しい読みの有無だけにかかり、長さ・見つけにくさの差が無い。難易度4 の 19% は C を使わない（§8.4）。違反表示が D を試し置きに変えるおそれもあり、5段階の意味を左右しうる最大の不確実性。
- **D と E の順序**: 入れ替えると難易度4 の 8.3% が 5 になる（§7.4）。
- **ラウンドの定義**: 同じ手筋の確定をまとめて置く。人間は1マスずつ置き、置いたマスから次の形が見えるので、実際の見つけやすさは局面ごとの場所の数より高いことがある。
- **生成方法**: 無作為な順での初期配置の削減と、解からの戻しだけで作った。別の生成方法では各レベルの出やすさや特徴量の分布が変わりうる。問題集での分布は §14.4 で測り直した。
- **規模との関係**: レベルと空きマスの数の相関は 0.48。どの帯にも全レベルが現れるが、上位レベルほど空きマスが多い。問題集では全レベルを空きマス 40〜48 の同じ範囲から採ったが、範囲の中でも上位レベルほど空きマスが多く、相関は 0.45 残る（§14.3）。
- **人間の読み方との対応**: C・E は「ルールを満たす並びを全部並べて共通部分を取る」で実装した。人間が同じ結論に別の筋道（たとえば仮定して矛盾を探す）でたどり着くとき、読みの重さが同じとは限らない。
- **評価不能の問題**: 2本以上の行・列を組み合わせる推論を扱わない。製品の問題は解法器で解き切れる範囲から作るので提供には影響しないが、その種の推論を楽しむ上級の挑戦は提供範囲に入らない。

## 14. 問題集（事実（実測））

問題供給として、各レベル 500問の問題集を作った。生成スクリプトは `frontend/scripts/generate-takuzu-problem-pool.ts`、生成物は `frontend/src/games/takuzu/problem/problem-pool.json`。

```sh
bun run --cwd frontend generate:takuzu-pool -- --jobs 4   # 生成
bun run --cwd frontend generate:takuzu-pool -- --verify   # 全問の検証
```

### 14.1 作り方

1. レベルごとに、そのレベルが現れやすい生成条件（§7.1）を決める。

   | レベル | 生成条件（手筋の上限・戻す数） |
   | ---: | --- |
   | 1 | A・0 |
   | 2 | B・0 / 2 / 4 / 6 |
   | 3 | C・0 / 2 / 4 / 6 |
   | 4 | D・2 / 4 / 6、E・2 / 4 / 6 |
   | 5 | D・0 / 2 / 4 / 6、E・0 / 2 / 4 / 6 |

2. 各生成条件で、seed `tk-<手筋の上限>-<戻す数>-<番号>` の候補を番号順に作り、分析・分類する（§6.3 の corpus と同じ seed の系列）。
3. そのレベルに分類され、**空きマスの数が 40〜48** の候補だけを採れる候補とする。範囲は全レベルで共通にした。
4. 生成条件を巡回し、各条件の採れる候補を番号順に1つずつ採る。盤面の回転・反転（8通り）と A / B の入れ替え（2通り）の16通りで初期配置の最小の表記を正規形とし、同じ正規形の問題は採らない。500問そろったら止める。

生成条件は候補を作る領域を決めるだけで、レベルは分類で決める（`難易度判定.md`「生成条件を難易度へ直結させない」）。採る問題は各条件の候補の番号順の並びだけで決まり、並列数（`--jobs`）や一度に調べる候補数（`--block`）に依存しない。`--jobs 4` と `--jobs 2 --block 150`・`--jobs 3` で生成した JSON がバイト単位で一致することを確かめた。生成スクリプトの出力をそのままコミットし、他のゲームの問題集と同じく Biome の整形対象から外している（整形すると生成し直したときに差分が出る）。

問題集の1問は `["D", 2, 160, "<32桁の16進>"]` の形で持つ。先頭の3つ（手筋の上限・戻す数・候補番号）から identity（生成器の版・seed・生成条件）を再構成し、16進は解（B を 1）と初期配置のマスク（固定マスを 1）を16桁ずつ並べたもの。実行時は16進を読んで問題を復元するだけで、生成器・解探索・難易度分析を呼ばない。記録に残した identity が問題集に無い（生成器の版が変わった後など）ときは再プレイできない（前提調査 §12.2）。

### 14.2 内訳

「候補」は、採る問題を決めるまでに調べた候補の数。「分類一致」はそのレベルに分類された割合、「採用率」はそのうえで空きマスの範囲に入った割合（同型の除外の前）。計算時間は1スレッドあたりの生成と分析の合計（Linux コンテナ）で、レベル4 と 5 が共有する生成条件の候補は両方に数える。

| レベル | 問題数 | 候補 | 分類一致 | 採用率 | 同型の重複 | 計算時間 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 500 | 547 | 97.6% | 91.4% | 0 | 7.3 s |
| 2 | 500 | 549 | 100.0% | 91.1% | 0 | 16.9 s |
| 3 | 500 | 976 | 71.9% | 51.2% | 0 | 32.1 s |
| 4 | 500 | 1,102 | 50.1% | 45.4% | 0 | 42.7 s |
| 5 | 500 | 1,891 | 46.3% | 26.4% | 0 | 71.3 s |

- 生成は全体で 56 秒（4並列の経過時間）。`--verify` で 2,500問すべてを identity から生成し直し、次を確かめた（4並列で 18 秒）: 問題集の表記と一致する、一意解で手筋だけで解き切れる（分析の状態が `analyzed`）、分類がそのレベルと一致する、空きマスが範囲内、同型の重複が無い。
- 生成条件の内訳: 1 は A・0 が 500。2・3 は各条件 125。4 は各条件 83〜84。5 は各条件 62〜63。
- 同型の重複は、今回調べた候補では1件も無かった。
- §9 の代表問題のうち `tk-adjacency-0-103`（1）、`tk-single-remaining-4-45`（3）、`tk-duplicate-avoidance-2-160`（4）は問題集に入っている。

### 14.5 大きさと選択時間

- 問題集の JSON は 133,807 バイト（gzip 48,562 バイト）。1問あたり約 54 バイト。
- プロダクションビルドのメイン JS は 1,183.85 kB（gzip 350.61 kB）から 1,300.96 kB（gzip 402.85 kB）へ増えた（+117 kB、gzip +52 kB）。ルートごとの分割をしていないので、他のゲームを遊ぶ利用者にも含まれる。
- 1レベル 1,000問でも試した: JSON 268,778 バイト（gzip 96,852 バイト）、生成 91 秒。500問は1日5問遊んで一巡するのに100日かかる量で、JSON の大きさ（圧縮前）を既存の問題集（マインスイーパー 109 kB、ウォーターソート 175 kB）と同じ程度に抑えられるので、500問を採った。
- 配信で効く gzip 後の大きさは、既存の問題集（マインスイーパー 約 18 kB、ウォーターソート 約 26 kB）の2〜3倍になる。既存の2つは identity（と少数の派生値）だけを持ち、実行時に生成器で問題を作り直すのに対し、この問題集は生成器・解探索をプレイ時に使わないよう解と初期配置そのもの（1問 128 ビット）を持つため。2,500問 × 16 バイト ≒ 40 kB がこの持ち方での下限に近く、表記を変えても大きくは縮まない。
- 選択と復元（seed のハッシュで1問を選び、16進から問題を作る）は 10,000回で平均 0.036 ms、p99 0.70 ms、最大 3.3 ms（Bun、Linux コンテナ）。
