# タクズピクトグラム検討

バイナリパズル（タクズ）のゲーム選択ピクトグラムの検討記録。どの着眼点を探索し、どの候補を比べたか。なぜ H（四角と丸の2連）を推奨するか。見直すときに、同じ比較をやり直さずに論点から始められるようにする。

この文書は導入調査の資料であり、現在仕様の正本ではない。採用したピクトグラムの形は `frontend/src/games/takuzu/assets/pictogram.svg` を正とする。制作手順と評価方法は `.claude/skills/design-game-pictogram/`（`SKILL.md`、`references/method.md`）を正とする。

記述は次のように区別する。

- **事実（リポジトリ）**: 現在のコード・文書から確かめたこと。
- **事実（実測）**: 候補 SVG を実表示サイズで描画して比べたときに見えたこと。候補 SVG は代表案だけをリポジトリに残している（§6）。
- **判断**: 上から導いた推奨と理由。

人間による方向の選択はまだ行っていない。人間が候補を比べて選び替えられるように、代替の候補も同じ品質まで仕上げている（§6）。

## 1. 結論

- 推奨案は **H（四角と丸の2連）**。外枠の中を 3列×2行 に区切り、上段に「■ ■ ○」、下段に「○ ○ ■」を置く。
  - ■（濃色の塗りの角丸四角）はプレイ画面の A（塗りの角丸四角）を、○（濃色の輪郭の丸）は B（輪郭の丸）を表し、プレイ画面のタイルと同じ形になる。
  - 「同じ形が2つ並んだら、その隣は反対の形」という基本の手筋を1枚で示す。
- 推奨の理由は次の3つ（§4.2）。
  - プレイ画面で見るタイルと同じ「四角と丸」で描くので、ゲーム自身の姿に近い。
  - 一覧の 50〜60px でも ■ と ○ が見分けられる。
  - 外枠と格子の階層が既存ピクトグラムとそろい、重さも突出しない。
- 見直すときの主な論点は次の4つ（§5）。有力な代替は H2・J・G（§5.2）。
  - 丸を輪郭にするか淡色の塗りにするか。
  - 手筋を描くか、盤を描くか。
  - 格子の盤が一覧に並びすぎること。
  - ダークテーマで明暗が反転すること。

## 2. 目的と制約

### 2.1 目的

ゲーム一覧でバイナリパズルを素早く見分けられ、ゲーム自身の姿を保ち、既存のピクトグラムと並べても強さが突出しないこと（`DESIGN.md`「ゲームピクトグラム」、`references/method.md` §1）。

### 2.2 制約（事実（リポジトリ））

- 共通描画契約（`SKILL.md`）
  - `viewBox="0 0 120 120"`。
  - 線幅は 4 と 2 だけ。
  - 色は `var(--game-pictogram-strong)` と `var(--game-pictogram-soft)` の2色だけ。
  - `check_svg.py --max-colors 2 --forbid-gradients --forbid-filters --forbid-external-images --forbid-text` を通す。
- 色は `GamePictogram` が与える。ライトとダークでは前景色と補助情報色、結果画面では `currentColor` になる。どのテーマでも読める形にする。
- 実表示サイズ（`GameSelectionGallery.tsx` のクラスから算出）
  - ゲーム選択のヒーロー: 177px（PC）/ 138px（スマホ）。
  - 一覧のカード: 60px（PC）/ 50px（スマホ）。
  - 結果画面: 48px。
  - 一覧の 50〜60px が最も厳しい。
- 比べる既存ピクトグラム: ウォーターソート、ナンプレ、マインスイーパー。ナンプレとマインスイーパーは、外枠と数字を持つ。
- プレイ画面のタイル（[タクズ導入前提調査](タクズ導入前提調査.md) §5.2・§9.1）
  - 数字の 0/1 は使わない。
  - A は塗りの角丸四角、B は輪郭の丸。形だけで見分けられ、A・B に別の色は持たせない。
  - 固定タイルは前景色、置いたタイルはゲーム固有の青で、色の濃淡だけで分ける。A・B の区別（形）とは別の区別で、ピクトグラムでは描き分けない。
- 表示名は「バイナリパズル」（同 §3.2）。SVG の `aria-label` もこれに合わせる。`GamePictogram` は SVG を `aria-hidden` で描画するので、読み上げには使われない。SVG 単体の説明として一致させる。

## 3. 比べた方向と分かったこと

| 方向 | 候補 | 比べたこと |
| --- | --- | --- |
| 数字 0/1 で描く | A 数字の完成盤、D 数字の2連、F 数字の2×2 | 盤・断片・二値の象徴のどれで描くか |
| 白黒の丸で描く | B 丸の盤、C 行と列の十字 | 盤か、手筋の十字か |
| プレイ画面の四角と丸で描く | E 2色の四角タイル、G 途中の盤、H 2連の断片、I 完成盤、J 2×2 | 盤・断片・2×2、丸の輪郭と塗り、H の細部 |

### 3.1 着眼点

次の着眼点から候補を作った。

- 盤と値: 0/1 の数字の盤、●○ の盤、2色タイルの盤、完成盤、途中の盤、盤の角の切り出し、1行だけの帯。
- 手筋: 2連の次が反対、挟み、行と列の十字で1マスが決まる、最後の1マスが個数で決まる。
- ルール: 3連続に×、行の重複に×、行の半数ずつ（天秤）。
- 二値の象徴: 大きな「0 1」、1 0 / 0 1 の2×2、スイッチ、コインの表裏、電光表示、半分塗りのマス。
- 操作: 空き → A → B → 空きの巡回、固定マスと置いたマスの区別。

候補にしなかったもの（判断）:

- スイッチ・コイン・天秤・電光表示: 二値の汎用記号で、パズルの盤に結びつかない。
- ×印: ルールの説明を読まないと意味が分からない。誤りの表示にも見える。
- 入力の巡回: 静止画では伝わらない。
- 6×6 以上の盤の縮小: 50px で粒の模様になる。
- 1行だけの帯: 盤に見えず、一覧で軽すぎる。

### 3.2 数字と白黒の丸（事実（実測））

- 数字の完成盤（A）は、60px 以下で「0101…」の文字の塊になった。
- 数字の2連（D）は、50px でも「0 0 1 / 1 1 0」が読めた。淡色と濃色で「決まる数字」も見えた。
- 白黒の丸の盤（B）は、50px でも ● と ○ が区別できた。空きマスを入れると、オセロの盤より「途中まで埋めたパズル」に見えた。
- 十字（C）は外形が独特だが、60px で丸が点になり、十字キーに見えた。

プレイ画面は数字を使わず、四角と丸の2種類のタイルで表す（導入前提調査 §5.2・§9.1。数字を使わない理由は、ナンプレと同じ見た目になることと、足し算の印象を与えること）。一覧でプレイ画面にない 0/1 を見せると、遊び始めたときに見る盤と結びつかない。白黒の丸は四角を持たない。どちらもゲーム自身の姿から一段離れるので、推奨の候補から外した（判断）。

### 3.3 四角と丸（事実（実測））

ピクトグラムは2色（濃色・淡色）の規格で、プレイ画面の青と黄の色相は使えない。そのため A と B は形で分ける。四角は濃色の塗りで A の「濃い面」を表す。丸は濃色の輪郭（中を抜く）か淡色の塗りで、B の「明るい面」を表す。

- E（2色の四角タイル）は、50px で黒い粒のモザイクになり、最も重かった。
- H（3列×2行の「■ ■ ○ / ○ ○ ■」）は 50px でも、上段の「四角2つと丸」、下段の「丸2つと四角」が読めた。ナンプレ・マインスイーパーと同じ外枠の大きさで、重さはナンプレとマインスイーパーの間。
- G（4×4 の外枠の盤）の完成盤と I（外枠なしの 4×4 の完成盤）は、60px 以下で ■ と ○ の粒の模様になった。I は数字の盤より軽いが、QR コードやドット絵に近い。
- G の空きマスありの版は、途中の盤に見える。ただ並びに規則が見えず、散らばった印に見えた。
- J（2×2 の「■ ○ / ○ ■」）は最も大きく読みやすい。一方で、盤やルールの感じは薄く、汎用的な「二値」の記号に寄った。
- 丸を淡色の塗りにした版は、形と濃淡の両方で A と B が分かれる。ただ 50px では灰色の丸が少しぼやけ、輪郭の版より塊に見えた。輪郭の版は ○ と ■ の対比がはっきりした。

### 3.4 H の細部（事実（実測））

- 図形の大きさ: 四角 18・丸 半径 10、四角 16・丸 半径 9、四角 17・丸 半径 9.5 を比べた。
  - 18 は、ヒーローでマスの左右の余白が詰まって見えた。
  - 16 は、50px で図形が小さくなった。
  - 17 を採った。
- 格子の有無: 格子なしは整って見えた。ただ、行としてのまとまりが弱く、タイルが浮いて見えた。格子ありは、行の並びが読めた。
- 外枠の比率: 横長の 84×56 は一覧で軽く見えた。84×84 はナンプレ・マインスイーパーの外枠と同じ大きさになった。

## 4. 推奨案 H

### 4.1 仕様（事実（リポジトリ））

- 外枠: `x=18 y=18 width=84 height=84`、`rx=2`、濃色、線幅 4。ナンプレ・マインスイーパーと同じ。
- 格子: 淡色、線幅 2。縦線は x=46 / 74、横線は y=60。3列×2行で、1マスは 28×42。
- 図形: マスの中心（x=32 / 60 / 88、y=39 / 81）に置く。
  - 四角: 一辺 17、`rx=3`、濃色の塗り。
  - 丸: 半径 8.5、濃色の輪郭、線幅 2（外径 9.5）。四角と丸の面積はほぼ等しい（289 と 284）。
- 並び: 上段は「■ ■ ○」、下段は「○ ○ ■」。上段と下段は互いに反対の並び。
- 光学中心の補正: なし。濃色の塗りが左上と右下に対角に分かれ、外枠が上下左右で均衡している。138px と 48px で偏りは目立たなかった（事実（実測））。
- 色は strong / soft の2色だけ。`check_svg.py` の2色・gradient / filter / 外部画像 / text 禁止の検査を通る。

### 4.2 推奨理由（判断）

- **意味的距離**: プレイ画面で置くのは「四角と丸」の2種類のタイルで、それをそのまま描いている。
  - 「■ ■ の隣は ○」「○ ○ の隣は ■」は、遊ぶ人が最初に使う手筋。
  - 上段と下段が反対の並びなので、「各行で同数」「行の重複禁止」の感覚にもつながる。
  - プレイ画面の B は明るい面に濃い縁取りのある丸で、○（輪郭の丸）はその縁取りに対応する。
- **実表示サイズ**: 図形は6つで、1つが 17 と大きい。50px（図形の幅は約 7px）でも ■ と ○ が見分けられた（事実（実測））。
- **弁別性**
  - 一覧で数字を持たない盤は、これだけになる。ナンプレ・マインスイーパーとは数字の有無で、ウォーターソートとは外枠と格子で見分けられた（事実（実測））。
  - 丸と四角が混ざる内部の形は、他のどのピクトグラムにもない。
- **光学的重量**: 濃色は外枠と四角3つ・丸3つの輪郭だけ。マインスイーパー（淡い面を多く持つ）より軽く、ナンプレより重い。
- **一覧の描画言語**: 外枠（濃・4）＋格子（淡・2）＋記号という階層は、外枠を持つナンプレ・マインスイーパーと同じ（マインスイーパーの格子は淡色の面）。

### 4.3 弱点（判断）

- 外枠と格子の盤は、一覧の中で3つ目になる。外形の新しさでは C（十字）や I（外枠なし）に劣る。
- 手筋を知らない人には、並びの意味（2連の隣が反対）は伝わらない。ただし意味が分からなくても「四角と丸を置く盤」としては読める。
- プレイ画面の色（青と黄）は、2色の規格上ピクトグラムに持ち込めない。形の対応だけで結びつける。
- ダークテーマでは濃色が明るい前景色になる。四角（A）が丸（B）より明るく見え、プレイ画面の明暗（A が暗い）と逆になる。既存ピクトグラムも同じ前景色の規則に従うので、ここだけ変えることはしない。

## 5. 再検討するときの論点

### 5.1 論点

- **丸を輪郭にするか淡色の塗りにするか**: プレイ画面の B は明るい面に縁取りのある丸なので、どちらも対応は立つ。
  - 輪郭（H）は、○ と ■ の対比が強く、50px でも形が崩れにくい。
  - 淡色の塗り（H2）は、形と濃淡の両方で分かれ、「2色のタイル」らしい。ただ 50px では灰色の丸が少しぼやける。
  - プレイ画面の「塗りのタイル」の感じを重く見るなら H2。
- **手筋を描くか、盤を描くか**: H は手筋、G は途中の盤、J は二値の象徴を描く。手筋は意味が深いが、ルールを知らない人には並びの意味が伝わらない。G は「途中の盤」だが、小サイズで散らばった印に見える。
- **格子の盤が並びすぎること**: 一覧の単調さを嫌うなら、外枠のない I か十字の C が候補になる。I は粒の模様で重く、C は丸が点になり十字キーに見える弱点がある（§3.2・§3.3）。
- **数字に戻すか**: 表示名「バイナリパズル」に最も直接つながるのは 0/1 の数字（D）。ただしプレイ画面に数字が出ないので、ゲームの姿からは離れる。プレイ画面を数字に変える場合だけ、D が推奨に戻る。

### 5.2 候補の一覧と代替案

| 案 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| **H 四角と丸の2連**（推奨） | 3列×2行、「■ ■ ○ / ○ ○ ■」、丸は輪郭 | プレイ画面の形で、二値と手筋が伝わる。50px でも読める。一覧の階層にそろう | 格子の盤の3つ目。並びの意味は手筋を知る人向け |
| H2 同・丸を淡色の塗り | H と同じ配置で、丸を淡色で塗る | 形と濃淡の二重で分かれる。塗りのタイルに近い | 50px で灰色の丸が少しぼやける |
| J 四角と丸の2×2 | 大きな「■ ○ / ○ ■」 | 最も大きく読みやすい | 盤やルールの感じが薄く、汎用的な二値の記号に寄る |
| G 四角と丸の途中の盤 | 4×4、■ と ○、空きマス7つ | 解いている途中の盤に見える | 並びに規則が見えず、小サイズで散らばった印に見える |
| I 四角と丸の完成盤 | 外枠なし、4×4 を ■ と ○ で埋める | 外枠がなく、一覧で外形が違う | 60px 以下で粒の模様。QR コードやドット絵に見えうる |
| D 数字の2連 | 3列×2行、淡色の「0 0」「1 1」と濃色の「1」「0」 | 二値と表示名に直接つながる | プレイ画面に数字がない。ナンプレと同じ「格子に数字」 |
| B 白黒の丸の盤 | 4×4、● と ○、空きマス5つ | 一覧で唯一の丸の盤 | オセロ・囲碁の連想。プレイ画面の四角と合わない |
| C 行と列の十字 | 行5マス×列5マスの十字 | 外形が一覧で唯一 | 60px 以下で丸が点になる。十字キーに見えうる |
| A・E・F | 数字の完成盤・2色の四角タイル・数字の2×2 | — | §3.2・§3.3 のとおり、数字の塊・モザイク・汎用記号 |

推奨順は H > H2 > J > G > I > D（判断）。部分採用もできる（例: H の並びを外枠なしで描く、G の盤に H の2連を入れる）。

## 6. 代表案の SVG と選び替え

[ピクトグラム検討/](ピクトグラム検討/) に、候補ごとの代表案だけを置く。

| ファイル | 内容 |
| --- | --- |
| `h-shape-pair.svg` | 推奨案 H（採用 SVG と同じ） |
| `h2-shape-pair-soft.svg` | H2 丸を淡色の塗り |
| `j-shape-2x2.svg` | J 四角と丸の2×2 |
| `g-shape-partial-board.svg` | G 四角と丸の途中の盤 |
| `i-shape-tiles.svg` | I 四角と丸の完成盤 |
| `d-digit-pair.svg` | D 数字の2連 |
| `a-digit-board.svg` / `b-disc-board.svg` / `c-disc-cross.svg` / `e-two-tone-tiles.svg` / `f-digit-2x2.svg` | A・B・C・E・F |

色は製品と同じ CSS 変数（`var(--game-pictogram-strong)` / `var(--game-pictogram-soft)`）のまま置いている。GitHub などで CSS 変数なしに見る場合は、ライトテーマの近似値に置き換えたコピーを作る。

```sh
sed -e 's/var(--game-pictogram-strong)/#0a0a0a/g' -e 's/var(--game-pictogram-soft)/#737373/g' \
  docs/パズル/導入調査/タクズ/ピクトグラム検討/h2-shape-pair-soft.svg > /tmp/h2.svg
```

### 6.1 選び替える手順

1. 採る候補の SVG を `frontend/src/games/takuzu/assets/pictogram.svg` へ複製する。`aria-label` は「バイナリパズル」のまま。
2. 最終検査を通す。

   ```sh
   python3 .claude/skills/design-game-pictogram/scripts/check_svg.py frontend/src/games/takuzu/assets/pictogram.svg \
     --max-colors 2 --forbid-gradients --forbid-filters --forbid-external-images --forbid-text
   ```

3. 既存ピクトグラムと同じサイズ・同じテーマで並べて見比べる（`references/method.md` §4「弁別性」「実表示サイズでの成立」）。サイズは §2.2 の 177 / 138 / 60 / 50 / 48px を使い、ライトとダークの両方で見る。

   ```sh
   python3 .claude/skills/design-game-pictogram/scripts/make_review_sheet.py \
     --output /tmp/takuzu-pictogram-review.html --size 112 \
     docs/パズル/導入調査/タクズ/ピクトグラム検討/*.svg \
     frontend/src/games/water-sort/assets/pictogram.svg \
     frontend/src/games/nanpure/assets/pictogram.svg \
     frontend/src/games/minesweeper/assets/pictogram.svg
   ```

4. この文書の §1 と §4 を、採った案に合わせて直す。
