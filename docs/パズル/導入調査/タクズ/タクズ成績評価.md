# タクズ成績評価

タクズ（利用者向けの表示名は「バイナリパズル」）の1プレイを100点満点で評価し、`perfect` / `great` / `good` / `clear` の評価段階と自己ベストの比較へつなげるための検討記録。

[タクズ導入前提調査.md](タクズ導入前提調査.md)（以下「前提調査」）§13 の仮説を出発点に、配点・基準時間・記録する事実を決める。

この文書は現在仕様の正本ではない。採用した評価規則は、正本化の段階でバイナリパズル仕様（`SPEC-011`）の「成績評価」へ移す。比べた案、採らなかった案、係数の根拠はこの文書に残す。

根拠は前提調査と同じ見出し語で区別する。

- **事実（実測）**: 同梱の問題集（各難易度 500問、計 2,500問）を人間向け解法器で解いた経過から計算した値。
- **導出**: 定義から論理的に導けること。
- **推測・仮説**: 実プレイで確かめていない判断。係数はすべてここに入る。

**まだ誰も実際に遊んで評価を確かめていない。** 係数は §9 の確認で校正する前提の仮置きである。

## 2. 良いプレイの定義

> 盤面を読んで確定したマスだけを置き、置き直しをせずに、迷いなく解き切ること。

（前提調査 §13.1 のまま採る。）

- 問題はどれも推測なしに解ける（前提調査 §4）。上手なプレイは「確定させてから置く」ことに表れる。試しに置いて後で直す回数が少ないほど、読みが正確だったと考える。
- 次の確定マスを素早く見つけられるほど、経過時間が短くなる。
- 2つの観点のうち、**正確さを重く** する。タクズには解答との照合が無く、ルール違反の印を頼りに「置いて確かめる」遊び方ができてしまう。速く置いて直すプレイを、読んでから置くプレイより高く評価すると、推測不要の問題で鍛えたい読みとは別の遊び方を称えることになる（推測）。
- 解けたかどうかはクリアとして別に扱う（`GAME.md`）。失敗の条件は無いので、クリアしたプレイだけを評価する。

## 3. 観点とプレイ事実

`session/session.ts` の `TakuzuSessionResult` がクリア時に返す事実をそのまま使う。session に事実を足す必要は無かった。

| 事実 | 意味 | 評価での扱い |
| --- | --- | --- |
| 経過時間 `elapsedMs` | 開始からクリアまで。やり直しても引き継ぐ | **速さ** |
| 置き直し回数 `correctionCount` | 一度置いた値を別の値や空へ変えた回数。同じマスを続けて押す間は1回の入力とみなし、別のマスを押した時点でそのマスの値を「置いた値」とする。解答との照合は使わない | **正確さ** |
| やり直し回数 `restartCount` | 盤面を初期配置へ戻した回数。消えたマスは置き直しに数えない | **正確さ** |
| 入力回数 `inputCount` | 固定マス以外を押した回数 | 記録だけ。巡回入力では B に2回押すので、値の種類で差が付く |
| ルール違反の発生回数 | ― | 記録しない。巡回の途中で一瞬出る違反も数えてしまう |

速さの基準時間には、遊んだ問題の事実（§5 の作業の量）も使う。これはプレイの事実ではなく問題の事実なので、記録では `workload` として `performance` と分けて持つ（§8）。

## 4. 評価式（推奨案）

| 観点 | 満点 | 規則 |
| --- | ---: | --- |
| 正確さ | 60 | 置き直し1回につき 5点、やり直し1回につき 15点を減点。0点を下回らない |
| 速さ | 40 | 問題ごとの基準時間以内で満点。超過に応じて線形に減らし、基準時間の2倍で0点 |

```
正確さ = max(0, 60 − 5 × 置き直し回数 − 15 × やり直し回数)
速さ   = round(40 × clamp(1 − max(0, 経過時間 − 基準時間) / 基準時間, 0, 1))
基準時間 = 10秒 + 2秒 × 空きマスの数 + 3秒 × 局面の数 + 10秒 × 行・列を読む局面の数
合計 = 正確さ + 速さ
```

評価段階は既存ゲームと同じ（100 `perfect` / 90以上 `great` / 80以上 `good` / それ未満 `clear`）。

この式から導かれる性質（導出）:

- `perfect` は、置き直し0回・やり直し0回・基準時間以内のときだけ。ただし速さの点は整数へ四捨五入するので、超過が基準時間の 1.25% 以下（基準 3分なら約2秒）は満点に丸まる。§7 の「3分で難易度4 は 100点」（基準 2:59）はこの丸めによる。
- 置き直し2回まで（押し間違いを直した程度）なら、基準時間以内で `great` に残る。3回で最高 `good`、5回以上は速さによらず `clear`。
- やり直しを1回すれば、ほかが完璧でも最高 `good`。やり直しで消したマスは置き直しに数えないので、試し置きの跡を消せる分を含めて重くした。マインスイーパーの「地雷1つで最高 `good`」と同じ強さ。
- 置き直しもやり直しも無いプレイは、基準時間の2倍かかっても 60点（`clear`）で、試し置きを重ねたプレイより高い。

実装: `frontend/src/games/takuzu/score.ts`。

## 5. 基準時間

### 5.1 使う量

問題ごとの「解き切るのに要る作業の量」（`TakuzuSolveWorkload`）から決める。

| 量 | 意味 | 出どころ |
| --- | --- | --- |
| 空きマスの数 `emptyCellCount` | 置くタイルの数 | 初期配置から数える |
| 局面の数 `roundCount` | 人間向け解法器が解き切るまでのラウンド数（[タクズ難易度.md](タクズ難易度.md) §4.2）。流れが止まって、次に確定できるマスを探し直す回数を表す | 問題集に持たせた |
| 行・列を読む局面の数 `lineReadingRoundCount` | そのうち C（残り1個）・D（重複の回避）・E（一般の行候補）が要った局面の数。行全体の並びを読む時間を表す | 問題集に持たせた |

難易度（レベル）そのものは使わない。レベルは「どの種類の読みが要るか」で決まり（タクズ難易度.md §8.2）、基準時間は「その問題で何回探し、何回行を読むか」で決まる。同じレベルでも、作業の量が違えば基準時間は違う。

プレイ時に解法器を動かさないよう、局面の数と行・列を読む局面の数は生成時の分析結果として問題集に持たせた（§7）。解法器で1問を解き直す時間は Bun で平均 0.7 ms で、実行時に計算することもできるが、問題集の他の値（解・難易度）と同じく生成時に確定させ、`--verify` で分析結果と一致することを確かめる方にした。

### 5.2 案の比較

| 案 | 式 | 難易度ごとの基準時間の中央値（1 / 2 / 3 / 4 / 5） |
| --- | --- | --- |
| T1 | 10秒 + 3秒 × 空きマス | 2:16 / 2:25 / 2:28 / 2:25 / 2:28 |
| T2 | 10秒 + 2秒 × 空きマス + 4秒 × 局面 | 1:58 / 2:36 / 2:50 / 2:52 / 3:02 |
| **T3（推奨）** | 10秒 + 2秒 × 空きマス + 3秒 × 局面 + 10秒 × 行・列を読む局面 | 1:52 / 2:21 / 2:47 / 2:59 / 3:25 |
| T4 | 10秒 + 2秒 × 空きマス + 5秒 × 1か所しかない局面 + 10秒 × 行・列を読む局面 | 1:37 / 2:00 / 2:28 / 2:44 / 3:15 |
| T5 | T3 に「1か所しかない局面 × 3秒」を足し、局面・行を読む局面の係数を下げたもの | 1:48 / 2:20 / 2:46 / 3:00 / 3:26 |

（事実（実測）: 問題集 2,500問で計算。）

案を比べる物差しとして、解法器の経過から1問ずつ所要時間を見積もる **参照モデル** を置いた（推測。係数は仮定）。

- 盤面把握 5秒。
- 置くタイル1枚ごとに、A は 1.0秒、B は 1.5秒（巡回で2回押す）。
- ラウンドごとに、次の一手を探す時間 = 手筋ごとの探索時間 ÷ √(確定を与える場所の数)。探索時間は A 2秒、B 4秒、C 8秒、D 10秒、E 15秒。場所が多いほど早く見つかる。

参照モデルは「同じ腕前の人が、どの問題にどれだけ時間がかかりそうか」を1問ずつ表すための仮定で、所要時間の絶対値は当てにしない。見たいのは、基準時間がこの見積もりに沿って問題ごとに伸び縮みするか、つまり **同じ腕前の人が、どのレベルを選んでも同じくらいの速さの点を取れるか** である。

| 案 | 参照モデルとの順位相関（全体） | 同（レベル内。1 / 2 / 3 / 4 / 5） | 参照モデルの 2.0倍の時間で解く人の速さの点（中央値。1 / 2 / 3 / 4 / 5） |
| --- | ---: | --- | --- |
| T1 | 0.69 | 0.77 / 0.62 / 0.48 / 0.38 / 0.42 | 40 / 32 / 25 / 20 / **9** |
| T2 | 0.94 | 0.95 / 0.98 / 0.94 / 0.92 / 0.88 | 37 / 36 / 33 / 29 / 23 |
| **T3** | **0.99** | 0.95 / 0.97 / 0.96 / 0.93 / 0.95 | **35 / 32 / 32 / 31 / 29** |
| T4 | 0.98 | 0.84 / 0.92 / 0.94 / 0.95 / 0.96 | 28 / 23 / 26 / 27 / 27 |
| T5 | 0.99 | 0.95 / 0.97 / 0.97 / 0.97 / 0.97 | 33 / 31 / 32 / 31 / 30 |

（事実（実測）: 問題集 2,500問で、参照モデルと各案を計算して比べた。参照モデルの係数は仮定。）

- **T1（空きマスだけ）を採らない**。問題集は全レベルを空きマス 40〜48 から採ったので（タクズ難易度.md §14.1）、T1 の基準時間はレベルによらずほぼ同じ 2分半になる。一方で上のレベルほど次の一手を探す時間と行を読む時間が増えるので、同じ腕前の人でも難易度5 では速さの点が大きく下がる（上の表で 40点 → 9点）。これは「高いレベルを選んだだけで点が下がる」規則で、前提調査 §13.3 に反する。
- **T3 を推奨する**。参照モデルとの相関が最も高い組（T3・T5）の中で使う量が3つと少なく、利用者へ「置くマスの数、探し直す回数、行を読む回数に応じて目安の時間が決まる」と説明できる。T5 は「場所が1か所しかない局面」を足すが、T3 との差は小さく（上の表で差は0〜2点）、量を1つ増やす価値が薄い。
- T4 は局面の数の代わりに「1か所しかない局面」を使う案。難易度1 で見積もりとの相関が下がる（0.84）。難易度1 は場所が多い局面ばかりで、この量がほぼ0になり、探し直す時間を表せない。
- 注意: T3 と参照モデルはどちらも「行・列を読む局面ほど時間がかかる」と仮定しているので、相関の高さはその仮定を共有していることにも由来する。T3 が正しいことの証拠ではなく、「その仮定を採るなら、少ない係数でよく追える」ことの確認である。仮定そのものは §9 の実プレイで確かめる。

### 5.3 T3 の係数の根拠（推測）

| 係数 | 値 | 根拠 |
| --- | ---: | --- |
| 盤面把握 | 10秒 | 8×8 に固定マスが16〜24個ある盤面を見渡し、どこから始めるかを決める時間。15パズル（導入中）の盤面把握 10秒、ウォーターソート・マインスイーパーの 5秒より、見る対象が多い |
| 空きマス1つ | 2秒 | タップ1〜2回（B は巡回で2回。平均 1.5回）に、置く前に3マスの形や行の個数を確かめる一瞥を足した時間。1秒未満の操作時間の約2倍を読みの確認に見込む |
| 局面1つ | 3秒 | 手元の流れが止まり、盤面を見渡して次に確定できる場所を探す時間。難易度1 は1局面で平均 8.5か所に確定の手掛かりがあり（タクズ難易度.md §14.4）すぐ見つかるが、難易度2 以上では2〜3か所に減る。1局面あたりの平均として置いた |
| 行・列を読む局面1つ | 10秒 | 行全体の個数を数え、残りの置き方を並べ、必要なら完成済みの行と見比べる時間。3マスの形を見るだけの手筋（A）の数倍と見込んだ |

**事実（実測）: 問題集での基準時間の分布**（`bun run --cwd frontend generate:takuzu-pool -- --verify` の出力。秒）

| 難易度 | 最小 | 25% | 中央値 | 75% | 最大 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 102 | 107 | 112 | 119 | 158 |
| 2 | 111 | 131 | 141 | 154 | 191 |
| 3 | 121 | 156 | 167 | 180 | 225 |
| 4 | 135 | 166 | 179 | 193 | 277 |
| 5 | 150 | 190 | 205 | 223 | 294 |

- 基準時間は、置き直しなく迷わず解ける人の目安として、8×8 のバイナリパズルで難易度1 が2分弱、難易度5 が3分半程度になるように置いた（推測。実プレイでの校正前）。
- 同じレベルの中でも作業の量で基準時間が変わる。例: 難易度1 の `tk-adjacency-0-96`（空きマス 44、局面 20）は、局面が多く次の一手が見つけにくい問題で、基準時間 2:38 は同じ難易度1 の `tk-adjacency-0-103`（空きマス 44、局面 6）の 1:56 より長い。

## 6. 配点案の比較

同じ基準時間（T3）で、配点と減点を変えた5案を §7 の代表的なプレイ例で比べた。時間は基準時間に対する倍率。

| 例 | 時間 | 置き直し | やり直し | **R 推奨**: 正確さ60 / 速さ40、置き直し −5、やり直し −15 | A: 速さ50 / 正確さ50、−5、−10 | B: 正確さ60 / 速さ40、−5、−10 | C: 正確さ60 / 速さ40、−10、−15 | D: 正確さ40 / 速さ40 / 安定20、−5、安定 −10 |
| --- | ---: | ---: | ---: | --- | --- | --- | --- | --- |
| a 迷いなく速い | 0.8× | 0 | 0 | 100 perfect | 100 perfect | 100 perfect | 100 perfect | 100 perfect |
| b 基準ちょうど | 1.0× | 0 | 0 | 100 perfect | 100 perfect | 100 perfect | 100 perfect | 100 perfect |
| c 少し遅い | 1.2× | 0 | 0 | 92 great | 90 great | 92 great | 92 great | 92 great |
| d やや遅い | 1.4× | 0 | 0 | 84 good | 80 good | 84 good | 84 good | 84 good |
| e 遅い | 1.7× | 0 | 0 | 72 clear | 65 clear | 72 clear | 72 clear | 72 clear |
| f とても遅い | 2.5× | 0 | 0 | 60 clear | 50 clear | 60 clear | 60 clear | 60 clear |
| g 押し間違いを1回直す | 0.9× | 1 | 0 | 95 great | 95 great | 95 great | 90 great | 95 great |
| h 置き直し2回 | 1.0× | 2 | 0 | 90 great | 90 great | 90 great | 80 good | 90 great |
| i 置き直し3回 | 1.0× | 3 | 0 | 85 good | 85 good | 85 good | 70 clear | 85 good |
| j 試し置きを1回たどり4マス直す | 1.2× | 4 | 0 | 72 clear | 70 clear | 72 clear | 52 clear | 72 clear |
| k 速いが試し置きで6マス直す | 0.6× | 6 | 0 | 70 clear | 70 clear | 70 clear | 40 clear | 70 clear |
| l 試し置きを重ねる | 1.5× | 10 | 0 | 30 clear | 25 clear | 30 clear | 20 clear | 40 clear |
| m 置き直しなしで1回やり直す | 1.0× | 0 | 1 | **85 good** | 90 great | 90 great | 85 good | 90 great |
| n 行き詰まってやり直す | 1.5× | 1 | 1 | 60 clear | 60 clear | 65 clear | 55 clear | 65 clear |

- **A（50 / 50。前提調査の例）を採らない**。置き直しなしで遅い（e・f）プレイが、速いが試し置きで何マスも直した（k）プレイ以下になる（e 65 < k 70、f 50 < k 70）。正確さを重くするという §2 の方針と逆になる。
- **C（置き直し −10）を採らない**。押し間違いを2回直しただけで `good` へ落ちる（h）。巡回入力では押し間違いが置き直しに混ざる余地が残るので（前提調査 §13.2）、1回あたりの減点を小さくしたい。
- **D（ナンプレ型の3観点）を採らない**。やり直しを別の観点に分けると、置き直しをいくら重ねても安定の20点が残り、試し置きを重ねたプレイ（l）が他案より高くなる（40点）。タクズのやり直しは「盤面を捨てる」操作で、置き直しと同じ正確さの問題として扱う方が意味が通る。
- **B と R の差はやり直しの重さだけ**。B ではやり直しても（m）`great` に残る。やり直しは盤面の試し置きをまとめて消せる操作で、消したマスは置き直しに数えないので、やり直しを軽くすると「行き詰まったら消して始め直す」方が、直しながら進めるより高くなる場合がある。R では1回で最高 `good` とした。
- R は、既存ゲームの共通の枠（速さ40点、各観点を0〜満点に収める）にも揃う。

基準時間に対する倍率で決まるので、同じ例はどの難易度でも同じ点になる（導出）。高いレベルを選んだことだけでは点は上下しない。

明らかに良い／悪いプレイとの矛盾が無いかの確認（導出。`score.test.ts` の「代表的なプレイ例」で固定）:

| 確認 | 結果 |
| --- | --- |
| 速く正確なプレイ（a・b）が最も高い | 100。`perfect` はこの2つだけ |
| 置き直しなしで少し遅い（c）は、速いが試し置きで直した（k）より高い | 92 > 70 |
| 置き直しなしでやや遅い（d）も、k より高い | 84 > 70 |
| 置き直しなしで基準の2.5倍（f）でも、試し置きを重ねた（l）より高い | 60 > 30 |
| 同じ速さなら、置き直しが多いほど低い | 0回 100、1回 95、2回 90、3回 85、6回 70、12回 40 |
| 押し間違いを1回直しただけ（g）で段階を大きく落とさない | 95 `great` |
| やり直しを使ったプレイ（m・n）は、使わずに同じ時間で解いたプレイより低い | m 85 < b 100、n 60 < 置き直し1回・1.5倍の 75 |

同じ実時間で解いた場合は、作業の量が多い問題ほど点が高い（事実（実測）: 置き直しなしで2分なら、問題集の中央値で難易度1 97点、難易度2〜5 100点。3分なら 76 / 89 / 97 / 100 / 100点）。これは難易度1 の問題の方が短い時間で解けて当然だからで、難易度そのものへの加点ではない。

## 8. 記録と自己ベスト

実装: `frontend/src/games/takuzu/play-record.ts`。

| payload | 内容 |
| --- | --- |
| `difficulty` | `"1"`〜`"5"` |
| `problemIdentity` | `{ generatorVersion, seed, conditions: { size, removalTechniqueLimit, extraGivenCount } }`。再プレイで問題を復元する |
| `workload` | `{ emptyCellCount, roundCount, lineReadingRoundCount }`。遊んだ問題の作業の量 |
| `performance` | `{ elapsedMs, correctionCount, restartCount, inputCount }`。プレイの事実 |

- 評価点・評価段階・基準時間・基準時間との差は保存しない。記録から現在の評価規則で導出する（`SPEC-006`）。
- `workload` を記録に持つ理由: 評価を記録だけから再計算できるようにするため。問題集を作り直して identity から問題を引けなくなった記録（前提調査 §12.2）でも、評価と自己ベストの比較は続けられる。マインスイーパーの「開く操作の最小回数」、15パズルの「最短手数」と同じ扱い。
- 読み込み時の検証: ゲームID・payload の版・難易度・identity の形（生成器の版、8×8、既知の手筋名、戻す数が0以上の整数）・作業の量（空きマスが1〜64、局面が1以上で空きマス以下、行・列を読む局面が局面以下）・事実（経過時間が有限の0以上、各回数が0以上の整数、置き直しが入力回数以下）を確かめ、どれかが崩れた記録は読み込まない。

**自己ベスト**（比較単位は難易度）:

| 指標 ID | 良い向き | 理由 |
| --- | --- | --- |
| `play-score` | 高い | 評価そのもの |
| `time-delta-ms` | 小さい | 基準時間に対するクリア時間の差。問題ごとに作業の量が違うので、実時間ではなく差で比べる（ウォーターソートと同じ） |
| `correction-count` | 小さい | 読みの正確さ。タクズの良いプレイの中心 |

共通の記録画面・結果画面への登録（表示ラベル、改善量の文言、記録一覧・再プレイへの接続）は、結果画面・記録の段階で行う。この段階は記録の形と比較の定義までを持つ。

## 10. 限界

- **実プレイをしていない**。基準時間の係数、参照モデルの係数、減点の重さはすべて仮定で、§9 で校正する。
- 参照モデルと T3 は「行・列を読む局面ほど時間がかかる」という同じ仮定に立つ（§5.2）。
- **ラウンドの定義**: 解法器は同じ手筋で確定するマスをまとめて1局面とする。人間は1マスずつ置き、置いたマスから次の形が見えるので、実際に探し直す回数は局面の数より少ないことがある（タクズ難易度.md §12）。
- **置き直しの数え方**: 同じマスを押し続ける間は数えない。違反の印を見て同じマスの値をすぐに変える使い方は置き直しにならない（前提調査 §7.3 で、分かるのは盤面を見ればすぐ分かる直接の違反だけと判断した）。
- **押し間違い**: 別のマスへ移ってから気づいて直した押し間違いは置き直しに数える。読み違いと区別できない。
- 経過時間は開始からクリアまでで、アプリを離れていた時間も含む（既存ゲームと同じ）。

## 11. ずれた場合の見直し方針

1. 良いプレイの定義（§2）が遊ぶ人の感覚と合っているか。速さを正確さより重く感じるなら、配点（§6 の A）を見直す。
2. 観点に対する事実が合っているか。置き直しが押し間違いばかりを数えているなら、数え方を見直す（session の事実）。
3. 基準時間の量（§5.1）が時間のかかり方を表しているか。レベルで偏るなら、使う量（例: 1か所しかない局面、T5）を見直す。
4. そのうえで係数を動かす。

係数だけを変える場合、記録は事実だけを持つので、過去の記録も新しい規則で評価し直される（`SPEC-006`）。解法器を変えて局面の数の数え方が変わっても、記録の `workload` は記録時の値のまま使う。
