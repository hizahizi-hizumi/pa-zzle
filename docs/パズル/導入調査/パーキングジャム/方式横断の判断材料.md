# パーキングジャムの方式横断の判断材料（#727）

Issue #727 の採否判断に使う材料をまとめた資料。現行ルール（以下クラシック）の再評価と、新ルール候補3方式の検証結果を同じ観点で並べる。方式ごとの根拠は、[出庫指令型の供給検証.md](出庫指令型の供給検証.md)、[乗客列型の検証.md](乗客列型の検証.md)、[同色ペア型の検証.md](同色ペア型の検証.md)にある。用語（判断局面、最小枠数、余裕、開口）はそれらの資料と同じ意味で使う。正式なルール・難易度・問題集・記録は変更していない。

## 結論

- クラシックには、選ぶと解けなくなる手が無い。ルールから導け、問題集5,000問の全到達状態でも0件だった。5段階が強めているのは、出せる車を見つける手間と、向きや車線の見誤りである。
- 新ルール候補のうち、選択に正誤がある問題を5段階に分けて作れたのは出庫指令型だけである。ただし、判断の型がほぼ1種類で、段階の一部が台数でしか分かれず、人による確認をしていない。
- 提案は「クラシックを維持し、出庫指令型を同じゲームの別の遊び方の候補として、人による試遊で確かめる」。クラシックを新方式へ置き換えることは提案しない。
- どの方式も、人が感じる難しさと面白さは確かめていない。採用の判断には人による試遊が要る。

## クラシックの再評価

### 選ぶと解けなくなる手が無い

車が出庫できるかは、盤面で決まる条件（向き、その車線の開口、進路の固定物）と、進路に残っている車の有無で決まる。残っている車が減るほど、出せる車は増えるだけである。出庫の順で解けなくなることは無い。

問題集5,000問の全到達状態（3,414,667状態）を、本番のコードを使わない別実装で数えた。

| 数えたもの | 件数 |
| --- | ---: |
| 車が残っているのに出せる車が無い局面 | 0 |
| 判断局面（選ぶと解けなくなる手がある局面） | 0 |
| 出庫の後に、ほかの車の出せる手が消えた例 | 0 |

固定物のある 2,425問、開口の無い向きを持つ車がいる 4,996問でも同じだった。新ルール候補の物差しでは、全問が判断局面0に当たり、出せる車を見つけて出すだけで全問が解ける。

正本（main の `docs/プロダクト/パズル/PZL-007-パーキングジャム.md`）は、手詰まりにならない問題を提供し、見えている進路と塞がり方を読むことに挑戦を絞る、としている。判断局面が無いことは、仕様どおりの性質である。

### 5段階が強めているもの

採点が測るのは、時間と、出せない車や方向を押した回数である。手数は車の台数で決まり、評価しない。

レベルごとの中央値（別実装による全件の集計）:

| 指標 | Lv1 | Lv2 | Lv3 | Lv4 | Lv5 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 最初に出せる車の割合 | 0.73 | 0.75 | 0.63 | 0.64 | 0.63 |
| 出せる車の割合（無作為に出し続けたときの手番の平均） | 0.81 | 0.83 | 0.72 | 0.75 | 0.65 |
| すぐ出せる車を出し尽くした後の残り台数 | 3 | 2 | 4 | 4 | 4 |
| それをもう一度繰り返した後の残り台数 | 0 | 0 | 1 | 1 | 2 |

- どのレベルでも、最初から過半の車が出せる。深い依存は、出せる車を出し尽くした後の数台にだけ現れる。Lv5 でも、3段目以降に出る車が3台以下の問題が 94% である。
- 遮断関係を逆向きにたどる読みは、解くのに要らない。出せる車を探して出すことを繰り返せば解け、終盤は車が少ない。
- Lv1 と Lv2 は、出せる車の割合が同じで、見誤りを誘う車の割合だけが違う。
- 同じ盤面と台数で比べると、Lv4 は Lv3 より出せる車の割合が高い。上がるのは見誤りを誘う車の割合だけである。現行の難易度文書が挙げていた「Lv4 が Lv3 より易しく感じるおそれ」と合う。
- Lv5 は台数だけで決まってはいない（8台の Lv5 が 217問ある）。Lv5 を分けているのは、出せる車が少ない局面の多さである。

5段階の差が人に難しさとして感じられるかは、確かめていない。既存の監査（`docs/メモ/全10ゲーム問題品質実態調査-2026-11-07.md`）も、人による校正は無いとしている。

### 価値と限界

- 構造から言えること: 失敗で詰まない。押し間違いは点数が減るだけで、盤面は変わらない。読むのは盤面だけで、指令も待機枠も無い。計画や先読みは、問題の作り方をどう変えても作れない。
- 確かめていないこと: 詰まないことが、気持ちよさになるか物足りなさになるか。見誤りを誘う車が、人の実際の押し間違いに効いているか。

## 4方式の比較

| 観点 | クラシック | 出庫指令型 | 乗客列型 | 同色ペア型 |
| --- | --- | --- | --- | --- |
| 選ぶと解けなくなる手 | 無い | ある。すべて車の遮断から生じる | ある。問題の作り方によって、4〜9割が車の遮断で決まる | ある。すべて車の遮断から生じるが、ほかの色を待たせない手を選べば避けられる |
| 判断の型 | — | 同色2台のどちらを先に使うかが 90〜99.9% | 同じ定員の同色車の使い分けに加え、定員と遮断の両方を読む判断がある | どの色を先にそろえるかの1種類 |
| 判断のある問題の多さ | 0 | 8台・余裕0の無作為な問題の 20% | 有利な条件で 45〜49% | 8台・余裕0の無作為な問題の 0.4%。条件を絞って1割弱 |
| 5段階 | ある。見つける手間と見誤りで分かれる | 機械的な基準を置けた。Lv2 と Lv3 は台数でしか分かれない | 置けなかった | 置けないと判断し、作っていない |
| 上位の問題の供給 | 問題集5,000問がある | Lv4・Lv5 で CPU 1分あたり 11〜38問 | 段階が無いので測れない | 出庫指令型の約10分の1 |
| 読む情報 | 盤面 | 盤面、指令（台数と同じ長さ）、待機枠 | 盤面、乗客の列（8台で約20人）、待機枠、定員 | 盤面、待機枠 |
| 試遊 | 人による校正なし | AI が15問。Lv2 と Lv3 は体感で分かれず、2問は Lv より2段以上易しい | なし | なし |
| 提案 | 維持 | 保留。候補として残す | 保留。出庫指令型の後に回す | 基本ルールは不採用 |

- 数値は方式ごとに母集団と数え方が違う。順位を付けるためのものではない。
- 同色ペア型のルールを変えた「同色4台のうち2台がそろうと出発」の案は、判断のある問題の割合では出庫指令型に並ぶ。判断の型が出庫指令型と重なり、探索と供給は測っていない。

## 置換・複数の遊び方・現行維持

| 案 | 得るもの | 失うもの・要るもの |
| --- | --- | --- |
| クラシックを新方式へ置き換える | 計画と先読みのあるゲームになる | 正本の出題方針（手詰まりにならない）を変える。既存の記録・自己ベスト・図鑑が、今の問題集と採点に結び付いている。新方式の5段階は人で確かめていない |
| 同じゲームに遊び方を足す | クラシックの記録と図鑑を保ったまま、計画のある遊び方を試せる | 問題ID・記録・比較単位・図鑑に遊び方の区別を足す。チュートリアルと画面構成が遊び方ごとに要る |
| 現行維持 | 変更なし | 「出庫順を誤って詰む判断が無い」という #727 の問題意識は残る |

提案は、クラシックを維持したうえで、出庫指令型を遊び方の候補として人による試遊で確かめることである。

- 置き換えを提案しない理由: 出庫指令型の5段階は機械的な基準で、難易度開発手順の条件（規模で段階を埋めない、人による校正）を満たしていない。クラシックの詰まない性質は正本が定めた出題方針で、既存の記録と図鑑がそれに結び付いている。
- 遊び方を足すかどうかを、今は決めない理由: 出庫指令型が別々に遊ぶ価値を持つかは、人の体感でしか分からない。試遊の前に本番の問題ID・記録・図鑑を変えると、不採用のときに戻す作業が要る。

### 試遊で確かめること

比較試作画面（`/puzzles/parking-jam/lab`）に、出庫指令型の Lv1〜Lv5 の15問、乗客列型の8問、同色ペア型の4問がある。

- 出庫指令型の Lv の順が、体感の順と合うか。特に Lv2 と Lv3、4辺が開く盤面の上位レベル。
- 同色2台の使い分けを覚えた後も、Lv3〜Lv5 に差が残るか。
- 原因が何手も前にある詰みを、納得できるか。
- クラシックと出庫指令型を、別々に遊びたいと感じるか。
- スマホ幅で、盤面・指令・待機枠を読めるか。今の試作画面は一度に表示できない。

## 遊び方を足す場合に影響を受ける箇所

main のコードと正本を読んで確かめた事実である。設計は決めていない。

- 正本 `PZL-007`: 出題方針・難易度・評価がクラシックを前提に書かれている。
- 問題ID: identity 全体のハッシュで、遊び方の欄が無い。新方式の問題は、identity に違う値を持たせないと区別できない。
- 記録: 遊び方の欄が無い。採点の版が今の版と一致しない記録は読まない作りなので、採点の版を差し替えると既存の記録が読めなくなる。成功した出庫の数が台数以上であることも検査している。
- 自己ベスト: 比較単位が難易度だけである。同じゲームに別方式の記録を入れると混ざる。
- 図鑑: 番号は問題集の並び順から付く。同じ問題集に別方式を足すと既存の番号が変わりうる。今の問題集から引けない記録は図鑑に出ない。
- 採点と結果: 押し間違い・待った・やり直しの回数だけを持ち、詰みを表す欄が無い。
- プレイ画面の行き先: 難易度と問題IDだけで決めている。

既存の記録を保つために守ること:

- 今の問題集の identity と問題IDを変えない。
- 遊び方の欄が無い記録を、クラシックとして読む。
- 採点の版と記録の版は、今の版を読む分岐を残して足す。
- 比較単位と図鑑の番号を遊び方ごとに分け、クラシックのものを動かさない。
- クラシックの問題集を残す。

```bash
python3 scripts/research/parking_jam_classic_audit.py dump --with-features --output <dump.jsonl>

```

クラシックの集計は `scripts/research/parking_jam_classic_audit.expected.json` にある。`dump` は本番のコードを `bun` で呼んで問題集を書き出す。新ルール候補の再現手順は各資料にある。
