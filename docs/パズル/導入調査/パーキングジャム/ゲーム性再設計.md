# パーキングジャム：ルール再設計の比較検証（#727）

## 判断と前提

**現時点では採用する新ルールを決めない。** 現行のゲームは出庫の気持ちよさがある一方、可解な初期盤面なら合法な出庫によって別の車の合法手を失うことはなく、手順を選び間違えて詰むことがない。問題の依存関係を深くしても、この単調性は変わらない。#708の画面・手触りの磨き込みより先に、ゲーム自体に考える価値を作れるか評価する。

この資料は比較試作の記録であり、正式なルール・問題集・採点・記録の変更ではない。箱入り娘と重複するRush Hour型の盤面内スライドは候補から外す。

「難しい」を次の観点に分ける。

1. **事前に読み取れる選択**：合法な出庫でも有利・不利が生じ、盤面の情報から理由を予想できる。
2. **駐車場を考える必要**：車の位置・方向・開口・遮断が、色や受付の順序より重要な判断に関わる。
3. **先読みの質**：目の前の一手で待機枠が満杯になるだけでなく、数手後の結果が変わる。
4. **解く過程の多様性**：問題の数・色数・失敗率ではなく、異なる手筋と納得できる発見を得られる。
5. **ゲームとしての成立**：問題生成の収率、繰り返し遊べる難易度、スマートフォンでの視認性、既存ゲームとの差別化。

## 4方式の比較画面

`/puzzles/parking-jam/lab` で以下の4方式と8台・12台の盤面を切り替えられる。同じ規模では車の配置と色を固定し、出庫後のルールだけを変える。現行の出庫可否判定を利用する。車の出庫、待った、最初から、全探索による答えの表示（検証用）を備える。固定障害物なし・四辺の全開口という**実際の問題集より緩い**条件である。

| 方式 | 待機枠の解放 | 想定した思考 | 初期所見 |
| --- | --- | --- | --- |
| 現行 | 出庫と同時に完了 | 遮断車の発見 | 合法手の選択による失敗なし |
| 同色ペア | 同じ色が2台そろったら同時出発 | どの色の車を解放するか | 2枠はペアの即時完成、3枠も短期の枠管理に偏る |
| 乗客列 | 左から順に乗り、車体長（2/3人）まで乗ると出発 | 駐車場・乗客順・容量の先読み | 長い列の読解が主役になる危険 |
| **出庫指令** | 表示された色の指令を先頭から1車ずつ消化し出発 | 遮断解除と、今待たせるべき車の計画 | 列が短く、乗客UIなし。遅れて表面化する悪手を作れるが、色照合だけになる危険 |

同色ペアと出庫指令は2～5枠を切り替えられる。乗客列は3枠固定。各方式では全情報を公開し、隠し情報による運任せを避ける。出庫指令型は単純な依頼列として以前に初手のみを評価していたが、**途中局面の先読みと遮断依存を測って再評価**した。

### 待機枠数による許容度と判断の変化

出庫指令の選抜した同一盤面について、**毎手合法な車を等確率で無作為に選ぶ**モデルのクリア確率を測定した。人間のクリア率ではなく、誤った選択がどれほど許されるかを比較する補助指標である。

| 待機枠 | 8台の無作為クリア確率 | 12台の無作為クリア確率 | 8台の出庫順数 | 12台の出庫順数 |
| --- | ---: | ---: | ---: | ---: |
| 2枠 | 0.44% | 0.05% | 42 | 5,556 |
| 3枠 | 5.62% | 1.17% | 512 | 141,836 |
| 4枠 | 21.09% | 5.60% | 2,010 | 664,876 |
| 5枠 | 42.14% | 15.39% | 4,272 | 1,829,719 |

12台では4・5枠でも駐車場の遮断を無視すると初めて成功する悪手があり、誤りが数手後に判明する局面も残る。枠を増やすほど必ず思考が浅くなるとはいえない。一方、5枠はスマートフォンの待機エリアを圧迫し、枠数だけで難易度を一律に上げ下げする設計は不適切。難易度ごとに操作の自由度、情報量、手筋の深さを併せて調整する必要がある。

## 探索方法：詰み率ではなく、失敗の原因を検証

- `scripts/research/parking_jam_rule_space.py`：既存のJavaScriptルールを呼ばない、独立の車両衝突・出庫・有限枠・全探索器。seed 727、8台・12台各120問の予備標本。四辺開口・固定物なし、色ペアは無作為、乗客列と指令列は可解な出庫順から構成。
- `scripts/research/parking_jam_choice_quality.py`：独立モデルで到達可能かつ可解な局面を列挙し、悪手後に何手進められるか、盤面の車両遮断を取り除く反実仮想で悪手が成功に変わるか、合法手を無作為に選んだ場合の全クリア確率を測る。seed 20261109、8台・12台各20問の探索標本（大標本では計算コストが高いため、この小標本は比較指標の検証用）。
- **反実仮想の限界**：車の遮断を無視したときだけ成功する悪手を「駐車場固有の判断に関与する可能性」と呼ぶ。これだけで人間が遮断関係を実際に理解したと証明するものではない。

### 20問×2規模の探索：失敗までの遅れと遮断依存

以下は可解な局面全体で、少なくとも1つの正しい選択と1つの悪手がある局面を調べたもの。悪手を選んだ後、**最善でも2手以上は続けられる**問題を「遅れて失敗」、車の遮断を取り除くと成功に変わる悪手がある問題を「遮断が本質的な悪手あり」とした。あくまで小標本の件数で、発生確率の推定ではない。

| 方式 | 8台：遅れて失敗 / 遮断が本質的 | 12台：遅れて失敗 / 遮断が本質的 |
| --- | --- | --- |
| ペア2枠 | 0 / 14 | 0 / 20 |
| ペア3枠 | 0 / 5 | 0 / 18 |
| 乗客列3枠 | 14 / 3 | 20 / 3 |
| 出庫指令2枠 | 2 / 6 | 10 / 14 |
| 出庫指令3枠 | 1 / 3 | 7 / 11 |

**暫定的な評価**：ペア型は駐車場の遮断が悪手に関与するものの、実際の失敗が待機枠の即時満杯に帰着しやすい。乗客列型には遅れた失敗があるが、駐車場の遮断なしでも失敗する局面が多い。出庫指令型は乗客列より少ない情報量で、遮断と遅れた失敗が両方ある。ただし指令列を読む作業そのものが面白いとは確認できていない。

## 現行の正式問題集へ仮に当てはめると

現行Lv1〜Lv5の問題集からそれぞれ4問を`selectParkingJamProblemForDifficulty(level, "issue727-<level>-<0..3>")`で復元した20盤面を使った。正式な固定物・開口・車両の向きを保持し、比較ルールの色・指令・乗客列は別途与えた（色はseed 9090+連番のPython乱数、指令と乗客列は合法な全出庫順に基づく）。各盤面への適合性の予備調査であり、新ルールの問題集サンプルではない。

- 車両数が奇数の問題が**20問中6問**あり、ペア型はそのままでは成立しない。
- 偶数車両の14問に対し、無作為にペア色を付けた2枠方式は**3問で不可解**だった。単に現行の盤面へ色を足すだけでは足りない。
- 同じ20問への指令2枠・3枠・乗客列3枠はすべて可解だったが、これらの順番は可解な出庫順を元に構成したため、可解率を測ったものではない。
- 指令2枠で初手の悪手があるのは**20問中3問**。固定物・限られた出口がある現行問題では、初手だけを見ても挑戦の質は十分には分からない。

## 問題選抜の収率：ルールだけでは良問を供給できない

`python scripts/research/parking_jam_selection_poc.py --sample 30 --seed 20261109` では、四辺開口・固定物なしの試作専用生成器から、8台30問・12台30問を構築した。出庫指令は必ず可解な出庫順を起点に作っているため、全枠数で全30問が可解。これは新ルールの一般的な問題生成成功率を測っているわけではない。

機械的に判定できる**仮の選抜条件**として次の両方を同時に要求した。

- 合法手を等確率で選んだときのクリア確率が5～50%で、あまりに一手の失敗が厳しい問題でも、適当に遊んでも解けるだけの問題でもない。
- 最初の3手以内の可解局面に、選ぶと2手以上は進めるものの最終的に詰み、かつ車両の遮断を無視すれば成功に変わる悪手がある。

| 生成規模 | 2枠 | 3枠 | 4枠 | 5枠 |
| --- | ---: | ---: | ---: | ---: |
| 8台30問中、両条件を満たす候補 | 0 | 1 | 1 | 0 |
| 12台30問中、両条件を満たす候補 | 0 | 0 | 0 | 0 |

これは「面白い問題が0～1問」という評価ではない。5～50%という境界も最初の3手という条件も人間校正前の探索用指標であり、別条件なら選抜結果は変わる。無作為な盤面・色・順序を可解にするだけでは、狙った駐車場固有の先読みと適切な許容度を同時に得にくいことを示す。**新ルールを実装する前に、必要な手筋から逆算する問題構築と選抜を設計する必要がある。**


## 難易度5段階と継続供給の評価

**新ルールの可解性、選択による詰み、5段階の難易度、良問の供給はそれぞれ独立に検証する。** この段階では、どの新方式も難易度Lv1〜Lv5が成立したとは判定しない。

pa-zzle の難易度は問題数・盤面規模・失敗率ではなく、そのパズル固有の思考をどの程度要求するかを表す。5段階に意味のある体験差があり、各段階へ継続供給できることが採用条件（難易度提供.md）。現在のクラシックは各レベル1,000問を保有し、67,968候補を走査して5,000問を採用した実績があるが、Lv1〜Lv5の人間校正は未実施である。新方式の予備標本と同一条件での収率比較には使えない。

| 方式 | 5段階を作り分ける可能性 | 継続供給上の懸念 | 現時点の判定 |
| --- | --- | --- | --- |
| クラシック | 遮断の依存・読み違い・規模で分類済み | Lv5を含む思考の面白さは未校正 | 問題数は確保、挑戦強度は未実証 |
| 同色ペア | 相方の解放と少数の保留を扱うが、即時の待機枠満杯に偏る | 奇数台はそのまま使えず、同型・近似手順が増えやすい | 独立した5帯を支える根拠が弱い |
| 乗客列 | 定員、乗客順、遮断、待機枠を別々に強められる | 列の長さによる作業負荷が難易度と混ざり、駐車場の役割が薄れる | 可能性はあるが未実証 |
| 出庫指令 | 遮断の先読み、指令の先送り、待機枠の予約、複数依存の競合を組み合わせられる | 解く価値がある問題の選抜収率が低い（上の30問予備標本） | 最優先の検証対象、5帯成立は未実証 |

出庫指令型については、まず次の**解く体験の段階差**を仮説として作り、数値の閾値より先に実在する代表問題を用意する。

| 仮のレベル | 何を読んで解くか |
| --- | --- |
| 1 | 目前の指令を満たすため、単純な遮断を1つ解く。色照合だけではない |
| 2 | 先に必要な車を出せないとき、1台を待機させて指令の車を解放する |
| 3 | 今の指令と次の指令を見比べ、2段以上の遮断関係と枠の空きを計画する |
| 4 | 複数の解放経路やおとりがあり、先に待機させる車を選び直す判断が要る |
| 5 | 異なる依存系列が待機枠を奪い合い、数手先の枠開放まで組み合わせて計画する |

これは**難易度仕様や採用基準表ではない**。各段の一言に対応する人間向け手筋と問題例が見つからない、Lv4と5が単なる台数差になる、素朴な一手読みで高位も解けるときは、枠数や閾値を調整する前にルール・問題構築を見直す。

供給性は「可解な盤面を生成できるか」だけでなく、次の工程の実測を分けて扱う。

1. **候補生成**：車両配置・出口・固定物・色・指令を再現可能なseedで生成し、候補生成時間と失敗率を測る。可解な出庫順から指令を作る方式は、可解性を保証する一方、難しさの分布を偏らせることを明記する。
2. **問題成立と分類**：全探索により解と途中の詰みを確認し、別に人間が使う手筋の特徴を測る。無作為クリア率、状態数、解法順数を難易度と同一視しない。
3. **良問の選抜**：偶然の色照合や即時の枠満杯だけでなく、遮断の読み・将来の枠開放・明示情報から予見可能な悪手を含むものを採る。類似盤面、色名の置換、指令だけ変えた実質同型を除いて数える。
4. **5帯の供給**：レベルごとに分類済み候補の実数・重複除去後の採用数・候補あたりの収率・生成所要時間・手筋の種類を測る。同じ盤面規模の異なる帯を対にして順序と逆転を検証する。
5. **段階的な検証**：まず各帯の代表・境界・異常な問題を遊ぶ。候補数を増やして収率の安定性と実際の供給量を確認してから、問題集の本生成に進む。現在の各帯1,000問という実績は比較目安だが、固定の必要件数とはみなさない。

**現段階で判定できるのは、無作為な可解盤面の選抜だけでは必要な挑戦を安定供給できていないということまで**。5段階の成立と供給可能量は未計測であり、生成不可能と断定しない。

## 複数方式を提供する場合の構成案

**1方式に絞ることは前提にしない。** 共通の駐車場・車の直進出庫を核に保てるなら、クラシックと出庫指令を同じゲームの独立した「遊び方」として持つ案を比較対象にする。乗客列も、固有の挑戦と供給性が確認できれば候補から外す必要はない。

| 提供方法 | 利点 | コスト・問題 |
| --- | --- | --- |
| 1方式へ置換 | 開始導線・チュートリアル・問題集が単純 | 従来の爽快感や既存の遊び方を失う可能性 |
| **同じゲーム内に複数の独立した遊び方** | 気軽な出庫と計画的な出庫を好きに選べる。盤面の題材と操作を共有できる | 各方式ごとに5段階・問題供給・採点・結果・チュートリアルを成立させる必要 |
| 異なる方式を同じ問題集に混在 | モード選択の操作が不要 | レベルによってルールが変わり、難易度の意味・記録比較・学習が不明瞭になるため現時点では推奨しない |
| 別ゲームとして独立 | 問題集・記録・評価を明確に分離 | 駐車場と出庫という体験の重複が大きく、カタログを不必要に増やす |

複数の遊び方を設けるなら、方式ごとの難易度・評価・問題集は**別に設計する**。現行の自己ベスト（SPEC-002）は「ゲーム×難易度」で比較し、図鑑（SPEC-026）はゲーム単位の問題集を表示するため、これをそのまま使ってルールの異なる記録を混ぜない。モードを含む比較単位・問題ID・既存の記録の読み戻し・図鑑のまとまりは、製品側の仕様変更として別途判断する。クラシックの既存問題と記録は消さない前提で比較する。

ただし、**供給性が成立しない方式を「種類が増えるから」という理由で残さない**。同色ペア型は他方式との思考の重複と難易度帯の不足を先に検証する。出庫指令に似た遊びを薄く複数置くより、独立した魅力が証明された方式だけを提供する。

## 次に判断すべきこと

方針は「出庫指令を中心候補として深掘りしつつ、最終的な提供方式の数を決めない」。以下の成果を揃えてから、1方式への置換・複数方式の併存・現行維持を比較する。

1. **5段階の具体的な手筋と問題例**：出庫指令とクラシックをまず比較し、それぞれのLv1〜Lv5の代表、境界、反例を実際に操作して示す。上位が単なる規模や罠の多さではないことを確かめる。
2. **生成器の作り方と収率**：完全な出庫手順を逆算した構成、遮断を作る配置、指令の組み合わせ、選抜器の比較を行う。レベル別の成立・採用率、重複率、時間、未充足の帯を報告する。
3. **複数方式の体験比較**：クラシック・出庫指令を同じゲームの別の遊び方として並べたとき、別々に遊ぶ価値があるか試す。乗客列も十分に異なる価値があれば比較対象に残す。
4. **製品への影響**：モードごとの自己ベスト・図鑑・採点・既存記録と、スマートフォンの導線・表示負担を整理する。採用前にゲーム全体の仕様変更として判断する。
5. **人間による実プレイ**：自動探索は候補の成立性と特性を検証する道具であり、面白さや体感難易度の代替ではない。試遊による納得感と挑戦の差が未確認なら採用しない。
