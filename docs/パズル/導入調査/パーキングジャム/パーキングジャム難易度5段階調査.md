# パーキングジャム難易度5段階調査

> **設計フェーズの調査記録**: Issue #405 の設計段階で、[難易度開発手順](../../難易度開発手順.md) の工程1〜8・11・12 を行った記録である。ここにある挑戦の定義・特徴・分類案・閾値・供給方式はすべて仮説・案であり、現在仕様ではない。現在の判定・供給・採点の正本は [パーキングジャム難易度判定](../../パーキングジャム難易度.md) と [パーキングジャム採点](../../パーキングジャム採点.md) で、このフェーズでは変更していない。工程9（ラベルを伏せた人間の実プレイ）はまだ行っておらず、その準備（問題リスト）までを行った。

## 1. 目的と範囲

現行の `visual-local-load-v1`（初期遮断車数・初期平均最小遮断台数・平均退出距離の等重み平均を 1/3・2/3 で3帯）を、アプリ共通のレベル1〜5へ再構成するための材料を作る。

このフェーズでやったこと:

- パーキングジャム固有の挑戦を言語化し、それを強める要因の候補を挙げた（3章）
- 候補特徴を機械計測する分析スクリプトを追加した（4章）
- 現行候補空間216条件×80 seed の17,280候補（生成成功7,948問）と、拡張候補空間48条件×80 seed の3,840候補（成功1,560問）で分布・相関・規模との関係を測った（5章）
- 提供範囲と5段階分類の案を複数作って比較した（6〜7章）
- 各案で現行供給と同じ方式の供給成功率・時間を測り、事前生成問題集の生成コストを見積もった（8章）
- 代表・境界・異常問題を抽出し、ラベルを伏せた遊び比べリストを用意した（9章、[遊び比べ問題](パーキングジャム難易度5段階_遊び比べ.md)）
- 現行3段階・旧記録・難易度プレビュー・採点への影響を案として整理した（10章）

製品コードの挙動は変えていない。追加したのは `frontend/scripts/` の分析スクリプトだけである。

## 2. 前提

- 車は向きに沿った前後方向にだけ出庫を試み、進路上に車・固定物がなく、その車線の外周が道路開口なら盤外へ消える。
- 合法な出庫は将来の可解性を悪化させない。したがって**合法な車を選び続ければ必ず解ける**。手詰まり・戻し・数手先の盤面配置を作る計画は存在しない（Rush Hour との境界。[再設計PoC](../../パーキングジャム再設計PoC.md)）。
- 不成立操作は盤面を変えないが、採点 `play-quality-v2` の正確さで1回5点減点される。待った・盤面を戻すは安定性で減点される。
- 生成器 version 2 は、車を1台ずつ「置いた時点では出庫できる」位置へ置く逆向き構築で、遮断配置バイアスで後置車が既存車の進路を塞ぎやすくする。候補空間 `candidate-space-v1` は盤面3種×車両3種×開口数2×開口幅2×固定物2×遮断バイアス3の216条件。

## 3. パーキングジャム固有の挑戦（工程1〜2）

### 3.1 挑戦の定義（案）

> **塞がれた車の進路をたどって「どの車を先に出せば道が開くか」を読み、今出せる車とその方向を、試さずに見つけ続けること。**

合法な車を選べば失敗しないので、挑戦は「順序の計画」ではなく**遮断関係の読み取り**にある。プレイヤーは次を繰り返す。

1. 車を見て、前後どちらの車線に開口があるかを読む（方向・車線の読み）
2. その進路上に車・固定物がないかを出口までたどる（進路の読み）
3. 塞がれているなら、塞いでいる車がさらに塞がれていないかを逆向きにたどる（依存の読み）
4. 出せる車を出し、盤面が変わったら次に出せる車を探す（探索）

### 3.2 基準とするプレイ条件（案）

- ルールと操作（スワイプ・車近傍の前後操作）を理解している。
- **不成立操作で試さずに読む**ことを基準にする。不成立で試せば読まずに進めるが、採点上は正確さを失う操作として扱っており、難易度はその試行を前提にしない。
- 待った・盤面を戻すは解法上不要（合法手は手詰まりを生まない）なので、難易度の基準では使わない。

### 3.3 挑戦を強める要因の候補

| 候補 | 観測する特徴（4章） | なぜ人間の挑戦が変わると考えるか |
| --- | --- | --- |
| 待ちの段数（依存の深さ） | `depth`（並列削除の段数）、`deepVehicleCount` | 塞いでいる車自体が塞がれていると、1台を出すために「A の前に B、B の前に C」と逆向きに2段3段たどる必要がある。段数2なら「塞いでいる車はすぐ出せる」ので1段の読みで済む |
| 重なり（AND） | `multiBlockedCount`、`maximumPrerequisiteCount`（最も奥の車を出すまでに最少で先に出す台数） | 1台の進路を2台以上が塞ぐと、複数の依存を同時に保持しないと出せる時点が分からない。段数との差（枝分かれ）が大きいほど、1本の連鎖ではなく木をたどる |
| 見つけにくさ（合法車の少なさ） | `meanLegalRatio`（一様ランダムに合法車を出すプレイでの手番ごとの合法車率の平均）、`meanScanCost`、`expectedScarceSteps` | 残りの車のうち出せる車が少ないほど、どれを見ても塞がれていて探す時間が増える。初期盤面だけでなくプレイ全体で見る |
| 手がかりのない探索 | `expectedUncuedScarceSteps` | 直前の出庫で新たに出せる車ができた手番は、その車線の奥を見れば次が分かる（連鎖解放が手がかりになる）。手がかりがなく合法車も少ない手番は盤面全体を探し直す |
| 連鎖解放 | `cuedStepRatio`、`maximumForcedChainLength` | 1台出すと次が1台だけ空く一本道は、見つけやすい半面「順になぞるだけ」になり得る。挑戦を上げる方向か下げる方向かは未確定 |
| ボトルネック | `maximumRequiredSuccessorCount`、`requiredPrecedenceCount` | 1台を出さないと多数の車が出られない構造。見落とすと盤面全体が止まって見える |
| 解順自由度 | `orderFreedom` | 出す順の自由が小さいほど「どれでもよい」が減る。ただし合法手は失敗しないので、自由度の低さ自体は判断の難しさと直結しない |
| 車線の読み違い | `nearMissVehicleCount`（開口のない方向が1車線ずれた開口に接する車）、`directionChoiceCount`（両方向に開口があり片方だけ塞がれた車） | 開口の端と車線が1つずれていると、出られそうに見えて不成立になる。方向を選ぶ判断が要る車が増える |
| 遠い遮断 | `averageBlockerGap`、`farBlockerCount` | 塞いでいる車が進路の遠くにあると、出口までたどらないと気付けない |
| 現行の局所負荷 | 初期遮断車数、初期平均最小遮断台数、平均退出距離（`visual-local-load-v1`） | 初期盤面での探す・読む・追視する量 |

### 3.4 挑戦として扱わないもの

- 車両数・盤面の広さ・手数（成功出庫回数は車両数で固定）: 作業量・複雑さであり、それ自体を段の根拠にしない。
- solver の探索量（到達状態数・合法順序数）: 単調削除の状態空間の大きさで、人間の判断量と対応する理由がない。
- 出口までの距離そのもの: 追視の量だが、盤面が広いほど長くなる（5.2）。

### 3.5 分析が表現できる解法過程の範囲

分析は遮断関係のグラフ（誰が誰の進路を塞ぐか）と、単調削除の全到達状態（最大14台で 2^14 状態）を扱う。表現できるのは「遮断関係を逆向きにたどる読み」と「合法車の少なさ」までで、**視覚探索そのもの（見落とし・視線移動・密集の見た目）は直接は測っていない**。`nearMissVehicleCount` と遠い遮断は、見誤りを誘う盤面の性質を近似するだけである。

## 4. 分析スクリプト（工程3〜4）

- `frontend/scripts/parking-jam-difficulty-features.ts`: 本番の盤面・ルール・生成・難易度分析の関数を使い、3.3 の特徴を求める。本番ルールの初期合法車と独自幾何の一致を問題ごとに確認する。盤面のテキスト図も出力する。
- `frontend/scripts/parking-jam-difficulty-plans.ts`: 7章の分類案。
- `frontend/scripts/analyze-parking-jam-difficulty.ts`: `corpus`（固定 seed で問題集合を生成）、`report`（分布・相関・案の比較）、`supply`（供給計測）、`pick`（代表・境界・異常と遊び比べリスト）、`show`（identity から盤面図）、`preview`（10.3 のプレビュー配置案の確認）。`bun run --cwd frontend analyze:parking-jam-difficulty <command>` でも実行できる。

主な特徴の定義:

| 特徴 | 定義 |
| --- | --- |
| 段数 `depth` | その時点で出せる車を全部同時に出す操作を繰り返したときの回数。段数2は「最初に出せる車を出せば残りは全部出せる」 |
| 最少先行台数の最大 `maximumPrerequisiteCount` | 各車について、その車が出せるようになる到達状態のうち既に出た車が最も少ないものの台数。その全車での最大 |
| 枝分かれ | 最少先行台数の最大 −（段数 − 1）。1本の連鎖だけなら0 |
| 平均合法車率 `meanLegalRatio` | 合法車から一様ランダムに1台ずつ出すプレイで、手番ごとの「合法車数 / 残り車数」の期待値を手番数で平均した値 |
| 手がかりのない探索局面 `expectedUncuedScarceSteps` | 同じプレイで、直前の出庫で新たに出せる車ができておらず、かつ合法車が残り車の1/3以下の手番数の期待値 |

再現手順（`bun` は 1.4 系）:

```sh
cd frontend
for i in 0 1 2 3; do bun scripts/analyze-parking-jam-difficulty.ts corpus --out /tmp/pj5/current-$i.jsonl --seeds 80 --shard $i --shards 4 & done; wait
for i in 0 1 2 3; do bun scripts/analyze-parking-jam-difficulty.ts corpus --out /tmp/pj5/extended-$i.jsonl --space extended --seeds 80 --shard $i --shards 4 & done; wait
bun scripts/analyze-parking-jam-difficulty.ts report --in /tmp/pj5/current-0.jsonl,/tmp/pj5/current-1.jsonl,/tmp/pj5/current-2.jsonl,/tmp/pj5/current-3.jsonl
bun scripts/analyze-parking-jam-difficulty.ts supply --plan D+ --seeds 40
bun scripts/analyze-parking-jam-difficulty.ts pick --in <上と同じ4ファイル> --plan D+
```

corpus は seed `pj5-<space>-<番号>`、各条件最大2生成試行（現行供給と同じ）で生成する。特徴は seed から決定的に再現する（時間だけは環境依存）。

### 5.3 特徴同士の重複（実測）

順位相関 |ρ| ≥ 0.8 の組から、特徴は大きく2群に分かれた。

- **依存の深さ群**: 段数、3段目以降の車数（0.96）、最少先行台数の最大（0.85）、必須先行関係数（0.81）、最大後続数（0.86）、一本道の最大長（0.90）、平均合法車率（−0.84）、手がかりのない探索局面（0.84）、最小合法車率（−0.88）。
- **遮断の広さ群**: 初期遮断車数、探索コスト（0.89）、平均合法車率（−0.87）、連鎖解放率（0.87）。
- 平均合法車率と探索コストは同じ量（−1.00）、解順自由度も平均合法車率とほぼ同じ（0.97）。
- 初期平均最小遮断台数と2台以上に塞がれた車（0.93）は同じ量。
- **車線の読み違い・方向判断・遠い遮断は依存群と独立**（段数との ρ は 0.05 / −0.29 / 0.22）。

合法車率・探索系の特徴は依存の深さと遮断の広さの帰結として動くので、段を作る主軸には人の言葉で説明しやすい段数と重なりを使い、合法車率は検証用の指標として見る方針にした（7章）。車線の読み違いは別の挑戦軸の可能性があるが、段の条件には入れず9章の異常問題で確かめる。

### 5.4 拡張候補空間の結果（実測）

深い問題を増やす狙いで16台・開口2の条件を試したが、段数5以上は1,560問中10問（0.6%）で、現行候補空間（154 / 7,948 = 1.9%）より少なかった。16台・開口4は成功率6〜7%だった。予備試行では開口2で14〜16台がほぼ生成できなかったため、最終の拡張空間から外した。開口2・5台は98%生成でき段数4まで出るが、段数5以上は出なかった。**候補条件を広げるだけでは最上位帯の供給は増えない**。

## 6. 評価可能範囲と提供範囲（工程6、案）

- **評価可能範囲**: 現行の生成器・車両数（最大16台の厳密解析上限以下）で生成される問題はすべて特徴を計算できる。評価不能は現行候補空間では発生しない。16台を超える問題は評価不能として扱う案とする（現行の `unsupported` と同じ境界）。
- **提供範囲の下限（軽すぎ）案**: 段数1（全車がすぐ出せる）、または初期遮断車数が1以下（待つ車が1台だけ）。出す順序を読む挑戦がほぼなく、車線と方向を読んで出すだけの作業になる。現行候補空間の生成成功問題の15.1%（1,199問）が該当し、その93%は v1 easy だった。
- **提供範囲の上限（重すぎ）案**: 段数7以上を仮に範囲外にする。生成成功問題の0.1%（8問）しかなく、代表を人が確かめていないため。段数10・合法車率0.29の問題（遊び比べ P21）のように、ほぼ1台ずつしか出せない一本道が続く。面白さが保たれるかは未確認で、**上限の根拠はまだ弱い**。
- 範囲外の問題は通常供給から除き、難易度1や5へ押し込まない。

## 7. 5段階分類案（工程7）

### 7.1 比較した案

### 7.2 比較結果（現行候補空間、実測）

収率は候補1つ（生成失敗を含む17,280）あたりの割合。規模との関連は、提供範囲内でレベルと車両数・盤面サイズの Cramér's V。「4レベル以上」は、生成成功20問以上の119条件のうち、同じ生成条件から4つ以上のレベルが出た条件の割合。

| --- | --- | ---: | ---: | ---: | ---: |
| D | 6.9 / 15.2 / 4.2 / 15.0 / 3.7 / 0.8 / 0.0% | 0.13 / 0.11 | 0.17 | 0.14 | 87.4% |
| **D+** | 6.9 / 15.2 / 4.2 / 12.9 / 4.7 / 2.1 / 0.0% | 0.14 / 0.11 | 0.18 | 0.14 | 96.6% |
| D+g | 6.9 / 15.2 / 4.7 / 12.4 / 4.7 / 2.1 / 0.0% | 0.14 / 0.11 | 0.18 | 0.14 | 96.6% |
| B | 6.9 / 15.2 / 12.5 / 6.0 / 4.3 / 1.0 / 0.0% | 0.16 / 0.09 | 0.20 | 0.12 | 98.3% |
| S | 6.9 / 3.5 / 16.3 / 13.1 / 5.7 / 0.4 / 0.0% | 0.14 / 0.11 | 0.09 | 0.14 | 88.2% |
| V | 6.9 / 9.3 / 10.2 / 9.3 / 7.2 / 3.0 / 0.0% | **0.27 / 0.28** | **0.37** | **0.39** | 89.9% |

実測から言えること:

- **V（v1 の等分）はレベルが盤面規模で分かれる**。レベル5の82%が8×8、6×6は0.6%だった。現行 v1 を5等分する延長は採らない。
- D / D+ / B / S は規模との関連が小さい（V 0.09〜0.16）。D+ のレベル5でも6×6が11%、8台が40%ある。
- **D はレベル5の収率が0.8%と薄い**。D+ は段数4の枝分かれを5へ上げることで2.1%に増える。
- B は先行台数だけで段を作るので、段数3の一本道（最少先行2）がレベル2に入り、段数2の重なりと区別されない。レベル5で14台が30%と、車両数に寄りやすい。
- S は合法車率の連続値の閾値だけで段を作るので、レベルの意味を人の言葉で説明しにくい（「平均で何割出せるか」はプレイヤーが盤面から読める量ではない）。D の段と S の段は隣接レベルで大きく重なる（7.4）。

### 8.1 現行供給と同じ方式での計測（実測）

レベルごとに候補条件を寄せる方式（`--space targeted`、レベル4〜5は遮断バイアス1・開口4・11台以下・6×8以上の16条件）も試した。D+ のレベル5は31/40（p95 835ms）で、候補条件が少ないため予算内の候補数が減り成功率は上がらず、採用問題の84%が8×8に偏った。**レベルで候補条件を絞る方式は盤面規模の偏りを生む**ので推奨しない。

マインスイーパー・ウォーターソートは各レベル1,000問の事前生成問題集で供給している。同じ方式を D+ に当てはめた見積もり（生成余白のある15,360候補での収率と平均34.6ms/候補から計算）:

| レベル | 候補1つあたりの収率 | 1問あたりの候補数 | 1,000問の生成時間（単一コア） |
| ---: | ---: | ---: | ---: |
| 1 | 17.1% | 5.9 | 約3分 |
| 2 | 4.8% | 21.0 | 約12分 |
| 3 | 14.5% | 6.9 | 約4分 |
| 4 | 5.3% | 18.9 | 約11分 |
| 5 | 2.3% | 43.3 | 約25分 |

- 合計で単一コア約1時間、4並列なら15分前後で各レベル1,000問を作れる見込み（推測。重複除去・検証の時間は含まない）。
- corpus の D+ 各レベルの問題は盤面がすべて異なり（レベル5の357問も357通り、109条件にまたがる）、1,000問規模の多様性は確保できる見込み。
- 問題集の1件は「候補条件の番号・seed 番号・生成試行」の3整数で表せ、本番の `restoreParkingJamProblem` で2試行以内の再生成（数十ms）で復元できる。
- 候補空間全体から採るので、レベル5でも6×6・8台が含まれる（オンデマンドの候補寄せより規模の偏りが小さい）。

**供給方式の案**: レベル1〜5すべてを事前生成問題集で供給する（マインスイーパー・ウォーターソートと揃える）。オンデマンド生成は、レベル5の失敗と時間の裾が解消できないため採らない。問題集の生成器は、同じ判定を通したかを `verify` で再確認できるようにする（マインスイーパーの `generate:minesweeper-pool -- --verify` と同じ）。

### 8.3 生成側の制約

段数5以上は候補空間全体でも生成成功問題の1.9%しかなく、拡張条件でも増えなかった（5.4）。レベル5を1,000問より多く、または深い段だけで作る場合は、依存の連鎖を意図して組み立てる生成（例: 既存の連鎖の末端を塞ぐ位置を優先する）を検討する必要がある。ただし5段階の成立のために候補条件を大盤面・多車両へ広げることはしない。

### 9.3 遊ぶ手段

**現状、特定の問題を製品の画面で開く手段はない**。プレイ画面は難易度から seed を新しく作って供給するだけで、identity を指定する入口がない（`frontend/src/views/ParkingJamPlayView.tsx`、`use-parking-jam-play.ts`）。

このフェーズでは実装していない。最小の手段の案:

1. **開発用の identity 指定（推奨）**: 内部診断が有効なビルド（`internalDiagnosticsAvailable`）に限り、プレイ画面の URL クエリ（例: `?problem=<identity の JSON を base64url>`）を `restoreParkingJamProblem` で復元して遊べるようにする。難易度表示・記録はその間は保存しないか、診断用として区別する。数十行の変更で済む見込み（推測）。
2. 盤面図で遊ぶ: [遊び比べ問題](パーキングジャム難易度5段階_遊び比べ.md) の図を紙や画面上で追う。時間・不成立操作の計測が曖昧になり、実操作の見誤り（車線・方向）が再現できない。
3. `show` コマンドで identity から盤面図と特徴を出す（答えが見えるので遊び比べには使わない）。

## 10. 現行3段階・記録・プレビュー・採点への影響（案）

### 10.1 現行3段階との対応

7.4 の通り、v1 easy / normal / hard と D+ のレベルは単調に対応しない。v1 easy の28%は下限未満、v1 hard にもレベル1がある。**旧ラベルと新レベルの一対一の読み替えは作らない**案とする。

### 10.2 旧3段階記録の扱い

記録（payloadVersion 3）は難易度・判定モデル版・採点版・問題識別情報を保存している。

- **案A（推奨）**: ウォーターソートの5段階移行と同じく、旧 `easy / normal / hard` を旧難易度として読み込み、旧ラベルのまま別の比較単位で表示する。新レベルの自己ベストと混ぜない。評価点は記録の採点版で再計算する（現行の仕組みのまま）。
- 案B: 記録の identity から問題を復元し、新判定でレベルへ編入する。生成器 version 2 のままなら復元できる。ただし下限未満になる記録（v1 easy の約3割）は編入先がなく結局旧区分が残ること、選んだ時の表示ラベルと異なるレベルに移ること、判定モデルを変えるたびに記録の所属が動くことから推奨しない。

### 10.3 難易度選択プレビューの5段階化

現行方針（本番部品による手設計の簡略図、上位が下位を含む、判定要因だけで差を付ける、全レベルで同じ盤面）を保つ。判定要因が「段数・重なり・枝分かれ」に変わるので、それが見える配置にする。

現行の3行7列・開口2か所の駐車場では、レベル1の配置に車を足していく形で D+ の5段階を作る配置を、乱択探索で見つけられなかった（作れないことの証明ではない）。4行7列・開口3か所（右の上2行、上の中央2列、左の下2行）なら、次の入れ子配置で D+ のレベル1〜5になることを本番の盤面検証・可解性解析・調査用特徴で確かめた（`preview` コマンド。形式は現行 `previewVehicleLayouts` と同じで、同じ英小文字のマスが1台）。

| レベル | 配置（上の行から） | 台数 | 段数 | 最少先行台数の最大 | 初期遮断車数 | 何が増えたか |
| ---: | --- | ---: | ---: | ---: | ---: | --- |
| 1 | `.......` `aac....` `..c..bb` `.......` | 3 | 2 | 1 | 2 | 縦の c が a と b の出口を塞ぐ。c はすぐ出せる |
| 2 | `.......` `aac.dd.` `..c..bb` `.......` | 4 | 2 | 2 | 2 | a の進路に d が加わり、a は c と d の2台を待つ |
| 3 | `.ee....` `aac.dd.` `..c..bb` `.......` | 5 | 3 | 3 | 3 | e が c の出口を塞ぎ、a・b は2段待つ |
| 4 | `.ee....` `aacfdd.` `..cf.bb` `...f...` | 6 | 3 | 4 | 3 | 縦の f が a の進路に加わり、待ちが枝分かれする |
| 5 | `.ee..gg` `aacfdd.` `..cf.bb` `...f...` | 7 | 4 | 5 | 4 | g が e の出口を塞ぎ、a は3段待つ |

- 盤面サイズを3×7から4×7へ変えるのは全レベル共通の変更で、判定要因ではない。
- レベル4・5は枝分かれ規則に依存する。案D で判定するとレベル4・5の配置はそれぞれ3・4になる。案D を採る場合はレベル4に段数4、レベル5に段数5が必要で、この大きさでは作れていない。
- 既存テストの「3要因が減らず少なくとも1つ増える」は、新しい判定要因（段数・最少先行台数・初期遮断車数）で同じ性質を確かめる形に置き換える。

### 10.4 採点 `play-quality-v2` への影響

基準時間 `T = 5秒 + 車両数×3秒 + 初期遮断車数×3秒` は難易度ラベルではなく問題特徴から求めるので、5段階へ移っても計算は変わらない。D+ の各レベルでの `T` は中央値 38 / 38 / 41 / 47 / 50秒（最小35〜38秒、最大65〜77秒、実測）。

- 懸念（推測）: `T` は段数を含まないため、レベル4〜5で「さかのぼって読む」時間が基準時間に入らず、速さの点が系統的に低くなる可能性がある。
- 案: 5段階の最初の提供では `play-quality-v2` を変えず、遊び比べ・実プレイで「経過時間 / T」がレベルとともに上がるかを見る。上がるなら、段数（または最少先行台数）1段あたりの秒数を足した新しい採点版にする。採点版を分けて記録しているので、旧記録の再計算は保たれる。

## 11. ユーザーに判断してほしい論点

1. **挑戦の主軸**: 「依存を何段さかのぼるか」（D 系）を主軸にしてよいか。広さ（塞がれた車の多さ・出せる車の少なさ）を主軸にする案（S）と比べて、遊び比べでどちらが体感に合うか。
2. **D と D+**: 枝分かれ（2段の待ちが2本重なる等）を1段上とみなすか。D+ はレベル5の供給が約2.6倍になるが、意味が「段数」だけより複雑になる。
3. **孤立した連鎖**: 大半がすぐ出せる盤面の深い連鎖を、段数どおりに高く扱うか（D+g で2へ留めるか、別の特徴にするか）。
4. **下限**: 待つ車が1台以下の問題を提供範囲外にしてよいか。レベル1を「1台に塞がれた車が2台以上」から始めてよいか。
5. **上限**: 段数7以上を仮に範囲外とするか。そもそも上限を設けるか。
6. **レベル1と2の差**: 重なりの有無だけで1段分の差になるか。
7. **供給方式**: 全レベルを事前生成問題集（各1,000問）で供給してよいか。
8. **旧記録**: 旧3段階を別の比較単位として残す案A でよいか。
9. **プレビュー**: 駐車場を4×7・開口3か所に変えてよいか。
10. **遊ぶ手段**: 9.3 の開発用 identity 指定を先に実装して遊び比べるか。

## 12. 限界と残るリスク

- 人間の実プレイによる確認はまだない。段数・重なりが人の難しさと対応するかは仮説である。
- 視覚探索（見落とし・密集の見た目・開口の見誤り）は直接測っていない。車線の読み違いが強く効くなら、段数だけのモデルでは説明できない。
- 平均合法車率などは「一様ランダムに合法車を出す」プレイの期待値で、人の選び方（開口の近くから見る、空いた車線の奥を見る等）とは異なる。
- 孤立した連鎖のように、段数は深いが盤面の大半がすぐ空く問題は段数を過大に見る可能性がある（9.2 #2）。
- レベル5は候補空間全体でも2.3%（候補あたり）しか現れない。事前生成なら量は足りる見込みだが、レベル5の中身は段数5と「段数4＋枝分かれ」が混ざり、同質かは未確認。
- レベル3以上で8×8の割合が増える。規模を条件に使っていなくても、深い依存は広い盤面で作られやすい。
- 供給時間は開発コンテナでの実測で、調査用特徴（全到達状態の列挙）を含む。製品に入れる分類は段数・最少先行台数だけで足り、到達状態の列挙は本番分析にもあるため大きく変わらない見込み（推測）。
- 分析は最大14台（候補空間）で確認した。本番の厳密解析上限16台までは同じ計算で扱える。
