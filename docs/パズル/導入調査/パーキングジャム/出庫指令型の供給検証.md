# 出庫指令型：難易度と問題供給の検証（#738）

#727 の子 Issue #738 の検証資料。出庫指令型で、選択に正誤がある問題を Lv1〜Lv5 に分けて継続供給できるかを調べた。4方式の比較は[ゲーム性再設計.md](ゲーム性再設計.md)にある。出庫指令型の難易度の基準・供給・問題例は、この資料が最新である。正式なルール・難易度・問題集・記録は変更していない。

## 結論

- 出庫指令型には、選択に正誤があり、誤りの帰結が数指令後に出る判断を作れる。機械的な基準で Lv1〜Lv5 を置き、手筋から逆算する生成と探索による生成で、全レベルの問題を作れた。
- 可解な出庫順から指令を作る従来の生成は、Lv4・Lv5 を1問も出せなかった。退けた問題の 99.3% は、待機が1台以下で解けてしまう。
- 判断のほぼすべては、同色2台のどちらを先に使うかである。採用した問題の判断局面のうち、この型は Lv2 で 98.7%、Lv3 で 99.9%、Lv4 で 95%、Lv5 で 90% を占めた（数え方は「レベルの基準」に書く）。
- 機械的な基準は、難易度開発手順が求める条件をまだ満たしていない。Lv2 と Lv3 は台数でしか分かれず、人間の体感による校正もしていない。AI による試遊では、15問のうち2問で体感が Lv より2段以上易しく、Lv2 と Lv3 は体感で分かれなかった。
- #727 への提案は「出庫指令型を候補として残し、採用は保留」。

## ルールと用語

- 車は向きの前後どちらかへ、開いている辺まで直線上が空なら出庫する。出庫した車は待機枠に入り、指令の先頭の色と一致する待機車が出発する。出庫して連鎖が止まったときに待機車が枠数に達していると、色が合う車も出せず失敗になる。
- 検証した問題は、各色がちょうど2台で、指令の長さは台数と同じ。開く辺は、4辺・隣り合う2辺・上下の2辺・1辺の4通り。
- 残っている車の集合が同じなら、消化済みの指令数と待機数は出庫順に依らず等しい。状態を車の残存集合だけで表し、可解性・解の数を厳密に求める。

| 用語 | 意味 |
| --- | --- |
| 最小枠数 | その問題が解ける最小の枠数。解く途中の待機車の最大数 + 1 に等しい。最小枠数1は、1台も待たせずに解けることを表す |
| 余裕 | 枠数 − 最小枠数 |
| 掘る | 塞がれた車を出すために、進路上の車を先に出す |
| 埋まった車 | ほかの車を先に出さないと出庫できない車 |

計算は、待機列を順序つきで持つ別実装の全探索（`test_parking_jam_dispatch_reading.py` の `ExplicitGame`）と照合してテストにしている。経緯を知らない検証者が一から書いた実装でも、可解性・解の数・最小枠数・判断の分類に不一致は無かった（この実装はリポジトリに置いていない）。比較試作画面のルールでも、問題例15問の解の数が研究用の探索と一致する（`dispatch-levels.test.ts`）。

## 従来の選抜条件が測れていなかったこと

先行の試作（`parking_jam_selection_poc.py` の条件と、それを使う `parking_jam_dispatch_supply_probe.py`・`parking_jam_dispatch_structured.py`）は、「合法手を無作為に選ぶとクリア率が5〜50%」「遅れて詰む悪手がある」を良問の仮条件にしていた。悪手は、最初の3手以内にあり、車の遮断を無視すれば成功に変わるものに限っていた。それでも、次の指令と関係のない車を出して待機枠を埋める手が悪手に数えられる。目的のある手だけを選ぶ人が迷うかは見ていない。

- 可解な出庫順から作った指令では、最小枠数1の問題が 82%、3以上は 98/8000 だった（同色2台と全色別の問題を合わせ、同じ問題を余裕0と余裕1で数えた件数）。待機枠を使わずに解ける問題が大半になる。
- 開口が隣り合う2辺か1辺で全車の色が違う問題では、次の指令を満たす出し方が常に1通りで、選択が無い。選択は、同色2台の使い分けか、2方向に出られる車の掘る側からしか生じない。

## 難しさの物差し

最初は「何指令先まで読めば、どう選んでも必ず解けるか」を物差しにした。独立検証で次の弱点が分かり、レベルの基準から外した。

- 同色の車がすぐ出せるのに埋まった方を掘る計画まで、負け筋に数える。値が高くても「先頭色の車が出せるなら出す」だけで100%解ける問題があった。
- 指令の区切り位置で値が変わる。読む指令数を増やすと負ける例があった。
- 値が高い問題の多くは最小枠数1の問題で、同色2台の1択に縮んでいた。

代わりに、1指令ずつ進む読み手を置く。読み手は、次の指令を満たす出庫の集合（余計な車を含まないもの）から1つを選ぶ。そのうち次の2つを除いたものを「自然な計画」と呼ぶ。

- 同じ車を、より少ない出庫で出せる計画がある。
- 同色のもう1台がすぐ出せるのに、埋まった方を掘る。

読み手が勝つ計画を選び続けたときに通る局面で、次を数える。勝つ自然な計画が無い局面では、自然でない勝つ計画で先へ進み、その局面も判断局面に数える。

| 特徴 | 数え方 |
| --- | --- |
| 判断局面 | 自然な計画の中に、選ぶと解けなくなるものがある局面の数 |
| 距離 | 負ける計画を選んでから、次の指令を満たせなくなるまでに消化される指令の数 |
| 理由 A | 負ける計画が残した車が、後で出す車の出口を塞ぐ |
| 理由 B | 負ける計画が余計に待機させた車で、待機枠が溢れる |

- 素朴な解き方は2つ置く。「先頭色優先」は先頭色の車が出せるなら出し、「遮断最少」は遮断の少ない方を掘る。どちらも、選べる手の中から等確率で選んだときにクリアする確率を勝率とする。100%勝てる問題は、上位レベルから外す。勝率の値は基準に使わない。素朴な解き方で負けることは、難しさの根拠にしない。
- 「すぐ出せる、先の指令の色の車を先に出すと負ける」局面（誘い）は、余裕0の無作為な問題の 87〜94% にあり、レベルを分けない。基準に使わず記録だけする。判断局面が0の Lv1 でも、誘いに乗れば負ける問題がある。

## レベルの基準

満たす中で最も高いレベルをその問題のレベルとする。全レベルで枠数は2〜4。盤は Lv1・Lv2 が 6×6 か 7×7、Lv3 が 7×7、Lv4・Lv5 が 7×7 か 8×8。

| Lv | 台数 | 枠と余裕 | 判断局面 | 距離の最大 | 理由 | 外す条件 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 8 | 余裕1以上 | 0 | — | — | — |
| 2 | 8 | 余裕0〜1 | 1 | 2以下 | A を含む | — |
| 3 | 10 | 余裕0 | 1〜2 | 2以上 | B を含まない | 先頭色優先で100%勝てる |
| 4 | 10〜12 | 3〜4枠、余裕0 | 2以上 | 3以上 | B を含む | 先頭色優先か遮断最少で100%勝てる |
| 5 | 12 | 3〜4枠、余裕0 | 3以上 | 3以上 | A と B の両方 | Lv4 と同じ |

この基準は、[ゲーム性再設計.md](ゲーム性再設計.md)の仮のレベル表を置き換える。仮の表の Lv1「単純な遮断を1つ解く」は、判断局面0の問題に当たる。ひとつ前の版（`LEVEL_TABLES["v2"]`）の分布を見て、次の点を直した。

- 枠数に上限が無いと、8枠の Lv1 が入る。
- Lv3 と Lv4 は、理由 B の有無で分ける。理由 B を含む問題は、余裕0の無作為な問題のうち8台で約2%、12台で約7%と少ない。
- Lv2 を余裕1に限ると供給が細る。8台の無作為な問題で判断局面がある割合は、余裕1で 1.7%、余裕0で 20.2%。余裕0も許した。これは供給に合わせて基準を広げた直しである。

採用した問題での分かれ方（乱数種2つ・生成器3つを合わせた件数。件数の多くは G2 による）:

- Lv1 と Lv2 は判断局面の有無で、Lv3 と Lv4 は理由 B の有無で分かれる。これは基準の定義による。
- Lv2 と Lv3 は台数でしか分かれていない。Lv3 の 22% は判断局面1・距離2で、Lv2 と同じ形をしている。
- Lv4 と Lv5 は、単独の特徴では分かれない。Lv4 の多くは判断局面2で、判断局面3以上の Lv4 は理由 A を欠くか10台である。
- 埋まった同色車を掘る計画も選択肢に残す数え方に変えると、Lv2 の 28%、Lv3 の 26%、Lv4 の 14% はレベルが変わる。Lv5 は全件が同じレベルに残る。
- 勝つ自然な計画が無い判断局面を持つ問題が、Lv2 の 12%、Lv3 の 13%、Lv4 の 59%、Lv5 の 64% にある。この局面 2364 件を調べると、1件を除いて、すぐ出せる同色車が負けで、埋まった方を掘ると勝つ局面だった。
- 判断局面を種類で分けると、負ける計画が勝つ計画と違う同色車を使うものが Lv2 86.5%、Lv3 89.1%、Lv4 65%、Lv5 63%。上の「勝つ自然な計画が無い局面」も同色2台の使い分けなので、合わせると 98.7%、99.9%、95%、90% になる。残りは、同じ車を別の側から掘る選択である。
- 先頭色優先の勝率の中央値は、Lv1 から順に 1.0、0.21、0.083、0.057、0.0057 と下がる。遮断最少は 1.0、0.5、0.5、0.25、0.0 で、Lv2 と Lv3 が同じ。

### 難易度開発手順に照らして足りないこと

[難易度開発手順.md](../../難易度開発手順.md)は、問題規模を増やして段階を埋めることを認めず、規模だけで難易度がほぼ決まっていないかの確認を求める。この基準は次の点で、その条件を満たしていない。

- Lv2 と Lv3 の違いが台数だけである。Lv3 を「判断局面2、または判断局面1で距離3以上」に狭める案はあるが、これは閾値の調整で、解き方の違いを作るものではない。
- 判断の型がほぼ1種類なので、Lv3〜Lv5 の違いは、同じ型の判断の数・距離・待機枠の圧迫の有無である。解き方が段階ごとに変わるわけではない。
- Lv2 に余裕0を許したのは、供給に合わせて基準を広げた直しで、手順が最初の対処にしないとする閾値の調整に当たる。
- 同じ台数で隣のレベルの問題を対にして、順序と逆転を確かめていない。
- 基準は満たすが体感が外れる問題（異常な問題）を、問題例として集めていない。
- 人間のプレイによる校正をしていない。

## 生成器の比較

3つの生成器が同じレベル判定で問題を採用する。

| 生成器 | 作り方 |
| --- | --- |
| G1 | 車を1台ずつ出庫順の逆に置いた盤面と、可解な出庫順から作る指令（従来の方式） |
| G2 | 手筋の台本から、車・色・指令を置く。台本は、遮断車を待機させて掘る、その2段重ね、同色2台の使い分け、すぐ出せる同色車が負けになる配置、掘る側の選択 |
| G3 | 無作為な問題から、色・指令・車の配置を変えて目標レベルへ登る |

CPU 1分あたりの採用数（乱数種 738 / 20261116。生成にかかった CPU 時間だけを数える）:

| Lv | G1 | G2 | G3 |
| --- | ---: | ---: | ---: |
| 1 | 15615 / 14360 | 17222 / 16626 | 14095 / 13739 |
| 2 | 231 / 253 | 2692 / 2699 | 231 / 251 |
| 3 | 126 / 114 | 2364 / 2511 | 179 / 160 |
| 4 | 0 / 0 | 28.6 / 38.2 | 21.0 / 16.0 |
| 5 | 0 / 0 | 17.6 / 22.1 | 14.0 / 11.0 |

- G1 は Lv4・Lv5 を出せない。退けた問題の 99.3% は最小枠数が2以下だった。
- G2 は1試行が 1〜3ms。Lv4・Lv5 では車の配置に約 86% 失敗するが、供給は G3 以上になる。同じ台本から似た問題が出やすい。
- G3 は4辺・隣り合う2辺・1辺のどの開口でも Lv2〜Lv5 を出せる。Lv4・Lv5 の1試行は平均 0.9〜1.6秒で、95%の試行が 3.1〜3.5秒以内に終わる。
- 上下の2辺だけが開く盤面は、縦の車しか置けず遮断がほとんど無い。Lv4・Lv5 は出なかった。
- G2 の Lv4・Lv5 は隣り合う2辺と1辺の開口に偏る。G3 は4辺の開口でも出す。
- 「掘る順で待機を節約する」は独立の手筋にならない。1つの指令を満たすまでの出庫では指令が消化されず、待機数が順序に依らないため。

重複（乱数種2つ・生成器3つを合わせた採用問題）:

- 盤の対称と色の付け替えで同じになる問題は、どのレベルにも無かった。
- 車の位置を捨てて遮断関係と色と指令だけで比べると、異なる問題の数は Lv1 71127/101909、Lv2 6598/9094、Lv3 7474/7553、Lv4 130/153、Lv5 95/96。

問題集に要る数は決めていない。仮に各レベル1000問とすると、G2 と G3 の採用数を足すと、Lv4 は CPU 約20分、Lv5 は約30分で届く計算になるが、遮断関係で見て異なる問題がその数だけ出るかは確かめていない。

## 問題例と試遊

各レベルの代表2問と境界1問を、比較試作画面（`/puzzles/parking-jam/lab` の「色別出庫指令＋待機枠」）に載せた。盤面・指令・特徴・最初の判断局面の勝ち筋と負け筋は `scripts/research/parking_jam_dispatch_levels.examples.json` にある。境界は、数え方を変えるとレベルが変わる問題か、そのレベルの条件をぎりぎり満たす問題。Lv2〜Lv5 の代表は、負ける理由を手で追って言葉にできたものを選んだ。Lv1 の代表と各境界は機械の判定だけで選んだ。

答えを知らない AI のプレイヤー1人が、解答表示も探索プログラムも使わずに15問を解いた（記録はリポジトリに置いていない）。体感は1〜5の主観。

| 問題 | 体感 | 詰んだ回数 | 所見 |
| --- | --- | ---: | --- |
| Lv1 代表1・代表2・境界 | 1 | 0 | 指令に沿って押すだけ |
| Lv2 代表1 | 2〜3 | 0 | 同色2台の罠がはっきりある |
| Lv2 代表2 | 1.5 | 0 | 縦に積んだ車を上から預ける整理だけ |
| Lv2 境界 | 1〜1.5 | 0 | 待機枠を使わない |
| Lv3 代表1 | 2 | 0 | 預ける車は決まる。同色の選び方で迷わなかった |
| Lv3 代表2 | 1.5〜2 | 0 | Lv2 代表2 と同程度 |
| Lv3 境界 | 2.5 | 0 | すぐ出せる同色車が負け |
| Lv4 代表1 | 2 | 0 | 待機枠に追い詰められる場面が無かった |
| Lv4 代表2 | 3.5 | 0 | すぐ出せる同色車を後に残す。2本の負け筋を読んで捨てた |
| Lv4 境界 | 3.5 | 0 | Lv4 代表2 と同じ型 |
| Lv5 代表1 | 4 | 0 | 2つ目の指令の選択が原因で、出庫7回の後に詰む筋がある |
| Lv5 代表2 | 2 | 1 | 4辺が開き、預けた車がすぐ出発する手が見つかりやすい。詰みは遮断の見落とし |
| Lv5 境界 | 4 | 0 | 最も考えた。3〜4本の筋を読んで捨てた |

- 体感が Lv より2段以上易しかったのは、Lv4 代表1 と Lv5 代表2 の2問。
- Lv2 と Lv3 は体感で分かれなかった。Lv2 代表1 は Lv3 の代表2問より難しく、Lv3 代表2 は Lv2 代表2 と同程度だった。
- 難しかった問題はどれも同色2台の使い分けで、型が分かると後の問題は早く読めた。
- 正しい方針が決まった後の終盤5手前後は、どの問題も手がほぼ自動で決まる。
- 原因が何手も前にある詰みは、戻す範囲の手がかりが無いと理不尽に感じうる。
- 390px 幅では、盤面・指令・待機枠・詰みの表示が一度に見えない。8×8 の盤では縦の車の幅が約 32px で、隣の車を押し間違えやすい。

AI は盤面全体を正確に読んでから打つので、詰みと戻しは人より少なく出る。人が色と位置を目で追うときの見落としやすさ、戻す手間の重さ、解けたときの手応えは、この試遊からは言えない。

## #727 への提案

出庫指令型を候補として残し、採用は保留する。

- 残す理由: 選択に正誤がある問題を作れる。従来の生成で出なかった、待機が2台以上要る Lv4・Lv5 の問題も、手筋からの逆算と探索で作れる。継続して供給できるかは、要る数を決めて測るまで分からない。
- 保留する理由:
  - 判断の型がほぼ1種類で、段階ごとに解き方が変わらない。型を覚えた後に Lv3〜Lv5 の差が残るかは分からない。
  - Lv2 と Lv3 が台数でしか分かれず、難易度開発手順の条件を満たさない。
  - 試遊で、体感が Lv より2段以上易しい問題が15問中2問あり、Lv2 と Lv3 は体感で分かれなかった。
  - スマホ幅で 8×8・12台の盤面と指令・待機枠を1画面に収める配置が無い。
- 採用を判断する前に要ること:
  - 人間のプレイ記録で、Lv の順と体感が合うかを確かめる。
  - 同色2台の使い分け以外の判断（掘る側の選択、待機枠の圧迫だけで決まる判断）を増やすルールや盤面の作りを試す。
  - 4辺が開く盤面で上位レベルの体感が下がるかを確かめる（試遊で易しく感じたのは Lv5 代表2 の1問で、同じ4辺の Lv5 境界は難しかった）。
  - 問題集に要る数を決め、遮断関係で見て異なる問題がその数だけ出るかを測る。
