# 送迎パーキング難易度

送迎パーキング（ゲーム ID `shuttle-parking`）の `レベル 1`〜`レベル 5` を、[難易度開発手順.md](../../難易度開発手順.md) の工程に沿って組み立てた検討記録。

この文書は正本ではない。採用した決まりとその意図はパズル仕様（PZL-015。まだ無い）に、特徴の計算・境目・分類条件はゲームのコード（`frontend/src/games/shuttle-parking/difficulty.ts` と `problem/`）に置く。ここには、比べた案、測った量、決めた理由、採らなかった案を残す。§2 の定義はコードと同じ意味で書き、値はコードを正とする。

根拠は次の見出し語で分ける。

- **計測**: ゲームのコードで測った値。出どころは主に問題集の生成スクリプトの統計（`bun run --cwd frontend generate:shuttle-parking-pool -- --stats --cache <キャッシュ>`）と `--verify`。一度だけ測った値は一時スクリプトと書く。調査の段階の値は [調査コード/shuttle-parking_difficulty.py](調査コード/shuttle-parking_difficulty.py) で測り、そう書く。
- **導出**: 定義から論理的に言えること。
- **推測**: 計測で確かめていない判断。

**人はまだ遊んでいない。** AI の試遊もしていない。各レベルの体験差は、読み手のモデルと素朴な解き方の模擬で測った仮説である。

**5段階について（最も大事な結論）**: 今の物差しで安定して分けられるのは4段階である。5段階は人間の判断で、4段階目を「8〜9人先」と「10人以上先」に分けて作った。

- Lv4 と Lv5 の間は、試し出しで戻す回数でわずかにしか並ばない（上のレベルが多く戻す確率 0.58。§8）。
- Lv4 は罠の重さが 8 か 9 の2値しかない。境目を片側へ1人動かすと Lv4 の 39〜61% が隣のレベルへ動き、両側のどちらへ動かしても Lv4 に残る問題は無い（§5）。
- 最終レビューで人間が遊んで確かめる。4段階にする別案は §13.4。

## 2. 挑戦・基準とするプレイ条件・定義

**挑戦の1文**: 乗客の列を先まで読み、いま出す車が何人先で待機枠をふさぐか（座席が余る・必要な車が出られなくなる）を見抜いて、出す車とその順番を決める。

挑戦に入れないもの: 列の長さ・台数・手数（作業量）、塞ぐ車を掘る台数、戻して試し直す量。押し切りの扱いは採点で決める。

基準とするプレイ条件: 列も盤面も全部見えていて、負けの知らせは無い。戻しは使わずに先を読んで解く人を基準にする（合意の「称えたい解き方の仮説」）。

分析は全部の状態をたどる（8台では1候補の生成と分析が p95 8.6 ms で終わる）。探索の打ち切りは無い。

### 2.1 ルールと状態

コードは `problem/generation/state-game.ts`。

- 状態は（残っている車の集合、色ごとに待機している車の定員を到着順に並べたもの）。乗った人数は残りの車の集合から決まる。2つの状態はこの組が同じときに同じとみなす。
- 出せる車: 待機している車の数が待機枠より少なく、出口の辺へ向かう進路（車の向きに沿った2方向のうち、出口の辺へ向かうもの）の上に残っている車が無い車。
- 列の先頭: 出た車の座席を色ごとに数え、列の前から順に、その色の空き座席がある限り乗せて進めた位置。
- 勝ち局面: 出せる車を選び続けて、全部の車を出せる局面。
- 解ける最小の待機枠: 待機枠を見ずに出していくどこかの順で、待つ車の数の最大を最も小さくした値 + 1。生成はこの数の待機枠だけを出し、2〜4 に無ければ捨てる。

### 2.2 先頭に合わせる人の候補

局面ごとに、次の段を順に試し、勝つ手を1つでも含む最初の段を候補にする（`problem/generation/readers.ts` の `widenedCandidates`。段は `headFirst → run1 → run2 → run3 → all`）。

1. 出せる車のうち、列の先頭の色の車。1台も無ければ 2 から始める。
2. 先頭の色の車（出せなくてもよい）と、その閉包（進路を塞ぐ車、それを塞ぐ車…）のうち、出せる車。
3. 列の先頭から数えて2つ目の色の区間までに出てくる色の車と、その閉包のうち、出せる車。
4. 3つ目の色の区間まで、同じように。
5. 出せる車すべて。

補足:
- 色の区間は、同じ色が続く並びを1つと数える。
- 「進路を塞ぐ車」は、出口の辺へ向かう進路の上にいる、残っている車（進路が2本あれば両方の上の車）。
- どの段にも、待機枠がすぐ埋まる手は含まれる（すぐ詰む手も罠として数える）。

### 2.3 先回りする人の候補

先頭から5人に出てくる色の車と、その閉包のうち、出せる車を候補にする。その中に勝つ手が無ければ、出せる車すべて（`candidates` の `window`。窓は5人に固定し、局面ごとに選び直さない）。

### 2.4 罠・深さ・重さ

- **罠**: 候補のうち、その手の後どう続けても勝てない手。
- **罠の深さ**: 2つの取り方がある。どちらも、罠の手を打つ前の局面の先頭から数えた人数で、罠の手そのもので乗る人も含む（`ShuttleParkingReader.distance`）。
  - **最善の続き**（`best`）: 罠の手の後、出せる車すべて（待機枠を埋める手も含む）を使って続けたときに、到達できる先頭の位置の最大 − 打つ前の先頭の位置。
  - **気づかずに続けた場合**（`continuation`）: 罠の手の後、素朴な解き方（§2.6）の候補から一様に選んで続ける。素朴な候補が空になった所で止まる。止まった先頭の位置の期待値 − 打つ前の先頭の位置を、切り捨てた整数（`Math.trunc`）。
- **罠の重さ**: 深さ + 1（負けが見えるのに要る人数）。
- **局面の重さ**: その局面の候補のうち、罠の手の重さの最大（罠が無ければ0）。

### 2.5 勝ち筋とレベル

- **勝ち筋**: 各局面で、候補のうち勝つ手だけを選び続けて全部の車を出す筋。
- **勝ち筋の重さ**: 勝ち筋の上の局面の重さの最大。
- **重さの最小と最大**: 勝ち筋の重さの、すべての勝ち筋の中での最小（どう進めても出会う最も重い罠）と最大（`measureShuttleParkingWeightBounds`）。
- **進め方を広げた重さ**: 罠の重さは先頭に合わせる人の候補で数えたまま、進め方を「勝つ手ならどれでもよい」（候補の外の勝つ手も選べる）に広げたときの、勝ち筋の重さの最小（`freePath`）。

レベルは重さの最小の段で決める（`SHUTTLE_PARKING_WEIGHT_BY_LEVEL`）。

| レベル | 重さの最小 | 意味 |
|---|---|---|
| 1 | 0 | 先頭に合わせて出せば罠に出会わない |
| 2 | 1〜4 | 罠の結果が4人先までに出る |
| 3 | 5〜7 | 罠の結果が5〜7人先に出る |
| 4 | 8〜9 | 罠の結果が8〜9人先に出る |
| 5 | 10 以上 | 罠の結果が10人以上先に出る |

### 2.6 素朴な解き方と規則の組（上位を止める条件）

**素朴な解き方**（`listNaiveMoves`）は、次の順に候補を作る。

1. 出せる車のうち、出した直後に待機枠が埋まる手（全部出し終える手は除く）を外す。
2. 残りに先頭の色の車があれば、それが候補。
3. 無ければ、先頭の色の残っている車ごとに、進路ごとの「塞ぐ車の数」の最小を求める。
4. その値が最も小さい車を全部取り、各車の、その最小の値をとる進路を全部取る。それらの進路を塞ぐ車をすべて合わせ、その閉包に入る出せる車を候補にする。
5. その中に出せる車が無ければ、1 の後の手すべてが候補。1 の後に手が無ければ候補は空。

**規則の組**（`SHUTTLE_PARKING_NAIVE_RULES`）は、候補の作り方と、候補の中の選び方（鍵の値が最小の車。同点なら一様）の組。候補の作り方は3つある。

- 素朴: 上の候補。
- 広い: 待機枠がすぐ埋まる手を外したうえで、先頭の色の車が出せればそれ、無ければ全部の先頭の色の車の進路を塞ぐ車の閉包に入る出せる車。閉包の中に出せる車が無ければ、外した後の手すべて。
- 深く掘る: 待機枠がすぐ埋まる手を外したうえで、先頭の色の残っている車ごとに「その車を出すのに出す車」（進路ごとの閉包とその車。最も少ない進路のもの）を求め、その台数が空いている待機枠以下の車のうち、台数が最も多い車の「出すのに出す車」に入る出せる車。当たる車が無ければ素朴の候補。

| 規則 | 候補 | 鍵 |
|---|---|---|
| any | 素朴 | 0 |
| small | 素朴 | 定員 |
| big | 素朴 | −定員 |
| unblock | 素朴 | (−その車が進路の上にいる「いま出られない車」の台数, 定員) |
| needed | 素朴 | (その車が進路の上にいる「いま出られない車」の色ごとの「座席が足りなくなる位置」の最小。そういう車が無ければ無限大, 定員) |
| fill | 素朴 | その色の空き座席 + 定員 人目のその色の客の、列の中の位置（その客がいなければ無限大） |
| wideNeeded | 広い | needed と同じ |
| wideFill | 広い | fill と同じ |
| deepDig | 深く掘る | 0 |

鍵で使う言葉:
- **いま出られない車**: 残っている車のうち、出口の辺へ向かう進路がどれも塞がっている車。
- **座席が足りなくなる位置**（色ごと）: 外に出ている車の空き座席に、いま出せる車（進路だけで判断し、待機枠の空きは見ない。鍵を測っている車は除く）の座席を合わせる。列の先頭から順に、その色の客1人ごとに座席を1つ使い、使える座席が無くなった最初の客の位置。

**規則の勝率**: 先読みせずにその規則で出し続ける人の勝率（候補が同点なら一様。負けの局面に入った時点で 0、候補が空なら 0）。

### 2.7 判定の順（`assessShuttleParkingDifficulty`）

1. 解ける最小の待機枠が 2〜4 に無ければ範囲外（`bayCountOutOfRange`）。待機枠が解ける最小の数でない問題は分析しない（`unsupported`。生成は出さない）。
2. 先頭に合わせる人の、深さの2つの取り方のどちらかで、重さの最小と最大の段が違えば範囲外（`pathDependent`。勝ち筋の選び方でレベルが変わる）。
3. 深さの2つの取り方で、重さの最小の段が違えば範囲外（`depthDefinitionsDisagree`）。
4. 先回りする人の重さの最小の段が違えば範囲外（`playStylesDisagree`）。ただし、レベルが1で先回りする人が2なら Lv1 とする。
5. Lv3 以上で、進め方を広げた重さの段が違えば範囲外（`freePathEscapes`。候補の外の勝つ手から進めると重い罠を避けて通れる）。
6. Lv3 以上で、規則の組のどれかの勝率が 0.8 以上なら範囲外（`naiveCeiling`）。
7. Lv2 で、規則の組がどれも勝率 0 なら範囲外（`headPoliciesAllLose`）。
8. 残りは、重さの最小の段のレベル（§2.5 の表）。

判定の決まりを変えたら判定モデル版（`SHUTTLE_PARKING_DIFFICULTY_MODEL_VERSION`、今は `1`）を上げ、問題集を作り直す。問題集は作ったときの版を持ち、今の版と同じことをテストで確かめる。

### 2.8 記録だけの回数

判断の回数（`countShuttleParkingDecisions`）は、レベルに使わない記録だけの量として残す。勝ち筋の上で、重さの段（1・5・8・10）ごとにその段以上の罠になっている車の集合を取り、直前の局面の集合と共通の車が無いときに新しい判断として1回数える（先頭の色の車のために塞ぐ車を1台ずつ出している間は、同じ車が罠のまま続くので1回）。どの勝ち筋でも出会う最小と、最も多い勝ち筋の最大を持つ。調査で決めた判定（判断の回数が段ごとに1以上か）と、§2.5 の重さの最小と最大による判定は、同じレベルを返す（導出。移植の期待値150問と全候補で一致。§6）。

## 4. 状態と分類

- `unsupported`: 待機枠が解ける最小の数でない。生成は出さない。
- `out-of-range`: §2.7 の 1〜7 のどれか。
- `classified`: §2.5 の表に当たる。
- 問題集に採らないもの（分類とは別。D-08）: 出せる車を一様に無作為に選んでも必ず勝つ問題、見た目か解き味のキーが重なる問題、同じレベルで同じ位置・向き・定員の車が7台以上ある盤面の組。

**利用者向けの一言と、隣のレベルとの違い**:

| レベル | 一言 | 下のレベルとの違い（1行） |
|---|---|---|
| 1 | 列の先頭に合う車を出していけば解ける | — |
| 2 | 罠があり、結果は1〜4人先に出る。すぐ先を見れば避けられる | 先頭に合う車の中に負ける手がある |
| 3 | 罠の結果が5〜7人先に出る。数台分先まで列を読む | 結果が5人以上先に出る罠を、どう進めても避けて通れない |
| 4 | 罠の結果が8〜9人先に出る | その罠の結果が8人以上先に出る |
| 5 | 罠の結果が10人以上先に出る。列の半分を読む | その罠の結果が10人以上先に出る |

認識合わせで見せた一言（合意）との違い:

| レベル | 合意で見せた一言 | 違い |
|---|---|---|
| 1 | 列の先頭に合う車を出していけば解ける | 同じ |
| 2 | 罠の結果が1〜4人先 | 同じ意味に「すぐ先を見れば避けられる」を足した |
| 3 | 5〜7人先 | 同じ意味に「数台分先まで列を読む」を足した |
| 4 | 8人以上先 | 「8〜9人先」に狭めた |
| 5 | 深い罠が重なる。5人先まで読んでも半分も勝てない | 「10人以上先」に変えた |

Lv4・Lv5 を変えた理由:
- 罠を判断の単位で数えると、上のレベルの問題の多くは深い判断が1つだけだった。重い罠に2回以上出会う問題は Lv3 25%・Lv4 5%・Lv5 14% で、上のレベルほど増えない（§5）。
- 判断の回数（重なり）は、どの模擬でもレベルの順に並ばなかった（§13.1）。
- そこで Lv5 を「重なり」ではなく「さらに深い」にした。合意の「深い罠が重なる」は、今の物差しでは問題の性質として現れない。最終レビューで人間に確かめる（実装前提調査 D-05）。

## 12. パズル仕様の難易度の節の案

- 挑戦: 乗客の列を先まで読み、いま出す車が何人先で待機枠をふさぐかを見抜いて、出す車と順番を決めること。
- 基準とするプレイ: 列と盤面が全部見え、負けの知らせは無い。戻さずに先を読む人を基準にする。
- 難易度に含めないもの: 列の長さ・台数・盤面の広さ・掘る台数・戻して試し直す量。
- 挑戦を強めるもの: どう進めても避けて通れない罠の、結果が何人先に出るか。読まずに素朴な規則で避けられる問題と、読み手の候補の外の勝つ手で避けて通れる問題は上位に置かない。
- 提供範囲: 進め方・遊び方・続け方でレベルが食い違う問題、読まずに8割勝てる上位の問題、候補の外の勝つ手で重い罠を避けられる上位の問題、先頭に合わせる遊び方では必ず詰む Lv2 の問題は提供しない。どう出しても必ず勝つ問題は出さない。

- 境目の近くの問題の扱い: 境目を両側に1人動かしても同じレベルの問題だけを採ると、Lv4（8〜9人先）が1問も残らない。5段階の形では採れないので採らなかった（4段階なら採れる。§13.4）。

- 列だけで立てる計画（盤面を無視して、色ごとに乗客の塊を車へ割り当てる計画）で解ける問題は、上位から外さない。列を先まで読んで計画することがこのパズルの核（先読み）そのもので、それで解ける問題は挑戦を求めている。人がこの計画を頭で立てられるかは試遊で確かめる。

調査の段階の、1手戻す人の模擬（調査コード `hdigest`。上の6,672行。1問7回の中央値。Lv1・Lv2 は300行の標本）。隣のレベルの順が保たれる確率は、先頭の色を優先して試す人・無作為に試す人・詰んだ局面を覚える人・4人先を読む人で 1-2 0.50〜0.83、2-3 0.76〜0.94、3-4 0.57〜0.63、4-5 0.55〜0.60。ゲームのコードの試し出しで戻す人（§8）と同じ傾向である。

### 13.2 生成条件の比較

### 13.3 列だけで決まる罠

盤面に関係なく列と定員だけで決まる罠も、核の「乗客の列の先を読む」の一部として除かない（仮決定。案F までの計測で Lv2〜Lv5 の 12〜40% に含まれる。案H では測り直していない）。

### 13.4 4段階にする別案（人に残す）

Lv4 と Lv5 を1つにして、「8人以上先の罠がある」を最上位にする形。調査の段階の計測（上の6,672行）:

| 隣 | 先頭の色を優先 | 無作為 | 覚える | 4人先を読む |
|---|---:|---:|---:|---:|
| 3-4（5段階の Lv3 と、Lv4∪Lv5） | 0.64 | 0.63 | 0.69 | 0.64 |
| 同上、境目を両側に1人動かしても同じレベルの問題だけ | 0.67 | 0.62 | 0.76 | 0.70 |

- 境目から離れた問題だけを採っても、Lv3 48行・Lv4 82行（11,396行中）が残る。
- 4段階では、隣の差が1手戻す人のどれでも 0.6 を超え、境目から離れた問題だけを採る形も作れる。人間は5段階を選んだ（実装前提調査 D-05）。最終レビューで Lv4・Lv5 が分かれて感じられなければ、上位2段階の作り直しの出発点にする。

5段階を保つ別の手（測っていない）: ルールの要素を足して、より深い先読みや判断の重なりが現れる問題を作る（列の一部を伏せる・待機枠に優先順を足す、など）。合意したルールの外で、人に聞く必要がある。
