送迎パーキング（ゲーム ID `shuttle-parking`）の `レベル 1`〜`レベル 5` を、[難易度開発手順.md](../../難易度開発手順.md) の工程2〜8 に沿って、導入調査の段階で組み立てた検討記録（下書き）。

この文書は正本ではない。採用した決まりとその意図はパズル仕様（PZL-015。まだ無い）に、特徴の計算・境目・分類条件はゲームのコード（まだ無い）に置く。ここには、比べた案、測った量、決めた理由、採らなかった案を残す。§2 の定義は、TypeScript へ移すときに同じ結果を出せるよう、調査コードの細部まで書く。

根拠は次の見出し語で分ける。

- **計測**: [調査コード/shuttle-parking_difficulty.py](調査コード/shuttle-parking_difficulty.py) で測った値。乱数は文字列の seed で固定し、同じ入力で同じ結果になることを確かめた（§6）。
- **導出**: 定義から論理的に言えること。
- **推測**: 計測で確かめていない判断。

**人はまだ遊んでいない。** AI の試遊もしていない。各レベルの体験差は、読み手のモデルと「1手戻す人」「h 人先まで読む人」「意味のない好みの人」の模擬で測った仮説である。

**5段階について（最も大事な結論）**: 今の物差しで安定して分けられるのは4段階である。
- 4段階: 罠なし / 浅い罠 / 5〜7人先の罠 / 8人以上先の罠。
- 5段階: 4段階目を「8〜9人先」と「10人以上先」に分けた形を採った。
  - この2つの間は、1手戻す人の戻し回数でわずかにしか並ばない（0.55〜0.60）。
  - Lv4 は境目を1人動かすと半分が動く。

合意は5段階なので、5段階の形で作り切った（§4）。4段階にする別案と、その根拠を §13.4 に置く。

経緯:

## 2. 挑戦・基準とするプレイ条件・定義

**挑戦の1文**: 乗客の列を先まで読み、いま出す車が何人先で待機枠をふさぐか（座席が余る・必要な車が出られなくなる）を見抜いて、出す車とその順番を決める。

挑戦に入れないもの: 列の長さ・台数・手数（作業量）、塞ぐ車を掘る台数、戻して試し直す量。押し切りの扱いは採点の観点で決める。

基準とするプレイ条件: 列も盤面も全部見えていて、負けの知らせは無い。戻しは使わずに先を読んで解く人を基準にする（合意の「称えたい解き方の仮説」）。

### 2.1 ルールと状態

- 状態は（残っている車の集合、色ごとに待機している車の定員を到着順に並べたもの）。乗った人数は残りの車の集合から決まる（研究の資料の導出どおり）。2つの状態はこの組が同じときに同じとみなす。
- 出せる車: 待機している車の数が待機枠より少なく、開口の辺へ向かう進路（車の向きに沿った2方向のうち、開口の辺へ向かうもの）の上に残っている車が無い車。
- 列の先頭: 出た車の座席を色ごとに数え、列の前から順に、その色の空き座席がある限り乗せて進めた位置。
- 勝ち局面: 出せる車を選び続けて、全部の車を出せる局面。

### 2.2 先頭に合わせる人の候補

局面ごとに、次の段を順に試し、勝つ手を1つでも含む最初の段を候補にする（`Model.tier`、段の並びは `headFirst → run1 → run2 → run3 → all`）。

1. 出せる車のうち、列の先頭の色の車。1台も無ければ 2 から始める。
2. 先頭の色の車（出せなくてもよい）と、その閉包（進路を塞ぐ車、それを塞ぐ車…）のうち、出せる車。
3. 列の先頭から数えて2つ目の色の区間までに出てくる色の車と、その閉包のうち、出せる車。
4. 3つ目の色の区間まで、同じように。
5. 出せる車すべて。

補足:
- 色の区間は、同じ色が続く並びを1つと数える。
- 「進路を塞ぐ車」は、開口の辺へ向かう進路の上にいる、残っている車（進路が2本あれば両方の上の車）。
- どの段にも、待機枠がすぐ埋まる手は含まれる（すぐ詰む手も罠として数える）。

### 2.3 先回りする人の候補

先頭から5人（`G_WINDOW`）に出てくる色の車と、その閉包のうち、出せる車を候補にする。その中に勝つ手が無ければ、出せる車すべて（`Model.window_candidates`。窓は5人に固定し、局面ごとに選び直さない）。

### 2.4 罠・深さ・重さ

- **罠**: 候補のうち、その手の後どう続けても勝てない手。
- **罠の深さ**: 2つの取り方がある。どちらも、罠の手を打つ前の局面の先頭から数えた人数で、罠の手そのもので乗る人も含む。
  - **最善の続き**（`Model.distance`）: 罠の手の後、出せる車すべて（待機枠を埋める手も含む）を使って続けたときに、到達できる先頭の位置の最大 − 打つ前の先頭の位置。
  - **気づかずに続けた場合**（`ContinuationDepthModel`）: 罠の手の後、素朴な解き方（§2.6）の候補から一様に選んで続ける。素朴な候補が空になった所で止まる（待機枠を埋める手しか残っていなくても、それは打たない）。止まった先頭の位置の期待値 − 打つ前の先頭の位置を、切り捨てた整数（Python の `int()`。期待値は浮動小数で計算する。TypeScript へ移すときは `Math.trunc` にし、ちょうど整数になる値の誤差に注意）。
- **罠の重さ**: 深さ + 1（負けが見えるのに要る人数）。

### 2.5 判断と、判断の回数（分類に使う特徴）

- **勝ち筋**: 各局面で、候補のうち勝つ手だけを選び続ける筋。
- **判断**: 段 θ（1・5・8・10）ごとに、その局面で重さ θ 以上の罠になっている車の集合 T_θ を取る。勝ち筋の上で、T_θ が空でなく、直前の局面の T_θ と共通の車が無いとき、新しい判断として1回数える。共通の車があれば、同じ判断が続いているとみなす。
  - 先頭の色の車を出すために塞ぐ車を1台ずつ出している間、同じ車が罠のまま続くので、1回になる。
  - 勝ち筋の最初の局面の「直前」は空の集合。
- **D_θ**: どの勝ち筋を通っても出会う、重さ θ 以上の判断の回数の最小。
- **D_θmax**: 最も多く出会う勝ち筋での回数（`h_counts`）。
- **局面の数（`states`）**: 勝ち筋の上で通った（局面、直前の T の組）の組の数。終わりの局面（車が残っていない局面）は数えない。移植の期待値に入っているのは、探索の打ち切りに関わる量として突き合わせるため。

### 2.6 素朴な解き方と規則の組（上位を止める条件）

**素朴な解き方**（`naive_options`）は、次の順に候補を作る。

1. 出せる車のうち、出した直後に待機枠が埋まる手（全部出し終える手は除く）を外す。
2. 残りに先頭の色の車があれば、それが候補。
3. 無ければ、先頭の色の残っている車ごとに、進路ごとの「塞ぐ車の数」の最小を求める。
4. その値が最も小さい車を全部取り、各車の、その最小の値をとる進路を全部取る。それらの進路を塞ぐ車をすべて合わせ、その閉包に入る出せる車を候補にする（並んだ車・並んだ進路は1つに選ばず、和集合を取る。`cheapest_dig`）。
5. その中に出せる車が無ければ、1 の後の手すべてが候補。1 の後に手が無ければ候補は空。

**規則の組**（`G_RULES`。前もって固定し、後から足さない）。候補の作り方は2つある。

- 素朴: 上の候補。
- 広い（`wide_options`）: 待機枠がすぐ埋まる手を外したうえで、先頭の色の車が出せればそれ、無ければ全部の先頭色の車の進路を塞ぐ車の閉包に入る出せる車。閉包の中に出せる車が無ければ、外した後の手すべて。

その候補の中で、鍵の値が最小の車を選ぶ（同点なら一様）。

| 規則 | 候補 | 鍵 |
|---|---|---|
| any | 素朴 | 0 |
| small | 素朴 | 定員 |
| big | 素朴 | −定員 |
| unblock | 素朴 | (−その車が進路の上にいる「いま出られない車」の台数, 定員) |
| needed | 素朴 | (その車が進路の上にいる「いま出られない車」の色ごとの「座席が足りなくなる位置」の最小。そういう車が無ければ無限大, 定員) |
| fill | 素朴 | その色の空き座席 + 定員 人目のその色の客の、列の中の位置（その客がいなければ無限大） |
| wideNeeded | 広い | needed と同じ |
| wideFill | 広い | fill と同じ |

鍵で使う言葉:
- **いま出られない車**: 残っている車のうち、開口の辺へ向かう進路がどれも塞がっている車。
- **座席が足りなくなる位置**（色ごと）: 外に出ている車の空き座席に、いま出せる車（進路だけで判断し、待機枠の空きは見ない。鍵を測っている車は除く）の座席を合わせる。列の先頭から順に、その色の客1人ごとに座席を1つ使い、使える座席が無くなった最初の客の位置。

**規則の勝率**: 先読みせずにその規則で出し続ける人の勝率（候補が同点なら一様。負けの局面に入った時点で 0、候補が空なら 0）。

### 2.7 レベルの決め方（`level_H`、判定の順）

各読み手について、D_θ から「最小のレベル」、D_θmax から「最大のレベル」を、下の表で出す。

1. 先頭に合わせる人の、深さの2つの取り方のどちらかで、最小と最大が違えば範囲外（`pathDependent`。進め方でレベルが変わる）。
2. 深さの2つの取り方で最小のレベルが違えば範囲外（`depthDefinitionsDisagree`）。
3. 先回りする人の最小のレベルが違えば範囲外（`playStylesDisagree`）。ただし、レベルが1で先回りする人が2なら Lv1 とする。
4. Lv3 以上で、規則の組のどれかの勝率が 0.8 以上なら範囲外（`naiveCeiling`）。
5. Lv2 で、規則の組がどれも勝率 0 なら範囲外（`headPoliciesAllLose`）。

| レベル | 条件（`h_level_depth`） |
|---|---|
| 1 | D1 = 0（判断が無い） |
| 2 | D5 = 0（判断はあるが、どれも結果が4人先まで） |
| 3 | D8 = 0（5〜7人先の判断がある） |
| 4 | D10 = 0（8〜9人先の判断がある） |
| 5 | D10 ≥ 1（10人以上先の判断がある） |

## 4. 状態と分類

- `invalid`: 全部の車を出せない、または解ける最小の待機枠が2〜4に無い。
- `out-of-range`: §2.7 の 1〜5 のどれか。
- `unsupported`: 使わない（8台では1候補 p95 0.014 秒で厳密探索が終わる）。
- `classified`: §2.7 の表に当たる。

**利用者向けの一言と、隣のレベルとの違い**:

| レベル | 一言 | 下のレベルとの違い（1行） | 合意で見せた一言からの変更 |
|---|---|---|---|
| 1 | 列の先頭に合う車を出していけば解ける | — | なし |
| 2 | 罠があり、結果は1〜4人先に出る。すぐ先を見れば避けられる | 先頭に合う車の中に負ける手がある | なし |
| 3 | 罠の結果が5〜7人先に出る。数台分先まで列を読む | 結果が5人以上先に出る罠を、どう進めても避けて通れない | なし |
| 4 | 罠の結果が8〜9人先に出る | その罠の結果が8人以上先に出る | 「8人以上先」を「8〜9人先」に |
| 5 | 罠の結果が10人以上先に出る。列の半分を読む | その罠の結果が10人以上先に出る | 「深い罠が重なる」を「10人以上先」に |

一言を変える理由:
- 罠を判断の単位で数え直すと、上のレベルの問題の多くは、深い判断が1つだけだった（§5）。
- 判断の回数（重なり）は、どの模擬でもレベルの順に並ばなかった（§13.1）。
- そこで、Lv5 を「重なり」ではなく「さらに深い」にした。合意の「深い罠が重なる」は、今の物差しでは問題の性質として現れない。

## 12. パズル仕様の難易度の節の案

- 挑戦: 乗客の列を先まで読み、いま出す車が何人先で待機枠をふさぐかを見抜いて、出す車と順番を決めること。
- 基準とするプレイ: 列と盤面が全部見え、負けの知らせは無い。戻さずに先を読む人を基準にする。
- 難易度に含めないもの: 列の長さ・台数・盤面の広さ・掘る台数・戻して試し直す量。
- 挑戦を強めるもの: どう進めても避けて通れない判断の、結果が何人先に出るか。読まずに素朴な規則で避けられる問題は上位に置かない。
- 提供範囲: 進め方・遊び方・続け方でレベルが食い違う問題、読まずに8割勝てる上位の問題、先頭に合わせる遊び方では必ず詰む Lv2 の問題は提供しない。

- 深さも回数も上のレベルで下がらない（深さだけで決める）。
