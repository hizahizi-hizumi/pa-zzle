根拠は次の見出し語で分ける。

- **計測**: [調査コード/shuttle-parking_difficulty.py](調査コード/shuttle-parking_difficulty.py) で測った値。乱数は文字列の seed で固定し、同じ入力で同じ結果になることを確かめた（§6）。

- **推測**: 計測で確かめていない判断。

**人はまだ遊んでいない。** AI の試遊もしていない。各レベルの体験差は、読み手のモデルと「1手戻す人」「意味のない好みの人」の模擬で測った仮説である。§10 の試遊が済むまで、そう扱う。

## 2. 挑戦・基準とするプレイ条件・定義

**挑戦の1文**: 乗客の列を先まで読み、いま出す車が何人先で待機枠をふさぐか（座席が余る・必要な車が出られなくなる）を見抜いて、出す車とその順番を決める。

挑戦に入れないもの: 列の長さ・台数・手数（作業量）、戻して試し直す量（罰と作業量）。押し切りの扱いは採点の観点で決める。

基準とするプレイ条件: 列も盤面も全部見えていて、負けの知らせは無い。戻しは使わずに先を読んで解く人を基準にする（合意の「称えたい解き方の仮説」）。

### 2.1 ルールと状態（計算の前提）

- 状態は（残っている車の集合、色ごとに待機している車の定員を到着順に並べたもの）。乗った人数は残りの車の集合から決まる（研究の資料の導出どおり）。
- 出せる車: 待機している車の数が待機枠より少なく、開いた辺へ向かう進路の上に残っている車が無い車。
- 列の先頭: 出た車の座席を色ごとに数え、列の前から順に、その色の空き座席がある限り乗せて進めた位置。
- 勝ち局面: 出せる車を選び続けて、全部の車を出せる局面。

### 2.2 先頭に合わせる人の候補

局面ごとに、次の段を順に試し、勝つ手を1つでも含む最初の段を候補にする（調査コードの `Model.tier`、段の並びは `headFirst → run1 → run2 → run3 → all`）。

1. 出せる車のうち、列の先頭の色の車。1台も無ければ、2 から始める。
2. 先頭の色の車（出せなくてもよい）と、その進路を塞ぐ車、さらにそれを塞ぐ車…（塞ぐ車の閉包）のうち、出せる車。
3. 列の先頭から数えて2つ目の色の区間までに出てくる色の車と、その閉包のうち、出せる車。
4. 3つ目の色の区間まで、同じように。
5. 出せる車すべて。

色の区間は、同じ色が続く並びを1つと数える。「塞ぐ車」は、開いた辺へ向かう進路の上にいる、残っている車。どの段にも、待機枠がすぐ埋まる手は含まれる（すぐ詰む手も罠として数える）。

### 2.3 先回りする人の候補

先頭から5人（`G_WINDOW`）に出てくる色の車と、その閉包のうち、出せる車。その中に勝つ手が無ければ、出せる車すべて（`Model.window_candidates`。窓は5人に固定し、局面ごとに選び直さない）。

### 2.4 罠と罠の重さ

- **罠**: 候補のうち、その手の後どう続けても勝てない手。
- **罠の深さ**: 2つの取り方を持ち、どちらも、その局面の先頭から数えた人数。
  - 最善の続き（`Model.distance`）: 罠の手の後、最善を尽くして乗れる人数の最大。
  - 気づかずに続けた場合（`ContinuationDepthModel`）: 罠の手の後、素朴な解き方（§2.6）で出し続けた人が、出せる候補が無くなるまでに乗せる人数の期待値を切り捨てた整数。候補が同点なら一様に選ぶ。
- **罠の重さ**: その局面の候補にある罠の深さの最大 +1（負けが見えるのに要る人数）。罠が無い局面の重さは 0。

### 2.5 罠に出会う回数（分類に使う特徴）

**勝ち筋** = 各局面で、候補のうち勝つ手だけを選び続ける筋（`g_counts`）。

| 量 | 意味 |
|---|---|
| K1 | どの勝ち筋を通っても出会う、重さ 1 以上の罠のある局面の数の最小 |
| K5 | 同じく、重さ 5 以上（結果が5人以上先に出る罠） |
| K8 | 同じく、重さ 8 以上 |
| K1max | 最も多く出会う勝ち筋での、重さ 1 以上の局面の数 |

罠の数は、負ける手の数ではなく、罠のある局面の数で数える（1つの局面に負ける手が何本あっても1回）。同点を無作為に割った勝率ではないので、二択の罠に1回だけ出会う問題と、罠を何度も通る問題が分かれる（前の案の崩れた所。§13.1）。

### 2.6 素朴な解き方と規則の組（上位を止める条件）

**素朴な解き方**（`naive_options`）は、次の順に候補を作る。

- 出した直後に待機枠が埋まる手（全部出し終える手は除く）を外す。
- 残りに先頭の色の車があれば、それが候補。
- 無ければ、先頭の色の車ごとに「進路のうち塞ぐ車が最も少ないものの、塞ぐ車の数」を数え、その数が最小の車の、その最小の進路を塞ぐ車と、それを塞ぐ車の閉包を候補にする。
- その中に出せる車が無ければ、外した後の手すべてが候補。

**規則の組**（`G_RULES`。前もって固定し、後から足さない）。どの規則も、まず候補の作り方を決め、その候補を鍵で選ぶ。

候補の作り方は2つ。
- 素朴: 上の素朴な解き方の候補。
- 広い（`wide_options`）: 掘る場面で、どの先頭色の車を掘ってもよい。待機枠がすぐ埋まる手を外し、先頭の色の車が出せればそれ、無ければ全部の先頭色の車の進路を塞ぐ車の閉包を候補にする。

候補の中で、鍵の値が最小の車を選ぶ。同点なら一様に選ぶ。鍵は、先頭の色の車を出す場面にも、掘る場面にも同じものを当てる。

| 規則 | 候補 | 鍵 |
|---|---|---|
| any | 素朴 | どれでも（0） |
| small | 素朴 | 定員の小さい順 |
| big | 素朴 | 定員の大きい順 |
| unblock | 素朴 | いま出られない車の進路の上にいる数が多い順、並べば定員の小さい順 |
| needed | 素朴 | その車が進路の上にいる「いま出られない車」の色のうち、座席が最も早く足りなくなる位置が早い順、並べば定員の小さい順 |
| fill | 素朴 | 出すと座席が最も早く埋まる順（その色の空き座席 + 定員 人目のその色の客の位置） |
| wideNeeded | 広い | needed と同じ |
| wideFill | 広い | fill と同じ |

鍵で使う言葉:

- **いま出られない車**: 残っている車のうち、開いた辺へ向かう進路がどれも塞がっている車。
- **座席が足りなくなる位置**（色ごと）: 次の座席を色ごとに合わせる。
  - 外に出ている車の空き座席
  - いま出せる車（鍵を測っている車は除く）の座席

  列の先頭から順に、その色の客1人ごとに座席を1つ使い、使える座席が無くなった最初の客の位置。

**規則の勝率**: 先読みせずにその規則で出し続ける人の勝率（候補が同点なら一様に選ぶ）。負けの局面に入った時点で 0 として数える。

### 2.7 レベルの決め方（`level_G`）

1. 次の3つで、それぞれ下の表からレベルを出す。
   - 先頭に合わせる人 × 最善の続き
   - 先頭に合わせる人 × 気づかずに続けた場合
   - 先回りする人 × 最善の続き
2. 先頭に合わせる人の2つが違えば範囲外（深さの取り方で食い違う）。
3. 先回りする人のレベルが違えば範囲外（遊び方で食い違う）。ただし、先頭に合わせる人が Lv1 で先回りする人が Lv2 なら、Lv1 とする（先頭に合わせて出せば罠に出会わない、という Lv1 の意味は保たれるため）。
4. Lv3 以上で、規則の組のどれかの勝率が 0.8 以上なら範囲外。
5. Lv2 で、規則の組がどれも勝率 0 なら範囲外（先頭に合わせる遊び方では必ず詰むので、低いレベルに置かない）。

| レベル | 条件（数え方は §2.5） |
|---|---|
| 1 | K1max = 0（先頭に合わせて出せば、どの候補を選んでも罠に出会わない） |
| 2 | K1max ≥ 1 で、K5 = 0（罠はあるが、どの勝ち筋でも5人以上先の罠には出会わずに済む） |
| 3 | K5 = 1（5人以上先の罠に、どの勝ち筋でも1回出会う） |
| 4 | K5 = 2 で、K8 ≤ 1 |
| 5 | K5 ≥ 3、または K8 ≥ 2（深い罠が重なる） |

## 3. 特徴

| 特徴 | 意味 | 扱い |
|---|---|---|
| K1max・K5・K8（先頭に合わせる人、深さ2つ） | どの勝ち筋でも出会う、結果が5人・8人以上先に出る罠の回数 | 分類に使う |

## 4. 状態と分類

- `invalid`: 全部の車を出せない、または解ける最小の待機枠が2〜4に無い。
- `out-of-range`: §2.7 の 2〜5 のどれか（理由は `depthDefinitionsDisagree`・`playStylesDisagree`・`naiveCeiling`・`headPoliciesAllLose`）。
- `unsupported`: 使わない（8台では1候補 p95 0.014 秒で厳密探索が終わる）。
- `classified`: §2.7 の表に当たる。

**利用者向けの一言と、隣のレベルとの違い**:

| レベル | 一言 | 下のレベルとの違い（1行） | 合意で見せた一言からの変更 |
|---|---|---|---|
| 1 | 列の先頭に合う車を出していけば解ける | — | なし |
| 2 | 罠があり、結果は1〜4人先に出る。すぐ先を見れば避けられる | 先頭に合う車の中に、負ける手がある | なし |
| 3 | 5人以上先に結果が出る罠を、1度は見抜く | 結果が5人以上先に出る罠を、どう進めても1回は避けなければならない | 「5〜7人先」を「5人以上先の罠に1度」に変えた |
| 4 | 5人以上先に結果が出る罠を、2度見抜く | その罠が2回ある | 「8人以上先」を「5人以上先の罠に2度」に変えた |
| 5 | 深い罠が重なる。5人以上先の罠が3度以上か、8人以上先の罠が2度以上 | 罠が3回以上か、8人以上先の罠が2回以上 | 「深い罠が重なる」はそのまま。中身を回数で書いた |

変更の理由: 前の案（F）までは「何人先まで読めば何割勝てるか」でレベルを分けていた。この量は、二択の罠に1回だけ出会う問題と、罠を何度も通る問題を区別できなかった。意味のない好みの人（車ごとに固定の優先順）で測ると、前の案の Lv3 の 47/49 は、必ず勝つ人と必ず負ける人に割れた（反例探しの役の計測）。つまり前の案の Lv3 は「1回の二択」だった。そこで、回数を主な軸にし、深さは「その罠が5人以上先か・8人以上先か」の段として使った。深い罠が1つだけの問題は、8人以上先でも Lv3 に置く。合意の一言「5〜7人先」「8人以上先」は深さだけで書かれているので、回数の言い方に変える必要がある。面白さの核（先読み）は変えていない。

言えること（計測）:

- 分類に使う K1・K5・K8 は、隣のレベルで 10/50/90 パーセンタイルが逆転しない（B1）。
- 規模とレベル: 8台に固定したので、列の長さとレベルの順位相関は −0.02。盤面 6×6・7×7、開口1辺・隣り合う2辺、色3・4・2台ずつ、待機枠2・3・4 のどれにも、5レベルすべてがある（色と開口ごとの数は調査コードの `gdigest` の `countsByColors`・`countsByOpening`）。

## 12. パズル仕様の難易度の節の案

- 挑戦: 乗客の列を先まで読み、いま出す車が何人先で待機枠をふさぐかを見抜いて、出す車と順番を決めること。
- 基準とするプレイ: 列と盤面が全部見え、負けの知らせは無い。戻さずに先を読む人を基準にする。
- 難易度に含めないもの: 列の長さ・台数・盤面の広さ・戻して試し直す量。
- 挑戦を強めるもの: どう進めても避けて通れない罠の回数と、その罠の結果が何人先に出るか。読まずに素朴な規則で避けられる問題は上位に置かない。先頭に合わせて出す遊び方と前もって出す遊び方、罠に気づいた後の続け方のどれでも、同じレベルになる問題だけを提供する。
- 1〜5 の違い: §4 の一言。
- 提供範囲: 遊び方や続け方でレベルが食い違う問題、読まずに8割勝てる上位の問題、先頭に合わせる遊び方では必ず詰む Lv2 の問題は提供しない。
