# 送迎パーキング難易度

送迎パーキング（ゲーム ID `shuttle-parking`）の `レベル 1`〜`レベル 5` を、[難易度開発手順.md](../../難易度開発手順.md) の工程に沿って組み立てた検討記録。

この文書は正本ではない。採用した決まりとその意図はパズル仕様（PZL-015。まだ無い）に、特徴の計算・境目・分類条件はゲームのコード（`frontend/src/games/shuttle-parking/difficulty.ts` と `problem/`）に置く。ここには、比べた案、測った量、決めた理由、採らなかった案を残す。§2 の定義はコードと同じ意味で書き、値はコードを正とする。判定モデル版は `2`。

根拠は次の見出し語で分ける。

- **計測**: ゲームのコードで測った値。出どころは主に問題集の生成スクリプトの統計（`bun run --cwd frontend generate:shuttle-parking-pool -- --stats --cache <キャッシュ>`）と `--verify`。一度だけ測った値は「一時スクリプト」と書く。調査の段階の値は [調査コード/shuttle-parking_difficulty.py](調査コード/shuttle-parking_difficulty.py) で測り、そう書く。
- **報告**: 経緯を知らない役（反例探し・自己点検・手追い）が報告した値。検証コードと結果はスクラッチパッドにだけあり、ここでは数を写す。
- **導出**: 定義から論理的に言えること。
- **推測**: 計測で確かめていない判断。

検査の記号（A3・B1・D1 など）は `/design-game-difficulty` の検査（`.claude/skills/design-game-difficulty/references/checks.md`）の記号である。

**人はまだ遊んでいない。** AI の試遊は代表の問題で1回した（体感の材料は §10）。各レベルの体験差は、読み手のモデルと素朴な解き方の模擬で測った仮説である。

## 2. 挑戦・基準とするプレイ条件・定義

**挑戦の1文**: 乗客の列を先まで読み、いま出す車が何人先で待機枠をふさぐか（座席が余る・必要な車が出られなくなる）を見抜いて、出す車とその順番を決める。

挑戦に入れないもの: 列の長さ・台数・手数（作業量）、塞ぐ車を掘る台数、戻して試し直す量。押し切りの扱いは採点で決める。

基準とするプレイ条件: 列も盤面も全部見えていて、負けの知らせは無い。罠に入らずに先を読んで解く人を基準にする（合意の「称えたい解き方の仮説」を、採点の前提（実装前提調査 D-15）と同じく「罠に入らずに」と読む）。

分析は全部の状態をたどる（8台では1候補の生成と分析が p95 11 ms で終わる。計測、一時スクリプト）。探索の打ち切りは無い。

### 2.1 ルールと状態

コードは `problem/generation/state-game.ts`。

- 状態は（残っている車の集合、色ごとに待機している車の定員を到着順に並べたもの）。乗った人数は残りの車の集合から決まる。2つの状態はこの組が同じときに同じとみなす。
- 待機している車の数: 出した車に乗れる乗客を全部乗せ、満席の車を出発させた後に、待機枠に残っている車の数。
- 出せる車: 待機している車の数が待機枠より少なく、出口の辺へ向かう進路（車の向きに沿った2方向のうち、出口の辺へ向かうもの）の上に残っている車が無い車。
- 待機枠がすぐ埋まる手: 出した後の待機している車の数が待機枠と等しくなる手（全部の車を出し終える手は除く）。
- 列の先頭: 出た車の座席を色ごとに数え、列の前から順に、その色の空き座席がある限り乗せて進めた位置。同じ色の車が2台待っていれば先に入った車に乗る。
- 勝ち局面: 出せる車を選び続けて、全部の車を出せる局面。
- 解ける最小の待機枠: 待機枠を見ずに出していくどこかの順で、待機している車の数の最大を最も小さくした値 + 1。

### 2.2 先頭に合わせる人の候補

局面ごとに、次の段を順に試し、勝つ手を1つでも含む最初の段を候補にする（`problem/generation/readers.ts` の `widenedCandidates`。段は `headFirst → run1 → run2 → run3 → all`）。

1. 出せる車のうち、列の先頭の色の車。1台も無ければ 2 から始める。
2. 先頭の色の車（出せなくてもよい）と、その閉包（進路を塞ぐ車、それを塞ぐ車…）のうち、出せる車。
3. 列の先頭から数えて2つ目の色の区間までに出てくる色の車と、その閉包のうち、出せる車。
4. 3つ目の色の区間まで、同じように。
5. 出せる車すべて。

補足:
- 色の区間は、同じ色が続く並びを1つと数える。
- 「進路を塞ぐ車」は、出口の辺へ向かう進路の上にいる、残っている車（進路が2本あれば両方の上の車）。
- どの段にも、待機枠がすぐ埋まる手は含まれる（すぐ詰む手も罠として数える）。

### 2.3 先回りする人の候補

先頭から5人に出てくる色の車と、その閉包のうち、出せる車を候補にする。その中に勝つ手が無ければ、出せる車すべて（`candidates` の `window`。窓は5人に固定し、局面ごとに選び直さない）。

### 2.4 罠・深さ・重さ

- **罠**: 候補のうち、その手の後どう続けても勝てない手。
- **罠の深さ**: 2つの取り方がある。どちらも、罠の手を打つ前の局面の先頭から数えた人数で、罠の手そのもので乗る人も含む（`ShuttleParkingReader.distance`）。
  - **最善の続き**（`best`）: 罠の手の後、出せる車すべて（待機枠を埋める手も含む）を使って続けたときに、到達できる先頭の位置の最大 − 打つ前の先頭の位置。
  - **気づかずに続けた場合**（`continuation`）: 罠の手の後、素朴な解き方（§2.6）の候補から一様に選んで続ける。素朴な候補が空になった所で止まる。止まった先頭の位置の期待値 − 打つ前の先頭の位置を、切り捨てた整数（`Math.trunc`）。
- **罠の重さ**: 深さ + 1（負けが見えるのに要る人数）。
- **局面の重さ**: その局面の候補のうち、罠の手の重さの最大（罠が無ければ0）。

### 2.5 勝ち筋とレベル

- **勝ち筋**: 各局面で、候補のうち勝つ手だけを選び続けて全部の車を出す筋。
- **勝ち筋の重さ**: 勝ち筋の上の局面の重さの最大。
- **重さの最小と最大**: 勝ち筋の重さの、すべての勝ち筋の中での最小（どう進めても出会う最も重い罠）と最大（`measureShuttleParkingWeightBounds`）。
- **進め方を広げた重さ**: 罠の重さは先頭に合わせる人の候補で数えたまま、進め方を「勝つ手ならどれでもよい」（候補の外の勝つ手も選べる）に広げたときの、勝ち筋の重さの最小（`freePath`）。

レベルは重さの最小の段で決める（`SHUTTLE_PARKING_WEIGHT_BY_LEVEL`）。

| レベル | 重さの最小 | 意味 |
|---|---|---|
| 1 | 0 | 先頭に合わせて出せば罠に出会わない |
| 2 | 1〜4 | 罠の結果が4人先までに出る |
| 3 | 5〜7 | 罠の結果が5〜7人先に出る |
| 4 | 8〜9 | 罠の結果が8〜9人先に出る |
| 5 | 10 以上 | 罠の結果が10人以上先に出る |

### 2.6 素朴な解き方と規則の組（上位を止める条件）

**素朴な解き方**（`listNaiveMoves`）は、次の順に候補を作る。

1. 出せる車のうち、待機枠がすぐ埋まる手を外す。
2. 残りに先頭の色の車があれば、それが候補。
3. 無ければ、先頭の色の残っている車ごとに、進路ごとの「塞ぐ車の数」の最小を求める。
4. その値が最も小さい車を全部取り、各車の、その最小の値をとる進路を全部取る。それらの進路を塞ぐ車をすべて合わせ、その閉包に入る出せる車を候補にする。
5. その中に出せる車が無ければ、1 の後の手すべてが候補。1 の後に手が無ければ候補は空。

**規則**（`SHUTTLE_PARKING_NAIVE_RULES`）は「候補の作り方」と「鍵」の組で、候補のうち鍵が最小の車を選ぶ。候補の作り方は4つある。

- 素朴: 上の候補。
- 広い: 待機枠がすぐ埋まる手を外したうえで、先頭の色の車が出せればそれ、無ければ全部の先頭の色の車の進路を塞ぐ車の閉包に入る出せる車。閉包の中に出せる車が無ければ、外した後の手すべて。
- 深く掘る: 待機枠がすぐ埋まる手を外したうえで、先頭の色の残っている車ごとに「その車を出すのに出す車」（その車と、進路を塞ぐ車の閉包。進路が2本あれば台数の少ない方）を求める。その台数が空いている待機枠（待機枠 − 待機している車の数）以下の車を「目標」の候補とし、台数が最も多い車を目標にする。最も多い車が複数あれば全部を目標にする。目標の「出すのに出す車」を合わせたものに入る出せる車が候補。目標が無い、または当たる出せる車が無ければ、素朴の候補。すぐ出せる先頭の色の車も、台数1の目標として同じ比べ方に入る。
- 全部: 待機枠がすぐ埋まる手を除いた、出せる車すべて。

| 規則 | 候補 | 鍵 |
|---|---|---|
| any | 素朴 | 0 |
| small | 素朴 | 定員 |
| big | 素朴 | −定員 |
| unblock | 素朴 | (−その車が進路の上にいる「いま出られない車」の台数, 定員) |
| needed | 素朴 | (その車が進路の上にいる「いま出られない車」の色ごとの「座席が足りなくなる位置」の最小。そういう車が無ければ無限大, 定員) |
| fill | 素朴 | その色の空き座席 + 定員 人目のその色の客の、列の中の位置（その客がいなければ無限大） |
| wideNeeded | 広い | needed と同じ |
| wideFill | 広い | fill と同じ |
| deepDig | 深く掘る | 0 |
| deepCommit | 深く掘る（目標を保つ） | 0 |
| untangle | 全部 | (−その車が進路の上にいる「いま出られない車」の台数, その車の色が列の先頭から最初に現れる位置。現れなければ無限大) |

- `deepCommit`（掘った車を使い切る）: 目標を決めたら、その目標の車が出るまで目標を変えない。目標の車がいま出せればその車を出す。目標の車が残っていて先頭の色でなくなったら、目標を決め直す。
- `untangle`（渋滞をほどく）: 先頭の色に関係なく、ふさいでいる車の多い車から出す。いまの `unblock` は素朴の候補の中だけで選ぶので別の規則である。

鍵で使う言葉:
- **いま出られない車**: 残っている車のうち、出口の辺へ向かう進路がどれも塞がっている車。
- **座席が足りなくなる位置**（色ごと）: 外に出ている車の空き座席に、いま出せる車（進路だけで判断し、待機枠の空きは見ない。鍵を測っている車は除く）の座席を合わせる。列の先頭から順に、その色の客1人ごとに座席を1つ使い、使える座席が無くなった最初の客の位置。

**同点の選び方**（`SHUTTLE_PARKING_TIE_BREAKS`）: 鍵が並んだ車の選び方を6通り持つ。`uniform`（一様に選ぶ）と、並んだ車を `needed`・`unblock`・`fill`・`small`（定員の小さい順）・`big`（大きい順）の鍵でさらに絞り、それでも並べば一様に選ぶもの。`deepCommit` は、目標が並べば目標を一様に選び、目標ごとの候補をこの選び方で絞る。

**規則の勝率**: 先読みせずにその規則で出し続ける人の勝率（負けの局面に入った時点で 0、候補が空なら 0）。規則ごとに、同点の選び方ごとの勝率を測り、その最大を「規則の最高勝率」とする。判定はこの最大で行う（一様に選んだ勝率も記録に残す）。

### 2.7 判定の順（`assessShuttleParkingDifficulty`）

0. 待機枠が解ける最小の数でない問題は分析しない（`unsupported`）。生成は解ける最小の数だけを出すので、問題集には入らない。
1. 解ける最小の待機枠が 2〜4 に無ければ範囲外（`bayCountOutOfRange`）。
2. 先頭に合わせる人の、深さの2つの取り方のどちらかで、重さの最小と最大の段が違えば範囲外（`pathDependent`。勝ち筋の選び方でレベルが変わる）。
3. 深さの2つの取り方で、重さの最小の段が違えば範囲外（`depthDefinitionsDisagree`）。
4. 先回りする人の重さの最小の段が違えば範囲外（`playStylesDisagree`）。ただし、レベルが1で先回りする人が2なら Lv1 とする。
5. Lv3 以上で、進め方を広げた重さの段が違えば範囲外（`freePathEscapes`）。
6. Lv3 以上で、規則のどれかの最高勝率が 0.8 以上なら範囲外（`naiveCeiling`）。
7. Lv2 で、規則のどれもが、同点をどう選んでも勝率 0 なら範囲外（`headPoliciesAllLose`）。
8. 残りは、重さの最小の段のレベル（§2.5 の表）。

7 は、規則の最高勝率が0であることと、一様に選んだ勝率が0であることが同じ（どの選び方も一様の選び方が選ぶ手の中から選ぶため。導出）。

**調査の判定**: 調査コードと同じ決まり（規則は any〜wideFill の8つ、同点は一様、5 の確かめなし）で判定したもの。移植の確かめ（§6）と、直しの効き（§6）を測るのに使う。

判定の決まりを変えたら判定モデル版（`SHUTTLE_PARKING_DIFFICULTY_MODEL_VERSION`）を上げ、問題集を作り直す。問題集は作ったときの版を持ち、今の版と同じことをテストで確かめる。

### 2.8 記録だけの回数

判断の回数（`countShuttleParkingDecisions`）は、レベルに使わない記録だけの量として残す。罠の深さは最善の続き（`best`）で取る。勝ち筋の上で、重さの段 t（1・5・8・10）ごとに、その局面で重さ t 以上の罠になっている車の集合を取り、直前の局面の集合と共通の車が無いときに新しい判断として1回数える（先頭の色の車のために塞ぐ車を1台ずつ出している間は、同じ車が罠のまま続くので1回）。どの勝ち筋でも出会う最小と、最も多い勝ち筋の最大を持つ。

調査の判定は「段 t の判断の回数が1以上か」でレベルを決めていた。これは §2.5 の重さの最小と最大で決めるのと同じレベルを返す。勝ち筋の上で段 t の判断が1回以上あることと、その勝ち筋の上に重さ t 以上の罠がある局面があることは同じだからである（導出）。

## 3. 特徴

| 特徴 | 意味 | 扱い |
|---|---|---|
| 重さの最小と最大（先頭に合わせる人 × 深さ2つ） | どう進めても出会う最も重い罠の人数と、勝ち筋の選び方での揺れ | 分類に使う |
| 先回りする人の重さの最小 | 前もって車を出す遊び方でも同じか | 分類に使う（一致） |
| 進め方を広げた重さ | 候補の外の勝つ手で重い罠を避けられないか | 分類に使う（Lv3 以上で一致） |
| 規則の最高勝率（11の規則 × 同点の選び方6通りの最大） | 読まずに素朴な規則で勝てる割合 | 分類に使う（止める条件） |
| 判断の回数 | 何回判断するか | 記録だけ（§2.8） |
| 規則の勝率（同点は一様）、一様に無作為な人の勝率、試し出しで戻す回数 | レベルの順の確かめ（§8） | 記録だけ |
| 罠の重さを手数で数えたもの、4手先まで読む人の勝率、出せる車すべてを候補にした重さ | 人数と手数のどちらが体感に近いかの材料（§5） | 記録だけ |
| 待機枠の数、色の数、列の長さ、出口の辺、盤面の大きさ | 生成条件 | 記録だけ |

## 4. 状態と分類

- `unsupported`: §2.7 の 0。
- `out-of-range`: §2.7 の 1〜7 のどれか。
- `classified`: §2.5 の表に当たる。
- 問題集に採らないもの（分類とは別。D-08）: 出せる車を一様に無作為に選んでも必ず勝つ問題、見た目か解き味のキーが重なる問題、同じレベルで、回転・反転して同じ位置・向き・定員になる車が7台以上ある盤面の組。レベルをまたぐ近い盤面は除かない（列が違う）。問題集に残るまたいだ組は12組（計測）。

**利用者向けの一言と、隣のレベルとの違い**:

|---|---|---|
| 1 | 列の先頭に合う車を出していけば解ける | — |

| レベル | 合意で見せた一言 | 違い |
|---|---|---|
| 1 | 列の先頭に合う車を出していけば解ける | 同じ |
| 2 | 罠の結果が1〜4人先 | 同じ意味に「すぐ先を見れば避けられる」を足した |
| 3 | 5〜7人先 | 同じ意味に「数台分先まで列を読む」を足した |
| 4 | 8人以上先 | 「8〜9人先」に狭めた |
| 5 | 深い罠が重なる。5人先まで読んでも半分も勝てない | 「10人以上先」に変えた |

Lv4・Lv5 を変えた理由:
- 罠を判断の単位で数えると、上のレベルの問題の多くは深い判断が1つだけだった。判断の回数（重さ5以上）の中央値は Lv3 1回・Lv4 1回・Lv5 2回で、重なりはレベルを分けない（§5）。
- 「5人先まで読んでも半分も勝てない」は Lv4 でも Lv5 でもほぼ同じに当てはまり、Lv5 だけの性質にならない（§13.1 の調査の段階の模擬で、4人先まで読む人の勝率の中央値が Lv3〜5 とも 0.25）。
- 合意の「深い罠が重なる」は、今の物差しでは問題の性質として現れない。最終レビューで人間に確かめる（§10）。

## 10. 人間の試遊で確かめること

- Lv1〜Lv5 の代表（§7）を順に遊び、難しさの順が体感と合うか。特に Lv3・Lv4・Lv5 の3段が分かれて感じるか（機械の模擬ではどの隣も 0.55 前後で弱い）。AI の試遊では、Lv3 の境界の問題（前の版の `2c7vi4r0ck`）が最も難しく、Lv5 の境界の問題（前の版の `7r5dm8g7fr`）は易しめに感じられた。
- 境界 3-4・4-5（§7）: 7人先と8人先、9人先と10人先の罠を、違う難しさに感じるか。
- 体感に近いのは人数（罠の結果が何人先に出るか）か、手数（何台先で詰むか）か。手数で数えると Lv2 と Lv3 が重なる（§5）。
- Lv2 を先回りして遊んだとき（列の先の色の車を早めに出す）、「すぐ先を見れば避けられる」の一言と合うか。先回りすると Lv2 の25%で深い罠に入りうる（§5）。
- 型（奥の同じ色の車を掘って使う、ふさいでいる車から出す）を覚えた後も、上位が考えさせるか。規則の最高勝率が上限の手前の問題（§7）で確かめる。
- 重い罠に2回以上出会う問題が、1回の問題より難しく感じるか（機械の模擬では差が出なかった）。
- スマホで20人前後の列を読み続けられるか。10人以上先を読めるか。

## 12. パズル仕様の難易度の節の案

- 挑戦: 乗客の列を先まで読み、いま出す車が何人先で待機枠をふさぐかを見抜いて、出す車と順番を決めること。
- 基準とするプレイ: 列と盤面が全部見え、負けの知らせは無い。罠に入らずに先を読んで解く人を基準にする。
- 難易度に含めないもの: 列の長さ・台数・手数（作業量）・盤面の広さ・掘る台数・戻して試し直す量。
- 挑戦を強めるもの: どう進めても避けて通れない罠の、結果が何人先に出るか。
- 提供範囲: 勝ち筋の選び方・罠の深さの取り方・遊び方（先回り）でレベルが食い違う問題、Lv3 以上で読み手の候補の外の勝つ手から進めると重い罠を避けられる問題、Lv3 以上で素朴な規則のどれかがどれかの同点の選び方で8割以上勝つ問題、Lv2 で素朴な規則の組がどれも勝率0の問題は提供しない。どう出しても必ず勝つ問題は出さない。

| G（3つ目） | どの勝ち筋でも出会う罠の局面の数 × 重さの段 | 同じ判断を、塞ぐ車を掘る局面ごとに数え直し、回数が掘る台数と待機枠で水増しされた。Lv2 の上限を勝ち筋の最小で決めていて、自然な進め方では深い罠に出会う問題が残った。Lv3（深さに上限なし）の罠が Lv4 より深かった |
| H 格子（試して退けた） | 判断の回数と深さの格子（Lv4 は「2回」か「1回で8人以上先」、Lv5 は「3回以上」か「2回以上でうち8人以上先」） | Lv5 が 28行しか無く、1手戻す人で 4-5 の順が 0.30〜0.54 と崩れた。判断が2回ある問題が、深い判断1回の問題より戻し回数が少なかった |
| **H 深さの段（採用）** | どう進めても出会う最も重い罠の段（§2） | 上位3段の間が弱い（§8） |

案H は、調査の段階で4回目の反例探しを、製品のコードで5回目の反例探しを受けて直した。

4回目の反例探し（案H、調査コード）の所見と扱い（報告）:
- 直した: Lv3 以上で、進め方を「勝つ手ならどれでもよい」に広げても同じレベルになることを条件に加えた（`freePathEscapes`）。上位の 12〜25% が、読み手の候補の外の勝ち手（先に別の車を掘る手）で始めると深い罠に一度も出会わずに解け、「どう進めても避けて通れない」という一言と合わなかった。
- 直した: 素朴な規則に `deepDig`（深く掘る）を足した。
- 直した: レベルの定義を重さの最小と最大の段で書き、判断の回数を記録だけにした（§2.8）。
- 人間に残す: Lv4 と Lv5 がほとんど分かれない。上位を分ける別の軸の候補「罠の手から詰みまでの最善の続きの上で、手が2つ以上ある局面の数」（Lv3〜5 をこの量で3群に分けると、上の群が多く戻す確率は 0.60〜0.78。レベルで分けると 0.54〜0.66）。最終レビューで上位が合わなかったときの作り直しの出発点にする。
- 直さない: Lv2 の 9% は手間が Lv3 並みだが、待機枠4で選べる手が多いための試行の量で、深い先読みは要らない。
- 反例が出なかった向き: 判断の区切り方、深い先読みが要る Lv1。

5回目の反例探し（判定モデル版1、製品のコードと問題集）の所見と扱い（報告）:
- 直した: 素朴な規則の上限を、同点を一様に選んだ勝率ではなく、規則ごと・同点の選び方ごとの勝率の最大で見るようにした。`deepDig` は、塞ぐ車を出し終えた後「掘っていた車」と「最初から出せた先頭の色の車」が同点になり、一様に選ぶと勝率0.5で止まっていた。同点を決まった選び方にすると、版1の問題集の Lv3 48%・Lv4 53%・Lv5 51% が勝率1で解けた。掘った車を使い切る規則 `deepCommit` も足した。
- 直した: 渋滞をほどく規則 `untangle` を足した。版1の問題集の Lv3 104・Lv4 127・Lv5 109問がこの規則で勝率0.8以上（すべて勝率1）だった。
- 直した: 同じレベルの近い盤面の検査に回転・反転を含めた（版1の問題集で、Lv4 の2問が左右反転で7台以上重なっていた）。
- 記録だけ足した: 罠の重さを手数で数えた量、4手先まで読む人の勝率、出せる車すべてを候補にした Lv2 の重さ（§5）。
- 直した結果は §5・§6・§8。上位3段がほとんど分かれないことは変わらない。

### 13.3 列だけで決まる罠

盤面に関係なく列と定員だけで決まる罠も、核の「乗客の列の先を読む」の一部として除かない（仮決定。案F までの計測で Lv2〜Lv5 の 12〜40% に含まれる。案H では測り直していない）。

### 13.4 4段階にする別案（人に残す）

上位を1つにまとめる形。調査の段階の計測（上の6,672行）で、Lv4 と Lv5 を1つにして「8人以上先の罠がある」を最上位にすると:
