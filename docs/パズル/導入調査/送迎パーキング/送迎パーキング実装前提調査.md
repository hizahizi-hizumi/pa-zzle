## 1. 根拠の書き分け

- **事実（リポジトリ）**: 今のリポジトリの文書・コード、別ブランチの資料、GitHub の Issue・PR で確かめたこと。
- **事実（計測）**: 上の調査コードで測った値。研究用 Python の実測で、製品コードの速さや人の手応えを表すものではない。
- **報告（保存していない計測）**: 調査役や確かめ役が一時のスクリプトで測り、コードと結果をリポジトリに置いていない値。流し直せない。スマホ操作の製品の枠の実測（値だけ `shuttle-parking_mobile.py` の定数に残した）、4回目・5回目の反例探し、F1 がこれにあたる。
- **事実（製品の計測）**: ゲームのコードで測った値。問題集の生成スクリプト（`generate:shuttle-parking-pool -- --stats`・`--verify`）の出力で、流し直せる。
- **導出**: 定義やルールから論理的に言えること。
- **推測**: 上から導いたが、人のプレイ・製品コード・測り直しで確かめていないこと。
- **AI判断（仮決定）**: 人間の判断を待たずに進めるため、合意と正本に沿って AI が決めたもの。§4 に理由・比べた案・覆したときに作り直す範囲を書く。
- **人間の判断**: 人間が決めたこと（§2）。AI は巻き戻さない。

§4 の数値は、断りの無いかぎり §3 の表と同じ出どころから引いた。ほかの文書の節は「難易度の資料 §n」のように文書名を添えて指し、番号だけの § はこの文書の節を指す。

難易度の検査の番号は `/design-game-difficulty` の `references/checks.md` のもの: A4 特徴の頑健さ（経緯を知らない役の反例探し）、B3 1か所ずつ読む重さ、C3 入口の広さ、E3 重複・自明・単調、F1 解法器の緩さ・深さ（定義の文だけから別に実装した確かめ）、F2 移植と打ち切り（製品のコードと移植の期待値の突き合わせ）。

人はまだこのパズルを遊んでいない。AI の試遊は判定モデル版1の問題集で1回した。難易度・採点・件数の判断は、読み手と遊び方の模擬による仮説である。

## 2. 認識合わせの合意と人間の判断

導入調査 Issue #988 の合意節を正とする。出どころは #727 の方式比較で、プロダクトオーナー（PO）が試作を遊び「いちばん面白い。パズルっぽい。先読みがある」と評価した。認識合わせのページへの人間の返事は「go」。要点:

- 既存のパーキングジャムとは別のゲームとして足す。パーキングジャムは変えない。
- ルール: 駐車場の車（縦か横、2人乗りか3人乗り。長さ＝定員）をタップすると、向きに沿って、出口の辺まで進路が空なら外へ出て待機枠に入る。最初から全部見える乗客の列の先頭から順に、同じ色の待機車へ1人ずつ乗る（同じ色が複数あれば先に入った車）。満席で出発して枠が空く。待機枠が埋まると次の車を出せない。出せる手が無くなると詰み。全員を送り出せばクリア。
- 考えること: 乗客の列の先を読み、どの車をいつ待機枠へ入れるかを計画する。
- 解は複数あってよい。推測は要らない。「この手は負け」の表示は出さない。「1手戻す」「最初から」を付ける。
- 称えたい解き方の仮説: 戻さずに先を読んで解くこと（合意では「採点の項目は調査で別案と比べて決める」。調査では方針までを比べ、採点項目・計測方法・配点は score で決める）。
- 難しさは盤面の広さで作らない。罠の深さ（間違った車を出してから詰みが確定するまでに乗客が何人進むか）と重なりで5段階にする。一言は Lv1「列の先頭に合う車を出していけば解ける」、Lv2「罠の結果が1〜4人先」、Lv3「5〜7人先」、Lv4「8人以上先」、Lv5「深い罠が重なる。5人先まで読んでも半分も勝てない」。
- 比較の試作は製品のコードとして引き継がず作り直す。難しさの測り方と問題の例は調査の材料に使う。

人間の判断（2026-11-22）: 「Lv4 と Lv5 の差が機械の計測では作れなかった。どう進めるか」に対し、「5段階のまま作る」が選ばれた。退けた選択肢は「要素を足して上位を作る」「このゲームだけ4段階」。Lv4・Lv5 は D-05 のとおりに置いて作り切り、最終レビューで実際に遊んで確かめる。合わなければ上位2段階の難易度と問題集を作り直す。

合意から変えることは2つある。

- レベルの分け方と一言（D-05）。Lv4 は「8人以上先」から「8〜9人先」に、Lv5 は「深い罠が重なる」から「10人以上先」に分け方が変わる。罠を判断の単位で数え直すと、上位の問題の多くは深い判断が1つだけで、判断の回数（重なり）はどの模擬でもレベルの順に並ばなかったため（難易度の資料 §4）。Lv1〜Lv3 は合意の帯のままで、Lv2・Lv3 は一言に文を言い足した。今の一言は難易度の資料 §4 の表にある。
- 採点の仮説の読み替え（§4.2）: 「戻さずに」を「罠に入らずに」と読む。

この文書の用語:

- **出口の辺**: 駐車場の4辺のうち、車が外へ出られる辺。問題ごとに1辺か、隣り合う2辺。調査コードと難易度の資料の「開口」と同じもの。
- **出庫**: 車をタップして駐車場から出し、待機枠に入れる1手。本文の「車を出す」も同じ意味。
- **1手戻す**（画面の名前）は GAME-005 の「待った」、**最初から**（画面の名前）は GAME-005 の「盤面を戻す」にあたる。どちらも同じプレイの続きで、「リセット」（新しいプレイ）とは別のもの。以下、画面の名前で書く。
- **罠**: 勝てる状態から、選ぶと負ける状態へ移る出庫（どう続けても全員を送り出せなくなる出庫）。難易度では、先頭に合わせて遊ぶ人の候補の中の罠を数える。
- **罠の結果が n 人先に出る**: 難易度の資料の「罠の重さ」（深さ + 1。負けが見えるのに要る人数）が n であること。レベルは、どう進めても出会う最も重い罠の重さの段で決まる。**判断**（勝ち筋の上で同じ車が罠のまま続く局面の並び）の回数は記録だけで、レベルに使わない。定義の細部は難易度の資料 §2。

### 4.2 採点の前提

D-15 の理由と比べた案。

- 採った方針: 主に「列の先を読み切り、罠の出庫を選ばずに全員を送り出すこと」、従に「その読みを速く行うこと」を称える。推測の要らない問題なので、罠に入る1回はどれも運ではなく読みの失敗と言え、プレイの事実から厳密に決まる（§3）。罠1回を数え、その後の続きや戻した手数は追加で数えないのは、原因が何手か前にあり、詰んでから原因を探す試行錯誤を自然な遊び方として残すため（詰将棋の誤王手・マインスイーパーの地雷・一筆パズルの試し引きと同じ考え方で、このゲームの構造から説明できる）。
- 認識合わせの仮説「戻さずに先を読んで解く」との関係: 称えたいもの（先読み）は同じ。文字どおり「1手戻す・最初からを使わない」と読むと、押し間違いの取り消しや、詰む前に自分で誤りに気づいて戻すことまで同じに扱い、深い罠ほど同じ1回の失敗が重く出る。「戻さずに」を「罠に入らずに」と読み替えて採った。
- 退けた案:
  - 1手戻す・最初からの回数を数える: 上の理由。推測: 1手戻すには押し間違い・詰んでからの原因探し・詰む前の気づき・試し出しの4つの意味があり、回数では分けられない。
  - 戻した出庫の数を数える（氷の床迷路型）: 事実（計測、`shuttle-parking_scoring.py`、試作15問の勝ち筋上の罠 1,944件）: 出した直後に詰む罠の割合は、結果が1〜4人先の罠で3%、5人以上先の罠で0%。詰むまでに出せる出庫の数は、1〜4人先の罠で中央値1、5〜7人先・8人以上先の罠で一様に進めた平均 2.0・1.95。推測: 深い罠ほど戻す出庫が増え、深い罠は上位に多いので、同じ失敗でも上位ほど点が下がる偏りになる。
  - 少ない手数（効率）: クリアの出庫数はルールで台数に固定され、差は戻した出庫としてしか現れない。
  - 出られないタップを主にする: パーキングジャムと同じ上手さになり、このゲームの挑戦（先読み）を表さない。副次の事実として扱いを score で決める。
  - 速さだけ（ブリッジパズル・リフレクション型）: 試して戻す遊び方と読み切る遊び方が時間でしか分かれず、PO が評価した先読みが点に表れにくい。
  - 詰みに達した回数を数える（次点）: 判定器が要らない利点があるが、詰む前に戻すと数えられず、読みの失敗を取り逃がす。

### 4.3 反例探しの所見の振り分け

4回目（調査の段階の案H）と5回目（判定モデル版1の製品のコードと問題集）に、経緯を知らない役の反例探し（A4）を当てた所見。数値は報告（保存していない計測）。直した結果の分布と供給は難易度の資料 §5・§6・§8。

4回目:
- 直した: Lv3 以上では、進め方を「勝つ手ならどれでもよい」に広げても同じレベルになることを条件に加えた。上位の 12〜25%（Lv3 18%、Lv4 12%、Lv5 25%）は、読み手の候補の外の勝ち手（先に別の車を掘る手）で始めると深い罠に一度も出会わずに解け、「どう進めても避けて通れない」という一言と合わなかった。
- 直した: 素朴な規則に「先頭の色の車のうち、掘る台数が空いている待機枠に収まる中で最も深い車を掘る」（`deepDig`）を足した。
- 直した: レベルの定義を「勝ち筋の上の罠の最大の重さの、勝ち筋の中での最小と最大の段」と書き、判断の区切りは記録だけの回数に移した。
- 人間に残す（D-05）: 上位のレベルがほとんど分かれない。反例探しの役が自分で解いた感触も「Lv1 < Lv2 < 上位（Lv3〜5 は入り混じる）」。
- 人間に残す・別案として記録: 上位を分ける別の軸の候補「罠の手から詰みまでの最善の続きの上で、手が2つ以上ある局面の数」。Lv3〜5 をこの量で3群に分けると、上の群が多く戻す確率は 0.60〜0.78（レベルで分けると 0.54〜0.66）。最終レビューで上位が合わなかったときの作り直しの出発点にする。
- AI が決める: Lv2 の 9% は手間が Lv3 並みだが、待機枠4で選べる手が多いための試行の量で、深い先読みは要らない。直さない。
- 反例が出なかった向き: 判断の区切り方、深い先読みが要る Lv1。

5回目:
- 直した: 素朴な規則の上限を、同点を一様に選んだ勝率ではなく、規則ごと・同点の選び方ごとの勝率の最大で見る。`deepDig` は同点を一様に選ぶと勝率0.5で止まり、同点を決まった選び方にすると版1の問題集の Lv3 48%・Lv4 53%・Lv5 51% が勝率1で解けた。掘った車を使い切る規則（`deepCommit`）を足した。
- 直した: 渋滞をほどく規則（`untangle`。出せる車すべてから、ふさいでいる車の多い車を出す）を足した。版1の問題集の Lv3 104・Lv4 127・Lv5 109問がこの規則で勝率0.8以上だった。
- 直した: 同じレベルの近い盤面の検査に回転・反転を含めた。
- 記録だけ足した: 罠の重さを手数で数えた量、4手先まで読む人の勝率、出せる車すべてを候補にした Lv2 の重さ。判定は変えない。
- 生成条件の端（扱いは決めていない。§7）: 上位に待機枠2の問題が多い（版2の問題集で Lv3 127問、Lv5 85問。母集団より多い）。定員がそろった盤からは Lv4・Lv5 が出ない（4回目の報告、0/265）。

## 7. 確かめていないこと

難易度

- 人の体感でレベルの順になるか。人は遊んでいない（AI の試遊は版1の問題集で1回）。特に Lv3・Lv4・Lv5 の3段は機械の模擬でほとんど分かれない（難易度の資料 §8）。最終レビューで遊んで確かめる（§2 の人間の判断）。試遊の問いと問題は難易度の資料 §7・§10。
- 合意から変えた一言（§2）を人が受け入れるか。体感に近いのが罠の人数か手数か（難易度の資料 §5）。
- 判断の数え方の F1（定義の文だけからの別実装との突き合わせ）は、案G の定義までしか確かめていない。判定モデル版2の規則と同点の選び方は、5回目の反例探しで使った別実装の範囲でしか確かめていない。
- 生成条件の端（§4.3）: 待機枠2の問題が上位に偏ること、定員がそろった盤から上位が出ないことの扱い。
- 定員・出口の辺・台数の比較は案E の分類で測ったまま。列だけで決まる罠の割合を案H で数えていない。

問題供給と図鑑

- 図鑑の特徴の分布と難易度との相関は、案F の分類で測ったまま。判定モデル版2の問題集の待機枠の分布は、難易度の資料 §5（2枠は Lv1 で1問、Lv3 で127問）。図鑑の待機枠の選択肢が成り立つかは zukan で確かめる。
- 件数の根拠にした、人が1つのレベルで遊ぶ数。人のプレイ記録が無い。

採点・音・スマホ

- 採点の計測は試作の8台15問だけ。人が実際にどれだけ押し間違い・試し出し・罠への進入をするか、クリア後に罠に入った回数を見せて納得されるか。
- 音の計測の入力（試作の23問）は `調査コード/shuttle-parking_sound.input.json` に置いたが、`shuttle-parking_sound.py` がこの入力を既定で読むようにする変更はしていない（流し直すときは引数にこのパスを渡す）。音のピーク・ラウドネス（FLAC を標準ライブラリで復号できない）と聞いた印象も未確認。
- 実機の Safari での高さ（ツールバーの出入り）、待機枠の中の車と座席が幅54px（320px・4枠）に収まるか、24px の札で3〜4色を色だけで見分けられるか、20人前後の列を読み続ける負担、乗った人を列から消すか薄く残すか（D-11）。

名前と番号

- 「送迎パーキング」と代案の登録商標、ストアの同名作品、送迎付き駐車場の呼び名との重なり（D-18。人が確かめる）。
- PZL-015 と PUZZLE-095 は、この環境で取得済みのブランチとオープンな Issue でだけ確かめた。取得していない変更があれば、予約の前に確かめ直す。
- #985 と #987 が同じ PZL-013 を予約している重なりは、このパズルの外の問題として残る。
