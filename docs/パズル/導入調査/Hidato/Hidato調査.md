# Hidatoの基礎仕様と自動生成の成立性調査

Issue #44 の調査結果。Hidatoを将来の実装候補として判断するため、基礎仕様、完成経路生成、一意解確認、解法探索、人間向け難易度制御の成立性を整理する。

## 結論

**技術的には採用候補として次段階へ進めてよい。ただし、7×7以上を同期生成する前提で素朴なバックトラッキングをそのまま採用するのはNO-GO。**

Hidatoは、盤面の全セルを1〜Nで一度ずつ使い、連続する数が縦・横・斜めで隣接する1本の経路を作るパズルである。正方形盤なら完成解は「キング移動グラフ上のハミルトン路」とみなせる。完成経路を先に生成し、数字をヒントとして残しながら他を隠し、各削除後に解数を最大2件まで探索すれば、一意解問題を機械的に生成できる。

今回の依存なしPython実験でも、完成経路からヒントを貪欲に削り、一意性を都度確認する方式で5×5・6×6の一意解問題を生成できた。一方、単純な逐次バックトラッキングは問題による振れが大きく、7×7では数秒級になり、探索上限へ達するケースも出た。一般化Hidatoの可解性判定がNP完全であることとも整合する。

判断は次のとおり。

- 完成経路の自動生成: GO
- 一意解問題の自動生成: GO
- 一意解確認: GO。ただし盤面が大きくなるほど制約伝播・変数選択などの探索最適化が必要
- 5×5〜6×6程度の小盤面: 素朴な実装でも実用域へ入り得る
- 7×7以上を毎回クライアントで同期生成: 素朴実装ではNO-GO
- 7×7以上: 最適化した制約充足問題ソルバー、生成時の計算量上限、事前生成・キャッシュ等を含めれば実現可能性がある
- 人間向け難易度制御: 後続検証へ進める。ヒント数だけではなく、人間向け解法手順を評価する
- 問題多様性: 致命的な不足はない。ただし完成経路の生成法が単調だと似た問題へ偏る

また、**Hidatoは登録商標として扱われているため、製品上の名称判断は技術成立性と分離する。** 公開時の名称は別途確認する。

## 1. 基礎仕様

### 1.1 盤面と数字

盤面にはN個の有効セルがある。

- 使用する数字は1〜N
- 各数字は厳密に1回だけ現れる
- すべての有効セルを埋める
- 連続する `k` と `k + 1` は隣接しなければならない

クラシックな正方形セルでは、縦・横・斜めの8方向を隣接とする。

公式サイトの説明でも、連続する数字を horizontally / vertically / diagonally に接続するとされている。

### 1.2 盤面形状

Hidatoは正方形盤に限定されず、長方形、不規則な外形、穴を含む盤面、六角形セル等が存在する。

pa-zzleで最初に実装する場合は、**正方形セルの長方形盤・全セル有効**から始めるのがよい。

理由:

- 隣接判定が固定の8近傍になる
- 完成経路生成と一意解探索の性能検証を盤面形状から分離できる
- UIのセル配置を単純化できる
- 後から「有効セル集合 + 隣接グラフ」へ一般化できる

不規則形・穴あり盤面も、有効セルを頂点、隣接関係を辺とするグラフに変換すれば同じ解法器へ載せられる。ただし、すべての形状が全セルを通るハミルトン路を持つとは限らないため、形状生成側で完成経路の存在確認が必要になる。

### 1.3 初期ヒント

開始時から固定されている数字を初期ヒントとする。

- プレイヤーは変更できない
- 1とNは初期ヒントとして固定する
- その他の数字を一部固定する
- 初期ヒント同士は完成経路と整合していなければならない
- 提供する問題では完成解を厳密に1つにする

公式Hidato資料でも、最小値と最大値が示され、各問題は一意解かつ論理で解けることが前提とされている。

### 1.4 クリア条件

次をすべて満たした時点をクリアとする。

1. N個の有効セルがすべて埋まっている
2. 1〜Nがそれぞれ1回ずつ存在する
3. すべての `k` について `k` と `k + 1` が隣接する
4. 初期ヒントの値が変更されていない

提供問題を一意解に限定するため、この条件を満たす完成盤は保存済み完成解と一致する。

## 2. HidatoとNumbrixの違い

最も重要な差は隣接規則である。

| 項目 | Hidato | Numbrix |
|---|---|---|
| 連番の隣接 | 縦・横・斜め | 縦・横のみ |
| 1セルの最大隣接数（正方形内部） | 8 | 4 |
| 代表盤面 | 正方形、不規則形、六角形等 | 主に正方形 |
| 完成解 | キング移動のハミルトン路 | 格子グラフ上のハミルトン路 |
| 初期ヒント | 途中の数字を固定 | 同様 |

PARADEのNumbrix説明では、連続数字は horizontal / vertical path を取り、diagonal は使わないと明記されている。

この差により、Hidatoの方が各セルの分岐数が大きい。完成経路の候補は作りやすい一方、ヒントを減らしたときの別解も生まれやすく、一意解確認が重要になる。

### 2.1 名称の扱い

「Hidato」は登録商標として掲載されている。米国では `HIDATO`、Registration Number 3623342 がゲームソフト・印刷物・オンラインゲーム等について登録・更新済みとされている。

したがって、pa-zzle内部の技術調査名として `hidato` を使うことと、製品上のゲーム名称を「Hidato」として公開することは分けて判断する。

本Issueでは法的判断までは行わない。公開名称は実装着手時または公開前に確認する。

## 3. 問題として成立する条件

### 3.1 完成経路

正方形セルの盤面を次のグラフとして見る。

```text
頂点 = 有効セル
辺   = 縦・横・斜めで隣接するセル対
```

完成解は、このグラフの全頂点をちょうど1回ずつ通るハミルトン路である。セルを経路順に `1, 2, ..., N` と番号付けすれば完成盤になる。

### 3.2 解の存在

問題の初期ヒントを `value -> cell` の制約として完成経路へ追加する。

完成経路からヒントを隠す生成方式なら、元の完成経路が必ず1解として残るため、**可解性そのものは構成的に保証できる**。

### 3.3 一意解

完成経路から数字を隠しただけでは一意解は保証されない。

一意性は問題ごとに、解を最大2件まで探索して確認する。

```text
0解      -> 生成・データ不整合
1解      -> 一意解
2解以上  -> 不採用
```

3解目以降を数える必要はない。

### 3.4 論理だけで解けること

一意解と、人間が当てずっぽうなしに解けることは別条件である。

公式Hidatoは一意解に加え、pure logic / no guesswork を掲げている。pa-zzleで同等の品質を狙うなら、機械探索で一意性を保証した後、別の**人間向け解法器**で解法手順を再現する必要がある。

## 4. 問題生成

### 4.1 採用候補の生成パイプライン

```text
seed
  ↓
盤面形状を決定
  ↓
全セルを通る完成経路を生成
  ↓
1〜Nを経路順に割り当て
  ↓
1とNを残して他ヒントを削除候補にする
  ↓
ヒントを1つ削除
  ↓
解数を最大2件まで探索
  ├─ 1解: 削除を採用
  └─ 2解以上: 元に戻す
  ↓
人間向け解法器で難易度・解き味を評価
  ↓
採否判定
```

### 4.2 完成経路生成

長方形・全セル有効盤なら、単純な蛇行経路でも完成経路を構成できる。

ただし毎回同じ蛇行経路を回転・反転するだけでは多様性が低いため、実用上は次を候補とする。

- ランダム化深さ優先探索
- 未訪問近傍の自由度が少ないセルを優先するヒューリスティック
- 制約充足問題として完成経路自体を生成
- 複数の経路生成戦略を混ぜる

今回の実験では、未訪問近傍数が少ない候補を優先するランダム化深さ優先探索で4×4〜9×9の完成経路自体は容易に得られた。

### 4.3 ヒント削除

最初は全数字をヒントとみなし、1とN以外をランダム順に削除する。各削除後に一意解確認を行う。

ある時点でヒントを削除して複数解になった場合、その後さらに別ヒントを削除しても一意性が復活することはない。そのため1回の削除順を最後まで走査すれば、その削除順に対して「これ以上1ヒントずつ削れない」状態へ到達できる。

ただし、ヒント数最小の問題になるとは限らない。完成経路とヒント配置の選択で最終ヒント数と解き味は変わる。

## 5. 解法探索と一意解確認

### 5.1 素朴な探索

1から順に次の数字の位置を深さ優先探索する方法でも解ける。

枝刈り候補:

- 既使用セルを除外
- 将来の固定ヒントセルを誤った数字で使用しない
- 次の固定ヒントまで残り手数で到達できない候補を除外
- 塞がれて後続経路を作れないセルを除外
- 2解を見つけた時点で打ち切る

### 5.2 制約充足問題としての定式化

より自然な定式化は「数字を変数、配置セルを値」とする方法である。

```text
変数: position[1], ..., position[N]
値域: 有効セル
制約:
- positionはすべて異なる
- 初期ヒントは指定セルに固定
- position[k] と position[k+1] は隣接
```

OR-ToolsのHidato例でもこの形を採り、`AllDifferent` と連続数字の隣接許容組を制約としてCP-SATへ渡している。

候補:

- 制約伝播付きバックトラッキング
- CP-SAT
- SAT / SMT
- 汎用制約充足問題ソルバー

### 5.3 理論計算量

一般化Hidatoの「解が存在するか」はNP完全であることが示されている。

したがって「完成形から数字を隠せば常に軽い」とは扱わない。一方、サービスで扱う盤面サイズは固定された小〜中規模であり、生成候補の棄却・事前生成・キャッシュも可能なので、NP完全性だけで採用不可とはならない。

## 6. 最小実験

### 6.1 方法

文献だけでは素朴な生成・一意解確認をどのサイズまで現実的に行えるか分からないため、依存ライブラリなしの小さな実験を行った。実験コードは成立性確認用であり、リポジトリへは追加しない。

環境:

- Python 3.13.5
- Linux x86_64
- 5 CPUが見える実行環境
- 単一プロセス

完成経路生成:

- 正方形・全セル有効
- 8近傍
- ランダム化深さ優先探索
- 未訪問近傍数が少ない候補を優先

一意解探索:

- 1からNへ逐次探索
- 既使用セル除外
- 固定ヒント保護
- 次の固定ヒントまでのチェビシェフ距離による枝刈り
- 局所的な行き止まり枝刈り
- 2解で打ち切り

ヒント削除:

- 1とNを保持
- その他をseedでシャッフル
- 1つずつ削除して一意解確認
- 複数解になれば元へ戻す

### 6.2 ランダムなヒント抽出

4×4〜6×6で、完成経路からヒントを単純にランダム抽出して25〜45%残す試行を各条件3件行った。今回の範囲では一意解になったものは0件だった。

サンプル数は小さいため一意解率を推定する実験ではないが、「一定割合の数字をランダムに見せるだけ」で生成する方針は採らない。

**ヒント数より、どの位置・どの番号を残すかが重要**である。

### 6.3 貪欲なヒント削除

複数seedで完成経路を生成し、一意性を保つ限りヒントを削除した。

| 盤面 | 試行数 | 最終ヒント数 中央 | 最小〜最大 | 総生成時間 中央 | 最大 | 探索上限到達 |
|---|---:|---:|---:|---:|---:|---:|
| 5×5 | 10 | 8 | 7〜9 | 約38ms | 約208ms | 0/10 |
| 6×6 | 10 | 11.5 | 10〜14 | 約324ms | 約1.41s | 1/10 |
| 7×7 | 6 | 16 | 14〜24 | 約5.12s | 約9.58s | 4/6 |

探索上限は実験用に1回の一意性確認あたり10万〜15万ノード程度に設定した。上限に達した削除候補は安全側に倒して「削除しない」としたため、問題の一意性自体は維持されるが、ヒント削減は保守的になる。

別の単発試行では、8×8で18ヒントまで削るのに約5.65秒、9×9で28ヒントまでの処理に約22.2秒かかった。9×9では複数回探索上限へ到達した。

### 6.4 解釈

これは性能競争用の実装ではないため、絶対時間を本番見積もりには使わない。

それでも次は判断できる。

- 完成経路を作る部分は難所ではない
- 一意解問題を構成する方法は成立する
- 小盤面では素朴な一意解確認でも現実的
- 盤面サイズが上がると一意解確認の問題依存の振れが急に大きくなる
- 生成時に何十回も一意性確認するため、1回の探索の外れ値が総生成時間を支配する
- 7×7以上を「いつでも同期的に数msで生成できる」とは言えない

後続実装では、**一意解確認の性能を独立した品質条件として計測する**。

## 7. サービスとしての生成戦略

7×7以上で探索時間が不安定でも、サービスとして直ちに問題にはならない。

### 7.1 時間上限付き生成

各候補に探索ノード数または時間上限を設定する。

```text
候補生成
  ↓
一意性確認
  ├─ 予算内で1解 -> 続行
  ├─ 2解以上     -> ヒントを戻す
  └─ 予算超過    -> ヒントを戻す / 候補全体を棄却
```

「難しい問題」と「ソルバーにとって時間がかかる問題」を同一視せず、生成器の運用予算として扱う。

### 7.2 事前生成・キャッシュ

リアルタイム生成が必須でなければ、問題を事前生成し、一意性と難易度を検証したうえで保存できる。難易度別に検証済み問題を確保すれば、プレイ開始時の生成待ち時間も切り離せる。

Hidatoはseedから再現可能なため、保存対象は問題表現だけでなくseed + 生成方式バージョンでもよい。

### 7.3 ソルバー最適化

専用探索器を使うなら、少なくとも次を候補とする。

- 数字ごとの候補セル集合
- 候補数最少の変数から探索
- 前後の確定数字から到達距離を伝播
- 使用済みセルによる連結性・行き止まり検出
- clue間の区間ごとの経路候補削減
- ビット集合による候補・隣接表現

性能根拠が出る前に独自最適化へ寄せすぎず、CP-SAT等との比較を先に行う。

## 8. 多様性・対称性・同型

### 8.1 多様性

完成経路の組合せ自体は非常に多い。

Gyora Benedekの9×9 Classic Hidatoに関する数え上げでは、9×9完成グリッドの下界がナンプレ完成盤数より数百倍以上大きいとされている。厳密な全列挙値ではなく下界だが、サービスで問題数が枯渇することを心配する規模ではない。

実務上の問題は組合せ総数ではなく、**生成器がその空間のごく狭い部分しか使わないこと**である。

### 8.2 単調な問題を避ける

次だけで問題を増やす方式は避ける。

- 同じ蛇行路の回転
- 反転
- 1〜Nの向き反転
- 同じ経路でヒントだけ少し変更

完成経路そのものを複数戦略・複数seedで生成する。

### 8.3 同型

長方形盤なら少なくとも次を同型変換候補として扱える。

- 回転
- 鏡映
- 経路の向き反転（`k -> N + 1 - k`）

完全一致重複は容易に除外できる。同型正規化は必要になってから導入する。

ヒント配置の対称性はルール上要求されない。見た目上の美しさとして採用することは可能だが、一意性・人間難易度を悪化させるなら優先しない。

## 9. 人間向け難易度と良問判定

### 9.1 ヒント数だけでは評価しない

同じヒント数でも、ヒント間の距離・位置・盤面境界・経路の分岐によって難しさが変わる。

したがって、ヒント数は生成メタデータには使えても難易度の正本にはしない。

### 9.2 人間向け推論候補

既存の解法資料から、少なくとも次を人間向け解法器へ段階的に実装できる。

- ある数字に置けるセルが1つだけ
- あるセルに入れる数字が1つだけ
- 2つの固定数字の間に取り得る経路が1つだけ
- 固定数字間の距離から候補を除外
- 盤面端・角による隣接候補の減少
- ある経路を選ぶと未使用セルが孤立するため除外
- 前向き・後ろ向きの両方向から連番を確定
- Naked Pair / Hidden Pair 相当の候補集合推論
- より長い連鎖・経路制約

PZLの実装例では、Exclusion、Prune on Distance、Prune on Path、Hidden Single、Naked/Hidden Pairs・Triples等を段階的ヒントとして扱っている。

### 9.3 難易度評価材料

後続検証では次を記録する。

- 使用した推論規則の種類
- 最も高度な推論規則
- 各規則の使用回数
- 1ステップで除外した候補数
- 確定までに必要な推論連鎖長
- clue間の最大ギャップ
- clue間の経路候補数
- 強制手がない局面の有無
- 人間向け解法器が途中停止したか

機械解法探索器のノード数・実行時間は生成器運用には有用だが、人間の体感難易度の正本にはしない。

### 9.4 良問判定

一意解かつ論理解可能でも、次は棄却候補にする。

- ほぼ全手が自明で作業だけ長い
- 序盤に入口がなく、長い仮定を強いる
- 1箇所だけ極端に難しく他が単調
- 同じ局所形状・推論を繰り返すだけ
- 直近に提供した問題と完成経路・ヒント配置が酷似

公開Hidatoサイトでも、機械生成は似た問題になりやすく、clue placementが解き味を左右すると指摘されている。これは自動生成不可の根拠ではなく、**候補生成後の品質評価が主戦場になる**ことを示す。

## 10. ヒント・Undo・ミス判定との境界

| 項目 | 位置付け | 備考 |
|---|---|---|
| 1〜Nを1回ずつ使う | 基本ルール | 完成盤制約 |
| 連番の8近傍隣接 | 基本ルール | 正方形セル版 |
| 初期ヒント固定 | 基本ルール | プレイヤー変更不可 |
| 一意解 | 提供問題の品質条件 | 生成時に保証 |
| 論理解可能 | 提供問題の品質条件 | 人間向け解法器で確認 |
| 数字入力・消去 | 基本プレイ操作 | UI契約は別途 |
| クリア判定 | 基本ルール | 全セル・全連番を検証 |
| ミス数 | 成績計測 | 完成解との不一致イベントとして扱える |
| 誤答の即時表示 | 補助機能 | ミス記録と分離 |
| Undo / Redo | プレイ履歴 | ルール外 |
| やり直し | プレイ管理 | ルール外 |
| ヒント | 補助機能 | 人間向け解法器の次手を利用可能 |
| 難易度 | 問題メタデータ | 人間向け推論から評価 |

入力をルール上禁止するか、間違いとして受理するかはプレイ体験の設計であり、自動生成成立性とは分離する。

## 11. 実装時の責務分割候補

```text
盤面・問題表現
  ├─ 有効セル
  ├─ 隣接グラフ
  ├─ 初期ヒント
  └─ 完成解

完成経路生成器
  └─ seed -> ハミルトン路

機械解法探索器
  ├─ 解探索
  └─ 0 / 1 / 2解以上の判定

問題生成器
  ├─ 完成経路生成
  ├─ ヒント削除
  ├─ 一意性確認
  └─ 生成予算管理

人間向け解法器
  ├─ 候補伝播
  ├─ 人間向け推論
  ├─ 解法手順記録
  └─ 難易度評価材料

プレイ状態
  ├─ プレイヤー入力
  ├─ ミス
  ├─ ヒント使用
  └─ Undo等の履歴
```

**機械解法探索器と人間向け解法器は統合しない。** 前者は完全性と速度、後者は人間の思考過程を説明可能に再現することが目的である。

## 12. 後続検証で確認すること

採用候補として実装へ進む前に、次の技術検証を行えば十分である。

1. 5×5 / 6×6 / 7×7 / 8×8程度で、専用探索器とCP-SAT等を比較する
2. 一意解確認1回の中央値・95%点・99%点・最大を測る
3. 問題1件完成までの一意解確認回数と総時間を測る
4. seedごとの外れ値率を測る
5. 時間上限で候補を棄却した場合の最終生成成功率を測る
6. 基本人間推論だけで解ける問題の採用率を測る
7. 難易度帯ごとの候補採用率を測る
8. 完成経路・ヒント配置の重複度を確認する

ここで7×7以上の同期生成が重ければ、事前生成へ寄せればよい。リアルタイム生成を採用条件にはしない。

## 13. 判断

| 調査項目 | 判断 | 根拠 |
|---|---|---|
| 基本ルール | GO | 1〜N・8近傍連番として明確 |
| 長方形盤の完成経路生成 | GO | 構成可能、ランダム化探索でも生成できた |
| 不規則形への拡張 | 条件付きGO | グラフ一般化可能だが形状ごとに経路存在確認が必要 |
| 解の存在保証 | GO | 完成経路からヒントを隠す方式で構成的に保証 |
| 一意解確認 | GO | 2解打ち切り探索で判定可能 |
| 一意解問題の自動生成 | GO | ヒント削除 + 一意性再確認で実験成立 |
| 5×5〜6×6の素朴生成 | GO | 実験では概ねms〜1秒台 |
| 7×7以上の素朴同期生成 | NO-GO | 数秒・探索上限到達が発生 |
| 7×7以上の最適化/事前生成 | PoCへ進む | CSP/CP-SAT定式化が明確で、生成予算・事前生成で吸収可能 |
| 問題多様性 | GO | 完成経路空間は十分大きい |
| 同型除去 | 後回し | 完全一致 + 基本対称だけから開始可能 |
| ヒント数だけの難易度 | NO-GO | 配置・経路候補・推論内容の影響が大きい |
| 人間向け難易度制御 | PoCへ進む | 既存の候補除外・経路推論を段階化可能 |
| 良問自動選別 | 要後続検証 | 技術的生成より品質評価が難所 |
| 「Hidato」名称の製品利用 | 技術判断外 | 登録商標の確認が必要 |

**#44として、技術的な致命傷は見つからなかった。Hidato系の連続数字経路パズルは採用候補として次段階へ進めてよい。**

ただし、実装時の最初の性能検証対象は「完成経路生成」ではなく**一意解確認**にする。今回の素朴探索では7×7付近から外れ値が顕著になったため、ここを計測せずに盤面サイズ・同期生成方式を固定しない。
