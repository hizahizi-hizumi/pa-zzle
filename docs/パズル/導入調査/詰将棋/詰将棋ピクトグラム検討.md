# 詰将棋ピクトグラム検討

詰将棋のゲーム選択ピクトグラムをどう検討したかの記録。どの着眼点を探索し、どの候補を比べ、なぜ P1（盤の右上隅の詰め上がり）を推奨するかをまとめる。見直すときに、同じ比較をやり直さずに論点から始められるようにする。

この文書は導入調査の資料であり、現在仕様の正本ではない。採用したピクトグラムの形は `frontend/src/games/tsume-shogi/assets/pictogram.svg` を正とする。制作手順と評価方法は `.claude/skills/design-game-pictogram/`（`SKILL.md`、`references/method.md`）を正とする。

記述は次のように区別する。

- **事実（リポジトリ）**: 現在のコード・文書から確かめたこと。
- **事実（実測）**: 候補 SVG を実表示サイズで描画して比べたときに見えたこと。見え方の記述は、比較画像を AI が見て書いたもの。候補 SVG は代表案だけをリポジトリに残している（§6）。
- **判断**: 上から導いた推奨と理由。

人間による方向の選択はまだ行っていない。Skill は方向を人間に選ばせる手順だが、本実装では人間のレビューを全段の実装後に1回だけ行うので、AI が推奨案で仮に決めた（[詰将棋実装前提調査](詰将棋実装前提調査.md) §11 段09）。最終レビューで選び替えられるように、代替の候補も同じ品質まで仕上げている（§5.2、§6）。

---

## 1. 結論

- 推奨案は **P1（盤の右上隅の詰め上がり）**。濃色の太い線で盤の上辺と右辺だけを描き（盤の右上隅）、淡色の細い線で隅を 2×2 の升に区切る。隅の升に玉方の玉（濃色の輪郭の五角形を 180° 回し、中に「王」の線）、その真下に攻方の駒（濃色の塗りの五角形）、左隣に攻方のもう1枚（淡色の塗りの五角形）を置く。
  - 「隅に追い込まれた玉の頭に駒を打って詰める」詰め上がりの形（頭金）を、駒の向き・塗り・升で示す。
  - 詰将棋の図面は盤の右上の一部だけを切り取って示すのが慣例で、上辺と右辺だけの枠はその見え方に合わせた。
  - 玉方の駒を 180° 回して見分けるのはプレイ画面の描き方（`TsumeShogiPieceGlyph`）と同じ。攻方の駒を塗り、玉方の駒を輪郭にするのは、棋譜の ☗（先手・攻方）☖（後手・玉方）の慣例に合わせた。
- 推奨の理由は次の3つ（§4.2）。
  - 五角形の駒・升・玉の向きという、将棋でしか見ない形を使い、「攻方が玉を詰める」詰将棋の結末を1枚で示す。
  - 一覧の 46〜56px でも、輪郭の玉・塗りの駒・淡色の駒の3つが見分けられる。
  - 一覧で唯一「五角形」と「上辺と右辺だけの枠」を持ち、ほかの7つと見分けやすい。
- 見直すときの主な論点は次の4つ（§5.1）。有力な代替は P2・P3・P4（§5.2）。
  - 盤を描くか、駒だけで描くか。
  - 詰め上がり（結末）を描くか、王手の候補の比較（考える過程）を描くか。
  - 玉の文字を描くか（「玉」か「王」か）。
  - 枠を隅だけにするか、四方を閉じるか。

## 2. 目的と制約

### 2.1 目的

ゲーム一覧で詰将棋を素早く見分けられ、ゲーム自身の姿を保ち、既存のピクトグラムと並べても強さが突出しないこと（`DESIGN.md`「ゲームピクトグラム」、`references/method.md` §1）。

### 2.2 制約（事実（リポジトリ））

- 共通描画契約（`SKILL.md`）
  - `viewBox="0 0 120 120"`。
  - 線幅は 4 と 2 だけ。
  - 色は `var(--game-pictogram-strong)` と `var(--game-pictogram-soft)` の2色だけ。
  - `check_svg.py --max-colors 2 --forbid-gradients --forbid-filters --forbid-external-images --forbid-text` を通す。
- 色は `GamePictogram` が与える。ライトとダークでは前景色と補助情報色、結果画面では `currentColor` になる。どのテーマでも読める形にする。プレイ画面の木の盤・駒の色と、成駒の赤い文字（`ui/tsume-shogi-tone.ts`）は2色の規格では使えない。
- `<text>` は使えないので、駒の文字は線（path）で描く。既存アプリや第三者の駒画像・ロゴは使わない。
- 実表示サイズ: ゲーム選択のヒーロー 177px（1280px 幅）/ 138px（390px 幅）、一覧のカード 56px（1280px 幅）/ 46px（390px 幅）、結果画面 48px（[リフレクションピクトグラム検討](../リフレクション/リフレクションピクトグラム検討.md) §2.2 の実測値を使った）。一覧の 46〜56px が最も厳しい。
- 比べる既存ピクトグラム: ウォーターソート、ナンプレ、マインスイーパー、パーキングジャム、スライドパズル、バイナリパズル、リフレクション。ウォーターソート以外の6つは濃色の太い外枠（パーキングジャムは出口の切れ目つき）を持ち、ナンプレ・マインスイーパー・スライドパズル・バイナリパズルはその中を格子で区切る。
- プレイ画面の見た目（[詰将棋実装前提調査](詰将棋実装前提調査.md) §10「盤と駒の見せ方」、`ui/board/TsumeShogiPieceGlyph.tsx`）
  - 駒は自前の SVG（五角形と1文字の漢字）。五角形は `50,3 83,16 95,108 5,108 17,16`（100×112）。
  - 玉方の駒は 180° 回して向きで見分ける。玉方の玉の文字は「玉」。
  - 盤は 9×9 を攻方から見た向きで描く。
- 表示名は「詰将棋」（`frontend/src/games/tsume-shogi/display-name.ts`）。SVG の `aria-label` もこれに合わせる。`GamePictogram` は SVG を `aria-hidden` で描画するので、読み上げには使われない。

## 3. 比べた方向と分かったこと

| 方向 | 候補 | 比べたこと |
| --- | --- | --- |
| 詰め上がりを盤の上に描く | A 盤の右上隅 2×2（P1）、A3 枠つき 3×3、A6b 枠つき 2×2（P2） | 枠を隅だけにするか閉じるか、升の数と駒の大きさ |
| 駒だけで描く | B 玉と攻め駒の対峙（P3）、E 玉1枚 | 盤なしで将棋・詰将棋に見えるか、一覧での重さ |
| 王手の候補を描く | D 玉＋候補3つ（P4）、D3 候補から玉への線 | 「候補を比べる」過程が小サイズで残るか |
| 王手の利きを描く | F 攻め駒から玉への線（X1） | 王手の関係を線で示せるか |
| 逃げ場がないことを描く | C 玉の周り8升に利きの点（X2） | 「詰み」の状態そのものを描けるか |
| 持駒を打つ | G 盤の外の駒と玉 | 打つ動作が伝わるか |

### 3.1 着眼点

次の着眼点から候補を作った。

- 盤と玉: 盤の右上隅に追い込まれた玉、9×9 盤の一部、隅の升の玉、玉の周り8升。
- 詰め上がり: 頭金（玉の頭に金）、玉の周りの升がすべて利きで埋まる、攻め駒に囲まれた玉。
- 王手: 攻め駒から玉へ伸びる利きの線（飛・香の遠い王手）、王手の連続を示す道筋、玉に向かう複数の候補。
- 読み: 候補手の比較（選んだ1手と退けた手）、玉方の応手の分岐、誤った王手を反証する×印、読みの分岐木。
- 駒: 玉1枚の拡大、向かい合う玉と攻め駒、駒台の持駒、☗☖ の記号。
- 将棋の象徴: 王冠・チェスのキング、扇子・和柄、手数（「3手詰」）の文字、将棋盤の星。

候補にしなかったもの（判断）:

- 王冠・チェスのキング: チェスのメイトに見え、将棋に結びつかない。
- 扇子・和柄・将棋盤の星: 和風・将棋の雰囲気だけで、詰める遊びにつながらない。星は 46px で点の粒になる。
- 「3手詰」などの文字: 説明文に頼り、`<text>` も使えない。
- 読みの分岐木・×印: 一般的な図表・不正解の記号で、盤に置く遊びに結びつかない。分岐木は 46px で線の束になる。
- 9×9 盤全体: 盤の縮小コピーになり、升が細かすぎる。
- 王手の連続の道筋: 1枚の静止画に手順を入れると、矢印と駒が増えて読めない。

### 3.2 盤の格子に駒を置く（事実（実測））

- ナンプレと同じ濃い外枠と 3×3 の淡色の格子に駒を置くと（A3）、升が 28 しかなく、駒は 22 前後になった。46px で駒は 8px ほどの粒になり、玉の文字は消え、五角形も四角に近づいた。外枠と格子の構成はナンプレ・バイナリパズルと同じになった。
- 盤を 2×2 の升に切り取ると（A・P1・P2）、駒を 30〜36 の大きさで置けた。46px でも五角形の尖りと、玉の輪郭・攻め駒の塗りの違いが見えた。
- 外枠を四方で閉じると（P2）、升に塗りと輪郭の形を置いた構成がバイナリパズル（濃い外枠の 3×2 の升に塗りと輪郭の形）に近づいた。上辺と右辺だけにすると（P1）、ほかのどのピクトグラムにもない外形になり、「盤の一部を切り取った」見え方になった。
- 駒の大きさを升いっぱいにすると、駒の輪郭が盤の枠や升の線に触れ、1つの塊に見えた。駒と枠・升の線の間に 2〜3 の隙間を残した。

### 3.3 駒の形と文字（事実（実測））

- プレイ画面と同じ肩の高い五角形（肩が高さの12%）を 180° 回すと、上辺の広い盾や紋章に見えた。肩を高さの27%へ下げ、肩の幅を底の84%へ広げると、回しても将棋の駒に見えた。
- 攻め駒を淡色の塗りだけにすると、46px で家や墓石の形に見えた。攻め駒を濃色の塗り（☗）、玉を濃色の輪郭（☖）にすると、駒の向きと塗りの組み合わせで「向かい合う2枚の駒」と読めた。
- 玉の文字を「玉」にすると、180° 回したときの点（左上に来る）が 138px で余計な線に見え、46px では見えなかった。「王」にすると、回しても形が崩れず、138px で文字として読めた。46px では「線が数本ある駒」として残る。
- 回した駒の中で文字を回さないと、長い横線が駒の細い側（尖り）へ寄り、窮屈に見えた。文字も駒と一緒に回すと、長い横線が駒の広い側に来て収まった。

### 3.4 駒だけ・候補・利き（事実（実測））

- B（玉と攻め駒が尖りを向け合う。P3）は、46px で最も大きく駒が見え、将棋の駒だとすぐ分かった。ただ盤がないので、一覧では幅の狭い縦長の形になり、濃色の塗りの駒が重く見えた。盤の線を1本足すと（B2）、砂時計や天秤に見えた。
- D（玉の下に、選んだ王手の駒を濃色の塗り、退けた候補2つを淡色の輪郭で並べる。P4）は、「候補を比べて1つを選ぶ」ことが 138px で読めた。46px では淡色の輪郭が細く、駒ではなく小さな山形に見えた。候補から玉への線を足すと（D3）、線が駒に紛れた。
- E（玉1枚）は将棋の駒だとすぐ分かるが、攻め駒がなく「詰める」ことが伝わらない。
- F（攻め駒から玉への短い利きの線。X1）は、線が駒に刺さる釘のように見えた。
- C（玉の周り8升に利きの点。X2）は、升が小さく玉が粒になり、マインスイーパーの盤に近く見えた。
- G（盤の外の駒を玉の下へ打つ）は、盤の線が少なく、駒が宙に浮いて見えた。

### 3.5 仕上げ（事実（実測））

P1 の細部は次を比べた。

- 駒の大きさ（幅 34 / 36）: 36 の方が 46px で駒の形が残った。ただ升の枠に触れたので、升の区切りを左・下へずらして隅の升を広げ（升の線を x=58・y=62）、玉は幅 32・攻め駒は幅 34 にした。左と下の升は盤の続きとして切れたままにした。
- 光学中心: 濃色の上辺・右辺と塗りの攻め駒が右に寄り、中央に置くと右へ重く見えた。左へ2・下へ1ずらした版を、ずらさない版・左へ2・左へ1下へ1と 138 / 56 / 46px で比べ、左へ2・下へ1 を採った。

## 4. 推奨案 P1

### 4.1 仕様（事実（リポジトリ））

- 全体を `translate(-2 1)` でずらす（光学中心の補正）。以下はずらす前の座標。
- 盤の隅: 上辺と右辺を1本の折れ線（`M16 18H102V104`）、濃色、線幅4、線端と角は丸。升の区切りは淡色・線幅2 の縦横1本ずつ（`M58 18V104M16 62H102`）。
- 玉: 中心 x=79.5、上端 y=25、幅 32・高さ 32 の五角形を 180° 回した形（尖りが下）。濃色の輪郭、線幅4、角は丸。中に「王」を濃色・線幅2・線端は丸の4本の線で描き、駒と同じく 180° 回す（長い横線が上）。
- 攻め駒（王手の駒）: 玉の真下の升、中心 x=79.5、上端 y=67、幅・高さ 34 の五角形（尖りが上）、濃色の塗り。
- 攻め駒（支える駒）: 左隣の升、中心 x=37、同じ大きさ、淡色の塗り。
- 五角形の比率: 尖りから肩までが高さの27%、肩の幅が底の84%。
- 色は strong / soft の2色だけ。`check_svg.py` の2色・gradient / filter / 外部画像 / text 禁止の検査を通る。

### 4.2 推奨理由（判断）

- **意味的距離**
  - 詰将棋は「攻方が王手を続けて玉を詰める」遊びで、手順の終わりは玉が逃げられない形になる。P1 は、隅に追い込まれた玉の頭に攻め駒が来た詰め上がり（頭金）を描く。左隣の淡色の駒は、王手の駒を支えて玉に取らせない駒にあたる。
  - 五角形の駒・180° 回した玉方の駒は将棋でしか見ない形で、プレイ画面の駒と同じ描き方。
  - 盤の右上だけを切り取った枠は、詰将棋の図面の見え方と同じ。
- **実表示サイズ**: 要素は枠・升の線・駒3枚だけ。46px でも玉の輪郭、王手の駒の塗り、支える駒の淡色が見分けられた（事実（実測））。
- **弁別性**
  - 五角形を持つのは詰将棋だけ。上辺と右辺だけの枠もほかにない（パーキングジャムは四方の枠に出口の切れ目、リフレクションは閉じた枠）。
  - 升に塗りと輪郭の形を置く点はバイナリパズルと似るが、形が五角形で、枠が閉じていないので、並べて見分けられた（事実（実測））。
- **光学的重量**: 濃色は枠の2辺・玉の輪郭・王手の駒の塗りだけ。塗りの駒は1枚に抑えた。ナンプレ・リフレクションと並べて突出しない（事実（実測））。
- **一覧の描画言語**: 主形状（濃・4）と補助情報（淡・2）の2段階の線を使う（`DESIGN.md`）。

### 4.3 弱点（判断）

- 「複数の王手候補を比べ、玉方の最善の応手を読み、もっともらしい誤手を反証する」という考える過程は描いていない。描いたのはその結末（詰め上がり）だけ。過程を描く P4 は 46px で候補が読みにくかった（§3.4）。
- 玉の文字は 46〜56px で文字として読めず、「線のある駒」になる。玉方の駒だと分かる手がかりは、向き（尖りが下）と輪郭の描き方。
- 文字は「王」で、プレイ画面の玉方の玉（「玉」）と1点だけ違う（§3.3）。
- 攻め駒は文字を持たないので、金かどうかは分からない。頭金だと読めるのは将棋を知る人だけで、知らない人には「隅の駒の前に駒が来た」形に見える。
- 一覧では、閉じた外枠を持つピクトグラムより、左下が開いた分だけ軽く見える。
- ダークテーマでは塗りの攻め駒が明るい前景色になり、☗（黒）の慣例とは明暗が逆になる。既存ピクトグラムも同じ前景色の規則に従うので、ここだけ変えることはしない。

## 5. 再検討するときの論点

### 5.1 論点

- **盤を描くか、駒だけで描くか**: 盤あり（P1・P2）は詰将棋の図面に近く、駒の位置関係（隅・頭）で詰め上がりを示せる。駒だけ（P3）は駒が最も大きく読めるが、一般の「将棋」に近づき、一覧で縦長に細く見える。
- **結末を描くか、過程を描くか**: 詰め上がり（P1）は小サイズで形が残る。候補の比較（P4）はゲーム体験の核に近いが、退けた候補の淡色の輪郭が 46px で弱い。
- **玉の文字**: 「王」（P1）は回しても崩れない。「玉」はプレイ画面と同じだが、回した点が 138px で余計な線に見える。文字なし（X2）は玉だと分からない。
- **枠を隅だけにするか、閉じるか**: 隅だけ（P1）は図面の切り取りに見え、ほかと見分けやすい。閉じる（P2）と一覧の重さがそろうが、バイナリパズルに近づく。

### 5.2 候補の一覧と代替案

| 案 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| **P1 盤の右上隅の詰め上がり**（推奨） | 上辺と右辺の枠、2×2 の升、隅の玉・真下の塗りの駒・左隣の淡色の駒 | 詰め上がりと図面の見え方。五角形と隅の枠で見分けやすい | 考える過程は描かない。46px で玉の文字が読めない |
| P2 閉じた枠の詰め上がり | P1 の枠を四方で閉じ、駒を少し小さく | 一覧の重さがそろう | バイナリパズルに構成が近い。駒が小さい |
| P3 玉と攻め駒の対峙 | 盤なし。大きな玉（輪郭・「王」）の尖りに、塗りの攻め駒の尖りが向かう | 駒が最も大きく読める。将棋の駒だとすぐ分かる | 盤がなく一般の将棋に近い。縦長で一覧では細く、塗りの駒が重い |
| P4 王手の候補の比較 | 大きな玉の下に、選んだ王手（塗り）と退けた候補2つ（淡色の輪郭） | 「候補を比べて1つ選ぶ」過程を示す | 46px で候補の輪郭が弱く、山形に見える |
| X1 王手の利き | 隅の枠、玉、下の攻め駒から玉への短い線、淡色の駒 | 王手の関係を線で示す | 線が駒に刺さる釘に見える |
| X2 逃げ場がない | 閉じた枠と 3×3 の格子、中央の玉、周りの8升に利きの点 | 「詰み」の状態そのもの | 玉が粒になり、マインスイーパーに近い |
| X3 玉1枚 | 隅の枠、淡色の升の線、大きな玉 | 将棋の駒だとすぐ分かる | 攻め駒がなく、詰めることが伝わらない |

推奨順は P1 > P3 > P4 > P2（判断）。部分採用もできる（例: P1 の左隣の淡色の駒を P4 の淡色の輪郭（退けた候補）に替える、P3 の大きな駒を P1 の隅の枠に置く）。

## 6. 代表案の SVG と選び替え

[ピクトグラム検討/](ピクトグラム検討/) に、候補ごとの代表案だけを置く。

| ファイル | 内容 |
| --- | --- |
| `p1-corner-mate.svg` | 推奨案 P1（採用 SVG と同じ） |
| `p2-full-frame.svg` | P2 閉じた枠の詰め上がり |
| `p3-face-off.svg` | P3 玉と攻め駒の対峙 |
| `p4-candidates.svg` | P4 王手の候補の比較 |
| `x1-check-ray.svg` | X1 王手の利き |
| `x2-no-escape.svg` | X2 逃げ場がない |
| `x3-single-king.svg` | X3 玉1枚 |

色は製品と同じ CSS 変数（`var(--game-pictogram-strong)` / `var(--game-pictogram-soft)`）のまま置いている。GitHub などで CSS 変数なしに見る場合は、ライトテーマの近似値に置き換えたコピーを作る。

```sh
sed -e 's/var(--game-pictogram-strong)/#0a0a0a/g' -e 's/var(--game-pictogram-soft)/#737373/g' \
  docs/パズル/導入調査/詰将棋/ピクトグラム検討/p3-face-off.svg > /tmp/p3.svg
```

### 6.1 選び替える手順

1. 採る候補の SVG を `frontend/src/games/tsume-shogi/assets/pictogram.svg` へ複製する。`aria-label` は表示名（`TSUME_SHOGI_DISPLAY_NAME`）に合わせる。
2. 最終検査を通す。

   ```sh
   python3 .claude/skills/design-game-pictogram/scripts/check_svg.py frontend/src/games/tsume-shogi/assets/pictogram.svg \
     --max-colors 2 --forbid-gradients --forbid-filters --forbid-external-images --forbid-text
   ```

3. 既存ピクトグラムと同じサイズ・同じテーマで並べて見比べる（`references/method.md` §4「弁別性」「実表示サイズでの成立」）。サイズは §2.2 の 177 / 138 / 56 / 46 / 48px を使い、ライトとダークの両方で見る。

   ```sh
   python3 .claude/skills/design-game-pictogram/scripts/make_review_sheet.py \
     --output /tmp/tsume-shogi-pictogram-review.html --size 112 \
     docs/パズル/導入調査/詰将棋/ピクトグラム検討/*.svg \
     frontend/src/games/*/assets/pictogram.svg
   ```

4. この文書の §1 と §4 を、採った案に合わせて直す。
