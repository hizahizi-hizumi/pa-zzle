# 詰将棋難易度

詰将棋の `レベル 1`〜`レベル 5` を、[難易度開発手順.md](../../難易度開発手順.md) の工程2〜8 に沿って組み立てた検討記録。

## 1. 目的と位置づけ

[詰将棋難易度PoC](詰将棋難易度PoC.md)（以下「PoC」）の仮説（初手の王手候補・もっともらしい誤王手・深く続く紛れ・玉方の応手幅・手筋で5段階に分ける）を、製品コードの難易度分析器へ落とす。問題集合で特徴の分布・分析時間・供給を測り、5段階の組み合わせ定義を暫定で決め、人間が試遊で確かめるための代表・境界・異常な問題を残す。

この文書は現在仕様の正本ではない。採用した契約は正本化の段（[詰将棋実装前提調査](詰将棋実装前提調査.md)（以下「前提調査」）§11 段13）で `docs/プロダクト/` へ移す。正確な組み合わせの値はコード（`frontend/src/games/tsume-shogi/difficulty.ts` の `tsumeShogiLevelCombinations`）を正とし、文書に書いた値は記録時点のものとして読む。

根拠は前提調査と同じ見出し語で区別する。

- **事実（実測）**: 本書 §6 の問題集合と、コミット済みの分析スクリプトで測った結果。一時スクリプトで測ったものはその旨を書く。
- **導出**: 定義から論理的に導けること。
- **推測・仮説**: 実プレイで確かめていない判断。

**人間の実プレイとの照合はまだ行っていない。** §11 の試遊が済むまで、各レベルの体験差は仮説として扱う。

## 2. 前提として引き継ぐ条件

| 条件 | 内容 |
| --- | --- |
| 問題 | V1 supported subset（前提調査 §1.1）。3手・5手詰、攻方毎手王手、玉方最長抵抗、駒箱、早詰なし、攻方正解一意（最終手も一意）、駒余り棄却、作意に合駒が現れない、無駄合・2手変長の解釈で答えが変わらない |
| 問題成立性 | strict validator（前提調査 §10「strict validator」）が `accepted` とすること。難易度分析は成立性を確かめ直し、成り立たない問題を評価しない |
| 基準とするプレイ条件 | 駒の動き・成り・持駒・二歩 / 打歩詰・毎手王手・玉方の最長抵抗を理解している（遊び方で説明する。ルール学習の負荷を難易度に含めない）。ヒント・答え表示は無い。**誤王手を指す前に読んで正解を選ぶ**プレイを基準にする。誤王手を指すと玉方の反証が再生される（前提調査 §10「合法だが不正解の王手」）が、反証を見て選び直すことは成績（誤王手の回数）の側で扱い、難易度の基準にはしない |
| 供給 | 事前生成した問題集から出す（段08） |

## 3. 詰将棋固有の挑戦

### 3.1 挑戦の定義

> 王手になる候補を挙げ、それぞれに対する玉方の最善の応手を読み、一見正しそうな誤王手を反証して、正しい王手の手順を最後まで保つこと。

PoC §1 の「プレイヤーが行う中心的な判断」をそのまま挑戦にした。

### 3.2 挑戦を強くするもの（仮説）

1. 王手の候補が多い（読み始めの候補を絞る負担）。
2. 誤王手の中に、自然な応手の一部が詰む「効いていそうな」手がある（その手を捨てるには、詰まない応手を見つける必要がある）。
3. 誤王手の反証が深い。玉方が逃れた後も攻方の脅しのある王手が続き、「この筋は詰まない」が数手先まで見えない（深い紛れ）。深い紛れが多いほど、比べる筋が増える。
4. 正しい手順が、捨駒・成 / 不成・駒取り・開き王手・遠い利きなど複数の手筋を組み合わせる。
5. 正しい王手の後、玉方の自然な応手が複数あり、どの応手でも詰むことを確かめる必要がある（変化の幅）。

### 3.3 挑戦にしないもの

- 手数そのもの（3手か5手か）。分類の条件にしない（§8）。
- 盤上の駒数・持駒の枚数。
- solver の探索量（ノード数・時間）。
- 誤王手の反証の「正確な深さ」。PoC §2 で、計算が重く中〜高帯で値が飽和したので主特徴にしない。代わりに、反証が4手目以降まで見えない誤王手の本数を数える（§4）。
- 玉方の合駒の手数。V1 は無駄合の解釈で答えが変わらない問題だけを扱うので、合駒は読みの候補に数えない（§4）。
- 駒の文字の見分けにくさ・升の押しにくさ・玉方の応手の待ち時間などのプレイ摩擦。

## 4. 分析モデル

`frontend/src/games/tsume-shogi/problem/difficulty-analysis.ts` の `analyzeTsumeShogiDifficulty` が、strict validator で問題を確かめた後、作意の攻方の手番（判断地点）ごとに、作意以外の王手を読む。

### 4.1 操作的な定義

| 用語 | 定義 | 人間の読みとの対応（仮説） |
| --- | --- | --- |
| 判断地点 | 作意の攻方の手番。残りの手数（その攻方の手を含む）を持つ | 次の王手を選ぶ場面 |
| 誤王手 | 判断地点の合法な王手のうち、残りの手数以内に詰まない手。採用した問題では作意以外のすべての王手 | 正解でない候補 |
| 自然な応手 | 玉方の応手のうち合駒でない手（玉が逃げる・王手した駒を取る） | 人間が最初に読む受け。V1 の問題では合駒は無駄合として読み飛ばせる（strict validator の `interpositionSensitive` が無い） |
| 逃れ | 王手の後の玉方の応手のうち、残りの手数以内に詰まなくなる手（合駒も含む） | 反証の手 |
| 脅しのある王手 | 自然な応手の少なくとも1つが、残りの手数以内に詰む王手 | 「効いていそう」に見える王手。どの自然な応手でも詰まない王手は、玉の逃げ道・取られ方を見るだけで捨てられる |
| 紛れの長さ | 誤王手から、玉方が最も早く崩れを見せる逃れを選び、攻方が脅しのある王手で最も長く続けたとき、脅しのある王手が尽きるまでの手数（誤王手を含む）。逃れの後に脅しのある王手が無ければ 2 | 誤王手を捨てるまでに読む深さ |
| 深い紛れ | 紛れの長さが4以上の誤王手 | 玉方がどう逃れても次の脅しが続き、「この筋は詰まない」が4手目以降まで見えない。PoC の「数手先まで続く紛れ」 |
| もっともらしい誤王手（すぐには崩れない誤王手） | 脅しのある誤王手か、深い紛れ | PoC の `plausibleWrong`。どの自然な応手でも詰まず、逃れた後にも脅しが続かない誤王手は、その局面を見ただけで崩れると分かるので数えない |

- 深い紛れは、誤王手・逃れ・脅しのある王手・逃れの4手の後に詰みを確かめる1手が要るので、**残りの手数が5以上の判断地点でだけ起きる**（導出）。V1 では5手詰の初手だけになる。最終手の誤王手は、残りの手数で詰まないことがその場で分かるので、もっともらしい誤王手にもならない（導出）。
- 紛れの長さは、玉方は早く崩れを見せる手を、攻方は長く続ける手を選ぶ min-max で数える。王手・応手の列挙順に依らない（導出）。
- 分析できる手数は5手まで（`TSUME_SHOGI_ANALYSIS_MAXIMUM_PLIES`）。それを超える問題は評価不能（`unsupported`）にする。

### 4.2 PoC との違い

PoC のコードはリポジトリに無いので、定義は PoC 文書の記述から作り直した。

- PoC の「浅い紛れ」（`plausibleWrong`）の中央値は、各帯で初手の王手候補の数から1を引いた値とほぼ同じだった（PoC §5 の表: 3→2、6→5、16→15 など）。PoC ではほぼすべての誤王手を数えていたと読める（**推測**）。本書は「脅しのある誤王手」に絞る。読まなくても崩れる誤王手を、挑戦に数えないためである。
- PoC の「深い紛れ」も、レベル3〜5 の中央値（3 / 4 / 7）が初手の王手候補（4 / 6 / 9）に近く、多くの誤王手を数えていた（**推測**）。本書は、続く王手にも脅しを求めるので、同じ問題でも PoC より少なく数える（§7.3）。

## 6. 問題集合

### 6.1 条件

生成器（版 1）の seed で、生成条件ごとに60問ずつ、計540問。生成条件は、初手の王手の数を絞らない3手・5手と、§8.2 の各レベルの生成条件（初手の王手の数の範囲）。

| --- | --- |
| 3手 / 5手（絞らない） | `ts-3-0`、`ts-5-0` |

- 生成器が上限までに作れなかった seed は無かった。
- 初手の王手の数の範囲で、出やすいレベルが動く。3手・1〜4 は92%がレベル1、5手・10以上はレベル5 が23%（絞らない5手では5%）。生成条件だけでレベルは決まらず、どの条件からも2〜4種類のレベルが出る（[難易度判定.md](../../難易度判定.md)「生成条件を難易度へ直結させない」）。
- 難易度分析の時間は p50 58ms / p90 305ms / p99 1.2秒 / 最大 2.6秒（540問）。初手の王手が多い5手詰ほど長い。

### 7.2 手数への依存

| 手数 | L1 | L2 | L3 | L4 | L5 | 提供範囲外 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 3手（180問） | 88 | 85 | 0 | 0 | 0 | 7 |
| 5手（360問） | 16 | 67 | 144 | 60 | 25 | 48 |

- 5手詰はレベル1〜5 のすべてに分かれる。手数でレベルは決まらない。
- 3手詰はレベル1・2 だけになる。深い紛れが5手詰の初手でしか起きない（§4.1）ためで、手数を条件にしたからではない（導出）。結果として、レベル3 以上は5手詰だけになる。

### 7.3 レベルごとの特徴（中央値（四分位））と PoC との比較

| 特徴 | L1（104問） | L2（152問） | L3（144問） | L4（60問） | L5（25問） |
| --- | --- | --- | --- | --- | --- |
| 手数の内訳 | 3手 88・5手 16 | 3手 85・5手 67 | 5手 144 | 5手 60 | 5手 25 |
| `rootChecks` | 3 (3〜4) | 5 (4〜7) | 7 (5〜10) | 9 (7〜11) | 14 (11〜16) |
| `plausibleWrong` | 0 | 1 (1〜2) | 5 (3〜8) | 7 (6〜9) | 13 (10〜15) |
| `deepDecoyCount` | 0 | 0 | 1 (1〜2) | 3 (3〜4) | 8 (7〜11) |
| `defenseBranching` | 0 (0〜1) | 1 (0〜1) | 1 (1〜2) | 1 (1〜2) | 1 (1〜2) |
| `tesujiKindCount` | 2 (2〜3) | 2 (2〜3) | 3 (2〜3) | 3 (2〜3) | 2 (2〜3) |
| 手筋の列の種類 | 16 | 60 | 77 | 45 | 20 |
| PoC の `rootChecks` 中央値 | 1 | 2 | 4 | 6 | 9 |
| PoC の深い紛れの中央値 | 0 | 0 | 3 | 4 | 7 |

- 初手の王手の数・もっともらしい誤王手・深い紛れは、レベルとともに単調に増える。PoC と比べると、初手の王手の数はどのレベルでも多め、深い紛れはレベル3・4 で少なめ（定義を絞ったため。§4.2）、レベル5 で同程度。
- レベル1 の初手の王手は PoC（中央値1）より多い（中央値3）。本書のレベル1 は「候補はあるが、どの誤王手もその局面で崩れると分かる」問題を含む。初手の王手が1つだけの問題は少ない（540問中 5問）。
- 変化の幅（`defenseBranching`）と手筋の種類は、レベルでほとんど変わらない。深い紛れと独立な量で、単独でレベルを分けない（§8）。
- 作意の手筋の偏り: レベル1 は最終手の 99%（103/104）が駒打ち、66%（69/104）が「初手で捨てて玉で取らせる」筋、手筋の列 16種のうち上位2つ（`動取捨 玉取 打` 35問、`動成取捨 玉取 打` 29問）で 62%。逆算の起点の1手詰の多くが駒打ちで、逆算で「玉が攻方の駒を取る」1組を作りやすい（前提調査 §10.2）ことの表れ。問題集での抑え方は段08。

## 8. 5段階の分類

### 8.1 案と比較

| 案 | 内容 | 判断 |
| --- | --- | --- |
| A | 手数で分ける（3手をレベル1・2、5手をレベル3〜5 など） | 不採用。手数は作業量で、5手詰でもレベル1〜5 の挑戦差が出る（§7.2、PoC §4） |
| B | 初手の王手の数だけで分ける | 不採用。同じ王手の数に深い紛れ0〜5本が混ざる（§7.1。5手・1〜4 からレベル3 が19問） |
| C | 深い紛れの本数だけで分ける | 骨格は採用。ただし深い紛れの無い3手・5手詰の中で、「誤王手がどれも崩れる」と「効いていそうな誤王手がある」を分けられず、レベル1・2 を区別できない |
| D | C に、レベル1・2 のもっともらしい誤王手・初手の王手の数の範囲と、レベル4・5 の正しい手順の比べどころを足す | **採用** |
| E | 特徴の加算スコアを五分位で分ける | 不採用。帯の意味が説明できず、生成条件で供給を狙えない |

### 8.2 採用する組み合わせ定義

範囲（両端を含む）にすべて入るレベルのうち、レベル1から順に最初に当たったレベルに分類する。

| レベル | 初手の王手 | もっともらしい誤王手 | 深い紛れ | 正しい手順の比べどころ | 生成条件（初手の王手） | 利用者にとっての変化（案） |
| ---: | --- | --- | --- | --- | --- | --- |
| 1 | 1〜4 | 0 | 0 | 問わない | 1〜4 | 王手の候補は少なく、正解以外はどれもすぐ崩れると分かる |
| 2 | 1〜10 | 0〜5 | 0 | 問わない | 2〜10 | 効いていそうな誤王手があるが、次の一手で詰まないと分かる |
| 3 | 問わない | 1以上 | 1〜2 | 問わない | 3〜12 | 数手先まで続く紛れが少しあり、候補を読み比べる |
| 4 | 問わない | 3以上 | 3〜5 | 手筋2種以上か、変化2以上 | 6以上 | 数手続く紛れが複数あり、正しい手順も手筋か玉方の応手を比べて確かめる |
| 5 | 問わない | 6以上 | 6以上 | 手筋2種以上か、変化2以上 | 10以上 | 数手続く紛れが多く、遠い利きや複数の手筋を含めて比べる |

- 上のレベルは下のレベルの挑戦を含む: レベル2 はレベル1 の候補の読みに効いていそうな誤王手を足し、レベル3〜5 はもっともらしい誤王手のうち深い紛れを1本・3本・6本以上と増やす。深い紛れはもっともらしい誤王手に含まれる（導出）ので、もっともらしい誤王手の下限は深い紛れの下限と同じにしてある。
- 手数は条件に入れない。1手詰は通常の難易度の手数として扱わず提供範囲外（`mate-in-one`）にする（前提調査 §1.1）。
- 生成条件（`generationRootChecks`）は候補の領域を寄せるためだけに使い、分類には使わない（[難易度判定.md](../../難易度判定.md)「問題供給は分析・分類結果へ従う」）。深い紛れを求めるレベル3〜5 の生成条件は5手だけにする（`listTsumeShogiGenerationConditions`）。
- レベル4・5 の比べどころは、PoC のレベル4「玉方応手・手筋を比較する」・レベル5「複数手筋や非局所的な利きを含めて比較する」を、手筋の種類か変化の幅のどちらかとして表した。§7.3 のとおり両者はレベルで増えないので、下限だけを置いた。
- 定義はデータ（`tsumeShogiLevelCombinations`）で持ち、境界を変えるときは値だけを直す。境界は人間の実プレイで確かめる前の暫定値。

### 8.3 評価可能範囲と提供範囲

| 判定 | 条件 | 扱い |
| --- | --- | --- |
| 評価不能（`unsupported`） | strict validator の supported subset の外（合駒・無駄合・2手変長）、または5手を超える | 提供しない。レベル5へ押し込まない |
| 提供範囲外（`out-of-range`） | 1手詰（`mate-in-one`）、または組み合わせがどのレベルにも当たらない（`unlisted-combination`） | 提供しない |
| 成立しない（`invalid`） | strict validator が `invalid` とする（不詰・早詰・余詰・駒余り）、または作意が strict validator の作意と違う | 提供しない。生成器が出さない |

§6 の問題集合では 540問のうち 485問（90%）が提供範囲に入った。範囲外 55問の主な内訳は次の通り（事実（実測））。

- 深い紛れが無いのに、もっともらしい誤王手が6以上ある5手詰（2手目以降の判断地点に効いていそうな誤王手が多い）、または初手の王手が11以上ある深い紛れの無い問題。浅い紛れが多いだけの問題を、深い紛れのあるレベル3 と同じに扱わないため外した。
- 深い紛れが3以上あるが、作意の手筋が1種類以下で変化も1以下の問題（例: 飛・角・龍・馬を動かすだけで詰む筋）。

## 12. ずれた場合の見直し方針

[難易度開発手順.md](../../難易度開発手順.md) 工程10 の順に疑う。閾値（範囲の端）を先に動かさない。

1. 挑戦の定義（§3.1）が体感と合わないなら、基準とするプレイ条件（誤王手を指す前に読む）を見直す。
2. 「脅しのある王手」の定義（自然な応手の一部が詰む）が人間の「効いていそう」と合わないなら、定義を見直す。例えば、逃れが1通りしかない王手だけを数える、合駒も読みの候補に入れる。
3. レベル内の差が大きいなら、記録のみの特徴（判断地点ごとの内訳、手筋ごとの数）を条件に足す。
4. そのうえで範囲の端を直す。

## 13. 限界と未解決

- 人間のプレイでの確認はまだ無い。境界はすべて問題集合の分布から置いた暫定値。
- 分析は5手まで。7手以上を扱うときは、紛れの長さの探索の重さと、深い紛れの定義（長さ4以上で足りるか）を見直す。
- 「自然な応手」から合駒を除くのは、V1 の問題では無駄合の解釈で答えが変わらないことに頼っている。合駒が意味を持つ問題（supported subset の外）を扱うときは読みの候補に入れる必要がある。
- 手筋（`motifs`）は作意の手の形から機械的に数えたもので、「詰将棋の手筋」の一般的な分類（例: 退路封鎖・焦点の捨駒・不成の妙）までは表していない。高度な手筋を要する問題を高いレベルとして扱うなら、その手筋を分析で表せる必要がある（[難易度判定.md](../../難易度判定.md)）。
- 誤王手の反証はブラウザで再生できるので、読まずに試すプレイでは挑戦が弱まりうる。難易度の基準は「指す前に読む」とし、試した回数は成績（段11）で扱う。
- 作意の手筋の偏り（§7.3。特にレベル1 の最終手の駒打ちと捨駒→玉取りの筋）は生成器の起点の作り方に由来する。分類ではなく問題集の選び方（段08）で抑え、レベル1 の最終手の駒打ちは段15で起点に盤上の駒を動かす1手詰を足して 93% から 50% にした（前提調査 §10.6）。

A の中での判断:

- **何を増やすか**: 玉方の駒（2一玉・3一金・1一香）はどのレベルでも同じにし、攻方の持駒（金 → 金・桂 → … → 金・桂・銀）と盤上の駒（レベル3 で 2三歩、レベル4 で 4二馬）を足す。上のレベルは下のレベルの駒と持駒をすべて同じ位置に含む。
- **候補の数**: 図の初手の合法な王手の数は 3・5・7・10・13 で、各レベルの生成条件（`generationRootChecks`）の範囲に入る（導出。テストで確かめる）。問題集のレベルごとの初手の王手の中央値 3 / 5 / 7 / 10 / 14（§14）に近い。
- **手筋の組み合わせ**: レベル4 から成駒（馬。文字が赤い）を置き、成と遠い利きを含む候補が増えることを見せる。レベル4・5 の正しい手順の比べどころ（§8.2）を形で表したもので、図の中に正しい手順は無い。
- **答えを持たない**: どの図も5手以内に詰まない（`isTsumeShogiMateWithin` で確かめる）。図は誤王手の候補の広がりだけを示す模式図で、解かせる局面ではない。
- **盤の端**: 上辺と右辺だけを盤の外枠の色で描き、左と下は盤の続きとして切り落とす（ピクトグラムと同じ見え方）。持駒はプレイ画面と同じく盤の外（右）に並べる。
- **大きさ**: 1升は 320px で 16px、360px 以上で 17px、PC で 26px。**事実（実測）**: Playwright（Chromium）で 320 / 360 / 375 / 390 / 1280px、ライト / ダークで、横スクロールが無く、選択肢の高さが 64px（PC は 240px）にそろい、ラベルが折り返さないことを確かめた。

### 15.3 テストで保証すること（`TsumeShogiDifficultyPreview.test.tsx`）

- 各レベルの図は詰将棋の局面として成り立ち、初手の王手の数がそのレベルの生成条件の範囲に入る。
- どの図も5手以内に詰まない。
- 隣り合うレベルで、上の図は下の図の駒と持駒をすべて同じ位置に含み、初手の王手を増やす（単調性）。
- 玉方の駒はどのレベルでも同じ。

### 15.4 実プレイで確かめること

- 駒が増えていく図が「読み比べる候補が増える」と伝わるか。単に「駒が多い局面が出る」と受け取らないか。
- 図を解こうとして詰まないことに戸惑わないか。
- 16px の升で駒の文字（特に馬の赤）が読めるか。
