# 詰将棋 スマホ操作PoC

調査日: 2026-09-30〜2026-10-02

## 目的

9×9盤と持駒を持つ詰将棋が、pa-zzleのスマートフォン向けWeb UIとして成立するか確認する。

## PoCの操作

- 盤上駒をタップして選択
- 移動先をタップ
- 持駒をタップして選択
- 打つ升をタップ
- 成/不成の両方が合法な場合は選択ダイアログ
- 戻る / やり直し

玉方の応手は本番では自動応手を前提とする。

## 画面幅

320 / 360 / 375 / 390pxで確認した。

| 幅 | 盤面の概算幅 | 1升の概算幅 | 判定 |
| ---: | ---: | ---: | --- |
| 320px | 約306px | 約34px | 画面内に収まる。タップ精度は本番UIで再確認 |
| 360px | 約346px | 約38px | 成立 |
| 375px | 約361px | 約40px | 成立 |
| 390px | 約374px | 約41px | 成立 |

横スクロールは不要で、盤面上部に玉方「残り全駒」、下部に攻方持駒を置いても基本プレイを収められた。

## 320pxの扱い

34px/升は一般的な44pxタップ目標より小さい。盤全体を44pxへすると9×9だけで396px必要になるため、画面幅320pxでは両立しない。

したがって本番では次を優先する。

1. 駒選択 → 移動先の2段階入力で誤入力を減らす。
2. 選択状態を明瞭にする。
3. タップ可能領域を升全体にする。
4. 実機で誤タップが問題になる場合だけ、盤面領域のズーム/パンをfallbackとして検討する。

## レビューHTMLの補足

難易度ブラインドレビュー用HTMLを当初JavaScriptで盤面生成したところ、iPhoneのChatGPT内蔵ビューアではJavaScriptが実行されず、盤面の枠だけ表示された。

レビュー用途については盤面50問を静的HTMLへ焼き込み、JavaScript無効でも表示できる版へ変更した。これはpa-zzle本番UIの制約ではなく、調査成果物をChatGPT内蔵ビューアで確認するための互換対応である。

## 判定

**スマホプレイ成立性: 通過。**

盤面サイズは導入阻害要因ではない。ただし製品UIでは320pxでの誤タップ、成/不成、持駒の選択、誤王手から戻る操作を実機相当で再確認する。
