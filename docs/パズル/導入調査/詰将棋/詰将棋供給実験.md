# 詰将棋 供給実験

調査期間: 2026-09-30〜2026-10-02

## 目的

詰将棋をpa-zzleで継続供給できるかを、既存問題の転載ではなく自前生成を前提に確認する。

確認したい条件は次の通り。

- 指定手数で強制詰み
- より短い手数で詰まない
- 攻方の正解が一意なaccepted subsetを作れる
- 駒余りや重大な品質問題を棄却できる
- 同じ局面・同じ詰み筋の量産にならない
- 難易度帯を狙って問題を作れる

調査コードはローカルPoCとして実行し、製品には持ち込まない。ここでは採用判断に必要な結果と限界を残す。

## 1. 供給方式

### ランダム配置

ランダムに駒を配置して完全検証する方式は、3,000候補規模でも短時間で十分な供給量を得られず、主方式として不向きだった。

### 逆算法

詰み上がりから局面を戻し、各段階で順方向solverにより指定手数・唯一性を再検証する方式は成立した。

PoCは段階的に次を追加した。

- 盤上駒の非捕獲移動
- 攻方の駒打ち
- 成る手
- 攻方の駒取り
- 玉方の駒取り
- 候補プール/ビーム型延長

全逆算候補を列挙すると候補数が爆発するため、合法性の早期検査と候補上限付き探索が必要だった。

## 2. 初期PoCの結果

500 seedの並列実験では次まで到達した。

| 到達 | 件数 |
| --- | ---: |
| 1手詰 | 51 |
| 3手詰 | 17 |
| 5手詰 | 3 |
| 7手詰 | 0 |

17件の3手詰をソースプールとしてビーム型に5手へ延長すると、異なる5手詰を5件確保できた。

7手への素朴なPython全幅探索は実行上限へ達した。これは7手詰の供給不能ではなく、長手数の供給評価にはdf-pn等の強い探索器が必要という結果である。

## 3. 逆算範囲を広げた結果

捕獲・成り・持駒を含む逆算へ広げると、5手作の作意に次を含む問題を生成できた。

- 攻方の成り
- 攻方の駒取り
- 玉方の駒取り
- 攻方の駒打ち

24 seedの小規模並列実験では、1手4・3手3・5手3まで到達した。件数自体は少ないが、単純な追い王手だけに限定されない供給経路が成立した。

## 4. 公開自動生成コーパスの比較

`tokuhirom/tanuki-tsume-shogi` の公開問題1,231問を研究用固定集合として集計した。

| 手数 | 問数 |
| ---: | ---: |
| 1 | 228 |
| 3 | 543 |
| 5 | 296 |
| 7 | 132 |
| 9 | 29 |
| 11 | 3 |

この実装では長手数ほど供給が急減している。長手数を難易度5の必須条件にすると供給リスクが高くなる。

### 解手順重複

初期局面hashは全問一意だったが、解手順には大きな重複があった。

- 1手: 完全に同じ解手順 41群 / 171問
- 3手: 92群 / 224問
- 5手: 45群 / 102問

玉位置を基準に平行移動を正規化すると、1手228問は64パターンまで減った。移動ベクトル列だけで見ると37パターンだった。

したがって、問題供給ではposition hashだけでなく少なくとも次を追う。

- canonical position fingerprint
- solution-tree fingerprint
- motif fingerprint

## 5. strict validatorの境界

PoCでは、通常の合法手だけでなく詰将棋作品としての品質状態を分離して扱う必要があることを確認した。

最低限の状態候補:

- 強制詰み / 不詰
- 早詰
- 作意線上の余詰
- 長い迂回詰み
- 駒余り
- 無駄合感度
- 変化同手数
- 変化別詰
- 非限定
- 循環 / 千日手
- 不要駒

公開問題8問とのクロスチェックでは、指定N手以内の唯一解へ定義を揃えると8/8で作意手数・初手・unique判定が一致した。PoC側でN+4手まで探索していたときに出た不一致は、長い迂回筋まで余詰扱いした定義差だった。

製品では「余詰」を1 booleanへ潰さず、品質状態を別々に保持する。

## 6. 玉方合駒

現存PoCの5手詰102局面を走査したところ、作意木に玉方の駒打ちを含む問題は0件だった。

さらに、1手詰へ長距離王手と遮蔽駒を意図的に追加し、玉方駒打ちを逆算する実験を行った。

- 完了した1手詰基底: 21
- 変異試行: 1,010
- 1手詰を維持: 755
- 玉方駒打ちを逆算可能: 755
- strictな3手詰として成立: 0

合駒構造そのものは作れるが、直前の攻方王手を足すと逃れや余詰が生じ、現PoCでは完全作にならなかった。

**判断:** V1供給PoCでは玉方合駒をsupported subsetから外す。これは詰将棋一般で合駒を不要とする判断ではない。合駒作品はgenerator/validatorが成熟した後の拡張課題とする。

## 7. 問題供給の現在地

難易度PoC用には、5手詰で各帯10問、計50問のミニプールを作れた。各帯の10問は解答木fingerprintも10/10ユニークだった。

これは「製品で必要な問題量を安定供給できた」ことを意味しない。導入調査として、次を確認した状態である。

- 自前生成経路がある
- 同一手数の中で難易度条件を変えられる
- 5帯すべてへ小規模に問題を供給できる
- 解答木の重複を除いたミニプールを作れる

製品実装では、strict validatorと独立oracleを前提に、本番で必要な問題量・生成時間・棄却率・p50/p90/p99を改めて測る。
