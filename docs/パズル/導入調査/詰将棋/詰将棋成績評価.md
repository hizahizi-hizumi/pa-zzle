# 詰将棋成績評価

詰将棋の1プレイを100点満点で評価し、`perfect` / `great` / `good` / `clear` の評価段階と自己ベストの比較へつなげるための検討記録。

[詰将棋実装前提調査](詰将棋実装前提調査.md)（以下「前提調査」）§8 の「保存候補となる生の事実」と、§10「プレイの状態と事実」（段05）の仮決定を出発点に、観点・配点・基準時間・記録する事実を決める。

この文書は現在仕様の正本ではない。採用した評価規則・記録する事実・自己ベストの比較は、正本化の段（前提調査 §11 段13）で `docs/プロダクト/` へ移す。係数はすべて仮置きで、正確な値はコード（`frontend/src/games/tsume-shogi/score.ts`）を正とする。比べた案、採らなかった案、係数の根拠はこの文書に残す。書き方は [リフレクション成績評価](../リフレクション/リフレクション成績評価.md) に倣う。

根拠は前提調査と同じく、次の見出し語で区別する。

- **事実（実測）**: 同梱の問題集（問題集の版 1、レベル1〜3 各300問・レベル4・5 各200問、計1,300問）と、その生成時の難易度分析の特徴から計算した値。一時スクリプトで計算したものはその旨を書く。
- **導出**: 定義から論理的に導けること。
- **推測・仮説**: 実プレイで確かめていない判断。係数・プレイの想定はすべてここに入る。

**人間の実プレイでの確認はまだ行っていない。** 基準時間の係数・減点の重さ・0点になる倍率はすべて仮置きで、§9 の確認で校正する。

## 2. 良いプレイの定義

> 王手の候補を読み比べ、誤王手を指さずに、正しい王手の手順を速く指し切ること。

- 詰将棋の挑戦は、王手の候補を挙げ、玉方の最善の応手を読み、一見正しそうな誤王手を反証することにある（[詰将棋難易度](詰将棋難易度.md) §3.1）。読みが深い人ほど、誤王手を指さずに、早く正解を選べる。
- 誤王手を指すと、玉方の反証が盤面に再生され、判断地点へ戻れる（前提調査 §10）。これは「この筋では詰まない」を盤面で確かめる学習でもあるので、**誤王手は小さく減点し、何回指しても減点の合計に上限を置く**。
- ただし、反証が盤面で見えるので、読まずに王手を順に試しても詰ませられる。誤王手を点に入れないと、試す方が読むより速く、高い点になる（§6 の総当たり）。誤王手を1回でも指したプレイは `perfect` にしない。
- 解けたかどうかはクリアとして別に扱う（`GAME.md`）。失敗の条件は無いので、クリアしたプレイだけを評価する。

## 3. 観点とプレイ事実

`session/session.ts` の `TsumeShogiSessionResult` がクリア時に返す事実（段05）をそのまま使う。

| 事実 | 意味 | 評価での扱い |
| --- | --- | --- |
| 経過時間 `elapsedMs` | 開始から詰むまで。玉方の応手の間（600ms）を含む。盤面を戻しても引き継ぐ。遊び方を読んでいる時間は含めない | **速さ**（80点） |
| 誤王手 `wrongCheckCount` | 作意・詰み筋の上の判断地点から、残りの手数以内に詰まない合法な王手を指した回数。誤王手の筋を続けた王手は数えない | **読みの確かさ**（20点）。1回 −5点、4回で0点 |
| 反証を見た回数 `refutationViewCount` | 玉方の反証の応手を盤面に指した回数。誤王手の筋を続けて見た反証も数える | 記録だけ。減点しない（誤王手の後に筋の先を確かめる学習で、時間は速さに入る） |
| 判断地点へ戻った回数 `returnCount` | 元に戻した回数のうち、誤王手の筋から判断地点へ戻った回数 | 記録だけ。減点しない（誤王手の後の考え直し） |
| 元に戻した回数 `undoCount` | 待ったを押した回数。作意の筋では攻方の1手（と玉方の応手）を取り消し、誤王手の筋では判断地点まで戻す | 記録だけ。減点しない（正しい筋の確かめ直しでも使う） |
| 盤面を戻した回数 `restartCount` | 同じプレイのまま初期局面へ戻した回数 | 記録だけ。減点しない（リフレクションと同じ。時間は引き継ぐ） |
| 非合法入力 `illegalInputCount` | 王手にならない手・ルールで指せない手（二歩・打歩詰・行き所のない駒など）を押した回数 | 記録だけ。**評価に使わない**（前提調査 §8。入力の摩擦で、読みの誤りではない） |
| 入力回数 `inputCount` | 盤面・持駒を押して状態が変わった回数 | 記録だけ。操作の迷いを後から見る目安 |

速さの基準時間には、遊んだ問題の事実（§5 の作業の量）も使う。これはプレイの事実ではなく問題の事実なので、記録では `workload` として `performance` と分けて持つ（§8）。

ヒント・答え表示は V1 に無い（前提調査 §10「ヒント・答え」）ので、その利用回数は事実に無い。後で入れるときは、利用したプレイを評価・自己ベストでどう扱うかを決め直す。

## 4. 評価式（推奨案）

| 観点 | 満点 | 規則 |
| --- | ---: | --- |
| 読みの確かさ | 20 | 誤王手1回ごとに −5点。0点を下回らない（4回以上で0点） |
| 速さ | 80 | 問題ごとの基準時間以内で満点。超過に応じて線形に減らし、基準時間の3倍で0点。1点単位に四捨五入 |

```
読みの確かさ = max(0, 20 − 5 × 誤王手)
速さ         = round(80 × clamp(1 − max(0, 経過時間 − 基準時間) / (2 × 基準時間), 0, 1))
基準時間     = 8秒 + 4秒 × 攻方の手の数 + 2秒 × 初手の王手 + 4秒 × min(もっともらしい誤王手, 20) + 6秒 × min(深い紛れ, 10)
攻方の手の数 = (手数 + 1) / 2（3手詰で2、5手詰で3）
点           = 読みの確かさ + 速さ
```

評価段階は既存ゲームと同じ（100 `perfect` / 90以上 `great` / 80以上 `good` / それ未満 `clear`）。実装: `frontend/src/games/tsume-shogi/score.ts`（`calculateTsumeShogiPlayScore`）。係数は名前付きの定数で、仮置きであることを定数のコメントに書いている。

この式から導かれる性質（導出。`score.test.ts` で固定）:

- `perfect` は誤王手0回で基準時間以内のときだけ。
- 誤王手が無ければ、基準時間の1.25倍以内で `great`（1.2倍で92点）、1.5倍以内で `good`（1.4倍で84点、1.5倍で80点）、2倍で60点、3倍以上で20点。
- 基準時間以内なら、誤王手1回で95点・2回で90点（`great`）、3回で85点・4回以上で80点（`good`）。**誤王手を何回指しても、速ければ `good` に残る**。誤王手で減るのは最大20点。
- 誤王手1回の後、反証を見て判断地点へ戻り、読み直した時間は速さに入る。反証を見た回数・元に戻した回数（判断地点へ戻った回数を含む）・盤面を戻した回数は点に入らない。
- メニューの「やり直す」（同じ問題を新しいプレイとして始める）は時間と回数を0から数え直す。
- 基準時間に対する倍率と誤王手の回数で決まるので、同じ倍率・同じ回数ならどの難易度でも同じ点になる。高いレベルを選んだことだけでは点は上下しない。

## 5. 基準時間

### 5.1 使う量

問題ごとの「読み切るのに要る作業の量」（`TsumeShogiSolveWorkload`）から決める。値は生成時の難易度分析（`analyzeTsumeShogiDifficulty`）の特徴で、段11で問題集の1問に足した（前提調査 §10「問題集の作業の量」）。`generate:tsume-shogi-pool -- --verify` が全問を分析し直して一致を確かめる（**事実（実測）**: 1,300問で不一致 0）。

| 量 | 意味 | 出どころ |
| --- | --- | --- |
| 手数 `plies` | 3 / 5。攻方が指す手の数は2 / 3 | 作意の長さ |
| 初手の王手 `rootChecks` | 初手の合法な王手の数。読み始めの候補 | 問題集に持たせた（分析の特徴） |
| もっともらしい誤王手 `plausibleWrong` | すべての判断地点の、自然な応手の一部が詰む「脅しのある」誤王手か深い紛れの数の和 | 同上 |
| 深い紛れ `deepDecoyCount` | すべての判断地点の、反証が4手目以降まで見えない誤王手の数の和（もっともらしい誤王手に含まれる） | 同上 |

難易度（レベル）そのものは使わない。レベルは特徴の組み合わせの帯（[詰将棋難易度](詰将棋難易度.md) §8）で、同じレベルの中でも作業の量は違う（レベル5 の深い紛れは6〜26）。変化の幅（`defenseBranching`）と手筋の種類（`tesujiKindCount`）は、レベルでほとんど変わらず（同 §7.3）、読む時間への効き方の仮説も立てにくいので使わない（§10）。

実行時に難易度分析を走らせない（5手詰で最大数秒かかり、`problem/generation/` の strict validator を通常プレイから呼ぶことになる）ため、特徴は問題集に持たせる。リフレクションが問題集に作業の量を持たせたのと同じ扱い。

### 5.2 案の比較

| 案 | 式 |
| --- | --- |
| T1 | 8秒 + 12秒 × 攻方の手の数（手数だけ） |
| T2 | 8秒 + 4秒 × 攻方の手の数 + 4秒 × 初手の王手 |
| **T3（推奨）** | 8秒 + 4秒 × 攻方の手の数 + 2秒 × 初手の王手 + 4秒 × min(もっともらしい誤王手, 20) + 6秒 × min(深い紛れ, 10) |
| T4 | T3 から上限を外したもの |
| T5 | レベルごとの定数 |

**事実（実測）: 問題集での基準時間の分布**（最小 / 25% / 中央値 / 75% / 最大。分:秒。一時スクリプトで計算）

| レベル | T1 | T2 | **T3** | T4 |
| ---: | --- | --- | --- | --- |
| 1 | 0:32 / 0:32 / 0:32 / 0:32 / 0:44 | 0:20 / 0:28 / 0:32 / 0:32 / 0:36 | **0:18 / 0:22 / 0:24 / 0:24 / 0:28** | T3 と同じ |
| 2 | 0:32 / 0:32 / 0:44 / 0:44 / 0:44 | 0:24 / 0:32 / 0:36 / 0:44 / 1:00 | **0:24 / 0:30 / 0:36 / 0:42 / 1:00** | T3 と同じ |
| 3 | 0:44（全問） | 0:28 / 0:36 / 0:44 / 1:00 / 1:44 | **0:34 / 0:50 / 1:00 / 1:14 / 2:22** | T3 と同じ |
| 4 | 0:44（全問） | 0:36 / 0:48 / 1:00 / 1:04 / 1:48 | **0:58 / 1:18 / 1:28 / 1:44 / 2:34** | 最大 2:50 |
| 5 | 0:44（全問） | 0:52 / 1:04 / 1:16 / 1:32 / 2:28 | **1:42 / 2:10 / 2:32 / 2:56 / 3:44** | 75% 3:02・最大 6:00 |

- **T1（手数だけ）を採らない**。レベル3〜5 はすべて5手詰なので基準時間が全問 44秒で、深い紛れを読む分が入らない。同じ腕前の人が上のレベルほど速さの点を取れず、「高いレベルを選んだだけで点が下がる」規則になる。手数は難易度の軸ではない（[詰将棋難易度](詰将棋難易度.md) §3.3）のと同じく、時間の軸の中心にもしない。
- **T2（初手の王手まで）を採らない**。候補の数は数えるが、その候補を捨てるための読み（もっともらしい誤王手・深い紛れ）が入らない。レベル5 の中央値が 1:16 とレベル3 の T3 並みで、深い紛れの多い問題ほど不利になる。
- **T4（上限なし）を採らない**。分析器はすべての判断地点の誤王手を数えるので裾が長く（もっともらしい誤王手の最大41、深い紛れの最大26）、極端な問題で6分になる。人間は正解を見つけた時点で残りの候補を読まない（§5.3）。上限に当たるのは問題集のもっともらしい誤王手で34問、深い紛れで46問（どちらもレベル5 の裾）。
- **T5（レベルごとの定数）を採らない**。前提 §1 のとおり難易度そのものを使わない。同じレベルの中で作業の量が2倍以上違う（レベル5 で 1:42〜3:44）。
- **T3 を推奨する**。「盤面を見る、指す手の数、候補の数、効いていそうな誤王手を捨てる読み、数手先まで続く紛れを読む深さ」と、詰将棋の挑戦（[詰将棋難易度](詰将棋難易度.md) §3.2 の1〜3）に対応する量だけで説明できる。中央値は 0:24 / 0:36 / 1:00 / 1:28 / 2:32 とレベルの順に伸び、レベル内でも作業の量で変わる。
- 注意: T3 の係数は人間の実測が無い仮置き（§5.3）。リフレクションのような参照モデルとの比較もしていない。参照モデルは同じ「深い紛れほど時間がかかる」仮定を共有するので、案の妥当性の証拠にはならない（[リフレクション成績評価](../リフレクション/リフレクション成績評価.md) §5.2 の注意）。水準と係数は §9 の実プレイで校正する。

### 5.3 T3 の係数の根拠（推測）

| 係数 | 値 | 根拠 |
| --- | ---: | --- |
| 盤面を見る | 8秒 | 玉の位置・攻方の駒・持駒を一通り見る時間。将棋を知っている人が9×9 の盤の隅を見渡す程度 |
| 攻方の1手 | 4秒 | 駒を選んで移動先を押す（約2秒）、玉方の応手の間（0.6秒）と、その応手を見て次の局面を確かめる時間 |

| もっともらしい誤王手1つ（20まで） | 4秒 | 自然な応手のうち詰まない逃れを見つけて、その王手を捨てる時間。読まなくても崩れる誤王手は数えない（同 §4.1）ので、ここに入る誤王手はどれも1手は読む |
| 深い紛れ1つ（10まで） | 6秒 | もっともらしい誤王手の4秒に足す。逃れの後にも脅しのある王手が続くので、さらに2手先まで読む |
| 上限 | 20 / 10 | レベル5 の p75（もっともらしい誤王手17、深い紛れ10）付近。読み比べの途中で正解を見つければ残りは読まない |

| 2.0 | 0 | 50 clear | 60 clear | 70 clear | 50 clear |
| 3.0 | 0 | 0 clear | 20 clear | 40 clear | 0 clear |

**総当たり（読まずに王手を順に試す）との比較**（推測）。初手の誤王手を平均の半分（切り上げ）試して正解に当たり、試す1回に約5秒（駒を選んで指す約2秒・応手の間0.6秒・反証を見る・戻る）かかるとし、2手目以降は迷わないとした。各レベルの代表問題（§5.3）で:

| レベル | 初手の王手 | 誤王手 | 時間 | 基準時間に対する倍率 | W0 | **W1** | W2 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 4 | 2 | 0:26 | 1.08 | 96 | **87 good** | 78 |
| 2 | 6 | 3 | 0:35 | 0.97 | 100 | **85 good** | 70 |
| 3 | 9 | 4 | 0:40 | 0.67 | 100 | **80 good** | 60 |
| 4 | 10 | 5 | 0:45 | 0.51 | 100 | **80 good** | 60 |
| 5 | 14 | 7 | 0:55 | 0.36 | 100 | **80 good** | 60 |

- 反証が見えるので、試す方が読むより速い。上のレベルほど基準時間（読む時間）に対して大きく速い。
- **W0（速さだけ）を採らない**。総当たりがレベル2〜5 で `perfect` になり、読み切ったプレイと区別できない。リフレクションでは「置いて確かめ、動かして直す」が遊び方の中心として速さだけにしたが、詰将棋の挑戦は指す前に読むことにある（[詰将棋難易度](詰将棋難易度.md) §2）。
- **W2（確かさ40、1回 −10）を採らない**。誤王手2回で、速くても `good` 止まり、3回で `clear`。誤王手を学習として扱う前提 §8 に対して重い。マインスイーパーの地雷（1つで −15）は失敗そのものだが、詰将棋の誤王手は反証を見て戻れる途中の試行である。
- **W3（誤王手で `perfect` だけを外す）を採らない**。誤王手を何回指しても速ければ `great` で、総当たりと読み切ったプレイの差が5点しかない。
- **W1 を採る**。誤王手1回は `great`（95点）に残り、反証を見て考え直すことを大きくは罰しない。総当たりは `good` の下端（80点）で止まり、`great` に届かない。ゆっくり読み切ったプレイ（1.5倍、誤王手0回）も80点なので、「速く試すこと」と「ゆっくり読むこと」が同じ段階になる（§9 の確認点）。
- 反証を見た回数・戻った回数を減点する案は採らない。誤王手1回の後にどこまで筋を確かめるかは学習の深さで、減点すると反証を見ずに戻る方が得になる。

## 8. 記録と自己ベスト

実装: `frontend/src/games/tsume-shogi/play-record.ts`。共通の記録（`frontend/src/records/`）に `gameId: "tsume-shogi"`・`payloadVersion: 1` で載せる。

| payload | 内容 |
| --- | --- |
| `difficulty` | `"1"`〜`"5"` |
| `problemIdentity` | `{ generatorVersion, seed, conditions: { plies, rootChecks?, baseMate? } }`。遊び直しで、ここから求めた問題IDで問題集から同じ問題を引く |
| `poolReference` | `{ poolVersion, problemId }`。遊んだときの問題集の版と問題番号（例: `1` と `4-17`） |
| `workload` | `{ plies, rootChecks, plausibleWrong, deepDecoyCount }`。遊んだ問題の作業の量 |
| `performance` | `{ elapsedMs, wrongCheckCount, refutationViewCount, returnCount, undoCount, restartCount, illegalInputCount, inputCount }`。プレイの事実 |

記録の id は `tsume-shogi:<開始時刻>:<完了時刻>:<seed>`。

- 評価点・評価段階・基準時間・基準時間との差は保存しない。記録から現在の評価規則で導出する（`SPEC-006`）。採点の版も保存しない（リフレクションと同じ。係数を変えたら過去の記録も新しい規則で評価し直す）。評価に使う事実の意味を変える（例: 誤王手の数え方を変える）場合は `payloadVersion` を上げる。
- **問題の識別は生成器の identity を正にし、問題集の版と番号も添える**。
  - 遊び直しは identity から問題集の問題を引く。identity は問題集を作り直しても変わらない。
  - 問題集の版と番号（`poolReference`）は、問題集を作り直すと別の問題を指すので、**遊び直しには使わない**。記録がどの版の問題集から出たか、問題集の何番だったかを後から確かめる（人間レビューで問題集の番号と照らす、問題集を作り直した後に旧い記録を見分ける）ためだけに残す。2つが食い違っても identity を使うので、食い違いの扱いは要らない。
  - リフレクションは問題集の番号を保存せず、必要なら identity から引くとした。詰将棋では、問題集を作り直した後でも記録時点の番号が分かるよう残した（§10）。
- `workload` を記録に持つ理由: 評価を記録だけから再計算できるようにするため。生成器の版を上げて問題集を作り直すと、それまでの記録は identity から問題を引けなくなるが、`workload` があれば評価し直せる（リフレクションと同じ）。
- **問題集に無い記録**（生成器の版が今と違う、または問題集を作り直して外れた問題）も読み込み、記録画面と自己ベストの比較に残す。できないのは遊び直しだけ（記録画面への接続は段12）。
- 遊ぶ問題はどれも問題集の問題で、作業の量があり評価・記録する。問題IDの URL で開いたプレイも、URL の難易度の問題集から引いた問題なので、自己ベストの比較単位を崩さない。
- 読み込み時の検証: ゲームID・payload の版・難易度・identity の形（生成器の版と seed が空でない文字列。今の版なら手数 1 / 3 / 5 と初手の王手の範囲の形）・問題集の版と番号（空でない文字列）・作業の量（手数が正の奇数、初手の王手が1以上、もっともらしい誤王手・深い紛れが0以上の整数で、深い紛れがもっともらしい誤王手以下。今の版の identity なら、手数と初手の王手がその生成条件に合う）・事実（経過時間が有限の0以上、各回数が0以上の整数、誤王手と非合法入力の和が入力回数以下、判断地点へ戻った回数が元に戻した回数以下で、戻ったことがあれば誤王手が1回以上）を確かめ、どれかが崩れた記録は読み込まない。

**自己ベスト**（比較単位は難易度）:

| 指標 ID | 良い向き | 理由 |
| --- | --- | --- |
| `play-score` | 高い | 評価そのもの |
| `time-delta-ms` | 小さい | 基準時間に対するクリア時間の差。問題ごとに作業の量が違うので、実時間ではなく差で比べる（リフレクション・バイナリパズルと同じ） |
| `wrong-check-count` | 小さい | 読みの確かさの観点。点に入る事実で、少ないほど良いと言える（マインスイーパーの踏んだ地雷の数と同じ扱い） |

反証を見た回数・元に戻した回数・判断地点へ戻った回数・盤面を戻した回数・非合法入力の回数は自己ベストに入れない。どれも点に入らず、少ないほど良いとは言えない。

結果画面・記録画面での見せ方は段12で決める（§8.1 として追記する）。

## 10. 限界

- **実プレイをしていない**。基準時間の係数・上限、誤王手の減点、0点になる倍率、総当たりの時間の見積もりはすべて仮定で、§9 で校正する。
- **分析器の数え方と人間の読みの違い**: もっともらしい誤王手・深い紛れは、すべての判断地点の誤王手を数えた和で、人間が実際に読む数ではない。人間は正解を見つけたら残りを読まない一方、分析器が「すぐ崩れる」とした誤王手も読むことがある。2手目以降の判断地点の王手の数は問題集に持たせていないので、初手の王手で代表させた。
- **変化の幅と手筋**: 正しい王手の後に玉方の応手が複数ある問題（変化）は、どの応手でも詰むことを確かめる時間がかかるはずだが、基準時間に入れていない（特徴がレベルで変わらず、効き方の仮説が立てにくいため。§5.1）。レベル4・5 の比べどころ（[詰将棋難易度](詰将棋難易度.md) §8.2）の時間が不足していれば、`defenseBranching` を足す。
- **反証の再生と速さ**: 誤王手の反証は盤面で見えるので、試す方が読むより速い（§6）。基準時間は「指す前に読む」前提で置いたので、試すプレイには長い。読みの確かさの観点で総当たりを `good` に留めたが、速さだけで見ると試す方が有利なまま。
- **玉方の応手の間**: 経過時間に含まれる（攻方の1手ごとに0.6秒）。基準時間の攻方の1手の係数に含めたが、誤王手の筋で応手を待つ時間も速さに入る。
- **問題集の番号**: `poolReference` は記録時点の値で、問題集を作り直すと今の番号とは違う。記録画面などで今の番号を見せるときは identity から引き直す。

## 11. ずれた場合の見直し方針

1. 「良いプレイ」（§2）が体感と合わない（例: 誤王手を試すことも遊び方の中心だと感じる）なら、読みの確かさの観点そのものを見直す（§6 の W0 / W3）。
2. 基準時間の水準がずれるなら、§9 の1・2 に沿って係数を直す。式の形（T3）は変えない。
3. レベル内で同じ腕前の点が大きくばらつくなら、使う量（2手目以降の王手の数、変化の幅）を足す。
4. そのうえで、0点になる倍率と誤王手の減点の重さを直す。
