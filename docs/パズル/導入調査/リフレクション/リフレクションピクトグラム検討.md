# リフレクションピクトグラム検討

リフレクションのゲーム選択ピクトグラムをどう検討したかの記録。どの着眼点を探索し、どの候補を比べ、なぜ P1（2回曲がってブラックホールへ届く光）を推奨するかをまとめる。見直すときに、同じ比較をやり直さずに論点から始められるようにする。

この文書は導入調査の資料であり、現在仕様の正本ではない。採用したピクトグラムの形は `frontend/src/games/reflection/assets/pictogram.svg` を正とする。制作手順と評価方法は `.claude/skills/design-game-pictogram/`（`SKILL.md`、`references/method.md`）を正とする。

記述は次のように区別する。

- **事実（リポジトリ）**: 現在のコード・文書から確かめたこと。
- **事実（実測）**: 候補 SVG を実表示サイズで描画して比べたときに見えたこと。見え方の記述は、比較画像を AI が見て書いたもの。候補 SVG は代表案だけをリポジトリに残している（§6）。
- **判断**: 上から導いた推奨と理由。

人間による方向の選択はまだ行っていない。Skill は方向を人間に選ばせる手順だが、本実装では人間のレビューを全段の実装後に1回だけ行うので、AI が推奨案で仮に決めた（[リフレクション実装前提調査](リフレクション実装前提調査.md) §19）。最終レビューで選び替えられるように、代替の候補も同じ品質まで仕上げている（§5.2、§6）。

---

## 1. 結論

- 推奨案は **P1（2回曲がってブラックホールへ届く光）**。淡色の細い枠（盤）の左の外に入口の点があり、そこから入った光（濃色の太い線）が右下がりの鏡2枚で下・右へ曲がり、右下のブラックホール（濃色の塗りの円）で止まる。
  - 入口の点と、線の形はプレイ画面の光路（外周ヒントを押したときの表示）と同じ描き方にした。鏡とブラックホールはプレイ画面のピースと同じ形（斜めの1本線と塗りの円）。
  - 「外から入れた光が、見えないピースで曲がる・吸い込まれる」という、このゲームの推理の題材を1枚で示す。
- 推奨の理由は次の3つ（§4.2）。
  - 光と鏡というゲーム名そのものの題材を、プレイ画面の見た目のまま描く。
  - 一覧の 46〜56px でも、点・折れ線・鏡・円が見分けられる。
  - 一覧で唯一「濃い外枠を持たない」形になり、ほかの6つと見分けやすい。
- 見直すときの主な論点は次の4つ（§5.1）。有力な代替は P2・P3・G2・C2（§5.2）。
  - 光で描くか、ピースで描くか。
  - 盤の枠を淡色にするか濃色にするか（一覧での重さ）。
  - 格子を描くか。
  - 吸収・退出・反射のどの結果を描くか。

## 2. 目的と制約

### 2.1 目的

ゲーム一覧でリフレクションを素早く見分けられ、ゲーム自身の姿を保ち、既存のピクトグラムと並べても強さが突出しないこと（`DESIGN.md`「ゲームピクトグラム」、`references/method.md` §1）。

### 2.2 制約（事実（リポジトリ））

- 共通描画契約（`SKILL.md`）
  - `viewBox="0 0 120 120"`。
  - 線幅は 4 と 2 だけ。
  - 色は `var(--game-pictogram-strong)` と `var(--game-pictogram-soft)` の2色だけ。
  - `check_svg.py --max-colors 2 --forbid-gradients --forbid-filters --forbid-external-images --forbid-text` を通す。
- 色は `GamePictogram` が与える。ライトとダークでは前景色と補助情報色、結果画面では `currentColor` になる。どのテーマでも読める形にする。ピースを光路から切り離す背景色の縁（プレイ画面の描き方）は、2色の規格では使えない。
- 実表示サイズ（Playwright で SVG の大きさを実測）
  - ゲーム選択のヒーロー: 177px（1280px 幅）/ 138px（390px 幅）。
  - 一覧のカード: 56px（1280px 幅）/ 46px（390px 幅）。
  - 結果画面: 48px（段10で使う）。
  - 一覧の 46〜56px が最も厳しい。
- 比べる既存ピクトグラム: ウォーターソート、ナンプレ、マインスイーパー、パーキングジャム、スライドパズル、バイナリパズル。ウォーターソート以外の5つは濃色の太い外枠（パーキングジャムは出口の切れ目つき）を持ち、ナンプレ・マインスイーパー・スライドパズル・バイナリパズルはその中を格子で区切る。
- プレイ画面の見た目（[リフレクション実装前提調査](リフレクション実装前提調査.md) §19「ピースの形」「外周ヒントの結果の形」「光路の見せ方」）
  - 斜め鏡は向きの違う1本線、両面鏡は2本線、反射体は四角の輪郭、ブラックホールは塗りの円。
  - 外周ヒントは数字と結果の形（退出は斜めの矢印、反射は折り返す矢印、吸収は塗りの点）。
  - 光路は入口に点、外へ出た位置に外向きの三角の矢印。
- 表示名は作業名「リフレクション」（`frontend/src/games/reflection/display-name.ts`）。SVG の `aria-label` もこれに合わせる。`GamePictogram` は SVG を `aria-hidden` で描画するので、読み上げには使われない。正式名が決まったら SVG の `aria-label` も直す。

## 3. 比べた方向と分かったこと

| 方向 | 候補 | 比べたこと |
| --- | --- | --- |
| 光の道筋を描く | A1 1回曲がる、A2 2回曲がる（Z）、A3 同じ辺へ戻る（U）、A4 吸収、A5 光の当たらないピースも置く、G 盤を淡色、H 光を淡色、P1〜P3・G2（仕上げ） | 光と盤のどちらを濃くするか、格子の有無、曲がる回数と結果 |
| 外周ヒントを描く | B 外周に結果の形を並べた盤、B2 小さな盤と光 | 外から推理する構造が小サイズで残るか |
| ピースを描く | C 6種の手持ち、C2（仕上げ） | 光なしでゲームが分かるか |

### 3.1 着眼点

次の着眼点から候補を作った。

- 光路: 1回曲がる、2回曲がる（階段・Z）、同じ辺へ戻る（U）、反射体で折り返す、ブラックホールで止まる、盤を貫く、潜望鏡のような2枚の鏡。
- 盤と外周: 外周に数字が並ぶ盤、外周に結果の形（矢印・折り返し・点）が並ぶ盤、盤の外から光が入る切れ目、中が見えない箱。
- ピース: 斜め鏡1枚の拡大、6種の手持ち、両面鏡が光を通す向きと跳ね返す向き、光の当たらないピースを淡色で置く。
- 光の象徴: プリズム、懐中電灯、レーザーポインタ、入射角と反射角の図、光線の放射、万華鏡。
- 遊び: ピンボール、迷路の道筋。

候補にしなかったもの（判断）:

- プリズム・懐中電灯・レーザーポインタ・光線の放射・万華鏡: 光の汎用記号で、盤に置くパズルに結びつかない。
- 入射角と反射角の図: 理科の図に見え、ゲームの盤を持たない。
- 中が見えない箱（「?」など）: 意味が抽象的で、説明に頼る。
- ピンボール・迷路: 別の遊びとして誤認される。
- 外周に数字が並ぶ盤: 数字を小さく多く描くことになり、50px 前後で模様になる（外周の形で代表させて B で確かめた）。

### 3.2 濃い外枠と格子の盤に光（事実（実測））

最初は既存ピクトグラムにそろえ、濃色・線幅4の外枠と淡色の 3×3 格子の中に、濃色・線幅2の光と濃色・線幅4の鏡を置いた（A1〜A5）。外枠には光が通る位置に切れ目を入れた。

- 138px では光の道筋が読めるが、46〜56px では光の線が格子の線と同じ細さに見え、盤の模様に溶けた。
- 外枠の切れ目は、光の出入りというより外枠が途切れた・壊れたように見えた。
- 濃い線が外枠・光・鏡の3種類になり、同じ強さの線が多すぎた（`DESIGN.md` の「同じ強さの線を反復しすぎない」に反する）。
- A4（吸収）は、ブラックホールの円が 46px でも残り、ほかより読みやすかった。
- A5（光の当たらない反射体とブラックホールを淡色で置く）は、「盤にピースを置く」感じは出るが、46px では淡色の小さな形が汚れに見えた。

### 3.3 光を主役にする（事実（実測））

- 盤を淡色・線幅2の枠にし、格子をなくし、光を濃色・線幅4にすると（G・P1〜P3）、46px でも光の折れ線がはっきり読めた。盤は「光が入っていく場所」として一段退いて見えた。
- 逆に外枠を濃色のまま光を淡色にすると（H）、46px で光が灰色の細い線になり、主役が外枠に移った。
- 淡色の格子を残すと（G・G2）、格子の線が光の線と交わり、46px で網目の中の折れ線になった。盤のマスの感じは出るが、読み取りの手間が増えた。
- 光の線を鏡に当てる（鏡の面まで伸ばす）か、手前で止めて隙間を空けるかを比べた。隙間を空けると、46px で光が切れ切れの線分に見えた。当てた方が「鏡で曲がる」一続きの光に見えた。

### 3.4 外周ヒントとピース（事実（実測））

- B（盤の外周4辺に、退出・反射・吸収の結果の形を3つずつ）は、138px では外から推理する構造が見えたが、46〜56px では結果の形が点の粒になり、盤の周りの飾りに見えた。
- B2（盤を小さくし、外から入る光を足す）は、濃い外枠の中の光が小さくなり、A 系の弱点が強まった。
- C（外枠を 3列×2行 に区切り、6種のピースを1つずつ）は、46px でも6つの形が見分けられた。ただ光がないので「形の違う記号の一覧」に見え、光のパズルだとは分からない。外枠と区切りの構成はバイナリパズルとほぼ同じになった。

### 3.5 仕上げ（事実（実測））

P1 の細部は次を比べた。

- 鏡の長さ（半分の長さ 11 / 12 / 13）とブラックホールの半径（10 / 11 / 12）: 13・12 は 138px で鏡が盤の中で窮屈に見え、11・10 は 46px で円が小さかった。12・11 を採った。
- 盤の枠の位置: 光の入口が枠の左の外へ出る分だけ、全体が左へ重く見えたので、盤を右へ2ずらした（枠は x=22..102）。

## 4. 推奨案 P1

### 4.1 仕様（事実（リポジトリ））

- 盤: `x=22 y=20 width=80 height=80`、`rx=2`、淡色、線幅2。格子は描かない。
- 光: 濃色、線幅4、線端は丸。入口の点（半径5）が盤の左の外（x=10, y=38）にあり、右へ進んで x=44 の鏡で下へ、y=82 の鏡で右へ曲がり、ブラックホールに届く。線は鏡の面まで伸ばす（鏡の中心から 4√2 手前で止める）。
- 鏡: 右下がりの斜めの1本線を2枚。中心は (44, 38) と (44, 82)、半分の長さ 12、濃色、線幅4、線端は丸。
- ブラックホール: 中心 (84, 82)、半径 11、濃色の塗り。
- 光学中心の補正: 右へ2。光の入口が盤の左の外へ出るため、盤を中央に置くと左へ重く見えた。138px と 46px で確かめた（事実（実測））。
- 色は strong / soft の2色だけ。`check_svg.py` の2色・gradient / filter / 外部画像 / text 禁止の検査を通る。

### 4.2 推奨理由（判断）

- **意味的距離**
  - このゲームの推理は「外から入れた光がどう曲がり、どこで出る・戻る・止まるか」から中のピースを決めること。P1 はその光の道筋を、プレイ画面の光路と同じ描き方（入口の点、太い線）で描く。
  - 鏡は斜めの1本線、ブラックホールは塗りの円で、プレイ画面のピースと同じ形。遊び始めたときに見る盤と結びつく。
  - ゲーム名（リフレクション＝反射）に最も直接つながるのは、鏡で光が曲がる形。
- **実表示サイズ**: 要素は点・折れ線・鏡2枚・円の5つだけ。46px でも光の折れ線と円が読め、鏡が光の曲がり角に斜めに当たっているのも見えた（事実（実測））。
- **弁別性**
  - 一覧で濃い外枠を持たないのはウォーターソートとリフレクションだけで、盤の形（淡い四角）を持つのはリフレクションだけ。ナンプレ・マインスイーパー・スライドパズル・バイナリパズルの「濃い外枠＋格子＋記号」と見分けられた（事実（実測））。
  - 盤の外から中へ伸びる線は、ほかのどのピクトグラムにもない。
- **光学的重量**: 濃色は光・鏡・点・円だけで、線幅4の線が外枠の代わりに主形状になる。一覧では格子のあるピクトグラムより軽いが、ウォーターソート・パーキングジャムと並べて突出しない（事実（実測））。
- **一覧の描画言語**: 主形状（濃・4）と補助情報（淡・2）の2段階の線を使う（`DESIGN.md`）。既存ピクトグラムの「外枠が主形状、中身が補助」とは役割が逆になるが、2段階の線という規則は守る。

### 4.3 弱点（判断）

- 一覧では、濃い外枠を持つピクトグラムより一段軽く見える（46〜56px）。
- 格子がないので、盤のマスに置くパズルという感じは弱い。淡色の四角を盤と読まない人には、光の図だけに見えうる。
- 外周ヒントの数字と結果の形（推理の手がかり）は描いていない。手がかりから推理するゲームだということは伝わらない。
- 描いた結果は「吸収」だけ。退出・反射はプレイ中によく見るが、ピクトグラムには出ない。
- ダークテーマでは光とブラックホールが明るい前景色になり、ブラックホールが光る円に見える。既存ピクトグラムも同じ前景色の規則に従うので、ここだけ変えることはしない。

## 5. 再検討するときの論点

### 5.1 論点

- **光で描くか、ピースで描くか**: 光（P1〜P3）はゲーム名と推理の題材に近い。ピース（C2）は6種の形がそのまま見えるが、光がなく記号の一覧に見える。
- **盤の枠を淡色にするか濃色にするか**: 淡色（P1）は光が主役になり 46px でも読めるが、一覧で一段軽い。濃色（A 系・H）は一覧の重さがそろうが、光が枠に負ける。一覧の重さを重く見るなら、淡色の枠のまま光の線幅（4 が上限）ではなく、円や鏡を大きくする方向で補う。
- **格子を描くか**: 格子あり（G2）は盤のマスの感じが出るが、46px で光が網目に紛れる。
- **どの結果を描くか**: 吸収（P1）は円が小サイズで強く残る。退出（P2）は外へ出る矢印で「光が抜ける」動きが出て、プレイ画面の矢印と同じ形になる。反射（P3）は入口と出口が同じ辺に並び、ゲームに特有の「戻ってくる」結果を示すが、プレイ画面の「反射」（同じ位置へ戻る）とは違い、同じ辺の別の位置へ出る「退出」の形になっている。

### 5.2 候補の一覧と代替案

| 案 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| **P1 2回曲がって吸収**（推奨） | 淡色の盤、入口の点→右下がりの鏡2枚→ブラックホール | 光・鏡・ブラックホールの3つをプレイ画面の形で描く。46px でも円が残る | 一覧で一段軽い。格子なし。外周ヒントなし |
| P2 2回曲がって退出（Z） | 淡色の盤、入口の点→右上がりの鏡2枚→盤の右の外へ矢印 | 光が抜ける動きと矢印。左下から右上への対角で均衡する | 盤の外へ出る線が左右にあり、外形が横に広い |
| P3 同じ辺へ戻る（U） | 淡色の盤、入口の点→鏡2枚→左の外へ矢印 | 入口と出口が同じ辺に並び、外から探る感じが出る | プレイ画面の「反射」とは意味が違う（§5.1）。左に矢印と点が集まる |
| G2 格子つきの吸収 | P1 に淡色の 4×4 格子を足す | 盤のマスに置くパズルに見える | 46px で光が網目に紛れる |
| C2 6種の手持ち | 濃い外枠を 3列×2行 に区切り、6種のピース | 6種の形がそのまま見える | 光がなく記号の一覧に見える。バイナリパズルと構成が近い |
| H 光を淡色（Z） | 濃い外枠（切れ目つき）、淡色の光、濃色の鏡 | 一覧の重さがそろう | 46px で光が灰色の細い線になる |
| A2 濃い外枠と格子（Z） | 濃い外枠（切れ目つき）＋淡色の格子＋濃色の細い光 | 既存ピクトグラムと同じ階層 | 光が格子に溶け、外枠の切れ目が壊れて見える |
| B 外周の結果の形 | 盤の外周に退出・反射・吸収の形を3つずつ | 外から推理する構造 | 46〜56px で点の粒になる |

推奨順は P1 > P2 > P3 > G2 > C2（判断）。部分採用もできる（例: P1 の吸収の終点を P2 の矢印に替える、P1 の盤を濃色にして鏡と円を大きくする）。

### 6.1 選び替える手順

1. 採る候補の SVG を `frontend/src/games/reflection/assets/pictogram.svg` へ複製する。`aria-label` は表示名（`REFLECTION_DISPLAY_NAME`）に合わせる。
2. 最終検査を通す。

   ```sh
   python3 .claude/skills/design-game-pictogram/scripts/check_svg.py frontend/src/games/reflection/assets/pictogram.svg \
     --max-colors 2 --forbid-gradients --forbid-filters --forbid-external-images --forbid-text
   ```

   ```sh
   python3 .claude/skills/design-game-pictogram/scripts/make_review_sheet.py \
     --output /tmp/reflection-pictogram-review.html --size 112 \
   ```
