- **導出**: 定義から論理的に導けること。
- **推測・仮説**: 実プレイで確かめていない判断。

まだ誰も実際に遊んで確かめていない。§11 の試遊が済むまで、各レベルの体験差は仮説として扱う。

## 3. リフレクション固有の挑戦

### 3.1 挑戦の定義（前提調査 §14.1 のまま）

> 外周ヒントの観測結果から、見えないピースの位置と種類を1つずつ確定させ、1本の光路で決まらないときは複数の光路・手持ちの残数・仮定の帰結まで読んで確定させること。

### 3.2 挑戦を強くするもの（仮説）

1. 1本のヒントでは決まらず、複数のヒントを照らし合わせる必要がある。
2. 1つ決まったことを別のヒントへ繰り返し持ち込む連鎖が長い。
3. 光路だけでは決まらず、手持ちの残り数を使う必要がある。
4. 候補を仮に置いて、その先の矛盾まで読まないと決まらない。
5. 一致表示があっても、外周ヒントを1本ずつ試し置きで満たす進め方では押し切れない。複数の外周ヒントが同じピースを取り合い、1本を直すと別の1本が崩れる（ヒント間の干渉）（4回目の人間レビューで追加。§16.2）。
6. 盤面が広く光路が長いので、1本の外周ヒントの候補（通り得る道筋）が多い（§16.2）。

### 3.3 挑戦にしないもの

- 盤面サイズ・ピース数だけによる作業量の増加（単独ではレベルを決めない。上位レベルの盤面を広げたのは、広い盤面で 5・6 の挑戦が強まり、推論レベルと試し置きの特徴で分けられるから（§16.3））
- 光路を頭の中で追い続ける作業記憶の負担（光路表示で軽減する）
- ピースの見分けにくさ・セルの押しにくさ、タップ回数・所要時間そのもの

## 4. 分析モデル（人間向け解法器）

`frontend/src/games/reflection/problem/generation/human-solver.ts` の `traceReflectionHumanSolve` が、手持ちと外周ヒントだけから（解を見ずに）各マスの候補を絞る。

### 4.1 推論レベル

| レベル | 推論 | 分析器での扱い |
| --- | --- | --- |
| L1 | 単一ヒント | 1本のヒントを満たす光路がどれも必ず通るマスで、その光路で使われ得るピース（または空き）が1つだけなら決める |
| L2 | 直接整合性 | マスとピースの候補を1つ固定し、全ヒントのどれかが満たせなくなる候補を除く（1回） |
| L3 | 制約伝播 | L2 を変化が無くなるまで繰り返す |
| L4 | 在庫 | L2 に、手持ちの残り数（使い切った種類を他のマスから除く、置ける場所の数が残り数と同じならそこへ置く）を交互に加えて繰り返す。L2 で照らす光路も、置き場所の決まっていないマスへ使うピースを種類ごとの残り数までに限る（例: `\` があと1個なら、`\` を2個使わないと届かない光路は考えない） |
| L5 | 仮定と矛盾 | 候補を1つ仮に置き、L2〜L4 を進めた先で矛盾が出る候補を除く。除けたら L2〜L4 を進め直す |

浅いレベルで手持ちの全ピースの置き場所が決まればそこで止め、決まらなければ次のレベルを加える。問題の推論レベルは、決め切るまでに使った最も深いレベル（`highestLevel`）である。

光路は、通るマスごとに1つのピース（または空き）を決めた並びとして扱う。同じマスを2回通るなら同じピースとみなす。ヒント1本ごとに、候補の範囲で置ける光路をすべて並べ、「どの光路も必ず通るマス」と「マスごとに使われ得るピース」を求める（導出）。

ヒント1本の光路を並べる探索が 20,000歩を超えたら、そのヒントはその回の推論に使わない（候補を絞らない）。置き場所の決まっていないマスが多いうちの長いヒントは、光路が膨大になって人間もまだ使えない、とみなす。上限を10倍にしても §6 の 3,300問で最高推論レベルが変わるのは8問で、どれも1段浅くなるだけだった（事実（実測。一時スクリプト））。

### 4.2 研究用 Python（PoC）との違い

レベルの手順（L1→L5 の順、各レベルの適用の仕方、仮定を試す順＝マスの並び順・ピースの番号順、特徴の数え方）は PoC の `scripts/research/reflection_difficulty_experiment.py` の `analyze_problem` と同じにしている。光路の扱いだけを次のように厳しくした（導出）。

| 観点 | PoC（と段05の最初の移植） | 現在 |
| --- | --- | --- |
| 同じマスを2回通る光路 | 距離ごとの状態の並びとして扱い、1回目と2回目で別のピースを使う並びも光路に数える | 同じピースとして扱う。別のピースとして通る並びは実際の配置にならないので数えない |
| L4 の光路とピースの残り数 | 光路は残り数を見ない | 置き場所の決まっていないマスへ使うピースを種類ごとの残り数までに限る |

PoC の扱いは、実際には置けない光路まで候補を支える根拠に数えるので、L2〜L4 で決まるはずの候補が残り、推論レベルが深い側へずれていた。人間は同じマスに2つのピースがあるとは考えず、`\` があと1個しかないのに2個要る光路も考えない。そこで [難易度開発手順.md](../../難易度開発手順.md) 工程10 の「特徴量の意味や計算が誤っていないか」に当たるとして直した。

段05の最初の移植は PoC と 123問（5×5 の 2・3・4・6・8・10ピース、6×6 の 6・9ピース、7×7 の 8・10ピース）で全特徴が一致することを確かめていた（事実（実測。一時スクリプト））。直した後は PoC と一致しない。

直す前と後の最高推論レベル（§6 の 3,300問、行が直す前、列が直した後）（事実（実測））:

| 直す前＼後 | L1 | L2 | L3 | L4 | L5 |
| --- | ---: | ---: | ---: | ---: | ---: |
| L1（164） | 164 | 0 | 0 | 0 | 0 |
| L2（141） | 26 | 115 | 0 | 0 | 0 |
| L3（1,161） | 96 | 226 | 837 | 2 | 0 |
| L4（1,080） | 0 | 0 | 212 | 868 | 0 |
| L5（753） | 0 | 0 | 35 | 581 | 137 |
| 評価不能（1） | 0 | 0 | 0 | 0 | 1 |

直す前の L5 の82%が L4 以下になった。L3 → L4 の2問は、光路を並べ切れないヒントを使わないこと（§4.1）で、直す前の緩い光路なら使えた手がかりが無くなったもの。

手で追った例（導出）:

- `rf-5-2-87`（`\` 2個、解 `..... ...\\ ..... ..... .....`）: L1 で右2行のヒント（距離2で退出）から5列2行が `\` に決まる。残りの `\` は1個。左2行のヒントは距離7で退出なので、2行目を右へ進んで1個の `\` で下へ曲がり、ちょうど7マス目で抜ける位置は4列2行だけ。直す前は `\` を3個使う光路（3列2行→3列3行→4列3行で曲がる）も数えていたため決まらず、仮定を使って L5 になっていた。光路を残り数までに限ると L4 で決まる（同じマスの扱いを直すだけでは L5 のまま）。
- `rf-6-9-25`（直す前は仮定1回の L5）: これも光路を残り数までに限ることで、最後の1個が L4 で決まる。
- `rf-5-5-9`（直す前の L5 の代表）: 同じマスを別のピースとして通る光路を除くと、L3 と L4 だけで決まる。
- `rf-5-7-36`（直した後も L5）: L4 まで使っても 1行2列の候補（`\`・両面鏡2種・空き）が残る。1行2列を空きと仮に置くと、伝播の先で矛盾が出て、そこから7個すべてが決まる。仮定の帰結を読む必要がある問題として L5 に残るのは妥当（推測）。

### 4.3 既知の一意解を落とさないこと

`human-solver.test.ts` で、生成した32問（5×5 の 2・3・4・6・8ピース、6×6 の 5・8ピース、7×7 の 10ピース、各4問）について、候補を絞るたびに既知の解が全マスの候補に残っていることを確かめる。代表6問では、決め切った後の候補が解のピースの置き場所だけを指すことも確かめる。§6 の 3,300問でも、解を落とした問題は0だった（事実（実測。一時スクリプト））。

これは完全性の証明ではなく、候補削減が既知の解と矛盾しないことの回帰検査である。

### 4.4 評価できる範囲

`frontend/src/games/reflection/problem/difficulty-analysis.ts` の `analyzeReflectionDifficulty` は、完全解法器で一意性を確かめてから推論を追う。

| 状態 | 条件 |
| --- | --- |
| `analyzed` | 一意解で、L1〜L5 で置き場所を決め切れた |
| `unsupported`（評価不能） | 一意解だが、L5 まで使っても決まらないマスが残る（`unresolved`）、または仮に置いて試す回数が1問1,000回の上限に達した（`assumption-limit-reached`。4回目の人間レビューで追加。§16.5） |
| `invalid` | 解が無い、2つ以上ある、または一意性の探索が上限（探索量 400万）に達した |

§6 の 3,300問に `unsupported` は無かった（事実（実測））。直す前（§4.2）に評価不能だった `rf-7-12-50` も L5 で決め切れる。4回目の人間レビューの問題集合（§16.3、生成器の版 3、1,560問）では、評価不能は 49問（すべて仮定の上限。8×8 以上の多ピース）だった。

## 5. 特徴量

| 特徴 | 意味 | 分類に使うか |
| --- | --- | --- |
| `highestLevel` | 決め切るのに要った最も深い推論レベル | 使う（レベルの挑戦の中身） |
| 盤面サイズ `size` | 読む範囲（外周ヒント 4n 本） | 使う（範囲として） |
| ピース数 `pieceCount` | 置く対象の数 | 使う（範囲として） |
| `fixedPieceCountByLevel` | 各レベルの推論で新しく決まったピースの数 | 記録のみ |
| `propagationRoundCount` | 直接整合性・在庫で候補が変わった回数 | 記録のみ |
| `assumptionTestCount` / `assumptionEliminationCount` | 仮に置いた回数と、矛盾で除いた候補の数 | 記録のみ |
| `pieceKindCount` | 手持ちの種類の数 | 記録のみ |
| `trial.solved` / `trial.retryCount` | 一致表示を見ながら外周ヒントを1本ずつ満たす試し置き（試行ソルバー、§16.2）で解き切れたか、一致を崩したり置き方を変えたりした手の数 | 使う（レベル4・5 の下限。4回目の人間レビューで追加） |
| `trial.moveCount` | 試行ソルバーの手数 | 記録のみ（速さの基準時間に使う。成績評価 §5） |

記録のみの特徴は、試遊でレベル内の差（例: 仮定を1回だけ使う L5 と何度も使う L5）が問題になったときに使う候補として残す。

## 6. 問題集合

### 6.1 手持ちの抽選の変更（generatorVersion 2）

段02の生成器（版 1）は研究用の供給実験に合わせて、基本の鏡4種（`/`、`\`、縦・横の両面鏡）を先頭から必ず含めていた。そのため2ピースの問題は必ず `/` と `\` の1個ずつになる。一方、PoC の難易度分布は6種から等確率に選ぶ手持ちで測っていた。

5×5 で手持ちの選び方を変えて各60問を分析した（事実（実測。一時スクリプト）。§4.2 で直した後の分析器で測り直した値）。

| 6種から等確率 | 2 | 35 | 21 | 4 | 0 | 0 |
| | 3 | 18 | 23 | 17 | 2 | 0 |
| | 4 | 7 | 17 | 32 | 4 | 0 |

版 1 の選び方では、L1 がどのピース数でも現れず、レベル1を供給できない。**6種から等確率に選ぶ方式へ変え、`REFLECTION_GENERATOR_VERSION` を `"2"` に上げた。** identity の形（`{ generatorVersion, seed, conditions: { size, pieceCount } }`）は変えていない。版 1 の identity は `isReflectionRecordedProblemIdentity` で記録として読めるが、今の生成器では再現しない。版 1 で残した記録・問題集はまだ無い。

### 6.2 条件

- 盤面 5×5・6×6・7×7 × ピース数 2〜12 の33条件、各100問（`rf-<size>-<pieceCount>-<0..99>`、生成器の版 2）
- 生成器の作り直し（全ピースの影響・一意性を満たさない候補の作り直し）の平均は 1.34 候補、最大14候補

### 6.3 再現手順

### 7.2 規模への依存

- 最高推論レベルとの Spearman 順位相関は、ピース数 0.707、盤面サイズ 0.099、手持ちの種類の数 0.666（analyzed 3,300問）。
- 33条件のすべてで、3種類以上の推論レベルが混ざる。同じ規模でも推論レベルは1つに決まらない。
- L1・L2 は盤面を広げても減らない（2ピースの L1 は 5×5 で56、6×6 で50、7×7 で57）。深い推論はピース数で増え、盤面サイズではほとんど増えない。
- L5 は少ない。最も多い 7×7/12 でも25問で、11ピース以下では多くの条件で1割に満たない。

盤面サイズは推論の深さをほとんど説明しない。ピース数は推論の深さと強く関係するが、同じピース数でも複数のレベルが混ざる（PoC の ρ≈0.668 とほぼ同じ）。

### 8.2 採用する組み合わせ定義（4回目の人間レビューで作り直した E）

推論レベルがちょうど一致し、盤面サイズとピース数が範囲（両端を含む）に入り、試し置きの下限を満たす問題だけをそのレベルに分類する。試し置きの下限は「試行ソルバー（§16.2）で解き切れない、または一致を崩したり置き方を変えたりした手（やり直し）がその回数以上要る」こと。

| レベル | 最高推論レベル | 盤面サイズ | ピース数 | 試し置きのやり直し | 利用者にとっての変化（案） |
| ---: | --- | --- | --- | --- | --- |
| 1 | L1 | 5×5 | 2〜4 | 問わない | 1本のレーザーを見れば、置く場所と種類が決まる |
| 2 | L2 | 5×5〜6×6 | 2〜4 | 問わない | 候補を他のレーザーと照らし合わせて絞る |
| 3 | L3 | 6×6〜7×7 | 4〜8 | 問わない | 1つ決まると別のレーザーの候補が減り、連鎖して決まる |
| 4 | L4 | 7×7〜9×9 | 8〜16 | 3回以上（または解けない） | 手持ちの残り数も手がかりにする。1本ずつ合わせていくと別のレーザーが崩れる |
| 5 | L5 | 9×9〜11×11 | 16〜18 | 15回以上（または解けない） | 広い盤面で、仮に置いた先の矛盾まで読まないと決まらない。1本ずつの試し置きでは押し切れない |

- 推論レベルを1段ずつ上げ、規模の範囲と試し置きの下限は両端とも下げない。上位のレベルは、下位のレベルが要る推論をすべて含む（L5 の分析は L1〜L4 を先に使い切っている）（導出）。
- 隣り合うレベルは同じ規模を共有する（1/2 は 5×5・2〜4、2/3 は 6×6・4、3/4 は 7×7・8、4/5 は 9×9・16）。共有する規模では、推論レベルと試し置きのやり直しでだけレベルが分かれる（§16.4）。規模だけでレベルが上がる・下がることはない。
- レベル1〜3 には試し置きの下限を置かない。L1〜L3 の問題はほとんどが試し置きでも崩さず解ける（試行ソルバーのやり直しの中央値0）ので、下限を置くとレベル1〜3 を供給できない。この帯は「読めば速い、試しても解ける」挑戦として扱う（推測。§11 で確かめる）。
- 定義はデータ（`reflectionLevelCombinations`）で持ち、境界を変えるときは値だけを直す。

| 判定 | 条件 | 扱い |
| --- | --- | --- |
| 評価不能（`unsupported`） | 一意解だが L5 まで使っても決まらない | 提供しない。レベル5へ押し込まない |
| 組み合わせ外（`out-of-range`） | 推論レベルと規模と試し置きの組がどのレベルの定義にも当たらない（例: 5×5 の L5、8×8 の L3、6×6・2ピースの L1、レベル5 の規模の L5 で試し置きで押し切れるもの） | 提供しない。近いレベルへ寄せると、そのレベルの規模の範囲や試し置きの下限が崩れる |

### 8.6 ピース種の段階導入（不採用）

前提調査 §14.3 は「下位は斜め鏡だけ → 上位で6種」のような段階導入を候補にしていた。採らない。

- 斜め鏡だけの手持ちは、むしろ推論が深くなる。5×5・4ピースで L4 が60問中31問（6種等確率では4問）、3〜4ピースの L1 は0問だった（§6.1）。
- 浅い推論の問題はブラックホールや反射体を多く含む（§7.3）。「斜め鏡から始める」順序は推論の深さと逆になる。
- 種類を絞るとレベル1・2 の供給がさらに細くなる。

したがって全レベルで6種を等確率に抽選し、どの種類が出るかは分類の結果に任せる。遊び方は6種すべてを説明する前提のまま（段04）。段08 の「上位が下位の構成を含む入れ子」は、ピース種ではなく推論レベルと規模の範囲（§8.2）について確かめる。

## 11. 人間のプレイで確かめること

§10 の問題をラベルを伏せて遊び、少なくとも次を確かめる（前提調査 §21 の必須1）。

- レベル1→5で、推理の深さが概ね増えると感じるか。

- 弱い L5・伝播の長い L4 のような問題で、機械判定と体感が逆転しないか。
- 外周ヒントごとの一致表示（2026-09-28 の人間判断で採用。前提調査 §11.4）がある状態で遊び、推論レベルの差が残るか。

- 11×11 のマス・外周ヒントの小ささ（320px で約23px）が、挑戦ではない負担（読み取りにくさ）になっていないか。

## 13. 限界と未解決

- 分析モデルは PoC の L1〜L5 の手順のまま（光路の扱いだけ厳しくした。§4.2）。人間が使う「光路を両端から読む」「退出ヒント同士を対応付ける」などの手筋を個別には表していない。
  - 退出ヒント同士の対応付け: 光は逆向きにも同じ道を通るので、入口 A から出口 B へ抜ける光路があるなら、B のヒントも「退出・同じ距離」でなければならない。今の L2 はヒントを1本ずつ候補に照らすだけなので、この対応を直接は使わない。一時スクリプトでこの制約を光路に加えると、§6 の 3,300問で L5 は138問から65問に、L4 は1,451問から1,353問に減った。§10.3 の `rf-7-3-89` も L4 になる（事実（実測。一時スクリプト））。加えると レベル5 の供給は各条件1割未満になる。人間が実際にこの対応付けをどの程度使うかを試遊で確かめてから採否を決める（最終レビュー論点）。
- ヒント1本の光路を並べる探索に上限（20,000歩）があり、上限を超えたヒントはその回の推論に使わない（§4.1）。上限の値で結果が変わる問題はわずか（3,300問中8問）だが、上限は人間の能力を測ったものではない。
- 分析時間は盤面が広いほど長い（§16.3 の問題集合で 11×11 の最大126秒）。実行時に分析することはせず、問題集の生成時だけに使う。検証情報でも、問題集の問題は問題集のレベルを示し、問題集に無い 8×8 以上の問題は分析しない。
- 試行ソルバー（§16.2）は、一致表示を見ながら1本ずつ満たす単純な進め方の代理で、人間の試し置きそのものではない。人間は光路表示で道筋を見たり、読みと試しを混ぜたりする。やり直しの回数の絶対値ではなく、「試し置きだけで押し切れるか」の目安として使う。手の順（狙う外周ヒント、試すマスと種類の順）を変えると回数は変わる。
- レベル4・5 の試し置きの下限（3回・15回）は、問題集合の分布から置いた暫定値で、人間の体感で確かめていない。
- 仮に置いて試す回数の上限（1,000回）と、一意性の探索量の上限（400万）は、分析と生成の時間を抑えるための値で、人間の能力を測ったものではない。上限で除かれる問題は評価不能・不成立として提供しない。
- 人間のプレイでの確認はまだ無い。

## 16. 一致表示と盤面の拡大に合わせた作り直し（4回目の人間レビュー、2026-09-28）

### 16.1 指摘と方針

プロダクトオーナーの指摘（原文）: 「レベル5でも簡単すぎる」「9x9は普通にいける」「11も操作的にはいけるな」。以前から、5段階は単一軸や規模だけに頼らず人間の挑戦として意味を持つこと（パーキングジャムでは単一軸案が不採用）を求めている。

- 1回目の人間レビューで外周ヒントごとの一致表示（前提調査 §11.4）を採用した。配置のたびに、どの外周ヒントが目標と合ったかが緑で分かる。人間向け解法器（§4）は一致表示の無い前提で推論の深さを測っていたので、「試し置きで1本ずつ合わせる」進め方の強さが難易度に入っていなかった。
- そこで [難易度開発手順.md](../../難易度開発手順.md) 工程10 の順に、(1) 基準とするプレイ条件を「一致表示を見ながら遊ぶ」に改め（§2）、(2) 観測できていなかった挑戦（ヒント間の干渉）を特徴量として足し（§16.2）、(3) 盤面の上限を 11×11 まで広げた問題集合で分布を見て（§16.3）、組み合わせ定義を作り直した（§8.2）。閾値だけを動かして合わせることはしていない。

### 16.2 一致表示がある前提での難しさ（仮説と特徴量）

一致表示では各外周ヒントの正否がすぐ分かるので、人間は「合っていない外周ヒントを1本選び、その光路の上にピースを置いて緑になるか見る」局所的な試行で進められる（推測）。この進め方で押し切れない問題が、一致表示があっても難しい問題である、と仮説を立てた。

- 押し切れない理由（推測）: 複数の外周ヒントが同じピースを取り合い、1本を直すと別の1本が崩れる（干渉）。光路が長く、1本の光路の上に置き場所の候補が多い。
- 観測する特徴: 試し置きを真似る決定的な **試行ソルバー**（`frontend/src/games/reflection/problem/generation/trial-solver.ts` の `traceReflectionTrialSolve`）を動かし、解き切れたか（`solved`）、一致を崩したり置き方を変えたりした手の数（`retryCount`）、手数（`moveCount`）を取る。

試行ソルバーの進め方（推論はしない）:

1. 合っていない外周ヒントのうち距離の短い順（同じなら外周の並び順）に1本を狙う。全て合っていてピースが残っていれば、置き場所を探す。
2. 狙った外周ヒントの今の光が通るマスだけを動かす。空きマスには手持ちの各種類を置き（手持ちが無ければ光路の外に置いたピースを移し）、ピースのあるマスは手持ちの別の種類と入れ替えるか手持ちへ戻す。一度通った盤面には戻らない。
3. 狙った外周ヒントが合い、合っていた外周ヒントを崩さない最初の手を打つ（崩さない一致）。無ければ、狙った外周ヒントが合う手のうち一致の数が最も多い最初の手（崩す一致。やり直しに数える）、一致の数を増やす最初の手の順に探す。どれも無ければ次の外周ヒントを狙う。全て無ければ、一致の数を減らさない最初の手、それも無ければ一致の数が最も多く残る最初の手を打つ（回り道。やり直しに数える）。
4. 手数の上限はピース数 × 20 + 20。上限に達するか、打てる手が無くなったら「解けない」。

手の順と狙う順を固定しているので同じ問題には同じ結果を返す。問題1つあたり数 ms（11×11 でも数十 ms）で、人間向け解法器（秒単位）よりずっと軽い。

静的な干渉の量（解の盤面で、1個のピースを通る外周ヒントの本数、ピースを共有する外周ヒントの本数、光路の長さ）も一時スクリプトで測ったが、推論レベルとの関係が弱い（ピースを通る外周ヒントの本数の平均はレベル1〜5で 3.8 / 3.7 / 3.4 / 2.8 / 2.7 と、上位ほどむしろ減る）ため採らなかった。ピースが多いと1個あたりのヒントは減るが、ヒント同士の取り合いは増える。静的な数では取り合いの強さを表せず、試行ソルバーのやり直しの方が「1つ直すと他が崩れる」をそのまま数えられる（事実（実測。一時スクリプト）・推測）。

生成器の版 2 の問題集（作り直す前、各500問）で試行ソルバーを動かすと、**レベル5 の 95%（475問）が試し置きで解き切れ、やり直しの中央値は6回**だった。レベル4 は 99% が解け、やり直しの中央値は1回（事実（実測。一時スクリプト））。「レベル5でも簡単」という指摘と整合する。

### 16.5 分析と生成の速さ（事実（実測））

盤面を 11×11 まで広げると、段05の解法器では1候補の生成に数分（`rf-11-18-0` で約4分）、9×9 の分析に最大87秒かかっていた。次のように直した。

| 対象 | 変更 | 結果が変わるか | 効果 |
| --- | --- | --- | --- |
| 完全解法器（一意性の確認） | 光路ごとの候補の重複判定と手持ちの判定を、光路で変わったマスだけで差分計算する（以前は盤面全体を毎回数えていた） | 変わらない。5×5〜9×9 の 1,680件（上限・解の上限を変えて）で、打ち切りの有無・解の数・最初の解が旧版と一致 | 5〜7×7 で 3.3倍、8〜9×9 で 5.9倍。版 2 の `rf-10-16-3` は 18.2秒 → 1.8秒 |
| 完全解法器 | 光路をたどる1マスも探索量に数え、外へ出られない長さの光路を枝刈りする。上限は探索量 400万（生成器と分析で共有） | 変わる（上限に達する候補が変わる）ので生成器の版を 3 に上げた | 1候補の判定の最悪が抑えられる。以前4分かかった `rf-11-18-0` の identity は 1.9秒、11×11・20ピースの最悪でも17秒（18候補目で採用） |

## 17. 一致の定義の修正と問題集の作り直し（5回目の人間レビュー、2026-09-29）

### 17.1 指摘と方針

プロダクトオーナーから「この10間違えてない？」と指摘を受けた。一致の判定が行き先の種別と通るマスの数だけを比べていたため、光が出た先の外周ヒントの目標が違うのに数と種別がたまたま同じで緑になる偽の一致があった（[リフレクション実装前提調査](リフレクション実装前提調査.md) §11.4）。退出の一致に「出た先の外周ヒントの目標も退出・同じマスの数」を加えた。

試行ソルバー（§16.2）は「一致表示のもとで人間が試す」ことの代理である。人間は新しい一致表示を見て試すので、**試行ソルバーも新しい定義に揃え、問題集を作り直した**（問題集の版 3。生成器の版 3 は変えない）。旧定義のまま据え置く案は採らない。旧定義では偽の一致が試し置きを誤った方向へ導き、やり直しの回数を実際の表示より多く数えるので、レベル4・5 の「試し置きでは押し切れない」ことの根拠が、人間が見ない表示に依存してしまう。

### 17.2 影響（事実（実測））

旧問題集（版 2）の2,100問を、旧定義と新定義の試行ソルバーで解き比べた。

| レベル | 問題数 | 試し置きの手数が変わった | 試し置きの下限を満たさなくなった | 試し置きで解き切れる（旧→新） | やり直しの中央値（旧→新） | 手数の中央値（旧→新） |
| ---: | ---: | ---: | ---: | --- | --- | --- |
| 1 | 500 | 0 | ―（下限なし） | 500 → 500 | 0 → 0 | 3 → 3 |
| 2 | 500 | 2 | ― | 500 → 500 | 0 → 0 | 3 → 3 |
| 3 | 500 | 38 | ― | 498 → 498 | 0 → 0 | 7 → 7 |
| 4 | 300 | 171 | **60** | 282 → 278 | 9 → 6 | 23 → 20 |
| 5 | 300 | 215 | **69** | 250 → 255 | 48 → 29 | 71.5 → 48 |

新定義では偽の一致に惑わされなくなり、試し置きは易しくなる。例: 報告の問題 `5-51`（`rf-10-18-16`）は、旧定義で154手・やり直し117回だったが、新定義では19手・やり直し0回で解ける。

作り直した問題集（版 3）では、レベル1〜3 は同じ問題で試し置きの手数だけが変わり（40問）、レベル4 は300問中60問、レベル5 は70問が入れ替わった。生成は4並列で4,420秒、`--verify` は585秒で不合格0。

| 特徴 | 版 2 レベル4 | 版 3 レベル4 | 版 2 レベル5 | 版 3 レベル5 |
| --- | --- | --- | --- | --- |
| 試し置きで解き切れる | 94% | 91% | 83% | 81% |
| 試し置きのやり直し（25% / 中央値 / 75%） | 5 / 9 / 22 | 4 / 8 / 18 | 26 / 48 / 117 | 21 / 42 / 105 |
| 試し置きの手数（中央値） | 23 | 23 | 78 | 67 |
| 全外周ヒントへ照らし直した回数（中央値） | 10 | 10 | 31 | 30 |
| 仮に置いて確かめた回数（中央値） | 0 | 0 | 103 | 91 |

（版 2 のやり直しは旧定義、版 3 は新定義の試行ソルバーの値。）

レベル5 の候補の採用率は 23%（1,300候補から300問）で、試し置きの下限で除いた候補は773。

### 17.3 付随所見（人間の実測）

同じ日に、プロダクトオーナーがレベル5 の問題（版 2 の `5-51`）を3分8秒・置き直し2回で解いた。同じ人のレベル5 の記録6件のうち5件は、当時の基準時間より4〜9分速かった（[リフレクション成績評価](リフレクション成績評価.md) §15）。少なくともこの人にとって、レベル5 は3分前後で解ける水準で、§16 の作り直しの目標（「レベル5 でも簡単すぎる」への対応）に届いていない可能性がある。また `5-51` は新しい一致の定義では試し置きで19手で解けるので、版 3 のレベル5 には入っていない（一致表示を見れば試しながら進められた問題だった）。**この作業では難易度の定義を変えない**。版 3 のレベル5 を実プレイで確かめ、下限（試し置きのやり直し15回）や規模を見直すかを最終レビューで判断する。
