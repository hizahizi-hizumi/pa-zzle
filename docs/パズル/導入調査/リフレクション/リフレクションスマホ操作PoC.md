# リフレクション スマホ操作PoC

調査日: 2026-09-28

## 目的

四辺に外周ヒントを持ち、盤面へピースを配置するリフレクションがスマートフォン幅で操作可能かを、pa-zzleの実レイアウト・実ブラウザで確認する。

## 操作試作

Repository Snapshot上へ一時的な研究用画面を作り、次の操作を試した。

- 7×7 / 8×8の切り替え
- 6種類のピースを44pxのストックボタンから選択
- 盤面セルをタップして配置
- 四辺の外周ヒントをタップ
- 選択したヒントのレーザー経路を盤面上へ表示

操作試作は調査用であり、本番ルート・本番UIとして採用するものではない。

## 実ブラウザ結果

`ChatGPTBrowser` + Chromiumで、同一ページのviewportを変更して測定した。

| viewport | 7×7 セル幅 | 8×8 セル幅 | ピースボタン | 横スクロール |
| --- | ---: | ---: | ---: | --- |
| 390×844 | 45.4px | 39.8px | 44px | なし |
| 375×667 | 43.3px | 37.9px | 44px | なし |
| 360×780 | 41.1px | 36.0px | 44px | なし |
| 320×568 | 35.4px | 31.0px | 44px | なし |

各条件で次を実操作した。

1. 盤面サイズを切り替える。
2. `/` ピースを選択する。
3. 盤面セルへ配置する。
4. 上辺の外周ヒントを選択する。
5. 選択した光路が盤面上へ表示されることを確認する。

全8条件で操作が成立した。

- ピース配置: 成功
- 外周ヒント選択: 成功
- 光路表示: 成功
- `pageerror`: 0
- 意図しない `console.error`: 0
- failed request: 0

## 視覚確認

390pxと320pxで7×7 / 8×8のスクリーンショットを確認した。

7×7は390pxでセルが約45pxあり、四辺のヒント・盤面・ストックを同時に把握しやすい。320pxでは約35pxまで縮むが、盤面構造とピースは識別でき、横スクロールも生じない。

8×8も操作自体は成立するが、390pxで約40px、320pxで31pxとなり、外周ヒントと盤面内ピースを同時に読む密度が上がる。特に複数ピースと曲がる光路を重ねる実プレイでは7×7より視認余裕が小さい。

## 盤面上限の判断

**スマホプレイ成立性は通過とする。**

初期提供では次を採用候補とする。

- 通常提供の標準上限: 7×7
- 8×8: 技術的には操作可能だが、初期の通常提供範囲外
- 9×9以上: 初期提供範囲外

8×8を永久に禁止する判断ではない。将来、盤面ズーム、外周ヒントの表現改善、タップ支援等を導入する場合は再評価できる。

難易度PoCでは5×5固定でも5段階が出るため、高難易度を成立させるために盤面を8×8以上へ拡大する必要はない。この点も7×7上限を採用しやすくする。

## 本実装への申し送り

- 基本入力は `ストック選択 → セルタップ` とし、ドラッグを必須にしない。
- ストックは44px級のタップ領域を維持する。
- 外周ヒントは数字だけでなく結果種別を形でも識別できるようにする。
- レーザー経路はピース形状を隠さず、曲がり・反射・吸収を追える線表現にする。
- 7×7でも360px以下ではセルが44pxを下回るため、ピース形状の描き込みを細かくしすぎない。
- 外周ヒントのタップ領域と盤面セルの境界で誤タップしない余白・状態反応を本実装で確認する。
- 本実装時にも320 / 360 / 375 / 390pxでPlaywright確認を行う。

## 検証方法

対象Snapshotと同じworkflow runのOffline Dependenciesを使用し、依存キー一致を確認してViteを起動した。

`scripts/chatgpt_playwright.py` の `ChatGPTBrowser` を使用し、Chromium管理ポリシーを変更せず要求中継方式で描画・操作した。
