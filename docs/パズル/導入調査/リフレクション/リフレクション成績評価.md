# リフレクション成績評価

リフレクション（作業名。正式名は最終レビューの論点）の1プレイを100点満点で評価し、`perfect` / `great` / `good` / `clear` の評価段階と自己ベストの比較へつなげるための検討記録。

[リフレクション実装前提調査.md](リフレクション実装前提調査.md)（以下「前提調査」）§16・§17 の仮決定を出発点に、配点・基準時間・記録する事実を決める。

この文書は現在仕様の正本ではない。採用した評価規則・記録する事実・自己ベストの比較は、段11で SPEC-013 の「成績評価」へ反映する。比べた案、採らなかった案、係数の根拠はこの文書に残す。

根拠は前提調査と同じ見出し語で区別する。

- **事実（実測）**: 同梱の問題集（各レベル 500問、計 2,500問。問題集の版 1）を人間向け解法器で解いた経過から計算した値。
- **導出**: 定義から論理的に導けること。
- **推測・仮説**: 実プレイで確かめていない判断。係数・参照モデル・プレイヤー像はすべてここに入る。

**まだ誰も実際に遊んで評価を確かめていない。基準時間の係数と0点になる倍率はすべて仮置きで、§10 の確認で校正する。**

2026-09-28 の3回目の人間レビュー（「置き直しのペナルティってどうなんや？」）で、段09の「正確性60（置き直し・盤面を戻す回数の減点）＋速さ40」をやめ、**基準時間と比べた速さだけの100点**にした。経緯・比べた案・段09の式は §13 に残す。

同じ日の4回目の人間レビュー（難易度の作り直し。[リフレクション難易度](リフレクション難易度.md) §16）で、盤面が 11×11 まで広がり、一致表示のもとでの試し置きを試行ソルバーで測れるようになったので、**基準時間の式を見直した**（§14）。スコア式（速さだけ、基準時間の3倍で0点）は変えていない。§5〜§8 の表は、断りの無い限り見直す前（問題集の版 1）の値。

## 2. 良いプレイの定義

> 外周ヒントと一致表示を手がかりに、迷わず速く配置を復元すること。

- 問題はどれも一意解で、推論レベル1〜5の範囲で推測なしに置き場所が決まる（リフレクション難易度.md §4）。読みが深い人ほど、次の置き場所を早く決められ、経過時間が短くなる。
- 2026-09-28 以降は外周ヒントごとの一致が常に見え（前提調査 §11.4）、「置いて一致や光路を見て、違えば動かす」ことがこのゲームの中心の操作になった。置き直しを減点すると、この遊び方そのもの（ストックの選び間違い・マスの押し間違いも含む）を罰することになる。**置き直しは減点せず**、読みの確かさは速さに表れるものとして扱う（推測）。
- 置き直しを重ねる試し置きは、そのぶん時間がかかる。速さだけで評価しても、読まずに当てずっぽうで置き直し続けるプレイは基準時間を超えやすい（§8）。
- 解けたかどうかはクリアとして別に扱う（`GAME.md`）。失敗の条件は無いので、クリアしたプレイだけを評価する。

## 3. 観点とプレイ事実

`session/session.ts` の `ReflectionSessionResult` がクリア時に返す事実をそのまま使う。

| 事実 | 意味 | 評価での扱い |
| --- | --- | --- |
| 経過時間 `elapsedMs` | 開始からクリアまで。盤面を戻しても引き継ぐ | **速さ（評価のすべて）** |
| 置き直し回数 `relocationCount` | 一度盤面に置いたピースを動かし直した回数。別のマスへ移す・入れ替える（2個動いても1回）・ストックへ戻す・別の種類で上書きされる、をそれぞれ1回と数える。解答との照合は使わない | 記録と結果・記録画面の表示だけ。減点しない |
| 盤面を戻した回数 `restartCount` | メニューの「盤面を戻す」で、同じプレイのまま全ピースをストックへ戻した回数。戻ったピースは置き直しに数えない | 記録と結果の内訳の表示だけ。減点しない（§4） |
| 光路を確かめた回数 `laserCheckCount` | 外周ヒントを押して光路を表示した回数。同じ位置を押して閉じる操作は数えない | 記録だけ（前提調査 §11.3・§16）。光路表示を補助から通常操作へ切り替えるかの判断材料 |
| 入力回数 `inputCount` | 盤面・ストックを押して状態（盤面または選択）が変わった回数。盤面を戻すは数えない | 記録だけ。操作の迷いを後から見る目安 |

速さの基準時間には、遊んだ問題の事実（§5 の作業の量）も使う。これはプレイの事実ではなく問題の事実なので、記録では `workload` として `performance` と分けて持つ（§9）。

待ったは 2026-09-28 の3回目の人間レビューで削除した（前提調査 §12.1）。置いたピースは直接押して移す・入れ替える・戻すことができ、1手戻す役割が重なるため。

## 4. 評価式（推奨案）

| 観点 | 満点 | 規則 |
| --- | ---: | --- |
| 速さ | 100 | 問題ごとの基準時間以内で満点。超過に応じて線形に減らし、基準時間の3倍で0点 |

```
点         = round(100 × clamp(1 − max(0, 経過時間 − 基準時間) / (2 × 基準時間), 0, 1))
読む時間   = 0.5秒 × 外周ヒントの本数 + 7秒 × ピース数 + 8秒 × 照らし直した回数 + 15秒 × min(仮に置いた回数, 10)
試し置きの時間 = 0.5秒 × 外周ヒントの本数 + 5秒 × 試し置きの手数（試し置きで解き切れない問題は無し）
基準時間   = (読む時間 + min(読む時間, 試し置きの時間)) / 2
```

（4回目の人間レビューで見直した式。見直す前は「基準時間 = 0.5秒 × 外周ヒント + 6秒 × ピース + 8秒 × 照らし直し + 15秒 × min(仮置き, 10)」。§14）

評価段階は既存ゲームと同じ（100 `perfect` / 90以上 `great` / 80以上 `good` / それ未満 `clear`）。

この式から導かれる性質（導出）:

- `perfect` は基準時間以内のときだけ。点は整数へ四捨五入するので、超過が基準時間の 1% 未満は満点に丸まる。
- 基準時間の1.2倍以内で `great`、1.4倍以内で `good`、2倍で50点、3倍以上で0点（`clear`）。
- 置き直し・盤面を戻した回数・光路を確かめた回数は点に入らない。置き直しても、その分の時間がかかるだけ。
- **盤面を戻すことも減点しない**。盤面を戻しても経過時間は止まらず、置き直した分の時間はすでに経過時間に入っている。減点すると、行き詰まったときに1個ずつ戻すより盤面を戻す方が損になり、操作の選び方で点が変わる。
- メニューの「やり直す」（同じ問題を新しいプレイとして始める）は時間を0から数え直す。これは段09と同じ。
- 基準時間に対する倍率で決まるので、同じ倍率ならどの難易度でも同じ点になる。高いレベルを選んだことだけでは点は上下しない。

実装: `frontend/src/games/reflection/score.ts`。係数は名前付きの定数で、仮置きであることを定数のコメントに書いている。

## 5. 基準時間

### 5.1 使う量

問題ごとの「解き切るのに要る作業の量」（`ReflectionSolveWorkload`、段06で問題集に持たせた）から決める。

| 量 | 意味 | 出どころ |
| --- | --- | --- |
| 外周ヒントの本数 `clueCount` | 読むヒントの数。盤面の一辺の4倍（5×5 で20、7×7 で28） | 問題から数える |
| ピース数 `pieceCount` | 置くピースの数（2〜12） | 問題から数える |
| 照らし直した回数 `propagationRoundCount` | 人間向け解法器で、全外周ヒントへ照らし直して候補が変わった回数（推論レベル2以上で増える） | 問題集に持たせた |
| 仮に置いた回数 `assumptionTestCount` | 人間向け解法器で、候補を仮に置いて確かめた回数（推論レベル5 でだけ増える） | 問題集に持たせた |

難易度（レベル）そのものは使わない。レベルは「どの深さの推論が要るか」で決まり（リフレクション難易度.md §8）、基準時間は「その問題で何個置き、何回照らし直し、何回仮に置くか」で決まる。

仮に置いた回数は、解法器が候補を端から順に試すので裾が長い（事実（実測）: レベル5 の中央値4回、p75 9回、最大776回）。人間は見込みの高い候補から試すとみなし、**10回で打ち切る**（推測）。打ち切らないと最大の問題で基準時間が3時間を超える（§5.2 の T4）。

### 5.2 案の比較

| 案 | 式 |
| --- | --- |
| T1 | 10秒 + 8秒 × ピース |
| T2 | 10秒 + 6秒 × ピース + 8秒 × 照らし直し |
| **T3（推奨）** | 0.5秒 × 外周ヒント + 6秒 × ピース + 8秒 × 照らし直し + 15秒 × min(仮に置く, 10) |
| T4 | T3 から仮に置く回数の上限を外したもの |
| T5 | T3 の「0.5秒 × 外周ヒント」を定数10秒にしたもの |

案を比べる物差しとして、解法器の経過から1問ずつ所要時間を見積もる **参照モデル** を置いた（推測。係数は仮定）。

- 盤面把握: 5秒 + 外周ヒント1本 0.5秒。
- 置く操作: ピース1個 2秒（ストックを選んでマスを押す）。
- 置き場所を決める時間: どの推論レベルで決まったピースかに応じて、L1 3秒、L2 6秒、L3 10秒、L4 15秒、L5 25秒（`fixedPieceCountByLevel`）。
- 照らし直し1回 2秒、仮に置いた回数 n に対して 4秒 × √n。

参照モデルは「同じ腕前の人が、どの問題にどれだけ時間がかかりそうか」を1問ずつ表すための仮定で、所要時間の絶対値は当てにしない。見たいのは、基準時間がこの見積もりに沿って問題ごとに伸び縮みするか、つまり **同じ腕前の人が、どのレベルを選んでも同じくらいの速さの点を取れるか** である。

| 案 | 参照モデルとの順位相関（全体） | 同（レベル内。1 / 2 / 3 / 4 / 5） | 基準時間の中央値（1 / 2 / 3 / 4 / 5） | 基準時間の最大 | 基準時間 ÷ 参照モデル（中央値。1 / 2 / 3 / 4 / 5） | 参照モデルの1.5倍で解く人の速さの点（中央値） |
| --- | ---: | --- | --- | --- | --- | --- |
| T1 | 0.97 | 1.00 / 0.92 / 0.78 / 0.71 / 0.33 | 0:34 / 0:34 / 0:58 / 1:14 / 1:38 | 1:46 | 1.13 / 0.91 / 0.75 / 0.56 / 0.34 | 27 / 14 / 0 / 0 / **0** |
| T2 | 0.99 | 1.00 / 0.92 / 0.87 / 0.75 / 0.74 | 0:28 / 0:36 / 1:10 / 2:06 / 3:14 | 6:10 | 0.93 / 0.97 / 1.00 / 0.94 / 0.69 | 16 / 18 / 20 / 16 / **0** |
| **T3** | **0.99** | 1.00 / 0.93 / 0.88 / 0.75 / 0.65 | 0:28 / 0:38 / 1:12 / 2:08 / 4:24 | 8:44 | **0.93 / 1.00 / 1.02 / 0.96 / 0.95** | **16 / 20 / 21 / 18 / 17** |
| T4 | 0.99 | 1.00 / 0.93 / 0.88 / 0.75 / 0.62 | 0:28 / 0:38 / 1:12 / 2:08 / 4:24 | **199:50** | 0.93 / 1.00 / 1.02 / 0.96 / 0.96 | 16 / 20 / 21 / 18 / 17 |
| T5 | 0.99 | 1.00 / 0.92 / 0.87 / 0.75 / 0.64 | 0:28 / 0:36 / 1:10 / 2:06 / 4:20 | 8:40 | 0.93 / 0.97 / 1.00 / 0.94 / 0.94 | 16 / 18 / 20 / 16 / 16 |

（事実（実測）: 問題集 2,500問で、参照モデルと各案を計算して比べた（一時スクリプト、コミットしていない）。参照モデルの係数は仮定。レベル1 は照らし直し・仮置きが0回で、レベル内の順位はピース数だけで決まるので、どの案も参照モデルと一致する。）

- **T1（ピース数だけ）を採らない**。上のレベルほど1個の置き場所を決める推論が深いのに基準時間が伸びず、同じ腕前の人がレベル3以上で速さの点を取れない。「高いレベルを選んだだけで点が下がる」規則で、前提調査 §14 に反する。
- **T2（仮に置く回数を使わない）を採らない**。レベル5 は仮に置いて決まるピースが平均6.7個あり（事実（実測））、照らし直しの回数だけでは伸びが足りず、レベル5 だけ速さの点が0になる。
- **T4（上限なし）を採らない**。解法器の試し方に引きずられ、仮に置いた回数が776回の問題で基準時間が約3時間20分になる。
- **T3 を推奨する**。基準時間 ÷ 参照モデルがレベル1〜5で 0.93〜1.02 に収まり、同じ腕前の人の速さの点がレベルによらずほぼ同じになる。T5 との差は小さい（速さの点で0〜2点）が、外周ヒントの本数は盤面の広さを表し、「見る外周ヒントの数、置くピースの数、照らし直す回数、仮に置く回数」と1つの言葉で説明できる。
- 注意: T3 と参照モデルはどちらも「深い推論ほど時間がかかる」と仮定しているので、相関の高さはその仮定を共有していることにも由来する。T3 が正しいことの証拠ではなく、「その仮定を採るなら、少ない係数でよく追える」ことの確認である。仮定そのものは §10 の実プレイで確かめる。レベル内の相関はレベル4・5 で 0.65〜0.75 と低めで、同じレベルの中での問題ごとの伸び縮みは参照モデルほど大きくない。

## 6. 評価式の案の比較

同じ基準時間（T3）で、3回目の人間レビューの対応として次の案を比べた。時間は基準時間に対する倍率、置き直しなしのプレイの点。

| 倍率 | R 段09（正確性60 / 速さ40、2倍で速さ0点） | S2 速さ100、2倍で0点 | **S3 速さ100、3倍で0点（採用）** | S4 速さ100、4倍で0点 |
| ---: | --- | --- | --- | --- |
| 0.8 | 100 perfect | 100 perfect | 100 perfect | 100 perfect |
| 1.0 | 100 perfect | 100 perfect | 100 perfect | 100 perfect |
| 1.1 | 96 great | 90 great | 95 great | 97 great |
| 1.2 | 92 great | 80 good | 90 great | 93 great |
| 1.4 | 84 good | 60 clear | 80 good | 87 good |
| 1.5 | 80 good | 50 clear | 75 clear | 83 good |
| 2.0 | 60 clear | 0 clear | 50 clear | 67 clear |
| 3.0 | 60 clear | 0 clear | 0 clear | 33 clear |

- **R（段09）をやめる**。置き直し1回 −5点・盤面を戻す1回 −15点は、一致表示のもとでの「置いて確かめ、動かして直す」遊び方を罰する（§2）。
- **S2 を採らない**。速さだけで100点にすると、倍率1.2で `good`、1.4で `clear` まで落ちる。段09の速さ40点の傾きをそのまま100点に広げたもので、時間の揺らぎで段階が大きく動く。
- **S4 を採らない**。1.5倍でも `good` に残り、段09の置き直しなしのプレイ（1.5倍で80点）より甘い。`good` と `clear` の境目が遠く、遅いプレイとの差がつきにくい。
- **S3 を採る**。段09で置き直しの無かったプレイの段階（1.2倍で `great`、1.4倍で `good`）をほぼ保つ（1.5倍だけ `good` → `clear`）。「基準時間の3倍で0点」と説明でき、`great` は基準の2割増し、`good` は4割増しまでと言い換えられる。
- 置き直しや盤面を戻す回数を少しだけ減点する案（例: 置き直し −1点）は採らない。どの重さでも、押し間違いを直した・一致表示で確かめて直した操作が点を下げることに変わりはなく、説明も「速さだけ」より複雑になる。

## 9. 記録と自己ベスト

実装: `frontend/src/games/reflection/play-record.ts`。共通の記録（`frontend/src/records/`、保存キー `pa-zzle.play-records.v1`）に `gameId: "reflection"`・`payloadVersion: 2` で載せる（4回目の人間レビューで `workload` に試し置きの手数を足して 1 から上げた。§14.3）。

| payload | 内容 |
| --- | --- |
| `difficulty` | `"1"`〜`"5"` |
| `problemIdentity` | `{ generatorVersion, seed, conditions: { size, pieceCount } }`。再プレイで問題集から同じ問題を引く |
| `workload` | `{ pieceCount, clueCount, propagationRoundCount, assumptionTestCount, trialMoveCount }`。遊んだ問題の作業の量。`trialMoveCount` は試行ソルバーの手数で、試し置きで解けない問題は `null` |
| `performance` | `{ elapsedMs, relocationCount, restartCount, laserCheckCount, inputCount }`。プレイの事実。2026-09-28 の3回目の人間レビューで待ったを削除し、`undoCount` を書かなくなった。以前の記録に残る `undoCount` は読み込みで無視する（`payloadVersion` は 1 のまま） |

記録の id は `reflection:<開始時刻>:<完了時刻>:<seed>`。

- 評価点・評価段階・基準時間・基準時間との差は保存しない。記録から現在の評価規則で導出する（`SPEC-006`）。
- **採点の版は保存しない**。前提調査 §17 は「スコアモデル版」を保存するとしていたが、バイナリパズルと同じく持たないことにした。配点・係数は仮置きで、変えたら過去の記録も新しい規則で評価し直すのが `SPEC-006` の意図に合う。公開前には記録が無いので、パーキングジャムのように旧式の点を残す必要も無い。評価に使う事実の意味を変える（例: 置き直しの数え方を変える）場合は `payloadVersion` を上げて区別する。
- **問題の識別は生成器の identity だけを保存する**（問題集の版と番号 `poolReference` は保存しない）。
  - identity は問題集を作り直しても変わらず、seed から問題集の問題を引ける（`restoreReflectionProblem`。問題集の中での位置は `findReflectionPooledProblem` で identity から求まる）。
  - 問題集の番号は問題集を作り直すと別の問題を指す（`poolVersion` を上げる）ので、記録に持つと古い番号の扱いが要る。検証情報や記録画面で番号を見せたいときは、読み出し時に identity から引く。
  - 比べた案: (a) identity だけ（採用。バイナリパズルと同じ）、(b) 問題集の版と番号だけ（問題集を作り直すと引けなくなり、生成器の版を上げていない問題まで再プレイできなくなる）、(c) 両方（2つが食い違った記録の扱いが要る）。
- `workload` を記録に持つ理由: 評価を記録だけから再計算できるようにするため。生成器の版を上げて問題集を作り直すと、それまでの記録は identity から問題を引けなくなる。`workload` があれば、そうした記録も評価し直せる（バイナリパズルと同じ扱い）。
- **問題集に無い記録**（生成器の版が今と違う、または問題集を作り直して外れた問題）も読み込み、記録画面と自己ベストの比較に残す。できないのは再プレイだけで、記録から遊び直そうとしたら「この記録は再プレイできません」「この記録の問題は、現在の問題集にありません。」と示す（バイナリパズルと同じ文言。`RecordedProblemReplayView` に接続した）。
- **内部診断で問題を指定して開いたプレイは記録しない**。URL の難易度と問題のレベルが一致する保証が無く、自己ベストの比較単位（難易度）を崩すため。パーキングジャムの「問題指定の比較プレイは記録しない」と同じ扱い（`PlayableReflection` の `initialProblem.purpose` で、記録からの再プレイ `replay` と問題指定 `blind-comparison` を区別する）。問題集に無い identity を指定したときは作業の量も無く、評価もできない（play hook は `workload` と `result` を `null` で返す）。
- 読み込み時の検証: ゲームID・payload の版・難易度・identity の形（生成器の版と seed が空でない文字列。今の版なら盤面サイズ 5〜11 とピース数の範囲）・作業の量（外周ヒントが4の倍数で1本以上、ピースが1個以上で盤面のマス数未満、照らし直し・仮に置く回数が0以上の整数、試し置きの手数が0以上の整数か `null`。今の版の identity なら、ピース数と盤面サイズが identity の生成条件と一致）・事実（経過時間が有限の0以上、各回数が0以上の整数、置き直しが入力回数以下）を確かめ、どれかが崩れた記録は読み込まない。

**自己ベスト**（比較単位は難易度）:

| 指標 ID | 良い向き | 理由 |
| --- | --- | --- |
| `play-score` | 高い | 評価そのもの |
| `time-delta-ms` | 小さい | 基準時間に対するクリア時間の差。問題ごとに作業の量が違うので、実時間ではなく差で比べる（バイナリパズル・ウォーターソートと同じ） |

置き直し回数・光路を確かめた回数は自己ベストに入れない。どちらも点に入らず、少ないほど良いとは言えない。置き直し回数は、段09〜2回目のレビュー後は指標（小さい）に入れていたが、3回目の人間レビューで減点をやめたので外した。記録画面の履歴には出さず、結果画面の主要成績にだけ出す。

## 11. 限界

- **実プレイをしていない**。基準時間の係数、0点になる倍率、参照モデルの係数、プレイヤー像はすべて仮定で、§10 で校正する。
- 参照モデルと T3 は「深い推論ほど時間がかかる」という同じ仮定に立つ（§5.2）。
- **照らし直した回数・仮に置いた回数の定義**: 解法器は全外周ヒントをまとめて照らし直し、候補を端から試す。人間は影響のあるヒントだけを見直し、見込みの高い候補から試すので、実際の回数は解法器と違う。仮に置く回数は10回で打ち切ったが、その値に根拠は薄い。
- **一致表示の影響**: 2026-09-28 の人間判断で外周ヒントごとの一致表示を採用した（前提調査 §11.4）。1個置くたびに合った外周ヒントが分かるので、試し置きのプレイは段09の想定より速く済みうる。3回目の人間レビューで置き直しの減点をやめ、試し置きも遊び方として認めた（§2・§13）。基準時間は一致表示が無い前提（外周ヒントから読む作業の量）で置いたままなので、一致表示を使うと基準時間より速く解けやすい可能性がある（§10 の1・4）。
- **光路表示の影響**: 光路表示を使うと、読みの一部を盤面で確かめる作業に置き換えられる。基準時間は光路表示を使わずに読む前提で置いたので、光路を使う人には長め（または短め）かもしれない。
- **速さだけの評価**: 置き直し・盤面を戻すことを減点しないので、同じ時間なら、確定させてから置いたプレイと試し置きで解いたプレイは同じ点になる。読みの確かさは時間にしか表れない。
- 経過時間は開始からクリアまでで、アプリを離れていた時間も含む（既存ゲームと同じ）。遊び方を初めて表示したときは、閉じた時点から測り直す（段04）。

## 12. ずれた場合の見直し方針

1. 良いプレイの定義（§2）が遊ぶ人の感覚と合っているか。確定させてから置くことを試し置きより高く評価したいと感じるなら、観点を足すところから見直す（§13 の段09の式が出発点になる）。
2. 観点に対する事実が合っているか。置き直しを評価に戻すなら、押し間違いと試し置きを区別できる事実が要るか、数え方から見直す（session の事実）。評価に使う事実の意味を変えたら `payloadVersion` を上げる。
3. 基準時間の量（§5.1）が時間のかかり方を表しているか。レベルで偏るなら、使う量（例: 推論レベルごとに決まったピースの数を問題集に持たせる）を見直す。問題集に量を足すと問題集を作り直すことになる。
4. そのうえで係数を動かす。

係数だけを変える場合、記録は事実だけを持つので、過去の記録も新しい規則で評価し直される（`SPEC-006`）。解法器を変えて照らし直しの数え方が変わっても、生成器の版を上げて問題集を作り直しても、記録の `workload` は記録時の値のまま使う。

## 13. 3回目の人間レビューでの見直し（2026-09-28）

プロダクトオーナーから「待ったいるのか？」「置き直しのペナルティってどうなんや？」と指摘を受けた。

- **待った**: 削除した（前提調査 §12.1）。記録の `undoCount` も書かなくなった。
- **置き直しの減点**: 廃止した。一致表示の導入（前提調査 §11.4）で、置いて確かめ、動かして直すことが中心の操作になった。置き直しを減点すると、この遊び方そのもの（押し間違いも含む）を罰する。置き直し回数は記録し、結果画面の主要成績にだけ出す。
- **盤面を戻す**: 減点しないことにした。全ピースをストックへ戻しても経過時間は止まらず、戻すまでに使った時間は速さに入っている。1個ずつ戻すのと盤面を戻すのとで点が変わらないようにした。比べた案: 段09と同じ −15点（行き詰まったときに盤面を戻すと損になる）、軽い減点（置き直しを減点しないのに盤面を戻すことだけ減点する理由がない）。
- **スコア**: 基準時間と比べた速さだけの100点（§4）。基準時間の式（T3）は変えず、0点になる倍率を2倍から3倍にした（§6）。評価段階の閾値は既存と同じ。
- **自己ベスト**: 置き直し回数（小さい）の指標を外し、スコアと基準時間との差の2つにした（§9）。
- **記録**: `payloadVersion` は 1 のまま。評価は速さだけなので、以前の記録（置き直しに待ったを含む、`undoCount` を持つ）も今の規則で評価し直せる。`undoCount` は読み込みで無視し、置き直しが入力回数を超える以前の記録（待ったを多く使ったもの）は読み込まない。公開前で、後方互換は保証しない方針（プロダクトオーナー）に沿って、移行は書かない。

段09〜2回目のレビュー後の式（参考。§6 の R）:

```
正確性 = max(0, 60 − 5 × 置き直し回数 − 15 × 盤面を戻した回数)
速さ   = round(40 × clamp(1 − max(0, 経過時間 − 基準時間) / 基準時間, 0, 1))
合計   = 正確性 + 速さ
```

## 14. 4回目の人間レビューでの基準時間の見直し（2026-09-28）

難易度の作り直し（[リフレクション難易度](リフレクション難易度.md) §16）で、盤面が 11×11 まで広がり、レベル4・5 は一致表示つきの試し置きで押し切れない問題に限った。一致表示では外周ヒントの正否がすぐ分かり、干渉の少ない問題は試し置きの方が読むより速い。そこで、試行ソルバーの手数（`ReflectionSolveWorkload.trialMoveCount`）を基準時間に入れた。スコア式（速さだけ、基準時間の3倍で0点）は変えていない。

- 読む時間のピース係数を6秒から7秒にしたのは、中間を取ると基準が縮むぶん、熟練した読み手の水準（見直す前の T3 とほぼ同じ `perfect` の割合）を保つため。
- 試し置き1手5秒は、ピースを選んで置き、盤面の外周ヒントの緑を見渡す時間（推測）。4秒（Hb）では熟練した読み手のレベル4 の中央値が90点まで下がる。
