# 氷の床迷路名称・権利調査

調査日: 2026-10-31

この文書は導入調査（資料）であり、現在仕様の正本ではない。法的判断ではなく、調査で確認できた事実に基づく推奨として書く。表示名を決める・変える場合は、人間の判断を経てから正本とコードへ反映する。

根拠の種類を次の語で区別する。

- **事実（リポジトリ）**: 現在のリポジトリの文書・コードから確認したこと。
- **外部知見**: Web 検索結果のタイトルと要約で確認したこと。この環境では商標データベースと多くの外部ページの本文を開けなかった（§5.1）ので、原典の全文は確認していない。
- **推測・仮説**: 上の2つから導いた判断で、原典の確認や権利確認が済んでいないもの。

## 結論

対象は、格子の盤面で上下左右のどれかを選ぶと駒が岩か外壁にぶつかるまで止まらずに滑り、ゴールのマスで止まればクリア（通過は無効）になるパズルである。

パズルのルール・仕組みそのものを、既存作のコード・文章・画像・音・キャラクター・固有名を使わず独自に実装することについて、現時点で導入を止める権利上の要因は確認できていない。

- 「止まるまで滑る」仕組みは、RPG のダンジョンの仕掛け（ポケモンの氷の床、ドラクエのツルツル床など）、アーケードゲーム（Pengo）、ボードゲーム（Ricochet Robots、Lunar Lockout）、単体アプリ、オープンソースのパズル集（Simon Tatham の Inertia）、パズル作家の作品群（Andrea Gilbert の Tilt Mazes）に広く見られる。特定の作品や事業者に固有の仕組みではない（外部知見。§2、§3）。
- 仕組みは遅くとも 1980 年代から公知で、基本ルールを直接拘束する特許は見つからなかった。正式な FTO 調査ではない（§4）。
- 「Ricochet Robots」「ハイパーロボット」「Lunar Lockout / Lunar Landing」「Pengo」「こおりのぬけみち（Ice Path）」などの作品名・地名と、ロボット・色付き目標チップ・ペンギンのキャラクターなど各作品に固有の見た目は使わない（§3.3）。

名称は次のとおり推奨する（推測・仮説。§6.2、§8）。

- **作業名は `氷の床迷路` を続けてよい。**
- **公開名の第一候補も `氷の床迷路` とする。** 遊び方（氷の床＝止まるまで滑る、迷路＝ゴールを目指す）が名前から伝わり、特定作品の名前ではない。代替は `すべる迷路`、次いで `氷の迷路`。`アイスパズル` と `アイススライド` は採らない。
- どの候補も、日本の文字商標を J-PlatPat で直接確認できていない（この環境から J-PlatPat と Brand Terrace に接続できなかった）。**公開名は、公開前に §8.2 の確認を済ませるまで確定しない。**

## 1. 調査対象と前提

- 対象ルール（作業名「氷の床迷路」）: 格子盤、1つの駒、盤内の岩と外壁。方向を選ぶと駒は岩か外壁の手前まで一直線に滑る。ゴールで止まったときだけクリアで、ゴールを通り過ぎてもクリアにならない。
- 特定の既存ゲームを再現せず、ジャンルとして独自に作る（事実（リポジトリ）: `docs/棚上げ/パズル候補.csv` の PUZZLE-094「氷の床迷路」、迷路・経路系）。
- 既存の表示名の付け方（事実（リポジトリ）: `frontend/src/games/*/display-name.ts`）は「ナンプレ」「マインスイーパー」「スライドパズル」「バイナリパズル」「ウォーターソート」「パーキングジャム」「リフレクション（正式名は未定の作業名）」で、ジャンルとして通じる短い名前を使い、特定事業者の商標とされる名前（数独、ナンバーリンク、Flow Free、Takuzu など）を避けている（[パーキングジャム名称調査](../パーキングジャム/パーキングジャム名称調査.md) §3）。内部 ID・ディレクトリ・ルートは表示名と分けて扱う。
- 同じ迷路・経路系に「迷路」（PUZZLE-050、実装候補）がある（事実（リポジトリ）: `docs/棚上げ/パズル候補.csv`、[迷路調査](../迷路/迷路調査.md)）。

## 2. 著作権とゲームルール

採用したい仕組みは次のとおりで、ゲームのアイデア・ルール・機能として扱う。

- 4方向のどれかを選ぶと、駒が障害物（岩・外壁）にぶつかるまで滑る
- 障害物の手前で止まった位置からしか次の方向を選べない
- ゴールのマスで止まればクリア。通過は無効
- 最少手数などで成績を評価する（評価の決め方は別途）

ルール・アイデアそのものではなく、具体的な表現物を複製しないことで足りると考える（推測・仮説）。pa-zzle では次を独自に作る。

- ルール説明文（既存アプリ・攻略記事・Tatham の説明文を写さない）
- 盤面・駒・岩・ゴールの見た目、ピクトグラム、アニメーション、効果音
- 問題生成器・解法器・難易度分析・実装コード

既存作のコードは使わない。Simon Tatham's Portable Puzzle Collection はオープンソースだが、ライセンス条件と、Inertia のルール（宝石集め・地雷・停止マス・斜め移動）が対象ルールと異なることから、参照するとしても挙動の比較にとどめる（ライセンス本文は今回確認していない）。

### 3.3 ルールの独自性と差別化

対象ルール（1つの駒、固定の岩と外壁、ゴールで止まればクリア）は、上の作品群の共通部分にあたる。ルールそのものに独自性はなく、特定作品のルールを写したものでもない（推測・仮説）。「通過は無効」という条件は Ricochet Robots と同じだが、それだけで同作の再現になるとは考えない。駒が1つで固定の岩だけが止め役なので、他の駒を止め役に使う Ricochet Robots / Lunar Lockout とは遊びの核が違う。

pa-zzle での差は、ルールではなく次で出す。

- 問題を生成し、難易度を段階に分けて供給すること
- pa-zzle 共通の操作・成績・記録の枠組みに載せること
- 独自の見た目（§9）

避けるもの:

| 避けるもの | 理由 |
| --- | --- |
| 「Ricochet Robots」「Rasende Roboter」「ハイパーロボット」「Lunar Lockout」「Lunar Landing」「Pengo」「Inertia」「Tilt Maze」「Tip & Tumble」などの作品名 | 特定作品の名前 |
| 「こおりのぬけみち」「Ice Path」「チョウジジム」など、ポケモン作品の地名・用語 | 特定作品の名前 |
| ロボット駒、記号つきの色付き目標チップ、16×16 盤と中央の 2×2 ブロック、マスの間に引く L 字の壁、砂時計 | Ricochet Robots の見た目・構成 |
| 宇宙・月面のロボット | Lunar Lockout の題材 |
| ペンギンなどのマスコットキャラクター、ポケモンの氷タイルの模様・主人公の滑る姿 | 多くの既存作が使う題材で、特定作品（Pengo など）と結びつきやすい |

## 4. 特許の予備調査

次の観点で公開の Web 検索を行った（Google Patents 等のデータベースを直接検索したのではない）。

- 選んだ方向へ障害物まで駒が動く格子パズル・ボードゲーム（英語）
- 氷の床・滑る移動・停止を含むゲームプログラム（英語・日本語）
- Ricochet Robots / Rasende Roboter の特許
- ポケモン（任天堂・ゲームフリーク）の氷の床に関する特許

結果（外部知見）:

- 対象ルールを直接請求する特許は見つからなかった。
- 近いものとして、溝に沿って駒を滑らせる盤ゲーム（US4303246「Table game」）、可変迷路の盤ゲーム（US4817957）、玉転がし迷路（US5145174 など）、障害物を通れる駒が限られるスライドパズル（US4269414）が出たが、どれも物理的な器具の構造に関するもので、対象ルールのソフトウェア実装とは対象が異なる（[US4303246](https://trea.com/information/table-game/patentgrant/16f03481-38d5-4847-aef6-fb27478ef651)、[US4817957](https://patents.google.com/patent/US4817957)、[US5145174](https://patents.google.com/patent/US5145174)、[US4269414](https://patents.google.com/patent/US4269414)）。
- 任天堂の JP2005296530A（パズルゲーム装置）はキャラクターの複製を扱うもので、対象ルールとは無関係だった（[Google Patents](https://patents.google.com/patent/JP2005296530A/en)）。
- Ricochet Robots の特許は見つからなかった。

判断（推測・仮説）: 「止まるまで滑る」仕組みは遅くとも 1982 年の Pengo、1999 年の Rasende Roboter とポケモン金・銀、2000 年の Lunar Lockout で公知になっている。当時に出願された特許があったとしても存続期間（出願から 20 年）を過ぎており、今から基本ルールに新たな特許が成立する余地も小さい。ただし、生成方式・UI・演出などの個別の技術実装には別の特許があり得る。これは正式な FTO（Freedom to Operate）調査ではない。商用展開などで厳密な評価が要る場合は別途確認する。

## 6. 称呼・近接名称

### 6.1 アプリ・ゲームでの使用状況（外部知見）

- 「氷のパズル」（GLOBAL GEAR）は 8×8 盤に氷ブロックを置いて列を消すブロックパズル、「ジグザグ氷パズル」は線をつなぐパズル、「Ice Crush」「Icicle Hexa」はマッチ3 である。**「アイスパズル」「氷のパズル」は、日本のストアでは滑る迷路と別のジャンルの名前として使われている**（[氷のパズル（App Store）](https://apps.apple.com/jp/app/id1437975751)、[ジグザグ氷パズル（App Store）](https://apps.apple.com/jp/app/id6470460781)）。
- 「Ice Slide」「Icy Slide」「IceSlide 3D」「Slide!!」など、`Slide` を含む名前の滑る系アプリが多数ある（[Icy Slide](https://apps.apple.com/us/app/id1540945755?l=en-us)、[IceSlide 3D](https://apps.apple.com/us/app/id1515022669)）。
- 「Ice Maze」は 2026 年配信の「Never Ever Ever: Ice Maze」が名前に含む（§3.2）。
- 「迷路 REAL」「ScrollMaze2」など、傾けて玉を転がす迷路アプリが「迷路」「Maze」を名乗る（[迷路 REAL](https://apps.apple.com/jp/app/%E8%BF%B7%E8%B7%AF-real-%E7%84%A1%E6%96%99%E3%81%AE%E5%AE%9A%E7%95%AA-%E3%81%B2%E3%81%BE%E3%81%A4%E3%81%B6%E3%81%97-%E3%82%B2%E3%83%BC%E3%83%A0/id1079295471)、[ScrollMaze2](https://apps.apple.com/app/id942083257)）。
- 「氷の床迷路」「すべる迷路」という名前のアプリは見つからなかった。

### 6.2 名前ごとの所見（推測・仮説）

- `氷の床迷路`: 特定作品の名前と重ならない。ゲームに慣れた人には「氷の床」で止まるまで滑ることが伝わり、そうでない人にも「氷」「床」から滑ることが想像できる。「迷路」を含むので、同じ迷路・経路系の「迷路」（PUZZLE-050）の仲間に見え、仕掛けで区別できる。5 文字でやや長い。
- `すべる迷路`: 短く、動きが伝わる。ただし日本語の「すべる」には「試験にすべる」「話がすべる」の含みがあり、ゲーム名としては好みが分かれる。
- `氷の迷路`: 短く自然だが、氷の壁でできた迷路（アトラクション）とも読め、滑ることが伝わりにくい。
- `氷すべり`: 遊び（スケート・そり）の語感が強く、ゴールを目指すパズルであることが伝わらない。
- `アイスパズル`: 日本のストアでブロックパズル・マッチ3の名前として使われており、ルールが伝わらない。
- `アイススライド`: pa-zzle の「スライドパズル」と取り違えやすい。海外の同系統アプリ名とも重なり、米国に近接登録がある（§7.1）。

### 8.2 公開前の最終確認

公開名を決める直前に、人間が少なくとも次を確認する。

1. J-PlatPat の商標検索で、文字 `氷の床迷路` と、称呼 `コオリノユカメイロ`・`ヒョウノユカメイロ`、要素 `氷の床`・`コオリノユカ` を検索する。
2. 区分は第9類（ダウンロード可能なゲームソフト等）、第28類（ゲーム・玩具等）、第41類（オンラインゲームの提供・娯楽等）、ブラウザで提供するウェブアプリを考えて第42類も見る。
3. 類似群を含む近接商標の存続状態・指定商品役務を確認する。
4. 代替候補へ変える場合は、その候補（`すべる迷路`・`スベルメイロ`、`氷の迷路`・`コオリノメイロ` など）で同じ確認をする。
5. 英語名を併記する場合は、USPTO・EUIPO・WIPO Global Brand Database で同じ確認をする。
6. 判断に迷う結果（類似の登録があるが指定商品が異なる等）が出た場合は、弁理士等に相談する。

## 9. 実装への申し送り

- 表示名は `frontend/src/games/<id>/display-name.ts` の定数だけから参照する既存の方式に従い、確定までは `リフレクション` と同じく「正式名は未定の作業名」と注記する。
- 内部 ID・ディレクトリ・ルートは表示名と分ける。既存作の名前（`ricochet` など）を ID に使わない。
- 駒・岩・ゴールは機能を表す独自の単純な図形で描き、§3.3 の見た目（ロボット、色付き目標チップ、マス間の壁、ペンギンなどのキャラクター、ポケモンの氷タイル）をなぞらない。障害物は「マスを占める岩」とし、Ricochet Robots の「マスの間の壁」と見た目を分ける。
- ルール説明文は pa-zzle 向けに書く。既存アプリ・攻略記事・Tatham の説明文を写さない。
- 「スライドパズル」と混同されないよう、表示名・説明文で「スライド」を避ける。
- 公開名の確定は、パズル本体の実装判断と切り離す。
