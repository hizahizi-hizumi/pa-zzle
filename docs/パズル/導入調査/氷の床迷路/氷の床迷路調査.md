## 調査対象

ルール（ユーザーと合意済み）:

- 格子の盤面に駒が1つ、ゴールが1マス。
- 上下左右のどれかを選ぶと、駒は岩か外壁にぶつかるまで止まらずに滑る。プレイヤーは止まる位置を選べない。
- ゴールのマスで止まったらクリア。ゴールを通過しただけではクリアにならない。

床・障害物の種類は調査で比べて決めることにした。比べたのは (a) 氷と岩だけ、(b) +ふつうの床（止まる）、(c) +穴（落ちたら失敗）、(d) +矢印床（向きが変わる）の4構成である。

「止まるまで滑る」仕組みは、RPG の氷の床、アーケードゲーム、ボードゲーム、オープンソースのパズル集などに広く見られる。特定の既存作を再現せず、ジャンルとして独自に作る。既存作のコード・文章・素材は使わない（名称・権利調査）。

調査の手段:

- Python 標準ライブラリだけの実験コード（[`scripts/research/ice_floor_supply_experiment.py`](../../../../scripts/research/ice_floor_supply_experiment.py)、[`scripts/research/ice_floor_difficulty_experiment.py`](../../../../scripts/research/ice_floor_difficulty_experiment.py)）。既定 seed は `20261031` で、同じコマンドで同じ結果を得る。
- `/tmp` に置いた調査用の単一 HTML と、Playwright / Chromium（タッチ入力を有効にした headless）。リポジトリには追加していない。
- 参考デモ（8×8・氷と岩だけ・最短9手の1問）。

## ゲート1: 問題供給成立性

詳細は [氷の床迷路供給実験](氷の床迷路供給実験.md) を参照する。

### 生成方式

ゴールは滑りを止めないので、停止点の集合と停止点間の移動はゴールの位置によらない。1つの盤面と開始位置について停止点のBFSを1回行えば、到達できる全停止点への最短手数が分かり、そのどれをゴールにしても成立する問題になる。BFSは、1マスずつ進める素朴な総当たりと1,500盤面で突き合わせて不一致0だった。

岩をランダムに置いてBFSし、到達停止点からゴールを選ぶ方式（G1）を採る。8×8の1盤面の生成とBFSは約0.16 ms で、どのサイズでも1 ms 未満だった。ゴールから逆向きに手順を組む方式（G2）は近道ができて意図した手数が崩れ、最短手数を伸ばす局所探索（G3）はレベル5の供給を増やさなかった。

### 品質条件

| 条件 | 扱い |
| --- | --- |
| ゴールで止まれる | ゴールを到達停止点から選ぶので構成で保証する |
| 自明な問題 | 最短1〜2手を除外する。最短3手以上を選べる盤面は8×8で94.2%。最短15手以上も提供範囲外とする（難易度PoC） |
| 最短解の一意性 | 要求しない。8×8で93.7%はもともと一意 |
| 止め石（ゴールの先の岩） | 要求しない。外壁で止まるゴールでも通過や遠回りは起こる |
| 無関係な岩 | 取り除いて正規化する。8×8で85.1%の問題にあり、岩の21.6%を占める。取り除いても停止点間の移動は変わらない |
| 同型の重複 | 回転・反転の正規化キーで除外する |

### 多様性

最短3手以上・6手以上の問題を各サイズ2,000問生成し、完全一致・回転・反転の同型重複はどちらも0件だった。この規模では問題空間の不足は見られない。

### 詰み

到達できる停止点のうち、そこからゴールへ二度と到達できないものを詰みと呼ぶ。滑りは一般に逆戻りできないので、詰みは構成上避けられない。8×8で約3割、10×10で約3分の1の問題に詰みがあり、約1割は最初の1手で詰みに入れる。

詰みのない問題だけに絞ると、高いレベルの供給と「戻れない場所を見抜く」挑戦を同時に削るので採らない。代わりに待った・盤面を戻す・リセットを必須にする。

### 床の種類

(b)〜(d) の追加マスは、問題供給を改善せず、高難度の供給源にもならなかった（レベル5の割合は (a) の±1.6ポイント以内）。ふつうの床は止まる場所を増やして読みの挑戦を薄め、穴は難しさを先読みでなく失敗の罰として増やし（ランダム操作の約半数が落下で終わる）、矢印床は循環の除外と小さいマスでの向きの読み取りが要る。

**初期実装は (a) 氷と岩だけにする。** 追加の床は、試遊で単調と分かった場合の拡張候補として残す。

### 供給方式

レベルは生成後の難易度分析で決めるので、seed から生成し直す方式では問題の同一性が分析器の版にも依存する。1問は小さい（8×8で約10バイト、各レベル1,000問でも約50KB）。**レベルごとの問題集を事前生成して同梱する。** 無関係な岩を除いた正規化盤面を identity に使い、問題 ID は [ADR-0001](../../../adr/ADR-0001-problem-id.md) どおり identity 全体から求める。

### 残りの確認

- 各レベルの問題数と本番ビルドの増分
- 無関係な岩を除いた盤面が不自然に見えないか（試遊）

**ゲート1判定: 通過。**

## ゲート2: 難易度運用成立性

詳細は [氷の床迷路難易度PoC](氷の床迷路難易度PoC.md) を参照する。

### 人間の挑戦と計画深さ

pa-zzle の難易度判定原則に従い、盤面サイズや最短手数を難易度そのものにしない。このパズルの挑戦は、どの方向へ滑ればどこで止まるかを読み、止まれる場所を何手先まで繋いでゴールで止まる道筋を組み立てることである。

これを**計画深さ**で測る。k 手先までの停止点を読み、ゴールへ「近づく」または「揃える」素朴な方針で手を選ぶ先読みプレイヤーが、解ける最小の k である。同点時の方向優先順位による揺れは、全順位の最小値をとって取り除いた。BFSの探索量・時間は難易度に使わない。

難易度の基準とするプレイは、待った・盤面を戻すを使える状態とした。詰みが3割前後の問題にあり、戻す手段なしでは挑戦ではなく行き詰まりになるため。

### 最短手数との違い

最短手数と計画深さの Spearman 相関は 0.19〜0.22 と弱い。最短9手以上の問題の58%は計画深さ1で、1手読みの素朴な方針で解ける。逆に最短4〜6手でも計画深さ4〜6の問題がある。長いだけの問題と、短いが目先の手がすべて罠になっている問題を分けられる。

### 5段階の仮案

主軸を計画深さ、補助を最短手数とする。レベル1は計画深さ1・最短3〜4手、レベル2は計画深さ1で最短5手以上または計画深さ2、レベル3〜5は計画深さ3 / 4 / 5〜6。計画深さ7以上は評価不能としてレベル5へ入れない。

- 盤面を8×8に固定しても5段階すべてが現れる。
- 計画深さとは別に作った試行手数（待った込みの試行錯誤モデル）が、レベル1→5で単調に増える（8×8で 4 / 8 / 12 / 15 / 17）。
- 1盤面のゴール候補をすべて分析すれば、8×8で最も希少なレベル5でも盤面の25.0%から得られ、Python PoCで1問約34 ms。各レベル数千問の事前生成は数分以内で済む。
- レベル別に採った問題でも、回転・反転の同型重複は0件だった。

### 残りの確認

代表・境界問題をラベルを伏せて遊び、少なくとも次を確かめる。

- レベル1→5で先読みの深さが概ね増えると感じられること
- レベル2の「深さ1で長い問題」と「深さ2の短い問題」が同じ帯として違和感がないこと
- レベル4と5の差が体感で区別できること（試行手数の差が2〜4手と小さい）
- ゴールから逆向きに考える解き方で、前向きだけのモデルが計画深さを過大評価しないこと
- ゴールの通過・詰みの罠が、計画深さの外で体感難易度を大きく変えていないこと

### 盤面の大きさと形

上のレベルほど広い盤面を使う前提で、10×10〜14×14 の正方形と、8×10〜12×16 の縦長の盤面を測った（難易度PoC「追加計測: 盤面の大きさと形」）。盤面を広げても、ランダムな問題の7割前後は計画深さ1のままで、1問の読みが一様に深くなるわけではない。一方、深い問題は出やすくなり（計画深さ5以上は 8×8 の4.2% から 12×14 の8.4%）、同じレベルの中で各手に比べる止まり先と試行手数が増える（レベル5の到達停止点の中央値は 21 → 40、試行手数は 17 → 28）。

このため計画深さを主軸に保ち、上のレベルほど広い縦長の盤面まで許す組み合わせ（レベル1の 8×8〜8×10 からレベル5の 12×14 まで）を仮決定した（[実装前提調査](氷の床迷路実装前提調査.md) §11）。同じレベルの狭い盤面と広い盤面の体感も試遊で確かめる。

**ゲート2判定: 確認中。** 機械側の成立性PoCは完了し、人間の試遊が残る。

## ゲート3: スマホプレイ成立性

詳細は [氷の床迷路 スマホ操作PoC](氷の床迷路スマホ操作PoC.md) を参照する。操作方式の一般的な比較、画面端の戻るジェスチャー、WCAG の扱いは [迷路調査](../迷路/迷路調査.md) のゲート3で確認済みなので、氷の床迷路に固有の点（1回の入力で何マスも動く、行・列を読む、滑りの途中の入力・通過・すぐ壁の伝え方）を確かめた。

### 盤面の寸法

pa-zzle のプレイ画面と同じ寸法の枠で、320〜390px の4つの viewport を確かめた。全条件で `pageerror`・意図しない `console.error`・failed request は0、スクロールは生じなかった。1マスは 320px で 8×8 36.3px / 10×10 29.0px / 12×12 24.2px、390px で 45.0px / 36.0px / 30.0px。方向ボタンを置いても操作欄は既存ゲームと同じ112pxに収まり、盤面の大きさは変わらない。

### 操作

- **盤面スワイプを主操作にする。** 盤面の領域全体で受け、18px を超えた時点で方向を1回だけ確定する。角度のずれ ±40° まで正しい方向になり、揺れやタップでは動かなかった。
- **方向ボタンを常に表示する代わりの操作にする。** 48px 角の逆T字形で、指のずれ 9px でも正しい方向になった。片手でも押しやすい。PCでは矢印キーも受ける。
- 駒の周りのタップは、指で盤面が隠れ、タップしたマスへ行くと誤解されやすいので採らない。

### 滑りの見せ方と連続入力

- 滑る時間は距離に比例させ、等速にする。一定の短い時間や加減速では、長い滑りの途中のマスが描かれず、通過が動きから読めなかった。
- 滑っている途中の入力は即時方式にする。入力した時点で状態を進め、表示中の滑りは終点へ飛ばして次を始める。入力を捨てる方式は入力の3分の2を失い、待ち行列方式は表示が最大約0.5秒遅れた。
- ゴールの通過は滑った跡で伝わり、動きを減らす設定でも読める。すぐ壁は押し戻しの揺れで返し、手数を増やさない。
- 逆方向へ入力しても元の停止点へ戻れない手が4〜5割あるので、待ったはすぐ押せる位置に置く。

### 盤面の上限

入力はマスの大きさに依存しないので、上限を決めるのは行・列を読む視認性である。スマホ操作PoCの時点では、基準を8×8、初期提供の上限を10×10とし、12×12（320px で24.2px）は氷と岩だけなら表示上は成立する候補、14×14 以上は範囲外とした。

その後、上のレベルで広い盤面を使うために見直し、**320×568 で1マス24px程度を下限に、縦長を含めて最大12×14（320×568 で23.9px、390×844 で30.0px）とする**（[実装前提調査](氷の床迷路実装前提調査.md) §12。仮決定）。320×568 では盤面の領域の高さが約340pxなので、行は14までとする。12×16・14×14 は 320×568 で約21pxになり、範囲外とする。12×14 と縦長の盤面の見た目は、本実装のプレイUIで確かめる。

### 残りの確認

- 実機（iOS Safari、Android Chrome）での画面端の戻るジェスチャーとの競合、120Hz 表示での見え方
- 45° 付近の斜めのスワイプを判定しない範囲を設けるか
- ダークテーマでの盤面の色

**ゲート3判定: 通過。**

## ゲート4: 導入判断

### 差別化

同じ迷路・経路系の迷路（PUZZLE-050）は、道をたどり、来た道を戻ることも探索の一部である。氷の床迷路は盤面が全部見えているのに止まれる場所が岩の手前と壁際に限られ、ゴールで止まる入り方から逆算し、わざと遠回りし、戻れない場所を入る前に見抜く読みが中心になる。最短手数と計画深さの相関が弱いことは、手数の長さではない読みの差があることを示す。

### 実装・保守上の論点

- 状態は駒の位置だけで、滑りの規則・BFS・難易度分析はどれも小さく決定論的に実装できる。
- 詰みがあるので待った・盤面を戻す・リセットが必須になる。詰みは、ウォーターソートと同じ線引き（閉じ込められたときだけ）で知らせる仮決定とした。閉じ込めは素朴な操作で試行の2割前後に起き、その多くは詰みに入った時点で起きる（[実装前提調査](氷の床迷路実装前提調査.md) §8.3）。
- 追加の床は表示・説明・難易度分析の負担を増やすので、初期実装は氷と岩だけに限る。
- 評価は、手数系の既存ゲーム（スライドパズル）に倣う案A（効率60 + 速さ40）を仮決定とした。称える対象（最短で止めるか、迷わず止めるか）はユーザーレビューで確かめる。

### 権利・名称

詳細は [氷の床迷路名称・権利調査](氷の床迷路名称・権利調査.md) を参照する。

- 仕組みは遅くとも1980年代から公知で、基本ルールを直接拘束する特許は見つからなかった。ルールの独自実装を止める権利上の要因は確認できていない（正式な FTO 調査ではない）。
- 作業名・公開名の第一候補とも `氷の床迷路` とする。代替は `すべる迷路`、次いで `氷の迷路`。
- どの候補も J-PlatPat で直接確認できていない。公開名は公開前の確認を済ませるまで確定しない。
- 記録と URL に残るゲーム ID は、表示名と切り離して `ice-floor-maze` とする仮決定とした（[実装前提調査](氷の床迷路実装前提調査.md) §15）。

### 現時点の評価

問題供給・多様性・スマートフォン操作は本実装へ進めるだけの成立性を確認できた。難易度も機械側の分析と5段階の供給は成立しているが、人間の体験との対応が未確認である。

**ゲート4判定: 条件付き保留。** 難易度の人間の試遊を経て実装候補化を判断する。

## 次の実験

1. 難易度PoCの代表問題と境界問題を固定し、ラベルを伏せて遊び、レベルの順序と隣接レベルの差を確かめる。
2. 同じ試遊で、試し滑りの安さが読みを損なわないか、氷と岩だけで単調にならないか、無関係な岩を除いた盤面が不自然でないかを確かめる。
3. 体感と食い違う問題があれば、ゴールの1手前の停止点を見る逆向きの推論をモデルへ加えるかを検討する。
4. 詰みを知らせるかを判断する材料として、閉じ込め（行ける位置どうしが互いに戻れ、ゴールを含まない状態）の頻度を測る。実施済み（難易度PoC「閉じ込めの頻度」）。
5. 本実装の問題集で、レベルごとの盤面の形の配分と速さの基準時間の係数を代表問題の実測で校正する。
