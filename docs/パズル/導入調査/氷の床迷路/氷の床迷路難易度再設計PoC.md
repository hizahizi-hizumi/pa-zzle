# 氷の床迷路難易度再設計PoC

調査日: 2026-11-01

氷の床迷路の5段階を作り直すために、長い問題を生成する方式と、長いだけで簡単な問題を見分ける特徴量を測った PoC の記録。

この文書は導入調査・検証資料であり、現在仕様の正本ではない。現在の5段階（計画深さが主軸）の検討記録は [氷の床迷路難易度](氷の床迷路難易度.md)（以下「難易度記録」）、その元の PoC は [氷の床迷路難易度PoC](氷の床迷路難易度PoC.md)（以下「旧PoC」）、生成方式の比較は [氷の床迷路供給実験](氷の床迷路供給実験.md)（以下「供給実験」）にある。

記述は次のように区別する。

- **事実（実測）**: [`scripts/research/ice_floor_hard_generation_experiment.py`](../../../../scripts/research/ice_floor_hard_generation_experiment.py) で測った結果。条件と再現コマンドは §9。
- **事実（リポジトリ）**: 現在のコード・問題集から確かめたこと。
- **推測**: 計測から導いた判断で、人間の実プレイで確かめていないもの。

まだ誰も新しい案の問題を遊んでいない。§7 の試遊が済むまで、新しい5段階の体験差は仮説として扱う。

## 1. 結論

- **長さは生成の制約にならない。** 岩の配置と開始位置を山登り（G3 と同じ「悪くならなければ受理」）で最適化すると、最短手数の中央値は 8×8 で28、10×10 で41、10×13 で51、12×12 で55、12×14 で63 手まで伸びる（8,000回の評価、Python で1問 0.2〜0.5 秒）。最短 15〜30 手の問題は、範囲の上限で止める探索なら 10×10 以上で 1問 0.03 秒以下で作れる（§4.1）。
- **現行の問題集は、人がゴールから逆向きにも考えるとほとんど浅い。** 前向き・逆向き・両方向の素朴な先読みのうち最も楽な方向で測る「読み深さ」は、現行レベル5の 34% が1、61% が2以下だった。現行の計画深さ（前向きだけ）は全問5〜6。前向きのモデルだけで深さを測っていたことが「レベル5でも簡単」の主な原因と考えられる（§4.2）。
- **長さだけを最大化すると「長い一本道」になる。** 最短手数だけを伸ばした問題は、最短の道筋の手の半分前後が「戻らない選択肢が1つしかない手」（一本道）で、最短 60 手前後でも半数が読み深さ1（近づく手を選ぶだけで解ける）だった（§4.3）。
- **目的関数に「読みどころ」と最短解の一意性を足すと、同じ長さで読み深さが上がる。** 「最短手数＋読みどころの手数（2手以上の遠回りか詰みになる選択肢がある手）−2×log₂(最短解の数)」を最大化すると、一本道はほぼ0になり、同じ最短手数の範囲で読み深さの中央値が上がった（12×14・18〜23手で 3.5 → 7）（§4.4）。
- **新しい5段階の案**（§5）: 盤面と最短手数の範囲を上げつつ、読み深さの範囲・一本道の割合・最短解の一意性で絞る。レベル5は 12×14・最短22〜30手・読み深さ8〜12。各レベル 500 問を Python 1コアで約28分、本番の TypeScript なら数分と見込む。
- **効いた特徴量**は、読み深さ（特に逆向き・両方向）と一本道の手数。最短解の数・ゴールの入口の数・詰みは、最適化した問題では差がつかなかった（§4.3）。
- **ふつうの床（入ると止まる床）は、最適化と読み深さの下で比べ直しても初期版に入れない。** 床は供給も読み深さも改善せず、中継点として働く床は、目印と見抜かれると L4・L5 の読みを2〜5手縮める（§10）。
- **生成 v2（§11）: 手筋を目的関数と採用条件に入れると、v1 で消えていた手筋を作れる。** v1 は詰みの誘いが各盤面 1〜2/32、ゴールを通過する滑りが0の問題が約半数、近い別解が 12×14 で254本だった。v2 は通過の誘い・入り直しがほぼ全問、近い別解が v1 の 1/4〜1/3 になった。ただし詰みの誘いのほとんどは入った直後に閉じ込めの知らせが出る袋小路で、知らせのない詰みは必須にして初めて採れる。段ごとに手筋を足す5段階の案と、試遊候補20問（最短 8〜29 手）を作った。
- **生成 v3（§12）: 盤面の状態が変わる要素（相棒の駒・もろい岩・割れる氷・雪の床）を1種類ずつ足すと、初期盤面を静的に読んでも解けない問題を作れる。** 相棒の駒・もろい岩・割れる氷は、要素を変化しないとみなした盤面が解なしか、解けてもその解が元の規則では通らない（もろい岩・割れる氷では、初期盤面から読める短い解が誤りになる盤面も作れる）。到達できる状態は、相棒の駒で 900〜3,500、もろい岩・割れる氷で 66〜940 と、v2 の停止点（50〜70）より多い。一方、**雪の床は溶けない床とみなして解いても必ず最短で解ける**（ランダム盤面 14,639 組で例外なし）ので、読みは静的な床と変わらない。試遊候補20問（4要素×5問、最短 12〜23 手）を作った。
- **生成 v4（§13）: もろい岩・薄い氷で難しさを最大にすると、使う順序がほぼ決まり、おとりを含む問題を作れる。** 同じ向きが続く手を最短+2手以内に作らない・効かない要素を置かない・おとりを2割以上置く、を条件にして山登りした。最短解で変化させる要素の組のほとんどで、使う順を入れ替えると解けない。薄い氷は「後から止め役を作る」要素として使われ、見た目どおり（氷とみなす）では必ず解なしになる。見た目どおりに読める短い解が誤りになるのは、もろい岩がある盤面だけだった。もろい岩は崩した直後に同じ向きへ必ず動けるので、条件1で 24 回中 18 回外れた。試遊候補9問（3種類×3問、最短 12〜19 手）を作った。

## 2. 前提（ユーザー評価）

実装済みの問題集（難易度記録 §5）を遊んだユーザーの評価は「難易度5でもクソ簡単。最短手数一桁ってやばい」だった。現行のレベル5は 12×14・計画深さ5〜6 で、最短手数の中央値は7（事実（リポジトリ）、難易度記録 §5.4）。

この評価から、次の2点を原因の仮説として調べた。

1. **人は盤面全体を見て、ゴールから逆向きに推論する。** 旧PoC の計画深さは前向きにだけ読むプレイヤーのモデルで、旧PoC 自身も「前向きだけのモデルが計画深さを過大評価しないこと」を試遊の確認点に残していた。
2. **ランダム配置では長い問題がほぼ出ない。** 現行の生成は岩20%のランダム配置から最短3〜14手のゴールを選ぶ（供給実験の G1）。供給実験の G3（局所探索）は長い問題を作れたが、旧PoC の計画深さが上がらないことを理由に採らなかった。その計画深さは6手で読むのをやめ、それより深い問題を評価不能として外していたので、長い問題の難しさを測れていなかった。

## 3. 方式

### 3.1 生成（局所探索）

盤面を岩と氷の配置と開始位置で表し、目的関数を最大化する。ゴールは評価のたびに、到達できる停止点から目的関数が最もよくなるものを選ぶ。

- **近傍**: 1マスの岩・氷の反転（45%）、岩の数を保った岩の移動（45%）、開始位置の移動（10%）。岩の密度は 8〜40% の範囲に保つ。
- **比較した方式**（同じ評価回数）: ランダム（G1 の盤面を作り直して最良をとる）、山登り（悪くならなければ受理。G3 と同じ受理）、焼きなまし（初期温度 0.5 と 1.5 から 0.05 へ指数で下げる）、遺伝的（24個体、行で切る交叉と1〜3回の変異、上位を残す）。
- **最短手数の範囲**: レベルを作るときは最短手数の範囲 [下限, 上限] を与え、上限を超えるゴールは選ばない。長さだけの目的関数は上限に届いた時点で打ち切る。
- 最後に、到達できる停止点からの滑りを止めない岩を除き（供給実験の正規化）、供給実験の `explore`（1マスずつ進める独立の BFS）で最短手数を確かめる。

### 3.2 人の読みのモデル

旧PoC の先読みプレイヤー（k 手先までにゴールがあればそこへ、無ければ各手の後 k−1 手以内で最もよい停止点で手を比べ、戻らず待ったを使わない。同点の向きの順位4通りの最小をとる）を、読む方向で3通りに広げた。

| モデル | 起点 → 目標 | 「よい」の基準 | 人の解き方との対応 |
| --- | --- | --- | --- |
| 前向き | 開始位置 → ゴール | 近づく・揃える（旧PoC と同じ） | 駒から滑らせて先を読む |
| 逆向き | ゴール → 開始位置（滑りを逆にたどる） | 開始位置に近づく・揃える | ゴールに止まれる入口を探し、その入口へ止まれる場所を探す |
| 両方向 | 開始位置 → ゴールへ k 手以内で止まれる停止点の集合 | その集合に近づく | ゴール側を k 手逆に読んでおき、駒側からも k 手読んでそこを目指す |

- 逆向き・両方向は、開始位置から到達できるかを問わず、盤面全体の停止点（岩・外壁に接する氷のマスと開始位置）で考える。人は到達できるかを知らずにゴールの手前を探すため。
- **読み深さ**（`human_depth`）は3つのモデルが解ける最小の k の最小値。12手読んでも解けなければ「読めない」（13）。
- **解けたとみなす手数の上限**は最短手数の 1.5倍＋2 にした。旧PoC の 4×最短手数+8 は、最短20手を超えると到達できる停止点の数（50〜70）より多い手数を許し、戻らないだけのプレイヤーが停止点を総なめにして着いても「読みで解けた」になり得るため。ただし一時スクリプトで §4.4 の800問を測り直すと、1.5倍＋2 と 4倍+8 で読み深さの中央値が違ったのは50群中1群（12×14・9〜12手の長さだけ、2 と 3）だけで、実際の差は小さかった。最短+2 まで縮めると読み深さ1が減る（12×14・18〜23手の合成で 1/16 → 0/16 など）ので、少しの回り道は「読みで解けた」に含める 1.5倍＋2 にした。

このほか、次の特徴量を測った。

| 特徴量 | 意味 |
| --- | --- |
| 一本道（`forced_steps`） | 方向番号の小さい手を優先した最短の道筋のうち、通ってきていない行き先が1つしかない手の数 |
| 読みどころ（`decisions`） | 同じ道筋のうち、最短より2手以上遠回りになるか詰みになる選択肢がある手の数 |
| 最短解の数・近い別解の数 | 最短手数の道筋の数、最短+2手以内で同じ停止点を二度通らない道筋の数 |
| ゴールの入口 | 1手でゴールに止まれる停止点の数（盤面全体）、ゴールへ2手以内の停止点の数 |
| 試行手数 | 待ったを使い近づく順に試す試行錯誤の手数（旧PoC と同じ） |
| 詰み | 到達できる停止点のうちゴールへ戻れない数、最短の道筋上で詰みへ入る選択肢の数 |
| BFS の調べる停止点 | 前向き・逆向き・小さい前線から広げる両方向の BFS が、出会うまでに調べる停止点の数 |

### 3.3 検証（事実（実測））

- 速い停止点の BFS（滑りの行き先を表で持つ）は、供給実験の `explore` と 283盤面で到達停止点と最短手数が一致した。
- 前向きモデルは、手数の上限を旧PoC と同じ 4×最短手数+8 にすると、旧PoC の `analyze` の計画深さと 283問で一致した（6手以内の範囲、不一致0）。
- 生成した問題は毎回 `explore` で最短手数を確かめ、無関係な岩を除いた後も最短手数が変わらないことを確かめている。

## 4. 結果

### 4.1 長い問題をどこまで作れるか（事実（実測））

**方式の比較**（長さだけを最大化、8,000回の評価、各16回。最短手数の 中央値 / 90%点 / 最大）:

| 盤面 | ランダム（G1） | 山登り | 遺伝的 | 1回の時間（山登り） |
| --- | ---: | ---: | ---: | ---: |
| 8×8 | 18 / 19 / 19 | 28 / 30 / 31 | 25 / 29 / 32 | 0.22 s |
| 10×10 | 22 / 23 / 26 | 41 / 44 / 44 | 35 / 39 / 43 | 0.31 s |
| 10×13 | 25 / 26 / 26 | 52 / 58 / 60 | 40.5 / 46 / 47 | 0.38 s |
| 12×12 | 26 / 28 / 29 | 56 / 61 / 62 | 43.5 / 48 / 49 | 0.43 s |
| 12×14 | 27 / 28 / 30 | 62 / 71 / 72 | 49.5 / 57 / 63 | 0.49 s |

焼きなましは 8×8 で 29（初期温度0.5）/ 27.5（1.5）、12×14 で 64 / 64 と山登りと同程度だった。山登りは途中経過でも速く（12×14 で 1,000回 43.5、2,000回 51、4,000回 58.5）、遺伝的は早く頭打ちになった。**最も単純な山登りを採る。**

**採用した方式での盤面ごとの最大**（山登り、8,000回、各40回）:

| 盤面 | 最短手数 中央値 / 90%点 / 最大 | 1問 | 正規化後の岩の密度 |
| --- | ---: | ---: | ---: |
| 8×8 | 28.5 / 31 / 32 | 0.22 s | 0.28 |
| 10×10 | 41 / 46 / 48 | 0.32 s | 0.31 |
| 10×13 | 51 / 55 / 57 | 0.40 s | 0.31 |
| 12×12 | 55 / 61 / 63 | 0.45 s | 0.30 |
| 12×14 | 63 / 68 / 74 | 0.49 s | 0.32 |
| 14×14（参考） | 71 / 77 / 85 | 0.57 s | 0.32 |
| 12×16（参考） | 70 / 76 / 83 | 0.56 s | 0.32 |

最短手数の範囲の上限で打ち切る探索では、範囲 24〜30 手の問題が 8×8 で平均0.15 s、10×10 以上で 0.03 s 以下だった（各16回）。目標の 15〜30 手は、どの盤面でも長さの点では容易に作れる。

**岩の密度**（山登り、8,000回、各16回。最短手数の中央値）:

| 盤面 | 固定12% | 16% | 20% | 25% | 30% | 8〜40%を探索に任せる |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 8×8 | 18 | 21 | 24 | 26 | 27 | 28.5（密度 0.28） |
| 10×10 | 25 | 28.5 | 32 | 37 | 39 | 42.5（0.31） |
| 12×14 | 32 | 40 | 47 | 54 | 57.5 | 64.5（0.32） |

ランダム配置で長い問題が出やすい密度は 18〜26%（供給実験）だったが、最適化すると密度は 30% 前後へ寄り、密度を固定するより範囲を与えて探索させる方が長くなる。以降は 8〜40% を探索に任せる。

### 4.2 現行の問題集を読み深さで測り直す（事実（実測））

現行の問題集（各レベル500問の全問）:

| レベル | 最短手数 中央値 | 現行の計画深さ | 前向き / 逆向き / 両方向 中央値 | 読み深さの分布 | 読み深さ2以下 |
| --- | ---: | --- | ---: | --- | ---: |
| 1 | 3 | 1 | 1 / 2 / 1 | 1: 490, 2: 10 | 100% |
| 2 | 5 | 1〜2 | 1 / 3 / 1 | 1: 443, 2: 52, 3: 5 | 99.0% |
| 3 | 5 | 3 | 3 / 2 / 2 | 1: 289, 2: 171, 3: 40 | 92.0% |

| 5 | 7 | 5〜6 | 5 / 4 / 2 | 1: 170, 2: 133, 3: 140, 4: 38, 5: 16, 6: 3 | 60.6% |

- 現行の計画深さ（前向き）はレベル3〜5で 3 / 4 / 5 と上がるが、両方向の中央値は 2 / 2 / 2 で、レベル間の差がほとんど無い。
- レベル5の 34% は読み深さ1で、「ゴールに1手で止まれる入口を見つけ、そこへ近づく手を選ぶ」だけで解ける。
- 推測: 人が盤面を見てゴールの入口から考える解き方をするなら、現行のレベル3〜5の体感差は小さく、レベル5も簡単に感じる。ユーザー評価と整合する。

### 4.3 長いだけで簡単な問題と、効いた特徴量（事実（実測））

12×14 で長さだけを最大化した16問（最短手数 中央値62）と、合成の目的関数（§4.4）で最大化した16問（同50.5）を、現行レベル5と比べた（中央値 / 90%点）。

| 特徴量 | 現行L5 | 長さだけ | 合成 |
| --- | ---: | ---: | ---: |
| 最短手数 | 7 / 11 | 62 / 71 | 50.5 / 57 |
| 読み深さ | 2 / 4 | 3 / 読めない | 読めない / 読めない |
| 読み深さ1の問題 | 34% | 8/16 | 0/16 |
| 一本道 | 1 / 3 | 35.5 / 45 | 10 / 15 |
| 読みどころ | 4 / 7 | 13 / 18 | 29 / 33 |
| 試行手数 | 26 / 55 | 71 / 79 | 74 / 85 |
| 最短解が一意 | 87% | 12/16 | 16/16 |
| ゴールの入口（盤面全体） | 3 / 6 | 1 / 2 | 1 / 1 |
| 詰みの停止点 | 0 / 16 | 0 / 0 | 0 / 0 |

- **長さだけの問題は一本道が多い。** §4.4 の 8×8・24〜30手の長さだけの問題の例（最短30手）では、30手のうち23手が一本道で、試行手数が最短手数と同じ（無駄な手が無い）だった。戻らずに「まだ行っていない方へ」滑り続ければ着くので、読み深さは1になる。
- **一本道の手数と読み深さが、長いだけの問題を見分けた。** 現行の問題集2,500問と上の32問をまとめた最短手数との順位相関は、読み深さ 0.46、両方向の深さ 0.43、試行手数 0.52 で、長さと別の量になっている。
- **差がつかなかった特徴量**: 最短解の数（どの方式でもほぼ一意）、ゴールの入口の数（最適化するとほぼ1）、詰み（最適化した問題は中央値・90%点とも0。長い道筋を作ると滑りが行き来できる盤面になる）、ゴールを通過する滑り（どの群も中央値0〜3）。BFS が調べる停止点の数（両方向）は最短手数との順位相関が 0.91 で、長さの言い換えだった。
- 近い別解（最短+2手以内）は合成の目的関数で大きく増える（12×14・18〜23手で 66.5 → 244）。最短解は一意でも、少し遠回りすれば着く道が多い。試遊で「どこからでも何となく着く」と感じられないかを確かめる（§7）。

### 4.4 目的関数の比較（事実（実測））

最短手数の範囲を与え、長さだけ（範囲の上限まで伸ばす）と合成（最短手数＋読みどころ−2×log₂(最短解の数)）を比べた。山登り6,000回まで、各16回。値は中央値。

| 盤面 | 範囲 | 目的関数 | 最短 | 読み深さ | 前 / 逆 / 両 | 試行手数 | 一本道 | 読みどころ | 読み深さ1 | 1問 |

## 7. 人の試遊で確かめること

1. **レベル5（最短22〜30手）が「簡単」でなくなり、かつ長すぎて嫌にならないこと。** スマホの 12×14（1マス24〜30 px）で25手前後を組み立てる負担が、挑戦として受け入れられるか。
2. **逆向きの推論で人が実際に楽をしているか。** §6 のレベル1の例（現行の計画深さ5、読み深さ2）を、現行レベル5の問題と並べ、ゴールから考える人にとって簡単かを確かめる。逆向きに考えないなら、読み深さは人の難しさを過小評価する。
3. **レベル1→5で難しさが概ね上がると感じられること。** 特にレベル4（読み深さ5〜7）と5（8〜12）の差。どちらも頭の中だけで読める手数を超えると考えられるので、差が試行錯誤の量でしか感じられないかもしれない。
4. **合成の目的関数の盤面が面白いこと。** 岩の密度が3割前後で、どの手にも遠回りになる選択肢がある盤面が、ごちゃごちゃして見づらくないか。近い別解（最短+2手以内）が多いので、少し回り道すればどこからでも着く感じにならないか。
5. **一本道の多い問題がつまらない（簡単すぎる）こと。** 対照として、§4.3 の長さだけで作った問題（例: 8×8 最短30手で23手が一本道）を1〜2問混ぜると確かめられる。
6. 詰みがほぼ無いこと（最適化した盤面は滑りを行き来できる）で、罠を読む挑戦が失われていないか。

## 8. この PoC で判断しないこと・限界

- 読み深さの3モデルは、人の解き方の素朴な近似である。逆向き・両方向の「よさ」は開始位置・入口の集合へのマンハッタン距離だけで、人が使う「この岩なら止まれる」という形の認識は表していない。
- 読み深さ 8〜12 の区別が人の体感に対応する根拠は無い。上のレベルの区別は最短手数と試行手数にも頼っている。
- 計測はすべて Python。TypeScript での時間は旧PoC の比から推測した。
- 盤面の形は 8×8・10×10・10×13・12×12・12×14 だけを使った。現行の 8×10・9×12 は測っていない。
- 合成の目的関数の重み（読みどころ1、最短解の数 −2×log₂）は1通りしか試していない。

## 10. ふつうの床の比べ直し

供給実験は「ふつうの床」（入ると止まる床。供給実験の (b)）を、岩のランダム配置と旧PoC の計画深さの下で比べて見送った（難易度PoCの仮レベル5の割合が (a) の±1.6ポイント、止まれる場所が増えて読みが薄まる）。§2 のとおり、その生成は長い問題をほぼ作れず、指標は人の難しさを表していなかった。そこで床を山登りの対象に入れ、§5 の新しい5段階案の範囲と読み深さで比べ直した。

### 10.1 床の規則と実装

- **規則**: 滑っている駒が床のマスに入ると、そこで止まる。床の上から動くときは氷と同じに滑る（隣が床なら、その1マスで止まる）。駒は岩と違って床に入れる。
- **ゴール・開始位置は床に置かない。** 置いてよいとした比較（§10.4）でも、最適化は床の上のゴール・開始位置を選ばなかった。
- **人のモデル**: 床のマスは停止点としてそのまま停止点グラフに入る。「揃える」（同じ行・列で間に障害が無い）の判定では床も遮るものとする（床の先へは1手で行けないため）。旧PoC の計画深さ（`legacy_depth`）の判定も同じに直した。床の無い盤面では、どちらも変わらない。
- **正規化**: 無関係な岩を除く前に、駒の動きを変えない床（到達できる滑りが入らない床と、入ってくるどの滑りも次のマスが岩・外壁で、氷でも同じマスで止まる床）を氷に戻す。以下の床の数は正規化後の数。
- **近傍**: 開始位置の移動 10%（§3.1 と同じ）、床の追加・削除・移動（各1/3）20%、残り 70% を岩の反転と岩の移動に半分ずつ充てる。床は上限の枚数をランダムに置いて始める。
- **床を中継点に使わせる条件**（表の「道筋 k 回以上」）: 方向番号の小さい手を優先した最短の道筋が、ゴールより前に床で止まる手が k 回以上あること。合成の目的関数では足りない1回につき10点を引き、採用条件にも加える。床を置いてよいだけでは最適化が床をほとんど使わない（§10.2）ため、床を使う問題の性質を測るために設けた。
- **検証（事実（実測））**: 床を含むランダム盤面300（岩20%、岩でないマスの8%を床）で、滑りの表が供給実験の `slide`（1マスずつ進める）と全マス・全方向で一致し、停止点の BFS が `explore` と一致し、正規化の前後で到達できる停止点と最短手数が変わらなかった（不一致0）。床の無い盤面では、`verify`・`levels`・`candidates` の出力（時間を除く）が拡張前と一致した。`floors` の床なしは `levels` と同じ seed を使い、同じ問題を作る。

### 10.5 推奨: 初期版に床を入れない

- **供給・難しさのどちらも改善しない。** 新しい5段階案の各範囲で、床は最短解の一意性・一本道・読み深さ・読みどころを変えず、採用数の増加（L3〜L5 で最大+15/64）も、§5.2 の生成時間では必要としていない。長さも生成の制約ではない。
- **床の構造上の効き目は中継点で、それは通り道の手がかりにもなる。** 床で区切ると L4・L5 の読み深さが2〜5縮む。「レベル5でも簡単」を直すための作り直しに、上のレベルの読みを縮めうる要素を足す理由が無い。
- **説明と見分けの負担が増える。** ルールに「床では止まる」が1文増え、「ゴールは通り過ぎると止まらないのに、床では止まる」の対比を伝える必要がある。スマホ操作PoC の改善案（灰緑に点模様）では 12×12・320px とグレースケールでも見分けられたが、新しい案の L4・L5（12×12・12×14、1マス約24 px）は表示の下限で、岩の密度も3割前後に上がる（§4.4）。3種類目の床面を足す余裕は小さい。

### 10.7 人の試遊で確かめること

1. **床を目印にして解くか。** §10.6 の L5 の2問を、床なしの L5 候補（§6）と並べて遊び、床のある問題が体感で易しいか、床へ向かう手から解き始めるかを見る。床を目印にするなら、§10.5 のとおり入れない（入れるなら床で区切った読み深さで絞る）。

### 10.8 この節の限界

- 床の働きの判断は、素朴な先読みのモデル（§3.2）と、それを床で区切った値にだけ基づく。人が床をどれだけ目印にするかは測っていない。
- 床の近傍の割合（20%）、道筋で止まる回数の罰（1回10点）、床の数の上限は1通りずつしか試していない。
- 各群64回で、採用数には95%の幅で±8問ほどの揺れがある。

## 11. 生成 v2: 手筋を含む問題

§4〜§6 の生成（以下「v1」。目的関数は最短手数＋読みどころ）の候補に対するレビューを受け、このパズル固有の手筋を特徴量にして目的関数と採用条件に入れた生成（以下「v2」）を作り、v1 と比べた。スクリプトは [`scripts/research/ice_floor_tactic_generation_experiment.py`](../../../../scripts/research/ice_floor_tactic_generation_experiment.py)（v1 のスクリプトから盤面・山登り・読み深さを import し、v1 の結果は変えない）。条件と再現コマンドは §11.9。

### 11.1 v1 へのレビューの指摘

- 長くした問題は「読む」でなく「探す」ゲームになり、20手を超えると一本道の通路歩きの作業感が出る。
- 長くした候補から、このパズル固有の手筋が消えていた。詰みへ入れる停止点が L4/L5 で0、ゴールを通り過ぎる滑りが L4 全問・L5 の2/3 で0、最短+2手以内の別解が L5 で233本（どこからでも何となく着く）。
- v1 の目的関数の「読みどころ」は、2手以上の遠回りになる選択肢の数を数えるだけで、手筋の質を測っていない。
- 遊ぶ側のレビュー: 「最短経路はほぼ1通り、道が1本の長い通路が多い」「罠や分かれ道を見抜く面白さが欲しい」。
- 提案: 手筋の特徴量を目的関数と採用条件に入れ、段ごとに手筋を1つずつ足す。

手数の長さはユーザー自身の試遊で決める（AI レビュアーの所要時間は人の体感と合わない）。v2 は長さを目的にせず、最短手数は範囲の制約にだけ使う。

### 11.2 手筋の特徴量

「最短の道筋」は v1 と同じく、方向番号の小さい手を優先した最短の道筋。「もっともらしい手」は、滑った先がゴールへ近づく（マンハッタン距離が減る）、ゴールと見通しで揃う（同じ行・列で間に岩が無い）、滑りがゴールを通過する、のどれかに当たる手で、人が目先で選びたくなる手のモデルである。

| 特徴量 | 定義 | タグ（試遊候補に付ける名前と条件） |
| --- | --- | --- |
| 止め石 | 最後の滑りを止めるのが岩（外壁でない）で、ゴールに1手で止まれる停止点（盤面全体）が2つ以下 | 止め石 |
| 回り込み | 最後の滑りが開始位置の側へ向かう（ゴールの向こう側へ回ってから入る） | 回り込み |
| ゴール通過の誘い | 最短+2手以内の道筋に乗る停止点から、ゴールを通過して止まらない滑りの数。そのうち通過した先が詰みのもの | 通過の誘い（1以上）、通過で詰む（1以上） |
| 入り直し | 最短の道筋で、ゴールと見通しで揃った停止点から揃わない停止点へ離れる回数 | 入り直し（1以上） |
| 詰みの誘い手 | 最短の道筋上の各停止点で、詰み（ゴールへ二度と止まれない停止点）に入る、もっともらしい選択肢の数。そのうち、入った直後に SPEC-019 の閉じ込めの知らせが出ないもの | 詰みの誘い（1以上）、知らせのない詰み（1以上） |
| 逆算の段数 | ゴールから盤面全体の停止点（無関係な岩を除いた出題される盤面、到達できるかを問わない）を逆にたどり、各段の候補が2つ以下（止め石を探す必要がある）の段が続く数。開始位置から1手で止まれる停止点に届いたら打ち切る | 逆算3段（3以上） |
| 分岐の質 | 最短の道筋で、もっともらしい選択肢が2つ以上ある手（分かれ道）。もっともらしいが3手以上の遠回りか詰みになる選択肢（偽の道） | 分かれ道（分かれ道の手が最短手数の1/4以上） |
| 遠回り | 最短の道筋でゴールから離れる手が続く区間のうち、もっともらしい別の手を捨てて始まるもの | 遠回り（1以上）、遠回り2回（2以上） |
| 近い別解 | 最短+2手以内で同じ停止点を二度通らない道筋の数（v1 と同じ）。目的関数ではその道筋に乗る停止点の数で代える | — |
| 一本道 | v1 の `forced_steps` | — |

- 特徴量は、到達できる停止点のグラフ（滑りの行き先を表で持つ速い実装）から求める。供給実験の `explore`（1マスずつ滑らせる独立の実装）と、最短手数・最短解の数・詰みの停止点・ゴールを通過する滑りが 285 問で一致した（事実（実測））。
- 目的関数では v1 の読み深さ（`human_depth`）を3まで（L5 は5まで）求める。全点対の距離を作らずに小さい BFS で求める実装で、v1 の `features_of` と 285 問で一致した（4 で打ち切った値の比較、事実（実測））。

### 11.3 目的関数と採用条件

v1 と同じ山登り（2,000回、悪くならなければ受理、岩の密度 8〜34%）で、次を最大化する。ゴールは最短手数の範囲内の停止点から、長い順に8つを比べる。

- 加点（それぞれ上限つき）: 通過の誘い（2点×最大2）、通過で詰む（2点）、詰みの誘い（3点×最大2）、入り直し（2点×最大2）、回り込み（1点）、逆算の段数（1.5点×最大4段）、偽の道（1.5点×最大10）、遠回り（1.5点×最大2）、分かれ道（0.5点×手数）、読み深さ（1.5点×最大3）。
- 減点: 一本道（2点×手数）、近い道筋に乗る停止点（1.5点×数）、最短解の数（2×log₂）、関係する岩が盤面の22%を超えた数（0.3点×数）。
- **長さには点を与えない。** 範囲に届かない盤面だけ、長さで比べて罰を与える。
- 条件ごとに必須のタグは重みを2倍にし、含めないタグは重みを −4 にする。さらに必須のタグが無い・含めないタグがあるごとに 6 点を引く（重みだけでは山登りが手筋を作り切れないため）。
- 採用条件: 必須のタグをすべて含み、含めないタグを含まない。最短解が一意、一本道が最短手数の25%以下。条件ごとに読み深さの範囲と近い別解の上限を与える。最後に無関係な岩を除き、`explore` で最短手数を確かめる。

### 11.7 人の試遊で確かめること

1. **手数の範囲。** 最短 8〜29 手の候補で、どの手数から「長すぎて作業になる」と感じるか。§11.5 の各段の最短手数の範囲は、これで決め直す。
2. **手筋が「読む」面白さになるか。** 誘いなし（q05・q07）と、同じくらいの手数の誘いのある問題（q02・q11、q01・q10・q18）を比べ、通過の誘い・詰みの誘いを見抜く楽しさが感じられるか。
3. **知らせのない詰みと知らせが出る詰み。** q12・q17・q01・q10（知らせが出る）と q06・q04・q15・q08（知らせなし）で、罠として働く差があるか。知らせが出る詰みが罠として弱いなら、詰みの誘いは知らせのないものだけを数える。
4. **逆算が手筋として感じられるか。** 逆算3段はほぼ全問に出る。ゴールの入口から逆にたどって解いたか、それが難しさ・面白さになったかを聞く。
5. **盤面の見た目。** 岩の密度 0.2〜0.25 の盤面で、止め石の意味が読めるか、ランダムな模様に見えないか。特に 12×12・12×14 の候補。
6. **段の順序。** §11.5 の L1→L5 の手筋の足し方（止め石 → 回り込み → 通過 → 詰み → 逆算と組み合わせ）が、難しさの順に感じられるか。

### 11.8 この節で判断しないこと・限界

- 「もっともらしい手」は、近づく・揃う・通過するの3つだけのモデルで、人が実際にどの手を選びたくなるかは測っていない。
- 逆算の段数は、各段の候補の数だけで測っている。候補が少ない段は止め石を探す必要があるとみなしたが、候補が1つなら逆向きに読むのは易しいとも言える（v1 の逆向きの読み深さは低くなる）。どちらに働くかは試遊で確かめる。
- 重み・上限・罰は、12×14・10×10 の各8〜12回の比較で決めた1通りしか試していない。
- 試遊候補は条件ごとに目的関数の点が最もよい1問で、その条件の平均的な問題ではない。
- 計測はすべて Python。TypeScript での時間は v1 と同じ比から推測した。

- **先行事例の調査**: 駒1つ・静的な盤面は停止点のグラフが小さく「見れば分かる」。難しさを生むのは、止め役が動く・消える・現れる要素で、初期盤面と解いている途中の盤面が違うこと。静的な床は状態を増やさない（§10 の床もこれに当たる）。
- **盤面の見た目への指摘**: 駒がどう動いても通らない領域が盤面として描かれているのは違和感がある。

### 12.2 要素の規則

盤面の文字は `.` 氷、`#` 岩、`x` 盤面の外。状態は（駒の位置, 変化したマスの集合）で、最短手数は状態の BFS で求める。

| 要素（文字） | 規則 |
| --- | --- |
| 相棒の駒（duo） | 駒が2つ。主駒 A（ゴールへ運ぶ）と相棒 B。1手で A か B の一方を滑らせる。滑る駒は岩・外壁・もう一方の駒の手前で止まる。B はゴールの上を通過・停止してよい。クリアは A がゴールで止まったときだけ。手数は A・B の移動の合計 |
| もろい岩（`b`） | 岩と同じ止め役。駒が滑ってぶつかって止まった（滑りの終わりで進行方向の次のマスがもろい岩だった）とき、その滑りの後で崩れて氷になる |
| 割れる氷（`c`） | 氷と同じく滑れる。駒がいたマスは、駒が離れた時点で岩になる。滑りの途中で通過したマスはその滑りの後で、止まったマスは次にそこから動いた滑りの後で岩になる。開始位置とゴールにしない |
| 雪の床（`s`） | 滑っている駒は雪の床に入るとそこで止まる。駒が雪の床から次に動いた時点で氷になる（1回だけ止まれる）。開始位置とゴールにしない |
| 盤面の外（`x`） | 外壁と同じ止め役。駒は入らない（§12.4） |

実装で決めたこと:

- **動かない入力は手にならない。** その場から動かない向きの入力は、どの要素でも状態を変えない（本番の「成立しない向きの入力」と同じ）。隣のもろい岩へ向けて入力しても崩れず、割れる氷の上で動かない入力をしても割れない。もろい岩を崩すには、離れたところから滑ってきてぶつかる必要がある。
- **もろい岩**が崩れるのは、そのもろい岩で止まったときだけ。崩れたマスは氷になり、以後は通過も停止もできる。同じもろい岩は止め役として1回しか使えない。
- **割れる氷**は、駒が上にいる間は氷のまま。滑りの出発マス（割れる氷の上に止まっていた場合）と途中で通過したマスが、その滑りの後で同時に岩になる。今の滑りの行き先には影響しない。
- **雪の床**は、入った滑りがそこで止まる（その先が氷でも岩でも同じ）。雪の上から出る滑りはふつうに滑り、出発マスの雪はその滑りで氷になる。1回の滑りの途中に雪が複数あれば、最初の雪で止まる。
- **相棒の駒**: 開始時に B をゴールに置かない。最短解の数は A の手の列と B の手の列の組で数え、独立な手の順序の入れ替えは同じ解とみなす（A と B の手を入れ替えても結果が同じなら、人には同じ解に見えるため）。順序で結果が変わる入れ替えも同じ組に数えるので、一意性は甘めに判定している。
- 最短解は、手の番号の小さい手（上・右・下・左の順、duo は A の手を B の手より先）を優先して1つ選ぶ。

### 12.3 状態つき BFS と検証（事実（実測））

- 状態を整数（単駒の要素は「変化した要素のビット列 × マス数 + 駒の位置」、duo は「B の位置 × マス数 + A の位置」）で表し、変化した要素の組ごとに v1 の滑りの表（`stop_tables`、雪は v1 の床の扱い）を作って使い回す。
- **手で作った小盤面**で、要素ごとの遷移が規則どおりになることを確かめた（もろい岩: 止まった後に崩れる・崩れた跡を通れる・隣へ向けた入力では崩れない。割れる氷: 通過したマス・止まって離れたマスが岩になる・止まっている間は割れない。雪: 止まる・離れると溶ける・溶けた跡を通れる・手前の雪で止まる。duo: もう一方の駒の手前で止まる・B を退かしてから A を運ぶ2手の解。x: 外壁と同じ）。
- **独立の実装との突き合わせ**: 1マスずつ進めて盤面の文字を書き換える独立の実装と、到達できる全状態の手を比べ、ランダム盤面（5〜7×5〜7、要素2〜6個）で各要素100問、不一致0だった。
- **x への置き換え**: 各要素約100問で、置き換えの前後で状態の数・最短手数・最短解の数・最短解の手が一致した（変わった0問）。試遊候補も生成のたびに同じことを確かめている。

### 12.4 特徴量・目的関数・盤面の外

**特徴量**（状態のグラフ上で測る。ゴールに止まった状態は終わり）:

| 特徴量 | 定義 |
| --- | --- |
| 使う回数 | 最短解で要素を使った回数。相棒の駒: A が B で止まる。もろい岩: 崩す＋崩れた跡を通る。割れる氷: 割れてできた岩で止まる。雪の床: 雪で止まる＋溶けた跡を通る |
| 見た目どおりの盤面 | 要素が変化しないとみなした静的盤面（もろい岩→岩、割れる氷→氷、雪の床→溶けない床、B→岩で A だけ動かす）の最短手数と、その最短解を元の規則で再生してクリアになるか |
| もう一方の盤面 | 要素をもう一方のふつうのマスにした静的盤面（もろい岩→氷、割れる氷→岩、雪の床→氷、B を除く）の最短手数と同じ再生 |
| 効く要素 | 要素を1つだけ見た目どおりの静的なマスにすると、解けなくなるか最短手数が変わる要素の数（雪の床は氷にして測る。§12.5）。duo は B を岩にした盤面で0か1 |
| 状態の読み深さ | v1 の読み深さのうち前向き・両方向のモデルを、状態のグラフに当てた深さ（規則を完全に知って先を読む人のモデル）。逆向きのモデルは、途中の状態がゴール側から分からないので使わない。8で打ち切り、それでも読めなければ「読めない」 |
| 静的な読み深さ | 見た目どおりの盤面に v1/v2 の読み深さモデル（前向き・逆向き・両方向）を当てた深さ。初期盤面だけを見て読む人のモデル |
| 近い状態 | 最短+2手以内の道筋に乗り、どの最短解にも乗らない状態の数 |
| 未使用のマス | 到達できる全状態で、駒（duo は A・B のどちらか）が一度も通過・停止しない、岩でないマス |

**目的関数**: v1/v2 と同じ山登り（1,500回、悪くならなければ受理）に、要素の追加・削除・移動（近傍の30%）と B の移動（duo、近傍の10%）を足した。ゴールは範囲内の最短手数で A が止まれる氷のマスから長い順に4つを比べる。

- 加点: 要素を置き換えた静的盤面が解けない（1）・元の規則で通らないか4手以上の遠回り（0.5）の合計×4点、効く要素×2点（最大4）、見た目どおりの盤面の解が元の規則で通らない 2点、使う回数×1.5点（最大6）、使う要素の数（duo は B の手の数）×1.5点（最大4）、duo の駒の替わり×0.5点（最大6）、最短解上で詰みへ入る選択肢×1点（最大3）、状態の読み深さ×1.5点（最大3）。

- 最短手数そのものには点を与えない（範囲の制約だけ）。

採用条件（全段共通）: 最短解が一意、一本道が最短手数の25%以下、どの状態でも変化しない要素が無い、要素を置き換えた静的盤面の合計（上の加点の 1/0.5）が1以上。見た目どおりの盤面の解が元の規則でも通り、最短+4手未満なら「静的な近道」、もう一方の盤面の解が通り最短+2手以内でも「静的な近道」として外す。duo の効く要素の下限は1。

「見た目どおりの読みが誤り」は、見た目どおりの盤面に解があり、その解が元の規則で通らないか4手以上の遠回りになること。何も求めない段では、見た目どおりの盤面が解なしの問題がほとんどになるため、段2・4で求めた。山登りが解なしの盤面に留まらないよう、この段では見た目どおりの盤面が解なしのときの不足を、近道のときの不足より重くした。duo は B を岩とみなした解が元の規則でも必ず通り（B が動かなければ盤面は同じ）、誤りは遠回りだけになる。B を3手以上動かす最短解と両立する遠回りの読みは作れなかった（4手以上で16回中0、2手以上でも8回中0）ので、duo では求めていない。

### 12.5 雪の床は溶けない床と同じに解ける（事実（実測）と推測）

雪の床を溶けない床とみなした静的盤面の最短解は、元の規則でも必ず通り、最短手数も変わらなかった（ランダム盤面 6〜8×6〜8・雪2〜6個の 14,639 組（盤面・ゴール）で例外0、事実（実測））。

理由（推測）: 静的盤面の最短の道筋は同じ停止点に二度止まらないので、溶けた雪のマスへ滑り込む手を含まず、元の規則でも同じに動く。逆に溶けた雪を通り抜ける手は、溶けない床なら「雪で止まる＋同じ向きへ滑る」の2手になるが、その雪にはすでに一度止まっているので、静的盤面では間の手を省いた短い道筋がある。雪の床の変化（1回しか止まれない・溶けた跡を通れる）は、最短の道筋では効かない。

そのため雪の床では、見た目どおりの盤面を「静的な近道」とみなさず、効く要素を「氷にすると解けない・長くなる」（止め役として要るか）で測った。雪の床の候補は、状態は増えるが読みは§10 のふつうの床と同じになる対照として出す。

- 最短解はすべて一意（duo は手の入れ替えを除いて一意）。x は各問 0〜3 マス。

例: v13（もろい岩、8×8、最短13手）。S が開始位置、G がゴール、b がもろい岩。

```text

........
```

もろい岩を岩とみなすと、上・右・下・右・下・左・上の7手で解ける（静的な読み深さ1）。しかし3手目の「下」で止めた最下段のもろい岩はその滑りの後で崩れるので、6手目の「左」はそのもろい岩で止まらず、開始位置まで滑ってしまう。元の規則の最短は13手で、もろい岩4つを崩し、崩れた跡を4回通る。

### 12.8 人の試遊で確かめること

1. **最初の数秒で読み切れないか。** v2 の試遊（最初の数秒〜十数秒で読み切り、待ったなし）と比べ、最初の手を入力するまでの時間・待ったの回数・最短手数ちょうどで解けたかを見る。雪の床（v02・v10・v04・v19・v14）は §12.5 のとおり静的な床と同じ読みで解けるはずの対照で、他の要素との差が出るかを見る。
2. **見た目どおりの読みの誤り。** v13・v17（もろい岩、静的な読み深さ1）、v20・v07（割れる氷）、v03 で、初期盤面から読んだ短い道筋を試して失敗するか。それが「騙された」面白さになるか、理不尽に感じるか。見た目どおりの盤面が解なしの問題（v18・v09・v01・v11・v16 など）との違いも聞く。
3. **相棒の駒は読みか作業か。** 状態は 900〜3,500 と最も多い。B を何手もかけて運ぶ部分（v12 は12手中 B が8手）が、読みどころになるか、位置合わせの作業に感じるか。
4. **要素の見分け。** 8×8〜10×12 で、もろい岩・割れる氷・雪の床が岩・氷と見分けられるか。割れた後・崩れた後の盤面の変化が追えるか（表示の工夫が要るか）。
5. **盤面の外（x）。** x のマスが盤面の欠けとして自然に見えるか。今回の候補は x が少ない（0〜3マス）ので、未使用の領域が残っていないかも見る。
6. **どの要素を初期版に入れるか。** 難しさと分かりやすさの両方で、4要素のどれを採るか（複数を組み合わせるかは、この実験では判断しない）。

### 12.9 この節で判断しないこと・限界

- 状態の読み深さは、変化した状態を正しく覚えて先を読む人のモデルで、盤面の変化を見落とす・忘れる人の読みは測っていない。見た目どおりの読みも、v1/v2 の読み深さモデルを要素を変化しないとみなした盤面に当てただけで、人が要素の変化をどこまで織り込んで読むかは測っていない。
- 「見た目どおりの読みが誤り」は、番号の小さい手を優先した1つの静的な最短解だけで判定している（JSON の `static_looks_valid_solutions` に、静的な最短解のうち元の規則で通る数を出した）。
- 雪の床が溶けない床と同じに解けることは、ランダム盤面での実測と推測による説明で、証明していない。生成した盤面（山登りで最適化した盤面）でも溶けた跡を通る最短解は出なかった。
- 重み・上限・罰は、各要素1〜2段の4〜8回の試しで決めた1通りしか試していない。試遊候補は各段で目的関数の点が最もよい1問で、その段の平均的な問題ではない。
- 要素の組み合わせ（例: 相棒の駒＋もろい岩）は試していない。
- 計測はすべて Python。

## 13. 生成 v4: もろい岩・薄い氷の難しさの上限

生成 v3（§12）の試遊を受け、もろい岩・薄い氷でどこまで難しくできるかを測るため、難しさを最大にする方向へ山登りする生成（以下「v4」）を作り、もろい岩だけ・薄い氷だけ・両方の3種類を比べた。スクリプトは [`scripts/research/ice_floor_hardest_generation_experiment.py`](../../../../scripts/research/ice_floor_hardest_generation_experiment.py)（v1〜v3 のスクリプトから滑りの表・状態の BFS・状態の読み深さ・並列実行を import し、v1〜v3 の結果は変えない）。条件と再現コマンドは §13.10。

### 13.1 経緯

- **v3 の試遊**（パズルに強いユーザー）: 氷と岩だけの問題（v2）は 21〜28 手でも最短手数ちょうど・待ったなし・20〜50 秒で解けた。v3 の候補では、薄い氷（v3 の割れる氷）の 12 手の問題で 70 手・2分10秒・盤面を戻す3回、薄い氷の 17 手で 20 手・56 秒、もろい岩の 15 手で 17 手・67 秒、もろい岩の 20 手で 32 手・74 秒かかった。雪の床は読みに何も足さず不採用。相棒の駒も v4 では使わない。
- **ユーザーの指摘1**: 同じ駒を同じ向きへ続けて動かす手が生まれる配置は作らない。雪の床が縦に並び、何回も下へフリックさせられたのが「操作に邪魔なだけ」だった。もろい岩も、滑る向きに並べると、崩した後に同じ向きでまた次のもろい岩へ、となる。
- **ユーザーの指摘2**: ただ滑りを邪魔するだけの、どの選択にも関わらない要素は置かない。ただし想定解で使うものだけを置くとヒントになるので、解で使わないが使いたくなる「おとり」（使うと詰む・大回り・ゴールへの道が閉じる）は置くべき。

### 13.2 規則

盤面の文字は `.` 氷、`#` 岩、`b` もろい岩、`c` 薄い氷、`x` 盤面の外。状態は（駒の位置, 変化した要素の集合）で、最短手数は状態の BFS で求める（v3 と同じ）。

| 要素（文字） | 規則 |
| --- | --- |
| もろい岩（`b`） | 止め役。駒が滑ってきてもろい岩の手前で止まると、その滑りの後で崩れて氷になる（v3 と同じ） |
| 薄い氷（`c`） | 滑れる。滑りの出発マスと途中で通過したマスのうち薄い氷だったものは、その滑りの後で水面（止め役）になる。止まったマスは、次にそこから動いた滑りの後で水面になる。開始位置とゴールにしない |

- 動かない入力は手にならず、もろい岩も薄い氷も変化しない。
- 薄い氷の動きは v3 の割れる氷と同じで、割れた後を水面 `w` と呼ぶ（v3 は岩 `#` で持っていた）。水面は初期盤面には現れない。
- 1回の滑りで、薄い氷を割り、かつもろい岩を崩すこともある（両方の盤面）。
- 実装は両方の要素を1つの規則で扱う（v3 の `Rules` は要素1種類ずつなので、v4 で作り直した）。

### 13.3 条件

**条件1（同じ向きが続く手）。** 文字どおりの「到達できる全状態で、直前と同じ向きに動ける手が出ない」は、もろい岩があると満たせない（事実（実装の規則から））。もろい岩で止まった直後は、崩れた跡が氷になっているので、同じ向きへ必ず1マス以上動ける。薄い氷だけの盤面では、止め役が消えないので同じ向きに続けて動ける手は無い（ランダム盤面 100 問で0、事実（実測））。そこで次の2つを採用条件にした。

- 最短+2手以内のどの道筋（同じ状態を二度通る道筋も含む）にも、同じ向きが続く2手が無い。状態 s→t→u が同じ向きなら、BFS の距離で `dist(s) + 2 + ゴールまで(u) ≤ 最短 + 2` かどうかで判定する。最短解自身にも無い。
- 到達できるどの状態でも、もろい岩を崩した直後に、同じ向きでもう一度もろい岩を崩せる組（連鎖）が無い。

同じ向きへ続けられる2手（崩した直後の1マス以上の滑り）の数と、そのうち続けた後もゴールへ行けるものの数は、特徴量として出した（§13.7）。

**条件2（効かない要素を置かない・おとりを置く）。** 要素を1つずつ中立の形（もろい岩→岩、薄い氷→氷）に置き換え、次のどれも変わらない要素を「効かない要素」として外す。

- 最短手数、最短解の数、最短解の手。
- 最短解の上の各状態の選択肢と、解でない選択肢から続く1手の選択肢（解から1〜2手外れた範囲）の、向き・もっともらしいか（v2 の定義を今の状態の盤面で測る）・詰みか遠回り（最短より3手以上長い）か。

要素の役割は次のとおり（効く要素だけに付ける）。

| 役割 | 定義 |
| --- | --- |
| 使う要素 | 最短解で変化させる（崩す・割る） |
| おとり | 最短解で変化させない。最短解から外れたもっともらしい1手目、または続くもっともらしい2手目がその要素を変化させ、その手の後が詰みか遠回りになる |
| 弱いおとり | おとりの条件を、もっともらしくない手で満たす |

採用条件は、効かない要素が0で、おとりが要素の数の2割（切り上げ、最低1）以上。

**その他の採用条件**: 最短解が一意、最短手数が範囲内、要素の数が範囲内（両方の盤面はもろい岩・薄い氷を2つ以上ずつ）、最短解で要素を使う回数（崩す・崩れた跡を通る・水面で止まる）が3以上、一本道が最短手数の25%以下、静的な近道が無い（見た目どおりの盤面の解が元の規則でも通り最短+4手未満、またはもう一方の盤面（もろい岩→氷、薄い氷→岩）の解が通り最短+2手以内なら外す。v3 と同じ）。

### 13.4 目的関数

v1〜v3 と同じ山登り（3,000回、悪くならなければ受理）で、ゴールは範囲内の最短手数で止まれる氷のマスから長い順に4つを比べる。近傍は、岩の追加・削除・入れ替え、開始位置の移動、要素の追加・削除・移動に加え、400回ごとに「おとりの候補」をすべて試して最もよいものを受け入れる。おとりの候補は、最短解から外れた1手目・2手目の滑りを止める岩をもろい岩にする置き方と、その滑りが通る氷をもろい岩・薄い氷にする置き方。ランダムに置いた要素はほとんどおとりにならないため、おとりになりうる置き方を直接試す（生成したもろい岩の盤面4つで、氷・岩のマスを1つずつもろい岩にすると、おとりになるのは364通り中11通り（3%）、効かない要素になるのは149通り（41%）、事実（実測））。

**難しさの点**（大きいほど難しいとみなす）:

| 項目 | 点 |
| --- | --- |
| 見た目どおり（もろい岩→岩、薄い氷→氷）の盤面の読み | 解が元の規則で通らない 6、解なし 5、解は通るが4手以上の遠回り 3 |
| 使う回数 | ×0.8（最大10回） |
| 最短解で変化させる要素の数 | ×1（最大6） |
| 順序の依存 | 最短解で a を b より先に変化させる組のうち、b より先に a を変化させる手を除くと解けなくなる組 ×1、3手以上長くなる組 ×0.5（各最大8）。順序の依存の最も長い連なり（要素の数−1）×1.5（最大3） |
| 順序の罠 | 最短解の上で、解が後で使う要素を先に変化させ、詰みか遠回りになる選択肢 ×1（最大4） |
| おとり | ×3（最大3）、弱いおとり ×1（おとりと合わせて最大3） |
| 誘い | 最短解の上の、もっともらしいが詰みか遠回りになる選択肢 ×0.5（最大4） |
| 状態の読み深さ | v3 の状態の読み深さ ×1.5（山登りでは4で打ち切り、候補の比較では8で打ち切り） |

**減点**: 一本道×1.5、近い状態（最短+2手以内の道筋に乗り、どの最短解にも乗らない状態）×0.3（最大60）、最短解の数 2×log₂、駒が通らないマス×0.3、採用条件（条件1・2を含む）の不足1つにつき6。最短手数そのものには点を与えない。

**盤面と範囲**: 8×8（最短12〜15手）、10×10（14〜19手）、10×12（17〜22手）。要素の数はもろい岩・薄い氷が3〜7個、両方が4〜8個（各2個以上）。

**盤面の外（x）**: v3 と同じく、到達できる全状態で駒が一度も通らない氷・薄い氷を x にし、使われたマスに接していない岩・もろい岩も x にする。どの状態でも崩れないもろい岩は岩にする（採用した問題では条件2により起きない）。

### 13.5 検証（事実（実測））

- **手で作った小盤面**で、遷移が規則どおりになることを確かめた（もろい岩: 手前で止まって崩れる・崩れた跡を通れる・隣へ向けた入力では崩れない。薄い氷: 通過したマスが水面になる・止まっている間は割れない・動かない入力では割れない・離れると水面になる・水面は止め役。両方: 1手で薄い氷を割りもろい岩を崩す・割れた薄い氷で止まる。x は外壁と同じ止め役）。
- **独立の実装との突き合わせ**: 1マスずつ進めて盤面の文字を書き換える実装（崩れたもろい岩は `.`、割れた薄い氷は `w`）と、到達できる全状態の手を比べ、ランダム盤面（5〜7×5〜7、もろい岩・薄い氷を合わせて2〜7個）100 問で不一致0。
- **x への置き換え**: 同じ 100 問のうちゴールを置けた98問で、置き換えの前後で状態の数・最短手数・最短解の数・最短解の手が一致した。候補も生成のたびに同じことを確かめている。
- **候補の検証**: 各候補で、到達できる全状態の手が1マスずつの実装と一致すること、1マスずつの実装の BFS（盤面の文字と駒の位置を状態にする）の最短手数が状態の BFS と一致すること、最短解を1マスずつの実装で再生して最後の手で初めてゴールに止まること、初期盤面の文字が `.` `#` `b` `c` `x` だけで開始位置とゴールが氷であることを確かめた。条件1・2は特徴量から判定し直して JSON の `condition1`・`condition2` に出した（9問すべて真）。

### 13.6 3種類の比較（事実（実測））

各種類の各盤面を8回作り、生成した全問を測った（Python 1コアあたりの時間）。値は採用した問題の中央値。「難しさ」は §13.4 の難しさの点に、状態の読み深さ（8で打ち切り、読めなければ9）×1.5 を足したもの。

| 種類 | 採用 | 1回 | 最短 | 状態の数 | 要素 | 使う回数 | 変化させる要素 | おとり | 順序の依存の組 | 連なり | 順序の罠 | 誘い | 状態の読み深さ | 近い状態 | 難しさ | 見た目どおりの読み |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| もろい岩 | 4/24 | 57 s | 15.5 | 398 | 7 | 6 | 5 | 2 | 10 | 5 | 2.5 | 6 | 7 | 8.5 | 49.1 | 解なし3・通らない1 |
| 薄い氷 | 22/24 | 60 s | 17 | 261 | 7 | 4 | 5 | 2 | 9 | 4 | 3 | 5 | 7 | 7 | 47.3 | 解なし22 |
| 両方 | 21/24 | 120 s | 15 | 552 | 8 | 5 | 6 | 2 | 9 | 4 | 3 | 6 | 7 | 4 | 50.7 | 解なし12・通らない9 |

- **もろい岩は条件1で外れる。** 外れた20問のうち18問が「最短+2手以内の道筋に同じ向きが続く2手がある」だった（10×10 は 0/8）。もろい岩を崩すと、その向きへ続けて動ける手が必ずでき、山登りが崩す回数を増やすほど、それが最短に近い道筋に乗りやすい。候補3問（§13.7）でも、同じ向きへ続けられる2手は全状態で 30〜274 組あり、そのほとんどは続けると詰む（続けた後もゴールへ行けるのは0〜1組）。
- **薄い氷は、見た目どおりの盤面が必ず解なしになった**（22/22）。薄い氷を氷とみなした盤面では止め役が足りず、最短解は水面で止まる手（候補で1問6回）を前提にしている。薄い氷は「通り道」より「後から止め役を作る」要素として使われた。見た目どおりに読める短い解が誤りになる盤面は、もろい岩があるときだけできた（もろい岩 1/4、両方 9/21）。
- **順序の依存はどの種類でも強い。** 最短解で変化させる要素の組のほとんどで、使う順を入れ替えると解けなくなった（もろい岩は 5 要素の 10 組すべて、連なり5＝全順序が決まる）。
- **おとりは全種類で2個に揃った。** 要素の数の上限（7・8）に張りつき、使う要素5〜6＋おとり2 になった。上限を広げたときの変化は §13.6.1。
- **両方の盤面**は状態の数が最も多く（中央値 552、候補では最大 3,173）、難しさの点も最も高い。生成時間はほかの約2倍。
- 状態の読み深さ（規則を知って先を読む人のモデル）は 7 前後で、v3（5.5〜7）と同程度。v4 で増えたのは、順序の依存・おとり・見た目どおりの読みの誤りである。

#### 13.6.1 要素の数の上限を広げると（事実（実測））

10×10（最短14〜19手）で、要素の数の上限を11にして各種類8回作った（`probe --max-elements 11`）。値は採用した問題の中央値（もろい岩は採用が無いので全8問）。

| 種類 | 上限 | 採用 | 1回 | 要素 | 変化させる要素 | おとり | 順序の依存の組 | 状態の数 | 難しさ | 見た目どおりの読み |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |

| 両方 | 11 | 6/8 | 511 s | 11 | 8 | 3 | 15.5 | 2,122 | 58.1 | 解なし4・通らない2 |

- **上限を広げても要素の数は上限に張りつき、難しさの点は5〜8点上がった**（§13.6 の上限7・8 では 47〜51）。上がった分は主に、変化させる要素と順序の依存の組の増加。おとりは難しさの点の上限（3個）に達した。要素を増やすほど点が上がり続けるので、この目的関数では「難しさの上限」は要素の数の上限で決まり、盤面や規則からの上限には届いていない。
- **もろい岩は全8問が条件1で外れた。** 崩す回数が増えるほど、最短に近い道筋に同じ向きが続く2手が乗る。もろい岩を増やして難しくする方向は、条件1と両立しにくい（推測）。
- 薄い氷でも、要素を増やすと見た目どおりの読みが誤りになる盤面が出た（1/8）。
- 1回の生成時間は上限7・8 の約4〜9倍になった（要素1つずつを置き換えた盤面の BFS が要素の数だけ要るため）。
- 要素10〜11個の盤面を人が読めるか、点の差が体感の差になるかは確かめていない。試遊候補（§13.7）は上限7・8 の問題から選んだ。

### 13.7 人が試遊する候補（9問）

各種類で、採用した問題を難しさの上位から、盤面の大きさと見た目どおりの読みの結果がなるべく重ならないように3問ずつ選んだ（もろい岩は 10×10 の採用が無いので 8×8 が2問）。`/tmp/v4-candidates.json` に、種類を混ぜた順に id を付けて書いた。JSON の `rows` は初期盤面（`.` `#` `b` `c` `x`）、`start`・`goal` は [x, y]、`solution` が最短解、`features` が特徴量（`elements` は要素の位置・種類・役割、`looks` は見た目どおりの読みの結果、`static_looks_depth` はその盤面の静的な読み深さ、`dynamic_depth` は状態の読み深さで9は読めない、`near_repeats`・`brittle_chains` は条件1、`repeat_moves_all`・`repeat_moves_live` は同じ向きへ続けられる2手の数とそのうち続けても解ける数）。

### 13.8 人の試遊で確かめること

1. **v3 より時間がかかるか、待ったが増えるか。** v3 の試遊（もろい岩 15 手で 67 秒、薄い氷 12 手で 2分10秒）と比べ、同じ程度の最短手数で、所要時間・入力した手数・盤面を戻した回数を見る。
2. **おとりが効くか。** 各問2個のおとり（JSON の `role` が `decoy`）に手を出したか。おとりがあることで「全部の要素を使う」というヒントが消えたと感じるか、置いてあるだけの要素に見えるか。
3. **順序の依存が読みどころになるか。** もろい岩の問題（w09・w01・w06）は、崩す順がすべて決まっている（連なり5）。順序を読む面白さになるか、試行錯誤の作業になるか。
4. **見た目どおりの読みの誤り。** w01・w05 で、ゴールの止め石を先に崩してしまう短い道筋を試すか。それが「騙された」面白さか、理不尽か。見た目どおりでは解なしの問題（ほかの7問）との違い。
5. **同じ向きへの続けた入力。** もろい岩を崩した直後に同じ向きへ続けられる手は全状態では残る（w01・w05 で約280組）。最短に近い道筋には無いが、試行錯誤の途中で同じ向きを続けて入力させられる場面が気になるか。
6. **薄い氷の「割って逆向きに戻る」手。** 薄い氷の最短解は、割った直後に逆向きへ滑ってその水面で止まる手を多用する。読みどころになるか、同じパターンの繰り返しに感じるか。
7. **どの種類を初期版に入れるか。** もろい岩だけ・薄い氷だけ・両方のどれが、難しさと分かりやすさの両方でよいか。

### 13.9 この節で判断しないこと・限界

- 「同じ向きが続く手」の条件は、最短+2手以内の道筋と、崩した直後の連鎖だけで判定している。全状態で同じ向きに続けられる手は、もろい岩がある限り残る。
- おとり・効かない要素の判定は、最短解の上の状態と、そこから1〜2手外れた範囲だけを見ている。もっともらしい手は v2 の定義（ゴールへ近づく・ゴールと見通しで揃う・ゴールを通過する）を今の盤面に当てたもので、人が要素の変化をどう見込んで手を選ぶかは測っていない。
- 順序の依存は、2つの要素の組ごとに「その組の順を入れ替えると解けるか」を見ている。3つ以上の要素の順序の組み合わせは見ていない。
- 難しさの点は §13.4 の重みの1通りだけで、候補は各種類で点の上位の問題であり、平均的な問題ではない。要素の数の上限（7・8）に張りついており、上限を11にすると要素を増やすほど点が上がった（§13.6.1）。難しさの点は要素の数で頭打ちにならないので、「上限」は要素の数の上限と条件1で決まっている。
- 最短手数は範囲の下側（12〜19手）に寄った。範囲の上側の問題は、条件を満たしながら点を上げにくいと考えられる（推測）。
- 計測はすべて Python。

### 13.10 再現方法

標準ライブラリだけを使う。既定の seed は `20261101`、`--workers` は並列数（既定4）、`--iterations` は山登りの回数（既定3,000）。

```sh
python3 scripts/research/ice_floor_hardest_generation_experiment.py verify --samples 100  # §13.5
python3 scripts/research/ice_floor_hardest_generation_experiment.py candidates --runs 8  # §13.6・§13.7、/tmp/v4-candidates.json
python3 scripts/research/ice_floor_hardest_generation_experiment.py probe --variants brittle --shape 1 --runs 8 --max-elements 11  # §13.6.1（thin・mixed も同じ。1種類で約20〜35分）
```

- `candidates` は4並列で約25分。盤面と範囲は `SHAPES`、要素の数は `ELEMENT_RANGE`、目的関数の重みは `Weights`、おとりの候補を試す間隔は `POLISH_EVERY` にある。
- 出力の各問に、盤面（S が開始位置、G がゴール）、最短解、要素の役割、最短解の出来事、順序の依存、見た目どおりの読みの結果、条件1・2の判定を表示する。
