# 氷の床迷路ピクトグラム検討

氷の床迷路のゲーム選択ピクトグラムをどう検討したかの記録。どの着眼点を探索し、どの候補を比べ、なぜ P1（岩で止まって曲がり、壁際のゴールで止まる L 字の滑り）を推奨するかをまとめる。見直すときに、同じ比較をやり直さずに論点から始められるようにする。

この文書は導入調査の資料であり、現在仕様の正本ではない。採用したピクトグラムの形は `frontend/src/games/ice-floor-maze/assets/pictogram.svg` を正とする。制作手順と評価方法は `.claude/skills/design-game-pictogram/`（`SKILL.md`、`references/method.md`）を正とする。

記述は次のように区別する。

- **事実（リポジトリ）**: 現在のコード・文書から確かめたこと。
- **事実（実測）**: 候補 SVG を実表示サイズで描画して比べたときに見えたこと。見え方の記述は、比較画像を AI が見て書いたもの。候補 SVG は代表案だけをリポジトリに残している（§6）。
- **判断**: 上から導いた推奨と理由。

人間による方向の選択はまだ行っていない。Skill は方向を人間に選ばせる手順だが、本実装では人間のレビューを全段の実装後にまとめて行うので（[氷の床迷路実装前提調査](氷の床迷路実装前提調査.md)）、AI が推奨案で仮に決めた。最終レビューで選び替えられるように、代替の候補も同じ表示条件で比べられる形で残している（§5.2、§6）。

採用した SVG は、ゲーム選択の一覧・ヒーローと、結果画面の見出しで使っている。

## 1. 結論

- 推奨案は **P1（岩で止まって曲がり、壁際のゴールで止まる L 字の滑り）**。濃色の太い枠（外壁）の中に、左の壁際から右へ伸びて下へ曲がる淡色の太い帯（滑った跡）がある。帯は右上の濃色の角丸の四角（岩）の手前で曲がり、下の壁際で、輪（ゴール）の中の濃色の円（駒）に届く。
  - 跡・駒・ゴール・岩・外壁は、プレイ画面の盤面と同じ意味で描いた。跡は駒の通ったマスの中心を結ぶ角の丸い帯、駒は塗りの円、ゴールは輪、岩はマスを占める角丸の四角、外壁は盤を囲む枠。
  - 岩と外壁はどちらも濃色にした。プレイ画面でも岩と外壁は同じ石の色で、どちらも「ぶつかって止まる面」と読ませている（`ice-floor-maze-tone.ts`）。
- 推奨の理由は次の3つ（§4.2）。
  - 「途中のマスで止まらず、岩か壁に当たるまで滑る」「岩に当たって向きを変える」「ゴールで止まる」を、1枚で順に読める。
  - 一直線の滑りだけの案は、46〜56px で UI のスライダー（つまみ付きの横棒）に見えた。L 字にすると盤の上を動いた道筋に見え、汎用 UI から離れる。
  - 一覧の 46〜56px でも、帯・岩・輪の中の駒が見分けられ、既存7ゲームのどれとも構成が重ならない。
- 見直すときの主な論点は次の4つ（§5.1）。有力な代替は P1G・P2・P3（§5.2）。
  - 1手で描くか、2手で描くか。
  - ゴールを描くか。
  - マスの目地（格子）を描くか。
  - リフレクションの「折れ線で終点に円」とどこまで離すか。

## 2. 目的と制約

### 2.1 目的

ゲーム一覧で氷の床迷路を素早く見分けられ、ゲーム自身の姿を保ち、既存のピクトグラムと並べても強さが突出しないこと（`DESIGN.md`「ゲームピクトグラム」、`references/method.md` §1）。このゲームでは、小さく表示しても「止まらずに滑る」「ぶつかって止まる」が伝わることを特に重く見た。

### 2.2 制約（事実（リポジトリ））

- 共通描画契約（`SKILL.md`）
  - `viewBox="0 0 120 120"`。
  - 線幅は 4 と 2 だけ。跡の帯は線ではなく塗りの形（角の丸い L 字の面）として描き、この契約に収めた。
  - 色は `var(--game-pictogram-strong)` と `var(--game-pictogram-soft)` の2色だけ。
  - `check_svg.py --max-colors 2 --forbid-gradients --forbid-filters --forbid-external-images --forbid-text` を通す。
- 色は `GamePictogram` が与える。ライトとダークでは前景色と補助情報色、結果画面では `currentColor` になる。どのテーマでも読める形にする。
- 実表示サイズは [リフレクションピクトグラム検討](../リフレクション/リフレクションピクトグラム検討.md) §2.2 の実測値を使った。ゲーム選択のヒーロー 177px / 138px、一覧のカード 56px / 46px、結果画面 48px。一覧の 46〜56px が最も厳しい。
- 比べる既存ピクトグラム: ウォーターソート、ナンプレ、マインスイーパー、パーキングジャム、スライドパズル、バイナリパズル、リフレクション。ウォーターソート以外の6つは濃色の太い外枠（パーキングジャムは出口の切れ目つき）を持つ。バイナリパズルは濃色の塗りの角丸の四角と円を、リフレクションは淡色の折れ線と終点の濃色の円を持ち、どちらも氷の床迷路の要素（岩・駒・跡）と形が近い。
- プレイ画面の見た目（`frontend/src/games/ice-floor-maze/ui/board/`、`ui/ice-floor-maze-tone.ts`）
  - 外壁は盤を囲む石の色の枠、氷は明るい地に細い目地。
  - 岩はマスを占める角丸の四角（下側に影の面を重ねた塊）。外壁と同じ石の色。
  - 駒は白い縁取りの濃い円、ゴールは輪と中心の点。駒がゴールに止まると、輪は駒の外側に見える。
  - 跡は、滑り始めたマスの中心から止まったマスの中心までの、駒と同じ色相の半透明で角の丸い帯。ゴールの輪の下を通る。
- 既存作の見た目を避ける（[氷の床迷路名称・権利調査](氷の床迷路名称・権利調査.md) §3.3、§9）。ロボット駒、色付き目標チップ、マスの間に引く壁、ペンギンなどのマスコット、特定ゲームの氷タイルの模様を描かない。障害物は「マスを占める岩」として描く。
- 表示名は作業名「氷の床迷路」（`frontend/src/games/ice-floor-maze/display-name.ts`）。SVG の `aria-label` もこれに合わせる。`GamePictogram` は SVG を `aria-hidden` で描画するので、読み上げには使われない。正式名が決まったら SVG の `aria-label` も直す。

## 3. 比べた方向と分かったこと

| 方向 | 候補 | 比べたこと |
| --- | --- | --- |
| 1手の滑りを描く | A 一直線で岩に当たる、C 一直線でゴールに止まり奥に岩、E 1列だけの盤、P3 岩を散らした盤で一直線 | 汎用 UI（スライダー）に見えないか、盤に見えるか |
| 2手の滑りを描く | B / P1 岩で曲がって壁際のゴール、P1G 目地つき | 道筋として読めるか、リフレクションとの近さ |
| 1手＋次の目標を描く | H / P2 岩で止まり、真下にゴールが待つ | 曲がらずに「次の一手」を示せるか |
| 滑りの表し方 | F 速度線、D 残像の点、A3 / P1D 衝突の線 | 跡の帯の代わり・追加になるか |

### 3.1 着眼点

次の着眼点から候補を作った。

- 滑り: 一直線に岩まで滑る、壁まで滑る、L 字に2手、階段状に3手以上、ゴールを通り過ぎる（通過は無効）、岩の手前で止まった駒の拡大。
- 動きの記号: プレイ画面と同じ跡の帯、漫画の速度線、残像の点、ぶつかった衝撃の線、出発点の淡い印。
- 盤: 外壁の枠だけ、目地（格子）つき、1列だけの通路、岩を散らした盤、盤の一部の切り出し。
- ゴール: 輪の中に駒が止まる、輪が先で待つ、岩がゴールの奥にあって止め役になる。
- 氷の象徴: 雪の結晶、氷の光沢の斜線、つるつるの床の反射、スケート、カーリングのストーン、ホッケーのパック。

候補にしなかったもの（判断）:

- 雪の結晶・氷の光沢・床の反射: 氷の汎用記号で、盤のパズルに結びつかない。光沢の斜線は特定ゲームの氷タイルの模様にも近づく（名称・権利調査 §3.3）。
- スケート・カーリング・ホッケー: 別の遊び（スポーツ）として誤認される。
- 出発点の印: プレイ画面に出発点の表示がなく、意味が説明に頼る。
- 階段状に3手以上: 折れ線が増え、46px で迷路の道筋（または稲妻）の模様になる。リフレクションの折れ線にも近づく。
- ゴールを通り過ぎる: 「通過は無効」を1枚で示すには帯・輪・駒の重なりが要り、小サイズで読めない。

### 3.2 一直線の滑り（事実（実測））

- A（左の壁際から右へ伸びる帯、帯の端の駒、その右の岩）は、177px では「滑って岩の手前で止まった」と読めた。
- 一方、46〜56px では帯とその端の円が、UI のスライダーや進捗バーのつまみに見えた。盤の中央に横長の要素が1本あるだけで、枠の中が空いて見えた。
- C（帯の端の駒が輪の中、その奥に岩）は、輪が加わって録音ボタンやラジオボタンの付いたスライダーに見え、A の弱点が強まった。輪の奥の岩は右の壁に近く、46px で壁と一体になった。
- E（1列だけの横長の盤）は、外形がほかのピクトグラムと違い見分けやすいが、トグルスイッチやスライダーの部品そのものに見えた。迷路の盤にも見えない。
- P3（A に岩を2つ足して盤に散らす）は、岩が繰り返されて「障害物のある盤」とは読めるようになり、スライダーの見え方は弱まった。ただ、岩の置き方によっては駒を中心に上下左右へ岩が並び、十字キーに見えた（最初の配置）。散らした配置でも、46px では濃い四角の粒が4つ（岩3つと駒）並ぶ模様になり、バイナリパズルの塗りの四角に近づいた。

### 3.3 2手の滑り（事実（実測））

- B / P1（右へ滑って岩の手前で下へ曲がり、下の壁際のゴールで止まる）は、46px でも L 字の帯・右上の岩・輪の中の駒が見分けられた。帯が岩の手前で曲がるので、「岩に当たって向きを変えた」と読めた。
- 帯が盤の上を動いた道筋に見えるので、A のようなスライダーの見え方は出なかった。
- リフレクション（淡色の折れ線が終点の濃色の円に届く）とは、「枠の中の淡い折れ線が濃い円で終わる」構成が共通する。並べると、帯の太さ（11 と 5）、斜めの鏡と角丸の四角の岩、枠の外へ出る入口の点の有無、輪の有無で見分けられた。それでも、構成の近さは見直すときの論点として残る（§5.1）。
- P1G（P1 に淡色の 4×4 の目地を足す）は、マスを数えて「途中のマスで止まらずに通り抜けた」と読める。一方、46px では帯が目地と交わって網目の中の線になり、ナンプレ・バイナリパズルの格子の言葉に近づいた。4×4 の目地に合わせると、帯の曲がり角の先の岩は外壁に接するマスにしか置けず、46px で岩と外壁が一体に見えた。

### 3.4 1手と次の目標（事実（実測））

- H / P2（右へ滑って岩の手前で止まった駒と、その真下の壁際にあるゴール）は、曲がる線がないのでリフレクションからは離れる。駒の次の一手（下）でゴールに止まれることも読める。
- 一方、上半分は A と同じ横棒とつまみで、46px ではスライダーと的（ターゲット）の組み合わせに見えた。ゴールの中心の点は 46px で直径 2px 弱になり、輪の中の点としては読みにくかった。

### 3.5 滑りの表し方（事実（実測））

- F（駒の後ろに淡色・線幅2 の速度線3本）は、動きの記号としては最も分かりやすいが、漫画の汎用表現で、プレイ画面の跡の帯と対応しない。46px で速度線が細い灰色の筋になった。
- D（駒の後ろに大きさを変えた淡色の点）は、読み込み中の表示や「…」に見えた。
- A3 / P1D（駒と岩の間に濃色・線幅2 の短い衝撃の線）は、138px 以上では「ぶつかった」が強まるが、46px では岩の角の汚れに見えた。帯が岩の手前で止まる・曲がるだけで、ぶつかったことは十分読めた。
- プレイ画面の跡の帯をそのまま使うのが、ゲームとの対応と小サイズの読みやすさの両方で最も良かった（判断）。

### 3.6 仕上げ（事実（実測））

P1 の細部は次を比べた。

- 寸法の段階: 最初は盤を 5×5 のマス（1マス 16）に合わせて描いたが、46px で岩が 6px ほどになり、駒・岩・帯が盤の中央の小さな塊になった。マスの格子に厳密に合わせるのをやめ、帯の幅 11、駒の半径 8、岩 18 角まで大きくした。
- 帯の幅（11 / 12）: 12 は 177px で太く重く見え、11 と 46px での読みやすさは変わらなかった。11 を採った。
- ゴールの縦位置（中心 y=82 / 84 / 85）: 82 は壁から離れ、「下の壁に当たって止まった」が弱かった。85 は輪と外壁の隙間が 46px でほぼ消えた。84 を採った（輪の外側と外壁の内側の隙間 3）。
- 岩の影: プレイ画面の岩の影の面を、淡色の細い帯として岩の下に覗かせる案を試した。177px では塊らしさが出るが、46px では岩の縁がにじんだように見えた。影は描かない。
- 光学中心の補正: なし。描いた要素の外接矩形の中心は (59.75, 62) で、右上の岩と左の帯の端、下の輪が釣り合い、177px と 46px で偏りは目立たなかった。

## 4. 推奨案 P1

### 4.1 仕様（事実（リポジトリ））

- 外壁: `x=18 y=18 width=84 height=84`、`rx=2`、濃色、線幅4。既存ゲームの外枠と同じ。
- 跡: 淡色の塗り。中心線 `M30 36H64V84` を幅 11 で太らせた L 字の面で、始まりと終わりの端と曲がり角の外側は半径 5.5 で丸める。線ではなく塗りの形なので、線幅の契約（4 と 2）に収まる。プレイ画面の跡と同じく、駒の中心で終わり、ゴールの輪の下を通る。
- 岩: `x=77 y=27 width=18 height=18`、`rx=3.5`、濃色の塗り。跡の曲がり角の右、横の跡と同じ高さに置く。
- ゴール: 中心 (64, 84)、半径 12、濃色、線幅2 の輪。
- 駒: 中心 (64, 84)、半径 8、濃色の塗り。輪との隙間は 3。
- 光学中心の補正: なし（§3.6）。
- 色は strong / soft の2色だけ。`check_svg.py` の2色・gradient / filter / 外部画像 / text 禁止の検査を通る。

### 4.2 推奨理由（判断）

- **意味的距離**
  - このゲームの遊びは「方向を選ぶと岩か外壁に当たるまで止まらずに滑り、ゴールで止まればクリア」。P1 は、左の壁際から右へ滑る、岩の手前で止まって下へ曲がる、下の壁際のゴールで止まる、の3つを1枚で順に示す。
  - 跡・駒・ゴール・岩・外壁は、プレイ画面と同じ形と意味（角の丸い帯、塗りの円、輪、マスを占める角丸の四角、盤を囲む枠）で描いた。遊び始めたときに見る盤と結びつく。
  - 岩と外壁を同じ濃色にしたので、どちらも「止める面」として読める。プレイ画面で同じ石の色にしている意図と揃う。
- **実表示サイズ**: 要素は枠・帯・岩・輪・駒の5つだけ。46px でも L 字の帯、右上の岩、輪の中の駒が見分けられた（事実（実測））。
- **弁別性**
  - 一直線の案（A・C・E）で出たスライダーの見え方が、L 字では出なかった（事実（実測））。
  - 太い淡色の L 字の帯は、既存7ゲームのどれにもない。リフレクションの細い折れ線と斜めの鏡、バイナリパズルの格子の中に並ぶ四角と円とは、並べて見分けられた（事実（実測））。
- **光学的重量**: 濃色は外枠・岩・駒と細い輪だけで、淡色の帯が面を受け持つ。一覧ではマインスイーパー・バイナリパズルより軽く、リフレクション・ナンプレと同じくらいに見え、突出しなかった（事実（実測））。
- **既存作との距離**: 駒は単純な円、障害物はマスを占める岩、壁は盤を囲む外壁だけで、ロボット駒・マスの間の壁・マスコット・氷タイルの模様を描いていない（名称・権利調査 §9）。

### 4.3 弱点（判断）

- 「氷」の手がかり（つるつるした床）は描いていない。滑る動きは帯の形から読むので、帯を「滑った跡」と読まない人には、盤の上の道筋（経路パズル）に見えうる。
- 枠の中の淡い折れ線が濃い円で終わる構成は、リフレクションと共通する。一覧で隣に並ぶと、両者の見分けは帯の太さと岩・鏡の形に頼る。
- 目地を描かないので、途中で何マス通り抜けたかは読めない。「途中で止まらない」は、帯が長く一続きであることで示している。
- 描いた止まり方は「岩で止まる」と「壁際のゴールで止まる」の2つ。ゴールを通り過ぎると無効、という条件は描いていない。
- 帯の幅 11 は、プレイ画面の跡（マスの 0.42）より駒に対して太い。小サイズで帯を残すための誇張。

## 5. 再検討するときの論点

### 5.1 論点

- **1手か2手か**: 1手（A・P3・P2）は滑りと衝突だけを最も単純に描けるが、46〜56px でスライダーに見えやすい。2手（P1）は道筋として読めるが、リフレクションの折れ線に近づく。
- **ゴールを描くか**: ゴール（P1・P2）があると「目標の場所で止める」パズルだと分かる。描かない P3 は、岩を増やして盤らしさを出すが、何を目指すかは伝わらない。
- **目地を描くか**: 目地あり（P1G）はマスの盤と「通り抜けたマスの数」が読めるが、46px で帯が網目に紛れ、格子を持つ既存ゲームに近づく。
- **リフレクションとの距離**: 一覧で並べて見分けにくいと感じるなら、曲がらない P2 に替えるか、P1 の曲がり角を岩の真横に寄せて「当たって曲がる」をさらに強める、帯を太くする、といった方向で離す。

### 5.2 候補の一覧と代替案

| 案 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| **P1 L 字で岩→壁際のゴール**（推奨） | 外壁、左の壁際から右へ滑って岩の手前で下へ曲がる帯、下の壁際の輪の中の駒 | 滑る・岩で止まる・ゴールで止まるを順に読める。スライダーに見えない | リフレクションと構成が近い。氷の手がかりがない |
| P1G 目地つき | P1 に淡色の 4×4 の目地を足す | マスの盤に見え、通り抜けたマスが数えられる | 46px で帯が網目に紛れる。岩が外壁と一体に見える |
| P2 岩で止まり、ゴールが待つ | 右へ滑って岩の手前で止まった駒と、真下の壁際のゴール | 曲がる線がなく、リフレクションから離れる。次の一手が読める | 上半分がスライダーに見える。ゴールの点が小さい |
| P3 岩を散らした盤で一直線 | 一直線の帯と駒、止める岩と、ほかに岩2つ | 障害物の盤に見え、スライダーの見え方が弱まる | ゴールがない。濃い粒が並ぶ模様になり、バイナリパズルに近い |
| A 一直線で岩に当たる | 左の壁際から右へ伸びる帯と駒、その右の岩 | 最小の構成で「滑って当たる」 | 46〜56px でスライダーに見える。枠の中が空く |
| C 一直線でゴールに止まり奥に岩 | A の駒を輪の中に置き、奥に岩 | 岩がゴールの止め役になる | スライダーとボタンに見える。岩が右の壁と一体になる |
| E 1列だけの盤 | 横長の外壁の中に帯・駒・岩 | 外形がほかと違う | トグルスイッチやスライダーの部品に見え、盤に見えない |
| F 速度線 | 帯の代わりに淡色・線幅2 の速度線 | 動きの記号として分かりやすい | 漫画の汎用表現で、プレイ画面の跡と対応しない |

推奨順は P1 > P2 > P1G > P3（判断）。部分採用もできる（例: P1 のゴールを P2 のように「待つ」形にして駒を曲がり角に置く、P1 に P3 の岩を1つ足す）。

```sh
sed -e 's/var(--game-pictogram-strong)/#0a0a0a/g' -e 's/var(--game-pictogram-soft)/#737373/g' \
  docs/パズル/導入調査/氷の床迷路/ピクトグラム検討/p2-rock-goal-wait.svg > /tmp/p2.svg
```

### 6.1 選び替える手順

1. 採る候補の SVG を `frontend/src/games/ice-floor-maze/assets/pictogram.svg` へ複製する。`aria-label` は表示名（`ICE_FLOOR_MAZE_DISPLAY_NAME`）に合わせる。
2. 最終検査を通す。

   ```sh
   python3 .claude/skills/design-game-pictogram/scripts/check_svg.py frontend/src/games/ice-floor-maze/assets/pictogram.svg \
     --max-colors 2 --forbid-gradients --forbid-filters --forbid-external-images --forbid-text
   ```

3. 既存ピクトグラムと同じサイズ・同じテーマで並べて見比べる（`references/method.md` §4「弁別性」「実表示サイズでの成立」）。サイズは §2.2 の 177 / 138 / 56 / 46 / 48px を使い、ライトとダークの両方で見る。

   ```sh
   python3 .claude/skills/design-game-pictogram/scripts/make_review_sheet.py \
     --output /tmp/ice-floor-maze-pictogram-review.html --size 112 \
     docs/パズル/導入調査/氷の床迷路/ピクトグラム検討/*.svg \
     frontend/src/games/*/assets/pictogram.svg
   ```

4. この文書の §1 と §4 を、採った案に合わせて直す。
