# 魔方陣ピクトグラム検討

魔方陣（ゲーム ID `magic-square`）のゲーム選択ピクトグラム（白黒版）をどう検討したかの記録。どの方向を比べ、なぜ D（数で埋めた 3×3 と、どの行の端にもそろった合計）を推奨するかをまとめる。見直すときに、同じ比較をやり直さずに論点から始められるようにする。

この文書は導入調査の資料であり、現在仕様の正本ではない。採用したピクトグラムの形は `frontend/src/games/magic-square/assets/pictogram.svg` を正とする。制作手順と評価方法は `.claude/skills/design-game-pictogram/`（`SKILL.md`、`references/method.md`）を正とする。

記述は次のように区別する。

- **事実（リポジトリ）**: 今のコード・文書から確かめたこと。
- **事実（実測）**: 候補 SVG を実表示サイズで描画して比べたときに見えたこと。見え方の記述は、比較画像を AI が見て書いたもの。
- **判断**: 上から導いた推奨と理由。

人間による方向の選択はまだ行っていない。人間のレビューを最終レビューで1回だけ行うので、AI が推奨案で仮に決めた。最終レビューで選び替えられるように、代替の候補も同じ品質まで仕上げている（§5、§6）。

---

## 1. 結論

- 推奨案は **D（数で埋めた 3×3 と、どの行の端にもそろった合計）**。洛書（4 9 2 / 3 5 7 / 8 1 6）で埋めた 3×3 の右に、行ごとの合計「15」を3つ縦に並べる。
- マスが数で埋まっていることと、同じ「15」が行ごとに繰り返されて「どの行も同じ合計」に見えることの2つを、文字を読まずに形の繰り返しで伝える。
- 見直すときの主な論点は §5.1。

---

## 2. 目的と制約

### 2.1 目的

ゲーム一覧で魔方陣を素早く見分けられ、ゲーム自身の姿を保ち、既存のピクトグラムと並べても強さが突出しないこと（`DESIGN.md`「ゲームピクトグラム」、`references/method.md` §1）。

### 2.2 制約（事実（リポジトリ））

- 共通描画契約（`SKILL.md`）: `viewBox="0 0 120 120"`、線幅は 4 と 2 だけ、色は `var(--game-pictogram-strong)` と `var(--game-pictogram-soft)` の2色だけ。`check_svg.py --max-colors 2 --forbid-gradients --forbid-filters --forbid-external-images --forbid-text` を通す。
- 実表示サイズ: ゲーム選択のヒーロー 177px（1280px 幅）/ 138px（390px 幅）、一覧のカード 56px / 46px、結果画面 48px（[ハミルトン路ピクトグラム検討](../ハミルトン路/ハミルトン路ピクトグラム検討.md) §2.2）。一覧の 46〜56px が最も厳しい。
- 比べる既存ピクトグラム: ブリッジパズル、一筆パズル、アイスフロア迷路、マインスイーパー、ナンプレ、パーキングジャム、リフレクション、スライドパズル、バイナリパズル、詰将棋、ウォーターソート。数を描くのはナンプレ（空きの多い 3×3 に数が2つ）、スライドパズル（1〜8 が順に並んだ札）、マインスイーパー（地雷と旗と数）。
- プレイ画面の見た目（`ui/board/board-layout.ts`）: マスの右に行の、下に縦の列の今の合計を帯で出し、斜めの合計は帯の角に置く。そろえる合計は左の帯の上の角に出す。
- 実際の盤は 4×4〜6×6 で、合計は 34・65・111。
- 数は `<text>` ではなくパスにする。

## 3. 比べた方向と分かったこと

### 3.1 着眼点

- 盤: 数で埋めた盤（解けた姿）、空きのある盤（解いている途中の姿）。
- 合計: 出さない、行ごとに出す、行・縦の列・斜めに1つずつ出す、途中の盤の真ん中の行と列にだけ出す。
- 盤の大きさ: 実際の 4×4 以上、3×3 への縮約。

### 3.2 形の比較（事実（実測））

| 比べたこと | 案 | 見え方 |
| --- | --- | --- |
| 盤の大きさ | 4×4 / 3×3 | 4×4 では 48px で数が読めなかった。3×3 は数の字形が判別できた。魔方陣の代表の形として広く知られている洛書の 3×3 と合計 15 を使った（ナンプレも 9×9 を 3×3 に縮約している前例） |
| 合計の置き方 | 行ごとに3つ縦に並べる（D）/ 行・縦・斜めに1つずつ（B） | D は同じ「15」が縦にそろい、48px でも数の 3×3 とそろった合計の帯として読めた。B は3つの合計が別々の向きに散り、同じ数がそろっていることが D より一目で読みにくかった。B の斜めの刻みは 48px でほぼ消えた |
| 盤を埋めるか | 埋めた盤（A・B・D）/ 十字に 9 / 3 5 7 / 1 だけ（C） | C は数を入れていく途中を示せたが、数が5つで、ナンプレの疎な数の格子に近づいた |
| 合計を出すか | 出す（B・C・D）/ 出さない（A） | A は数で埋まった分の濃色が多く、合計が無いので数の格子にしか見えなかった |
| 数の字形 | Inter SemiBold（合計の B・C は Bold）、等幅の数字（tnum） | 桁の位置がそろい、3×3 の数が列にそろって見えた |

### 3.3 光学中心（事実（実測））

D は合計の帯の分だけ右が重い。合計の帯を含めた全体の外接（横 10〜110・縦 18〜100）が中央に来るよう、格子を左へ寄せた（格子 x 12〜90）。112px と 48px で偏りが目立たなかった。

## 4. 推奨案 D

### 4.1 仕様（事実（実測））

- 盤: 濃色の外枠（`x=12 y=20 width=78 height=78 rx=2`、線幅4）と、淡色の区切り線（線幅2）の 3×3。
- 数: 洛書 4 9 2 / 3 5 7 / 8 1 6（濃色の塗り）。
- 合計: 各行の右に「15」（濃色の塗り）。
- `check_svg.py` の2色・gradient / filter / 外部画像 / text 禁止の検査を通る。

### 4.2 推奨理由（判断）

- **意味的距離**: このゲームの題材は「どの列の合計も同じになるよう数を入れる」こと。D は埋まった数と、そろった合計の繰り返しでそれを示す。試遊で出た「斜線と点からは数のパズルに見えなかった」に対して、数で埋まっていることが一目で分かる。
- **プレイ画面との結び付き**: 行の右に合計の帯を出すのは、プレイ画面の合計の置き方と同じ。遊んだ人には盤面と結び付く。
- **弁別性**: 数を描く既存のピクトグラム（ナンプレ・スライドパズル・マインスイーパー、§2.2）とは、順でない9つの数で埋まった盤と、盤の外の合計の帯で分かれる。
- **実表示サイズ**: 48px でも、数の 3×3 とそろった3つの合計の帯として読めた。

### 4.3 弱点（判断）

- 縦の列と斜めもそろえることは描いていない。行の合計だけを見せる。
- 実際の盤（4×4〜6×6、合計 34・65・111）とは大きさも合計も違う。
- 1倍の画素の 46px では、ほかの数のピクトグラムと同じく数は形の塊になる。

## 5. 再検討するときの論点

### 5.1 論点

- **縦の列と斜めまで描くか**: B は行・縦・斜めに合計を1つずつ置き、ゲームの規則に最も近い。代わりに「同じ数がそろう」ことが一目で読みにくく、斜めの刻みは小さいサイズで消える。
- **解けた姿か途中の姿か**: C は空きのある盤で「数を入れていく」遊びを示せる。代わりにナンプレに近づく。
- **合計を描くか**: A は魔方陣を知っている人には最も象徴的だが、知らない人には数の格子にしか見えない。

### 5.2 候補の一覧と代替案

| 案 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| **D 行ごとの合計**（推奨） | 洛書で埋めた 3×3 の右に、行ごとの「15」を3つ | どの行も同じ合計に見える。プレイ画面の帯と同じ置き方。48px で読める | 縦と斜めを描かない |
| B 三方の合計 | 同じ 3×3 の、行の端・縦の列の下・斜めの角（短い刻み付き）に「15」を1つずつ | 規則に最も近い。プレイ画面の合計の置き方そのもの | 合計が散ってそろって見えにくい。斜めの刻みが 48px で消える |
| C 途中の十字 | 9 / 3 5 7 / 1 だけの途中の盤と、真ん中の行の端・真ん中の列の下に「15」 | 数を入れていく遊びが分かる | 数が5つでナンプレに近い |
| A 洛書だけ | 洛書で埋めた 3×3。合計は出さない | 魔方陣を知る人には象徴的 | 合計が無く数の格子に見える。濃色が多い |

推奨順は D > B > C > A（判断）。部分採用もできる（例: D の行の帯に、B の斜めの角の刻みを足す）。

## 6. 代表案の SVG と選び替え

[ピクトグラム検討/](ピクトグラム検討/) に、候補ごとの代表案を置く。

| ファイル | 内容 |
| --- | --- |
| `d-row-sums.svg` | 推奨案 D（採用 SVG と同じ） |
| `b-three-ends.svg` | B 三方の合計 |
| `c-cross.svg` | C 途中の十字 |
| `a-loshu.svg` | A 洛書だけ |

色は製品と同じ CSS 変数のまま置いている。

### 6.1 選び替える手順

1. 採る候補の SVG を `frontend/src/games/magic-square/assets/pictogram.svg` へ複製する。`aria-label` は表示名に合わせる。
2. 最終検査を通す。

   ```sh
   python3 .claude/skills/design-game-pictogram/scripts/check_svg.py frontend/src/games/magic-square/assets/pictogram.svg \
     --max-colors 2 --forbid-gradients --forbid-filters --forbid-external-images --forbid-text
   ```

3. 既存ピクトグラムと同じサイズ・同じテーマで並べて見比べる。サイズは §2.2 の 177 / 138 / 56 / 46 / 48px を使い、ライトとダークの両方で見る。

   ```sh
   python3 .claude/skills/design-game-pictogram/scripts/make_review_sheet.py \
     --output /tmp/magic-square-pictogram-review.html --size 112 \
     docs/パズル/導入調査/魔方陣/ピクトグラム検討/*.svg \
     frontend/src/games/*/assets/pictogram.svg
   ```

4. 選んでいるときの姿（`pictogram-showcase.svg`）は白黒版の図形を写して描いている。白黒版を変えたら、`/design-game-pictogram-showcase` で選んでいるときの姿も合わせる。
5. この文書の §1 と §4 を、採った案に合わせて直す。
