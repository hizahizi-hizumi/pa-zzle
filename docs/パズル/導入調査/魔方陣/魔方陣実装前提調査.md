- **事実（リポジトリ）**: 現在のリポジトリの文書・コードから確かめたこと。

## 2. 認識合わせの合意

導入調査 Issue #986 の合意節を正とする。要点:

- 依頼は「魔法陣をパズルとして追加して」。マスに数を並べる「魔方陣」と読み、認識合わせのページで示した。
- ルール: n×n のマスに 1〜n² を1回ずつ置き、縦・横・斜め2本のどの列も同じ合計 n(n²+1)/2 にすればクリア。いくつかの数は最初から置いてある。
- 答えは1つで、どのレベルも推理だけで解ける。3×3 は出さない（回転と裏返しを除くと1通りしかない）。
- 数は残っているものから選ぶ。答えどおりかは途中で出さない。
- 称えたい解き方の仮説は「確かめてから置く」。一手戻す・最初からやり直すがある。
- 人間の判断: 列の「あといくつ」の表示を出すかは要検討。盤面の上限を 5×5 に固定しない。この2つは調査で案を比べて決めた（§4 の D-05・D-03）。調査の途中（2026-11-24）に、難易度の調整はそこそこでよく、それまでで最も良かった案を採ると判断した（§4 の D-16）。
- 表示名は「魔方陣」、ゲーム ID は magic-square。新しい別ゲームとして作る。

## 6. PR の切り方

`/add-puzzle` の層をそのまま使う。各ファイルは import 先がすべてその層以下にそろう最も下の層に入れる。

| 層 | ブランチ | 入るもの |
|---|---|---|
| 01 調査 | `magic-square/01-research` | `docs/パズル/導入調査/魔方陣/`（調査コードを含む） |
| 02 ルールと問題 | `magic-square/02-rules-problem` | `frontend/src/games/magic-square/` の `puzzle/`・`problem/`・`session/`・`difficulty.ts`・`problem-selection.ts`・`display-name.ts`、`frontend/scripts/*magic-square*` と `package.json` の scripts、`frontend/biome.json`、カタログの網羅テストの一時的な除外 |
| 03 プレイと画面 | `magic-square/03-play-ui` | `play/`・`tutorial/`・`ui/`・`assets/`・`score.ts`・`play-record.ts`・`play-attempt.ts`・`diagnostics.ts`、`scripts/assets/magic_square_sounds.ts` |

## 7. 確かめていないこと

- 人の手応え: 各レベルの違いが分かるか、L5 の天井が足りるか、鎖を1つの数で表す読みや巡4までを推理と感じるか（試遊と最終レビュー）。
- 4×4 の L1 の解き味が繰り返しに感じられないか。与える数を減らし切っても置く数の約7割は1マスだけ空いた列で決まる（[導入判断調査](魔方陣導入判断調査.md)）。
- 「今の合計」から合計を引く計算が、6×6（合計 111）で負担にならないか（[補助表示調査](魔方陣補助表示調査.md) は 6×6 で試遊で「あといくつ」と比べ直すとした）。
- 6×6 の盤面・列の端の表示・36個の数の欄が 320px に収まり、2桁の数とメモが読めるか（play-ui で撮って確かめる）。
- 実機（iOS Safari）での押し分け・連打、端末の実際の表示の高さ。
- 「魔方陣」の商標（J-PlatPat）と、同じ読みの「魔法陣」と取り違えられないか（人間）。
- 音の素材の外部知見の出典と、実際に聞いた印象（AI は音を聞けない）。
