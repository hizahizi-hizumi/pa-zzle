# 魔方陣音の調査

## 結論

合意した前提（ルール・操作・答えどおりかを途中で出さない）は、音の観点でどれも成り立つ。前提とぶつかる所は1つだけある。外すことを採点で数えるかどうかで、外す操作に音が要るかが変わる（下の1）。

1. **どの操作の瞬間に何を返すか: 成り立つ。** `DESIGN.md`「音」と `.claude/rules/game-structure.md`「効果音」で全部決まる。鳴らすのは、数を置く（置き換える・移すを含む）、不成立（UI が不成立の反応を出す場合だけ）、クリアの3つ。マスを選ぶ、数を外す、列がそろう、違反の知らせ、待った・盤面を戻す・リセットでは鳴らさない。例外は、採点で外すことを「ミスとして数え」て回数を画面に出す場合。そのときは `DESIGN.md` に従い、外す操作にミスの段の音を鳴らす（採点の前提の観点が決める）。
2. **題材のどの素材から作るか: 条件つきで成り立つ。** 推奨は、置く音を「数を刻んだ石の札が石の盤のくぼみに収まる音」、クリアを「石の打楽器（磬のような石の板）の響き」にすること。条件は2つ。play-ui が盤面と数の欄を同じ石の素材で描くこと。アイスフロア迷路の岩の音、スライドパズルの木琴のようなクリア、ブリッジパズルの鐘と並べて聞き、聞き分けられること。
3. **本数と合計の大きさの目安: 成り立つ。** 目安は6本前後（多くて9本）、PADDING を外した合計で 25 KiB 以下。推奨の組（置く・不成立・クリアの3段と仕上げ）は約 22.7 KiB と見積もった。これは既存ゲームの中央値（9本・21.4 KiB）並みで、全ゲームの音を読み込む待ちには、1.6 Mbps を仮定して約 0.12 秒足される。
- 観点の外で見つけたこと: ブリッジパズルの10本と、アイスフロア迷路の `glided-short`・`glided-long` の2本に、ffmpeg が付ける PADDING（1本 8196 バイト）が残っている。計 96.0 KiB で、アプリ全体の FLAC の 15.6% にあたる。以前のコミット 400387e4 でいったん外したものが、その後の書き出しスクリプトで戻った。

## 事実と推測

### 決まり（事実）

- 鳴らす場面: `DESIGN.md`「効果音を鳴らすとき」
  - 前進（中心の操作の成立。同じ操作の中で取り消す向きになるものを含む）と、操作の結果（不成立・ミスとして数える操作・クリア・結果）に鳴らす。
  - 次の操作の対象を選ぶだけの操作、中心の操作とは別に用意した消す・手持ちへ戻す操作、確かめるための表示、待った・盤面を戻す・リセットには鳴らさない。
  - 音だけで知らせる情報を作らない。同じ知らせの中で、正解や先の展開によって音を変えない。
- 鳴らす強さ: `DESIGN.md`「効果音の強さ」
  - 不成立は責めない短い音、ミスはそれより一段重く罰に聞こえない音、クリアは完成演出に合わせる。
  - 回数の多い操作の音ほど小さく短くし、同じ音の機械的な繰り返しにしない。
  - ゲームの音は題材から作る。
- 置き方と鳴らし方: `.claude/rules/game-structure.md`「効果音」
  - FLAC を `assets/` に置いて `playSound` で鳴らし、回数の多い操作には `REPEATED_SOUND_VARIATION` を渡す。
  - 盤面操作の音は `useOperationSound` で、クリアは `useClearSound` で鳴らす。
  - 動きを減らす設定では、画面が何も変わらない不成立の音と、完成演出なしで結果へ進むときのクリア音を鳴らさない。
  - 結果の報酬・選ぶ・始める音と BGM はアプリが持つ。チュートリアルと遊び方の例も、同じフックで鳴らす。
- 前のゲームの見た目・実装をそのまま当てはめない: `GAME.md`「やらないこと」
- 大きさが効く理由
  - タイトルは、`frontend/src/frontend.tsx` の glob が拾う FLAC すべての読み込みを、上限4秒まで待つ（`frontend/src/lib/app-launch.ts`、`docs/プロダクト/仕様/SPEC-005-アプリの入口.md`、`docs/adr/ADR-0011-app-title-sound-loading.md`）。
  - FLAC は JS に埋め込まず1本ずつ取りに行く（`frontend/vite.config.ts` の `assetsInlineLimit`）。
  - 上限までに読み込めなかった音は、読み込み終えるまで鳴らない（`DESIGN.md`、ADR-0011）。

### 前例（事実）

- 手持ちへ戻す操作は鳴らさない: リフレクションは、盤面のピースが減る操作（手持ちへ戻す）に知らせを付けない（`frontend/src/games/reflection/play/use-reflection-play.ts` の `createReflectionOperation`）。ナンプレは、消す操作に知らせを付けない（`frontend/src/games/nanpure/play/use-nanpure-play.ts` の `erase`）。
- 同じ操作の中で取り消す向きのものは鳴らす: バイナリパズルの空きに戻す（`emptied`）、ブリッジの外す（`bridge-removed`）、ナンプレのメモを消す（`note-removed`）、一筆の巻き戻し（`path-shortened`）。いずれも、置くのと同じ押し方の繰り返しで戻る（各ゲームの `ui/use-<game>-sound-effects.ts`）。
- 状態の知らせには音を付けない
  - バイナリパズルは違反を盤面に出すが、操作の知らせは `placed`・`emptied`・`invalid` だけで、違反の音は無い（`frontend/src/games/takuzu/play/use-takuzu-play.ts`、`docs/プロダクト/パズル/PZL-005-バイナリパズル.md`）。
  - 一筆パズルは「行き止まりは延ばした結果の状態の知らせで、同じ延ばす操作の音を先の展開で変えない」と決め、道の長さで音の高さを上げる案を「進み具合を音で知らせることになる」として退けた（`docs/パズル/導入調査/ハミルトン路/ハミルトン路実装前提調査.md` の効果音の行）。
  - ブリッジパズルは島の本数の知らせに音を付けていない（`frontend/src/games/bridges/ui/use-bridges-sound-effects.ts`）。
- 固定のマスの不成立: バイナリパズルは、固定タイルを押すと `invalid` で揺らして鳴らす。動きを減らす設定では揺らさず、画面が変わらないので鳴らさない（`use-takuzu-play.ts`、`use-takuzu-sound-effects.ts`）。
- 置き換え・移すも置く音: リフレクションは、移す・入れ替える・置き換えるときもピースが現れるので、置く音を鳴らす（`use-reflection-sound-effects.ts`）。
- 既存ゲームの素材（素材が重ならないかを見るため）
  - ナンプレ: 鉛筆の先が紙に当たる音（合成から音声ファイルへ移す前のコード、`git show 8182fd4e^:frontend/src/games/nanpure/ui/NanpurePlay/use-nanpure-sound-effects.ts`）
  - リフレクション: ガラスの鏡を置いたような澄んだ音（同じコミットの前のコード）
  - スライドパズル: 小さく乾いた「コト」、クリアは木琴のような C5〜C6 の音階（同上と今の `use-slide-puzzle-sound-effects.ts`）
  - ウォーターソート: 泡と、満ちたグラスの澄んだ音（同上）
  - 詰将棋: スラップスティック・カホン・スリットドラムの録音から作った駒と盤の音（`scripts/assets/tsume_shogi_sounds.py`）
  - ブリッジパズル: 木の板、水、ブイの鐘、ド・ミ・ソの鐘の和音と波（`scripts/assets/bridges_sounds.py`）
  - アイスフロア迷路: 氷のこすれ、岩で止まるこつん、もろい岩が崩れる、雪、氷の割れ（`use-ice-floor-maze-sound-effects.ts`）
  - 一筆パズル: ペン先が点に触れる音（`use-hitofude-puzzle-sound-effects.ts`）
- クリアの調: 既存のクリアの音は、結果の報酬の音と同じ調にそろえている。ブリッジは「ド・ミ・ソの鐘の和音…続けて鳴る結果の報酬の音と同じ調」、一筆は「続けて鳴る結果の報酬の音と同じ調」、スライドは C5〜C6 の音階（各ゲームの `use-<game>-sound-effects.ts`）。
- クリアの全体の長さ: ブリッジのコードのコメントに「ほかのゲームの完成の音（重ねた全体で 1.3〜1.8 秒、ピーク −18.5〜−19.5dBFS）」とある（`use-bridges-sound-effects.ts`）。この値は、この調査では測っていない。
- 回数の多い操作の大きさ: ブリッジのコメントに「一筆の道を伸ばす、ナンプレの数字を入れる、マインスイーパーの旗を立てると同じ小ささ（50ms 窓の最大 RMS −37dB 前後）」とある。計測で、それぞれ −37.5・−37.0・−36.6 dBFS と確かめた。
- PADDING の経緯: コミット 400387e4（「効果音のファイルから空きを除き、JS に埋め込まない」）で、ffmpeg が付ける 8KiB の PADDING を外し、約 770KB を約 278KB にした。
  - 詰将棋のスクリプトは `without_padding` で PADDING を外している。
  - ブリッジ（`scripts/assets/bridges_sounds.py`）は外す処理を持たない。
  - アイスフロアの glided（`scripts/assets/ice_floor_maze_glide_sounds.py`）は説明に「PADDING なし」と書いてあるが、計測では、書き出した2本に PADDING が残っていた。
- パーキングジャムの出られない手はミスに数える（`docs/プロダクト/パズル/PZL-007-パーキングジャム.md`）。そのため `blocked` をミスの段に分けた。
- 5×5 で与える数が11個の問題は空きが14マス（共通の入力の「計測済みの事実」）。この問題では、数を置く操作が最低14回ある。

### 外部知見（記憶による。この調査では出典を開いて確かめていない）

- 有名な4×4の魔方陣には、石に刻まれたものがある。インドのカジュラーホー、パールシュヴァナータ寺院の銘（10世紀ごろ、和34）と、デューラーの版画『メランコリアI』（1514年）の壁の銘板。後者では、銘板の上に鐘が、近くに天秤が描かれている。
- 魔方陣の東アジアでの起こりとされる洛書は、古代中国の伝説に結びつく。同じ古代中国には、石の板を打つ楽器（磬・編磬）がある。

### 推測

- 列がそろった（✓）瞬間の音は、✓ の印より「答えが合った」と聞こえやすい。合意の「答えどおりかは途中で出さない」とぶつかりうる。確かめるには、試遊で、✓ の音ありとなしの版を聞かせて受け取り方を比べる。
- 魔方陣の1プレイの置く回数（空きマスの数と置き直し）は、9×9 のナンプレより少ない。スライドパズル（「1プレイで百回を超えて続けて鳴る」: 合成から音声ファイルへ移す前のスライドパズルのコメント）や、アイスフロア（「1プレイで何十回も鳴る」: 今の `use-ice-floor-maze-sound-effects.ts` のコメント）よりも少ない。根拠は盤面の大きさ（4×4〜6×6 で空きは最大36マス）と、上の5×5の例。難易度の観点の問題集で、空きマスの数を測れば確かめられる。
- 石の札の音のうち、打った瞬間のこすれは雑音だが短い。響きの部分は音程のある減衰音なので、1秒あたりの大きさは純音の群（約 13 KB/s）に近くなる。書き出した後に、このスクリプトで測れば確かめられる。
- 数ごとに音の高さを変えると、数の大小に「順番」の意味を聞き取らせる。魔方陣のルール（どの列も同じ合計）とは関係が薄い。

### 当てた失敗パターン（`.claude/skills/add-puzzle/references/pitfalls.md`）

- 根拠が1つ・推測を事実として言う（全項目）: 決まり・前例・計測・外部知見・推測を節に分けた。推奨には、理由を2つ以上つけた。
- 試作の条件を完成仕様と取り違える（research）: 案ごとの大きさは、既存の中央値と置いた見積もり。目標の長さと大きさは、既存の音の分布から取った出発点。どちらも、書き出して測った値ではない。
- そろえる所と当てはめる所の取り違え（「いつ」は sound だが、この観点の問いに直結するので当てた）: 鳴らす瞬間はアプリの決まりにそろえた。素材とクリアの形は題材から選び、既存の音と重なりうる所（岩・木琴・鐘）を、聞き比べる相手として挙げた。

  | 固定の数のマスや使った数を押し、揺れなどの不成立の反応を出す場合 | 鳴らす | 不成立 | 責めない短い音（0.08〜0.15 秒、RMS50 −37 前後）。動きを減らす設定で画面が変わらないなら鳴らさない（バイナリ・一筆の前例）。押せない（無効）にするなら反応も音も無い |
  | 候補のメモを書く・消す（補助の観点がメモを置くと決めた場合） | 鳴らす（揺らぎ付き） | 操作の成立 | 同じ操作の中で取り消す向き（ナンプレの前例）。置く音より小さく短く（ナンプレのメモ 0.045〜0.055 秒、RMS50 −44 前後） |
  | 待った・盤面を戻す・リセット・遊び方・メニュー | 鳴らさない | ― | `DESIGN.md` |

- **列がそろう（✓）に音を付けない**: 推奨は、✓ の瞬間も置く音だけにすること / 理由は次の4つ / 比べた案: ✓ が出た瞬間に、置く音へ小さな石の鳴りを重ねる（音が1本増え、操作の知らせにそろった列の数を持たせる） / 覆したときに作り直す範囲: 音1本、効果音のフックの分岐、プレイフックの操作の知らせ
  - `DESIGN.md` の鳴らす場面（前進・操作の結果）に、状態の知らせは入っていない。
  - 一筆パズル（同じ操作の音を結果の状態で変えない）、バイナリパズル（違反の表示に音なし）、ブリッジ（島の本数の知らせに音なし）とそろう。
  - ✓ の音は「答えが合った」と聞こえやすい（推測）。
  - ✓ を出すかどうか自体が、補助と状態の知らせの観点で未定（「あといくつ」と同じ）。音を ✓ に結び付けなければ、補助の決定に合わせて音を作り直さずに済む。
- **違反に音を付けない**: 推奨は、合計を超える・埋まって合わない置き方でも、同じ置く音にすること / 理由は次の2つ / 比べた案: 違反を生んだ置く音を沈んだ音に替える / 覆したときに作り直す範囲: 上と同じ
  - 違反の音は、ミスと数えない操作を罰のように聞かせる。
  - 列の表示を出さない案になったとき、違反の音は音だけで知らせる情報になる（`DESIGN.md`「音だけで知らせる情報を作らず」）。
- **外す操作の音は採点に従う**: 推奨は、採点で数えないなら鳴らさず、数えて画面に回数を出すならミスの段の音を1本足すこと / 理由: 外した数は数の欄（手持ち）へ戻るので、`DESIGN.md` の「手持ちへ戻す操作」に当たる。バイナリの空きに戻す・一筆の巻き戻しは、同じ押し方の繰り返しで戻る操作で、魔方陣の外す（置くのとは別の押し方）とは違う / 比べた案: 数えなくても、置く音より小さく下がる音を鳴らす（バイナリ・一筆の扱い）/ 覆したときに作り直す範囲: 音1本と効果音のフックの分岐
  - 合意の「置いた数を外すと少し減点」を採るなら、外すことを数える事実が画面に見えている必要がある。音を鳴らすなら、同じ瞬間に回数の表示が変わることが前提になる（`DESIGN.md`「その瞬間に画面上の変化があるときだけ鳴らす」）。
- **素材は石**: 推奨は、数を刻んだ石の札と石の盤（置く）、石の打楽器の響き（クリア） / 理由は次の4つ / 比べた案は下の4つ / 覆したときに作り直す範囲: 書き出しスクリプトと `assets/sounds/` の音だけ。鳴らす瞬間の表と目標の大きさは素材によらない
  - 有名な4×4の魔方陣が石に刻まれてきた（外部知見）。
  - 洛書と同じ古代中国に、石の打楽器（磬）がある（外部知見）。
  - 既存ゲームで素材が空いている。鉛筆と紙はナンプレ、木の盤と駒は詰将棋、木の板と水はブリッジ、ガラスはリフレクション、泡はウォーターソートが使っている。
  - 数を置く操作が「刻んだ札をはめる」手応えになる。
  - 比べた案:
    - 分銅と天秤（合計を釣り合わせる）。『メランコリアI』に天秤と鐘がある。しかし、盤面を分銅の姿にしにくく、クリアの鐘がブリッジの鐘と重なる。
    - 算木と算盤（和算）。木の音が詰将棋・ブリッジと重なり、算木で書いた数は読みにくい。
    - 紙と筆・鉛筆。ナンプレと重なる。
    - 題材を持たない電子音。`DESIGN.md`「題材から作る」に反する。
  - 条件:
    - play-ui が、盤面と数の欄を同じ素材で描くこと。違う素材の盤面になったら、音はその素材に合わせ直す。
    - sound の項目で、アイスフロアの `stopped`・`rock-crumbled`（岩）、詰将棋の `piece-moved`（木の駒）と並べて聞き、置く音が紛れないこと。ねらいの違いは、アイスフロアの「駒が岩にぶつかって止まる鈍いこつん」に対して、「札が盤のくぼみに収まる乾いた接触に、札そのものの短い鳴りを添える」こと。
- **置く音の大きさ**: 推奨は、長さ 0.06〜0.09 秒、RMS50 −37〜−36.5 dBFS（LUFS −46〜−45）。`REPEATED_SOUND_VARIATION` を付け、数ごとに高さは変えない / 理由: 測った「盤面に物を置く音」の中央（0.075 秒、−36.5 dBFS）に合わせる。置く回数は中くらいなので、小さくしすぎも大きくしすぎもしない（推測） / 比べた案: 数ごとに高さを変える（1つの音を再生の速さで変える）。採らない理由は次の3つ / 覆したときに作り直す範囲: 効果音のフックの再生の速さだけ（音は1本のまま）
  - 数の大小は、魔方陣のルールと関係が薄い（推測）。
  - 1〜36 を聞き分けられる幅にすると、3オクターブに広がる。
  - 再生の速さで変えると、音の長さも変わる。
- **クリアの組み立て**: 推奨は、完成演出に合わせて、横・縦・斜めの3つの向きの段と仕上げを鳴らすこと。演出は play-ui が決め、列を向きごとに光らせる演出を候補として渡す / 理由は次の3つ / 比べた案は下の3つ / 覆したときに作り直す範囲: クリアの音と、効果音のフックのうち演出の時刻を読む部分
  - 段の数が盤面の大きさ（4×4〜6×6）によらず3つのままになる。盤面の上限は未確定（人間の判断）。
  - 5段の波（バイナリ・ブリッジ・リフレクション・一筆・詰将棋）や8音の音階（スライド）と違う、魔方陣の列の向きから来る形になる。
  - 結果の報酬の音と同じハ長調にそろえる（既存のクリアの前例）。
  - 目安の大きさ:
    - 段: 0.2〜0.3 秒、RMS50 −35 前後。
    - 仕上げ: 0.5〜0.6 秒、RMS50 −29 前後、ピーク −20 dBFS 前後（測った仕上げの中央）。結果の報酬（RMS50 −26.7〜−23.6）より小さくする。
    - 動きを減らす設定で完成した盤面を見せるなら、仕上げだけを鳴らす（ブリッジ・リフレクション・一筆の前例）。
  - 段の高さ: 「どの列も同じ合計」を「どの向きも同じ高さ」に写す案（同じ高さで3回、重なりを増やし、仕上げの和音で開く）を第一候補にする。上がっていく案（ド・ミ・ソ）と聞き比べて決める（推測なので、聞いて選ぶ）。
  - 比べた案:
    - 列ごとに1音。2n+2 音（10〜14音）になり、盤面で数が変わるので、ブリッジのように間引きが要る。
    - 仕上げ1本だけ。最小だが、演出が列を順に光らせるなら、演出と音がずれる。
    - 3段を1本の音から高さを変えて鳴らす。約 7 KiB 減るが、既存のどのゲームも段ごとに別の音を持つ。再生の速さで長さも変わる。
- **本数と大きさの目安**: 推奨は6本前後（多くて9本）、PADDING を外した合計 25 KiB 以下 / 理由は次の3つ / 比べた案: 上限を置かない、最小の2本（クリアの段を持てない） / 覆したときに作り直す範囲: 音の作り直しだけ
  - 既存ゲームの中央値（9本・21.4 KiB）並みに収めるため。
  - タイトルは全ゲームの FLAC を上限4秒まで待つ。ゲームを足すたびに、どの人の待ちにも足される。仮定の 1.6 Mbps では、今の全体が 3.16 秒で、上限までの余りは 165 KiB（PADDING を外せば 261 KiB）しかない。
  - 測った中で大きいゲーム（詰将棋 79.9、ブリッジ 65.3、一筆 52.3、アイスフロア 48.9 KiB）は、本数が多い（詰将棋14本、アイスフロア12本）か、クリアの音が長く雑音の層を含む（ブリッジのクリア 54.7 KiB、一筆のクリア 48.0 KiB）。仕上げの雑音の層は短くする。
- **書き出しの形式**: 推奨は、モノラル・16bit・48kHz の FLAC にし、PADDING を外す（詰将棋の `without_padding` の前例）こと。書き出した後に `magic_square_sound.py` で PADDING・MD5・RMS50・LUFS を測り、上の目標値と比べる（作り込みの間の確かめにだけ使い、継続的な検査にはしない: `.claude/rules/research-artifacts.md`） / 理由: PADDING を外さないと1本ごとに 8196 バイト増え、推奨の6本で +48 KiB になる。合計は約3倍になる / 比べた案: ffmpeg の出力をそのまま使う（ブリッジ・アイスフロアの glided の今の状態） / 覆したときに作り直す範囲: 書き出しスクリプトだけ

## 確かめていないこと

- 実際に音を聞いていない。素材・高さ・聞き分けの判断は、数値と前例のコメントからの推測。sound の項目で書き出して聞き比べる必要がある。
- 重ねたクリアの音の全体の長さとピーク。完成演出の時刻（play-ui がまだ無い）と、各ゲームの重ね方の時刻が要るので、1本ずつしか測っていない。全体の値は、ブリッジのコメントの値を引いただけ。
- 回線越しの読み込み時間。HTTP の往復・同時接続・端末での復号の時間は含めず、仮定の帯域での割り算だけ。1.6 Mbps などの帯域は仮定で、利用者の回線を測った値ではない。
- 外部知見（カジュラーホーの銘、『メランコリアI』の鐘と天秤、磬）の出典。この調査では文献を開いていない。
- UI に不成立の反応があるか（固定の数のマス・使った数を押したとき）、候補のメモを置くか。スマホ操作と、補助と状態の知らせの観点が決めるので、表は場合分けで書いた。
- 採点が外すことを数えるか。採点の前提の観点が決める。
- 魔方陣の1プレイの置く回数。空きマスの数は、難易度の観点の問題集が決まってから測れる。
