# ブリッジパズルピクトグラム検討

ブリッジパズル（ゲーム ID `bridges`）のゲーム選択ピクトグラムをどう検討したかの記録。どの着眼点を探索し、どの候補を比べ、なぜ A（数字の島3つと、1本・2本の橋）を推奨するかをまとめる。見直すときに、同じ比較をやり直さずに論点から始められるようにする。

この文書は導入調査の資料であり、現在仕様の正本ではない。採用したピクトグラムの形は `frontend/src/games/bridges/assets/pictogram.svg` を正とする。制作手順と評価方法は `.claude/skills/design-game-pictogram/`（`SKILL.md`、`references/method.md`）を正とする。

記述は次のように区別する。

- **事実（リポジトリ）**: 現在のコード・文書から確かめたこと。
- **事実（実測）**: 候補 SVG を実表示サイズで描画して比べたときに見えたこと。見え方の記述は、比較画像を AI が見て書いたもの。
- **判断**: 上から導いた推奨と理由。

人間による方向の選択はまだ行っていない。本実装では人間のレビューを最終レビューで1回だけ行うので、AI が推奨案で仮に決めた。最終レビューで選び替えられるように、代替の候補も同じ品質まで仕上げている（§5、§6）。

---

## 1. 結論

- 推奨案は **A（数字の島3つと、1本・2本の橋）**。枠を持たず、濃色の輪郭の丸（島）3つを L 字に置き、それぞれに数字 3・2・1 を入れる。左上の「3」から右の「2」へ平行な2本の橋、下の「1」へ1本の橋を架ける。どの島も数字と同じ本数の橋が出ていて、3島が1つにつながった解けた局面になっている。
- 推奨の理由は次の3つ（§4.2）。
  - 島の数字と、数字に合う本数の橋（1本と2本）で、「数字の数だけ橋を架ける」ことが分かる。
  - 格子の盤が多い一覧の中で、丸と線の L 字の外形がほかのどれとも違う。
  - 一覧の 46〜56px でも、丸・数字・2本の橋が見分けられる（端末の画素密度で。§3.4）。
- 見直すときの主な論点は次の3つ（§5.1）。代替は B（数字なし、ちょうどの島を塗る）と C（盤の枠の中の島と橋）。
  - 数字を描くか。
  - 盤の枠を描くか。
  - 島の状態の知らせ（ちょうどの島の色）を描くか。

## 2. 目的と制約

### 2.1 目的

ゲーム一覧でブリッジパズルを素早く見分けられ、ゲーム自身の姿を保ち、既存のピクトグラムと並べても強さが突出しないこと（`DESIGN.md`「ゲームピクトグラム」、`references/method.md` §1）。

### 2.2 制約（事実（リポジトリ））

- 共通描画契約（`SKILL.md`）: `viewBox="0 0 120 120"`、線幅は 4 と 2 だけ、色は `var(--game-pictogram-strong)` と `var(--game-pictogram-soft)` の2色だけ。`check_svg.py --max-colors 2 --forbid-gradients --forbid-filters --forbid-external-images --forbid-text` を通す。
- 色は `GamePictogram` が与える。ライトとダークでは前景色と補助情報色、結果画面では `currentColor` になる。
- 実表示サイズ: ゲーム選択のヒーロー 177px（1280px 幅）/ 138px（390px 幅）、一覧のカード 56px / 46px、結果画面 48px（[ハミルトン路ピクトグラム検討](../ハミルトン路/ハミルトン路ピクトグラム検討.md) §2.2）。一覧の 46〜56px が最も厳しい。
- 比べる既存ピクトグラム: 一筆パズル、マインスイーパー、ナンプレ、パーキングジャム、リフレクション、スライドパズル、バイナリパズル、ウォーターソート。ウォーターソート以外は濃色の外枠を持ち、多くはその中を格子で区切る。バイナリパズルは輪郭の丸を持つ。
- プレイ画面の見た目（[実装前提調査](橋をかけろ実装前提調査.md) D-12、`ui/board/BridgesFigure.tsx`）: 島は数字の入った丸（半径 0.40マス）、橋は島の間の線で、2本の橋は平行な2線。島の状態は足りない・ちょうど・多すぎを色で知らせる。盤の格子線は描かない。
- 似たゲームとの違い（合意の写し）: 既存のマインスイーパー・バイナリパズルはマスの中身を決める。こちらは島どうしを線でつなぐ。
- 数字は `<text>` ではなくパスにする。アプリの UI フォント（Zen Kaku Gothic New、700）の字形をパスにし、字形の外接矩形の中心を島の中心に合わせた。

## 3. 比べた方向と分かったこと

### 3.1 着眼点

- 島と橋: 数字の島と1本・2本の橋、数字の無い丸と線、2島と2本の橋の拡大、中央の島から4方向へ伸びる橋。
- 盤: 枠の中に島と橋、枠なし。
- 状態: ちょうどの島を淡色で塗る、まだ橋の足りない島を白で残す。
- ルール: 交差しない橋（交わる所で片方が止まる）、全島が1つにつながる。

候補にしなかったもの（判断）:

- 交差しない橋: 「交わらない」は2本の線が離れているだけの図になり、説明に頼る。
- 格子線の上の島: プレイ画面に格子線は無く、格子の盤のピクトグラムと同じ系統になる。

### 3.2 形の比較（事実（実測））

| 比べたこと | 案 | 見え方 |
| --- | --- | --- |
| 島の数と並べ方 | 2島（横一列）/ 3島（L 字）/ 4島（U 字・π 字）/ 中央の島から4方向 | 2島で数字が「2」「2」だと、2本の橋が等号に見え「2=2」と読めた。4島の U 字は2本の橋が2組になり、短い2本線が等号に見えやすく、46px で詰まった。π 字は「3=3」と読めた。中央から4方向は照準・方位の記号に見えた。L 字の3島が、数字・1本・2本を最も少ない要素で見せた |
| 島の大きさと橋の長さ | 半径 13〜16、中心の間隔 54〜60 | 島が大きく橋が短いと、2本の橋が等号に見えた。半径 15・中心の間隔 60（橋の長さ 26）で、2本の線が島の間を渡る線に見えた |
| 外形の大きさ | 島の中心 30 / 90 と 34 / 86 | 内側へ寄せると、外枠を持つ既存ピクトグラムより一回り小さく見えた。30 / 90 で外形が 13〜107（光学中心の補正前）に広がり、既存と大きさがそろった |
| 2本の橋の間隔 | 中心の間隔 10、線幅 4 | 46px（端末の画素密度 3）で2本の間に地が残った |
| 数字の大きさ | 字形の高さ 14〜16 | 15 で、島の輪郭の内側に余白を残して読めた |

### 3.3 方向ごとの見え方（事実（実測））

- **A 数字の島**: 濃色の輪郭の丸と数字、線だけで、枠の盤が並ぶ一覧の中で外形が L 字になり目立った。面の塗りが無いので、外枠のあるピクトグラムより一段軽く、ウォーターソートと同じくらいの重さだった。
- **B 数字なし・ちょうどの島を塗る**: 4島の U 字で、3つを淡色で塗り、右下の島だけ白で残した。数字が無いので、分子・ネットワーク図の記号に近づいた。淡色の面があるので A より重く、既存の枠の盤とほぼ同じ重さだった。
- **C 盤の枠の中**: 既存と同じ枠（`x=18 y=18 width=84 height=84 rx=2`）の中に、半径 12 の島3つと線幅2の橋を置いた。一覧の描画言語（枠が主形状）にそろうが、島が小さくなり、46px で数字と2本の橋が A より読みにくく、1倍の画素では潰れた。

### 3.4 画素密度（事実（実測））

1倍の画素（デスクトップの 1x 表示）で 46px にすると、どの候補も数字は形の塊になった（既存のナンプレ・マインスイーパーの数字も同じ）。iPhone の画素密度 3 で 46px にすると、A の数字 3・2・1 と2本の橋は読めた。

## 4. 推奨案 A

### 4.1 仕様（事実（実測））

- 島: 半径 15、濃色の輪郭、線幅4。中心は (30, 33)・(90, 33)・(30, 89)（下の光学中心の補正の前の座標）。
- 数字: 3・2・1（濃色の塗り、字形の高さ約15）。
- 橋: 濃色、線幅4、線端は丸。上の2島の間に平行な2本（y=28 と 38、x=47〜73）、左の2島の間に1本（x=30、y=51〜71）。
- 局面: 3は2本＋1本、2は2本、1は1本で、どの島も数字どおり。3島が1つにつながる。
- 光学中心の補正: 全体を右へ3・下へ2。右下に島が無く、左上の島に重さが寄って見えたため。177px と 46px で、補正後は外枠のあるピクトグラムと並べて偏りが目立たなかった。
- `check_svg.py` の2色・gradient / filter / 外部画像 / text 禁止の検査を通る（使う色は濃色の1つだけ）。

### 4.2 推奨理由（判断）

- **意味的距離**: このゲームの題材は「島の数字と同じ本数の橋を架け、全島をつなぐ」こと。A は数字の入った島と、1本と2本の橋を、数字に合う解けた局面で描く。プレイ画面の島（数字の入った丸）と橋（2本は平行な2線）と同じ形。
- **弁別性**: 枠と格子を持たないので、マスの中身を決める既存のパズル（ナンプレ・マインスイーパー・バイナリパズル）と形で分かれる。バイナリパズルの丸は格子の中に並ぶが、A の丸は線でつながる。
- **実表示サイズ**: 要素は島3つ・数字3つ・橋3本だけ。端末の画素密度で 46px でも読めた（§3.4）。
- **光学的重量**: 塗りの面が無く、外枠のあるピクトグラムより一段軽いが、ウォーターソートと同じくらいで突出しない。

### 4.3 弱点（判断）

- 丸を線でつないだ図は、分子の構造図やネットワーク図にも見えうる。数字と2本の橋でパズルに寄せたが、完全には消えない。
- 「全島が1つにつながる」ことは、3島がつながっているだけで、それ以上は描いていない。
- 2本の橋は、短くすると等号に見える（§3.2）。島の数を増やす・島を大きくするなどで橋が短くなるときは、等号に見えないか確かめ直す。
- 一覧の中では、外枠を持つピクトグラムより一段軽い。

## 5. 再検討するときの論点

### 5.1 論点

- **数字を描くか**: 数字あり（A・C）は「数字の数だけ架ける」ルールが伝わる。数字なし（B）は形が大きく単純になるが、分子・ネットワーク図に近づく。
- **盤の枠を描くか**: 枠あり（C）は一覧の描画言語にそろい、盤のパズルに見える。代わりに島が小さくなり、数字と2本の橋が読みにくい。枠なし（A・B）は外形で目立つが、一覧で一段軽い。
- **島の状態の知らせを描くか**: B はちょうどの島を淡色で塗り、プレイ画面の知らせ（合意 5）を示す。数字と同時に描くと要素が増える。

### 5.2 候補の一覧と代替案

| 案 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| **A 数字の島**（推奨） | 枠なし。数字 3・2・1 の島3つを L 字に置き、2本と1本の橋 | ルールが数字と橋の本数で分かる。外形が一覧で唯一。46px で読める | 分子・ネットワーク図に見えうる。一段軽い |
| B ちょうどの島を塗る | 枠なし・数字なし。4島の U 字、3島を淡色で塗り1島を白で残す。2本1組・1本2組の橋 | 形が大きく単純。状態の知らせを示す | 数字が無くルールが伝わりにくい。分子の図に近い |
| C 盤の枠の中 | 既存と同じ枠の中に、数字の島3つと線幅2の橋 | 一覧の描画言語にそろう | 島が小さく、46px で数字と2本の橋が読みにくい |
| 2島と2本の橋 | 「2」と「2」の島を2本の橋で | 最も単純 | 「2=2」の等号に見える |
| 4島の U 字（数字あり） | A に島を1つ足す | 外形が四角にそろう | 2本の橋が2組で等号に見え、詰まる |
| 中央の島から4方向 | 「6」の島から上下左右へ橋 | 島の数字と本数が1島で分かる | 照準・方位の記号に見える |

推奨順は A > C > B（判断）。部分採用もできる（例: A の島の1つを淡色で塗って知らせを示す、C の枠を外して島を大きくする＝A）。

## 6. 代表案の SVG と選び替え

[ピクトグラム検討/](ピクトグラム検討/) に、候補ごとの代表案だけを置く。

| ファイル | 内容 |
| --- | --- |

| `b-island-state.svg` | B ちょうどの島を塗る |
| `c-framed-board.svg` | C 盤の枠の中 |

色は製品と同じ CSS 変数のまま置いている。

### 6.1 選び替える手順

1. 採る候補の SVG を `frontend/src/games/bridges/assets/pictogram.svg` へ複製する。`aria-label` は表示名に合わせる。
2. 最終検査を通す。

   ```sh
   python3 .claude/skills/design-game-pictogram/scripts/check_svg.py frontend/src/games/bridges/assets/pictogram.svg \
     --max-colors 2 --forbid-gradients --forbid-filters --forbid-external-images --forbid-text
   ```

3. 既存ピクトグラムと同じサイズ・同じテーマで並べて見比べる。サイズは §2.2 の 177 / 138 / 56 / 46 / 48px を使い、ライトとダークの両方で見る。

   ```sh
   python3 .claude/skills/design-game-pictogram/scripts/make_review_sheet.py \
     --output /tmp/bridges-pictogram-review.html --size 112 \
     docs/パズル/導入調査/橋をかけろ/ピクトグラム検討/*.svg \
     frontend/src/games/*/assets/pictogram.svg
   ```

4. この文書の §1 と §4 を、採った案に合わせて直す。
