## 1. 根拠の書き分け

- **事実（リポジトリ）**: 現在のリポジトリの文書・コードから確かめたこと。

## 2. 認識合わせの合意

導入調査 Issue #576 の合意節を正とする。要点:

- ルール: 数字つきの島どうしを、縦横にまっすぐ、間に島のない2島の間に1〜2本の橋でつなぐ。橋は交差しない。どの島も数字と同じ本数で、全島が1つにつながればクリア。
- 一意解で、推理だけで解ける問題だけを出す。試し置きを要する問題は出さない。
- 盤面は最大 10×10。5段階で、上ほど盤面が広く島が多く、全体のつながりまで読まないと決まらない所が増える。
- 操作はタップで 1本 → 2本 → なし。島から島へなぞって架ける操作も付ける。交差する所には架けられない。
- 知らせるのは島ごとの本数（ちょうど・多すぎ）だけ。橋の正誤は出さない。
- 「ひとつ戻す」がある。点数は速さが中心で、架け直しと戻すは減点しない。
- 表示名は「ブリッジパズル」、ゲーム ID は bridges。新しい別ゲームとして作る。

| D-11（交点） | 交わる2候補では橋がある方、どちらにも無ければマスを対角線で4つに分けて選ぶ | 線が最も近い候補を選び、交わる橋に阻まれていれば阻まれた知らせを返す。線までの距離の差が 0.15マス以内のときだけ、2島の間の真ん中に近い方を選ぶ。両方の真ん中が 0.15マス以内で重なれば短い辺を選ぶ。そのうえで片方にだけ橋があれば橋のある方を選ぶ。それでも決まらなければ盤面を変えず、2つの候補の線を短く示す | 人は「つなぎたい2島の間の真ん中」を押すので、対角線の分け方では短い辺の真ん中を押しても長い辺に架かった（試遊）。橋のある方をいつも選ぶと、交わる候補を狙ったタップで阻まれた知らせが出ずに橋が増え、交点の真上では何も起きないことがあった（試遊）。値は問題集の盤面で、真ん中を狙う押し方と交点を避ける押し方を指のぶれ付きで模して置いた |

| D-13 | 交差の相手の橋を短く知らせる | 阻んだ橋を薔薇色で0.9秒点ける。動きを減らす設定でも点ける。島を押している間は架けられる相手への線を空色で示す。クリアは島0 から橋をたどって島が順に跳ねる波で見せる。キーボード（矢印で島を移る・Shift と矢印で回す）も足した | 阻まれた操作に反応が無いと壊れて見える（試遊）。全島がちょうどでもつながらない盤面と見分けられるよう、つながりに沿って波を渡す |
| D-15 | 基準時間は作業量（橋の本数・島の数・推論の量）から | 基準時間 = 8秒 + 島 1秒 + 橋 0.8秒 + 「少なくとも1本」の手詰まり 3秒 + つながりの手詰まり 6秒 + 数字だけでは決まらない行き先 1秒。0点は基準時間の3倍 | 項の割合が過半にならず、操作だけでは満点に届かない値。見渡す・島・橋の項は、初見のレベル1 が厳しすぎた試遊を受け、既存ゲームのレベル1 と比べて上げた（[成績評価](橋をかけろ成績評価.md) §3・§3.1）。レベル4・5 で試し置きでも満点になりうる懸念が残る（同 §3.4） |
| D-16 | 事実と作業量を保存する | 作業量は6項目（島・行き先・橋の本数・2種の手詰まりの回数・決まらない行き先）。離れたプレイは架けていた橋の本数と要る本数を残す。結果画面の主な成績は時間と橋の操作の回数 | 問題集から引けない記録も評価し続けるため（[成績評価](橋をかけろ成績評価.md) §5） |
| ―（難易度選択） | 計画に無し | 難易度の見本は、レベルの盤面の上限の大きさの、そのレベルの組み合わせに入る一意解の盤面（問題集には無い）から、横幅いっぱいを5行だけ、数字も印も描かずに島の丸だけで描く（描く島 7・9・12・12・14）。1マスはスマホで 10px | 横幅（盤面の大きさ）と島の数の差を図の量で見せるため。数字の読みだけでは決まらない島に外側の輪を付ける形は、3巡の試遊と最終レビューで何の印か分からないとされ、人間の判断で外した（つながりの読みの差は図に表れない）。帯に数字と黄色の塗りを描いた形は、スマホで数字が読めず塗りが島の状態の4つ目に読まれ、盤面全体の縮図は1マス 5.5px で潰れて L4 と L5 が同じ姿になった（試遊・読まれ方の確かめ） |
| ―（ピクトグラム） | 計画に無し | 数字 3・2・1 の島3つを L 字に置き、2本と1本の橋で結ぶ（枠なし） | [ピクトグラム検討](橋をかけろピクトグラム検討.md) |

## 6. PR の切り方

`/add-puzzle` の層をそのまま使う。各ファイルは import 先がすべてその層以下にそろう最も下の層に入れる。

| 層 | ブランチ | 入るもの |
|---|---|---|
| 01 調査 | `bridges/01-research` | `docs/パズル/導入調査/橋をかけろ/`、`scripts/research/bridges_*` |
| 02 ルールと問題 | `bridges/02-rules-problem` | `frontend/src/games/bridges/` の `puzzle/`・`problem/`・`session/`・`difficulty.ts`・`problem-selection.ts`・`display-name.ts`、`frontend/scripts/*bridges*` と `package.json` の scripts、`frontend/biome.json`、カタログの一時的な除外 |
| 03 プレイと画面 | `bridges/03-play-ui` | `play/`・`ui/`・`assets/`・`score.ts`・`play-record.ts`・`play-attempt.ts`・`diagnostics.ts` |
| 04 掲載 | `bridges/04-catalog` | `frontend/src/game-catalog/bridges/` と `game-catalog.ts`、`frontend/src/pages/puzzles/bridges/` と View、`frontend/src/router.ts`、一覧のテスト、一時的な除外の削除 |

問題集の生成スクリプトが `score.ts`（基準時間）を import するなら、そのスクリプトは 03 に入れる。切り出しの時点で外れたファイルはこの表に足す。

## 7. 確かめていないこと

- 人の手応え: L1/L2・L3/L4 の違いが分かるか、L5 の天井が足りるか、段 D を推理と感じるか（試遊と最終レビュー）。
- 2本橋の出やすさは、p2 0.5 が L5 に入らないことだけ確かめた（D-08）。
- 解法器の独立した確かめ（作った本人以外による手追い）。
- 実機（iOS Safari）での押し分け・連打・なぞり、端末の実際の表示の高さ。
- 交わる所のタップの押し心地。線が最も近い候補を選び、決まらないときは候補を示す形にした（§4.1 の D-11）が、実機で狙いどおりに押せるかは確かめていない。
- 既製の問題の島の数。10×10 の島の数の上限を上げる生成法は、§4.1 の D-02（分割）で対処した。
- 「ブリッジパズル」の商標と、「ブリッジ」がトランプや橋の組み立てゲームと取り違えられないか（人間）。
- 市場の大きさ（一次調査の代表例は Play 500+ / JP 15評価と小さい）。
