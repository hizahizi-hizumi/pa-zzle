# ノノグラムピクトグラム検討

ノノグラムのゲーム選択ピクトグラムをどう検討したかの記録。どの着眼点を探索し、どの候補を比べ、なぜ A（盤の上と左にヒントの数字を置く）を推奨するかをまとめる。見直すときに、同じ比較をやり直さずに論点から始められるようにする。

この文書は導入調査の資料であり、現在仕様の正本ではない。採用したピクトグラムの形は `frontend/src/games/nonogram/assets/pictogram.svg` を正とする。制作手順と評価方法は `.claude/skills/design-game-pictogram/`（`SKILL.md`、`references/method.md`）を正とする。

記述は次のように区別する。

- **事実（リポジトリ）**: 現在のコード・文書から確かめたこと。
- **事実（実測）**: 候補 SVG を実表示サイズで描画して比べたときに見えたこと。見え方の記述は、比較画像を AI が見て書いたもの。
- **判断**: 上から導いた推奨と理由。

人間による方向の選択はまだ行っていない。本実装では人間のレビューを全段の実装後に1回だけ行うので、AI が推奨案で仮に決めた。最終レビューで選び替えられるように、代替の候補も同じ品質まで仕上げて [ピクトグラム検討/](ピクトグラム検討/) に置いている（§5）。

---

## 1. 結論

- 推奨案は **A（盤の上と左にヒントの数字を置く）**。濃色の太い枠の 3×3 の盤（淡色の格子）に、濃色の四角で塗ったマスを5つ置き、盤の上に列のヒント「1 2 2」、左に行のヒント「2 2 1」を濃色の数字で並べる。ヒントは塗ったマスと合っている。
- 推奨の理由（§4.2）:
  - 「盤の外の上と左に数字が並び、左上の角が空く」形は、ノノグラムの盤そのものの外形で、ほかのパズルにない。
  - 一覧で数字が盤の外にあるピクトグラムはほかに無く、46〜56px でも外形で見分けられる。
  - 外枠・格子・記号の3段の階層は既存のナンプレ・バイナリパズルと同じで、一覧の重さがそろう。
- 見直すときの主な論点は次の3つ（§5.1）。
  - ヒントを数字で描くか、棒で描くか（C）。
  - ヒントを描くか（D は描かない）。
  - ヒントを盤の外に開いて置くか、外枠で囲んだ表にするか（E）。

## 2. 目的と制約

### 2.1 目的

ゲーム一覧でノノグラムを素早く見分けられ、ゲーム自身の姿を保ち、既存のピクトグラムと並べても強さが突出しないこと（`DESIGN.md`「ゲームピクトグラム」、`references/method.md` §1）。

### 2.2 制約（事実（リポジトリ））

- 共通描画契約（`SKILL.md`）: `viewBox="0 0 120 120"`、線幅は 4 と 2 だけ、色は `var(--game-pictogram-strong)` と `var(--game-pictogram-soft)` の2色だけ。`check_svg.py --max-colors 2 --forbid-gradients --forbid-filters --forbid-external-images --forbid-text` を通す。
- 数字は `<text>` を使えないので、字形をパスで描く（Inter Bold の字形を写した）。
- 実表示サイズ（`GameSelectionGallery` の大きさから計算）: ヒーロー 177px（PC）/ 138px（スマホ）、一覧のカード 56px（PC）/ 46px（スマホ）、結果画面 48px。一覧の 46〜56px が最も厳しい。
- 比べる既存ピクトグラム: ウォーターソート、ナンプレ、マインスイーパー、パーキングジャム、スライドパズル、バイナリパズル、リフレクション。ウォーターソート以外は濃色の太い外枠を持ち、ナンプレ・マインスイーパー・スライドパズル・バイナリパズルはその中を格子で区切って記号を置く。
- プレイ画面の見た目（事実（リポジトリ））: 盤の上に列のヒントを縦に、左に行のヒントを横に並べる。塗ったマスはマス全体を濃色で塗り、× は細い線で控えめに描く。完成図は機械で作る図柄で、意味のある絵ではない（合意1）。

## 3. 比べた方向と分かったこと

### 3.1 着眼点

次の着眼点から候補を作った。

- 盤とヒント: 上と左にヒントの数字が並ぶ盤、ヒントを棒の長さで示す盤、ヒントを外枠の中の欄に入れた表、1本の行とそのヒント、交わる行と列とそれぞれのヒント、行のヒントだけの盤。
- 塗りと印: 塗ったマスだけの図柄、塗りと × が混じる途中の盤、なぞって1行を塗る動き、塗りの塊とヒントの数の対応（括弧で長さを示す）。
- 完成図: 図柄が現れる盤、点描のような画素絵。

候補にしなかったもの（判断）:

- 画素絵（ハートなど意味のある絵）: 合意1で完成図を意味のある絵にしないので、遊ぶ内容と食い違う。
- 1本の行とそのヒント（B として試作）: 盤が帯になり、138px でも細く軽い。一覧でほかの正方形のピクトグラムと重さが合わない。
- 塗りの塊に括弧で長さを示す、なぞる動き: 記号が増え、46px で潰れる。
- 盤を 4×4 にしてヒントに2つの数を含める（A3 として試作）: 138px では「1 1」の並びが見えるが、46px で数字が粒の模様になった。

### 3.2 塗りの描き方（事実（実測））

- 3×3 の盤で塗ったマスをマス全体で塗ると（最初の試作）、隣り合う塗りがつながって大きな黒い塊になり、一覧で突出して重かった。
- 塗りを格子から 3.5 だけ内側に縮めると、マスが1つずつ読め、重さが既存のバイナリパズル・マインスイーパーと同程度になった。
- 盤の9マス中5マスを塗った。7マス以上では塊に、3マス以下では空の盤に見えた。

### 3.3 ヒントの数字（事実（実測））

- 数字を淡色にすると（A4）、138px でも盤の飾りに見え、46px でほぼ消えた。濃色にした。
- 数字の高さは 13（盤のマス 22 に対して）。46px では数字の形は読めないが、盤の外の上と左に並ぶ粒として外形に残る。

## 4. 推奨案 A

### 4.1 仕様（事実（リポジトリ））

- 盤: `x=34 y=35 width=66 height=66`、`rx=2`、濃色、線幅4。3×3 の格子は淡色・線幅2。
- 塗ったマス: 濃色の四角（1辺15、格子から3.5内側）を5つ。図柄は左上から右下への階段（`##.` / `.##` / `..#`）。
- ヒント: 濃色の数字（高さ13）。列のヒント「1 2 2」を盤の上（中心 y=28）に、行のヒント「2 2 1」を盤の左（右端を盤から7離して右寄せ）に置く。塗ったマスと合っている。
- 光学中心の補正: 左へ2・上へ1。盤の外の数字を含めた外形の中心に置くと、盤の重さで右下へ寄って見えた（138px と 46px で確かめた。事実（実測））。
- `check_svg.py`（2色・gradient / filter / 外部画像 / text 禁止）を通る。

### 4.2 推奨理由（判断）

- **意味的距離**: 盤の外にヒントの数字が並び、中のマスを塗るのはノノグラムの盤そのものの姿。プレイ画面と同じく、列のヒントは上、行のヒントは左に置いた。
- **弁別性**: 数字を盤の外に置くのは一覧で A だけ。左上の角が空いた外形が、ほかの「濃い外枠の正方形」と分かれる（46〜56px で確かめた。事実（実測））。
- **光学的重量**: 外枠（濃・4）、格子（淡・2）、塗りと数字（濃）の3段で、ナンプレ・バイナリパズルと同じ階層。盤が 66 とほかの外枠（84）より小さいぶん、外の数字が埋めて全体の大きさがそろう。
- **実表示サイズ**: 46px では数字は読めないが、盤の上と左の粒の並びとして残り、塗ったマスは1つずつ見える。

### 4.3 弱点（判断）

- 46px では数字そのものは読めない（既存のナンプレ・スライドパズルも同じ）。
- 塗りがマス全体ではなく縮めた四角なので、プレイ画面の塗りより「置いた駒」に近く見える。バイナリパズルの四角と似る。
- 完成図が現れる報酬（クリアの演出）は描いていない。

## 5. 候補と代替案

### 5.1 論点

- **ヒントを数字で描くか、棒で描くか**: 数字（A）はプレイ画面のヒントと同じ。棒（C）は数を長さで示し抽象的で、46px では盤から伸びる短い線が光の放射や目盛りに見えた。
- **ヒントを描くか**: 描かない（D）と、塗りと × の盤だけになり、バイナリパズル・マインスイーパーと構成が近い。
- **ヒントを盤の外に開くか、外枠で囲むか**: 囲む（E）と外形がほかと同じ正方形になり重さはそろうが、ヒントの欄が表の見出しに見え、ナンプレ・スライドパズルの「格子に数字」と近づく。

### 5.2 候補の一覧

| 案 | ファイル | 内容 | 長所 | 短所 |
| --- | --- | --- | --- | --- |
| **A 上と左のヒント数字**（推奨） | `a-clue-digits.svg`（採用 SVG と同じ） | 3×3 の盤、塗り5つ、盤の外の上と左に数字 | 盤とヒントの外形がそのまま。一覧で唯一、数字が盤の外 | 46px で数字は粒になる |
| C ヒントを棒で | `c-clue-bars.svg` | A の数字を、数の長さに比例した濃色の棒にする | 数字を使わず、塊の長さを形で示す | 棒が放射・目盛りに見え、ヒントと読めない |
| D 塗りと×だけ | `d-fills-crosses.svg` | 4×4 の盤（ほかと同じ外枠）、塗り8つと × 4つ、ヒントなし | 外形と重さが既存とそろう。塗りと×のメモが見える | ヒントがなく、バイナリパズル・マインスイーパーと構成が近い |
| E 枠に囲んだヒント欄 | `e-enclosed-clues.svg` | 外枠の中を濃い線で分け、1行目と1列目をヒント欄にする | 印刷された問題の表に近く、外形がほかとそろう | 表の見出しに見え、ナンプレ・スライドパズルと近い |

推奨順は A > E > C > D（判断）。部分採用もできる（例: A の盤を 4×4 にして外の数字を増やす、A に × を1つ足す）。

[ピクトグラム検討/comparison.png](ピクトグラム検討/comparison.png) は、4候補と既存7ゲームを 177 / 138px（ヒーロー）と 56 / 46px（一覧のカードの枠つき）で、ライトとダークに並べた比較表示。

### 5.3 選び替える手順

1. 採る候補の SVG を `frontend/src/games/nonogram/assets/pictogram.svg` へ複製する。`aria-label` は表示名（`NONOGRAM_DISPLAY_NAME`）に合わせる。
2. 最終検査を通す。

   ```sh
   python3 .claude/skills/design-game-pictogram/scripts/check_svg.py frontend/src/games/nonogram/assets/pictogram.svg \
     --max-colors 2 --forbid-gradients --forbid-filters --forbid-external-images --forbid-text
   ```

3. 既存ピクトグラムと同じサイズ・同じテーマで並べて見比べる（§2.2 の 177 / 138 / 56 / 46 / 48px、ライトとダーク）。

   ```sh
   python3 .claude/skills/design-game-pictogram/scripts/make_review_sheet.py \
     --output /tmp/nonogram-pictogram-review.html --size 112 \
     docs/パズル/導入調査/ノノグラム/ピクトグラム検討/*.svg \
     frontend/src/games/*/assets/pictogram.svg
   ```

4. この文書の §1 と §4 を、採った案に合わせて直す。
