# ノノグラム難易度

ノノグラムの `レベル 1`〜`レベル 5` を、[難易度開発手順.md](../../難易度開発手順.md) の工程に沿って組み立てた検討記録。[ノノグラム実装前提調査](ノノグラム実装前提調査.md)（以下「前提調査」）§11 の仮の組み合わせ定義に行・列あたりの塊の数を足して製品コードへ移し、製品の問題集で分布・供給・素朴なプレイヤーを測った結果を残す。

この文書は現在仕様の正本ではない。採用した契約（挑戦の定義、基準とするプレイ条件、組み合わせで分類する考え方、評価不能・提供範囲外の扱い、問題集からの供給）は [SPEC-020 ノノグラム](../../../プロダクト/仕様/パズル/SPEC-020.md) を正とする。組み合わせの正確な値はコード（`frontend/src/games/nonogram/difficulty.ts` の `nonogramLevelCombinations`）を正とし、ここには検討時点の値として写す。

根拠は次の見出し語で区別する。

- **計測**: 製品コードと問題集（問題集の版 1・生成器の版 1）で測った結果。一時スクリプトで測ったものはその旨を書く。
- **導出**: 定義から論理的に導けること。
- **推測**: 実プレイで確かめていない判断。

まだ人間が遊んで確かめていない。AI の試遊（実ブラウザでの実プレイ）の所見で組み合わせと図柄の作り方を直した（§4.1）が、§9 の人間の試遊が済むまで、各レベルの体験差は仮説として扱う。

| 条件 | 内容 |

## 2. 挑戦と基準とするプレイ条件

- **挑戦**（前提調査 §11.1 のまま）: 1本の行・列のヒントと決まったマスから確定できるマスを見つけ、その結果が交わる行・列を開く連鎖を、手を付けられる場所が少ない局面でも見つけ続けて最後までたどること。
- **基準とするプレイ条件**（前提調査 §11.2 のまま）: 1本の行・列について、ヒントと今のマスに合う塊の置き方をすべて考え、どの置き方でも同じになるマスを確定できる（完全な線の読み）。待った・盤面を戻すは使わない。
- **分析が表現できる解法過程の範囲**: 1本の行・列の中で完結する読み（完全な線の読み）と、その結果を交わる行・列へ渡す連鎖まで。2本以上の行・列を同時に仮定する読み・仮置き・背理は表現しない。そうした読みが要る問題は出さないので、提供する問題では分析が表現できない読みは要らない（導出）。
- 人が普通に使う端寄せの読み（重なり・端からの押し出し）は完全な線の読みより弱い。端寄せの読みでは止まり、完全な線の読みで初めて進む場面の回数を特徴「端寄せでは進まない読み」として測り、分類には使わず分布だけを見る（§5）。

## 3. 特徴

`frontend/src/games/nonogram/problem/difficulty-analysis.ts`。線の読みの特徴は、完全な線の読みで、読める行・列をすべて同時に読む「段」を重ねる伝播で測る。読む順序に依らない。行・列あたりの塊の数はヒントの並びだけから求め、線の読みの経過には依らない。

| 特徴 | 意味 | 分類に使うか |
| --- | --- | --- |
| 連鎖の深さ（`roundCount`） | 解き終わるまでの段の数 | 使う（主） |
| 最初に進められる行・列（`entryLineCount`） | 1段目で何か決まる行・列の数。入口の広さ | 使う（上限） |
| 細い段の数（`narrowRoundCount`） | 進められる行・列が2本以下の段の数 | 使う（下限） |
| 行・列あたりの塊の数（`clueShape.blockCountPerLine`） | ヒントの数字の数の、行・列あたりの平均（黒の無い行・列は0）。1本の行・列を読む重さ | 使う（範囲） |
| 盤面の大きさ | 見渡す範囲 | 使う（許す範囲） |
| 最初の段で決まるマス（`firstRoundFixedCellCount`） | 序盤の楽さ | 使わない（分布を見る） |
| 進められる行・列の最小（`minimumProgressedLineCount`） | 最も細い局面 | 使わない（分布を見る） |
| 端寄せでは進まない読み（`readingsBeyondEdgesCount`） | 塊の割り当てまで考える読みの回数 | 使わない（分布を見る） |
| 塊が1つだけの行・列の割合 | 重ね合わせだけで読める行・列の多さ | 使わない（分布を見る。生成スクリプトの出力だけ） |

### 4.1 行・列あたりの塊の数を足した理由

最初は前提調査 §11.4 の案（塊の数なし）のまま問題集を作った。AI の試遊で、レベル1・3・5の1問目の手応えがほぼ同じで、レベル3の問題は全行が塊1つでなぞるだけだった。塊が1つだけの行・列は重ね合わせだけで読めるので、連鎖の深さが上がっても1本ずつの読みが軽いままになる。

その問題集を測ると、連鎖の深さはレベルごとに分かれていた一方、塊の分かれ方はレベル間で大きく重なっていた（計測。一時スクリプトで、直す前の問題集と今の問題集（§5）に同じ定義で当てた。10 / 50 / 90 パーセンタイルの取り方は §5 と同じ）。

| レベル | 塊が1つだけの行・列の割合（直す前） | 同（今の問題集） | 行・列あたりの塊の数（直す前） | 同（今の問題集） |
|---|---|---|---|---|
| 1 | 0.13 / 0.44 / 0.86 | 0.44 / 0.64 / 0.93 | 1.07 / 1.50 / 2.25 | 1.06 / 1.31 / 1.56 |
| 2 | 0.06 / 0.39 / 0.81 | 0.31 / 0.44 / 0.56 | 1.19 / 1.63 / 2.50 | 1.44 / 1.56 / 1.72 |
| 3 | 0.05 / 0.35 / 0.70 | 0.06 / 0.20 / 0.33 | 1.28 / 1.70 / 2.70 | 1.80 / 2.15 / 2.40 |
| 4 | 0.00 / 0.25 / 0.60 | 0.00 / 0.05 / 0.14 | 1.40 / 1.90 / 2.95 | 2.50 / 2.68 / 2.77 |
| 5 | 0.00 / 0.09 / 0.41 | 0.00 / 0.04 / 0.09 | 1.73 / 2.82 / 3.20 | 2.80 / 3.05 / 3.32 |

- 分類には、塊が1つだけの行・列の割合ではなく行・列あたりの塊の数を使う。塊が2つ・3つの行・列の違いも表せるので、上のレベルの間も分けられる（導出）。
- 塊の数は連鎖の深さとはほぼ独立に、図柄の平滑化の回数で決まる（§6）。範囲を足しただけでは当たる候補がほとんど無いレベルが出るので、生成の作り方もレベルごとに絞った（§6）。
- AI の試遊では、レベル5の左右対称の問題が、対称を仮定すると読みの大半を飛ばせた（1分18秒。同じレベル5の非対称の問題は3分54秒）。完全な線の読みは対称を使わないので特徴には出ない。
- 左右対称を知っている人の読み（各行・列を、左右対称になる置き方だけで読む）を、左右対称の図柄を全レベルで作っていた問題集に一時スクリプトで当てた（計測）。レベル2〜4の左右対称の問題はほぼすべて、そのレベルの連鎖の深さの範囲を下回った。左右対称の図柄はレベル1だけに残した（§6）。レベル1は最も易しいレベルなので、範囲を下回っても易しい側に外れるだけになる（導出）。

| レベル | 左右対称の問題 | 連鎖の深さの中央値（完全な線の読み） | 同（対称を仮定した読み） | 範囲を下回る問題（左右対称の中で） |
|---|---:|---:|---:|---:|
| 1 | 247 | 3 | 2 | 74（30%） |
| 2 | 250 | 5 | 2 | 242（97%） |
| 3 | 250 | 7 | 4 | 237（95%） |

## 6. 供給

生成は `frontend/scripts/generate-nonogram-problem-pool.ts`。レベルごとに、そのレベルの盤面の大きさ × 図柄の作り方の組（生成条件）で決定的な seed の候補を番号順に作り、分析・分類して、そのレベルに当たった候補を、同型（回転・反転）の重複と近い図柄（回転・反転込みで2マス以下しか違わない図柄）を除きながら生成条件を巡回して採る。生成条件ごとに候補30,000を上限とする（上限は採否を変えず、条件の内訳にだけ効く）。

レベルごとの図柄の作り方（`levelPatternStyles`）:

| レベル | 平滑化 | 黒の確率 | 左右対称 | 作り方の数 |
|---|---|---|---|---:|
| 1 | 1〜2回 | 0.45〜0.65 | あり・なし | 20 |
| 2 | 1〜2回 | 0.45〜0.65 | なし | 10 |
| 3 | 0〜1回 | 0.45〜0.65 | なし | 10 |
| 4 | なし | 0.45〜0.65 | なし | 5 |
| 5 | なし | 0.45〜0.55 | なし | 3 |

- 行・列あたりの塊の数は平滑化の回数でほぼ決まる（各レベルの連鎖の深さの帯に入る候補の10〜90パーセンタイルで、平滑化2回は 1.0〜1.8、1回は 1.1〜2.1、なしは 1.8〜3.3。計測）。レベルの塊の数の範囲に当たる候補がほとんどできない平滑化の回数は、上限まで調べても採れないので除いた。
- 左右対称はレベル1だけに使う。レベル2以上では、対称を仮定した読みで連鎖の深さがそのレベルの範囲を下回る（§4.1）。
- レベル5は、黒の確率 0.60 以上では連鎖の深い問題が候補1,000個に1問ほどしかできないので 0.45〜0.55 に絞った。

- 作り方ごとの問題数は、レベル1で20〜28問、レベル2で50問、レベル3で52〜58問、レベル4で133〜138問、レベル5で165〜168問。当たりにくい作り方だけが少ない（レベル3の黒 0.65 の2通りで33問・15問、レベル4の黒 0.60 で80問、黒 0.65 で12問）（計測）。
- 候補が落ちる理由の大半は提供範囲外（レベル3で 107,365 / 208,251）と図柄の条件（同 74,738）。線の読みで止まる候補はレベル3で 20,585（9.9%）（計測）。

- `--verify` は全2,500問を identity から作り直し、解・分類・特徴の一致と、レベルをまたいだ同型・seed の重複と近い図柄が0件であることを確かめる（計測: 不合格0、重複0、近い図柄0組、約2秒）。
- 実行時は問題集から引くだけで、選んで復元する処理は1万回で平均 0.028ms（計測）。

## 8. 素朴なプレイヤー

`/add-puzzle` Skill の素朴なプレイヤーの共通部品（`scripts/naive-play-core.ts`）と、ノノグラムのアダプタ（`examples/naive-play-ng.ts`）で、問題集の各レベル30問 × 3回を測った（計測）。測ったときの Skill の版は、`/add-puzzle` Skill のブランチ `claude/epic-faraday-bdl9bn` のコミット `831686b4` 以降（合法手に取り消しの手を入れない版）。知らせ（aid）は「ヒントに合った行・列が分かる」だけ。プレイヤーが打てる手はマスを塗ることだけにし、塗りを消す手を入れない。消す手を入れると、試し塗りして戻すプレイヤーが未訪問の盤面を作り続けて一度も戻らず、塗りの付け外しを総当たりして解いてしまう。

| プレイヤー | 知らせ | 打ち切り | レベル1 | レベル2 | レベル3 | レベル4 | レベル5 |
|---|---|---|---:|---:|---:|---:|---:|
| 当てずっぽう: 塗れるマスを無作為に塗る | なし | 1回に黒の数の2倍まで塗り、5回まで最初から | 0% | 0% | 0% | 0% | 0% |
| 貪欲: ヒントに合った行・列の数が最も多くなるマスを塗る。合う数が減る手しか無ければ最初から | あり | 1回に黒の数の3倍まで、5回まで | 2% | 0% | 0% | 0% | 0% |
| 貪欲: 同上。合う数が減っても最良の手を塗り続ける | あり | 同上 | 0% | 0% | 0% | 0% | 0% |
| 試し塗りして戻す: ヒントに合った行・列の数の多い順に塗る深さ優先。黒の数だけ塗って解けていなければ1手戻す | あり | 戻すのは50回まで、塗るのは黒の数の20倍まで | 0% | 0% | 0% | 0% | 0% |

- 汎用のプレイヤー（当てずっぽう・貪欲・試し塗りして戻す）は、どのレベルでもほぼ解けない（解けたのはレベル1の貪欲の2%だけ）。試し塗りして戻すは、すべてのレベルで戻す上限に達した（計測）。ヒントに合った行・列の数は、その行・列の塗りが揃いきるまで増えないので、塗る途中の手がかりにならない（推測）。
- 前提調査 §11.6 の試し塗りは、レベル1では、解けたときの手数の中央値が35〜40手（塗るマスの中央値34マス）、戻した回数の中央値が0〜4回で、ほとんど戻らずに解く。レベル2で解けたときの手数の中央値は297〜521手（塗るマスの中央値39マスの約8〜13倍）、レベル3で解けた3%（知らせあり）は703手（同45マスの約16倍）。レベル4・5は解けない（計測）。
- 最上位を試し塗りで押し切れる割合は、どのプレイヤーも0%（計測）。
- レベルが上がるほど、どのプレイヤーも解ける割合が下がり、逆転しない（計測）。
- 限界: 素朴なプレイヤーは「知らせで試行錯誤に落ちないか」を止める向きの検査で、難しさの根拠にしない。完全な線の読みができる人は試し塗りを要しない（導出）。熟練者の手応えは測っていない（最上位の天井は前提調査 §11.7）。
- 再現: 共通部品とアダプタは `/add-puzzle` Skill の中にあり、リポジトリのこの版には無い。Skill が main に無い版では再現できない。

## 9. 採用ゲートと完了ゲート

| ゲート | 条件 | 判定 | 根拠 |
|---|---|---|---|
| 採用ゲート | 5段階の体験差を定義でき、各レベルを継続して供給できる見込み | 満たす | 前提調査 §2・§5・§11（研究用 Python の計測） |
| 完了ゲート1 | 5段階に意味がある | 機械側は満たす。体験は未確認 | 同じ挑戦（連鎖を細い局面でもたどる）が連鎖の深さ・入口・細い段で段階的に強まり、1本ずつの読みの重さ（行・列あたりの塊の数）も上のレベルほど重い（§4・§5）。AI の試遊で手応えが揃った点は塊の数で直した（§4.1）。人間の体験としての説明は試遊で確かめる |

### 人間の試遊で確かめること

- §7 の代表・境界問題をラベルを伏せて遊び、レベルの順序が体験と矛盾しないか。特にレベル1・3・5の手応えに段差があるか、レベル4・5が「広いだけ」に感じないか。
- 端寄せの読みで止まる場面（レベル5の31.6%が含む）で、人が塊の置き方をすべて考えて進めるか、試し塗りに落ちるか。
- 左右対称の図柄（レベル1の47.2%）で、半分を読めば済み、レベル1の中でも易しすぎないか（1-61 で比べる）。
- レベル5が、熟練者に物足りなくないか（仮置きなし・幅10列までの天井を受け入れた判断は前提調査 §11.7）。
- レベル4・5の平滑化しない図柄（塊のまとまりが無い細かい模様）で、クリアで図柄が現れる報酬が足りるか。
- 連鎖の深さ（すべて同時に読む段の数）が、人が1本ずつ読むときの体験とどれだけ合うか。
