## 3. 守る遊びの核

1本の行・列のヒントとすでに決まったマスから「ここは必ず黒・必ず白」を確定させ、行で決めたマスが列の手がかりになって次の行を開く連鎖を追うこと。上のレベルほど、連鎖が長く、手を付けられる行・列が少ない局面を挟む。

正誤を出さず、試し塗りで当てる遊びにしない。作業量や罰で難しくしない。

### 3.1 GAME.md の原則への対応（AI判断（仮決定））

| 原則 | ノノグラムでの具体化 |
| --- | --- |
| そのパズルならではの面白さを強める | 面白さは行・列の読みの連鎖（上記）。正誤・ミスの数・数字ごとの消し込み・自動の×を出さず、読む部分を奪わない（§8）。ドラッグで1行・1列をまとめて入れ、作業量を難しさにしない。難易度は連鎖の深さ・入口の広さ・細い局面を主にし、大きさは1つのつまみにする（§11）。スコアは速さと塗り直しの少なさで、読んでから塗るプレイを称える（§13） |
| 盤面が主役 | 盤面と行・列のヒントを画面幅いっぱいに置き、ズームなしで全体を見せる。計測値は見出しの共通部品に置き、プレイ画面に並べない |
| 盤面で分からせる | 塗りはマスを黒く塗る見た目、×はメモとして控えめに描き、どちらもその場で切り替える。ヒントにちょうど合った行・列はヒントを薄くして知らせ、文章で知らせない（§8）。5マスごとの太線と操作中の行・列の強調で位置を示す。クリアでは未確定と×を消して図柄を現す（§10） |

## 4. 採用ルール

**AI判断（仮決定）**:

- 白黒だけ。多色は扱わない。
- 盤面は幅 × 高さの長方形で、幅は10列まで。正方形または縦長にする（横長は作らない。スマホ縦画面で幅が先に尽きるため）。
- 各行の左と各列の上に、黒の塊の長さを順に並べたヒントを出す。黒の無い行・列のヒントは `0` と表示する。
- プレイヤーのマスは「未確定・塗り・×」の3状態。×はメモで、クリアに要らない。
- 問題は、完全な線の読み（1本の行・列について、ヒントと今のマスに合う塊の置き方をすべて考え、どの置き方でも同じになるマスを確定する。§11.2）を行・列に繰り返すだけで全マスが決まるものに限る。この条件を満たす問題は解が一意になる（事実: 線の読みは解を外さないので、全マスが決まればその1つしかない。`selfcheck` で小盤面の総当たりと照合）。

外すもの: 多色、横長の盤面、15列以上、仮置きの要る問題、意味のある絵と題材名。

## 5. 問題供給

### 5.1 生成の方式（AI判断（仮決定））

1. 図柄の候補を作る: 無作為に黒を置き（黒の確率 0.45〜0.65）、半分を左右に写して左右対称にするか決め、多数決の平滑化（0〜2回）で塊のまとまりを作る。生成条件（黒の確率 × 平滑化 × 対称）は30通りで、巡回して偏りを避ける。
2. 図柄の条件で除く: 黒の割合 35〜72%、黒の無い行・列が縦横合わせて1本まで、上下左右に黒の無い孤立した黒マスが黒の12%まで。
3. 仮置きなしで解けるかを、線の読みの固定点で確かめる。探索をしないので、採否が節点数の上限などの打ち切りに左右されない（移植で供給が黙って変わる失敗を避けられる）。
4. 難易度の特徴を測り（§11.3）、5段階の組み合わせ（§11.4）に当てはめる。
5. 回転・反転で重なる図柄を正規化キーで除く。

### 5.2 計測

条件: 7種の大きさ × 30生成条件 × 300候補 = 63,000候補（seed 17）。仮置きなしで解けなかった候補は大きさごとに200件を抜き取り、解を2つまで数えた（節点の上限 20,000。打ち切りは0件）。時間は Python 3.13・1コア。

|---|---:|---:|---:|---:|---:|---|
| 7×7 | 9000 | 5206 | 3418 | 38.0% | 0.1 | 45 / 155 |
| 8×8 | 9000 | 4788 | 3676 | 40.8% | 0.2 | 52 / 148 |
| 9×9 | 9000 | 4679 | 3769 | 41.9% | 0.3 | 31 / 169 |
| 10×10 | 9000 | 4279 | 3952 | 43.9% | 0.4 | 48 / 152 |
| 10×12 | 9000 | 4273 | 3818 | 42.4% | 0.5 | 42 / 158 |
| 10×13 | 9000 | 4357 | 3684 | 40.9% | 0.6 | 45 / 155 |
| 10×15 | 9000 | 4302 | 3613 | 40.1% | 0.7 | 40 / 160 |

- 図柄の条件で約半分を除くのは、平滑化で黒が偏る（黒の確率 0.65・平滑化2回では大半が黒72%超）ためで、候補は安いので問題にならない（計測）。
- 解けない候補の約4分の3は複数解、約4分の1は一意だが仮置きが要る。どちらも採らない（計測）。

## 6. 問題 identity と供給方式（AI判断（仮決定））

- 問題は事前に作った問題集から出す（既存ゲームと同じ方式）。実行時には生成しない。
- `NonogramProblem` は幅・高さ・行ヒント・列ヒントと、クリア判定と完成演出に使う解（黒マスの集合）を持つ。
- `NonogramProblemIdentity` は生成器の版・大きさ・生成条件（黒の確率・平滑化・対称）・seed を持ち、identity から問題を作り直せる。問題集は identity と難易度の特徴（作業量を含む）を持つ。
- 問題 ID は共通の `createProblemId(problemIdentity)` を使う。
- 生成は製品コード（TypeScript）で行い、問題集はそれで作る。研究用 Python の乱数とは図柄が一致しないので、移植で揃えるのは線の読み・特徴・採否の判定の出力で、固定した図柄の入出力をテストで照合する。

## 7. 操作（AI判断（仮決定））

- 盤面の下に「塗り / ×」のモード切り替えを置く。タップでそのモードを1マスに入れる。同じ状態のマスをタップすると未確定に戻す。
- ドラッグで同じ行・列に連続して入れる。方向は最初に動いたマスで行か列に固定し、斜めには入れない。ドラッグの最初のマスで「入れる / 消す」を決め、ドラッグの間は変えない。1回のドラッグを待ったの1手とする。
- 塗りモードで×のマスをタップすると塗りにする。×モードで塗りのマスをタップすると×にする（塗り直しに数える。§13）。
- 盤面ではページのスクロールとダブルタップの拡大を止める。操作中の行・列とヒントを強調する。5マスごとに太線を引く。
- 長押し・2本指・ズームは使わない。

比べた案: 塗りと×をタップの回数で巡回（1回で塗り、2回で×）。モード切り替えが要らないが、ドラッグで「何を入れるか」が最初のマスの状態で変わり、誤入力が増えると考えた（推測）。

## 8. 状態の知らせ（合意4の具体化）

- 塗ったマスの並びがヒントにちょうど一致した行・列は、そのヒントを薄くする。未確定・×は問わず、塗りだけで判定する。これは今の盤面だけから分かる状態の知らせ（SPEC-017）で、正解を使わない（事実: SPEC-017 の定義）。
- クリアの判定（塗りの集合が解と一致）は、「すべての行・列のヒントが薄くなった」と同じになる。一意解なので、全行・全列が一致する塗りは解しかない（事実）。クリアが正解を使った隠れた判定にならない。
- 出さないもの: 解と照らした正誤、ミスの数、数字ごとの消し込み、空きマスへの自動の×、行・列が破綻していること（塗りすぎ等）の表示。破綻の表示は今の盤面から分かる状態の知らせに当たるが、合意4の範囲を超えるので入れない（AI判断（仮決定））。

## 9. 補助操作（AI判断（仮決定））

- 待った（1手戻す。1回のドラッグを1手）・盤面を戻す・リセット・別の問題を、共通の語（`play-vocabulary.ts`）と共通部品で置く。
- やり直し（redo）は置かない。既存ゲームに無いため。
- ヒント（次に読める行・列を教える）は置かない。線の読みから作れるが、合意の範囲に無い。

## 10. クリア条件

塗ったマスの集合が解の黒マスと一致した時点でクリアとする。×や未確定が残っていてもよい。クリアの演出では、未確定と×を消して図柄だけを見せる（AI判断（仮決定））。

## 11. 難易度

### 11.1 挑戦の定義（AI判断（仮決定））

> 1本の行・列のヒントと決まったマスから確定できるマスを見つけ、その結果が交わる行・列を開く連鎖を、手を付けられる場所が少ない局面でも見つけ続けて最後までたどること。

挑戦にしないもの: 盤面の大きさだけによる作業量、塗る手数、マスの押しにくさ、ヒントの読み取りにくさ、仮置き。

### 11.2 基準とするプレイ条件（AI判断（仮決定））

- ルールを知っていて、1本の行・列について、ヒントと今のマスに合う塊の置き方をすべて考え、どの置き方でも同じになるマスを確定できる（完全な線の読み。§11.3）。
- 知らせは §8 のものだけ。待った・盤面を戻すは使わない（仮置きの要らない問題だけを出すため）。

### 11.3 特徴（計測で使ったもの）

線の読みは2種類を持つ。

- **完全な線の読み**: その行・列のヒントと今のマスに合う塊の置き方すべてで同じになるマスを確定させる。1本だけを読む読みの上限で、基準とするプレイ条件（§11.2）の読み。採否と特徴はこの読みで測る。
- **端寄せの読み**: 各塊の最も左と最も右の位置の重なりを黒、どの塊も届かないマスを白にする。人が普通に使う読み（重なり・端からの押し出し）に近い。完全な線の読みより弱い（`selfcheck` で4,000本中99本で差が出た）。特徴「端寄せでは進まない読み」を測るためだけに使う。

特徴は、完全な線の読みで、読める行・列をすべて同時に読む「段」を重ねる伝播で測る。読む順序に依らない（解き順・視点への依存の失敗を避ける）。

| 特徴 | 意味 | 挑戦との関係（推測） |
| --- | --- | --- |
| 連鎖の深さ | 解き終わるまでの段の数 | 前の結果を使って次を開く読みが何重に要るか |
| 最初に進められる行・列の数 | 1段目で何か決まる行・列の数 | 入口の広さ。少ないほど最初に探す |
| 最初の段で決まる割合 | 1段目で決まるマスの割合 | 序盤の楽さ |
| 細い段の数 | 進められる行・列が2本以下の段の数 | 手を付けられる場所が少ない局面の多さ |

### 11.6 素朴なプレイヤー（止める向きの検査）

「ヒントにちょうど合った行・列だけが分かる」知らせのもとで、試し塗りで押し切れるかを測った。

素朴なプレイヤー: 最初に、黒の無い行・列と、何も決まっていない行・列の重なりだけを使う。以降は行・列を読まない。知らせありでは、ヒントに合った行・列の残りを×にする（知らせを信じる）。行き詰まると、黒の足りない数が最も少ない行・列の未確定マス（塗ったマスの隣を優先）を試しに塗る。数えるだけで分かる破綻（塗りすぎ・塊が長すぎる・埋まったのに合わない・足りない）が出たら戻して×にし、破綻が出ないまま行き詰まったら深さ優先で戻る。上限は3,000節点。各レベル40問（計測）。

|---|---|---:|---|---|---:|
| 1 | あり | 40/40 | 1 / 8 / 80 | 0 / 2 / 70 | 32/40 |
| 1 | なし | 39/40 | 0 / 10 / 100 | 0 / 5 / 93 | 25/40 |
| 2 | あり | 17/40 | 20 / 189 / 1026 | 1 / 171 / 1008 | 3/40 |
| 2 | なし | 13/40 | 28 / 160 / 929 | 9 / 144 / 914 | 2/40 |
| 3 | あり | 1/40 | 814 | 793 | 0/40 |
| 3 | なし | 0/40 | - | - | 0/40 |
| 4 | あり・なし | 0/40 | - | - | 0/40 |
| 5 | あり・なし | 0/40 | - | - | 0/40 |

- 最上位を試し塗りで押し切れる割合は0/40。レベル3でも1/40で、そのときも800回の塗り直しを要した（計測）。
- 知らせの有無で差は小さい。知らせは塗りが正しいかを教えないので、試し塗りの確かめにならない（推測）。
- 限界: このプレイヤーは弱い。完全な線の読みができる人は、すべての問題が仮置きなしで解けるので試し塗りを要しない。この検査は「知らせで試行錯誤に落ちる」ことを止める向きにだけ使い、難しさの根拠にしない。段04で、`/add-puzzle` Skill の素朴なプレイヤーの共通部品（`.claude/skills/add-puzzle/scripts/naive-play-core.ts`）にアダプタを書き、問題集で測り直す。

### 13.1 良いプレイの定義（AI判断（仮決定）。合意5）

### 13.2 評価に使う事実（AI判断（仮決定））

| 事実 | 評価に使うか | 定義・理由 |
| --- | --- | --- |

- 塗り直しの少なさ 15点: 1マスごとに3点減らす（5マスで0点）。
- 記録には事実と作業量だけを保存し、点数は保存しない（SPEC-006）。

## 17. 確かめていないこと

- 人間の確認: §1 の合意6点はすべて人間未確認の想定。
- 難易度の人間対応: 5段階の順序と意味を実プレイで確かめていない。連鎖の深さ（同時に読む段の数）が、人が1本ずつ読むときの体験とどれだけ合うかも確かめていない。
- 人の手筋との対応: 基準とするプレイ条件は完全な線の読み（§11.2）とした。人が普通に使う端寄せの読み（重なり・押し出し）では止まる問題が、レベル3で1%、レベル4で4%、レベル5で24%ある（計測。§11.4）。その局面で人が塊の置き方をすべて考えて進めるか、止まるか・試し塗りに落ちるかは確かめていない。
- 図柄の見栄えと、クリアで図柄が現れる報酬の強さ。
- スマホ: 幅320での約21〜24px のマスのタップとドラッグを実機で押し分けられるか、iOS（WebKit）のタッチ。マスの大きさと収まりは段03で実ブラウザ（Chromium）で測った（§15.1「縦の上限」）。
- 素朴なプレイヤーは弱いモデルで、熟練者の手応えは測っていない（製品の問題集での結果は [ノノグラム難易度](ノノグラム難易度.md) §8）。
- 表示名の商標（§14）。
