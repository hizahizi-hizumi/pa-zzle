# ソリティア 調査: 採点の前提

## 結論

- **合意の「待ったは、読み違いを取り消す手として扱う」は、そのままでは成り立たない。** 待ったには、読み違いの取り消しのほかに、山札のめくりを戻す（山札の確認）・押し間違いの直しが混ざる。素朴な解き方が詰んだ配り方では、解けなくした手まで戻るのに、めくり以外の手は中央値9手、めくりも1手ずつ戻すなら中央値28手かかった（計測7）。待ったを押した回数は、読み違いの数ではなく、めくりを待ったで戻せるか、待ったで戻すか盤面を戻すかで決まる。代案（推奨）: 読み違いは「めくり以外の、打った手を取り消したこと」で捉え、待ったの連続と盤面を戻すを同じ取り消しの別の手段として扱う（仮決定の候補2）。
- 称えたい解き方（合意の案「先まで読んで、待ったに頼らず運び切る。速さも見る」）: **条件つきで成り立つ**。8つの候補（仮決定の候補の表）を比べても、読みの確かさを主に、速さを次に見るのがこのパズルに合う。難易度の作りが「目先の手で進めると詰む」で、全部の札が見えていて推測が要らないので、詰むのは読み違いだと言えるため。条件は、上の代案で読み違いを捉えることと、1回の取り消しで評価段階が大きく下がらないこと。読み違いは、知らせが出る所まで進んでからでないと分からず、どの手が悪かったかも知らされないため。
- 山札を何周もめくる操作: **読み違いとして扱わない（成り立つ）**。山札の中身は配った時点で決まっている。列の28枚が見えていて、残りの24枚が山札にある。1枚ずつ何周でもめくれるので、どの札もめくり進めればいつでも使え、解けるかどうかは山札の順番によらない。100回配って、順番を持つ解法器と、山札を札の集まりとして扱う解法器の判定は一度も食い違わなかった（計測1）。めくりは、札の順番を見るためと、札を取り出すための手間で、速さの作業量に入れて扱う。
- 待った・盤面を戻す: **条件つきで成り立つ**。めくり以外の手を取り消したことは、読み切れなかった筋を捨てたことを表す。ただし、待ったで戻るのと、盤面を戻してやり直すのとは、どちらも自然に選ばれる。解けなくした手が、配った直後から数えたほうが近い配り方が19のうち7あった（計測7）。だから、片方だけを軽く扱うと、点の抜け道になる。
- 組札から列へ戻す手: **ふつうの手として扱う（成り立つ）**。解けると分かった72の配り方で、この手を禁じて解き直すと、68が解け、解けなくなったものは無かった（残り4は打ち切り。計測6）。解くのに要る技ではなく、早く組札へ上げた札を戻すための、ルールで認めた手なので、減点も加点もしない。
- 手数を称えるか: **称えない（合意どおり成り立つ）**。どの順で解いてもよいと約束している。最短手数は求まらない。今の解法器では、解けるかどうかさえ、配り方の20〜25%で判定できなかった（計測1）。同じ配り方の解どうしで、めくり以外の手数が中央値1.14倍、最大2.06倍ばらつく（計測4）。めくりの数は、札を取り出す順が同じでも、山札の順番だけで1.45〜2.23倍変わる（計測5）。
- 速さ: **条件つきで成り立つ**。素朴な解き方で解ける配り方でも、めくり以外が約88手・めくりが約35回で、1問に約120の操作が要る（計測2）。時間の多くが操作に使われるので、基準はレベルからではなく、配り方の作業量（列の移動・山札からの取り出し・めくり）から作る。組札へ置く52手のうち中央値39.5手は、自動で置いても損が無い（計測3）。自動で置くかどうかで操作の量が大きく変わるので、play-ui で決めてから基準を作る。
- 図鑑から遊び直したとき: **通常のプレイと同じに扱う（成り立つ）**。遊び直しは新しいプレイで、自己ベストの比較にも入る（GAME-009、SPEC-002、ADR-0001）。2回目は、山札の順番と要の手を覚えているので、取り消しが無く速くなる。これは同じ配り方を解けるようになった上達として受け入れる。1回目と、覚えた解をなぞる2回目の点は、score で計算して確かめる。

期待値ファイル（`.expected.json`）は作っていない。採点の前提は案を seed で選ぶ計測ではなく、score の項目で採点を決めるときに、レベル分けした配り方で測り直すため。

限界:

- 集合 DFS は、損の無い組札への手を自動で打ち、山札と組札の札を列へ置く手は、その上へすぐ置ける札があるときだけ作る（遅らせても損が無いため）。それでも25%は10万局面で打ち切った。
- 素朴な解き方は、列を丸ごと動かし、最初に見つけた置き先を選ぶ、の1通りだけで測った。人の目先の手とは違う。
- 集合 DFS の解は、人が選ぶ順に札を取らないので、めくりが多めに出る（計測5の96〜194回）。人のめくりは、素朴な解き方の24〜47回とのあいだにあると見込む（推測）。
- 時間は Python で測った値で、ブラウザでの時間ではない。

## 事実と推測

- 事実: 列の28枚は表で配り、山札はその残りの24枚である。山札の中身は、配った時点で列から引き算して決まる: 導入調査 Issue #987 の合意節（「列の札は全部表向きで配る」「52枚・7列」）
- 事実: 1枚めくり・何周でもなら、山札と捨て札に残る札は、どれでもめくり進めれば捨て札の右端に出せる。だから、解けるかどうかは山札の順番によらない。ルールからの論証で、計測1で食い違いが無いことを確かめた: 導入調査 Issue #987 の合意節（「山札は1枚ずつめくり、何周でもめくれる」）、計測1
- 事実: 素朴な解き方で解けるか（L1 の判定）は、山札の順番で変わる。素朴な解き方は、捨て札に出た札をその場で使うため。解けるかどうかとは違い、レベルの判定は順番に左右される。難易度の観点に渡す: 計測10
- 事実: 採点は称えたい解き方から決め、待った・やり直しは操作名ではなく意味で扱う: `docs/プロダクト/ゲーム/GAME-004-プレイ成績と評価.md`「採点の考え方」
- 事実: 待った・盤面を戻すは同じプレイの続きで、回数はプレイの事実として数える。リセットは新しいプレイで、計数を数え直す。どれを提供するかはパズル仕様で決める: `docs/プロダクト/ゲーム/GAME-005-1プレイの区切りとやり直しの操作.md`
- 事実: 合意したのは待ったと盤面を戻すで、プレイ中のリセットは挙がっていない: 導入調査 Issue #987 の合意節。パーキングジャムは、同じ問題の新しいプレイを結果画面からだけ始められるようにして、計数を捨てられないようにしている: `docs/パズル/導入調査/パーキングジャム/パーキングジャム採点.md`（29行目）
- 事実: 「今の盤面からもう進められないこと」は状態の知らせで、「この先の手詰まり」は補助にあたる: `docs/プロダクト/ゲーム/GAME-008-状態の知らせと補助.md`。合意も「先回りして『もう解けない』とは言わない」: 導入調査 Issue #987 の合意節。プレイ中に、どの手で解けなくなったかは知らされない
- 事実: 遊び直しは新しいプレイで、自己ベストの比較に含め、記録の遊び直しと通常のプレイを分けない: `docs/プロダクト/ゲーム/GAME-009-図鑑.md`「図鑑から遊ぶ」、`docs/プロダクト/仕様/SPEC-002-自己ベスト.md`、`docs/adr/ADR-0001-problem-id.md`
- 事実: 同じパズルでは、より良いとみなすプレイほど良い評価にする: `docs/プロダクト/要件/NFR-010-より良いプレイほど良い評価になる.md`
- 事実（近い既存ゲームとの比較。出典は各パズル仕様と `frontend/src/games/water-sort/score.ts`）:

- 推測: L4〜5 では、上手な人でも取り消しが起きる。読み違いは手詰まりまで中央値9手（めくりを含めて28操作）進んでから表れ、どの手かは知らされない（計測7・8）。52枚の先を全部読み切るのは難しいため。人の試遊で、レベルごとの取り消しの数を見て確かめる

- 推測: 覚えた解をなぞる2回目は、取り消しが無く、時間は操作だけになるので、最高評価に届きやすい。score で1回目と2回目の点を計算して確かめる
- 推測: 解けなくした手を解法器で見つけて数える案は、ブラウザでは重く、判定できない局面も残る（Python で p90 5.3秒、5%が打ち切り。計測9）。遊ぶ人からも、どの手が悪かったか見えない

## 仮決定の候補

- 称えたい解き方: [推奨] **「見えている列を読み、どの札をどの順で掘り出し、どこへ置き、空いた列をいつ使うかを先まで決めて、打った運びを取り消さずに52枚を組札へ運び切るプレイを最も称え、速さを次に見る」** / [理由] (1) 難易度は「目先の手で進めると詰む」で作る（合意）ので、詰まずに運べることが、レベルで求めている読みそのものである。(2) 全部の札が見えていて、山札の順番は解けるかどうかに効かない（計測1）。解けるかどうかに推測も運も入らないので、詰んだのは読み違いだと言える。(3) L1 は誰でも取り消し無しで解けるので、そこでは速さが上手さの差になる。読みと速さの両方を見れば、どのレベルでも差が出る / [比べた案] 下の表 / [覆したときに作り直す範囲] score の採点項目・計測する事実・テスト、パズル仕様の「評価」の節、結果画面の主要成績

  | 候補 | 何の上手さか | 扱い | 理由 |
  |---|---|---|---|
  | A 読みの確かさ: 打った運びを取り消さずに運び切る（合意の案の中心） | 先読み | 採る（主） | 上の理由 (1)(2) |
  | B 速さ: 早く運び切る | 読みの速さと操作の手際 | 採る（次） | 理由 (3)。ただし時間の多くは操作なので、作業量から基準を作る（計測2・3・5） |
  | C 気づきの早さ: 解けない局面に入っても、知らせが出る前に自分で戻す | 自分の筋を見直す読み | A に含める | 知らせより早く戻れば、捨てる手が少なくて済む。A の取り消しを捨てた手の量で数えれば自然に表れ、回数で数えれば表れない（どちらにするかは score で決める）。別の項目にすると、A と同じ事実を2度数える |
  | D 試して見つける: 盤面で試し、待ったで戻して正しい筋を探す（速さだけで採点） | 試行錯誤の手際 | 採らない。ただし罰しすぎない | 戻すのが安いので、読まずに試す遊び方が速さで上回りうる（推測）。レベルが求める読みが点に表れない。それでも、読み違いは遅れて表れ、どの手かも分からないので、1回の取り消しで評価段階が大きく下がらないようにする |
  | E 手数の効率: 少ない手で運ぶ | 手の無駄の少なさ | 採らない | どの順でもよいと約束した。最短は求まらない。解どうしで手数が最大2.06倍ばらつく（計測4）。手数の大半は決まった手（組札へ52手） |
  | F 山札の扱い: 少ない周回・少ないめくりで使い切る | 山札の順番を覚える | 採らない（時間には表れる） | 「何周でもめくれる」というルールを、隠れた周回の制限に変えてしまう。めくりの数は、同じ取り出し順でも山札の順番だけで1.45〜2.23倍変わる（計測5）。解けるかどうかに関わらないので、読みではなく記憶と運になる |
  | G 組札を戻さない・組札へ着実に積む | 組札の扱い | 採らない | 組札から戻す手は解くのに要らず（計測6）、ルールで認めた立て直しの手である。罰する理由も、称える理由も無い |
  | H 操作の正確さ: 置けない所へ置こうとしない（パーキングジャム型） | ルールの見落とし | 採らない | 置けるかどうかは色と数で見えているので、試しても何も分からない。外れた操作の多くは、小さい札への押し間違いだと見込む（推測） |

- 読み違いの事実の捉え方: [推奨] 待ったを押した回数ではなく、**めくり以外の打った手を取り消したこと**で捉える。めくりと山札を戻す操作の取り消しは読み違いに数えない。待ったを続けて押して戻るのと、盤面を戻すのとは、同じ取り消しの別の手段として、どちらかだけが軽くならないようにする（数え方は score で決める） / [理由] めくりを待ったで戻せるなら、取り消しの操作の約3分の2はめくりになる（計測7: めくり以外は中央値9、めくりを含めると28）。盤面を戻すほうが近い配り方が7/19ある。片方を軽くすれば、そちらで取り消すのが点の抜け道になる（失敗パターン「自己ベストの抜け道」） / [比べた案] (a) 待ったを押した回数（合意の文言どおり）: めくりを待ったで戻せるか、待ったか盤面を戻すかで数が変わるので採らない。(b) 手詰まりの知らせに着いた回数: 知らせより前に自分で気づいて戻ったプレイを数えず、知らせが出ない手詰まり（計測8の4/28）も数えないので、主には使わない（記録だけにするかは score で決める）。(c) 解けなくした手の数を解法器で数える: 読み違いを最も正確に表す。ただし重く、判定できない局面が残り（計測9）、遊ぶ人に見えない / [覆したときに作り直す範囲] `session/` の計測事実、score のテスト、記録の版

- 山札のめくり・周回: [推奨] 点に使わない。速さの基準の作業量に入れる / [理由] めくりは、山札の順番を見るためと、札を取り出すための手間である。推測は要らない（計測1） / [比べた案] 候補 F（周回やめくりの少なさを称える） / [覆したときに作り直す範囲] score の採点項目と基準時間

- 組札から列へ戻す手: [推奨] ふつうの手として扱い、減点も加点もしない / [理由] 解くのに要らず（計測6）、早く上げた札を戻すための、ルールで認めた手である。組札へ自動で置く場合には、その立て直しにも使われる / [比べた案] 候補 G（戻さないことを称える）、上級の技として称える（解くのに要らないので根拠が無い） / [覆したときに作り直す範囲] score の採点項目

- 手数・成立しない操作: [推奨] 点に使わない。最短手数は問題集に持たない / [理由] 候補 E・H / [比べた案] ウォーターソート・スライドパズル・アイスフロア迷路の効率（最短手数との比）、パーキングジャムの正確さ（不成立の操作） / [覆したときに作り直す範囲] 問題集に最短手数を持たせる生成（今の解法器では求まらない）、score、図鑑の手数の出来と絞り込み（GAME-009 の「手数を評価に使うパズル」の扱いが加わる）

- 速さ: [推奨] 主の項目の次に見る。基準時間は、配り方の作業量（掘り出しに要る列の移動、山札からの取り出し、めくり）から求め、レベルからは決めない。組札へ自動で置くかを play-ui で決めてから基準を作る / [理由] 1問に約120の操作が要り、時間の多くが操作に使われる（計測2）。めくりの量は山札の順番で変わる（計測5）。自動で置くかで、操作が中央値39.5手変わる（計測3） / [比べた案] 速さだけ（候補 D）、速さを見ない（L1 で差がつかない） / [覆したときに作り直す範囲] score の基準時間と、問題集に持つ作業量

- 図鑑・記録から遊び直したとき: [推奨] 通常のプレイと同じに採点する。覚えた解での2回目が最高評価に届くことは、同じ配り方を解けるようになった上達として受け入れる / [理由] GAME-009・SPEC-002・ADR-0001 で、遊び直しを通常のプレイと分けないと決めている。どの手が要だったかを覚えて解き直すのも、読みの上達である / [比べた案] 遊び直しを自己ベストから外す、または印を付ける（SPEC-002 に反する） / [覆したときに作り直す範囲] 記録・自己ベスト（アプリ全体の決まりになるので ADR が要る）

- プレイ中のリセット: [推奨] 置かない（合意どおり、待ったと盤面を戻すだけ）。同じ問題を初めからやり直すのは、盤面を戻すにする / [理由] リセットは新しいプレイなので、取り消しの事実が消え、自己ベストの抜け道になる。パーキングジャムの前例と同じ / [比べた案] リセットを置く / [覆したときに作り直す範囲] プレイ画面の操作、score の抜け道の確かめ

## 確かめていないこと

- 人が遊んだときの1問の時間、押し間違いの直しの頻度、レベルごとの取り消しの数、遊び直しの時間: 人の試遊が要る（作り込みの試遊と最終レビュー）
- レベル分けした配り方での値: 難易度の観点がレベルを決める前なので、ランダムに配った100回で測った。決まったら、計測2・4・5・7を、各レベルの配り方で測り直す
- 判定できなかった配り方: 100回のうち20回は、どの解法器でも判定できなかった。計測7でも、手詰まりで解けない28のうち9は、解けなくした手の位置まで分からなかった（途中の局面で打ち切り）
- めくりを待ったで戻せるか、組札へ自動で置くか、待ったが自動で置いた手もまとめて戻すか: play-ui の決定である。決まると、取り消しの操作の数と操作の量が変わる
- 「どう動かしても組札へ運べない」の正式な定義と、スマホでの判定の重さ: この観点では、知らせの条件の一つの読み方（組札の枚数を増やせない）で測っただけ
- 人の目先の手での詰み方: 素朴な解き方を1通りしか測っていない
