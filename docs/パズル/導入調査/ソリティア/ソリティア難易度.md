ソリティア（PZL-013。全部表向きのクロンダイク、山札は1枚ずつ何周でも）の `レベル 1`〜`レベル 5` を、[難易度開発手順.md](../../難易度開発手順.md) の工程1〜8 に沿って導入調査の段階で組み立てた検討記録。

この文書は資料で、正本ではない。採用した決まりとその意図はパズル仕様（PZL-013）に、特徴の計算・境目・分類条件はゲームのコードとテストに置く。ここに書く値は、調査コード [solitaire_difficulty.py](調査コード/solitaire_difficulty.py) で検討した時点のもので、ゲームのコードへ移した後はコードを正とする。

特徴の定義は6回作り直した。反例探し（検査 A4）で、版1 は道筋の選び方・乱数・数え方で、版2 は分かれ道の数え方・安全な組札送りの扱い・打ち切りの扱いで、版3 は詰んだ局面の見分け方と罠の置き場所の決め方で、レベルが動くと分かった。版1〜3 の段の中を分ける量は、どれも「何を1つと数えるか」（1手・1つの分かれ道・1つの終わり）に自由度が残っていた。版4 は、数える単位を持たない量（組札の枚数）で段の中を分けた。版4 に当てた反例探しでは、読むモデルが規則の手をすべては使っていないこと（実装の誤り）と、G の数え終わりが定義に明記されていないことが見つかり、版5 で直した。版5 に当てた反例探しでは、G の数え始めが「1手」の区切り方で動くことが見つかり、版6 は区切り方の両端で G の段がそろう問題だけを分類した。版6 に当てた反例探しでは、まとめる側の端の「選ぶ所」に、どの手を選んでも同じ局面へ合流する見かけの選ぶ所が入っていて、それを除くと G が動くことが見つかった。今の定義（版7）は、選ぶ所を手の行き先が違う所（本当の選ぶ所）に限り、局面をどこまで粗く同一視するかの線とその外を定義に書いた。境目 2 / 6 は版7 の分布で確かめて保った。版7 には反例探しを当てていない（PO の判断で、難易度の調整を版7 で打ち切った。§13.4）。§3〜§13 は版7 で書き（前の版で測って測り直していない値はそう書く）、版1〜6 とその反例は §14 に残す。見つかった向きのうち版7 で直したものと残るものは §14.12、版5・版6・版7 の比べは §14.13。

根拠は次の見出し語で書き分ける。

- 計測: 調査コードで測った結果。どのコマンドで測ったかを添える。一度だけ測った値は「一時スクリプト」と書く（調査コードの関数を呼んで集計だけを変えたもの。残していない）。

## 2. 挑戦と基準とするプレイ条件

### 2.1 挑戦の1文

> 列の奥に埋まった札をどの順で掘り出し、どの札をどの列に置き、空いた列と山札の札をいつ使うかを先まで読んで、置ける手をそのまま打つと先で詰む所を見抜いて避けること。

挑戦に入れないもの:

- 山札をめくる回数（何周でもめくれるので、欲しい札が出るまでめくるのは作業量）
- 解き終えるまでの手数そのもの
- 山札の中身を覚えておくこと（見えている札の残りとして分かる。覚える負担はプレイ摩擦として扱う）

### 2.2 山札の扱い（読むモデルと試すモデル）

- 読むモデル（人間向け解法器）は、山札を「いつでも取れる札の集まり」として扱う。
  - 導出: 1枚ずつ何周でもめくれると、山札と捨て札の並びは「巡回する1本の列と、めくる位置」になる。めくり進めればどの札も捨て札の一番上に出せ、1枚取っても残りの巡回の順は変わらない。したがって、どの札をどの時点で使えるかは山札の並びに依らず、並びはめくる回数（作業量）にだけ効く。
  - 列が全部表なので、山札の中身は見えている札の残りとして分かる。読むモデルは中身を知っている扱いにする。
- 試すモデル（素朴な解き方、§3.1）は、実際の山札の順で1枚ずつめくり、捨て札の一番上だけを使う。
  - 合意のレベル1「置ける所に置き、無ければめくる」は、めくる順で置ける札が変わる遊び方なので、山札の並びを含めて1問とする。
- 難しさの源への効き方:
  - 運と隠れた情報が無くなり、どの配り方も読めば解ける（合意の「推測は要らない」を満たす）。
  - 山札は24枚の「いつでも取れる予備」になる。難しさは列の28枚の掘り出しと、予備の札を「いつ列へ出すか」に集まる。§7 の例の致命の手（§3.4）も、多くが捨て札を列へ置く手か、並びを動かす手。
  - 素朴な解き方の結果は山札の並びに依る。山札の並びだけを変えると分類が多く変わる（版1 で 31%。版2 に当てた反例探しでも30問中7〜23問）。並びを含めて1問とするので、これは定義どおり。

### 2.3 基準とするプレイ条件

- ルールと操作を知っている。次の手は見せない。待ったと盤面を戻すを使ってよい。
- 状態の知らせは「どの手順でも、今より多くの札を組札に置ける局面へ行けない」ときに出る、と定義して測った（AI 判断）。組札から戻して置き直すだけでは札は増えないので、知らせは止まらない。
  - 判定の関数（`foundation_progress_reachable`）は、規則の手をすべて1手ずつ、枝刈りなしで探す。ルールとプレイ画面へ移すもの。
  - 版1〜4 の関数（`foundation_progress_reachable_v1` として残した）は、探索の中で組札へ送る手を打たず、各局面で「1枚送れば今より多くなるか」だけを見ていた。組札から一度戻して並びを動かし、戻した札と下から出た札を送り直すと増える局面で「増やせない」と答える誤りがあり、版4 に当てた反例探しで見つかった（seed 200・256 の詰み）。版5 で直した。
  - 計測（`notifycmp`）: 素朴な解き方（版1 の手の範囲）が詰んだ局面60件のうち、直した関数では知らせが出るのは31件、出ないのは24件（組札から戻す・並びの途中から動かす手でまだ組札を増やせる）、20万局面で決まらないのが5件。直す前の関数とは5件で答えが違った（直す前は 34・20・6）。調べた局面数は中央値136、90パーセンタイルで約15万（Python で最大約7秒）。致命の手の先の詰みでの重さは §3.9。
  - 知らせは詰んだ後にしか出ないので、§3.4 の罠の後の進みを短くしない（導出）。知らせが出ないことは「まだ手がある」合図になる（推測）。判定の重さはルールとプレイ画面の側で上限を決める必要がある（決まらないときの扱いを含む）。

### 2.4 分析が表せる解き方の範囲

- 素朴な解き方（試すモデル）: §3.1 の手だけを打つ。置ける手が無いときだけめくる。組札から戻す手、組札へ送る目的の無い並びの途中からの移動、置ける手があるのにめくる手は打たない。
- 読むモデル（解けるかの判定）: 規則で打てる手をすべて表す（§3.3）。
- 定石つきの素朴な解き方（確かめにだけ使う。§8.1）: 読むモデルの手から無作為に選び、行き止まりで待ったをする。分類には使わない。
- 表せないもの: なし（規則の手はすべて読むモデルに入る）。ただし読むモデルの探索には上限があり、上限で判定が決まらない問題は評価不能にする（§3.6）。

## 3. 特徴

### 3.1 素朴な解き方の手と網

素朴な解き方の置ける手（`nat_candidates`）:

| 記号 | 手 |
| --- | --- |
| TF | 列の一番上の札を組札へ |
| WF | 捨て札の一番上を組札へ |
| TT | 並びの始まりから上を丸ごと別の列へ。列の一番奥から始まる K 以外の並びを動かして列を空ける手（E）と、K から始まる並びを空いた列へ動かす手を含む |
| WT | 捨て札の一番上を列へ（K は空いた列へ） |
| PF | 並びの途中から上を別の列へ動かし、その下に出た札を組札へ送る（2つの動きで1手と数える。2手に分けても G は変わらない。§3.5） |

- 置ける手が1つも無いときだけ、実際の山札の順で1枚めくる。山札が尽きたら捨て札を裏返して戻す（これも1回のめくりと数える）。置ける手が無いまま1周したら詰み。
  - 1周: 山札と捨て札の札の合計を n とすると、n + 1 回めくると元の並びに戻る。その間のどの局面でも置ける手が無ければ詰み。
  - 実装（`_nat_advance`）は、1周の後さらに1回めくってから詰みとし、そのときの局面（1周で戻った局面の次）を詰んだ局面として記録する。増えた2つの局面は1周の中ですでに調べた局面と同じなので、詰みかどうかは変わらない。詰んだ局面の組札の枚数も、読むモデルの札（山札を札の集まりとして扱う）も、めくりの位置に依らないので、G と分類も変わらない（導出）。詰んだ局面を本当の選ぶ所の行き先（§3.4）として見分けるときも、記録する局面は、最後の手を打った直後の局面から1回めくった局面に決まっていて、違う詰みは違うまま、同じ詰みは同じままなので、選ぶ所は変わらない（導出）。
- PF を入れる理由: 「並びの一番上の札を移して下の札を組札へ送る」は、表向きの札をまとめて動かせるこのルールの基本の手で、置ける所（組札）に置くための動きとして「置ける所に置く」に含めるのが字義に近い（AI 判断）。
- 目的の無い途中からの移動を入れない理由: 同じ並びを2つの列の間で往復できるので、「置ける手があれば置く」と決めるとめくりに進まず同じ所を回り続ける。素朴に遊ぶ人がする手とも考えにくい（推測）。入れたときの感度は §8.2。
- 網（`natural_graph`）: 置ける手が1つ以上ある局面（めくりを済ませた後）を節点、置ける手ごとの次の局面・勝ち・詰みを子とする。
  - 列を並べ替えて同じになる局面は同じ局面とする。同じ局面へ進む手は1つの手と数える。
  - 導出: 素朴な手は打つたびに「組札の枚数×3 ＋ 正しく重なった組 − 正しくない組 ＋ 列の札の数」が増えるので、網は輪を持たない。どの道筋も勝ちか詰みで終わる。
- 素朴な手の変種（§3.2 の段の確かめに使う）: 列を空ける手 E を除く（noE）、PF を除く（noPF）、両方を除く（basic）。
- 安全な組札送りを先に打つ網（`restrict_safe_all`。版7）: 安全な組札送り（§3.3 と同じ条件）がある局面では、安全な組札送りだけを打つ道筋に絞った網。2つ以上あれば、どれを先に打ってもよい。安全な札を必ずすぐ組札へ送る人の道筋で、アプリが安全な札を自動で組札へ送るときの網と同じ（§4.3）。
  - 安全な組札送りは互いに妨げない（送っても別の安全な札は安全なままで、列の一番上か捨て札の一番上のまま）ので、どの順で送っても送り終えた局面は同じ（導出）。だから順を1つに決めた網（版6 までの `restrict_safe` は最初の1つだけを残す）と、段・本当の選ぶ所・終わり・G は同じになる（導出）。計測: 段2・段3 の274件で、段・G の両端・分類が同じ。あり得る致命の手の数だけが、打ち切りの残る2件（267・338）で違う（どの順でも打てる網は辺が多い。安全な組札送りは解けるかを変えない（§3.3）ので、増えた辺が確かな致命の手になることは無い）（`compare7`）。

### 3.2 段 T（素朴な解き方で勝てるか）

| 段 | 条件 |
| ---: | --- |
| 1 | 網のどの道筋も勝ちで終わる |
| 2 | 勝ちで終わる道筋と、詰みで終わる道筋の両方がある |
| 3 | どの道筋も詰みで終わる |

- 道筋の有無だけで決まるので、置ける手をどんな重みで選ぶか（等しい確率・札を先に選ぶ・置き場所を先に選ぶ）に依らない（導出）。優先順位を持つ遊び方は網の道筋の一部をたどるので、段1 と段3 は変わらない。段2 だけが、優先順位によって「その人にとっては必ず勝てる」か「必ず詰む」になり得る（導出。§8.2 に測った）。
- 安全な組札送りを先に打つ網でも、段は解ける364件すべてで同じだった（計測: 一時スクリプト。版7 の `restrict_safe_all` の網でも、段2・段3 の274件すべてで同じ（`compare7`）。段1 の網は、絞っても道筋がどれも勝ちのままなので段1（導出））。
- 段1 と段3 は「すべての道筋」についての約束なので、素朴な手の4つの変種（すべて・noE・noPF・basic）のどれでも同じ段のときだけ使う（`classify_v7`。段 T の扱いは版4〜6 の `classify_v4`・`classify_v6` と同じ）。変種で段が変わる問題は提供範囲外にする（§4.1）。
- 勝てる確率 p（置ける手から等しい確率で選ぶとき。網の上の正確な値）は記録だけで、分類に使わない。

### 3.3 読むモデル（解けるかの判定）

- 解法器（`AliveOracle(bc=True)`。中は `Solver(partial=True, back=True, pfilter="v2", bc=True)`）: 規則で打てる手をすべて表す。山札はいつでも取れる札の集まりとして扱う（§2.2）。
- 規則の手と、解法器での表し方（遅延の議論が覆う範囲）:

| 規則の手 | 解法器での表し方 | 答えを変えない理由 |
| --- | --- | --- |
| 列の一番上・山札の札を組札へ | そのまま打つ。安全な組札送り（A・2 と、反対の色の2マークの組札がその1つ下まで、同じ色のもう1マークが2つ下まで進んでいる札）は先に済ませる | 安全な組札送りはよく知られた決まりで、組札から戻す手があっても答えを変えない（導出） |
| 並びの始まりから上を別の列へ | そのまま打つ | — |
| 列の一番奥から始まる並び（K 以外）を動かして列を空ける | 空いた列に置ける K（並びの中の奥でない K、山札の K、組札の K）があるときだけ | 空いた列に置けるのは K だけなので、空けた列を使う直前まで遅らせられる |
| 並びの途中から上を別の列へ | 下に出る札が組札へ行けるか、下に出る札の上に乗せられるもう1枚（動かす札と同じ数・同じ色の札）が、動かせる列の札か、組札の一番上か、上に何かを乗せられる山札・組札の札のとき | 下に出る札を列に残す使い道は、組札へ送るか、その上に札を乗せるかだけ（乗せられるのは動かす札とそのもう1枚だけ）。もう1枚がまだ動かせないときは、動かせるようになるまで遅らせられる。下に出る札ごと動かすなら、下に出る札から上を動かす手で同じ局面になる |
| 山札の札を列へ | 上に乗せる札と一続きの手（足場）としてだけ打つ。上に乗せるのは、列の札（上の3つの手）か、組札から戻す札（下の BC） | 山札の札を列へ置く理由は上に札を乗せることだけ。乗せる直前まで遅らせても、その間ほかの手は置き場所の札を使えない（上がふさがっている）ので、同じ手順が打てる |
| 組札の一番上を列へ | (1) 山札の札と同じく足場として、(2) 列の一番上（K は空いた列）へ単独で、(3) 山札・組札の札の足場の上へ（BC。版5 で足した）。(2)(3) は絞らない | 足場としての (1) は山札の札と同じ。(2)(3) は規則の手そのもの |

- 版4 までの読むモデルには (3) の BC が無く、足場の上に乗せるのは列の札だけだった。(2) も、戻した札かその下の組札の札の上に、動かせる札か使い道のある札が乗れるときだけに絞っていた。そのため「山札の札を足場に並べ、その上へ組札の一番上を戻す」手順の要る局面を「解けない」としていた（版4 に当てた反例探し。seed 282 の致命の手の先は、山札の 7D 6C 5D を 8C に並べて組札の 4C を 5D へ戻すと解ける）。版5 で直し、版1〜4 の関数は直す前の読むモデル（`bc=False`）のまま残した（§14.6）。
- 行き止まり（`dead`）: 並びの始まりの札 x（K 以外）が、同じ列のより奥に同じマークの小さい札を持ち、x を置ける2枚がどちらも同じ列のより奥にある局面は解けない（x は動かせず、その下の札を組札へ送れない。導出）。
- 決まりが答えを変えないことは、導出だけでなく、分類に効く所を狙った確かめで支える（§3.12）。
- 上限: 1回の問い合わせ4万局面、1問の合計200万局面。同じ問題の中では、探し切って勝ちが無かった探索で訪れた局面（どれも解けない）、勝ちへ続く道の上の局面（どれも解ける）、打ち切った局面を覚えて使い回す。

### 3.4 致命の手と、罠の後の進み G

- 致命の手: 網の辺 x → y（素朴な手1つ。置ける手が1つだけの局面の手も含む）で、局面 x は読むモデルで解け、局面 y は解けないもの（`fatal_depths`）。ここを過ぎると、どの規則の手を打っても勝てない。
  - 導出: 解けない局面から素朴な手で進んだ先も解けない（素朴な手は規則の手なので、先で解けるなら手前も解ける）。だから、解けない詰みで終わる道筋には、致命の手がちょうど1つある。
  - 致命の手そのものは、組札へ送る手のこともある（例: seed 354 の「捨て札の 10D を組札へ」）。置ける手が1つだけの局面の手のことも多い（版7 の L2〜L5 の83件の確かな致命の手 802 のうち 263。それを含む問題 53件、すべてそれの問題 28件。計測: 一時スクリプト）。
- 罠の後の進み G: 致命の手の後、素朴な解き方でどう続けても、詰むまでに組札に置かれる札の枚数の最小を、致命の手を含む「1手」の始まりの局面から数えたもの。1手の区切り方の両端で求める（区切り方と選ぶ所の決め方の範囲は §3.5）。
  - G_f（規則の1手で区切る）: 数え始めは x。G_f(x → y) = 組札の枚数(y から行ける詰みの最小) − 組札の枚数(x)。版5 までの G と同じ。
  - 本当の選ぶ所: 網の後ろから、手ごとの「行き先」を決める。子が終わり（勝ち・詰み）か本当の選ぶ所なら、行き先はその子。そうでなければ、その子の行き先。手の行き先が2つ以上違う節点を本当の選ぶ所とする（根は数え始めとしていつも使う）（`real_choices`）。
    - 本当の選ぶ所でない節点では、どの手を選んでも、ほかの本当の選びを経ずに同じ局面へ合流する。置ける手が1つだけの局面（強制手）と、見かけの選ぶ所（組札へ送る順番の入れ替え、7H を直接組札へ送るか 8S に置いてから送るかのような寄り道）がこれに当たる。
  - G_b（本当の選ぶ所での選びと、行き先までの手を1手にまとめる）: 本当の選ぶ所 d の手ごとの行き先 D について、d が解け、D が解けない選びを致命の選びとし、G_b = 組札の枚数(D から行ける詰みの最小) − 組札の枚数(d)（`fatal_depths_v7`）。d から D までのどの道筋も D を通るので、致命の手 x → y がその間のどこにあっても、y から行ける詰みの最小は D からの最小と同じ（導出）。
  - y の先は解けないので、どの続け方も詰みで終わる（導出）。
  - 数え終わりの「詰み」は、素朴な解き方の詰み（置ける手が無いまま山札を1周した局面。§3.1）とする。状態の知らせが出る所（どの規則の手順でも組札を増やせない所。§2.3）ではない。理由と、知らせまでで数えたときの感度は §3.9。
- 問題の G_f・G_b: それぞれ、すべての致命の手・すべての致命の選びの中の最大。
- G の段: G_f と G_b の段（§4.2 の B）が同じ問題だけを分類し、その段を使う。違えば提供範囲外（`trap-depth-depends-on-grouping`）。どの区切り方・どの選ぶ所の決め方（§3.5 の範囲）でも G は G_f 以上 G_b 以下なので、両端の段が同じなら、どれでも同じ段になる。
  - 問題の G の段が表すこと: 「この問題には、打った後どう続けても、組札がその段の枚数だけ進むまで行き詰まらない致命の手がある。その枚数は、詰む手そのものから数えても、その前の本当の選びから数えても同じ段に入る」。
  - 両端をそろえる理由: 置ける手をそのまま打つ人にとって、置ける手が1つだけの所の手や、どれを選んでも同じ局面に合流する所の手は選びではないので、間違えたと感じるのはその前の本当の選びになる（G_b の数え始め。推測）。置かずにめくる・組札へ送るのを待つ手まで考える人には、詰む手そのものが罠になる（G_f の数え始め）。両端の段をそろえると、どちらの人にも同じ段の約束になる。遊び方で数え始めが変わるのを両方そろえて扱う点は、安全な札をすぐ送る網での確かめ（§3.7）と同じ。
  - 版6 の G_b は、違う局面へ進む素朴な手が2つ以上ある節点をすべて選ぶ所とし、見かけの選ぶ所からも数えていた（§14.11）。
- 致命の手は2つに分けて記録する（分類には使わない）。
  - 後戻りの無い所の致命の手: x の素朴な手がどれも致命の手。x は解けるので、正しい手は素朴でない規則の手（置けても置かずにめくる、組札へ運ぶのを待つ、並びの途中から動かす、組札から戻す）。
  - 別の手が残る所の致命の手: x に、打っても解けるままの別の素朴な手がある。

### 3.5 G の数え方の自由度と、1手の区切り方・選ぶ所の決め方

版1〜3 の反例は、どれも「何を1手・1つの分かれ道・1つの終わりと数えるか」を替えると値が動くものだった（§14）。G は分かれ道と終わりを数えない。1手の区切り方と選ぶ所の決め方は数え始めを動かすので、両端を求めて段がそろうことを求める（版5・版6 に当てた反例探しで見つかった。§14.9・§14.11）。

- 単位: 組札の枚数は札そのもの（52 − 列・山札・捨て札に残る札の数）で、ルールが決める。手・分かれ道・めくりの数え方を使わない。
- 1手の区切り方と選ぶ所の決め方（定義が覆う範囲）:
  - 区切り方は、素朴な遊び方の道筋（規則の手の列）を「1手」に分ける分け方とする。本当の選ぶ所（§3.4）では必ず新しい1手が始まり、それ以外の所（強制手の前、見かけの選ぶ所、PF の中間、めくり）では区切っても区切らなくてもよい。最も細かいのは規則の1手（G_f）、最も粗いのは本当の選ぶ所での選びと行き先までの手のまとまり（G_b）。
  - 選ぶ所の決め方は、どの節点で必ず1手が始まるかの決め方で、上の区切り方に含まれる。どの節点も選ぶ所とする（規則の1手）、違う局面へ進む手が2つ以上ある節点を選ぶ所とする（版6）、本当の選ぶ所だけとする（版7）の順に粗くなり、粗いほど数え始めは前に動く。
  - 導出: 致命の手 x → y を含む1手の始まりは、道筋の上で d（x 以前で最後の本当の選ぶ所。無ければ根）から x の間にある。素朴な手は組札を減らさないので、組札の枚数は d ≤ 始まり ≤ x の順に並び、どの区切り方でも G は G_f(x → y) 以上 G_b 以下になる。問題の値は致命の手の中の最大なので、問題の G も［G_f, G_b］に入る。
  - PF の中間の局面（並びを動かした後、組札へ送る前）とめくりの局面は、組札の枚数が直前の節点と同じなので、そこで区切っても G_f は変わらない（導出）。めくりは列と組札を変えず、読むモデルは山札をいつでも取れる札の集まりとして扱うので、めくりが致命の手になることも無い。
  - 局面の同一視（合流を見るとき、どの局面を同じとみなすか）は網の節点と同じで、列を並べ替えて同じになる局面を同じとする（§3.1。K を2つの空いた列のどちらへ置くかは選びにならない）。山札の位置（次にめくる札）は局面に入れる。
- 線の引き方: まとめる側の端（G_b）は、次の2つを守る中で最も粗い選ぶ所の決め方で取る。粗いほど G_b は大きくなる（導出）ので、この端が、定義が覆う区切り方の中の G の最大になる。
  - (1) 選ぶ所かどうかを、手の後に遊ぶ人が次に見る局面と次の選び（手の行き先）だけで決める。手の先の結果（行ける終わり、解けるか、詰みの組札の枚数）を使わない。結果を使うと、数え始めを、G が数える対象そのものや、選んだ後のさらに先の選びの結果で決めることになる。
  - (2) 局面の同一視は、素朴な遊び方の次の手を変えない違いだけにする。列の並び（左右の位置）は、置ける手を列の付け替えで写すだけで、その先の局面も列の付け替えで同じになるので同一視する。同一視しない網では、同じ局面へ進む手が別の行き先になって選ぶ所が増えるだけなので、G_b は小さい側に動くだけ（導出）。山札の位置は、次に出る札と置ける手を変えるので同一視しない。
- 線の外（区切り方・選ぶ所の決め方とは見ない。反例探しで外側として試せる）。外す理由と、測った値（感度の一覧は §3.9）:
  - 行ける終わり（勝ち・詰み）の集まりが違う所だけを選ぶ所にする（(1) に反する）: 終わりの集まりが同じでも、手の行き先（次の本当の選ぶ所）が違えば、遊ぶ人はその後に違う局面を見て違う選びをする。終わりの集まりで決めると、選んだ結果の違い（その後の別の選びと、そこまでの進み）を G に入れてしまう。また、数え始めを決めるのに、G が数える対象（詰みの組札）そのものを使う。計測: 版7 の L2〜L5 の83件のうち網が5万節点以下の80件で、本当の選ぶ所 21,793 のうち終わりの集まりでも選ぶ所になるのは 13,499。この決め方を端にしても分類が変わる問題は0（`compare7` の `bend`。網の大きい3件（7・179・258）は求めていない）。
  - 山札の位置を見ずに合流を見る（列と組札が同じなら同じ局面とする。(2) に反する）: 素朴な遊び方は実際の山札の順でめくり、捨て札の一番上だけを使う（§2.2）。山札の位置だけが違う局面では、次に出る札と置ける手が違い、遊ぶ人が次に見る局面と選びが違う。読むモデルは山札をいつでも取れる札の集まりとして扱うので、この2つの局面は「解けるか」では同じになるが、それは (1) が使わないと決めた結果の側の同じさ。計測: 版7 の L2〜L5 の83件の網で、選ぶ所の数は 25,930（本当の選ぶ所。根を含む）から 25,869（山札の位置を見ない。根を含まない）へ減るだけで、この決め方を端にしても分類が変わる問題は0（`compare7` の `bns`）。
  - 解けるか（札）で選ぶ所を飛ばす（解けるままの別の手がある最後の選ぶ所まで戻す、など。(1) に反する）: 区切り方ではなく、誤りの決め方を替える別の概念で、alt（§3.8）や、「解ける」を素朴な解き方で勝てるかにする形（§3.9）の仲間。版6 に当てた反例探しが測った値は 15/86。
  - 本当の選ぶ所を2つ以上またいで1手にまとめる: 1手に2つの本当の選びが入ると、数え始めが正しく選んだ所まで戻り、その後の進みまで数える。根まで戻せば G は「詰みの組札 − 根の組札」になり、罠の深さを表さない。前の本当の選びにまとめられるのは、合流するだけの手（強制手と見かけの選び）だけ。版6 に当てた反例探しが測った値は 35/86。
  - 強制手を、その後の選びと1手にまとめる（1手の途中に本当の選ぶ所が来る）: 選ぶ所の前の強制手は、前の選びで決まった結果で、この選びより前に打ち終わっている。1手を、遊ぶ人が何も選んでいない局面から始め、罠より前の進みを「罠の後」に数えることになる。版6 に当てた反例探しが測った値は 17/86。
  - 選ぶ所を、別の素朴な手の範囲や癖を持つ遊び方の網で決める: 素朴な手の範囲の選択として §3.7 で扱う（安全な札をすぐ送る網では、その網の本当の選ぶ所で両端を求めてそろうことを求め、ほかの網では一致を求めない）。
- 局面で決まる: 致命の手は「解ける局面から解けない局面へ」で決まり、解けるかは局面だけで決まる。G_f は x の組札の枚数と、y から行ける詰みの組札の枚数だけで、G_b はそれに加えて網の本当の選ぶ所（網の形だけで決まる）で決まる。
  - x から数える理由（G_f）: 致命の手そのものが組札へ送る手でも、PF を2手に分けても値が同じ。y から数えると、PF を2手に分けたとき、致命になるのが「並びを動かす」の方か「組札へ」の方かで値が1枚ずれ得る。
- 終わりの見分け方を使わない: G は詰んだ局面の組札の枚数だけを使い、詰んだ局面どうしを同じとみなすかを決めない。版3 の反例1（同じ数・同じ色の札の入れ替えを同じとみなす、組札だけで見分ける、勝ちか詰みかだけ、山札の位置まで見分ける）は、G の定義に入る所が無い（導出）。
- 罠の置き場所を使わない: 致命の手と致命の選びはすべて数える。版3 の反例2（罠の置き場所の決め方）への答えは §3.8。
- 最小と最大: 続け方は最小、問題の値は致命の手の中の最大。どちらも網のすべての道筋の上の値で、乱数・道筋の抜き出し・中央値を使わない（導出）。
- 詰んだ局面では組札へ送れる札が残っていない（組札へ送る手は素朴な手なので、送れるなら詰みではない）。だから、組札へ送るのを後回しにする続け方で G が小さく出ることは無い（導出）。

### 3.6 打ち切りの扱い（G の幅）

- 読むモデルが打ち切った局面には、解ける・解けないのどちらもあり得る。札を次の順で絞ってから、幅を取る（`label_graph`・`fatal_depths`・`fatal_depths_grouping`）。
  - 解ける子を持つ節点は解ける。解けない節点の子は解けない（どちらも、素朴な手が規則の手であることから。導出）。
  - 確かな致命の手: x が確かに解け、y が確かに解けない。
  - あり得る致命の手: x が解けないと決まっておらず、y が解けると決まっていない。
  - 導出: 確かな致命の手 ⊆ 本当の致命の手 ⊆ あり得る致命の手。G(x → y) は網だけで決まり札に依らないので、本当の G_f は［確かな致命の手の G_f の最大, あり得る致命の手の G_f の最大］に入る。致命の選びと G_b も同じ。
  - 鎖からの下限: 違う局面へ進む手が2つ以上ある節点か根 d から、置ける手が1つだけの局面の手（強制手）だけをたどった鎖で、d が確かに解け、鎖の行き先が確かに解けないなら、鎖の中に本当の致命の手が必ず1つある（導出）。その G_f は、鎖の最後の局面（行き先の直前）から数えた値以上。だから G_f の幅の下端は、確かな致命の手の G_f の最大と、この下限の最大の大きい方（`G_lo_f`。版6 から同じ。版6 に当てた反例探しで、打ち切りの無い186の遊び方で違反 0）。
- 区切り方の両端と幅の組み合わせ: どの区切り方・どの打ち切りの札付けでも、本当の G は［G_lo_f, G_hi_b］に入る。
  - G_hi_f の段 < G_lo_b の段なら、規則の1手で区切った段とまとめた段が必ず違う。区切り方で段が変わると決まるので提供範囲外（`trap-depth-depends-on-grouping`）。
  - G_lo_f と G_hi_b の段が同じなら、どの区切り方・どの札付けでも同じ段なので、分類する。
  - どちらでもなければ評価不能（`oracle-unresolved`）。

### 3.7 遊び方の違いと G

- G は、素朴な手すべての網（どの素朴な遊び方の続きも含む）の上で求める。特定の癖を持つ人の網に絞ると、出会う致命の手と、その後の続け方が変わるので、G の段が動くことがある。これは段2 が存在の約束であるのと同じ性質で、定義には含めない。
- ただし、安全な札をすぐ組札へ送る遊び方だけは確かめに入れる（§4.3 の採用形）。多くの人がする遊び方で、アプリが自動で送るときの網とも同じだから（推測）。この網でも本当の選ぶ所は変わる（安全な組札送りのある局面では、安全な組札送りだけが打てる）ので、この網の本当の選ぶ所で区切り方の両端を求め、両端とも素朴な手すべての網と同じ段であることを求める（§3.6）。この網で段が同じなのに罠が無い（あり得る致命の手が無い）ときも、遊び方で罠の有無が変わるので、G の段が変わるときと同じく範囲外（`trap-depth-depends-on-play`）とする（版7 で定義に書いた。解ける364件で該当は0。計測: 一時スクリプト）。素朴な手すべての網に罠が無いのに、この網にだけ罠があることは無い（この網の道筋は素朴な手すべての網の道筋なので、致命の手もその網の致命の手。導出）。

### 3.8 致命の手をすべて数える理由（罠の置き場所を限らない）

版3 に当てた反例探しは、罠を「同じ局面に、打っても解けるままの別の素朴な手がある所」に限る（alt）と、多くの罠が消えることを示した。版7 でも、両端とも alt に限ると（規則の1手の端は別の素朴な手が解けるままの所の致命の手だけ、本当の選ぶ所の端は別の行き先が解けるままの所の致命の選びだけ）、分類済みの83件のうち39件が変わり、L1〜L5 は 10 / 22 / 20 / 1 / 3 件になる（L4 は 13 → 1、L5 は 11 → 3。計測: `compare7` の `Galt`。案A'。§13.2）。alt を基本にせず、致命の手をすべて数える。理由:

- 後戻りの無い所（x の素朴な手がどれも致命の手）でも、x は解けるので、正しい手はある。正しい手は素朴でない規則の手（置けても置かずにめくる、組札へ運ぶのを待つ、並びの途中から動かす、組札から戻す）。x の手前は解ける局面だけなので、誤りは x で素朴な手を打つことのほかに無い。これは L4・L5 が求める「置けても置かない」判断そのもの。
- 段3 の問題では、根から解ける子をたどると、必ず後戻りの無い所か、解けるまま詰む局面に行き着く（導出: 段3 ではどの道筋も詰みで終わり、解ける子をたどれなくなる所が後戻りの無い所）。版7 の L4 の 11/13 件、L5 の 5/11 件は、確かな致命の手がすべて後戻りの無い所にある（§5.3）。alt はこれらを罠から外すので、L4・L5 の挑戦を測れなくなる。
- alt は「別の素朴な手」の範囲に依る。素朴な手を足し引きすると、後戻りの無い所かどうかが変わる。すべて数える形では、素朴な手を足しても今ある致命の手は致命のまま（札は局面だけで決まる）で、足した手が新しい致命の手を加えるだけ（導出）。
- 反例探しの見立て「人が罠と呼ぶのは、正しい手があったのに外した手」は、すべて数える形でも満たす。後戻りの無い所にも正しい手（規則の手）がある。素朴な手しか打たない人にはそこで選ぶ余地が無いが、その人は段3 の問題をそもそも解けない（段3 の定義）。

#### 進みの量: 組札の枚数を選んだ理由

- 組札の枚数はゲームの目的そのもので（52枚を組札へ）、画面で常に見え、合意の知らせも「組札へ運べなくなったら」と組札で言う。人が「進んだ」と感じる手応えに最も直接につながる（推測）。
- 素朴な手では組札の枚数は減らない（素朴な手に組札から戻す手は無い）ので、致命の手の後の進みはいつも 0 以上で、「どう続けても G 枚進むまで行き詰まらない」と読める（導出）。列の札の数や空いた列の数は素朴な手で増えも減りもするので、進みが負になり、この読み方ができない。
- 埋まった札（並びの下にある札）の減りは、どの札を「埋まった」と数えるかに定義の自由度が残り、版1〜3 と同じ「何を1つと数えるか」の問題が戻る。山札から出た札の数は、山札をいつでも取れる予備とみなす読み（§2.2）では、局面の進みを表さない（出さなくても使える）。
- 版4 に当てた反例探しが、量を替えて L2〜L5 の段の割合が近くなる境目で比べた結果（版4 の札。定義の範囲を替えたときの感度として記録する）:

| --- | --- | --- | --- |
| 並びの下に埋まった札の減り | 1 / 4 | 0.53 | 48（別のレベルへ 29） |
| 山札から出た札 | 5 / 12 | 0.70 | 36 |
| 列の札の減り | −4 / 0 | −0.27 | 76 |

- 「行き詰まりが見えるまでの距離」は量の選び方に強く依る。人の進み具合の感覚が組札の枚数と埋まった札の減りのどちらに近いかは、試遊で確かめる（§10）。

### 3.11 つまみが人の挑戦を変える理由

- 段 T: 段2 は、置ける手をそのまま打つと詰む道があるので、手を打つ前にその先を読む必要がある。段3 は、置ける手をどの順で打っても詰むので、「置けても置かない」「先にめくる」「組札へ運ばずに待つ」などの判断が少なくとも1回要る。合意の「上ほど、目先の手で進めると詰む」をそのまま表す。
- 罠の後の進み G: 致命の手を打っても組札が何枚も進むなら、手応えはしばらく「うまく行っている」ままで、行き詰まりが見えない。打つ前に見抜くには、その枚数の分だけ先まで読む必要がある。詰んでから戻るときも、組札へ送った手を何枚分もさかのぼって、どこで間違えたかを探す。知らせ（§2.3）も詰んだ後にしか出ないので、この間は何も教えない。G の段は、詰む手そのものから数えても、その前の本当の選び（どれを選んでも合流するだけの所を除いた、最後に選んだ所）から数えても同じ段の問題だけを使うので、どちらを「間違えた所」と感じる人にも同じ距離の約束になる（§3.4）。

### 3.12 読むモデルの確かめ（R1）

- 分類に効く「解けない」の札は、致命の手の先 y（解けないと決まっていない局面 x から出る手の先で、読むモデルが解けないとしたもの）に集まる。読むモデルが本当は解ける局面を解けないとしたとき、その誤りの一番上の局面は、必ずこの y のどれかになる（その局面の親は解けるか、決まっていないので。導出）。
- 確かめ（`verify_fatal_dead`。`v5` の中で、各問題の致命の手の先をすべて解き直す。集計は `verify5`、版6・版7 の分類で分けた集計は `verify6`・`verify7`）:
  - y（局面で重ねない）を、枝刈りの無い別の実装（`plain_solve`。規則の手を1手ずつ打つ）で2万局面まで解き直す。打ち切りなら、安全な組札送りだけを先に済ませる形で10万局面まで解き直す。確かな致命の手の先から順に、1問60秒まで。
  - y から素朴な手で行く詰み e（読むモデルが解けないとしたもの）も、同じく枝刈りなしで5万局面まで解き直す。
  - 勝ちが見つかれば、読むモデルの「解けない」が誤り。
- 結果（計測: `v5`・`verify5`。解ける364件のうち致命の手のある274件）:

| 対象 | 局面 | 枝刈りなしで解けない | 安全な組札送りだけ使って解けない | 打ち切り | 60秒を超えて解き直していない | 解けた |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| y（版5 の L2〜L5 の102件） | 1,083 | 677 | 241 | 98 | 67 | 0 |
| y（274件すべて） | 4,074 | 1,261 | 703 | 397 | 1,713 | 0 |
| e（版5 の L2〜L5 の102件） | 1,022 | 1,022（2回目を含む） | — | 0 | — | 0 |
| e（274件すべて） | 2,212 | 2,209（2回目を含む） | — | 3 | — | 0 |

  - 解き直していない y は14件にあり、ほとんどがあり得る致命の手の多い提供範囲外と評価不能の問題（L2 は 274 の31局面と 313 の36局面）。
  - 打ち切りの y も、その先の詰み e はすべて解けないと確かめた（L2〜L5）。y そのものが解けるかは、打ち切りの分だけ確かめきれていない。
  - 時間: 1問あたり 10 / 50 / 90 パーセンタイルで 0.01 / 3.6 / 44 秒、最大66秒、274件で合計3,223秒。
- 版6・版7 での扱い: 版6・版7 は版5 と同じ読むモデル・同じ札を使う。版7 で分類に効く「解けない」の札は、確かな・あり得る致命の手の先 y と、致命の選びの行き先 D（本当の選ぶ所の手の行き先）にある。D が解けないとされるのは、d から D までの道筋のどこかの局面 y が解けないとされ、その子として解けないと伝わったからで、その y は版5 の確かめの対象に入る（導出）。だから版5 の解き直しの結果をそのまま使う。版7 の L2〜L5 の83件（`verify7`）では、y 844局面のうち解き直して解けないと確かめたのが673（枝刈りなし 450・安全な組札送りだけ使う形 223）、打ち切り99、時間切れで解き直していないのが72（274・313 の67と L3 の5）。e 844局面はすべて解けない。勝ちは0。版6 の92件では y 911・e 889 で、同じく勝ち0だった。
- 版4 までの確かめ（`verify-oracle`）が誤りを見逃した理由: 作った順で最初の節点の子を1問6つまで解き直すだけで、致命の手の先を狙っていなかった。網の札の食い違い（解けない節点の子が解ける）は、解けない節点の子を問い合わせない作りなので、誤りがあっても出ない。
- 読むモデルの「解ける」は、見つけた勝ち筋が規則の手でできていることで支える（解き筋は配った盤面から1手ずつ確かめ直す `validate_path`。BC の手も確かめる）。

### 4.2 レベルごとの基準表（検討時点の暫定値）

段 T と、罠の後の進みの段 B（1: G ≤ 2、2: G が 3〜6、3: G ≥ 7）の組で決める（`classify_v7`。境目は `G_SHORT = 2`・`G_LONG_V7 = 6`。版6 と同じ値）。B は、区切り方の両端（G_f と、本当の選ぶ所から数えた G_b）と打ち切りの幅のどこを取っても同じ段のときだけ決まる（§3.4〜§3.6）。

| レベル | T | B | 利用者向けの一言 |
| ---: | ---: | ---: | --- |
| 1 | 1（4つの変種すべてで） | — | 置ける所に置いていけば、どう置いても解ける |
| 2 | 2 | 1 | 置いていくと詰む進め方がある。どの詰む手も、打った後、組札が2枚以下しか進まずに行き詰まることがある |
| 3 | 2 | 2 | 置いていくと詰む進め方があり、その中に、打った後どう続けても組札が3枚以上進むまで行き詰まりが見えない手がある |
| 4 | 3（4つの変種すべてで） | 2 | 置いていくだけでは、どの順でも詰む。どこかで「置けても置かない」判断が要る |
| 5 | 3（4つの変種すべてで） | 3 | 置いていくだけではどの順でも詰み、打った後どう続けても組札が7枚以上進むまで行き詰まりが見えない詰む手がある |

- L2〜L5 の一言は、列を空ける手も PF も打つ素朴な遊び方（合意の「置ける所に置き」の字義）についての約束（§3.7）。「詰む手」は致命の手（どの規則の手を打っても勝てなくなる手）。「打った後」は、詰む手そのものから数えても、その前の本当の選び（どれを選んでも合流するだけの所を除いた、最後に選んだ所）から数えても同じ段になる（§3.4）。

組み方の理由:

- 隣のレベルとは、どちらか1つのつまみだけを1段上げる（1→2 は T、2→3 は B、3→4 は T、4→5 は B）。問題ごとに、上のレベルの T と B は下のレベル以上。
- (T2, B3) と (T3, B1) は、近いレベルへ寄せると「上は下を含む」が問題ごとに崩れるので提供範囲外にする（解けると確かめた364件のうち 23 と 7 件）。
- 境目は分布から置いた。段2 の G_f（幅の決まったもの）は 0〜16 に、4つの変種で段3 の G_f は 0〜15 に広がり、切れ目は無い（計測: 一時スクリプト）。版5 までと同じく、L2〜L5 がおおよそ揃う所に置く。
  - 版6 では、区切り方の両端で段が変わる問題を外したので、版5 の境目 2 / 5 のままだと L4 が薄くなり（L2〜L5 が 30 / 29 / 8 / 14 件）、境目を 2 / 6 に置き直した（§14.10）。
  - 版7 では、本当の選ぶ所から数えると G_b が境目をまたぐ問題がさらに外れる（版6 の L2〜L5 のうち L2 2・L3 5・L4 2 の9件）。境目 2 / 6 のままで L2〜L5 は 28 / 31 / 13 / 11 件。ほかの境目は 2/5 で 28 / 25 / 6 / 14、2/7 で 28 / 42 / 18 / 9、2/8 で 28 / 46 / 22 / 3、1/6 で 19 / 44 / 19 / 11、1/7 で 19 / 56 / 25 / 9、3/6 で 38 / 18 / 7 / 11、3/7 で 38 / 29 / 11 / 9、1/5 で 19 / 36 / 12 / 14、2/4 で 28 / 17 / 3 / 22（計測: `compare7` と一時スクリプト。§3.9）。
  - 2 / 6 は、最も少ないレベルが 11 件で、最も多いレベルとの比（31 / 11）が表の中で最も小さい。上限5倍の2回目の後（§6）も、2 / 6 で 29 / 32 / 15 / 19 件になり最も揃う（2/5 で 29 / 26 / 7 / 22、2/7 で 29 / 43 / 21 / 14、1/6 で 19 / 44 / 21 / 19、3/6 で 39 / 19 / 8 / 19、1/5 で 19 / 36 / 13 / 22。計測: 一時スクリプト）。版7 でも境目は 2 / 6 のまま保つ。

読み方と限界:

- 待ったつきの行は導出（段の定義から）。レベル4・5は、置ける手を置く解き方では待ったを何回使っても解けない。
- 定石つき＋待ったの押し切り率は乱数に依る（乱数は `random.Random(seed*101+k)`、k = 0〜9）。分類には使わない。定石つきの解き方の手（`savvy_undo`）は版4 までの読むモデルの手（BC を含まない）で、押し切り率は配り方だけで決まる。

  - 定石つきの形では L4 と L5 の中央値がどちらも 0.5 で下がらない（L5 の 6/11 が 0.5 以上）。L5 は後戻りの無い所が L4 より少ない（§5.3）ので、無作為に戻る試し方では、致命の手の手前の別の手に当たりやすいのかもしれない（推測）。件数が少なく（13 と 11）、版6 では L4 0.5・L5 0.5、版5 でも L4 0.5・L5 0.5、版3 の採った分類では L4 0.6・L5 0.3 だった。L5 が上級者向けに足りるかは §10 で確かめる。
- 解けないことは難しいことの根拠にならない（守ること 5）。上のレベルの難しさは、§3 の T と G（読むモデルで致命の手を決める）で支える。

### 8.2 素朴な手の範囲と遊び方への感度

## 12. パズル仕様の難易度の節の案

### 基準とするプレイ

- 列の札と、見えている札の残りとして分かる山札の中身を見て、置ける手をそのまま打つか、置かずに先を読むかを決めるプレイを基準とする。
- 山札を何周めくるか、解き終えるまでの手数は難しさに含めない。

### 挑戦

- 列の奥に埋まった札をどの順で掘り出し、どの札をどの列に置くかを先まで読む。
- 空いた列へ入れる K と、山札の札を列へ出す時期を選ぶ。置ける手をそのまま打つと先で詰む所を見抜いて避ける。

### 段階設計

| 難易度 | 挑戦 |
| --- | --- |
| 1 | 置ける所に置いていけば、どう置いても解ける。 |
| 2 | 置いていくと詰む進め方があるが、詰む手を打っても早めに行き詰まって気づける。 |
| 3 | 置いていくと詰む進め方があり、詰む手を打っても、組札が何枚か進むまで行き詰まりが見えないことがある。 |
| 4 | 置いていくだけではどの順でも詰む。どこかで置けても置かない判断が要る。 |
| 5 | 置いていくだけではどの順でも詰み、詰む手を打っても、組札がかなり進むまで行き詰まりが見えないことがある。 |

- 「置いていくと詰む進め方があるか」と「詰む手を打ってから行き詰まるまでに、組札が何枚進むか」の2つを、1段ずつ交互に上げて段階を分ける。
- 行き詰まるまでの枚数は、詰む手そのものから数えても、その前の本当の選び（どれを選んでも同じ局面に合流するだけの所は選びに数えない）から数えても同じ段に入る問題だけを使う。
- 盤面の大きさはどのレベルも同じで、配り方だけで段階を分ける。
- 山札の並びは素朴に遊ぶときの手応えを変えるので、並びを含めて1問とする。

### 13.3 正本との食い違いの候補

- [難易度提供.md](../../難易度提供.md) は、提供範囲の下限を「挑戦が軽い形でも成立している側」に置き、挑戦がほとんどない問題を最も低いレベルに置くことを目的にしないとする。合意したレベル1（置ける所に置いていけば、どう置いても解ける）は、罠が無いので先読みの挑戦がほとんど無い。合意（人間の判断）に従ってそのまま作り、食い違いとして最終レビューで人間に渡す。

python3 solitaire_difficulty.py compare7 --cache <cache> --big v7big_random.jsonl
python3 solitaire_difficulty.py notify7 --cache <cache> --out <cache>/notify7_random.jsonl --big v7big_random.jsonl
python3 solitaire_difficulty.py sens7 --cache <cache> --out <cache>/sens7_random.jsonl

python3 solitaire_difficulty.py verify7 --cache <cache>

python3 solitaire_difficulty.py expected7 --only 3,39,170,76,363,51,200,251,354,7,158,282,6,27,0,281,349,304,53,45,103,327,307,137,352,381,286,1,148,4,2,203,30,10,14,78,85,315,185 --out solitaire_difficulty.expected.json
