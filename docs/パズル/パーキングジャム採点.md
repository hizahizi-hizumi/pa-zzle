# パーキングジャム採点

> **人間のプレイデータによる校正前の暫定値**: `play-quality-v2` の基準時間・減点は、問題特徴と操作の構造から置いた初期値である。実プレイの時間分布・体感とはまだ照合していない。

## 目的

パーキングジャムの評価点は、問題そのものの難しさではなく、その問題をどのように解いたかを評価する。

合法に出庫した車は盤面から消え、合法な車を選んだことで後から手詰まりになることはない。また、クリアに必要な成功出庫回数は車両数で固定される。したがって成功手数や最短手数との差はプレイ品質を表さない。

`play-quality-v2` では次の3点を評価する。

- **正確さ 40点**: 盤面を読み、出せない方向を選ばずに判断できたか
- **速さ 40点**: その問題に見合う時間で盤面を読み続けられたか
- **安定性 20点**: 出庫済みの車を戻したり、最初からやり直したりせずに進められたか

配点を40 / 40 / 20とするのは、判断の正確さと判断速度を同じ主評価とし、待った・やり直しはプレイを支える補助操作なので副評価とするためである。

## 採点基準

### 正確さ

40点から開始し、出せない方向を1回選ぶごとに5点減点する。0点未満にはしない。

不成立操作は単なる操作回数ではなく、その時点の盤面について「この車はこの方向へ出せる」と判断した結果なので、正確さとして扱う。現在の盤面表現では、縁石・道路開口・植栽島・車の向きを盤面から読めるため、不成立を UI 解読ではなくパズル判断の結果として扱う。

不成立操作は盤面を変えない代わりに、どの車が出せるかを試して知る手段にもなる。試して知った情報を持ったまま計数だけを捨てられないよう、プレイ中は同じ問題の新しいプレイを始められない。初期盤面へ戻す操作は「盤面を戻す」だけで、やり直しとして計上し、経過時間も継続する。同じ問題の新しいプレイはクリア後の結果画面からだけ始められる。

### 速さ

問題ごとに次の満点基準時間 `T` を求める。

```text
T = 盤面把握 5秒 + 車両数 × 3秒 + 初期遮断車数 × 3秒
```

- **盤面把握 5秒**: 初めて盤面を見て、道路開口・固定物・車の向きを把握する時間
- **車両1台 3秒**: 全車を1回ずつ出庫させる必要があるため、出せる車を探して車軸方向へ操作する1台分の時間
- **初期遮断車1台 3秒**: 初期盤面で塞がっている車は、邪魔な車を読み、出す順序を判断する必要があるため追加する時間

基準時間を難易度ラベルではなく問題特徴から求めることで、同じレベルでも車両数や塞がり方の違う問題を、同じ「基準時間に対する倍率」で比較する。上のレベルだから点を取りにくい、小さい盤面だから点を取りやすい、という状態を避ける。難易度判定が `challenge-levers-v1`（レベル1〜5）へ変わっても、`T` の式は変えていない。

`T` 以内は40点。超えた分だけ線形に減点し、`2T` で0点とする。

現在の問題集（各レベル1,000問から等間隔に250問）での `T` の分布は次の通り。

| レベル | 最小 | 中央 | 最大 |
| ---: | ---: | ---: | ---: |
| 1 | 35秒 | 38秒 | 53秒 |
| 2 | 35秒 | 38秒 | 56秒 |
| 3 | 35秒 | 47秒 | 71秒 |
| 4 | 35秒 | 50秒 | 71秒 |
| 5 | 35秒 | 53秒 | 71秒 |

`T` は段数（さかのぼって読む深さ）と読み違いを誘う車を含まない。上位レベルで「さかのぼって読む」時間が基準時間に入らず速さの点が系統的に低くなる、読み違いを誘う盤面で不成立操作が増え正確さと二重に効く、という可能性がある（推測）。5段階の最初の提供では `play-quality-v2` を変えず、実プレイで「経過時間 / `T`」と不成立操作がレベルとともに上がるかを見る。

1台3秒・初期遮断1台3秒は人間の計測値ではなく、1回の出庫がスワイプ1回で完了する操作と、塞がった車だけに追加の読みが必要になる構造から置いた値である。

### 安定性

20点から開始し、次を減点する。

- 待った1回: -2点
- やり直し（盤面を戻す）1回: -5点

合法な出庫は将来の手詰まりを生まないため、待ったは必須の探索手段ではなく、既に成立した判断を戻した事実として扱う。やり直しはそれより大きくプレイを巻き戻すため、減点も大きくする。

時間は待った・やり直し中も継続する。これは二重罰ではなく、判断に要した実時間と、補助操作へ頼った度合いを別の評価軸として扱うためである。

## 評価段階

既存ゲームと同じ結果段階の意味へ接続する。

| 評価点 | 段階 |
| --- | --- |
| 100 | perfect |
| 90〜99 | great |
| 80〜89 | good |
| 0〜79 | clear |

クリア自体と高評価は分離する。80点未満でもパズルを解いた事実は `clear` として成立する。

## 固定シナリオ

問題ごとの基準時間を `T` としたとき、同じプレイ品質なら問題・難易度によらず次の点数になる。

| プレイ例 | 時間 | 不成立 | 待った | やり直し | 点数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 迷いなく解く | `1.00T` 以下 | 0 | 0 | 0 | 100 |
| 正確だが少し慎重 | `1.25T` | 0 | 0 | 0 | 90 |
| 正確だがゆっくり | `1.50T` | 0 | 0 | 0 | 80 |
| 小さな読み違いから復帰 | `1.00T` | 1 | 1 | 0 | 93 |
| 読み違いが複数ある | `1.00T` | 2 | 1 | 0 | 88 |
| 一度やり直して慎重に完了 | `1.25T` | 0 | 0 | 1 | 85 |
| 読み違いと時間超過が重なる | `1.50T` | 3 | 1 | 0 | 63 |

この表は点数の分布を作るための目標値ではなく、「明らかに良いプレイほど高い」という順序が式から崩れていないかを確認するための固定例である。

## 保存と再計算

評価点自体をプレイ事実の正本にしない。記録（payloadVersion 4）には次を保存し、評価点は採点版に従って再計算する。

- 難易度（レベル1〜5）
- 問題を分類した難易度モデル版（`challenge-levers-v1`）
- 採点版（`play-quality-v2`）
- 問題識別情報（車両数を含む）
- 初期遮断車数
- 経過時間・総操作数・成功出庫数・不成立操作数・待った回数・やり直し回数

成功出庫数は待った・やり直しで戻した車の再出庫も含むため、車両数以上になる。総操作数は成功出庫数と不成立操作数の和であり、採点には使わない。

payloadVersion 3 の記録は3段階（easy / normal / hard、`visual-local-load-v1`）の難易度を持つ。形は payloadVersion 4 と同じで、`play-quality-v2` でそのまま再計算する。難易度はレベルへ読み替えず、旧区分として表示する。

payloadVersion 2 の記録は難易度モデル版・採点版・初期遮断車数を持たない。これらは当時の `play-quality-v1`（8×8・14台固定の問題に対する難易度別基準時間 easy 60秒 / normal 90秒 / hard 120秒、他の減点は同じ）で再計算して表示し続ける。

自己ベストの比較単位は難易度とし、評価点・経過時間・不成立操作数を比較する。レベル1〜5と旧3段階（かんたん / ふつう / むずかしい）は別の比較単位で、混ぜない。

## 再校正

実プレイ記録が集まったら、同じ採点版の記録について次を確認し、軸の意味を保ったまま係数を調整する。

- 経過時間 / `T` の分布が、レベル・盤面規模・車両数によって系統的に偏っていないか（偏るなら1台あたり・初期遮断1台あたりの秒数を回帰で見直し、段数など依存の深さの項を足すかを検討する）
- レベル1〜5で、100 / 90台 / 80台 / それ未満の体感が不自然にずれないか
- 不成立1回の5点が大きすぎないか、小さすぎないか
- 待ったとやり直しの差が実際のプレイ感に合うか
- 基準時間の1.25倍・1.5倍・2倍の評価が体感に合うか

採点軸の意味や係数を変える場合は `PARKING_JAM_SCORE_MODEL_VERSION` を更新し、記録の採点版で旧式と新式を区別して再計算できるようにする。
