# PUZZLE-095 送迎パーキング

## 問題供給成立性

確認中。

パーキングジャムのルール再設計（#727）の比較試作で、乗客列型の問題を無作為に作る生成を測った。判断があり、そのすべてが車の遮断で決まる問題が CPU 1分あたり374〜436問できた（定員2と3の車を混ぜ、列を無作為に作り、開口を隣り合う2辺か1辺にした条件）。導入調査の研究用の生成と5段階の案では、最も少ないレベルでも CPU 1分あたり33問を採れた。製品の生成器・問題集はまだ無い。

- [送迎パーキング実装前提調査](../../導入調査/送迎パーキング/送迎パーキング実装前提調査.md)

## 難易度運用成立性

確認中。

盤面の広さではなく、どう進めても避けて通れない罠の結果が何人先に出るか（罠なし・4人先まで・5〜7人先・8〜9人先・10人以上先）で5段階にする方針。研究用の生成では、レベル1〜3 は読み方を変えた模擬でも順に並んだが、レベル4 と 5 はほとんど分かれなかった。5段階のまま作り、遊んで確かめる。人による試遊はしていない。

- [送迎パーキング実装前提調査](../../導入調査/送迎パーキング/送迎パーキング実装前提調査.md)
- [送迎パーキング難易度](../../導入調査/送迎パーキング/送迎パーキング難易度.md)

## スマホプレイ成立性

確認中。

製品のプレイ画面の枠の実測から、320×568 で乗客の列・待機枠と戻す操作の1行・盤面を縦に積み、盤面の下に操作の足場を持たない構成にすると、7×7 の盤面で車の短辺が既存のパーキングジャムの下限以上に収まると見積もった。20人前後の列を読み続ける負担と、実機での押しやすさは確かめていない。

- [送迎パーキング実装前提調査](../../導入調査/送迎パーキング/送迎パーキング実装前提調査.md)

## 導入判断

調査中。

パーキングジャム（PUZZLE-038）の再設計の比較（#727）から生まれた別のゲーム。パーキングジャムには、選ぶと解けなくなる手が無い。送迎パーキングでは、乗客の列・定員・待機枠によって、列の先を読んで出す順を計画することが要る。パーキングジャムは変えない。表示名「送迎パーキング」は仮の名前で、公開前に商標を確かめてから確定する。比較の材料は #727 と PR #977 にある。
