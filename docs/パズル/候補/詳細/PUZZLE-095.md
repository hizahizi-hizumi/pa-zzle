# PUZZLE-095 送迎パーキング

## 問題供給成立性

通過。

製品の生成器で、盤面の大きさ（6×6・7×7）と出口の辺（上だけ・上と右）の4組から候補 1,060,000 を分析し、各レベル500問（計2,500問）の問題集を作って同梱した。最も少ないレベル4 でも候補の 0.04%台が当たった。生成スクリプトの `--verify` で、全問を符号から作り直して分析し直し、レベル・罠の重さ・見た目と解き味の重複・同じレベルの近い盤面を確かめた。

## 難易度運用成立性

確認中。

どう進めても避けて通れない罠の結果が何人先に出るかで5段階にした。製品の問題集でも、レベル1〜3 は試し出しで戻す人・無作為に選ぶ人の模擬で順に並んだが、レベル3〜5 の3段はほとんど分かれなかった。人間の判断で5段階のまま作り、最終レビューで遊んで確かめる。合わなければレベル3〜5 の難易度と問題集を作り直す。人による試遊はしていない。

## スマホプレイ成立性

確認中。

320×568・390×664 と PC の実ブラウザ（Playwright）で、上から乗客の列・待機枠と待ったの1行・駐車場を積み、盤面の下に操作の足場を持たない画面が縦送りなしに収まることを確かめた。390×664 では、AI の試遊で各レベルの問題を最後まで遊べた。20人前後の列を読み続ける負担と、実機の Safari での操作（連打の拡大、端からの戻るジェスチャーなど）は確かめていない。

- [送迎パーキング実装前提調査](../../導入調査/送迎パーキング/送迎パーキング実装前提調査.md) §4.1・§7

## 導入判断

正式採用。マージで決まる。

パーキングジャム（PUZZLE-038）の再設計の比較（#727）から生まれた別のゲーム。パーキングジャムには、選ぶと解けなくなる手が無い。送迎パーキングでは、乗客の列・定員・待機枠によって、列の先を読んで出す順を計画することが要る。パーキングジャムは変えない。表示名「送迎パーキング」は、公開前に商標を確かめてから確定する。比較の材料は #727 と PR #977 にある。
