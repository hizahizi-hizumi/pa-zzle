# 難易度判定

## 役割

この文書は、[難易度.md](難易度.md) で定めた人間の挑戦強度という概念を、各パズルで再現可能な難易度判定へ落とすための原則を定める。

各パズル固有の特徴量、閾値、分類規則、実装ファイルは、そのパズルの現在仕様とコードを正とする。

## この文書で実現すること

多数のパズルを追加しても、同じ特徴量や同じ計算式を強制せずに、各パズル固有の挑戦を機械的に判定できる状態を作る。

難易度判定を、測りやすい値への置き換えではなく、人間の挑戦を再現可能に近似する責務として保つ。問題をどう生成・選択して供給するかは別の責務とし、難易度判定そのものへ混ぜない。

## 判定の責務

難易度を扱うときは、少なくとも次の責務を分ける。

1. **問題成立性**: 問題がルール上正しく成立しているかを確認する。
2. **難易度分析**: その問題が要求するパズル固有の挑戦を、特徴として観測する。
3. **難易度分類**: 分析結果から、その問題が提供範囲のどこに位置するかを判断し、提供対象なら難易度1〜5へ分類する。
4. **問題供給**: 必要な難易度レベルの問題を生成・取得・選択する。

問題成立性、難易度分析、難易度分類、問題供給を、一つの値や一つの処理へ混ぜない。

問題供給は分析・分類の結果を利用するが、生成条件や選択都合を理由に分類結果をねじ曲げない。

## 原則

### 各パズルで挑戦の中身を先に定義する

特徴量を探す前に、そのパズルで何を考えることが面白さを生み、何がその挑戦を強くするのかを言語化する。

既存ゲームの特徴量や、取得しやすい数値から逆算して難易度の意味を決めない。

### 特徴量は難易度そのものではない

難易度特徴量は、人間の挑戦強度を機械的に観測するための代理値である。

特徴量が安定して計算できても、人間の挑戦との意味的なつながりを説明できなければ、それだけを難易度判定の根拠にしない。

### 生成条件を難易度へ直結させない

盤面サイズ、色数、ヒント数などの生成条件は、特定の挑戦強度を持つ問題が現れやすい候補領域を作るために使える。

ただし、生成条件の値をそのまま難易度ラベルへ対応させない。生成された問題そのものを分析し、難易度を判定する。

### 計算機上の難しさを人間の難しさと同一視しない

探索状態数、探索時間、最短手数などの solver 内部値は、それが人間の挑戦と対応する理由を説明できる場合に限って難易度の根拠として使う。

計算機にとって探索が重いことだけを理由に、人間にとって難しいと判定しない。

### 必要な次元を一つの数値へ無理に潰さない

パズル固有の挑戦が複数の性質から成る場合、判定内部では複数の観点を保持できる。

利用者向けに一つの難易度帯を返す必要があっても、内部の理由まで一つの加算スコアにすることを共通要件にはしない。

単一指標へまとめる場合は、その指標が挑戦の違いを失っていないことを確認する。

### 判定は再現可能にする

同じ問題を同じ判定条件で評価したとき、同じ分析結果と難易度判定を得られることを基本とする。

人間の主観そのものを実行時判定へ持ち込まず、人間の挑戦との対応を検討した結果を再現可能な判定へ落とす。

### 判定できない問題と提供範囲外の問題を分ける

現在の分析方法で挑戦強度を評価できない問題は、「難しい問題」とは別である。

また、挑戦強度を評価できても、[難易度提供.md](難易度提供.md) の提供範囲より軽すぎる、強すぎる、またはゲームとして提供したい体験から外れる問題は、難易度1〜5へ必ず分類する必要はない。

したがって少なくとも次を区別できる設計にする。

- ルール上成立しない問題
- ルール上成立するが、現在の分析では難易度を評価できない問題
- 難易度を評価できるが、現在の提供範囲には含めない問題
- 提供範囲に含まれ、難易度1〜5へ分類できる問題

評価不能や提供範囲外を難易度5へ押し込まない。具体的な状態名や表現方法は各パズルで定める。

### 問題供給は分析・分類結果へ従う

必要な難易度レベルの問題を供給するときは、生成条件だけでレベルを決めるのではなく、生成・取得した候補を分析・分類した結果に基づいて選択する。

候補生成は、目的の難易度が現れやすい領域へ探索を寄せるために分析・分類結果を利用してよい。反対に、生成しやすさを理由として問題の難易度分類を変更しない。

候補生成と難易度判定は協調してよいが、両者の責務は分ける。

## 各パズルが持つべき具体化

各パズルの現在仕様では、少なくとも次を説明できる状態にする。

- そのパズル固有の挑戦は何か。
- 挑戦強度が何によって変わると考えるか。
- それをどのような特徴で観測するか。
- 問題成立性をどのように確認するか。
- 現在の分析で評価できる問題の範囲はどこか。
- 提供範囲に含める問題をどう判断するか。
- 分析結果から難易度1〜5へどう分類するか。
- 評価不能・提供範囲外の問題をどう扱うか。

具体的な実装方式や値はゲームごとに異なってよい。難易度レベルへの問題供給方法は、[難易度提供.md](難易度提供.md) と各パズルの現在仕様に従って別途定める。

## 用語

| 用語 | 意味 |
| --- | --- |
| 難易度分析 | 問題が要求するパズル固有の挑戦を、再現可能な特徴として観測すること |
| 難易度分類 | 難易度分析の結果から提供範囲内の相対的位置を判断し、提供対象を難易度1〜5へ対応させること |
| 評価不能 | 問題は成立しているが、現在の難易度分析では挑戦強度を根拠を持って評価できない状態 |
| 提供範囲外 | 挑戦強度は評価できるが、現在のpa-zzleが通常の難易度選択として提供する範囲に含めない状態 |

## この文書で固定しないこと

- 全パズル共通の特徴量
- 全パズル共通の難易度計算式
- 全パズル共通の閾値
- 単一の difficulty score の採用
- 特定の solver や探索方式
- 実装ファイル名やモジュール構成
- モデル識別子や版管理の一律導入
- 問題生成・選択アルゴリズム
